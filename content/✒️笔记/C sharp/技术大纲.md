| 名词     | 意思              | 大白话          |
| ------ | --------------- | ------------ |
| **同步** | 做完一件再做下一件       | 排队等          |
| **异步** | 启动任务，不等完成，先去干别的 | 不用死等         |
| **串行** | 一个接一个执行         | 顺序执行         |
| **并发** | 多个任务**交替执行**    | 看起来同时跑（单核也能） |
| **并行** | 多个任务**真・同时执行**  | 必须多核 CPU     |

## 技术细节
- var是C#的隐式类型，让编译器自动推断变量类型，不用手写完整类型，简化代码
- AutoMapper

重要区别：
- C# 用 `out` 可以返回多个值
- C# 属性直接访问，不用 get/set
- C# 接口推荐以 `I` 开头，字段用下划线 `_`
- 冒号：兼具继承和实现

**VS2026 开发老项目的关键避坑指南（和 VS2019 不一致的地方）**

1. **不要用.NET Core/.NET 10 + 的模板**：你要的老项目，必须选带【(.NET Framework)】后缀的模板，这是和 VS2019 老项目完全兼容的唯一选择
2. **框架版本优先选 4.8**：.NET Framework 4.8 是最终稳定版，VS2019、VS2022、VS2026 全版本兼容，不会出现版本不匹配的问题
3. **老项目不要用新的顶级语句、文件范围命名空间等 C# 新语法**：.NET Framework 最高支持 C# 7.3，新语法会编译报错，保持和 VS2019 一样的 C# 语法写法即可
4. **NuGet 包版本不要盲目升级**：MVC5 的最高稳定版本是 5.2.9，不要升级到.NET Core 的 MVC 包，否则会直接不兼容
5. **调试服务器统一用 IIS Express**：和 VS2019 保持一致，不要用 Kestrel（这是.NET Core 的服务器，老 Framework 项目不推荐用）

#### IIS问题
---
1. **VS 项目的调试（非 IIS 托管）**
    如果你的 VS 项目是用自带的 IIS Express、Kestrel 等内置服务器运行（比如默认的 [ASP.NET](https://ASP.NET) Core 项目），它和系统级的 IIS 是互相独立的，Default Web Site 关不关都不影响这些调试。
2. **其他软件的网络访问**
    只要不是依赖本地 IIS 80 端口的软件，都不会受到影响。
    
 **⚠️ 唯一会受影响的地方**

Default Web Site 默认占用的是 **本地 80 端口**，关闭它之后：

- 原来通过 `http://localhost`（或本机 IP）访问的 IIS 默认站点内容会无法访问（你本来就不用它，所以对你来说没影响）。
- 如果你有其他程序 / 服务也需要占用 80 端口，关闭 Default Web Site 后，80 端口就被释放了，反而能避免端口冲突，对你的 VS 项目调试是有帮助的。

 💡 **给你的调试避坑建议**

- 如果你只是怕它占用 80 端口影响 VS 项目调试：
    
    停止 Default Web Site 就足够了，不需要删除。停止后它就不会占用端口了，也不会自动启动（除非你手动点了启动，或者设置了自动启动）。
- 如果你之后需要再用 IIS：
    
    随时在 IIS 管理器里选中它，点右侧的「启动」就能恢复，非常方便。
这个操作对你的目标是正向的：**既不会影响你正常上网，还能避免端口冲突干扰调试**
