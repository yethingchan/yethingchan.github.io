# 项目分层架构与调用流程分析

## 一、整体架构图
```
HTTP Request
     ↓
┌─────────────────────────────────────────┐
│        Controller 层 (控制器)           │
│  - 接收 HTTP 请求                       │
│  - 参数验证                             │
│  - 调用 Service / Repository           │
│  - 返回 HTTP 响应                       │
└─────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────┐
│       AutoMapper 层 (对象映射)          │
│  - DTO ↔ Entity 转换                    │
│  - 配置文件：Profiles/*.cs             │
└─────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────┐
│     Repository 层 (数据访问层)          │
│  - 接口：I*Repository.cs                │
│  - 实现：*Repository.cs                 │
│  - 数据库 CRUD 操作                     │
└─────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────┐
│        DbContext 层 (EF Core)           │
│  - AppDbContext.cs                      │
│  - DbSet<T> 实体集合                    │
│  - 数据库连接管理                       │
└─────────────────────────────────────────┘
     ↓
┌─────────────────────────────────────────┐
│          Database (MySQL)               │
│  - 物理数据库                           │
└─────────────────────────────────────────┘
```

## 二、完整调用链路示例
以 `WmsMaterialOutController.CreateOutOrder` 为例

### 1. Controller 层 - 接收请求
**文件：** `Controllers/Another/WmsMaterialOutController.cs`
```csharp
[Route("api/[controller]")]
[ApiController]
public class WmsMaterialOutController : ControllerBase
{
    private readonly IOutOrderWmsRepository _outOrderListRepository;
    private readonly IMapper _mapper;

    // 依赖注入
    public WmsMaterialOutController(
        IOutOrderWmsRepository outOrderListRepository,
        IMapper mapper)
    {
        _outOrderListRepository = outOrderListRepository;
        _mapper = mapper;
    }

    [HttpPost]
    public async Task<IActionResult> CreateOutOrder([FromBody] WmsOutOrderDto outDto)
    {
        // 1. 参数验证
        if (outDto == null)
            return BadRequest("参数不能为空");

        // 2. 业务处理
        outDto.ORDER_NO = Guid.NewGuid();

        // 3. DTO → Entity
        var outOrder = _mapper.Map<WmsOutOrder>(outDto);

        // 4. 仓储层保存
        _outOrderListRepository.CreateOutOrder(outOrder);
        var result = await _outOrderListRepository.SaveAsync();

        // 5. 返回响应
        return Ok(new { success = result, orderNo = outDto.ORDER_NO });
    }
}
```

**职责：**
- 接收 HTTP 请求
- 参数校验
- 调用 AutoMapper 转换对象
- 调用 Repository 完成数据操作
- 返回统一格式响应

### 3. AutoMapper 层 - 对象映射配置
**文件：** `Profiles/WmsMaterialOutProfile.cs`
```csharp
public class WmsMaterialOutProfile : Profile
{
    public WmsMaterialOutProfile()
    {
        // 必须配置：WmsOutOrderDto ↔ WmsOutOrder
        CreateMap<WmsOutOrderDto, WmsOutOrder>().ReverseMap();
    }
}
```

**注册位置：** `Startup.cs`
```csharp
services.AddAutoMapper(AppDomain.CurrentDomain.GetAssemblies());
```

**职责：**
- DTO 与 Entity 自动转换
- 集中管理映射规则
- 减少手动赋值

### 4. Repository 接口层
**文件：** `Controllers/Another/Services/IOutOrderWmsRepository.cs`
```csharp
public interface IOutOrderWmsRepository
{
    Task<List<WmsOutOrder>> GetOutOrderByDate(DateTime datetime);
    void CreateOutOrder(WmsOutOrder wmsOutOrder);
    Task<bool> SaveAsync();

```

**职责：**
- 定义数据访问契约
- 解耦控制器与具体实现
- 便于测试与替换

### 5. Repository 实现层
**文件：** `Controllers/Another/Services/OutOrderWmsRepository.cs`
```csharp
public class OutOrderWmsRepository : IOutOrderWmsRepository
{
    private readonly AppDbContext _context;

    public OutOrderWmsRepository(AppDbContext context)
    {
        _context = context;
    }

    public void CreateOutOrder(WmsOutOrder wmsOutOrder)
    {
        _context.Add(wmsOutOrder);
    }

    public async Task<bool> SaveAsync()
    {
        return await _context.SaveChangesAsync() > 0;
    }
}
```

**注册：** `Startup.cs`
```csharp
services.AddScoped<IOutOrderWmsRepository, OutOrderWmsRepository>();
```

**职责：**
- EF Core 数据库操作
- 实现 CRUD
- 事务提交

## 五、分层职责总结
| 层级 | 位置 | 核心职责 |
|------|------|----------|
| **Controller** | Controllers/ | 接收请求、参数校验、返回响应 |
| **DTO** | */Dto | API 数据传输对象 |
| **AutoMapper Profile** | Profiles/ | 对象映射配置 |
| **Repository 接口** | */Services | 数据访问抽象 |
| **Repository 实现** | */Services | 数据库操作 |
| **Entity** | */Model | 数据库表映射 |
| **DbContext** | DataBase/ | EF Core 上下文 |
| **Startup** | 根目录 | 服务注册、配置 |

## 六、关键设计模式
1. **依赖注入 DI**
   解耦、便于测试、统一管理生命周期

2. **仓储模式 Repository**
   封装数据访问，隔离业务与数据库

3. **DTO 模式**
   保护实体、灵活控制接口字段

4. **AutoMapper 对象映射**
   减少重复赋值，提升维护性

## 七、常见问题排查（修正版）
### 问题 1：AutoMapper 映射失败
错误：`Missing type map configuration`
- 原因：未配置 `CreateMap`
- 解决：在 Profile 添加 `CreateMap<Dto, Entity>()`

### 问题 2：依赖注入失败
错误：`Unable to resolve service for IXXXRepository`
- 原因：未在 Startup 注册
- 解决：`services.AddScoped<IXXXRepository, XXXRepository>()`

### 问题 3：EF Core 不生成 SQL
- 原因：忘记调用 `SaveChangesAsync()`
- 解决：必须调用 `await SaveAsync()`

## 八、最佳实践（修正建议）
1. **路由统一加 api 前缀**：`[Route("api/[controller]")]`
2. **命名空间规范**：不要使用 `Another/aother` 这种不规范命名
3. **Entity 命名规范**：`DbSet<WmsOutOrder> WmsOutOrders` 复数形式
4. **推荐使用 Scoped**：Repository 注册用 `AddScoped` 而非 `Transient`
5. **统一响应格式**：所有接口返回相同结构 JSON
6. **增加全局异常处理**
7. **增加日志记录**
