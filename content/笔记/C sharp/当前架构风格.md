# 项目分层架构与调用流程分析

  

## 一、整体架构图

  

```

HTTP Request

     ↓

┌─────────────────────────────────────────┐

│         Controller 层 (控制器)           │

│  - 接收 HTTP 请求                        │

│  - 参数验证                              │

│  - 调用 Service/Repository               │

│  - 返回 HTTP 响应                        │

└─────────────────────────────────────────┘

     ↓

┌─────────────────────────────────────────┐

│      AutoMapper 层 (对象映射)            │

│  - DTO ↔ Entity 转换                    │

│  - 配置文件: Profiles/*.cs              │

└─────────────────────────────────────────┘

     ↓

┌─────────────────────────────────────────┐

│    Repository 层 (数据访问层)            │

│  - 接口: I*Repository.cs                │

│  - 实现: *Repository.cs                 │

     ↓

     ↓
```

## 二、完整调用链路示例

  

以 `WmsMaterialOutController.CreateOutOrder` 为例：

  

### 1. **Controller 层** - 接收请求

  

**文件：** `Controllers/Another/WmsMaterialOutController.cs`

  

```csharp

[Route("[controller]")]

[ApiController]

public class WmsMaterialOutController : ControllerBase

{

    private IOutOrderWmsRepository _OutOrderListRepository;

    private IMapper _mapper;

  

    // 依赖注入

    public WmsMaterialOutController(

        IOutOrderWmsRepository outOrderListRepository,

        IMapper mapper)

    {

        _OutOrderListRepository = outOrderListRepository;

        _mapper = mapper;

    }

  

    [HttpPost]

    public async Task<IActionResult> CreateOutOrder([FromBody] WmsOutOrderDto outDto)

    {

        // 1. 参数验证

        if (outDto == null) { ... }

        // 2. 业务逻辑处理

        outDto.ORDER_NO = Guid.NewGuid();

        // 3. 调用 AutoMapper 进行 DTO → Entity 转换

        var outOrder = _mapper.Map<WmsOutOrder>(outDto);

        // 4. 调用 Repository 层保存数据

        _OutOrderListRepository.CreateOutOrder(outOrder);

        bool result = await _OutOrderListRepository.SaveAsync();

        // 5. 返回响应

        return Ok(returnjson);

    }

}

```

  

**职责：**

- 接收 HTTP POST 请求

- 验证输入参数

- 协调各层完成业务逻辑

- 返回 HTTP 响应

### 3. **AutoMapper 层** - 对象映射

  

**文件：** `Profiles/WmsMaterialOutProfile.cs`

  

```csharp

public class WmsMaterialOutProfile : Profile

{

    public WmsMaterialOutProfile()

    {

        // 配置映射规则

        CreateMap<WmsMaterialOutDto, OutOrderList>()

            .ForMember(dest => dest.ORDER_NO, opt => opt.MapFrom(src => ...))

            .ForMember(dest => dest.CUST_CODE, opt => opt.MapFrom(src => src.CustCode));

        // ⚠️ 缺少：CreateMap<WmsOutOrderDto, WmsOutOrder>()

    }

}

```

  

**职责：**

- 配置 DTO 与 Entity 之间的映射规则

- 自动转换对象属性

- 支持自定义映射逻辑

  

**注册位置：** `Startup.cs` 第 54 行

```csharp

services.AddAutoMapper(AppDomain.CurrentDomain.GetAssemblies());

```

### 5. **Repository 实现层** - 数据访问实现

  

**文件：** `Controllers/Another/Services/OutOrderWmsRepository.cs`

  

```csharp

public class OutOrderWmsRepository : IOutOrderWmsRepository

{

    private readonly AppDbContext _context;

    public OutOrderWmsRepository(AppDbContext context)

    {

        _context = context;

    }

    public void CreateOutOrder(WmsOutOrder wmsOutOrder)

    {

        _context.Add(wmsOutOrder);  // 添加到 EF Core 跟踪

    }

  

    public async Task<bool> SaveAsync()

    {

        return (await _context.SaveChangesAsync() >= 0);  // 提交到数据库

    }

}

```

  

**职责：**

- 实现数据访问逻辑

- 使用 EF Core 操作数据库

- 执行 CRUD 操作

  

**注册位置：** `Startup.cs` 第 46 行

```csharp

services.AddTransient<IOutOrderWmsRepository, OutOrderWmsRepository>();

```

## 五、分层职责总结

  

| 层级 | 文件夹 | 职责 | 示例文件 |

|------|--------|------|---------|

| **Controller** | `Controllers/` | 接收请求、参数验证、响应返回 | `WmsMaterialOutController.cs` |

| **DTO** | `Dtos/` 或 `Controllers/*/Dto/` | 数据传输对象、API 接口契约 | `WmsOutOrderDto.cs` |

| **Profile** | `Profiles/` | AutoMapper 映射配置 | `WmsMaterialOutProfile.cs` |

| **Repository Interface** | `Services/` 或 `Controllers/*/Services/` | 数据访问接口定义 | `IOutOrderWmsRepository.cs` |

| **Repository Implementation** | `Services/` 或 `Controllers/*/Services/` | 数据访问实现 | `OutOrderWmsRepository.cs` |

| **Entity/Model** | `Models/` 或 `Controllers/*/Model/` | 数据库实体映射 | `WmsOutOrder.cs` |

| **DbContext** | `DataBase/` | EF Core 上下文、数据库连接 | `AppDbContext.cs` |

| **Configuration** | 根目录 | 启动配置、依赖注入 | `Startup.cs`, `Program.cs` |

## 六、关键设计模式

  

### 1. **依赖注入 (Dependency Injection)**

- Controller 通过构造函数注入 Repository 和 IMapper

- Startup.cs 中注册服务生命周期（Transient/Scoped/Singleton）

  

### 2. **仓储模式 (Repository Pattern)**

- 接口与实现分离

- 隐藏数据访问细节

- 便于单元测试

  

### 3. **DTO 模式 (Data Transfer Object)**

- 隔离 API 接口与数据库结构

- 灵活控制暴露的字段

- 支持不同场景的不同视图

  

### 4. **对象映射 (Object Mapping)**

- AutoMapper 自动转换对象

- 减少手动赋值代码

- 集中管理映射规则

## 七、常见问题排查

  

### 问题 1：AutoMapper 映射异常

**错误信息：** `Missing type map configuration or unsupported mapping`

  

**原因：**

- Profile 中未配置映射规则

- 命名空间不一致导致类型不匹配

  

**解决：**

- 在 Profile 中添加 `CreateMap<Source, Destination>()`

- 检查源类型和目标类型的命名空间是否一致

  

### 问题 2：依赖注入失败

**错误信息：** `Unable to resolve service for type 'IXXXRepository'`

  

**原因：**

- Startup.cs 中未注册服务

  

**解决：**

- 添加 `services.AddTransient<IXXXRepository, XXXRepository>()`

  

### 问题 3：数据库连接失败

**错误信息：** `Connection refused` 或 `Access denied`

  

**原因：**

- 连接字符串配置错误

- 数据库服务未启动

  

**解决：**

- 检查 `appsettings.json` 中的连接字符串

- 确认 MySQL 服务运行状态

## 八、最佳实践建议

  

1. **统一路由前缀**：所有 Controller 使用 `[Route("api/[controller]")]`

2. **统一命名空间**：避免 `Another` 和 `aother` 这种拼写不一致

3. **完善映射配置**：每个 DTO ↔ Entity 对都应有对应的 Profile

4. **添加异常处理**：使用全局异常中间件统一处理错误

5. **添加日志记录**：记录关键操作和异常信息

6. **使用异步方法**：Repository 方法全部使用 async/await

7. **添加输入验证**：使用 DataAnnotations 或 FluentValidation
