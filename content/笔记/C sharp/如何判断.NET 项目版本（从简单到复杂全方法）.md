# 如何判断.NET项目版本（从简单到复杂全方法）
**核心一句话**：最准确的方法是直接查看`.csproj`项目文件，其次是在Visual Studio中看项目属性。

---

## 一、最推荐：直接查看.csproj项目文件（100%准确）
用任何文本编辑器（记事本、VS Code、Notepad++）打开项目根目录下的`.csproj`文件，根据文件格式判断：

### 1. 现代SDK风格项目（.NET Core/.NET 5+）
**特征**：第一行有`<Project Sdk="Microsoft.NET.Sdk">`标签
**找版本**：搜索`<TargetFramework>`（单目标）或`<TargetFrameworks>`（多目标）标签

```xml
<!-- 单目标框架 -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <!-- 这就是版本：.NET 8.0 -->
    <TargetFramework>net8.0</TargetFramework>
  </PropertyGroup>
</Project>

<!-- 多目标框架（同时支持多个版本） -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <!-- 同时支持.NET Framework 4.8和.NET 6.0 -->
    <TargetFrameworks>net48;net6.0</TargetFrameworks>
  </PropertyGroup>
</Project>
```

### 2. 传统风格项目（.NET Framework）
**特征**：没有`Sdk`属性，有大量复杂的XML配置
**找版本**：搜索`<TargetFrameworkVersion>`标签

```xml
<Project ToolsVersion="15.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <PropertyGroup>
    <!-- 这就是版本：.NET Framework 4.7.2 -->
    <TargetFrameworkVersion>v4.7.2</TargetFrameworkVersion>
  </PropertyGroup>
</Project>
```

### 常见TFM（目标框架名字对象）对照表
| TFM值 | 对应.NET版本 |
|-------|--------------|
| net9.0 | .NET 9 |
| net8.0 | .NET 8 |
| net7.0 | .NET 7 |
| net6.0 | .NET 6（长期支持） |
| net5.0 | .NET 5 |
| netcoreapp3.1 | .NET Core 3.1（最后一个Core版本） |
| net48 | .NET Framework 4.8 |
| net472 | .NET Framework 4.7.2 |
| net461 | .NET Framework 4.6.1 |
| netstandard2.0 | .NET Standard 2.0（类库通用标准） |

## 二、最方便：在Visual Studio中查看（可视化）
1. 在**解决方案资源管理器**中右键点击你的项目
2. 选择**属性**（或直接按快捷键`Alt+Enter`）
3. 在打开的窗口中，切换到**应用程序**（或**常规**）选项卡
4. 找到**目标框架**下拉框，这里显示的就是项目的.NET版本

**示例**：
- 显示`.NET 8.0` → .NET 8项目
- 显示`.NET Framework 4.8` → .NET Framework 4.8项目

## 三、补充方法
### 1. 查看global.json文件（指定SDK版本）
如果项目根目录有`global.json`文件，它会指定编译时使用的.NET SDK版本：
```json
{
  "sdk": {
    "version": "8.0.100"
  }
}
```
这表示项目需要使用.NET SDK 8.0.100或更高版本来编译。

### 2. 命令行查看（适合VS Code或无VS环境）
打开项目根目录的命令行（PowerShell/CMD），运行：
```bash
# 查看项目的目标框架
dotnet list frameworks

# 查看本地已安装的所有.NET SDK版本
dotnet --list-sdks

# 查看本地已安装的所有.NET运行时版本
dotnet --list-runtimes
```

### 3. 查看已编译的.exe/.dll文件（无源代码时）
如果你只有编译好的程序，没有源代码：
1. 右键点击`.exe`或`.dll`文件 → 选择**属性**
2. 切换到**详细信息**选项卡
3. 查看**产品名称**或**文件版本**字段
   - 产品名称会显示类似`.NET 8.0`或`.NET Framework 4.8`
   - 文件版本会显示类似`8.0.0.0`或`4.8.4084.0`

**更准确的方法**：使用ILSpy或dnSpy等反编译工具打开程序集，查看引用的`mscorlib.dll`或`System.Runtime.dll`的版本号。

### 4. 代码方式获取运行时真实版本
在程序中运行这段代码，可以获取实际运行时的.NET版本：
```csharp
using System;
using System.Runtime.InteropServices;

class Program
{
    static void Main()
    {
        // 推荐：获取完整的运行时描述
        Console.WriteLine(RuntimeInformation.FrameworkDescription);
        // 输出示例：.NET 8.0.0
        // 输出示例：.NET Framework 4.8.4084.0
    }
}
```

## 四、快速判断流程
1. 先看项目根目录有没有`.csproj`文件 → 打开看`<TargetFramework>`或`<TargetFrameworkVersion>`
2. 如果有Visual Studio → 右键项目→属性→应用程序→目标框架
3. 如果只有编译好的程序 → 右键属性→详细信息，或用反编译工具
4. 如果想知道运行时实际用的版本 → 用`RuntimeInformation.FrameworkDescription`代码

---

## 五、常见误区
❌ 不要混淆**项目目标框架版本**和**本地安装的SDK版本**
- 项目目标框架版本：决定了你的代码可以使用哪些API
- 本地SDK版本：决定了你用哪个版本的编译器来编译代码

❌ 不要认为`.NET Standard`是一个运行时
- .NET Standard只是一个API规范，不是实际的运行时
- 一个.NET Standard类库可以被多个不同的.NET运行时引用
