你的这个设计思路本质上是：  
👉 **“项目说明（文档层）” 和 “代码文件（资源层）分离”**

这个方向是对的，但我要先直接指出一个关键问题：

> ❗如果你用两个完全独立的顶级目录（`projects/` 和 `project-files/`），在 Quartz 里**导航会割裂、URL 也不直观**。

所以我给你两个方案：一个是**你当前思路的可行实现**，一个是**更合理的结构（推荐）**。

---

# ✅ 方案一：按你当前思路实现（两个目录）

## 目录结构

```text
content/
├── projects/              ← 项目介绍（对外展示）
│   ├── project-a.md
│   └── project-b.md
│
├── project-files/         ← 代码 / 技术细节
│   ├── project-a/
│   │   ├── index.md
│   │   ├── api.md
│   │   └── db.md
│   └── project-b/
│       └── index.md
```

---

## 页面效果

|页面|URL|
|---|---|
|项目介绍|`/projects/project-a`|
|项目代码说明|`/project-files/project-a/`|

---

## 如何在“项目介绍”里跳转

在 `project-a.md` 写：

```md
# Project A

这是项目介绍...

## 技术细节
- [[project-files/project-a/index]]
- [[project-files/project-a/api]]
```

👉 Quartz 会自动转成链接

---

## 优点

- 结构清晰（逻辑分层）
    
- 代码内容不会污染项目介绍
    

---

## ❌ 缺点（很重要）

- URL 割裂：
    
    - `/projects/project-a`
        
    - `/project-files/project-a`
        
- 用户理解成本高
    
- Explorer 看起来像两个系统
    

---

# 🚀 方案二（强烈推荐）：**按项目聚合（更专业）**

👉 核心思想：

> **一个项目 = 一个文件夹（所有东西都放里面）**

---

## 推荐结构

```text
content/
├── projects/
│   ├── project-a/
│   │   ├── index.md        ← 项目介绍（主页面）
│   │   ├── api.md
│   │   ├── db.md
│   │   └── README.md
│   │
│   └── project-b/
│       ├── index.md
│       └── ...
```

---

## 页面表现

|页面|URL|
|---|---|
|项目首页|`/projects/project-a/`|
|API文档|`/projects/project-a/api`|

---

## index.md 示例（你要的“入口页”）

```md
---
title: Project A
---

# Project A

这是项目介绍

## 📦 模块
- [[api]]
- [[db]]

## 🧠 技术点
- Spring Boot
- Redis
```

👉 注意：  
这里可以直接写 `[[api]]`（同目录自动解析）

---

## 优点（非常关键）

### ✅ 1. URL 干净

```text
/projects/project-a/api
```

而不是：

```text
/project-files/project-a/api
```

---

### ✅ 2. SEO / 可读性更好

- Google 更喜欢这种结构
    
- 用户也更容易理解
    

---

### ✅ 3. Explorer 更自然

```
projects
 └── project-a
     ├── index
     ├── api
     └── db
```

---

### ✅ 4. 不需要手动跨目录跳转

内部链接天然简单

---

# 🧠 什么时候用你那种“两目录结构”？

只有一种情况推荐你这么做：

👉 **代码文件特别多 + 想隐藏**

例如：

```text
project-files/
  project-a/
    100+ 文件
```

这时候你可以：

- 用 `project-files` 做“技术仓库”
    
- 不在导航里展示（通过 Quartz 配置隐藏）
    

---

# ⚙️ 进阶：隐藏“代码目录”

在 `quartz.config.ts`：

你可以：

- 不在 Explorer 显示某些路径
    
- 或用 `draft: true`
    

---

# 🧩 折中方案（高级用法）

```text
content/
├── projects/
│   └── project-a/
│       ├── index.md
│       ├── docs/
│       │   ├── api.md
│       │   └── db.md
│       └── notes/
```

👉 分层但不分根目录

---

# ✅ 最终建议（直接结论）

如果你是：

### 👉 做博客 / 展示项目

✔ 用：**方案二（按项目聚合）**

---

### 👉 做技术知识库（很复杂）

✔ 可以考虑：

- 项目页 + 独立技术库（但要有链接策略）
    

---

# 总结一句话

> ❗Quartz 最合理的结构不是“按类型分目录”，而是：  
> 👉 **按实体（项目）分目录**
