Quartz 的页面不是由单个模板文件生成的，而是通过一个声明式的布局配置系统将多个组件组装成最终的 HTML 结构。理解这套布局系统是进行任何页面定制的前提。

## FullPageLayout 接口详解

Quartz 的完整页面布局由 `FullPageLayout` 接口定义，位于 `quartz/cfg.ts`：

```ts
export interface FullPageLayout {
  head: QuartzComponent           // <head> 区域，唯一组件
  header: QuartzComponent[]       // 页面顶部区域，组件数组
  beforeBody: QuartzComponent[]   // 正文内容之前，组件数组
  pageBody: QuartzComponent       // 页面主体内容，唯一组件（如 Content 页面）
  afterBody: QuartzComponent[]    // 正文内容之后，组件数组
  left: QuartzComponent[]         // 左侧边栏，组件数组
  right: QuartzComponent[]        // 右侧边栏，组件数组
  footer: QuartzComponent         // 页面底部，唯一组件
}
```

这七个区域对应了页面的 DOM 结构中的不同位置，它们的关系如下：

| 区域 | 位置 | 数量限制 | 典型组件 |
|------|------|---------|---------|
| `head` | `<html>` 内 `<body>` 之前 | 单个 | Head（meta、title、CSS） |
| `header` | 页面顶部 `<header>` 内 | 数组 | 搜索、暗色模式切换 |
| `beforeBody` | 正文区域上方 | 数组 | 面包屑、文章标题、元信息 |
| `pageBody` | 正文中部 | 单个 | Content（文章 HTML） |
| `afterBody` | 正文区域下方 | 数组 | 导航、评论、脚注 |
| `left` | 左侧边栏 | 数组 | Explorer、PageTitle、Search |
| `right` | 右侧边栏 | 数组 | Graph、TOC、Backlinks |
| `footer` | 页面底部 | 单个 | Footer |

## PageLayout 与 SharedLayout

在实际使用中，布局被拆分为两个更轻量的类型：

```ts
export type PageLayout = Pick<FullPageLayout, "beforeBody" | "left" | "right">
export type SharedLayout = Pick<FullPageLayout, "head" | "header" | "footer" | "afterBody">
```

`SharedLayout` 定义了**跨页面共享**的组件 -- 这些组件在每个页面都会出现。`PageLayout` 定义了**页面特定**的组件 -- 不同类型的页面（文章页、列表页、404 页）可以有不同的配置。

这种拆分的原因是：Quartz 有多种页面类型（Content 页面、Folder 页面、Tag 页面、404 页），每种页面共享相同的 head/footer，但 beforeBody/left/right 的内容不同。

## sharedPageComponents -- 共享组件配置

在 `quartz.layout.ts` 中，`sharedPageComponents` 定义了全局共享的布局：

```ts
import BackToTop from "./quartz/components/BackToTop"
import StarryBackground from "./quartz/components/StarryBackground"

export const sharedPageComponents: SharedLayout = {
  head: Component.Head(),
  header: [],
  afterBody: [
    StarryBackground(undefined),
    BackToTop(undefined),
  ],
  footer: Component.Footer(),
}
```

这里的设计值得注意：

- `head` 放置 `Component.Head()`，负责生成 `<meta>` 标签、`<title>`、CSS 引用等
- `header` 为空数组，说明本项目没有使用顶部导航栏（原版 Quartz 可能有 Search 按钮等）
- `afterBody` 中放置了 `StarryBackground` 和 `BackToTop` 两个自定义组件，它们会在每个页面的正文之后渲染
- `footer` 放置 `Component.Footer()`

BackToTop 和 StarryBackground 是直接导入的构造器函数（不在 Component 命名空间中），通过 `BackToTop(undefined)` 调用时传入空选项。

## defaultContentPageLayout -- 文章详情页布局

文章详情页是博客最核心的页面类型，其布局配置如下：

```ts
export const defaultContentPageLayout: PageLayout = {
  beforeBody: [
    Component.ConditionalRender({
      component: Component.Breadcrumbs(),
      condition: (page) => page.fileData.slug !== "index",
    }),
    Component.ArticleTitle(),
    Component.ContentMeta(),
    Component.TagList(),
  ],
  left: [
    Component.PageTitle(),
    Component.MobileOnly(Component.Spacer()),
    Component.Flex({
      components: [
        { Component: Component.Search(), grow: true },
        { Component: Component.Darkmode() },
        { Component: Component.ReaderMode() },
      ],
    }),
    Component.Explorer(),
  ],
  right: [
    Component.Graph(),
    Component.DesktopOnly(Component.TableOfContents()),
    Component.Backlinks(),
  ],
  afterBody: [
    Component.PrevNextNav(),
    BackToTop(undefined),
  ],
}
```

各个区域的组件排列有其设计逻辑：

- **beforeBody**：面包屑（首页不显示） -> 文章标题 -> 元信息（日期、阅读时间） -> 标签列表
- **left**：页面标题 -> 移动端留白 -> 搜索/暗色模式/阅读模式（Flex 横向排列） -> 文件树
- **right**：关系图谱 -> 桌面端 TOC（移动端隐藏） -> 反向链接

注意 `afterBody` 同时出现在 `SharedLayout` 和 `PageLayout` 中。构建系统会将两者合并，`SharedLayout` 的 `afterBody` 在前，`PageLayout` 的在后。

## defaultListPageLayout -- 列表页布局

列表页用于文件夹页面和标签页面，展示一组文章的摘要：

```ts
export const defaultListPageLayout: PageLayout = {
  beforeBody: [
    Component.Breadcrumbs(),
    Component.ArticleTitle(),
    Component.ContentMeta(),
  ],
  left: [
    Component.PageTitle(),
    Component.MobileOnly(Component.Spacer()),
    Component.Flex({
      components: [
        { Component: Component.Search(), grow: true },
        { Component: Component.Darkmode() },
      ],
    }),
    Component.Explorer(),
  ],
  right: [],
}
```

与文章详情页相比，列表页的差异在于：
- `beforeBody` 中没有 `ConditionalRender` 包裹面包屑（列表页始终显示面包屑），没有 `TagList`
- `right` 为空（列表页不需要 TOC、Graph、Backlinks）
- `left` 的 Flex 组件中少了 `ReaderMode`（阅读模式对列表页无意义）

## 组件排列顺序对渲染的影响

在 `beforeBody`、`left`、`right` 等数组中，组件的排列顺序直接决定了它们在 DOM 中的渲染顺序。构建系统按照数组索引依次调用每个组件的渲染函数，生成的 HTML 元素按相同顺序排列。

例如，`beforeBody` 数组中的 `[Breadcrumbs, ArticleTitle, ContentMeta, TagList]` 会在页面上按从上到下的顺序依次显示。如果你想调整文章标题和元信息的位置，只需要交换它们在数组中的顺序。

## renderPage.tsx -- 布局组装引擎

`quartz/components/renderPage.tsx` 是将布局配置转换为最终 HTML 的核心函数。它定义了 `RenderComponents` 接口并实现了 `renderPage` 函数：

```ts
interface RenderComponents {
  head: QuartzComponent
  header: QuartzComponent[]
  beforeBody: QuartzComponent[]
  pageBody: QuartzComponent
  afterBody: QuartzComponent[]
  left: QuartzComponent[]
  right: QuartzComponent[]
  footer: QuartzComponent
}
```

`renderPage` 函数接收布局配置，将所有组件组装成完整的 HTML 文档。其核心 JSX 结构如下：

```tsx
const doc = (
  <html lang={lang} dir={direction}>
    <Head {...componentData} />
    <body data-slug={slug}>
      <div id="quartz-root" class="page">
        <Body {...componentData}>
          <div class="left sidebar">
            {left.map((BodyComponent) => (
              <BodyComponent {...componentData} />
            ))}
          </div>
          <div class="center">
            <div class="page-header">
              <Header {...componentData}>
                {header.map((HeaderComponent) => (
                  <HeaderComponent {...componentData} />
                ))}
              </Header>
              <div class="popover-hint">
                {beforeBody.map((BodyComponent) => (
                  <BodyComponent {...componentData} />
                ))}
              </div>
            </div>
            <Content {...componentData} />
            <hr />
            <div class="page-footer">
              {afterBody.map((BodyComponent) => (
                <BodyComponent {...componentData} />
              ))}
            </div>
          </div>
          <div class="right sidebar">
            {right.map((BodyComponent) => (
              <BodyComponent {...componentData} />
            ))}
          </div>
          <Footer {...componentData} />
        </Body>
      </div>
    </body>
    {/* afterDOMReady scripts */}
  </html>
)
```

几个关键设计点：

1. 所有组件都通过 `{...componentData}` 接收相同的 props，每个组件自行解构所需字段
2. `Header` 和 `Body` 组件不在布局配置中定义，它们是 renderPage 内部创建的固定包装器（通过 `HeaderConstructor()` 和 `BodyConstructor()` 实例化）
3. `page-header` 区域包含 `Header` 组件和 `beforeBody` 组件，用 `popover-hint` div 包裹
4. `<hr />` 分隔线将正文内容（Content）和页脚区域（afterBody）分开
5. `afterDOMReady` 脚本被放置在 `<body>` 之后

## 页面 DOM 结构树

根据 renderPage.tsx 的 JSX 结构，最终生成的 HTML 页面结构如下：

```html
<!DOCTYPE html>
<html lang="zh-CN" dir="ltr">
  <head>
    <!-- Head 组件生成的 meta、title、CSS -->
  </head>
  <body data-slug="/post/hello-world">
    <div id="quartz-root" class="page">
      <div id="quartz-body">
        <!-- 左侧边栏 -->
        <div class="left sidebar">
          <!-- PageTitle -->
          <!-- MobileOnly(Spacer) -->
          <!-- Flex(Search, Darkmode, ReaderMode) -->
          <!-- Explorer -->
        </div>

        <!-- 中央内容区 -->
        <div class="center">
          <div class="page-header">
            <!-- Header 组件 -->
            <div class="popover-hint">
              <!-- beforeBody: Breadcrumbs, ArticleTitle, ContentMeta, TagList -->
            </div>
          </div>

          <!-- pageBody: Content（文章正文 HTML） -->
          <article class="popover-hint">
            ...
          </article>

          <hr />

          <div class="page-footer">
            <!-- afterBody: PrevNextNav, BackToTop, StarryBackground 等 -->
          </div>
        </div>

        <!-- 右侧边栏 -->
        <div class="right sidebar">
          <!-- Graph -->
          <!-- DesktopOnly(TableOfContents) -->
          <!-- Backlinks -->
        </div>

        <!-- Footer -->
      </div>
    </div>

    <!-- afterDOMReady 脚本 -->
    <script type="module" src="postscript.js"></script>
  </body>
</html>
```

这个结构说明了一个重要的渲染原理：Quartz 是**纯服务端渲染**，所有组件在构建时就被执行并转换为静态 HTML。客户端脚本（如 Explorer 的交互、SPA 导航）只是增强体验的附加层，页面的核心内容在 JavaScript 加载前就已经完整呈现。
