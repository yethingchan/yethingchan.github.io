Quartz 的组件系统是整个博客渲染架构的核心。每一个可见的 UI 元素 -- 侧边栏的文件树、搜索框、文章标题、图谱视图 -- 都是一个 QuartzComponent。本节将深入剖析这个组件系统的设计思路和实现细节。

## QuartzComponent 与 QuartzComponentProps

在 Quartz 中，组件本质上是一个 Preact 函数组件，但它扩展了三个额外的静态属性来支持样式和脚本的注入。核心类型定义位于 `quartz/components/types.ts`：

```ts
export type QuartzComponentProps = {
  ctx: BuildCtx
  externalResources: StaticResources
  fileData: QuartzPluginData
  cfg: GlobalConfiguration
  children: (QuartzComponent | JSX.Element)[]
  tree: Node
  allFiles: QuartzPluginData[]
  displayClass?: "mobile-only" | "desktop-only"
} & JSX.IntrinsicAttributes & {
    [key: string]: any
  }

export type QuartzComponent = ComponentType<QuartzComponentProps> & {
  css?: StringResource
  beforeDOMLoaded?: StringResource
  afterDOMLoaded?: StringResource
}

export type QuartzComponentConstructor<Options extends object | undefined = undefined> = (
  opts: Options,
) => QuartzComponent
```

`QuartzComponentProps` 是组件接收的全部参数，各字段的职责如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ctx` | `BuildCtx` | 构建上下文，包含命令行参数、输出目录等构建期信息 |
| `externalResources` | `StaticResources` | 当前页面加载的外部 CSS/JS 资源引用 |
| `fileData` | `QuartzPluginData` | 当前页面的数据，包含 frontmatter、slug、HTML AST 等 |
| `cfg` | `GlobalConfiguration` | 全局配置对象（站点标题、主题、语言等） |
| `tree` | `Node` | 当前页面的 HAST（HTML 抽象语法树），即 Markdown 渲染后的 DOM 树 |
| `allFiles` | `QuartzPluginData[]` | 构建中所有已处理的文件列表，用于跨文件查询 |
| `displayClass` | `string?` | 条件渲染时传入的 CSS 类名，如 `"mobile-only"` 或 `"desktop-only"` |

`QuartzComponent` 类型不仅是一个函数组件，还附加了三个可选的静态属性：

- `css`：组件的样式内容，会被注入到页面的 `<style>` 标签中
- `beforeDOMLoaded`：在 DOM 加载前执行的脚本（如搜索索引初始化）
- `afterDOMLoaded`：在 DOM 加载后执行的脚本（如交互逻辑、SPA 导航监听）

## QuartzComponentConstructor 工厂模式

如果你观察项目中组件的导出方式，会发现几乎所有的组件都使用了工厂函数而非直接导出：

```ts
// quartz/components/ArticleTitle.tsx
export default (() => ArticleTitle) satisfies QuartzComponentConstructor
```

```ts
// quartz/components/Explorer.tsx
export default ((userOpts?: Partial<Options>) => {
  const opts: Options = { ...defaultOptions, ...userOpts }
  const Explorer: QuartzComponent = ({ cfg, displayClass }: QuartzComponentProps) => {
    // ...
  }
  Explorer.css = style
  Explorer.afterDOMLoaded = concatenateResources(script, ...)
  return Explorer
}) satisfies QuartzComponentConstructor
```

工厂模式的优势在于 **配置化**。通过构造器函数，使用方可以传入自定义选项（如 Explorer 的排序策略、折叠行为），而组件内部将这些选项与默认值合并后再返回实际的组件实例。这种模式让同一个组件在不同页面可以有不同的配置，同时保持了接口的一致性。

注意看 `QuartzComponentConstructor` 的泛型定义 `Options extends object | undefined = undefined`。如果组件不需要配置选项，可以省略泛型参数（如 ArticleTitle）；如果需要（如 Explorer），则通过泛型约束确保类型安全。

## 组件注册流程

Quartz 的组件注册分为两步：**导出** 和 **布局配置**。

**第一步：在 `quartz/components/index.ts` 中导出**

这个文件是组件的注册中心，所有需要在布局中使用的组件都必须在这里导出：

```ts
// quartz/components/index.ts
import ArticleTitle from "./ArticleTitle"
import Explorer from "./Explorer"
import Search from "./Search"
import PrevNextNav from "./PrevNextNav"
// ...

export {
  ArticleTitle,
  Explorer,
  Search,
  PrevNextNav,
  // ...
}
```

注意这里导出的是**构造器**而非组件实例。当你调用 `Component.ArticleTitle()` 时，实际上是在调用构造器函数，返回一个配置好的 QuartzComponent 实例。

**第二步：在 `quartz.layout.ts` 中配置布局**

```ts
import * as Component from "./quartz/components"

export const defaultContentPageLayout: PageLayout = {
  beforeBody: [
    Component.ArticleTitle(),
    Component.ContentMeta(),
  ],
  left: [
    Component.Explorer(),
  ],
  right: [
    Component.Graph(),
  ],
  afterBody: [
    Component.PrevNextNav(),
  ],
}
```

## 组件样式注入机制

Quartz 组件的样式注入使用 SCSS 文件配合静态属性赋值。标准模式如下：

```ts
import style from "./styles/explorer.scss"

const Explorer: QuartzComponent = (props) => {
  return <div class="explorer">...</div>
}

Explorer.css = style
```

SCSS 文件通过 Vite 的 CSS 模块能力被导入为字符串，然后赋值给组件的 `css` 属性。构建系统会在 `renderPage.tsx` 中收集所有组件的样式，统一注入到最终 HTML 的 `<head>` 中。

部分组件选择直接内联样式字符串，这种方式适用于样式较短的组件：

```ts
ArticleTitle.css = `
.article-title {
  margin: 2rem 0 0 0;
}
`
```

样式文件统一放在 `quartz/components/styles/` 目录下，命名与组件同名（如 `explorer.scss`、`search.scss`）。SCSS 文件可以使用 `@use "../../styles/variables.scss" as *` 引入全局变量。

## 条件渲染组件

Quartz 提供了三个包装组件来实现条件渲染，它们本身不渲染任何可见内容，而是根据条件决定是否渲染被包装的子组件。

**ConditionalRender** -- 根据自定义条件渲染：

```ts
Component.ConditionalRender({
  component: Component.Breadcrumbs(),
  condition: (page) => page.fileData.slug !== "index",
})
```

只有当 `condition` 函数返回 `true` 时，才会渲染内部组件。 ConditionalRender 会透传子组件的 css、beforeDOMLoaded、afterDOMLoaded 属性。

**DesktopOnly / MobileOnly** -- 根据屏幕尺寸渲染：

```ts
Component.DesktopOnly(Component.TableOfContents())
Component.MobileOnly(Component.Spacer())
```

这两个组件通过给子组件注入 `displayClass` 属性（`"desktop-only"` 或 `"mobile-only"`）来控制显示。Quartz 的全局 CSS 会根据 `@media` 查询隐藏对应类名的元素。

注意这三个包装组件都接受 **组件实例**（而非构造器调用）作为参数。这意味着你需要先调用构造器：`Component.DesktopOnly(Component.TableOfContents())`，其中内层是实例化的组件，外层是条件包装。

## 组件数据获取

Quartz 组件有三种主要的数据来源：

**1. fileData -- 当前页面数据**

每个组件都能访问当前渲染页面的完整信息，包括标题、描述、日期、标签等 frontmatter 字段，以及渲染后的 HTML 树。

```ts
const PrevNextNav: QuartzComponent = ({ fileData, allFiles, cfg }: QuartzComponentProps) => {
  const currentSlug = simplifySlug(fileData.slug!)
  // 使用 fileData 获取当前页面的 slug
}
```

**2. allFiles -- 全站文件索引**

这是一个包含所有已处理文件的数组，适用于需要跨页面查询的场景，如文件树构建、上一篇/下一篇导航、相关文章推荐等。

```ts
function getFlatFileList(allFiles: QuartzPluginData[]): QuartzPluginData[] {
  return allFiles
    .filter((file) => !isFolderPath(file.slug!))
    .sort((a, b) => a.slug!.localeCompare(b.slug!))
}
```

**3. cfg -- 全局配置**

通过 `cfg` 可以获取 `quartz.config.ts` 中定义的配置项，最常用的是 `cfg.locale`（语言设置）和 `cfg.pageTitle`（站点标题）。国际化文本的获取依赖此参数：

```ts
const searchPlaceholder = i18n(cfg.locale).components.search.searchBarPlaceholder
```

## 完整示例：ArticleTitle

以 ArticleTitle 组件为例，展示一个最简单的 Quartz 组件的完整结构。源码位于 `quartz/components/ArticleTitle.tsx`：

```ts
import { QuartzComponent, QuartzComponentConstructor, QuartzComponentProps } from "./types"
import { classNames } from "../util/lang"

const ArticleTitle: QuartzComponent = ({
  fileData,
  displayClass,
}: QuartzComponentProps) => {
  const title = fileData.frontmatter?.title
  const cover = fileData.frontmatter?.cover

  if (title) {
    return (
      <>
        {cover && (
          <div class="article-cover">
            <img src={String(cover)} alt={title} />
          </div>
        )}
        <h1 class={classNames(displayClass, "article-title")}>
          {title}
        </h1>
      </>
    )
  } else {
    return null
  }
}

ArticleTitle.css = `
.article-title {
  margin: 2rem 0 0 0;
}
`

export default (() => ArticleTitle) satisfies QuartzComponentConstructor
```

这个组件展示了 Quartz 组件的几个核心特征：

1. **解构 props**：从 `QuartzComponentProps` 中只提取需要的字段（`fileData`、`displayClass`），忽略其余
2. **条件渲染**：如果没有 title 则返回 null，不渲染任何内容
3. **CSS 类名合并**：使用 `classNames()` 工具函数将 `displayClass`（可能为 undefined）与组件自有类名合并
4. **样式注入**：通过 `ArticleTitle.css` 赋值内联样式字符串
5. **工厂导出**：虽然不需要配置选项，仍使用 `(() => ArticleTitle) satisfies QuartzComponentConstructor` 保持接口统一
6. **frontmatter 数据**：从 `fileData.frontmatter` 中读取 title 和 cover 字段

这种简洁的模式在 Quartz 的内置组件中被广泛使用，是开发自定义组件的最佳起点。
