本节以 PrevNextNav 组件为例，从零开始展示开发一个完整 Quartz 组件的全流程。这个组件在每篇文章底部提供"上一章/下一章"的线性导航，帮助读者按顺序阅读博客内容。

## 第 1 步：需求分析

我们要实现的组件需要：

- 在每篇文章底部显示"上一章"和"下一章"两个导航链接
- 链接指向全局排序中相邻的文章
- 当当前文章是第一篇或最后一篇时，显示禁用状态提示
- 支持多语言（中文显示"上一章/下一章"，英文显示"Previous/Next"）
- 移动端适配为垂直堆叠布局
- 提供可配置选项（自定义边界提示文本）

## 第 2 步：创建组件文件

在 `quartz/components/` 目录下创建 `PrevNextNav.tsx`，使用 QuartzComponentConstructor 工厂模式：

```ts
import { QuartzComponent, QuartzComponentConstructor, QuartzComponentProps } from "./types"
import { resolveRelative, simplifySlug, isFolderPath } from "../util/path"
import { QuartzPluginData } from "../plugins/vfile"
import { i18n } from "../i18n"

interface PrevNextNavOptions {
  /** 当没有上一篇文章时显示的文本 */
  noPrevText?: string
  /** 当没有下一篇文章时显示的文本 */
  noNextText?: string
}

const defaultOptions: PrevNextNavOptions = {}

export default ((opts?: Partial<PrevNextNavOptions>) => {
  const options: PrevNextNavOptions = { ...defaultOptions, ...opts }
  // 组件实现...
  return PrevNextNav
}) satisfies QuartzComponentConstructor
```

设计考虑：使用 `Partial<PrevNextNavOptions>` 作为参数类型，允许用户只覆盖部分选项。内部通过展开运算符将默认值和用户选项合并，确保未指定的选项使用默认值。`satisfies QuartzComponentConstructor` 确保返回值符合 Quartz 的组件构造器接口。

## 第 3 步：数据获取逻辑

组件需要从 `allFiles` 中获取所有文件，排序后找到当前文章的前后文章：

```ts
export default ((opts?: Partial<PrevNextNavOptions>) => {
  const options: PrevNextNavOptions = { ...defaultOptions, ...opts }

  /**
   * 获取一个扁平化、排序后的文件列表
   * 排除 index 文件和文件夹页面
   */
  function getFlatFileList(allFiles: QuartzPluginData[]): QuartzPluginData[] {
    return allFiles
      .filter((file) => {
        if (!file.slug) return false
        // 跳过 index 文件和文件夹页面
        if (isFolderPath(file.slug!)) return false
        return true
      })
      .sort((a, b) => a.slug!.localeCompare(b.slug!))
  }

  const PrevNextNav: QuartzComponent = ({
    fileData,
    allFiles,
    cfg,
  }: QuartzComponentProps) => {
    const currentSlug = simplifySlug(fileData.slug!)
    const flatList = getFlatFileList(allFiles)
    const currentIndex = flatList.findIndex(
      (f) => simplifySlug(f.slug!) === currentSlug
    )

    const prevFile = currentIndex > 0 ? flatList[currentIndex - 1] : null
    const nextFile =
      currentIndex >= 0 && currentIndex < flatList.length - 1
        ? flatList[currentIndex + 1]
        : null

    // 渲染逻辑...
  }
  return PrevNextNav
}) satisfies QuartzComponentConstructor
```

设计考虑：

- `simplifySlug` 去除 slug 末尾的 `index` 后缀，确保路径比较的一致性
- `isFolderPath` 判断 slug 是否为文件夹路径（如 `/tags/`），排除这类特殊页面
- `localeCompare` 按字典序排序，这与文件系统的字母排序一致，确保导航顺序可预期
- `findIndex` 而非 `find` 获取当前文章在列表中的位置，便于通过 `currentIndex - 1` 和 `currentIndex + 1` 获取相邻文章

## 第 4 步：JSX 渲染

使用条件渲染生成导航链接或禁用状态：

```tsx
const PrevNextNav: QuartzComponent = ({
  fileData,
  allFiles,
  cfg,
}: QuartzComponentProps) => {
  const currentSlug = simplifySlug(fileData.slug!)
  const flatList = getFlatFileList(allFiles)
  const currentIndex = flatList.findIndex(
    (f) => simplifySlug(f.slug!) === currentSlug
  )

  const prevFile = currentIndex > 0 ? flatList[currentIndex - 1] : null
  const nextFile =
    currentIndex >= 0 && currentIndex < flatList.length - 1
      ? flatList[currentIndex + 1]
      : null

  const prevTitle = prevFile?.frontmatter?.title
  const nextTitle = nextFile?.frontmatter?.title

  return (
    <nav class="prev-next-nav">
      {prevFile ? (
        <a href={resolveRelative(fileData.slug!, prevFile.slug!)}
           class="prev-next-link prev">
          <span class="prev-next-direction">
            {i18n(cfg.locale).components.prevNextNav.previous ?? "上一章"}
          </span>
          <span class="prev-next-title">{prevTitle}</span>
        </a>
      ) : (
        <div class="prev-next-link prev disabled">
          <span class="prev-next-direction">
            {i18n(cfg.locale).components.prevNextNav.previous ?? "上一章"}
          </span>
          <span class="prev-next-title">
            {options.noPrevText ??
              (i18n(cfg.locale).components.prevNextNav.noPrev ?? "已是第一章")}
          </span>
        </div>
      )}
      {nextFile ? (
        <a href={resolveRelative(fileData.slug!, nextFile.slug!)}
           class="prev-next-link next">
          <span class="prev-next-direction">
            {i18n(cfg.locale).components.prevNextNav.next ?? "下一章"}
          </span>
          <span class="prev-next-title">{nextTitle}</span>
        </a>
      ) : (
        <div class="prev-next-link next disabled">
          <span class="prev-next-direction">
            {i18n(cfg.locale).components.prevNextNav.next ?? "下一章"}
          </span>
          <span class="prev-next-title">
            {options.noNextText ??
              (i18n(cfg.locale).components.prevNextNav.noNext ?? "已是最后一章")}
          </span>
        </div>
      )}
    </nav>
  )
}
```

设计考虑：

- 使用 `<nav>` 语义标签，提升可访问性
- `resolveRelative` 生成相对路径，确保 SPA 导航正常工作
- `??` 运算符提供多层回退：自定义选项 > i18n 翻译 > 硬编码中文默认值
- 有链接时使用 `<a>`，无链接时使用 `<div>`，避免生成无效的 `href="#"`

## 第 5 步：创建 SCSS 样式文件

在 `quartz/components/styles/prevNextNav.scss` 中创建样式：

```scss
@use "../../styles/variables.scss" as *;

.prev-next-nav {

      font-size: 0.75rem;
      text-transform: uppercase;
      letter-spacing: 0.05em;
      color: var(--gray);
      font-weight: $semiBoldWeight;

      font-size: 0.95rem;
      font-weight: $normalWeight;
      line-height: 1.4;
      color: var(--dark);
      overflow: hidden;
      text-overflow: ellipsis;

      border-color: var(--secondary);
      background-color: var(--highlight);
```

设计考虑：

- 使用 `@use` 引入全局 SCSS 变量（如 `$semiBoldWeight`、`$normalWeight`）
- `flex: 1 1 50%` 让两个链接平分宽度
- `-webkit-line-clamp: 2` 限制标题最多显示两行，避免长标题破坏布局
- 禁用状态使用虚线边框 + 降低透明度 + 斜体文字，与可用链接形成明确区分

然后在组件文件中引入样式：

```ts
import style from "./styles/prevNextNav.scss"

// ... 在 return PrevNextNav 之前
PrevNextNav.css = style
```

## 第 6 步：移动端适配

在 SCSS 文件末尾添加移动端媒体查询：

```scss
@media all and ($mobile) {
  .prev-next-nav {
    flex-direction: column;    // 从横向变为纵向
    gap: 0.4rem;
    margin: 1rem 0 0.5rem 0;

    .prev-next-link {
      padding: 0.75rem 1rem;
      border-radius: 0.6rem;

      &.prev, &.next {
        text-align: left;      // 移动端统一左对齐
      }

      // 添加方向箭头提示
      &.prev::before { content: "\2190"; margin-right: 0.35rem; opacity: 0.5; }
      &.next::before { content: "\2192"; margin-right: 0.35rem; opacity: 0.5; }

      .prev-next-direction { font-size: 0.68rem; }
      .prev-next-title {
        font-size: 0.88rem;
        line-height: 1.35;
        -webkit-line-clamp: 1;  // 移动端只显示一行
      }
    }
  }
}
```

设计考虑：`$mobile` 是 Quartz 全局定义的断点变量，确保与整个博客的响应式行为一致。移动端使用 `flex-direction: column` 垂直堆叠，添加 Unicode 箭头字符作为方向提示。

## 第 7 步：i18n 国际化

### 7.1 在类型定义中声明新字段

在 `quartz/i18n/locales/definition.ts` 的 `Translation` 接口中添加：

```ts
components: {
  // ... 其他组件
  prevNextNav: {
    previous: string
    next: string
    noPrev: string
    noNext: string
  }
}
```

### 7.2 在各语言文件中添加翻译

以中文 `zh-CN.ts` 为例：

```ts
prevNextNav: {
  previous: "上一章",
  next: "下一章",
  noPrev: "已是第一章",
  noNext: "已是最后一章",
},
```

英文 `en-US.ts`：

```ts
prevNextNav: {
  previous: "Previous",
  next: "Next",
  noPrev: "First chapter",
  noNext: "Last chapter",
},
```

所有支持的语言文件都必须添加 `prevNextNav` 字段，否则 TypeScript 编译会报错（因为各语言文件使用 `satisfies Translation` 约束）。这是 Quartz 国际化系统的编译期安全保障。

## 第 8 步：注册组件

### 8.1 在 index.ts 中导出

在 `quartz/components/index.ts` 中添加导入和导出：

```ts
import PrevNextNav from "./PrevNextNav"

export {
  // ... 其他导出
  PrevNextNav,
}
```

### 8.2 在 quartz.layout.ts 中配置

将组件添加到文章详情页的 `afterBody` 区域：

```ts
export const defaultContentPageLayout: PageLayout = {
  beforeBody: [/* ... */],
  left: [/* ... */],
  right: [/* ... */],
  afterBody: [
    Component.PrevNextNav(),   // 添加在 afterBody 开头
    BackToTop(undefined),
  ],
}
```

设计考虑：放在 `afterBody` 数组中，意味着导航链接会渲染在文章正文之后、页面底部。在数组中的位置决定了 DOM 中的渲染位置 -- 放在最前面使其紧跟在文章正文下方，符合阅读习惯。

## 第 9 步：构建验证

完成以上所有步骤后，运行构建命令验证：

```bash
npx quartz build
```

构建成功后，启动预览服务器：

```bash
npx quartz build --serve
```

验证清单：

- 打开任意文章页面，检查底部是否出现导航卡片
- 点击"上一章"/"下一章"链接，确认跳转到正确的相邻文章
- 打开第一篇文章，确认"上一章"显示为禁用状态
- 打开最后一篇文章，确认"下一章"显示为禁用状态
- 使用浏览器的响应式模式切换到移动端视图，确认导航变为垂直堆叠
- 如果配置了多语言（如 `locale: "en-US"`），确认显示英文文本

如果构建报 TypeScript 错误，最常见的原因是忘记在某个语言文件中添加 `prevNextNav` 字段 -- 检查所有 `quartz/i18n/locales/*.ts` 文件是否都已更新。
