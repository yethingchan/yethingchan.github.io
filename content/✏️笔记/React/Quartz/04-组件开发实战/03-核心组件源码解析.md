本节选取五个最具代表性的 Quartz 组件进行源码级别的深度分析，帮助你理解不同复杂度的组件在 Quartz 中是如何实现的。

## 1. Explorer.tsx -- 最复杂的组件之一

Explorer 组件实现了侧边栏的文件树浏览器，是 Quartz 中架构最复杂的组件。它涉及服务端模板渲染、客户端动态 DOM 构建、Trie 数据结构、状态持久化等多个技术点。

### 服务端渲染：模板 + 数据传递

Explorer 的 JSX 部分（服务端渲染）不生成实际的文件列表，而是生成 DOM 模板和配置数据：

```tsx
const Explorer: QuartzComponent = ({ cfg, displayClass }: QuartzComponentProps) => {
  const id = `explorer-${numExplorers++}`
  return (
    <div
      class={classNames(displayClass, "explorer")}
      data-behavior={opts.folderClickBehavior}
      data-collapsed={opts.folderDefaultState}
      data-savestate={opts.useSavedState}
      data-data-fns={JSON.stringify({
        order: opts.order,
        sortFn: opts.sortFn.toString(),
        filterFn: opts.filterFn.toString(),
        mapFn: opts.mapFn.toString(),
      })}
    >
      {/* 移动端切换按钮 */}
      <button class="explorer-toggle mobile-explorer hide-until-loaded"
              data-mobile={true} aria-controls={id}>...</button>

      {/* 桌面端头部 */}
      <div class="explorer-header">
        <button class="title-button explorer-toggle desktop-explorer">...</button>
        <button id="explorer-collapse-all">⤢</button>
      </div>

      {/* 文件列表容器（初始为空） */}
      <div id={id} class="explorer-content" aria-expanded={false} role="group">
        <OverflowList class="explorer-ul" />
      </div>

      {/* HTML 模板 */}
      <template id="template-file">
        <li><a href="#"></a></li>
      </template>
      <template id="template-folder">
        <li>
          <div class="folder-container">
            <svg class="folder-icon">...</svg>
            <div><button class="folder-button"><span class="folder-title"></span></button></div>
          </div>
          <div class="folder-outer"><ul class="content"></ul></div>
        </li>
      </template>
    </div>
  )
}
```

设计要点：配置数据（排序函数、过滤函数等）通过 `data-data-fns` 以 JSON 字符串形式序列化到 DOM 属性上。由于函数无法直接序列化为 JSON，这里使用 `.toString()` 将函数转为源码字符串，客户端再通过 `new Function("return " + str)()` 重建函数。

### 客户端脚本：Trie 构建与 DOM 生成

`quartz/components/scripts/explorer.inline.ts` 中的 `setupExplorer` 函数负责客户端的逻辑：

```ts
async function setupExplorer(currentSlug: FullSlug) {
  // 1. 从 DOM 属性反序列化配置
  const dataFns = JSON.parse(explorer.dataset.dataFns || "{}")
  const opts: ParsedOptions = {
    folderClickBehavior: explorer.dataset.behavior || "collapse",
    folderDefaultState: explorer.dataset.collapsed || "collapsed",
    useSavedState: explorer.dataset.savestate === "true",
    sortFn: new Function("return " + (dataFns.sortFn || "undefined"))(),
    filterFn: new Function("return " + (dataFns.filterFn || "undefined"))(),
    mapFn: new Function("return " + (dataFns.mapFn || "undefined"))(),
  }

  // 2. 从 localStorage 恢复折叠状态
  const storageTree = localStorage.getItem("fileTree")
  const serializedExplorerState = storageTree && opts.useSavedState
    ? JSON.parse(storageTree) : []

  // 3. 从 contentIndex.json 构建 Trie 树
  const data = await fetchData
  const entries = [...Object.entries(data)] as [FullSlug, ContentDetails][]
  const trie = FileTrieNode.fromEntries(entries)

  // 4. 按配置的顺序应用 filter → map → sort
  for (const fn of opts.order) {
    switch (fn) {
      case "filter": if (opts.filterFn) trie.filter(opts.filterFn); break
      case "map":    if (opts.mapFn) trie.map(opts.mapFn); break
      case "sort":   if (opts.sortFn) trie.sort(opts.sortFn); break
    }
  }

  // 5. 递归创建 DOM 节点
  const fragment = document.createDocumentFragment()
  for (const child of trie.children) {
    const node = child.isFolder
      ? createFolderNode(currentSlug, child, opts)
      : createFileNode(currentSlug, child)
    fragment.appendChild(node)
  }
  explorerUl.insertBefore(fragment, explorerUl.firstChild)
}
```

### 折叠状态的持久化

当用户点击文件夹折叠/展开时，状态会被保存到 localStorage：

```ts
function toggleFolder(evt: MouseEvent) {
  const childFolderContainer = folderContainer.nextElementSibling
  childFolderContainer.classList.toggle("open")
  const isCollapsed = !childFolderContainer.classList.contains("open")
  setFolderState(childFolderContainer, isCollapsed)

  // 更新状态并写入 localStorage
  currentExplorerState.push({
    path: folderContainer.dataset.folderpath,
    collapsed: isCollapsed,
  })
  localStorage.setItem("fileTree", JSON.stringify(currentExplorerState))
}
```

### 移动端全屏覆盖

在移动端，Explorer 以全屏覆盖方式显示。当点击汉堡按钮时：

```ts
function toggleExplorer(this: HTMLElement) {
  const nearestExplorer = this.closest(".explorer")
  const explorerCollapsed = nearestExplorer.classList.toggle("collapsed")
  if (!explorerCollapsed) {
    document.documentElement.classList.add("mobile-no-scroll")
  } else {
    document.documentElement.classList.remove("mobile-no-scroll")
  }
}
```

`mobile-no-scroll` 类通过 CSS 禁止 `<html>` 的滚动，使 Explorer 获得独占的滚动区域。SPA 导航后，移动端会自动折叠 Explorer 并恢复滚动。

## 2. BackToTop.tsx -- 多功能浮动组件

BackToTop 是本项目中一个高度自定义的组件，它将多个浮动功能整合到一个组件中。源码位于 `quartz/components/BackToTop.tsx`。

### 扇形进度按钮

组件渲染了一个带进度的圆形按钮，使用 CSS `conic-gradient` 实现扇形进度效果：

```tsx
<button id="scroll-toggle" aria-label="Scroll Toggle">
  <div className="progress-ring"></div>
  <span id="scroll-icon">▲</span>
</button>
```

客户端脚本通过 CSS 变量 `--progress` 控制进度：

```js
const progress = Math.min(scrollTop / Math.max(scrollHeight - clientHeight, 1), 1)
scrollBtn.style.setProperty("--progress", progress.toString())
```

对应的 CSS 使用 `conic-gradient` 将 `--progress` 变量渲染为扇形进度条（样式定义在自定义 CSS 中）。

### 浮动时钟

```tsx
<div id="floating-clock" role="timer" aria-label="当前时间">--:--</div>
```

时钟每分钟更新一次：

```js
const updateClock = () => {
  const now = new Date()
  const hh = String(now.getHours()).padStart(2, "0")
  const mm = String(now.getMinutes()).padStart(2, "0")
  clockBtn.innerText = hh + ":" + mm

clockTimer = setInterval(updateClock, 60000)
```

### 浮动 TOC 面板

点击时钟按钮会弹出浮动目录面板。TOC 的内容在客户端动态生成：

```js
function buildAndShowToc() {
  const headings = document.querySelectorAll("article h1, article h2, article h3")
  headings.forEach((heading, index) => {
    if (!heading.id) heading.id = "heading-" + index
    const a = document.createElement("a")
    a.href = "#" + heading.id
    a.textContent = heading.innerText
    a.className = "toc-item toc-" + heading.tagName.toLowerCase()
    tocContent.appendChild(a)
  })

  // 使用 IntersectionObserver 高亮当前标题
  tocObserver = new IntersectionObserver((entries) => {
    entries.forEach((entry) => {
      if (!entry.isIntersecting) return
      const tocLinks = document.querySelectorAll(".toc-item")
      tocLinks.forEach((link) => {
        link.classList.toggle("active", link.getAttribute("href") === "#" + entry.target.id)
      })
    })
  }, { rootMargin: "-25% 0px -60% 0px" })
}
```

### Hero Banner 视差效果

当文章有封面图片时，滚动会产生视差效果：

```js

if (banner) {
  const offset = getScrollTop() * 0.12
```

### SPA 导航后的重新初始化

BackToTop 的脚本通过监听 `nav` 事件实现 SPA 导航后的状态重置：

```js
document.addEventListener("nav", () => {
  triggerPageTransition()  // 触发页面切换动画
  setTimeout(() => {
    init()                 // 重新初始化所有功能
    updateScroll()         // 更新滚动进度
    tocPanel?.classList.remove("show")  // 关闭 TOC 面板
  }, 80)
})
```

这种设计确保了在 SPA 模式下页面切换时，所有浮动组件的行为正确重置。

## 3. Search.tsx -- 搜索组件

Search 组件集成了 FlexSearch 库，提供全文搜索和标签搜索功能。

### FlexSearch 集成

搜索索引在客户端从 `contentIndex.json` 加载数据后构建：

```ts
let index = new FlexSearch.Document<Item>({
  encode: encoder,  // 自定义编码器，支持 CJK 字符逐字分词
  document: {
    id: "id",
    tag: "tags",
    index: [
      { field: "title", tokenize: "forward" },
      { field: "content", tokenize: "forward" },
      { field: "tags", tokenize: "forward" },
    ],
  },
})
```

编码器 `encoder` 函数特别处理了中日韩（CJK）字符，将每个 CJK 字符作为独立的 token：

```ts
const isCJK =
  (code >= 0x4e00 && code <= 0x9fff) ||  // 中文
  (code >= 0x3040 && code <= 0x309f) ||  // 平假名
  (code >= 0x30a0 && code <= 0x30ff) ||  // 片假名
  (code >= 0xac00 && code <= 0xd7af)     // 韩文
```

### 服务端 HTML 结构

Search 组件的服务端渲染非常简洁，只生成搜索按钮和容器：

```tsx
const Search: QuartzComponent = ({ displayClass, cfg }: QuartzComponentProps) => {
  return (
    <div class={classNames(displayClass, "search")}>
      <button class="search-button">
        <svg>...</svg>
        <p>{i18n(cfg.locale).components.search.title}</p>
      </button>
      <div class="search-container">
        <div class="search-space">
          <input class="search-bar" type="text" placeholder={searchPlaceholder} />
          <div class="search-layout" data-preview={opts.enablePreview}></div>
        </div>
      </div>
    </div>
  )
}
```

### 搜索预览布局

当 `enablePreview` 为 true 时，搜索界面分为左右两栏：左侧是搜索结果列表，右侧是选中结果的 HTML 预览。预览内容通过 `fetch` 动态获取目标页面的 HTML，然后用 DOMParser 解析并高亮匹配内容。

### 快捷键支持

搜索组件支持 `Ctrl+K`（基本搜索）和 `Ctrl+Shift+K`（标签搜索）两种快捷键。

## 4. Graph.tsx -- D3 力导向图谱

Graph 组件使用 D3.js 进行力模拟计算，Pixi.js 进行 Canvas 渲染，实现了高效的交互式图谱。

### localGraph vs globalGraph

Graph 组件提供了两种图谱视图：

```tsx
// localGraph：当前页面的一跳邻居
<div class="graph-container" data-cfg={JSON.stringify(localGraph)}></div>
// globalGraph：全站图谱
<div class="global-graph-container" data-cfg={JSON.stringify(globalGraph)}></div>
```

两者的默认配置差异主要在于：
- `localGraph.depth = 1`：只显示当前页面的直接链接邻居
- `globalGraph.depth = -1`：显示全站所有节点
- `globalGraph.enableRadial = true`：使用径向布局
- `globalGraph.focusOnHover = true`：悬停时聚焦邻居

### SVG → Pixi.js 渲染

本项目使用 Pixi.js 替代了原版 Quartz 的 SVG 渲染。`graph.inline.ts` 中的 `renderGraph` 函数初始化 Pixi Application，创建节点和连线的 Graphics 对象，然后通过 D3 的 `forceSimulation` 计算物理模拟的位置数据，在 `requestAnimationFrame` 循环中更新 Pixi 渲染：

```ts
function animate(time: number) {
  for (const n of nodeRenderData) {
    const { x, y } = n.simulationData
    n.gfx.position.set(x + width / 2, y + height / 2)
    n.label.position.set(x + width / 2, y + height / 2)
  }
  for (const l of linkRenderData) {
    l.gfx.clear()
    l.gfx.moveTo(linkData.source.x! + width/2, linkData.source.y! + height/2)
    l.gfx.lineTo(linkData.target.x! + width/2, linkData.target.y! + height/2)
    l.gfx.stroke({ alpha: l.alpha, width: 1, color: l.color })
  }
  tweens.forEach((t) => t.update(time))
  app.renderer.render(stage)
  requestAnimationFrame(animate)
}
```

### 拖拽与导航

节点支持拖拽交互，短时间点击（< 500ms）会触发 SPA 导航：


## 5. PrevNextNav.tsx -- 上一章/下一章导航

PrevNextNav 是本项目自定义开发的一个导航组件，为博客文章提供"上一章/下一章"的线性阅读导航。源码位于 `quartz/components/PrevNextNav.tsx`。

### 全局 slug 排序策略

组件使用一个扁平化、排序后的文件列表来确定文章的前后关系：

```ts
function getFlatFileList(allFiles: QuartzPluginData[]): QuartzPluginData[] {
  return allFiles
    .filter((file) => {
      if (!file.slug) return false
      if (isFolderPath(file.slug!)) return false  // 排除文件夹页和 index
      return true
    })
    .sort((a, b) => a.slug!.localeCompare(b.slug!))  // 按 slug 路径排序
}
```

排序依据是 slug 的字典序，这意味着文件在文件系统中的路径结构直接决定了阅读顺序。例如 `/notes/chapter-01` 会排在 `/notes/chapter-02` 之前。

### 边界处理

当当前文章是列表的第一篇或最后一篇时，组件会显示禁用状态：

```tsx
{prevFile ? (
  <a href={resolveRelative(fileData.slug!, prevFile.slug!)} class="prev-next-link prev">
    <span class="prev-next-direction">{i18n(cfg.locale).components.prevNextNav.previous}</span>
    <span class="prev-next-title">{prevTitle}</span>
  </a>
) : (
  <div class="prev-next-link prev disabled">
    <span class="prev-next-direction">{i18n(cfg.locale).components.prevNextNav.previous}</span>
    <span class="prev-next-title">{i18n(cfg.locale).components.prevNextNav.noPrev}</span>
  </div>
)}
```

有链接时渲染 `<a>` 标签，无链接时渲染 `<div>` 并添加 `disabled` 类。CSS 将禁用项的边框改为虚线、透明度降低，视觉上清晰区分。

### i18n 国际化

组件文本通过 `i18n(cfg.locale)` 获取，支持多语言。在 `quartz/i18n/locales/definition.ts` 中定义了类型：

```ts
prevNextNav: {
  previous: string
  next: string
  noPrev: string
  noNext: string
}
```

各语言文件提供对应翻译，中文翻译在 `zh-CN.ts` 中：

```ts
prevNextNav: {
  previous: "上一章",
  next: "下一章",
  noPrev: "已是第一章",
  noNext: "已是最后一章",
}
```

这种国际化模式在 Quartz 中是统一的：先在 `definition.ts` 中声明类型接口，然后每个语言文件必须实现所有字段（通过 `satisfies Translation` 确保编译期类型安全）。
