当 Markdown 文件经过解析、变换和过滤之后，最终需要被渲染为完整的 HTML 页面。Quartz 的页面渲染引擎由 `renderPage.tsx` 驱动，将 HAST（HTML Abstract Syntax Tree）与 Preact 组件系统结合，生成最终的 HTML 文档。本文将深入分析这个渲染引擎的每个环节。

## 一、renderPage.tsx 的核心职责

`quartz/components/renderPage.tsx` 是 Quartz 页面渲染的核心函数。它接收以下参数：

- **cfg**：全局配置对象
- **slug**：当前页面的 FullSlug
- **componentData**：包含文件数据、AST 树、所有文件列表等信息的组件数据
- **components**：页面布局所需的各组件集合
- **pageResources**：页面所需的静态资源（CSS、JS）

它的核心职责可以概括为四步：

1. **处理 Transcludes**（块引用替换）
2. **组装页面组件树**
3. **渲染为 HTML 字符串**
4. **返回完整的 HTML 文档**

## 二、页面文档结构

renderPage 构建的 HTML 文档结构如下：

```
<!DOCTYPE html>
<html lang="zh-CN" dir="ltr">
  <head>
    <!-- Head 组件：meta 标签、CSS 引入、favicon 等 -->
    <Head {...componentData} />
  </head>
  <body data-slug="path/to/page">
    <div id="quartz-root" class="page">
      <Body {...componentData}>
        <!-- 左侧边栏 -->
        <div class="left sidebar">
          <PageTitle />
          <Spacer />          <!-- 移动端间距 -->
          <Search />
          <Darkmode />
          <ReaderMode />
          <Explorer />
        </div>

        <!-- 中心内容区 -->
        <div class="center">
          <div class="page-header">
            <Header>
              <!-- header 组件（本项目为空） -->
            </Header>
            <div class="popover-hint">
              <!-- beforeBody 组件 -->
              <Breadcrumbs />
              <ArticleTitle />
              <ContentMeta />
              <TagList />
            </div>
          </div>

          <!-- 页面主体内容 -->
          <Content {...componentData} />

          <hr />
          <div class="page-footer">
            <!-- afterBody 组件 -->
            <PrevNextNav />
            <BackToTop />
            <StarryBackground />
          </div>
        </div>

        <!-- 右侧边栏 -->
        <div class="right sidebar">
          <Graph />
          <TableOfContents />
          <Backlinks />
        </div>

        <!-- 页脚 -->
        <Footer {...componentData} />
      </Body>
    </div>

    <!-- afterDOMReady 脚本（SPA、搜索等） -->
    <script src="./postscript.js" type="module"></script>
  </body>
</html>
```

对应的组件接口 `RenderComponents` 定义了这些区域：

```ts
interface RenderComponents {
  head: QuartzComponent
  header: QuartzComponent[]
  beforeBody: QuartzComponent[]
  pageBody: QuartzComponent
  afterBody: QuartzComponent[]
  left: QuartzComponent[]
  right: QuartzComponent[]
  footer: QuartzComponent
}
```

`body` 元素上的 `data-slug` 属性至关重要——它是 SPA 路由系统识别当前页面的依据，也是页面间导航时的锚点。

## 三、Transcludes 处理

Transcludes（内容引用）是 Obsidian 的核心特性之一，允许在一个页面中嵌入另一个页面的内容。`renderPage.tsx` 中的 `renderTranscludes` 函数处理三种引用类型。

### 3.1 块引用（`![[page#^blockId]]`）

块引用通过 `#^` 前缀标识，引用目标页面中特定 ID 的块：

```ts
if (blockRef?.startsWith("#^")) {
  blockRef = blockRef.slice("#^".length)
  let blockNode = page.blocks?.[blockRef]
  if (blockNode) {
    // 如果是列表项，需要包装为 <ul>
    if (blockNode.tagName === "li") {
      blockNode = {
        type: "element",
        tagName: "ul",
        properties: {},
        children: [blockNode],
      }
    }
    node.children = [
      normalizeHastElement(blockNode, slug, transcludeTarget),
      // 添加"链接到原文"的锚点
      { type: "element", tagName: "a", properties: { href: inner.properties?.href, class: ["internal", "transclude-src"] },
        children: [{ type: "text", value: i18n(cfg.locale).components.transcludes.linkToOriginal }] },
    ]
  }
}
```

### 3.2 标题引用（`![[page#heading]]`）

标题引用通过 `#` 前缀（非 `#^`）标识，引用目标页面中某个标题及其下方的全部内容：

```ts
} else if (blockRef?.startsWith("#") && page.htmlAst) {
  blockRef = blockRef.slice(1)
  // 在目标页面的 HTML AST 中查找匹配的标题
  for (const [i, el] of page.htmlAst.children.entries()) {
    if (!(el.type === "element" && el.tagName.match(headerRegex))) continue
    const depth = Number(el.tagName.substring(1))

    if (startIdx === undefined || startDepth === undefined) {
      if (el.properties?.id === blockRef) {
        startIdx = i
        startDepth = depth
      }
    } else if (depth <= startDepth) {
      endIdx = i
      break
    }
  }
  // 提取 startIdx 到 endIdx 之间的所有内容
  node.children = [
    ...(page.htmlAst.children.slice(startIdx, endIdx)).map(child =>
      normalizeHastElement(child, slug, transcludeTarget)),
    // "链接到原文"
  ]
}
```

算法的思路是：找到目标标题的位置后，继续向下遍历，直到遇到同级或更高级别的标题为止，以此确定需要截取的内容范围。

### 3.3 页面引用（`![[page]]`）

最简单的引用形式，嵌入整个页面的内容：

```ts
} else if (page.htmlAst) {
  node.children = [
    // 页面标题
    { type: "element", tagName: "h1", properties: {},
      children: [{ type: "text", value: page.frontmatter?.title ?? "Transclude of ..." }] },
    // 页面全部内容
    ...(page.htmlAst.children).map(child => normalizeHastElement(child, slug, transcludeTarget)),
    // "链接到原文"
  ]
}
```

### 3.4 循环引用检测

transclude 系统内置了循环引用检测机制：

```ts
const visited = new Set<FullSlug>([slug])

visit(root, "element", (node, _index, _parent) => {
  // ...
  if (visited.has(transcludeTarget)) {
    console.warn(`Warning: Skipping circular transclusion: ${slug} -> ${transcludeTarget}`)
    // 替换为警告文本
    return
  }
  visited.add(transcludeTarget)
  // ... 处理 transclude
})
```

`visited` 集合跟踪当前渲染链路中已经引用过的页面，如果发现循环引用，会输出警告并将 transclude 替换为提示文本，而不是无限递归。

值得注意的是，renderPage 在处理 transcludes 之前会先对 AST 做深拷贝：

```ts
const root = clone(componentData.tree) as Root
```

这确保 transclude 的替换操作不会影响 `contentMap` 中缓存的原始 AST 数据。

## 四、Content 组件

`quartz/components/pages/Content.tsx` 是页面正文的渲染入口，它负责将 HAST 转换为 Preact JSX：

```ts
const Content: QuartzComponent = ({ fileData, tree }: QuartzComponentProps) => {
  const content = htmlToJsx(fileData.filePath!, tree) as ComponentChildren
  const classes: string[] = fileData.frontmatter?.cssclasses ?? []
  const classString = ["popover-hint", ...classes].join(" ")
  return <article class={classString}>{content}</article>
}
```

这里有两点关键逻辑：

1. **htmlToJsx 转换**：调用 `htmlToJsx` 将 HAST 树转换为 Preact 可渲染的 JSX 元素
2. **cssclasses 支持**：支持在 frontmatter 中通过 `cssclasses` 字段为页面添加自定义 CSS 类，这些类会被添加到 `<article>` 元素上

## 五、HAST 到 JSX 的转换原理

`quartz/util/jsx.tsx` 中的 `htmlToJsx` 函数是连接 AST 世界和 JSX 世界的桥梁：

```ts
import { Components, Jsx, toJsxRuntime } from "hast-util-to-jsx-runtime"
import { Fragment, jsx, jsxs } from "preact/jsx-runtime"

const customComponents: Components = {
  table: (props) => (
    <div class="table-container">
      <table {...props} />
    </div>
  ),
}

export function htmlToJsx(fp: FilePath, tree: Node) {
  try {
    return toJsxRuntime(tree as Root, {
      Fragment,
      jsx: jsx as Jsx,
      jsxs: jsxs as Jsx,
      elementAttributeNameCase: "html",
      components: customComponents,
    })
  } catch (e) {
    trace(`Failed to parse Markdown in \`${fp}\` into JSX`, e as Error)
  }
}
```

这里使用了三个核心库的协作：

1. **hast-util-to-jsx-runtime**：将 HAST 树转换为 JSX 运行时可执行的格式。它接受一个 `toJsxRuntime` 函数，将 HAST 节点逐一转换为 JSX 调用
2. **preact/jsx-runtime**：Preact 的 JSX 运行时，提供 `jsx` 和 `jsxs` 函数，用于创建 Preact VNode
3. **customComponents**：自定义组件映射表，可以在转换过程中替换特定的 HTML 元素。当前实现中，所有 `<table>` 元素会被自动包装在 `<div class="table-container">` 中，实现表格的水平滚动容器

`elementAttributeNameCase: "html"` 确保属性名保持 HTML 原样（如 `class` 而非 `className`、`tabindex` 而非 `tabIndex`），这在静态站点生成中非常重要，因为最终输出是纯 HTML 而非 React DOM。

## 六、SPA 资源注入

`pageResources` 函数负责为每个页面准备所需的静态资源：

```ts
export function pageResources(
  baseDir: FullSlug | RelativeURL,
  staticResources: StaticResources,
): StaticResources {
  const contentIndexPath = joinSegments(baseDir, "static/contentIndex.json")
  const contentIndexScript = `const fetchData = fetch("${contentIndexPath}").then(data => data.json())`

  const resources: StaticResources = {
    css: [
      { content: joinSegments(baseDir, "index.css") },  // 主样式表
      ...staticResources.css,                            // 插件声明的额外 CSS
    ],
    js: [
      { src: joinSegments(baseDir, "prescript.js"), loadTime: "beforeDOMReady", contentType: "external" },
      // 内联脚本：预加载 contentIndex
      { loadTime: "beforeDOMReady", contentType: "inline", spaPreserve: true, script: contentIndexScript },
      ...staticResources.js,  // 插件声明的额外 JS
    ],
    additionalHead: staticResources.additionalHead,
  }

  resources.js.push({
    src: joinSegments(baseDir, "postscript.js"),
    loadTime: "afterDOMReady",
    moduleType: "module",
    contentType: "external",
  })

  return resources
}
```

资源被分为三种加载时机：

- **beforeDOMReady**：在 DOM 构建之前加载，包括主样式表和预加载脚本
- **afterDOMReady**：在 DOM 完成构建后加载，主要是功能脚本（SPA 路由、搜索、图表等）
- **inline**：直接内联到 HTML 中的脚本，如 contentIndex 的预加载代码

注意 `spaPreserve: true` 标记——带有此标记的内联脚本在 SPA 导航时不会被移除，避免重复执行。

在 renderPage 的返回值中，afterDOMReady 的脚本被渲染为 `body` 的直接子元素（在 `</body>` 之前），而非放在 `head` 中：

```tsx
{pageResources.js
  .filter((resource) => resource.loadTime === "afterDOMReady")
  .map((res) => JSResourceToScriptElement(res, true))}
```

## 七、页面布局系统

页面布局由 `quartz.layout.ts` 和 `quartz/cfg.ts` 共同定义。

`FullPageLayout` 接口定义了页面的完整结构：

```ts
export interface FullPageLayout {
  head: QuartzComponent          // 页面 <head>
  header: QuartzComponent[]      // 页面头部区域
  beforeBody: QuartzComponent[]  // 内容区上方的组件（面包屑、标题等）
  pageBody: QuartzComponent      // 页面主体内容
  afterBody: QuartzComponent[]   // 内容区下方的组件
  left: QuartzComponent[]        // 左侧边栏
  right: QuartzComponent[]       // 右侧边栏
  footer: QuartzComponent        // 页脚
}
```

布局分为三个层次：

1. **SharedLayout**（`sharedPageComponents`）：所有页面共享的组件
2. **PageLayout**（`defaultContentPageLayout` / `defaultListPageLayout`）：特定页面类型的组件，只包含 `beforeBody`、`left`、`right` 三个区域
3. **FullPageLayout**：SharedLayout + PageLayout + pageBody 的完整组合

以内容页为例，`ContentPage` emitter 在初始化时就完成了布局的组合：

```ts
export const ContentPage: QuartzEmitterPlugin<Partial<FullPageLayout>> = (userOpts) => {
  const opts: FullPageLayout = {
    ...sharedPageComponents,       // 1. 基础：共享组件
    ...defaultContentPageLayout,   // 2. 覆盖：内容页布局
    pageBody: Content(),            // 3. 设置：页面主体
    ...userOpts,                   // 4. 最终：用户自定义覆盖
  }
  // ...
}
```

这种分层设计允许你灵活地定制：只需修改 `quartz.layout.ts` 中的 `defaultContentPageLayout` 就能改变所有内容页的布局，而不会影响列表页或共享组件。

本项目的 `sharedPageComponents` 定义了：

```ts
export const sharedPageComponents: SharedLayout = {
  head: Component.Head(),
  header: [],                          // 不使用 header 组件
  afterBody: [StarryBackground(undefined), BackToTop(undefined)],
  footer: Component.Footer(),
}
```

`defaultContentPageLayout` 定义了内容页的左侧（搜索、暗色模式、阅读模式、Explorer）、右侧（图谱、目录、反向链接）以及 beforeBody/afterBody 区域的组件排列。

## 八、ContentPage Emitter 调用 renderPage

`ContentPage` emitter 是将一切串联起来的关键环节。它遍历所有过滤后的内容，对每个页面调用 `renderPage`：

```ts
async function processContent(
  ctx: BuildCtx, tree: Node, fileData: QuartzPluginData,
  allFiles: QuartzPluginData[], opts: FullPageLayout, resources: StaticResources,
) {
  const slug = fileData.slug!
  const cfg = ctx.cfg.configuration
  const externalResources = pageResources(pathToRoot(slug), resources)

  // 组装组件数据
  const componentData: QuartzComponentProps = {
    ctx,
    fileData,
    externalResources,
    cfg,
    children: [],
    tree,          // HAST 树
    allFiles,       // 所有文件的数据（用于 transcludes、backlinks 等）
  }

  // 渲染页面
  const content = renderPage(cfg, slug, componentData, opts, externalResources)

  // 写入文件
  return write({ ctx, content, slug, ext: ".html" })
}
```

`componentData.allFiles` 是整个渲染系统中的关键数据——它包含了所有页面的完整数据（包括 frontmatter、HTML AST、链接、TOC 等），使得 transcludes 可以引用任何页面的内容，backlinks 可以查找引用当前页面的其他页面。

emit 使用 AsyncGenerator 模式：

```ts
async *emit(ctx, content, resources) {
  const allFiles = content.map((c) => c[1].data)
  for (const [tree, file] of content) {
    const slug = file.data.slug!
    if (slug.endsWith("/index") || slug.startsWith("tags/")) continue  // 跳过 index 和 tag 页面
    yield processContent(ctx, tree, file.data, allFiles, opts, resources)
  }
}
```

使用 `yield` 逐个生成文件路径，而不是一次性返回数组，这样 `emitContent` 处理器可以在文件生成的同时进行统计和日志输出。

最终，renderPage 返回的 HTML 字符串经过 `preact-render-to-string` 的 `render()` 函数序列化，加上 `<!DOCTYPE html>` 前缀，就是一个完整的 HTML 文档。

通过这套渲染引擎，Quartz 将 Markdown 内容与 Preact 组件系统完美地结合在一起——你写的 Markdown 文件最终被包裹在一个功能丰富的页面布局中，拥有搜索、图谱、目录、面包屑导航等完整功能。
