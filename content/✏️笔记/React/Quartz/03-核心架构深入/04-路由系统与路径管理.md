Quartz 的 SPA 路由和路径管理系统是让静态站点拥有近乎原生应用体验的关键。SPA 路由通过 DOM morphing 实现无刷新页面切换，而路径系统通过类型化的 slug 确保链接的正确性。本文将深入分析这两个子系统的工作原理。

## 一、SPA 路由的核心原理

传统的多页站点（MPA）在导航时会触发完整的页面刷新——浏览器销毁当前页面的所有 DOM 和 JS 状态，重新下载并解析新的 HTML 文件。这种方式的问题在于：页面切换时会出现"白屏"闪烁，所有客户端状态（如搜索框内容、暗色模式偏好、Explorer 展开状态）都会丢失。

Quartz 的 SPA 路由采用 **DOM Morphing** 技术来解决这个问题。核心思路是：拦截页面的链接点击，通过 `fetch` 获取目标页面的 HTML，然后用 `micromorph` 库对当前页面的 DOM 进行"变形"——只更新变化的部分，保留不变的元素和状态。

与传统 SPA 框架（如 React/Vue 的客户端路由）的区别在于：Quartz 不需要在客户端维护一套虚拟 DOM 或组件状态，每个页面仍然是服务端渲染的完整 HTML，只是切换方式从"替换整个页面"变成了"局部变形"。

## 二、spa.inline.ts 的关键逻辑

SPA 路由的完整实现位于 `quartz/components/scripts/spa.inline.ts`，以下逐一分析各环节。

### 2.1 Click 事件拦截

路由系统的起点是对 `<a>` 标签点击事件的拦截：

```ts
window.addEventListener("click", async (event) => {
  const { url } = getOpts(event) ?? {}
  // 不拦截：Ctrl/Meta 键点击（新标签页打开）
  if (!url || event.ctrlKey || event.metaKey) return
  event.preventDefault()

  // 同页面锚点：直接滚动，不触发导航
  if (isSamePage(url) && url.hash) {
    const el = document.getElementById(decodeURIComponent(url.hash.substring(1)))
    el?.scrollIntoView()
    history.pushState({}, "", url)
    return
  }

  navigate(url, false)
})
```

`getOpts` 函数负责判断一个点击事件是否应该被 SPA 路由处理：

```ts
const getOpts = ({ target }: Event): { url: URL; scroll?: boolean } | undefined => {
  if (!isElement(target)) return
  if (target.attributes.getNamedItem("target")?.value === "_blank") return  // 跳过新窗口链接
  const a = target.closest("a")                                             // 找到最近的 <a> 元素
  if (!a) return
  if ("routerIgnore" in a.dataset) return                                   // 跳过 data-router-ignore 标记
  const { href } = a
  if (!isLocalUrl(href)) return                                             // 跳过外部链接
  return { url: new URL(href), scroll: "routerNoscroll" in a.dataset ? false : undefined }
}
```

只有满足以下所有条件的链接才会被拦截：是 `<a>` 元素、指向本站地址、没有 `target="_blank"`、没有 `data-router-ignore` 属性。外部链接会正常跳转。

### 2.2 Fetch + MorphDOM 流程

`navigate` 函数是导航的核心，它执行以下步骤：

```ts
async function _navigate(url: URL, isBack: boolean = false) {
  isNavigating = true
  startLoading()                    // 1. 显示导航进度条
  p = p || new DOMParser()
  const contents = await fetchCanonical(url)  // 2. 获取目标页面 HTML
    .then(res => res.text())

  // 3. 触发 prenav 事件，允许组件做导航前清理
  const event = new CustomEvent("prenav", { detail: {} })
  document.dispatchEvent(event)

  // 4. 清理旧页面的资源
  cleanupFns.forEach(fn => fn())
  cleanupFns.clear()

  // 5. 解析新页面的 HTML
  const html = p.parseFromString(contents, "text/html")
  normalizeRelativeURLs(html, url)  // 修正相对路径

  // 6. 更新页面标题
  let title = html.querySelector("title")?.textContent
  if (title) document.title = title

  // 7. 无障碍通知
  if (announcer.textContent !== title) announcer.textContent = title
  announcer.dataset.persist = ""
  html.body.appendChild(announcer)

  // 8. DOM morphing：将当前页面变形为新页面
  await micromorph(document.body, html.body)

  // 9. 滚动处理
  if (!isBack) {
    if (url.hash) {
      document.getElementById(decodeURIComponent(url.hash.substring(1)))?.scrollIntoView()
    } else {
      window.scrollTo({ top: 0 })
    }
  }

  // 10. Head patching（见下文）

  // 11. 更新浏览器历史
  if (!isBack) history.pushState({}, "", url)

  // 12. 触发 nav 事件
  notifyNav(getFullSlug(window))
}
```

`normalizeRelativeURLs` 确保新页面中的相对 URL 被正确地解析为基于目标 URL 的绝对路径：

```ts
export function normalizeRelativeURLs(el: Element | Document, destination: string | URL) {
  el.querySelectorAll('[href=""], [href^="./"], [href^="../"]').forEach(item =>
    _rebaseHtmlElement(item, "href", destination))
  el.querySelectorAll('[src=""], [src^="./"], [src^="../"]').forEach(item =>
    _rebaseHtmlElement(item, "src", destination))
}
```

### 2.3 Popstate 处理（浏览器前进/后退）

```ts
window.addEventListener("popstate", (event) => {
  const { url } = getOpts(event) ?? {}
  if (window.location.hash && window.location.pathname === url?.pathname) return
  navigate(new URL(window.location.toString()), true)  // isBack = true
})
```

当用户点击浏览器的前进/后退按钮时，`popstate` 事件被触发。此时 `isBack` 参数为 `true`，导航函数会跳过滚动处理（保持浏览器自带的滚动位置恢复行为）。

### 2.4 Head Patching

Head patching 是 SPA 路由中最精巧的部分。问题在于：不同页面可能需要不同的 `<head>` 内容（如不同的 CSS、meta 标签、Open Graph 信息），但又不能简单地替换整个 `<head>`——因为某些 `<script>` 和 `<style>` 标签在 SPA 模式下需要被保留。

解决方案是使用 `data-persist` 标记：

```ts
// 移除当前 head 中所有非持久化的元素
const elementsToRemove = document.head.querySelectorAll(":not([data-persist])")
elementsToRemove.forEach(el => el.remove())

// 从新页面中获取所有非持久化的元素并添加
const elementsToAdd = html.head.querySelectorAll(":not([data-persist])")
elementsToAdd.forEach(el => document.head.appendChild(el))
```

带有 `data-persist` 属性的元素（如 SPA 的内联脚本和主样式表）不会被移除也不会被重新添加，避免了重复加载和状态丢失。

### 2.5 Route Announcer（无障碍导航通知）

`route-announcer` 是一个自定义 HTML 元素，用于向屏幕阅读器播报页面导航：

```ts
if (!customElements.get("route-announcer")) {
  const attrs = {
    "aria-live": "assertive",
    "aria-atomic": "true",
    style: "position: absolute; left: 0; top: 0; clip: rect(0 0 0 0); ...",
  }
  customElements.define("route-announcer", class RouteAnnouncer extends HTMLElement {
    connectedCallback() {
      for (const [key, value] of Object.entries(attrs)) this.setAttribute(key, value)
    }
  })
}
```

它通过 `aria-live="assertive"` 使屏幕阅读器在内容变化时立即播报。该元素在视觉上完全隐藏（通过 `clip` 裁剪为 1x1 像素），但对辅助技术可见。

### 2.6 导航进度条

```ts
function startLoading() {
  const loadingBar = document.createElement("div")
  loadingBar.className = "navigation-progress"
  loadingBar.style.width = "0"
  document.body.appendChild(loadingBar)
  setTimeout(() => { loadingBar.style.width = "80%" }, 100)
}
```

创建一个 `navigation-progress` 类的 div 元素，初始宽度为 0，100ms 后过渡到 80%宽度。由于 CSS transition 的存在，这会产生一个从左到右的加载动画。当导航完成后，整个 `body` 被 micromorph 替换，进度条自然消失。

同时，`isNavigating` 标志位确保同一时间只有一个导航在执行，避免快速连续点击导致的竞态问题：

```ts
async function navigate(url: URL, isBack: boolean = false) {
  if (isNavigating) return
  isNavigating = true
  try {
    await _navigate(url, isBack)
  } catch (e) {
    window.location.assign(url)  // 出错时回退到完整页面加载
  } finally {
    isNavigating = false
  }
}
```

## 三、Slug 路径系统

Quartz 的路径系统定义在 `quartz/util/path.ts` 中，使用 TypeScript 的 **名义类型（Nominal Types）** 模式区分四种 slug 类型，防止类型的误用。

### 3.1 四种 Slug 类型

```ts
// 名义类型的实现方式：通过 brand 字段区分
type SlugLike<T> = string & { __brand: T }
```

四种类型及其约束：

```
FilePath ──────────────────────────────────────────────────
  必须有文件扩展名，不能是相对路径
  示例: "content/笔记/C sharp/EF Core 链式查询.md"

         │ slugifyFilePath()
         v

FullSlug ──────────────────────────────────────────────────
  不能有扩展名（.md/.html 除外），不能有前导/后缀斜杠
  可以包含 "index" 作为最后一段
  示例: "content/笔记/c-sharp/ef-core-链式查询"
  示例: "content/笔记/网络/index"

         │ simplifySlug()
         v

SimpleSlug ───────────────────────────────────────────────
  不能有文件扩展名，不能以 /index 结尾
  可以有尾部斜杠表示文件夹路径
  示例: "content/笔记/c-sharp/ef-core-链式查询"
  示例: "content/笔记/网络/"

         │ resolveRelative()
         v

RelativeURL ───────────────────────────────────────────────
  必须以 ./ 或 ../ 开头
  用于 href 和 src 属性
  示例: "../c-sharp/ef-core-链式查询"
```

### 3.2 slugifyFilePath：文件路径到 Web Slug 的转换

`slugifyFilePath` 是将文件系统路径转换为 URL 友好 slug 的核心函数：

```ts
export function slugifyFilePath(fp: FilePath, excludeExt?: boolean): FullSlug {
  fp = stripSlashes(fp) as FilePath
  let ext = getFileExtension(fp)
  const withoutFileExt = fp.replace(new RegExp(ext + "$"), "")

  // .md/.html 扩展名会被自动移除
  if (excludeExt || [".md", ".html", undefined].includes(ext)) {
    ext = ""
  }

  let slug = sluggify(withoutFileExt)

  // _index 视为 index
  if (endsWith(slug, "_index")) {
    slug = slug.replace(/_index$/, "index")
  }

  return (slug + ext) as FullSlug
}
```

其中 `sluggify` 函数执行具体的字符转换：

```ts
function sluggify(s: string): string {
  return s
    .split("/")
    .map(segment =>
      segment
        .replace(/\s/g, "-")        // 空格 -> 连字符
        .replace(/&/g, "-and-")    // & -> -and-
        .replace(/%/g, "-percent") // % -> -percent
        .replace(/\?/g, "")         // 移除问号
        .replace(/#/g, "")         // 移除井号
    )
    .join("/")
    .replace(/\/$/, "")             // 移除尾部斜杠
}
```

转换示例：

| 输入 (FilePath) | 输出 (FullSlug) |
|---|---|
| `content/笔记/C sharp/EF Core 链式查询.md` | `content/笔记/c-sharp/ef-core-链式查询` |
| `content/笔记/网络/index.md` | `content/笔记/网络/index` |
| `content/✏️笔记/index.md` | `content/✏️笔记/index` |

### 3.3 simplifySlug：去除 index 后缀

```ts
export function simplifySlug(fp: FullSlug): SimpleSlug {
  const res = stripSlashes(trimSuffix(fp, "index"), true)
  return (res.length === 0 ? "/" : res) as SimpleSlug
}
```

将 `content/笔记/网络/index` 转换为 `content/笔记/网络/`（文件夹路径以斜杠结尾）。如果结果是空字符串（即根目录的 index），则返回 `/`。

### 3.4 resolveRelative：计算相对路径

```ts
export function resolveRelative(current: FullSlug, target: FullSlug | SimpleSlug): RelativeURL {
  const res = joinSegments(pathToRoot(current), simplifySlug(target as FullSlug)) as RelativeURL
  return res
}
```

`pathToRoot` 计算从当前页面到站点根目录的相对路径：

```ts
export function pathToRoot(slug: FullSlug): RelativeURL {
  let rootPath = slug
    .split("/")
    .filter(x => x !== "")
    .slice(0, -1)  // 去掉最后一段（文件名）
    .map(_ => "..")  // 每段对应一个 ..
    .join("/")
  if (rootPath.length === 0) rootPath = "."
  return rootPath as RelativeURL
}
```

示例：当前页面是 `content/笔记/c-sharp/ef-core`，则 `pathToRoot` 返回 `../../..`。要从当前页面链接到 `content/笔记/网络/`，`resolveRelative` 会计算为 `../../../网络/`。

### 3.5 transformInternalLinks：Obsidian 链接转换

`transformInternalLink` 将各种格式的内部链接统一转换为标准的 RelativeURL：

```ts
export function transformInternalLink(link: string): RelativeURL {
  let [fplike, anchor] = splitAnchor(decodeURI(link))
  const folderPath = isFolderPath(fplike)
  let segments = fplike.split("/").filter(x => x.length > 0)
  let prefix = segments.filter(isRelativeSegment).join("/")
  let fp = segments.filter(seg => !isRelativeSegment(seg) && seg !== "").join("/")

  const simpleSlug = simplifySlug(slugifyFilePath(fp as FilePath))
  const joined = joinSegments(stripSlashes(prefix), stripSlashes(simpleSlug))
  const trail = folderPath ? "/" : ""
  const res = (_addRelativeToStart(joined) + trail + anchor) as RelativeURL
  return res
}
```

它处理了多种输入格式：带或不带相对路径前缀（`../`）、文件夹路径（以 `/` 结尾或以 `index` 结尾）、带锚点的链接等。`splitAnchor` 使用 `github-slugger` 将锚点文本转换为 URL 友好的格式。

## 四、FileTrie 字典树

`quartz/util/fileTrie.ts` 实现了一个泛型字典树，用于管理文件的层级结构。它在面包屑导航（Breadcrumbs）、Explorer 侧边栏等组件中发挥关键作用。

### 4.1 泛型设计

```ts
interface FileTrieData {
  slug: string
  title: string
  filePath: string
}

export class FileTrieNode<T extends FileTrieData = ContentDetails> {
  isFolder: boolean
  children: Array<FileTrieNode<T>>
  private slugSegments: string[]    // 从根到当前节点的 slug 路径段
  private fileSegmentHint?: string  // 原始文件名（用于显示更友好的名称）
  private displayNameOverride?: string
  data: T | null                     // 当前节点的数据（仅叶子节点有）
  // ...
}
```

`FileTrieNode` 是泛型的，允许存储任意实现了 `FileTrieData` 接口的数据。默认使用 `ContentDetails`（包含 slug、title、filePath 等字段）。

### 4.2 文件夹层级的表示方式

字典树通过递归的 `insert` 方法构建。每个节点代表路径中的一个段，文件夹节点（`isFolder: true`）可以有子节点，叶子节点存储文件数据。

以如下文件结构为例：

```
content/
  笔记/
    C sharp/
      EF Core 链式查询.md
      async await.md
    网络/
      index.md
      arp -a.md
  index.md
```

对应的 Trie 结构：

```
(root) isFolder=true
  ├── 笔记/        isFolder=true
  │   ├── c-sharp/  isFolder=true
  │   │   ├── ef-core-链式查询  data={slug, title, filePath}
  │   │   └── async-await        data={slug, title, filePath}
  │   └── 网络/     isFolder=true
  │       ├── (index) data={slug, title, filePath}  // index 的数据存储在文件夹节点上
  │       └── arp-a   data={slug, title, filePath}
  └── (index)       data={slug, title, filePath}      // 根 index
```

`index.md` 的数据会存储在对应的文件夹节点上，而不是作为子节点。

### 4.3 ancestryChain：面包屑导航的路径计算

```ts
ancestryChain(path: string[]): Array<FileTrieNode<T>> | undefined {
  if (path.length === 0 || (path.length === 1 && path[0] === "index")) {
    return [this]
  }
  const child = this.children.find(c => c.slugSegment === path[0])
  if (!child) return undefined
  const childPath = child.ancestryChain(path.slice(1))
  if (!childPath) return undefined
  return [this, ...childPath]
}
```

`ancestryChain` 从根节点出发，沿着路径段逐层查找，返回从根到目标节点的完整路径数组。这正是面包屑导航所需要的数据结构。

例如，查找 `笔记/c-sharp/ef-core-链式查询` 的 ancestryChain 会返回：

```
[
  (root),
  笔记/,
  c-sharp/,
  ef-core-链式查询
]
```

每个节点的 `displayName` 属性提供了显示名称：优先使用 data.title（如果是 index 文件且标题也是 "index" 则跳过），其次使用 `fileSegmentHint`（原始文件名，保留了中文等字符），最后才使用 slugSegment（经过 sluggify 处理的名称）。

### 4.4 fromEntries：从扁平文件列表构建 Trie

```ts
static fromEntries<T extends FileTrieData>(entries: [FullSlug, T][]) {
  const trie = new FileTrieNode<T>([])
  entries.forEach(([, entry]) => trie.add(entry))
  return trie
}
```

这是一个工厂方法，接受一个 `[FullSlug, Data]` 的数组，将每个条目添加到 Trie 中。`add` 方法将 slug 按斜杠分割，递归地插入到树中：

```ts
add(file: T) {
  this.insert(file.slug.split("/"), file)
}
```

这种设计将扁平的文件列表（从 contentIndex 获取）转换为具有层级结构的树，供 Explorer、Breadcrumbs 等组件使用。Trie 还提供了 `filter`、`map`、`sort` 等方法，支持在树结构上直接进行查询和排序操作，无需先展开为扁平数组。

通过 SPA 路由和 Slug 路径系统的配合，Quartz 实现了既有静态站点的性能优势（SEO 友好、首屏加载快），又有单页应用的用户体验（无刷新导航、状态保持）的混合架构。
