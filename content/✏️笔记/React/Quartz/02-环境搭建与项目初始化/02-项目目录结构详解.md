## 二、content/ —— 博客内容目录

这是你日常打交道最多的目录。所有的 Markdown 文章都放在这里。

### 组织规则

- **文件夹即分类**：`content/C sharp/async await.md` 会生成路径 `/C sharp/async await/` 的页面，文件夹自动成为导航层级
- **index.md 是目录首页**：每个文件夹下的 `index.md` 对应该文件夹的入口页面。例如 `content/网络/index.md` 就是"网络"这个分类的首页
- **文件名即标题**：如果文章的 Frontmatter 没有设置 `title` 字段，Quartz 会自动使用文件名作为标题
- **必须使用 .md 后缀**：Quartz 只处理 `.md` 文件，不支持 `.txt` 或其他格式

### 示例结构

```
content/
├── index.md                    # 站点首页
├── C sharp/
│   ├── EF Core 链式查询.md
│   ├── async await.md
│   └── Vue学习.md
├── 网络/
│   ├── index.md                # "网络"分类的首页
│   ├── arp -a.md
│   └── 交换机数据通信情况.md
└── 若依/
    └── 前端/
        └── 大概分析/
            ├── 01-项目概述与技术栈.md
            └── 02-项目结构与目录说明.md
```

## 四、quartz/plugins/ —— 插件系统

Quartz 的插件系统分为三层：**transformers**（转换器）、**filters**（过滤器）、**emitters**（发射器）。它们按顺序串联，将原始 Markdown 文件最终转化为可部署的静态网站。

### 整体流程

```
原始 .md 文件
    │
    ▼
[Transformers] 转换器 ── 解析和转换内容
    │
    ▼
[Filters] 过滤器 ── 决定哪些文件应该发布
    │
    ▼
[Emitters] 发射器 ── 生成最终输出文件
    │
    ▼
public/ 目录（静态网站文件）
```

### transformers/ —— 转换器

转换器负责解析 Markdown、提取元数据、添加增强功能。它们按配置顺序依次执行。

| 插件文件 | 对应配置名 | 功能说明 |
|----------|-----------|----------|
| `frontmatter.ts` | `Plugin.FrontMatter()` | 解析 Markdown 文件开头的 YAML Frontmatter，提取标题、日期、标签等元数据 |
| `lastmod.ts` | `Plugin.CreatedModifiedDate()` | 从 Frontmatter、Git 提交记录或文件系统获取创建/修改时间 |
| `syntax.ts` | `Plugin.SyntaxHighlighting()` | 代码块语法高亮，基于 Shiki 引擎，支持数百种语言和多种主题 |
| `toc.ts` | `Plugin.TableOfContents()` | 从文章标题层级自动生成目录（Table of Contents）数据 |
| `latex.ts` | `Plugin.Latex()` | 数学公式渲染，支持 KaTeX 和 MathJax 两种引擎 |
| `links.ts` | `Plugin.CrawlLinks()` | 解析 `[[]]` 内部链接语法，处理链接间的引用关系 |
| `ofm.ts` | `Plugin.ObsidianFlavoredMarkdown()` | 支持 Obsidian 特有语法（嵌入、标签页、高亮等） |
| `gfm.ts` | `Plugin.GitHubFlavoredMarkdown()` | 支持 GitHub 风格 Markdown（表格、删除线、任务列表、脚注） |
| `citations.ts` | `Plugin.Citations()` | 支持学术引用语法 `[[cite:xxx]]`，生成引用列表 |
| `description.ts` | `Plugin.Description()` | 自动提取文章摘要，用于 SEO 的 meta description |
| `linebreaks.ts` | `Plugin.HardLineBreaks()` | 将单个换行符转换为 `<br>` 标签 |

### filters/ —— 过滤器

过滤器决定哪些文件应该被发布到最终站点。

| 插件文件 | 对应配置名 | 功能说明 |
|----------|-----------|----------|
| `draft.ts` | `Plugin.RemoveDrafts()` | 过滤掉 Frontmatter 中 `draft: true` 的草稿文章 |
| `explicit.ts` | `Plugin.ExplicitPublish()` | 仅发布 Frontmatter 中设置了 `publish: true` 的文章（需手动启用） |

> **注意**：默认配置中只启用了 `RemoveDrafts()`。`ExplicitPublish()` 未启用，意味着所有非草稿文件都会被发布。

### emitters/ —— 发射器

发射器负责将处理后的内容生成实际的输出文件（HTML、CSS、JS、JSON 等）。

| 插件文件 | 对应配置名 | 功能说明 |
|----------|-----------|----------|
| `contentPage.tsx` | `Plugin.ContentPage()` | 为每篇文章生成完整的 HTML 页面 |
| `folderPage.tsx` | `Plugin.FolderPage()` | 为每个文件夹生成索引列表页 |
| `tagPage.tsx` | `Plugin.TagPage()` | 为每个标签生成标签聚合页 |
| `contentIndex.tsx` | `Plugin.ContentIndex()` | 生成全局内容索引（JSON 格式），用于搜索和站点地图 |
| `aliases.ts` | `Plugin.AliasRedirects()` | 为文章的别名（aliases）生成 HTML 重定向页面 |
| `assets.ts` | `Plugin.Assets()` | 复制 content 目录中的非 Markdown 文件（图片等）到输出目录 |
| `static.ts` | `Plugin.Static()` | 复制 quartz/static/ 目录中的静态资源到输出目录 |
| `favicon.ts` | `Plugin.Favicon()` | 处理站点图标（favicon） |
| `cname.ts` | `Plugin.CNAME()` | 生成 CNAME 文件（用于自定义域名部署） |
| `ogImage.tsx` | `Plugin.CustomOgImages()` | 使用 Satori 为每篇文章自动生成社交分享封面图 |
| `componentResources.ts` | `Plugin.ComponentResources()` | 收集组件所需的 CSS 和 JS 资源 |
| `404.tsx` | `Plugin.NotFoundPage()` | 生成 404 错误页面 |

## 五、quartz/processors/ —— 构建管线处理器

处理器是构建流程的三个核心阶段，每个阶段对应一个文件：

| 文件 | 阶段 | 功能 |
|------|------|------|
| `parse.ts` | 解析阶段 | 读取 `.md` 文件，经过 remark 插件链将文本转为 Markdown AST，再经过 rehype 插件链转为 HTML AST。支持多线程并行处理 |
| `filter.ts` | 过滤阶段 | 遍历所有解析后的内容，依次执行 filter 插件的 `shouldPublish` 方法，移除不应发布的文件 |
| `emit.ts` | 发射阶段 | 依次执行所有 emitter 插件，将处理后的内容生成最终的 HTML、CSS、JS 等文件到输出目录 |

三者的协作流程如下：

```typescript
// 简化的构建流程
const files = scanContentDir()        // 扫描 content/ 目录
const parsed = await parseMarkdown(files)   // parse.ts: 文本 -> AST
const filtered = filterContent(parsed)       // filter.ts: 过滤掉草稿等
await emitContent(filtered)                  // emit.ts: 生成静态文件
```

## 六、quartz/styles/ —— 全局样式目录

| 文件 | 职责 |
|------|------|
| `variables.scss` | 定义全局 SCSS 变量：断点（mobile: 800px, desktop: 1200px）、栅格布局模板、侧栏宽度（380px）等 |
| `base.scss` | 基础样式重置和核心排版规则，定义了页面布局的 CSS Grid 系统、通用排版样式、链接/引用/列表等基础元素样式 |
| `custom.scss` | **用户自定义样式文件**。你所有的样式修改都应该写在这里。它引入了 base.scss，所以可以覆盖和扩展任何基础样式 |
| `callouts.scss` | Callout（提示框）组件的样式，支持 note、warning、tip 等多种类型 |
| `syntax.scss` | 代码高亮相关的辅助样式 |

> **最佳实践**：永远不要修改 `base.scss` 和 `variables.scss`（它们是 Quartz 引擎的一部分，升级时会被覆盖）。所有自定义样式都写在 `custom.scss` 中。

## 十、docs/ —— 官方文档副本

`docs/` 目录是 Quartz 官方文档的副本，用于构建 Quartz 自身的文档站点。在日常开发中你通常不需要修改这个目录，但它是学习 Quartz 功能和插件用法的优质参考。

文档覆盖了以下主题：

- `configuration.md` —— 配置文件详解
- `layout.md` / `layout-components.md` —— 布局和组件说明
- `authoring content.md` —— 内容编写指南
- `build.md` —— 构建命令和部署
- `features/` —— 各功能特性说明（搜索、图谱、i18n、暗色模式等）
- `plugins/` —— 所有插件的配置参数说明
- `advanced/` —— 高级主题（架构、自定义组件、自定义插件、路径系统）

理解了这些目录结构后，你就清楚地知道：想改内容就去 `content/`，想改外观就去 `quartz/styles/custom.scss` 和 `quartz.layout.ts`，想改配置就编辑 `quartz.config.ts`。接下来，我们就来写第一篇博客文章。
