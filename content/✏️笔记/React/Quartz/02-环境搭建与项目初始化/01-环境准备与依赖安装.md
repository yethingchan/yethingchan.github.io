在开始搭建 Quartz 博客之前，我们需要先准备好开发环境。本教程将带你从零开始，完成 Node.js 安装、项目克隆、依赖安装和基础配置的全部流程。

## 一、安装 Node.js（版本 >= 22）

Quartz v4.5.2 要求 Node.js 版本不低于 22，同时在 `package.json` 中也要求 npm >= 10.9.2。请务必确认你的 Node.js 版本满足要求，否则构建时会直接报错。

### 为什么需要 Node.js >= 22？

Quartz 的构建管线重度依赖 unified 生态（remark/rehype 系列）进行 Markdown 到 HTML 的 AST 转换，同时使用 esbuild 进行快速的代码打包和 SCSS 编译。Node.js 22 提供了更好的 ES Module 支持和性能优化，是项目正常运行的最低要求。

### Windows 用户推荐使用 nvm-windows

nvm-windows（Node Version Manager for Windows）可以让你在多个 Node.js 版本之间自由切换，非常方便。安装步骤如下：

1. 前往 [nvm-windows 的 GitHub Releases 页面](https://github.com/coreybutler/nvm-windows/releases)，下载最新版的 `nvm-setup.exe`
2. 运行安装程序，一路默认选项即可完成安装
3. 安装完成后，打开新的终端窗口，执行以下命令安装并启用 Node.js 22：

```powershell
# 安装 Node.js 22 的最新 LTS 版本
nvm install 22.16.0

# 切换到该版本
nvm use 22.16.0
```

4. 验证安装是否成功：

```powershell
node -v
# 应输出 v22.x.x

npm -v
# 应输出 10.x.x
```

> **提示**：如果终端显示 `nvm` 不是可识别的命令，请关闭当前终端窗口，重新打开一个新窗口再试。nvm-windows 安装时会修改系统环境变量，需要新终端才能生效。

### macOS / Linux 用户

macOS 和 Linux 用户推荐使用 [nvm](https://github.com/nvm-sh/nvm)（注意：这是 nvm-windows 对应的原版 nvm，不是同一个项目）：

```bash
# 安装 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

# 安装 Node.js 22
nvm install 22

# 使用该版本
nvm use 22
```

## 二、克隆 Quartz 模板仓库

Quartz 官方提供了一个初始化模板，我们基于这个模板来创建自己的博客项目。

```bash
# 克隆 Quartz 模板到本地
npx quartz create

# 或者手动克隆后删除 .git 目录重新初始化
git clone https://github.com/jackyzha0/quartz.git
cd quartz
rm -rf .git
git init
```

执行 `npx quartz create` 时，CLI 会引导你选择一个目录名，然后自动从官方模板复制文件。如果你已有项目（就像当前这个博客），可以跳过这步，直接进入项目目录即可。

本项目使用的 Quartz 版本为 v4.5.2，可以在 `package.json` 中的 `"version": "4.5.2"` 字段确认。

## 三、安装项目依赖

进入项目根目录后，运行以下命令安装全部依赖：

```bash
npm install
```

> **为什么用 npm 而不是 pnpm 或 yarn？** 项目根目录下有 `package-lock.json` 文件，说明作者使用 npm 管理依赖。`package-lock.json` 锁定了每个依赖包的精确版本号，能保证所有协作者安装完全相同的依赖树。如果你使用其他包管理器，可能会因为解析逻辑不同导致版本差异，从而引发难以排查的构建问题。因此强烈建议统一使用 npm。

安装完成后，`node_modules` 目录中会下载约 300 多个包。核心依赖的功能我们稍后会详细介绍。

## 四、quartz.config.ts —— 全局配置文件

这是 Quartz 最重要的配置文件，位于项目根目录。它导出一个 `QuartzConfig` 类型的对象，包含 `configuration`（全局设置）和 `plugins`（插件链）两大部分。

以下是一份简化后的配置示例，附带注释：

```typescript
import { QuartzConfig } from "./quartz/cfg"
import * as Plugin from "./quartz/plugins"

const config: QuartzConfig = {
  configuration: {
    // 博客标题，会显示在浏览器标签页和页面头部
    pageTitle: "我的博客",
    // 标题后缀，格式为 "pageTitle + pageTitleSuffix"
    pageTitleSuffix: " | 技术笔记",

    // 是否启用单页应用模式（SPA），开启后页面切换不会白屏闪烁
    enableSPA: true,
    // 是否启用链接悬浮预览（类似维基百科的 popover 效果）
    enablePopovers: true,

    // 部署域名，用于生成 sitemap、RSS feed 和 CNAME 等需要绝对 URL 的场景
    // 不需要加 https:// 前缀
    baseUrl: "yethingchan.github.io",

    // 忽略的文件/文件夹模式（glob 语法）
    // 匹配到的内容不会被构建处理
    ignorePatterns: ["private", "templates", ".obsidian"],

    // 语言区域设置，影响日期格式和 UI 文本
    // 格式遵循 BCP 47 标准
    locale: "zh-CN",

    // 默认日期类型：使用 "created"（创建时间）、
    // "modified"（修改时间）还是 "published"（发布时间）
    defaultDateType: "modified",
  },
  plugins: {
    // 插件配置将在后续教程中详细讲解
    transformers: [],
    filters: [],
    emitters: [],
  },
}

export default config
```

各字段要点：

| 字段 | 说明 |
|------|------|
| `pageTitle` | 显示在浏览器标签页的站点名称 |
| `pageTitleSuffix` | 追加在标题后面的文字，如 " \| 技术笔记" |
| `baseUrl` | 部署域名，用于生成绝对 URL（sitemap/RSS/CNAME） |
| `ignorePatterns` | glob 匹配规则，被匹配的文件会被跳过 |
| `locale` | 语言区域，影响日期格式化和 UI 翻译 |
| `enableSPA` | 单页应用模式，页面切换更流畅 |
| `enablePopovers` | 链接悬浮预览功能 |

## 五、quartz.layout.ts —— 页面布局文件

这个文件定义了博客的页面布局结构。Quartz 将页面分为多个区域，每个区域可以放置不同的组件。

```typescript
import { PageLayout, SharedLayout } from "./quartz/cfg"
import * as Component from "./quartz/components"

// 所有页面共享的组件
export const sharedPageComponents: SharedLayout = {
  head: Component.Head(),       // <head> 标签内容（meta、CSS 引入等）
  header: [],                   // 页面顶部区域（本项目留空）
  footer: Component.Footer(),   // 页脚
  afterBody: [],                // body 末尾（可放回到顶部按钮等）
}

// 单篇文章页面的布局
export const defaultContentPageLayout: PageLayout = {
  beforeBody: [
    Component.Breadcrumbs(),    // 面包屑导航
    Component.ArticleTitle(),   // 文章标题
    Component.ContentMeta(),    // 日期、阅读时间等元信息
    Component.TagList(),        // 标签列表
  ],
  left: [
    Component.PageTitle(),     // 左侧栏站点名称
    Component.Search(),         // 全站搜索
    Component.Explorer(),       // 文件/文件夹浏览树
  ],
  right: [
    Component.Graph(),          // 站点关系图谱（D3.js 驱动）
    Component.TableOfContents(), // 右侧目录
    Component.Backlinks(),      // 反向链接
  ],
}
```

布局区域说明：

- `head`：HTML `<head>` 部分，负责引入样式、脚本和 meta 标签
- `beforeBody`：正文内容上方，通常放标题、元信息和导航
- `left`：左侧边栏，放置搜索、文件浏览树等导航组件
- `right`：右侧边栏，放置目录、关系图谱等辅助组件
- `afterBody`：正文内容下方，可放评论、回到顶部等
- `footer`：页脚，显示版权信息等

## 六、关键依赖说明

`package.json` 中包含大量依赖，以下是核心依赖的功能说明：

| 依赖包 | 作用 |

| `preact` | 轻量级 React 替代品（仅 3KB），用于服务端渲染页面组件 |

| `remark-gfm` | GitHub Flavored Markdown 支持（表格、删除线、任务列表等） |
| `remark-math` | Markdown 数学公式语法解析（`$...$` 和 `$$...$$`） |

| `gray-matter` | 解析 Markdown 文件中的 Frontmatter（YAML 格式的元数据） |
| `satori` | 将 JSX 转为 SVG，用于自动生成 Open Graph 社交分享图片 |
| `sharp` | 高性能图片处理库，用于图片裁剪和格式转换 |

## 七、常见环境问题排查

### 问题 1：Node.js 版本不满足要求

**症状**：运行 `npm install` 或 `npx quartz build` 时报错，提示 `ERR_MODULE_NOT_FOUND` 或其他模块错误。

**排查方法**：

```powershell
# 检查当前 Node.js 版本
node -v

# 如果版本低于 22，使用 nvm 切换
nvm install 22
nvm use 22
```

### 问题 2：端口被占用

**症状**：运行 `npx quartz build --serve` 时提示 `Port 8080 is already in use`。

**解决方法**：

```powershell
# 方法一：查看并终止占用 8080 端口的进程
netstat -ano | findstr :8080
# 找到 PID 后终止
taskkill /PID <进程ID> /F

# 方法二：使用其他端口启动
npx quartz build --serve --port 3000
```

### 问题 3：npm install 安装失败

**症状**：网络超时或依赖下载失败，常见于国内网络环境。

**解决方法**：

```bash
# 切换到国内镜像源
npm config set registry https://registry.npmmirror.com

# 然后重新安装
rm -rf node_modules package-lock.json
npm install
```

### 问题 4：构建时 SCSS 编译错误

**症状**：报错信息中包含 `sass` 或 `scss` 字样。

**解决方法**：确保安装了完整依赖，SCSS 编译由 `esbuild-sass-plugin` 和 `lightningcss` 处理，缺一不可：

```bash
npm install
```

### 问题 5：TypeScript 类型检查报错

**症状**：编辑器中大量红色波浪线，但构建能正常通过。

**解决方法**：这通常是因为编辑器使用的 TypeScript 版本与项目不一致。在 VS Code 中按 `Ctrl+Shift+P`，输入 "TypeScript: Select TypeScript Version"，选择 "Use Workspace Version"。

## 八、验证环境是否就绪

完成以上步骤后，运行以下命令验证环境是否正确配置：

```bash
# 开发模式启动（带热重载）
npx quartz build --serve
```

如果一切正常，终端会输出类似如下信息：

```
Compiling SCSS...
Building 12 files...
Listening on http://localhost:8080
```

打开浏览器访问 `http://localhost:8080`，如果你能看到博客页面，说明环境搭建成功。按 `Ctrl+C` 可以停止开发服务器。
