Quartz 提供了一套完整的构建工具链，围绕 `npx quartz build` 命令展开。理解每一个参数的含义和工作原理，能帮助你建立高效、可预测的日常开发流程。

## 构建命令完整参数说明

`npx quartz build` 是整个项目构建的核心命令。通过查看 `quartz/cli/args.js` 中的 `BuildArgv` 定义，我们可以看到所有可用的参数：

### 基础参数

| 参数 | 简写 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--directory` | `-d` | string | `"content"` | 内容文件的源目录路径 |
| `--output` | `-o` | string | `"public"` | 构建输出的目标文件夹 |
| `--verbose` | `-v` | boolean | `false` | 打印额外的日志信息，用于调试 |

### 开发服务器参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--serve` | boolean | `false` | 启动本地 HTTP 服务器进行实时预览，同时自动开启 `--watch` |
| `--watch` | boolean | `false` | 监视文件变更并自动重新构建 |
| `--port` | number | `8080` | 指定开发服务器的监听端口 |
| `--wsPort` | number | `3001` | WebSocket 热重载通知端口 |
| `--baseDir` | string | `""` | 本地服务器的基础路径，适用于非根目录部署的预览 |
| `--remoteDevHost` | string | `""` | 远程开发时的 WebSocket 连接地址覆盖 |

### 性能与调试参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--concurrency` | number | 自动 | 内容解析的线程并发数 |
| `--bundleInfo` | boolean | `false` | 显示详细的打包信息，包含每个输入文件的体积分析 |

### 注意：--clean 的真实行为

在 Quartz v4.5.2 中，并没有独立的 `--clean` 参数。实际上，**每次 `npx quartz build` 执行时都会自动清理输出目录**。查看 `quartz/build.ts` 第 69-71 行可以确认这一点：

```typescript
await rm(output, { recursive: true, force: true })
console.log(`Cleaned output directory \`${output}\` in ${perf.timeSince("clean")}`)
```

也就是说，无论你是否手动添加 `--clean` 参数，`public/` 目录都会被完全清除后重新生成。

## 开发工作流推荐

### 本地开发循环

日常开发中最常用的工作流是**编辑-构建-预览**循环。推荐的步骤如下：

**第一步：启动开发服务器**

```bash
npx quartz build --serve
```

这一条命令完成了三件事：
1. 首次构建所有内容到 `public/` 目录
2. 启动 HTTP 服务器（默认 `http://localhost:8080`）
3. 开启文件监视（chokidar），检测到变更后自动增量构建

**第二步：编辑 Markdown 内容**

在 `content/` 目录中创建或编辑 `.md` 文件。例如，在 `content/笔记/` 下新建一篇笔记。

**第三步：浏览器自动刷新**

当你保存文件后，chokidar 检测到变更，触发增量构建。构建完成后通过 WebSocket 向浏览器发送 `rebuild` 信号，浏览器自动刷新页面。整个流程无需手动干预。

### 指定端口

如果 8080 端口被占用，可以使用 `--port` 参数指定其他端口：

```bash
npx quartz build --serve --port 3000
```

### 增量构建机制

当进入 `--serve` 或 `--watch` 模式后，后续的变更会触发**增量构建**而非全量构建。核心逻辑在 `quartz/build.ts` 的 `rebuild` 函数中：

1. `chokidar` 监听 `content/` 目录中的文件变更事件（`add`、`change`、`unlink`）
2. 记录 `changesSinceLastBuild` 变更集合
3. 仅重新解析发生变更的 Markdown 文件
4. 对支持 `partialEmit` 的 Emitter 插件（如 `ContentPage`），只重新生成受影响页面的 HTML
5. 对不支持 `partialEmit` 的 Emitter（如 `Static`、`Assets`），仍使用完整的 `emit` 方法

这种增量机制在内容文件较多时能显著缩短重新构建的时间。

### 项目自定义脚本

在本项目的 `package.json` 中，已经预设了便捷脚本：

```json
"scripts": {
  "quartz": "./quartz/bootstrap-cli.mjs",
  "local": "npx quartz build --serve",
  "docs": "npx quartz build --serve -d docs"
}
```

因此你也可以直接使用：

```bash
npm run local        # 等同于 npx quartz build --serve
npm run docs         # 以 docs 目录为内容源启动开发服务器
```

## 构建性能数据参考

以本项目为例，在普通开发机器上执行全量构建：

- **输入**：约 152 个 Markdown 文件（含教程、笔记等所有内容）
- **输出**：约 208 个 HTML 文件 + 静态资源
- **全量构建时间**：约 20-30 秒（取决于机器性能）
- **增量构建时间**：通常在 2-5 秒内（仅重新生成变更涉及的页面）

## 常见构建错误排查

### LaTeX incompatible input 警告

当使用 KaTeX 渲染包含不兼容 LaTeX 语法的内容时，会出现类似以下警告：

```
LaTeX incompatible input: '...' 
```

**解决方法**：检查 Markdown 中的行内公式（`$...$`）和块级公式（`$$...$$`），确保语法符合 KaTeX 规范。常见的错误包括：
- 在数学模式中使用了不支持的命令
- 公式中包含未转义的特殊字符（如 `_`、`^` 在数学模式外使用）

### 端口被占用

如果启动 `--serve` 时提示端口已被占用：

```
Error: listen EADDRINUSE: address already in use :::8080
```

**解决方法**：

方法一：指定其他端口
```bash
npx quartz build --serve --port 3000
```

方法二：查找并终止占用进程（以 Windows 为例）
```powershell
# 查找占用 8080 端口的进程
netstat -ano | findstr :8080
# 终止对应 PID 的进程
taskkill /PID <进程ID> /F
```

### TypeScript 编译错误

修改 `quartz/` 目录下的 TypeScript 源文件后，如果出现编译错误：

```
Couldn't parse Quartz configuration: quartz/config.ts
```

**解决方法**：
1. 确认 TypeScript 语法正确，运行 `npx tsc --noEmit` 检查类型错误
2. 检查 `quartz.config.ts` 和 `quartz.layout.ts` 中导入的组件路径是否正确
3. 如果修改了插件接口，确认实现符合 `QuartzTransformerPluginInstance` 或 `QuartzEmitterPluginInstance` 的类型定义

### SCSS 编译错误

修改 `.scss` 文件后出现编译错误：

```
Error: expected "{" but found "..."
```

**解决方法**：
1. 确认 SCSS 语法正确（注意使用正确的缩进和大括号）
2. 自定义样式应写入 `quartz/styles/custom.scss`，而不是修改核心 SCSS 文件
3. 使用 `@use` 导入其他样式文件而非 `@import`（已废弃）

## 构建优化技巧

### 使用 ignorePatterns 排除不需要的文件

在 `quartz.config.ts` 中配置 `ignorePatterns`，可以让构建过程跳过不需要处理的文件或目录：

```typescript
// quartz.config.ts
configuration: {
  ignorePatterns: ["private", "templates", ".obsidian"],
}
```

本项目的配置排除了 `private`（私有笔记）、`templates`（模板文件）和 `.obsidian`（Obsidian 配置目录）。你还可以添加更多模式：

```typescript
ignorePatterns: [
  "private",
  "templates",
  ".obsidian",
  "drafts/**",       // 排除所有草稿
  "**/*.draft.md",   // 排除以 .draft.md 结尾的文件
  "archive/**",      // 排除归档内容
],
```

注意：`ignorePatterns` 使用的是 minimatch glob 模式匹配，支持 `**`、`*`、`?` 等通配符。

### 并发数控制

在性能较差的机器上，可以通过 `--concurrency` 限制内容解析的线程数：

```bash
npx quartz build --concurrency 1
```

本项目在 `package.json` 中还提供了一个性能分析脚本：

```json
"profile": "0x -D prof ./quartz/bootstrap-cli.mjs build --concurrency=1"
```

这会使用 0x 工具生成构建过程的 CPU 火焰图，帮助定位性能瓶颈。

### 小结

掌握 `npx quartz build` 的各种参数和构建机制，是高效开发 Quartz 博客的基础。日常开发中，`npm run local`（即 `npx quartz build --serve`）是最常用的命令，它提供了完整的编辑-预览循环。遇到构建问题时，善用 `--verbose` 参数获取详细日志，是快速定位问题的关键。
