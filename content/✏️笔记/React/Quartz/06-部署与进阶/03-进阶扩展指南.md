## 自定义主题配色

Quartz 提供了完整的亮色/暗色双主题支持。在 `quartz.config.ts` 的 `theme.colors` 中定义：

```typescript
// quartz.config.ts
theme: {
  colors: {
    lightMode: {
      light: "#faf8f8",       // 页面背景（最浅色）
      lightgray: "#e5e5e5",   // 次浅灰色
      gray: "#b8b8b8",        // 中间灰色
      darkgray: "#4e4e4e",    // 次深灰色
      dark: "#2b2b2b",        // 主要文本色（最深色）
      secondary: "#284b63",   // 链接、按钮等强调色
      tertiary: "#84a59d",    // 辅助强调色
      highlight: "rgba(143, 159, 169, 0.15)",  // 高亮背景
      textHighlight: "#fff23688",               // 文本高亮标记
    },
    darkMode: {
      light: "#161618",       // 暗色模式背景
      lightgray: "#393639",
      gray: "#646464",
      darkgray: "#d4d4d4",
      dark: "#ebebec",        // 暗色模式主要文本色
      secondary: "#7b97aa",
      tertiary: "#84a59d",
      highlight: "rgba(143, 159, 169, 0.15)",
      textHighlight: "#b3aa0288",
    },
  },
}
```

### 配色设计建议

- `light`/`dark` 分别代表两种模式下"页面最浅/最深"的底色
- `secondary` 是最重要的强调色，用于链接、标签、交互元素，选择一个与主色调对比明显但和谐的色值
- `highlight` 使用半透明 rgba 值，这样在不同背景上都能自然融合
- 修改配色后运行 `npx quartz build --serve` 实时预览效果

本项目采用了一套偏蓝灰的配色方案，暗色模式的背景使用了深色调，与自定义的渐变背景和星空效果形成整体视觉统一。

## 自定义字体

本项目的字体配置是一个很好的实践案例。我们使用了「霞鹜文楷」作为全站字体：

### 第一步：添加字体文件

将字体文件放在 `quartz/static/fonts/` 目录下：

```
quartz/static/fonts/
└── LXGWWenKaiScreen.woff2    # Web 开放字体格式，体积小、加载快
```

使用 `.woff2` 格式而非 `.ttf` 或 `.otf`，因为 woff2 的压缩率更高，通常能减少 30-50% 的文件体积。

### 第二步：声明 @font-face

在 `quartz/styles/custom.scss` 中添加字体声明：

```scss
@font-face {
  font-family: "LXGWWenKaiScreenR";
  src: url("/static/fonts/LXGWWenKaiScreen.woff2") format("woff2");
  font-display: swap;  // 确保字体加载期间显示系统字体，避免不可见文本
}
```

`font-display: swap` 是关键的优化选项：它告诉浏览器在自定义字体尚未下载完成时先使用系统字体显示文本，字体下载完成后自动切换，避免"空白文本闪烁"（FOIT）问题。

### 第三步：应用字体到元素

```scss
body,
body .quartz-content,
body h1,
body h2,
body h3,
body h4,
body h5,
body h6 {
  font-family: "LXGWWenKaiScreenR";
}
```

### 第四步：配置 quartz.config.ts

在 `quartz.config.ts` 中声明字体名称，并设置为本地加载：

```typescript
theme: {
  fontOrigin: "local",        // 使用本地字体文件，不从 CDN 加载
  cdnCaching: false,
  typography: {
    header: "LXGWWenKaiScreenR",
    body: "LXGWWenKaiScreenR",
    code: "monospace",
  },
}
```

`fontOrigin: "local"` 和 `cdnCaching: false` 告诉 Quartz 不要从 Google Fonts CDN 加载默认字体，而是完全依赖我们在 `custom.scss` 中定义的 `@font-face`。

## 开发自定义 Transformer 插件

Transformer 插件用于在构建过程中转换 Markdown 内容，通过操作 MDAST（Markdown AST）或 HAST（HTML AST）树来实现自定义处理逻辑。

### QuartzTransformer 接口定义

查看 `quartz/plugins/types.ts` 中的类型定义：

```typescript
export type QuartzTransformerPluginInstance = {
  name: string
  textTransform?: (ctx: BuildCtx, src: string) => string
  markdownPlugins?: (ctx: BuildCtx) => PluggableList
  htmlPlugins?: (ctx: BuildCtx) => PluggableList
  externalResources?: ExternalResourcesFn
}
```

一个 Transformer 插件可以有四个功能入口：
- `textTransform`：在 Markdown 解析前对原始文本进行预处理
- `markdownPlugins`：添加 remark 插件，操作 MDAST 树
- `htmlPlugins`：添加 rehype 插件，操作 HAST 树
- `externalResources`：注入额外的 CSS/JS 资源

### 示例：自动为图片添加 lazy loading 属性

以下是一个完整的 Transformer 插件示例，它遍历 HAST 树，为所有 `<img>` 标签添加 `loading="lazy"` 属性：

```typescript
// quartz/plugins/transformers/lazyImages.ts
import { QuartzTransformerPlugin } from "../types"
import { visit } from "unist-util-visit"

export const LazyImages: QuartzTransformerPlugin = () => ({
  name: "LazyImages",
  htmlPlugins(ctx) {
    return [
      () => (tree) => {
        visit(tree, "element", (node) => {
          // 找到所有 img 元素
          if (node.tagName === "img") {
            // 确保 properties 对象存在
            node.properties = node.properties || {}
            // 添加 loading="lazy"
            node.properties.loading = "lazy"
          }
        })
      },
    ]
  },
})
```

然后在 `quartz/plugins/transformers/index.ts` 中导出并在 `quartz.config.ts` 中注册：

```typescript
// quartz/plugins/transformers/index.ts
export { LazyImages } from "./lazyImages"

// quartz.config.ts
transformers: [
  // ...其他 transformers
  Plugin.LazyImages(),
]
```

## 开发自定义 Emitter 插件

Emitter 插件负责将处理后的内容生成为最终的输出文件。

### QuartzEmitter 接口定义

```typescript
export type QuartzEmitterPluginInstance = {
  name: string
  emit: (
    ctx: BuildCtx,
    content: ProcessedContent[],
    resources: StaticResources,
  ) => Promise<FilePath[]> | AsyncGenerator<FilePath>
  partialEmit?: (
    ctx: BuildCtx,
    content: ProcessedContent[],
    resources: StaticResources,
    changeEvents: ChangeEvent[],
  ) => Promise<FilePath[]> | AsyncGenerator<FilePath> | null
  getQuartzComponents?: (ctx: BuildCtx) => QuartzComponent[]
  externalResources?: ExternalResourcesFn
}
```

关键点：
- `emit`：全量构建时调用，生成所有输出文件
- `partialEmit`：增量构建时调用，仅处理变更的文件。返回 `null` 表示该 emitter 不支持增量构建，会回退到 `emit`
- `getQuartzComponents`：声明该 emitter 使用了哪些组件，帮助 Quartz 优化资源加载（只包含必要的 CSS/JS）

### 示例：生成自定义的导航数据文件

```typescript
// quartz/plugins/emitters/navData.ts
import { QuartzEmitterPlugin } from "../types"
import { write } from "./helpers"

export const NavData: QuartzEmitterPlugin = () => ({
  name: "NavData",
  async emit(ctx, content) {
    // 从所有内容中提取导航结构
    const nav = []
    for (const [_tree, file] of content) {
      nav.push({
        title: file.data.title ?? "",
        slug: file.data.slug ?? "",
        tags: file.data.tags ?? [],
      })
    }

    // 写入 JSON 文件到 public/ 目录
    await write({
      ctx,
      content: JSON.stringify(nav, null, 2),
      slug: "nav-data",
      ext: ".json",
    })

    return ["nav-data.json"]
  },
})
```

## 性能优化策略

### 图片优化

**压缩与格式转换**：
- 使用 WebP 格式替代 PNG/JPEG，通常能减少 25-35% 的文件体积
- 使用 `squoosh-cli` 或 `sharp` 批量转换图片格式
- 对于屏幕截图类图片，使用有损 WebP（quality 80-85）即可获得很好的视觉质量

**Lazy Loading**：
- Quartz 默认不会为图片添加 `loading="lazy"` 属性，可以通过上面介绍的 Transformer 插件实现
- 对于首屏可见的关键图片，避免添加 lazy loading，以免延迟渲染

**响应式图片**：
- 使用 `srcset` 属性为不同屏幕宽度提供不同尺寸的图片
- 在 Markdown 中可以这样写：`![alt](image-800.webp#width=800)`

### CSS 优化

- Quartz 使用 esbuild 编译 SCSS 并自动压缩 CSS
- 自定义样式应写入 `quartz/styles/custom.scss`，esbuild 会将其与核心样式一起打包
- 避免在 custom.scss 中引入过大的第三方 CSS 库

### JavaScript 优化

- 内联脚本（`.inline.ts` 后缀的文件）会被 esbuild 编译并内联到 HTML 中
- 控制内联脚本的大小，过大的内联脚本会增加 HTML 文件体积
- 非关键的 JavaScript 逻辑应考虑异步加载

### 构建缓存

- 开发时使用 `--serve` 模式利用增量构建，避免每次修改都全量构建
- GitHub Actions 中通过 `cache: npm` 缓存 node_modules，加速 CI 构建

## SEO 优化

### Meta Description

Quartz 的 `Plugin.Description()` 会自动从 Markdown 内容中提取描述信息。它会优先使用 frontmatter 中的 `description` 字段，如果没有则取正文前 200 个字符。在 Markdown frontmatter 中添加：

```yaml
---
title: "C# async await 详解"
description: "深入理解 C# 中的异步编程模型，包括 Task、ValueTask、ConfigureAwait 等核心概念。"
---
```

### Open Graph 标签

Quartz 的 `Head` 组件会自动生成 Open Graph 标签，包括 `og:title`、`og:description`、`og:type` 等。如果你想自定义 OG 图片，可以启用 `Plugin.CustomOgImages()`（本项目出于构建速度考虑已注释掉）：

```typescript
// quartz.config.ts
emitters: [
  // ...
  // Plugin.CustomOgImages(),  // 取消注释即可启用
]
```

### Sitemap.xml

通过 `Plugin.ContentIndex({ enableSiteMap: true })` 自动生成。本项目已启用：

```typescript
Plugin.ContentIndex({
  enableSiteMap: true,
  enableRSS: true,
}),
```

构建后在 `public/sitemap.xml` 中生成完整的站点地图。

### RSS Feed

同样通过 `ContentIndex` 插件启用。生成的 RSS feed 位于 `public/index.xml`，包含所有文章的标题、链接、描述和发布时间。

### Robots.txt

本项目的 `quartz/static/robots.txt` 内容：

```
User-agent: *
Allow: /
Sitemap: https://yethingchan.github.io/sitemap.xml
```

如果你更换了域名，记得同步更新此文件中的 Sitemap URL。

## 内容管理策略

### 文件夹组织最佳实践

查看本项目的 `content/` 目录结构，可以看到清晰的分类体系：

```
content/
├── index.md              # 首页
├── 笔记/
│   ├── C sharp/          # 按技术领域分类
│   ├── Vue/
│   ├── Spring/
│   ├── 网络/
│   └── 若依/
│       ├── 前端/
│       └── 后端/
├── 📚READING/
└── 📱安卓开发/
```

建议的文件夹组织原则：
- 使用 Emoji 前缀对大类进行视觉分组（如 `📚`、`📱`、`✏️`）
- 按技术领域或主题建立一级分类
- 子层级不超过 3-4 层，过深的嵌套会影响 Explorer 的可读性
- 每个文件夹下放置一个 `index.md` 作为该分类的概述页

### Frontmatter 规范

建议为每篇 Markdown 文件编写完整的 frontmatter：

```yaml
---
title: "文章标题"              # 必填，显示在页面标题和搜索结果中
date: 2024-01-15              # 创建日期（可选，CreatedModifiedDate 插件可自动获取）
updated: 2024-03-20           # 修改日期（可选）
description: "简要描述"       # 用于 SEO 和搜索结果摘要
tags:
  - "C#"
  - ".NET"                    # 标签，用于标签聚合页
draft: true                   # 设为 true 时不发布（RemoveDrafts 插件会过滤）
aliases:
  - "旧路径/旧文件名"         # 旧 URL 重定向（AliasRedirects 插件）
---
```

### 标签体系设计

- 使用扁平化的标签体系，避免层级标签
- 每篇文章 2-5 个标签为佳
- 标签名统一使用中文或英文，不要混用
- 利用 Quartz 的 `TagPage` 插件自动生成标签聚合页

### 搜索优化

- 文章标题应简洁明确，包含核心关键词
- `description` 字段应准确概括文章内容，这是搜索结果中显示的摘要文本
- 使用合理的标题层级（h1 > h2 > h3），Quartz 的 `TableOfContents` 插件会自动生成目录
- 善用 `[[wikilinks]]` 和 `aliases` 建立文章间的关联，Quartz 的 `Backlinks` 组件会在每篇文章底部显示反向链接

## 项目维护

### Quartz 版本升级

Quartz 的升级使用 `npx quartz update` 命令（对应 `quartz/cli/handlers.js` 中的 `handleUpdate` 函数）。升级流程：

1. 自动备份 `content/` 目录
2. 从上游仓库拉取最新代码
3. 恢复 `content/` 目录
4. 运行 `npm i` 更新依赖

```bash
npx quartz update
```

如果升级后出现冲突（比如你修改了 `quartz/` 下的核心文件），需要手动解决 git 冲突。

### 依赖更新

定期检查并更新项目依赖：

```bash
# 检查可更新的依赖
npm outdated
# 更新所有依赖（保守更新）
npm update
# 更新到最新主版本（谨慎使用）
npx npm-check-updates -u && npm i
```

### 备份策略

- **内容备份**：`content/` 目录是你的核心资产，确保它始终被 git 追踪
- **配置备份**：`quartz.config.ts`、`quartz.layout.ts` 和 `quartz/styles/custom.scss` 是个性化配置的核心文件
- **Git 分支管理**：在进行重大配置变更前，创建新分支进行实验，确认无误后再合并到 main

本项目还提供了一个 Windows 批处理脚本 `自动提交Github.bat`，用于快速提交和推送变更，减少了手动执行 git 命令的步骤。
