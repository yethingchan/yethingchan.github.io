## 实时数据推送

工业物联网上位机的核心价值之一是实时展示设备运行数据。IoTGateway通过MQTT WebSocket桥接技术，将设备采集的变量数据以毫秒级延迟推送到浏览器端，实现了类似SCADA系统的实时监控体验。本章深入解析这套实时数据推送的完整链路和实现细节。

## 实时通信方案对比

在Web应用中实现实时数据推送，有以下几种常见方案：

| 方案 | 原理 | 延迟 | 适用场景 |
|------|------|------|---------|
| HTTP轮询 | 客户端定时请求 | 秒级 | 低频数据更新 |
| 长轮询 | 服务端挂起请求直到有数据 | 百毫秒级 | 中等实时性 |
| SSE | 服务端单向推送 | 毫秒级 | 单向通知 |
| WebSocket | 全双工通信 | 毫秒级 | 高频双向通信 |
| MQTT over WS | MQTT协议封装在WebSocket上 | 毫秒级 | IoT设备数据推送 |

IoTGateway选择了**MQTT over WebSocket**方案，这是因为：
1. 系统本身已经内置了MQTT Broker（MQTTnet），无需额外引入WebSocket服务
2. MQTT的发布/订阅模型天然适合"设备数据 -> 多个观察者"的场景
3. MQTT主题（Topic）机制便于按变量粒度订阅，减少不必要的数据传输

## 架构原理

```
设备/PLC                   IoTGateway内部                    浏览器
+--------+    Modbus/      +-------------+     MQTT         +---------+
| 传感器  | ──→ OPC UA ──→ | 驱动采集层   | ──→ over ──→    | MQTT.js |
| 仪表   │                 | (后台服务)   │     WebSocket    | 客户端  │
+--------+                 +-------------+                   +---------+
                                 │                              │
                                 │ 发布到内部Topic               │ 订阅Topic
                                 ▼                              ▼
                           +-------------+              +-------------+
                           | MQTT Broker  |              | DOM更新     |
                           | (MQTTnet)   |              | 动画效果    |
                           +-------------+              +-------------+
```

**数据流向：**
1. 驱动层从PLC/仪表采集数据
2. 后台服务将数据发布到内部MQTT Topic
3. 浏览器中的MQTT.js客户端订阅对应Topic
4. 收到消息后解析JSON并更新DOM元素

## MQTT Topic设计

IoTGateway为实时数据推送设计了统一的Topic格式：

```
internal/v1/gateway/telemetry/{deviceId}/{varName}
```

- `internal/v1/` - 内部消息前缀，区别于外部MQTT通信
- `gateway/telemetry/` - 遥测数据类型
- `{deviceId}` - 设备ID（使用`+`通配符匹配任意设备）
- `{varName}` - 变量名称

例如：
- `internal/v1/gateway/telemetry/dev001/Temperature` - 设备dev001的温度变量
- `internal/v1/gateway/telemetry/dev001/Pressure` - 设备dev001的压力变量

## MQTT.js客户端集成

### 引入MQTT.js

在设备变量页面（`DeviceVariable/Index.cshtml`）中引入MQTT.js库：

```html
<link href="~/sitecss/animate.min.css" rel="stylesheet" />
<script src="~/mqtt.min.js" type="text/javascript"></script>
```

`mqtt.min.js`存放在`wwwroot/`目录下，`animate.min.css`提供数据更新时的动画效果。

### 建立WebSocket连接

```javascript
var options = {
    clientId: 'iotgatewayInternal_' + (Math.random()),
    clean: true
};
var client = mqtt.connect('ws://' + window.location.host + '/mqtt', options);
```

**关键配置说明：**

| 配置项 | 说明 |
|--------|------|
| `clientId` | 客户端唯一标识，加随机数防止多标签页冲突 |
| `clean` | true表示不保留离线消息，每次连接获取最新数据 |
| 连接地址 | `ws://当前域名/mqtt`，复用HTTP服务器的WebSocket端口 |

### WebSocket端点配置

在`Startup.cs`中，MQTT WebSocket端点通过MQTTnet配置：

```csharp
// 注册MQTT服务
services.AddHostedMqttServer(mqttServer => 
    mqttServer.WithoutDefaultEndpoint())
    .AddMqttConnectionHandler()
    .AddConnections();

// 映射WebSocket端点
app.UseEndpoints(endpoints => {
    endpoints.MapMqtt("/mqtt");
});
```

同时在`Program.cs`中，Kestrel配置了MQTT专用端口：

```csharp
webBuilder.UseKestrel(option => {
    option.ListenAnyIP(1888, l => l.UseMqtt());  // MQTT TCP端口
    option.ListenAnyIP(518);                      // HTTP端口(含WebSocket)
});
```

## 数据订阅机制

### 订阅时机

IoTGateway的一个精妙设计是：在表格渲染完成后自动订阅当前页面显示的变量。这通过`<wt:grid>`的`done-func`回调实现：

```cshtml
<wt:grid vm="@Model" 
         url="/BasicData/DeviceVariable/Search" 
         hidden-grid-index="true" 
         done-func="subTopics" />
```

### 订阅逻辑

```javascript
// 已订阅topic列表
var subedTopics = null;

function subTopics() {
    // 1. 取消以前的订阅
    if (subedTopics) {
        client.unsubscribe(subedTopics, function (err) {
            if (!err) {
                console.log('取消订阅成功!');
            } else {
                console.error('取消订阅失败:', err);
            }
        });
    }

    // 2. 从DOM中提取当前表格的变量名
    const variableNames = Array.from(
        document.querySelectorAll('td[data-field="Name"]')
    ).map(el => el.getAttribute('data-content'));

    // 3. 构造MQTT Topic列表
    let topics = variableNames.map(
        v => "internal/v1/gateway/telemetry/+/" + v
    );

    // 4. 批量订阅
    client.subscribe(topics, function (err) {
        if (!err) {
            subedTopics = topics;
            console.log("订阅成功!");
        } else {
            console.log(err);
        }
    });
}
```

**设计要点：**

1. **按需订阅** - 只订阅当前页面可见的变量，避免全量订阅导致消息风暴
2. **先取消后订阅** - 翻页或筛选后重新订阅，避免旧数据干扰
3. **通配符使用** - `+`通配符匹配任意设备ID，简化订阅逻辑
4. **DOM驱动** - 从渲染后的表格DOM中提取变量名，确保订阅与显示一致

## 消息处理与DOM更新

### 消息格式

MQTT消息的Payload为JSON格式：

```json
{
    "VarId": "abc123",
    "Value": "25.6",
    "CookedValue": "25.6",
    "StatusType": "Good",
    "Timestamp": "2024-01-15 14:30:22",
    "Message": ""
}
```

| 字段 | 说明 |
|------|------|
| `VarId` | 变量唯一标识 |
| `Value` | 原始采集值 |
| `CookedValue` | 经过缩放/转换后的工程值 |
| `StatusType` | 数据质量状态（Good/Bad/Uncertain） |
| `Timestamp` | 采集时间戳 |
| `Message` | 附加信息（如错误描述） |

### DOM更新逻辑

```javascript
client.on('message', function (topic, message) {
    var objmsg = $.parseJSON(message.toString());

    // 更新原值
    $('#id' + objmsg.VarId + '_Value').text(objmsg.Value);
    $('#id' + objmsg.VarId + '_Value').addClass('animated bounceIn');
    setTimeout(function () {
        $('#id' + objmsg.VarId + '_Value').removeClass('bounceIn');
    }, 1500);

    // 更新加工值
    $('#id' + objmsg.VarId + '_CookedValue').text(objmsg.CookedValue);
    $('#id' + objmsg.VarId + '_CookedValue').addClass('animated bounceIn');
    setTimeout(function () {
        $('#id' + objmsg.VarId + '_CookedValue').removeClass('bounceIn');
    }, 1500);

    // 更新状态
    $('#id' + objmsg.VarId + '_State').text(objmsg.StatusType);
    $('#id' + objmsg.VarId + '_State').addClass('animated bounceIn');
    setTimeout(function () {
        $('#id' + objmsg.VarId + '_State').removeClass('bounceIn');
    }, 1500);

    // 更新时间戳
    $('#id' + objmsg.VarId + '_Timestamp').text(objmsg.Timestamp);
    $('#id' + objmsg.VarId + '_Timestamp').addClass('animated bounceIn');
    setTimeout(function () {
        $('#id' + objmsg.VarId + '_Timestamp').removeClass('bounceIn');
    }, 1500);

    // 更新消息
    $('#id' + objmsg.VarId + '_Message').text(objmsg.Message);
    $('#id' + objmsg.VarId + '_Message').addClass('animated bounceIn');
    setTimeout(function () {
        $('#id' + objmsg.VarId + '_Message').removeClass('bounceIn');
    }, 1500);
});
```

### DOM元素ID约定

WTM表格渲染时为每个单元格生成了约定格式的ID：

```
id{VarId}_{FieldName}
```

例如：
- `idabc123_Value` - 变量abc123的原始值单元格
- `idabc123_CookedValue` - 变量abc123的加工值单元格
- `idabc123_State` - 变量abc123的状态单元格
- `idabc123_Timestamp` - 变量abc123的时间戳单元格
- `idabc123_Message` - 变量abc123的消息单元格

jQuery选择器通过拼接VarId和字段名，精确定位到需要更新的DOM元素。

## 动画效果

数据更新时使用了CSS3动画（`animate.min.css`）提供视觉反馈：

```javascript
// 添加bounceIn动画类
$('#id' + objmsg.VarId + '_Value').addClass('animated bounceIn');

// 1.5秒后移除动画类，为下次更新做准备
setTimeout(function () {
    $('#id' + objmsg.VarId + '_Value').removeClass('bounceIn');
}, 1500);
```

**动画效果说明：**
- `bounceIn` - 数据变化时弹性跳入效果
- 持续1.5秒后自动移除，避免影响后续更新
- 让操作人员能够快速注意到哪个数据发生了变化

在实际工业场景中，还可以考虑：

```javascript
// 根据数据质量状态变色
if (objmsg.StatusType === 'Bad') {
    $('#id' + objmsg.VarId + '_State')
        .css('color', 'red')
        .addClass('animated shake');
} else {
    $('#id' + objmsg.VarId + '_State')
        .css('color', 'green');
}

// 根据值范围报警
var value = parseFloat(objmsg.CookedValue);
if (value > 100) {
    $('#id' + objmsg.VarId + '_Value')
        .css('background-color', '#ffebee');
}
```

## 连接状态管理

在实际生产环境中，网络可能不稳定。建议增加连接状态管理：

```javascript
// 连接成功
client.on('connect', function () {
    console.log('MQTT连接成功');
    layer.msg('实时数据已连接', { icon: 1, time: 1000 });
    subTopics(); // 连接成功后重新订阅
});

// 连接断开
client.on('close', function () {
    console.log('MQTT连接断开');
    layer.msg('实时数据已断开，正在重连...', { icon: 2 });
});

// 连接错误
client.on('error', function (error) {
    console.error('MQTT错误:', error);
});

// 重连
client.on('reconnect', function () {
    console.log('正在重连...');
});
```

## 写入（反向控制）

除了读取实时数据，IoTGateway还支持通过页面下发控制命令。在`SetValue.cshtml`中：

```cshtml
<wt:form vm="@Model" Url="/BasicData/DeviceVariable/DoSetValue">
    <wt:row items-per-row="ItemsPerRowEnum.One">
        @if (@Model.SetValues.Any())
        {
            foreach (var setValue in @Model.SetValues)
            {
                <hr class="layui-border-blue">
                <wt:quote>@setValue.DeviceName/@setValue.Name：
                    【原值：@setValue.RawValue】=>【计算值：@setValue.Value】</wt:quote>
                <div style="display: none">
                    <wt:textbox field=@setValue.ID />
                </div>
                <wt:textbox field=@setValue.SetRawValue/>
            }
        }
    </wt:row>
    <wt:row align="AlignEnum.Right">
        <wt:submitbutton text="下发" />
        <wt:closebutton text="取消" />
    </wt:row>
</wt:form>
```

这个表单展示了变量的原始值和计算值，用户输入新的原始值后点击"下发"，系统通过RPC机制将值写入设备。

## 性能考量

在大规模部署时需要注意：

1. **Topic数量** - 每个变量一个Topic，1000个变量意味着1000个订阅
2. **消息频率** - 高频采集（如100ms周期）可能导致浏览器处理压力
3. **内存管理** - 长时间运行需要关注DOM节点的内存泄漏
4. **并发连接** - 多个浏览器标签页各建立一个MQTT连接

**优化建议：**
- 控制采集周期，非关键变量可以降低频率
- 使用虚拟滚动处理大量表格行
- 页面不可见时暂停订阅（利用`document.visibilityState`）

## 小结

IoTGateway通过MQTT WebSocket实现了从设备到浏览器的毫秒级实时数据推送。整个链路基于发布/订阅模型，通过精心设计的Topic格式和DOM元素ID约定，实现了精准的数据绑定和动画反馈。这种架构既利用了MQTT的轻量级特性，又通过WebSocket突破了传统HTTP的单向限制，是工业物联网上位机实时通信的优秀实践。
