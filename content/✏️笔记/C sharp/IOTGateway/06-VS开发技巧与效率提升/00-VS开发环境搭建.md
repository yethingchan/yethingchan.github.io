## 为什么选择 Visual Studio 2022

对于上位机开发而言，Visual Studio 2022（以下简称 VS 2022）是目前最强大的 .NET 开发 IDE。IoTGateway 项目基于 .NET 8.0 构建，VS 2022 提供了完整的 .NET 8 支持，包括：

- **64 位进程**：VS 2022 是首个 64 位版本的 Visual Studio，不再受 4GB 内存限制，可以轻松加载 IoTGateway 包含的 21 个项目
- **智能感知增强**：对 C# 12 的完整支持，包括主构造函数、集合表达式等新语法
- **热重载**：在调试期间修改代码并立即生效，对于调试通信协议非常有用
- **内置 Git 工具**：无需额外安装 Git 客户端
- **Docker 集成**：IoTGateway 支持 Docker 部署，VS 2022 提供了一流的容器支持

> [!tip] Community 版完全免费
> 对于个人开发者和开源项目，VS 2022 Community 版提供了与 Professional 版几乎相同的功能，完全满足上位机开发需求。

## 第一步：下载安装 VS 2022

### 下载渠道

访问 [Visual Studio 官网](https://visualstudio.microsoft.com/zh-hans/downloads/) 下载最新版本。建议选择 **Community 2022** 版本。

> [!warning] 不要使用预览版
> 上位机项目通常需要长期稳定运行，建议使用正式版（GA）而非 Preview 版本，以避免 IDE 本身的不稳定性影响开发。

### 安装程序选择

下载完成后运行 `VisualStudioSetup.exe`，安装程序会自动更新到最新版本，然后进入工作负载选择界面。

## 第二步：选择工作负载

IoTGateway 是一个综合性项目，涉及 ASP.NET Core Web 应用、EF Core 数据库操作、MQTT 通信以及多个类库项目。因此需要安装以下工作负载：

### 必选工作负载

```
1. ASP.NET 和 Web 开发
   - 包含：ASP.NET Core、Web API、Blazor 支持
   - 用途：IoTGateway 的 Web 管理界面、API 服务

2. .NET 桌面开发
   - 包含：WPF、WinForms、控制台应用模板
   - 用途：上位机客户端程序开发、调试工具、串口调试助手

3. 数据存储和处理
   - 包含：EF Core 工具、SQL Server 数据工具
   - 用途：IoTGateway 使用 EF Core 管理设备数据、配置数据
```

### 推荐工作负载

```
4. Azure 开发（可选）
   - 用途：如果需要将 IoT 数据上传至 Azure IoT Hub

5. 使用 C++ 的桌面开发（可选）
   - 用途：当需要编写或调试原生 DLL 调用的驱动程序时
   - 例如：某些 PLC 驱动需要调用厂商提供的 C++ DLL

6. .NET Multi-Platform App UI 开发（可选）
   - 用途：如果需要开发跨平台上位机界面（MAUI）
```

### 安装摘要中的可选组件

在安装程序右侧的"安装详细信息"面板中，确认勾选以下组件：

| 组件名称 | 用途 |
|---------|------|
| .NET 8.0 Runtime | IoTGateway 目标运行时 |
| .NET SDK | 编译 .NET 8.0 项目 |
| NuGet 包管理器 | 管理项目依赖 |
| Git for Windows | 版本控制 |
| GitHub 扩展 | 如果使用 GitHub 托管代码 |
| Docker Desktop（可选） | 容器化部署 |

> [!note] 磁盘空间
> 完整安装大约需要 15-30 GB 磁盘空间。如果磁盘空间紧张，可以只安装必选工作负载，大约需要 10 GB。

## 第三步：克隆 IoTGateway 项目

### 使用 VS 内置 Git 克隆

1. 打开 VS 2022，选择 **克隆存储库**
2. 输入 IoTGateway 的 Git 仓库地址
3. 选择本地存储路径（建议 `D:\WorkSpace\C#\` 或类似路径）
4. 点击 **克隆**

```bash
# 也可以使用命令行克隆
git clone https://github.com/iioter/iotgateway.git D:\WorkSpace\C#\iotgateway
```

### 打开解决方案

克隆完成后，VS 会自动检测 `.sln` 文件并打开解决方案。首次打开时需要注意：

1. **NuGet 包还原**：VS 会自动还原所有 NuGet 包，IoTGateway 包含大量工业通信相关的包（如 `HslCommunication`、`MQTTnet` 等），可能需要几分钟
2. **项目加载**：解决方案包含 21 个项目，分布在 4 个解决方案文件夹中
3. **首次构建**：按 `Ctrl+Shift+B` 进行首次完整构建

## 第四步：解决方案结构认知

IoTGateway 的解决方案结构如下：

```
IoTGateway.sln
├── 01-Infrastructure/          # 基础设施层
│   ├── IoTGateway.Model        # 数据模型定义
│   ├── IoTGateway.Repository   # 数据仓储
│   └── IoTGateway.IService    # 服务接口定义
│
├── 02-Core/                    # 核心层
│   ├── IoTGateway.Core         # 核心业务逻辑
│   ├── IoTGateway.Service      # 服务实现
│   └── IoTGateway.RpcClient   # RPC 客户端
│
├── 03-Web/                     # Web 层
│   ├── IoTGateway.Host        # 主程序（启动项目）
│   └── IoTGateway.Identity    # 身份认证
│
├── 04-Driver/                  # 驱动插件层（重点！）
│   ├── Driver.Plugin1         # 示例驱动插件
│   ├── Driver.Modbus          # Modbus 驱动
│   ├── Driver.OpcUA           # OPC UA 驱动
│   ├── Driver.S7              # 西门子 S7 驱动
│   └── ...其他驱动
│
└── 05-Client/                  # 客户端层
    └── IoTGateway.Client      # 上位机客户端
```

> [!important] 驱动插件的输出路径
> 驱动插件项目的 DLL 需要输出到主程序的 `drivers` 目录下，这在 [[03-项目配置与构建]] 中有详细说明。理解这个机制对于上位机开发至关重要。

## 第五步：配置启动项目

### 设置主启动项目

1. 在解决方案资源管理器中，右键点击 `IoTGateway.Host` 项目
2. 选择 **设置为启动项目**
3. 项目名称将变为粗体，表示它是当前的启动项目

### 多启动项目配置（调试驱动时需要）

当调试驱动插件时，你可能需要同时启动 Host 和 Client：

1. 右键点击解决方案 → **配置启动项目**
2. 选择 **多个启动项目**
3. 将 `IoTGateway.Host` 和 `IoTGateway.Client` 都设置为 **启动**

```
项目                    操作
IoTGateway.Host        启动
IoTGateway.Client      启动
IoTGateway.Model       无
IoTGateway.Service     无
...
```

## 第七步：环境配置优化

### 字体和颜色配置

上位机开发中经常需要同时查看多个文件，建议调整编辑器设置：

1. **工具** → **选项** → **环境** → **字体和颜色**
2. 字体推荐：**Cascadia Code**（VS 2022 默认）或 **Consolas**
3. 字号推荐：**12-14 号**（根据显示器分辨率调整）

```
推荐配置：
- 字体：Cascadia Code, 12pt
- 启用连字（Ligatures）：是
- 行号显示：是
- 参考线（Guidelines）：120 列处添加参考线
```

### 代码折叠配置

上位机项目中驱动代码通常较长，建议启用代码折叠：

1. **工具** → **选项** → **文本编辑器** → **C#** → **高级**
2. 启用 **折叠 #region 块**
3. 启用 **折叠 using 语句**

### 自动保存配置

```
工具 → 选项 → 环境 → 文档
☑ 自动保存文件（间隔 5 分钟）
☑ 当 Visual Studio 为后台进程时保存文档
```

> [!tip] 防止代码丢失
> 在调试驱动插件时，VS 可能因为异常而崩溃。开启自动保存可以最大程度减少代码丢失风险。

## 第八步：首次构建与验证

### 构建项目

按 `Ctrl+Shift+B` 或选择 **生成** → **生成解决方案**。

首次构建时，观察 **输出** 窗口（`Ctrl+Alt+O`），应该看到类似以下信息：

```
========== 生成: 成功 21 个，失败 0 个，最新 0 个，跳过 0 个 ==========
```

### 常见构建问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| NuGet 包还原失败 | 网络问题或包源不可用 | 配置国内 NuGet 镜像源 |
| 找不到 .NET 8.0 SDK | SDK 未安装 | 安装 .NET 8.0 SDK |
| 驱动项目输出路径错误 | OutputPath 配置不正确 | 检查 .csproj 中的 OutputPath |
| 权限不足 | 项目路径需要管理员权限 | 以管理员身份运行 VS |

### 配置国内 NuGet 源

如果 NuGet 包还原速度慢，可以添加国内镜像：

```xml
<!-- NuGet.Config -->
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
    <add key="tencent" value="https://mirrors.cloud.tencent.com/nuget/" />
    <add key="aliyun" value="https://mirrors.aliyun.com/nuget/v3/index.json" />
  </packageSources>
</configuration>
```

### 运行项目

按 `F5` 启动调试，或按 `Ctrl+F5` 不调试启动。项目启动后应该看到：

1. 控制台窗口显示 IoTGateway 启动日志
2. 浏览器自动打开 Web 管理界面（默认 `http://localhost:5000`）
3. MQTT Broker 开始监听（默认端口 1883）

## 常见问题 FAQ

### Q: VS 2022 和 VS Code 应该选哪个？

**上位机开发强烈建议使用 VS 2022。** 原因如下：

1. VS 2022 的调试器远比 VS Code 强大，特别是在多线程调试方面（上位机必用）
2. 解决方案管理器可以直观管理 21 个项目
3. 内置的性能分析工具（Profiler）是 VS Code 不具备的
4. EF Core 的可视化工具支持更好

VS Code 更适合轻量级编辑和前端开发。

### Q: 能否使用 JetBrains Rider？

可以。Rider 是一个优秀的替代方案，部分开发者甚至更喜欢它的重构功能。但本系列教程以 VS 2022 为准，所有快捷键和操作说明基于 VS 2022。如果你使用 Rider，可以参考 [[01-快捷键大全]] 中的 Rider 快捷键对照表。

### Q: 项目构建很慢怎么办？

1. 确保已安装 SSD（HDD 会严重拖慢构建速度）
2. 在 Windows Defender 中排除项目文件夹和 `devenv.exe` 进程
3. 关闭不必要的扩展
4. 使用 **并行构建**：工具 → 选项 → 项目和解决方案 → 生成并运行 → 最大并行项目生成数设置为 CPU 核心数
