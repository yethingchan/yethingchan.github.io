## 代码质量对上位机的重要性

上位机程序与普通 Web 应用不同，它通常需要 **7x24 小时不间断运行**，管理数十到数千台工业设备。代码质量的直接影响包括：

- **可靠性**：糟糕的异常处理可能导致设备数据丢失
- **可维护性**：通信协议代码的重复度高，不重构难以维护
- **可测试性**：硬件依赖使得单元测试困难，需要良好的抽象
- **一致性**：团队协作时需要统一的编码风格

VS 2022 提供了丰富的代码质量工具链，本章将系统介绍。

## 一、代码分析器（Code Analyzers）

### 1.1 .NET 内置分析器

.NET 8 内置了大量代码分析规则，可以在编译时检查代码质量：

```xml
<!-- .csproj 中启用代码分析 -->
<PropertyGroup>
  <AnalysisLevel>latest</AnalysisLevel>
  <AnalysisMode>All</AnalysisMode>
  <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
  <TreatWarningsAsErrors>false</TreatWarningsAsErrors>
</PropertyGroup>
```

### 1.2 分析级别配置

| 分析级别 | 说明 | 适用场景 |
|---------|------|---------|
| `none` | 禁用所有分析 | 性能敏感的生成代码 |
| `default` | 默认规则集 | 一般开发 |
| `minimum` | 仅最关键的规则 | 快速开发阶段 |
| `recommended` | 推荐规则集 | 日常开发（推荐） |
| `all` | 启用所有规则 | 代码审查和 CI |
| `latest` | 使用最新规则 | 新项目（推荐） |

### 3.1 提取方法（Extract Method）

```
快捷键：Ctrl+R, Ctrl+M
```

```csharp
// 重构前：一个过长且职责不清的方法
public async Task PollDevice()
{
    // 构建请求
    var request = new byte[8];
    request[0] = _slaveId;
    request[1] = 0x03;
    BitConverter.GetBytes((ushort)_startAddress).CopyTo(request, 2);
    BitConverter.GetBytes((ushort)_count).CopyTo(request, 4);
    var crc = CalculateCrc(request, 0, 6);
    request[6] = (byte)(crc & 0xFF);
    request[7] = (byte)(crc >> 8);

    // 发送请求
    await _serialPort.WriteAsync(request, 0, request.Length);
    await _serialPort.FlushAsync();

    // 读取响应
    var response = new byte[256];
    var bytesRead = await _serialPort.ReadAsync(response, 0, response.Length);

    // 验证响应
    if (bytesRead < 5)
        throw new CommunicationException("响应数据不足");
    var responseCrc = response[bytesRead - 2] | (response[bytesRead - 1] << 8);
    var expectedCrc = CalculateCrc(response, 0, bytesRead - 2);
    if (responseCrc != expectedCrc)
        throw new CommunicationException("CRC 校验失败");

    // 解析数据
    var byteCount = response[2];
    var data = new byte[byteCount];
    Array.Copy(response, 3, data, 0, byteCount);
    _lastData = data;
}

}
```

### 3.2 提取接口（Extract Interface）

```
操作：右键类名 → 快速操作 → 提取接口
```

```csharp
// 重构前：具体实现直接依赖
public class ModbusDriver
{
    public async Task<byte[]> ReadRegisters(int address, int count) { ... }
    public async Task WriteRegister(int address, short value) { ... }
}

// 重构后：提取接口，实现依赖倒置
public interface IModbusDriver
{
    Task<byte[]> ReadRegisters(int address, int count);
    Task WriteRegister(int address, short value);
}

public class ModbusDriver : IModbusDriver
{
    public async Task<byte[]> ReadRegisters(int address, int count) { ... }
    public async Task WriteRegister(int address, short value) { ... }
}

// 使用接口而不是具体类（方便单元测试和替换实现）
public class DeviceService
{
    private readonly IModbusDriver _driver;  // 依赖接口

    public DeviceService(IModbusDriver driver)
    {
        _driver = driver;
    }
}
```

### 3.3 重命名（Rename）

```
快捷键：Ctrl+R, Ctrl+R
```

> [!important] 永远使用重构重命名
> 不要手动搜索替换来重命名变量/方法/类。使用 `Ctrl+R, Ctrl+R` 可以安全地重命名所有引用，包括注释中的引用和字符串中的引用（可选）。

### 3.4 其他有用重构

| 重构操作 | 快捷键 | 用途 |
|---------|-------|------|
| 提取方法 | Ctrl+R, Ctrl+M | 将选中代码提取为独立方法 |
| 内联方法 | Ctrl+R, Ctrl+I | 将方法调用替换为方法体 |
| 引入局部变量 | Ctrl+R, Ctrl+V | 将表达式提取为局部变量 |
| 引入常量 | Ctrl+R, Ctrl+C | 将魔法数字提取为常量 |
| 引入参数 | Ctrl+R, Ctrl+P | 将表达式提取为方法参数 |
| 移除参数 | - | 删除未使用的参数 |
| 重新排列参数 | - | 调整参数顺序 |


## 五、单元测试与代码覆盖率

### 5.1 编写可测试的通信代码

```csharp
// 不好的写法：直接依赖硬件，无法测试
public class DeviceController
{
    private readonly SerialPort _port = new SerialPort("COM1");

    public async Task<byte[]> ReadData()
    {
        _port.Open();
        var buffer = new byte[256];
        await _port.BaseStream.ReadAsync(buffer, 0, 256);
        _port.Close();
        return buffer;
    }
}

// 好的写法：通过接口抽象，可以 Mock 测试
public class DeviceController
{
    private readonly ICommunicationChannel _channel;

    public DeviceController(ICommunicationChannel channel)
    {
        _channel = channel;
    }

    public async Task<byte[]> ReadData()
    {
        await _channel.OpenAsync();
        var buffer = new byte[256];
        var bytesRead = await _channel.ReadAsync(buffer, 0, 256);
        await _channel.CloseAsync();
        return buffer.AsSpan(0, bytesRead).ToArray();
    }
}

public interface ICommunicationChannel
{
    Task OpenAsync();
    Task<int> ReadAsync(byte[] buffer, int offset, int count);
    Task CloseAsync();
}
```

### 5.2 编写单元测试

```csharp
using Moq;
using Xunit;
using FluentAssertions;

public class DeviceControllerTests
{
    [Fact]
    public async Task ReadData_ShouldReturnCorrectBytes()
    {
        // Arrange
        var mockChannel = new Mock<ICommunicationChannel>();
        var expectedData = new byte[] { 0x01, 0x03, 0x04, 0x00, 0x1A };

        mockChannel
            .Setup(c => c.ReadAsync(It.IsAny<byte[]>(), 0, 256))
            .ReturnsAsync((byte[] buffer, int offset, int count) =>
            {
                expectedData.CopyTo(buffer, 0);
                return expectedData.Length;
            });

        var controller = new DeviceController(mockChannel.Object);

        // Act
        var result = await controller.ReadData();

        // Assert
        result.Should().BeEquivalentTo(expectedData);
        mockChannel.Verify(c => c.OpenAsync(), Times.Once);
        mockChannel.Verify(c => c.CloseAsync(), Times.Once);
    }

    [Fact]
    public async Task ReadData_ShouldRetryOnTimeout()
    {
        // Arrange
        var mockChannel = new Mock<ICommunicationChannel>();
        var callCount = 0;

        mockChannel
            .Setup(c => c.ReadAsync(It.IsAny<byte[]>(), 0, 256))
            .ReturnsAsync(() =>
            {
                callCount++;
                if (callCount == 1)
                    throw new TimeoutException();
                return 5;
            });

        var controller = new DeviceController(mockChannel.Object);

        // Act & Assert - 应该能处理超时
        await Assert.ThrowsAsync<TimeoutException>(() => controller.ReadData());
    }
}
```

## 九、代码审查清单

在上位机项目的代码审查中，重点关注以下方面：

```
上位机代码审查清单：

1. 异常处理
   [ ] 所有通信操作都有 try-catch
   [ ] 没有空的 catch 块
   [ ] 异常信息包含设备标识和地址信息
   [ ] 超时异常有重试机制

2. 资源管理
   [ ] SerialPort、Socket 等使用 using 语句
   [ ] 定时器和事件订阅有对应的取消/取消订阅
   [ ] CancellationToken 被正确传递

3. 线程安全
   [ ] 共享数据有适当的同步机制
   [ ] 没有使用 lock 包裹异步操作
   [ ] ConcurrentDictionary 用于并发集合

4. 性能
   [ ] 高频循环中没有字符串拼接
   [ ] 大数组使用 ArrayPool
   [ ] 异步方法使用 ConfigureAwait(false)

5. 日志
   [ ] 关键操作有日志记录
   [ ] 日志包含足够的上下文信息
   [ ] 敏感信息（密码、密钥）不出现在日志中
```
