## 监控与故障排查

工业物联网上位机运行在生产环境中，可能面临网络中断、设备故障、数据库锁定、内存泄漏等各种问题。完善的监控手段和系统的故障排查方法，是保障系统稳定运行的关键。本章介绍IoTGateway的监控能力、常见故障现象及其排查方法。

## 系统监控手段

### 1. Swagger API文档

IoTGateway内置了Swagger API文档，可以在线测试所有API接口：

```
http://localhost:518/swagger
```

在`Startup.cs`中启用：

```csharp
services.AddWtmSwagger();
// ...
app.UseWtmSwagger();
```

Swagger可用于：
- 验证API是否正常工作
- 测试MQTT和RPC相关接口
- 外部系统对接时的接口调试

### 2. 内置操作日志

WTM框架自动记录用户的操作日志，通过管理后台查看：

```
/_Admin/ActionLog/Index
```

操作日志包含：
- 操作用户
- 操作时间
- 请求URL
- 请求方法
- 操作结果

### 3. RPC调用日志

IoTGateway为每次RPC（远程过程调用）操作记录详细日志：

```
/Rpc/RpcLog/Index
```

RPC日志页面提供了丰富的筛选条件：

```cshtml
<wt:searchpanel vm="@Model" reset-btn="true">
    <wt:row items-per-row="ItemsPerRowEnum.Three">
        <wt:combobox field="Searcher.RpcSide" empty-text="全部" />
        <wt:datetime field="Searcher.StartTime" range="true" />
        <wt:combobox field="Searcher.DeviceId" items="Searcher.AllDevices" 
                     empty-text="全部" />
        <wt:textbox field="Searcher.Method" />
        <wt:textbox field="Searcher.Params" />
        <wt:combobox field="Searcher.IsSuccess" empty-text="全部" />
    </wt:row>
</wt:searchpanel>
```

通过RPC日志可以追踪：
- 哪个设备下发了什么控制命令
- 命令执行是否成功
- 命令参数和执行时间

### 4. MQTT客户端监控

IoTGateway提供了MQTT连接客户端的监控页面：

```
/MqttServer/MqttClient/Index
```

可以看到当前所有连接到内置MQTT Broker的客户端信息，包括：
- 客户端ID
- 连接状态
- 连接的IP地址
- 订阅的主题

### 5. NLog日志文件

如[[03-NLog日志系统]]中所述，NLog日志文件记录了系统运行时的详细信息：

```bash
# 查看错误日志
cat /opt/iotgateway/logs/$(date +%Y-%m-%d)_Error.log

# 实时监控错误日志
tail -f /opt/iotgateway/logs/$(date +%Y-%m-%d)_Error.log
```

### 6. 系统级监控

```bash
# 进程状态
systemctl status iotgateway

# CPU和内存占用
top -p $(pgrep -f IoTGateway)

# 端口监听
ss -tlnp | grep -E "518|1888"

# 磁盘空间
df -h /opt/iotgateway/
```

## 常见故障与排查

### 故障一：服务无法启动

**现象：** `systemctl start iotgateway`后服务立即退出。

**排查步骤：**

```bash
# 1. 查看服务状态
systemctl status iotgateway

# 2. 查看详细日志
journalctl -u iotgateway --no-pager -n 50

# 3. 手动运行查看错误信息
cd /opt/iotgateway
./IoTGateway
```

**常见原因及解决：**

| 原因 | 解决方式 |
|------|---------|
| 端口被占用 | `lsof -i :518` 查看并停止占用进程 |
| 数据库文件损坏 | 从备份恢复或删除db文件让系统重建 |
| .NET运行时未安装 | 安装.NET 8.0 Runtime或使用自包含发布 |
| 权限不足 | 检查文件和目录权限 |
| 配置文件语法错误 | 检查`appsettings.json`的JSON格式 |

### 故障二：MQTT连接失败

**现象：** 设备无法连接到MQTT Broker，或浏览器无法接收实时数据。

**排查步骤：**

```bash
# 1. 检查MQTT端口是否监听
ss -tlnp | grep 1888

# 2. 检查防火墙
iptables -L -n | grep 1888

# 3. 使用MQTT客户端工具测试连接
mosquitto_pub -h localhost -p 1888 -t "test" -m "hello"

# 4. 查看MQTT客户端监控页面
# 浏览器访问: http://<ip>:518/MqttServer/MqttClient/Index
```

**常见原因：**

| 原因 | 排查方法 |
|------|---------|
| 端口未开放 | 检查防火墙规则 |
| WebSocket路径错误 | 确认连接地址为`ws://host:518/mqtt` |
| MQTT客户端ID冲突 | 检查是否有重复的clientId |
| 网络延迟/丢包 | `ping`和`traceroute`测试网络质量 |
| TLS证书问题 | 如果使用HTTPS，确认证书有效 |

### 故障三：设备变量数据不更新

**现象：** 管理页面上设备变量的值长时间不变。

**排查思路：**

```
1. 驱动层是否正常采集？
   → 查看驱动日志（命名空间 Plugin.*）
   → 确认设备通信链路正常（ping设备、检查串口）

2. 数据是否发布到MQTT？
   → 使用MQTT客户端订阅内部Topic验证
   → mosquitto_sub -h localhost -p 1888 -t "internal/v1/gateway/telemetry/#"

3. 浏览器是否收到消息？
   → 打开浏览器开发者工具（F12），查看Console和Network
   → 确认WebSocket连接已建立
   → 确认已订阅正确的Topic

4. DOM更新是否正确？
   → 检查DOM元素ID是否与VarId匹配
   → 检查JavaScript是否有错误
```

### 故障四：数据库文件锁定

**现象：** 页面报错"database is locked"。

**原因：** SQLite在写入时锁定数据库文件，如果另一个进程（或IoTGateway的多个实例）同时访问，会导致锁冲突。

**解决方式：**

```bash
# 1. 确认没有多个IoTGateway进程
ps aux | grep IoTGateway

# 2. 如果有残留进程，终止
kill -9 <pid>

# 3. 重启服务
systemctl restart iotgateway
```

**预防措施：**
- 确保只有一个IoTGateway实例访问同一个SQLite文件
- 如果并发访问需求高，切换到MySQL或PostgreSQL
- 在连接字符串中设置`Default Timeout=30`增加超时时间

### 故障五：内存泄漏

**现象：** 服务运行一段时间后内存持续增长。

**排查步骤：**

```bash
# 1. 监控内存使用
watch -n 5 "ps -o pid,rss,vsz,cmd -p $(pgrep -f IoTGateway)"

# 2. 检查日志文件是否过大
du -sh /opt/iotgateway/logs/

# 3. 检查是否有大量MQTT订阅未释放
# 查看MQTT客户端监控页面
```

**常见原因：**
- MQTT订阅积累（翻页后旧订阅未取消）
- 日志文件过大占用磁盘
- 数据库连接池未释放
- 静态集合不断增长

### 故障六：页面加载缓慢

**现象：** 管理页面响应慢，表格数据加载时间长。

**排查思路：**

```bash
# 1. 检查数据库大小
ls -lh /opt/iotgateway/data/iotgateway.db

# 2. 检查系统资源
top
free -h

# 3. 检查网络延迟（如果是远程访问）
ping <gateway-ip>

# 4. 检查数据库查询性能
sqlite3 /opt/iotgateway/data/iotgateway.db "EXPLAIN QUERY PLAN SELECT * FROM DeviceVariables WHERE DeviceId = 'xxx';"
```

**优化建议：**
- 数据库过大时考虑归档历史数据
- 为常用查询字段添加索引
- 减少每页显示记录数（修改`UIOptions.DataTable.RPP`）
- 使用MySQL/PostgreSQL替代SQLite以获得更好的并发性能

## 监控脚本示例

### 健康检查脚本

```bash
#!/bin/bash
# health_check.sh - IoTGateway健康检查

GATEWAY_URL="http://localhost:518"
MQTT_PORT=1888

# 1. 检查HTTP服务
HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" ${GATEWAY_URL}/Login/Login)
if [ "$HTTP_STATUS" != "200" ] && [ "$HTTP_STATUS" != "302" ]; then
    echo "ERROR: HTTP服务异常 (状态码: $HTTP_STATUS)"
    systemctl restart iotgateway
    exit 1
fi

# 2. 检查MQTT端口
if ! ss -tlnp | grep -q ":${MQTT_PORT}"; then
    echo "ERROR: MQTT端口 ${MQTT_PORT} 未监听"
    systemctl restart iotgateway
    exit 1
fi

# 3. 检查磁盘空间
DISK_USAGE=$(df /opt/iotgateway | tail -1 | awk '{print $5}' | tr -d '%')
if [ "$DISK_USAGE" -gt 90 ]; then
    echo "WARNING: 磁盘使用率 ${DISK_USAGE}%，正在清理日志..."
    find /opt/iotgateway/logs/ -name "*.log" -mtime +3 -delete
fi

# 4. 检查内存使用
RSS=$(ps -o rss= -p $(pgrep -f IoTGateway) 2>/dev/null)
if [ -n "$RSS" ] && [ "$RSS" -gt 1048576 ]; then  # 超过1GB
    echo "WARNING: 内存使用过高 (${RSS}KB)，建议重启"
fi

echo "OK: IoTGateway运行正常"
exit 0
```

### 定时执行

```bash
# 每5分钟执行一次健康检查
crontab -e
*/5 * * * * /opt/iotgateway/health_check.sh >> /opt/iotgateway/logs/health.log 2>&1
```

### 日志轮转脚本

```bash
#!/bin/bash
# log_rotate.sh - 日志清理和压缩

LOG_DIR="/opt/iotgateway/logs"
KEEP_DAYS=7

# 压缩3天前的日志
find ${LOG_DIR} -name "*.log" -mtime +3 -not -name "*.gz" -exec gzip {} \;

# 删除超过保留天数的日志
find ${LOG_DIR} -name "*.log.gz" -mtime +${KEEP_DAYS} -delete

# 统计日志大小
echo "日志目录大小: $(du -sh ${LOG_DIR} | cut -f1)"
```

## Docker环境下的监控

### Docker健康检查

在Dockerfile中添加HEALTHCHECK指令：

```dockerfile
HEALTHCHECK --interval=30s --timeout=10s --start-period=30s --retries=3 \
  CMD curl -f http://localhost:518/Login/Login || exit 1
```

### Docker日志收集

```bash
# 使用json-file日志驱动，限制日志大小
docker run -d \
  --log-driver json-file \
  --log-opt max-size=50m \
  --log-opt max-file=5 \
  --name iotgateway \
  iotgateway:latest
```

### 资源限制

```bash
docker run -d \
  --name iotgateway \
  --memory=512m \
  --cpus=1.0 \
  --restart always \
  -p 518:518 -p 1888:1888 \
  iotgateway:latest
```

## 告警策略建议

| 监控项 | 告警阈值 | 告警方式 |
|--------|---------|---------|
| 服务状态 | 进程不存在 | 自动重启 + 邮件/短信通知 |
| CPU使用率 | 持续 > 80% | 日志告警 |
| 内存使用 | > 1GB | 日志告警 + 考虑重启 |
| 磁盘使用率 | > 90% | 自动清理日志 + 告警 |
| MQTT连接数 | 超过预期值 | 日志告警 |
| 数据库大小 | > 5GB（SQLite） | 告警 + 数据归档 |
| RPC失败率 | > 10% | 告警 + 检查设备通信 |

## 小结

IoTGateway提供了Swagger API、操作日志、RPC日志、MQTT客户端监控、NLog文件日志等多层监控手段。在故障排查时，应按照"服务层 → 通信层 → 数据层 → 应用层"的顺序逐步定位问题。建议在生产环境中部署健康检查脚本，实现自动化的监控和告警，确保工业物联网系统的7x24稳定运行。
