## 串口通信基础

串口通信（Serial Communication）是工业现场最基础的通信方式之一。即使在以太网高度普及的今天，大量传感器、仪表、老式PLC仍然使用RS232或RS485串口进行数据交换。理解串口通信原理是上位机开发者的必备技能。

---

## 串行通信原理

### 并行 vs 串行

```
并行通信（8位数据同时传输）        串行通信（逐位传输）
                               
  D7 ────┐                        ┌─ D0 ─┐
  D6 ────┤                        │ D1 ──┤
  D5 ────┤                        │ D2 ──┤   时间 ──→
  D4 ────┼── 同时到达              │ D3 ──┤
  D3 ────┤                        │ D4 ──┤
  D2 ────┤                        │ D5 ──┤
  D1 ────┤                        │ D6 ──┤
  D0 ────┘                        └─ D7 ─┘
  需要8根数据线                     只需1根数据线
  距离短、成本高                     距离远、成本低
```

工业场景几乎全部使用串行通信，原因是：
- 线缆少，布线成本低
- 传输距离远（RS485可达1200米）
- 抗干扰能力强（差分信号）

### 数据帧结构

串口通信将数据按"帧"发送，每帧的结构如下：

```
空闲 ─┬─ 起始位 ─┬─ 数据位(5-8bit) ─┬─ 校验位(可选) ─┬─ 停止位(1-2bit) ─┬─ 空闲
      │          │                  │                │                │
 ─────┘ ┌────────┘  ┌──┬──┬──┬──┐  ┌┐              ┌────────────────┘
     ___│ 0        │D0│D1│D2│..│Dn│ │P│            │
        └──────────┘──┴──┴──┴──┘──┘└┘──────────────┘
```

| 组成部分 | 作用 | 典型值 |
|---------|------|-------|
| 起始位 | 通知接收方数据到来 | 固定低电平(0)，1bit |
| 数据位 | 实际传输的数据 | 7bit(ASCII) 或 8bit(二进制)，最常用8bit |
| 校验位 | 简单的错误检测 | None(无)、Even(偶校验)、Odd(奇校验) |
| 停止位 | 标记帧结束 | 1bit、1.5bit 或 2bit |
| 空闲状态 | 无数据传输时线路状态 | 高电平(1) |

> **工业现场最常用的配置**：8数据位、无校验、1停止位，简称 **8N1**。Modbus RTU默认使用此配置。

## RS232 标准

### 电气特性

RS232是最早的串行通信标准（1962年制定），使用**单端信号**：

```
        RS232 信号电平
  逻辑 "0" (Space):  +3V ~ +15V
  逻辑 "1" (Mark):   -3V ~ -15V
  不确定区域:        -3V ~ +3V
  
  注意：RS232电平与TTL电平相反！
  TTL: 高电平=1, 低电平=0
  RS232: 负电压=1, 正电压=0
```

### 接口与接线

RS232标准定义了DB9（9针）和DB25（25针）接口，工业中最常用DB9：

```
DB9 公头引脚定义（面向接头）:

    1  2  3  4  5         1 - DCD (载波检测)
     6  7  8  9           2 - RXD (接收数据) ← 重要
                         3 - TXD (发送数据) ← 重要
                         4 - DTR (数据终端就绪)
                         5 - GND (信号地)   ← 重要
                         6 - DSR (数据设备就绪)
                         7 - RTS (请求发送)
                         8 - CTS (清除发送)
                         9 - RI  (振铃指示)
```

### 最简三线制接法

大多数工业场景只需三根线即可完成通信：

```
  设备A (DTE)              设备B (DCE)
  ┌──────┐                ┌──────┐
  │  TXD ├────────────────┤ RXD  │
  │  RXD ├────────────────┤ TXD  │
  │  GND ├────────────────┤ GND  │
  └──────┘                └──────┘
  
  注意：TX接RX，RX接TX，交叉连接！
```

### RS232的局限

| 参数 | 限制 |
|------|------|
| 最大传输距离 | 15米（实际可达30米，取决于波特率） |
| 最大速率 | 20kbps（标准），实际可达115.2kbps |
| 连接设备数 | 1对1（点对点） |
| 抗干扰能力 | 较弱（单端信号） |

> **实践提示**：RS232适合短距离、点对点通信，如PC连接编程电缆、近距离仪表通信。如果需要长距离或多设备，请使用RS485。

## RS485 标准

### 电气特性

RS485使用**差分信号**，通过两根线的电压差来表示逻辑状态：

```
RS485 差分信号:

     A线 ──────┐
               ├── VA - VB = 差模电压
     B线 ──────┘
     
  逻辑 "1": VA - VB > +200mV
  逻辑 "0": VA - VB < -200mV
  
  A ─╲     ╱───╲     ╱───
       ╲   ╱     ╲   ╱
  B ────╲─╱───────╲─╱────
       ↑           ↑
     逻辑1       逻辑0
```

差分信号的优势：
- **抗共模干扰**：外部电磁干扰同时作用于A/B两线，差值不受影响
- **传输距离远**：最远可达1200米（9600bps时）
- **支持多设备**：一条总线最多32个设备（标准），增强型可达256个

### RS485总线拓扑

```
    终端电阻(120Ω)                          终端电阻(120Ω)
    ┌──/\/\/──┐                              ┌──/\/\/──┐
    │    A  B │                              │    A  B │
────┼─────────┼──────────────────────────────┼─────────┼──── 主干线
    │  ┌─┐    │   ┌─┐    ┌─┐    ┌─┐         │         │
    │  │1│    │   │2│    │3│    │N│         │         │
    │  └─┘    │   └─┘    └─┘    └─┘         │         │
    └─────────┘                              └─────────┘
     主站                                  从站1  从站2  从站N
     
  ★ 星形接线（不推荐）     ✓ 手拉手菊花链（推荐）
  
    ┌─┐                     ┌─┐   ┌─┐   ┌─┐
    │M│                     │1│───│2│───│3│
    └┬┘                     └─┘   └─┘   └─┘
    /│\
   / │ \
 ┌─┐┌─┐┌─┐
 │1││2││3│   ← 分支长度应<0.3m
 └─┘└─┘└─┘
```

### 终端电阻

RS485总线两端需要120欧姆终端电阻，用于消除信号反射：

```
不加终端电阻时:                    加终端电阻后:

信号 ─────→ 到达末端              信号 ─────→ 到达末端
         ←── 反射！                         被电阻吸收 ✓
         
反射导致信号失真,                  信号干净,通信稳定
通信不稳定
```

> **实践提示**：短距离（<50米）、低波特率（<9600）时，不加终端电阻通常也能工作。但长距离或高波特率时必须加装。

### RS485的半双工特性

RS485是**半双工**通信——同一时刻只能发送或接收，不能同时进行：

```
时间 ──→
主站发送: ████████████                    
从站接收: ████████████                    

            方向切换（需延时）

从站发送:             ████████████
主站接收:             ████████████

在Modbus RTU中，主站发完请求后必须切换为接收模式，
等待从站应答。这个切换时间通常为3.5个字符时间。
```

## 波特率与传输速度

### 波特率计算

波特率（Baud Rate）表示每秒传输的码元数。对于串口通信（每个码元=1bit），波特率=比特率：

```
配置: 8N1 (8数据位 + 无校验 + 1停止位 = 10bit/帧)

波特率 9600 bps:
  每秒传输帧数 = 9600 / 10 = 960 帧/秒
  每帧传输时间 = 10 / 9600 ≈ 1.04ms

波特率 115200 bps:
  每秒传输帧数 = 115200 / 10 = 11520 帧/秒
  每帧传输时间 = 10 / 115200 ≈ 0.087ms
```

### 常用波特率对照

| 波特率 | 每字符时间(8N1) | 典型应用 |
|--------|----------------|---------|
| 2400 | 4.17ms | 低速仪表、GPS模块 |
| 4800 | 2.08ms | 老式仪表 |
| 9600 | 1.04ms | Modbus RTU默认、大多数仪表 |
| 19200 | 0.52ms | 中速通信 |
| 38400 | 0.26ms | PLC编程口 |
| 57600 | 0.17ms | GPS模块 |
| 115200 | 0.087ms | 高速通信、固件下载 |

### 波特率与距离的关系（RS485）

```
距离(m)
1200 ─┐
      │ ● 9600bps
 800 ─┤
      │   ● 19200bps
 400 ─┤
      │       ● 57600bps
 100 ─┤
      │           ● 115200bps
   0 ─┴────────────────── 波特率(bps)
      9600  19200  57600  115200
```

> **经验法则**：RS485总线上，距离和速率成反比。1200米时建议不超过9600bps，100米内可使用115200bps。

## C# System.IO.Ports 编程

### SerialPort 基本使用

.NET提供了 `System.IO.Ports.SerialPort` 类来操作串口。以下是IoTGateway中Modbus RTU驱动使用串口的方式：

```csharp
using System.IO.Ports;

// 创建串口实例 - 方式1: 构造函数指定参数
var serialPort = new SerialPort(
    portName: "COM1",       // 串口号
    baudRate: 9600,         // 波特率
    parity: Parity.None,    // 校验位
    dataBits: 8,            // 数据位
    stopBits: StopBits.One  // 停止位
);

// 设置超时
serialPort.ReadTimeout = 3000;   // 读取超时3秒
serialPort.WriteTimeout = 3000;  // 写入超时3秒

// 打开串口
serialPort.Open();

// 检查是否打开
if (serialPort.IsOpen)
{
    Console.WriteLine("串口已打开");
}
```

### IoTGateway中的实际应用

在Modbus驱动中，串口通过 `SerialPortAdapter` 适配器包装后传给NModbus4库：

```csharp
// DeviceModBusMaster.cs - Modbus RTU连接
case MasterType.Rtu:
    // 1. 创建并打开串口
    _serialPort = new SerialPort(PortName, BaudRate, Parity, DataBits, StopBits);
    _serialPort.ReadTimeout = Timeout;
    _serialPort.WriteTimeout = Timeout;
    _serialPort.Open();
    
    // 2. 通过适配器桥接NModbus4
    _adapter = new SerialPortAdapter(_serialPort);
    
    // 3. 创建Modbus RTU主站
    _master = ModbusSerialMaster.CreateRtu(_adapter);
    break;

// Modbus ASCII连接（使用ASCII字符传输二进制数据）
case MasterType.Ascii:
    _serialPort = new SerialPort(PortName, BaudRate, Parity, DataBits, StopBits);
    _serialPort.ReadTimeout = Timeout;
    _serialPort.WriteTimeout = Timeout;
    _serialPort.Open();
    _adapter = new SerialPortAdapter(_serialPort);
    _master = ModbusSerialMaster.CreateAscii(_adapter);
    break;
```

### 直接读写串口

如果不使用Modbus协议，直接通过串口收发原始数据：

```csharp
// 发送数据
byte[] sendData = new byte[] { 0x01, 0x03, 0x00, 0x00, 0x00, 0x01, 0x84, 0x0A };
serialPort.Write(sendData, 0, sendData.Length);

// 接收数据 - 方式1: 阻塞读取
byte[] buffer = new byte[256];
int bytesRead = serialPort.Read(buffer, 0, buffer.Length);

// 接收数据 - 方式2: 事件驱动
serialPort.DataReceived += (sender, e) =>
{
    SerialPort sp = (SerialPort)sender;
    string data = sp.ReadExisting();
    Console.WriteLine($"收到数据: {data}");
};

// 接收数据 - 方式3: 读取到特定字符
string line = serialPort.ReadLine(); // 读到 \n 为止
```

### SerialPortAdapter 适配器模式

IoTGateway中，SerialPort需要适配为NModbus4库要求的 `IStreamResource` 接口：

```csharp
/// <summary>
/// 串口适配器 - 桥接System.IO.Ports与NModbus4
/// </summary>
public class SerialPortAdapter : IStreamResource
{
    private readonly SerialPort _serialPort;

    public SerialPortAdapter(SerialPort serialPort)
    {
        _serialPort = serialPort;
    }

    public int InfiniteTimeout => SerialPort.InfiniteTimeout;
    public int ReadTimeout
    {
        get => _serialPort.ReadTimeout;
        set => _serialPort.ReadTimeout = value;
    }
    public int WriteTimeout
    {
        get => _serialPort.WriteTimeout;
        set => _serialPort.WriteTimeout = value;
    }

    public void DiscardInBuffer() => _serialPort.DiscardInBuffer();
    public void DiscardOutBuffer() => _serialPort.DiscardOutBuffer();
    
    public int Read(byte[] buffer, int offset, int count)
        => _serialPort.Read(buffer, offset, count);
    
    public void Write(byte[] buffer, int offset, int count)
        => _serialPort.Write(buffer, offset, count);

    public void Dispose() => _serialPort?.Dispose();
}
```

> **设计模式**：这是经典的**适配器模式**（Adapter Pattern）。当两个库的接口不兼容时，通过适配器进行桥接。在驱动开发中经常会遇到类似场景。

## 串口枚举与选择

### 获取可用串口列表

```csharp
// 获取系统所有可用串口
string[] ports = SerialPort.GetPortNames();
foreach (var port in ports)
{
    Console.WriteLine($"可用串口: {port}");
}
// 输出: COM1, COM3, COM4 ...
```

### USB转串口芯片

工业现场常用的USB转串口芯片：

| 芯片 | 稳定性 | 价格 | 驱动支持 | 推荐度 |
|------|--------|------|---------|-------|
| FT232 (FTDI) | 优秀 | 较高 | Win/Linux免驱 | 强烈推荐 |
| CH340 | 一般 | 低廉 | 需装驱动 | 临时使用 |
| CP2102 | 良好 | 中等 | 需装驱动 | 可以使用 |
| PL2303 | 一般 | 低廉 | 需装驱动 | 不推荐(假货多) |

> **实践提示**：购买USB-RS485转换器时，认准FT232芯片。CH340在Windows 10以上可能遇到驱动签名问题，导致设备管理器中出现感叹号。

## 常见问题排查

### 通信不通的检查清单

```
1. 物理层检查
   ├─ [ ] 串口线是否连接？TX-RX交叉接法？
   ├─ [ ] RS485的A/B线是否接反？（调换试试）
   ├─ [ ] 终端电阻是否正确安装？
   ├─ [ ] GND是否共地？
   └─ [ ] USB转串口驱动是否正确安装？

2. 参数检查
   ├─ [ ] 波特率是否一致？（主站和从站必须相同）
   ├─ [ ] 数据位数是否一致？（7位 vs 8位）
   ├─ [ ] 校验位是否一致？（None/Even/Odd）
   ├─ [ ] 停止位数是否一致？（1位 vs 2位）
   └─ [ ] 从站地址是否正确？

3. 协议层检查
   ├─ [ ] 请求帧格式是否正确？
   ├─ [ ] CRC校验是否通过？
   ├─ [ ] 超时时间是否足够？
   └─ [ ] 帧间隔是否符合要求？
```

### Wireshark抓包分析

虽然Wireshark不能直接抓串口数据，但可以通过以下方式辅助调试：

1. **串口监控工具**：使用 `Serial Port Monitor`（Eltima）或 `com0com` + `hub4com` 做串口数据监听
2. **协议分析**：对于Modbus RTU，使用 `Modbus Poll` 的通信日志功能
3. **Wireshark**：如果使用了串口转以太网（如USR-N510），可以直接抓以太网包

### 常见错误与解决

| 现象 | 可能原因 | 解决方案 |
|------|---------|---------|
| 完全无响应 | TX/RX接反 | 交叉检查接线 |
| 偶尔通信失败 | 干扰或线缆过长 | 加终端电阻，降低波特率 |
| 数据乱码 | 波特率不匹配 | 统一波特率 |
| 超时错误 | 帧间隔不对 | 调整帧间隔延时 |
| CRC错误 | 线路干扰 | 使用屏蔽双绞线 |

## 串口的资源管理

### 正确的资源释放

串口是独占资源，一个串口同一时刻只能被一个程序使用。正确的释放方式：

```csharp
// IoTGateway Modbus驱动的Dispose实现
public void Dispose()
{
    try
    {
        _tcpClient?.Dispose();
        _udpClient?.Dispose();
        _serialPort?.Dispose();   // 释放串口资源
        _master?.Dispose();

        // 抑制终结器，避免二次释放
        GC.SuppressFinalize(this);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, $"Device:[{_device}],Dispose(),Error");
    }
}
```

### 串口操作的最佳实践

1. **使用 using 语句**确保资源释放：
```csharp
using var port = new SerialPort("COM1", 9600);
port.Open();
// 使用串口...
// using结束时自动调用Dispose
```

2. **避免在UI线程操作串口**，串口读写可能阻塞：
```csharp
// 错误做法：在UI线程同步读取
var data = serialPort.ReadLine(); // 可能阻塞UI

// 正确做法：异步读取
await Task.Run(() => {
    var data = serialPort.ReadLine();
    // 处理数据...
});
```

3. **合理设置超时**，防止无限等待：
```csharp
serialPort.ReadTimeout = 3000;  // 3秒超时
serialPort.WriteTimeout = 3000;
```
