## 工业通信协议总览

在工业自动化领域，**上位机**（通常指运行Windows/Linux的工控机或服务器）需要与各种底层设备（PLC、传感器、CNC机床、仪表等）进行数据交换。IoTGateway项目作为一个典型的C#上位机网关，支持了10余种工业通信协议，涵盖了从现场总线到云端物联网的完整通信链路。

### 本系列文章定位

本系列面向**工业自动化工程师**和**C#上位机开发者**，以IoTGateway开源项目的真实代码为蓝本，系统讲解工业通信协议的底层原理与C#实现方法。无论你是刚接触上位机开发的新手，还是需要对接新设备的老手，都能从中找到实用的参考。

## OSI模型与工业协议的映射

理解协议在OSI七层模型中的位置，有助于排查通信问题和选择合适的协议。

### 各层对应的工业协议

| OSI层次 | 通用协议 | 工业协议映射 |
|---------|---------|------------|
| 第7层 应用层 | HTTP/FTP | Modbus应用层、S7应用层、OPC UA应用层、MQTT应用层 |
| 第6层 表示层 | SSL/TLS | OPC UA安全层、MQTT TLS |
| 第5层 会话层 | - | S7会话管理、OPC UA Session |
| 第4层 传输层 | TCP/UDP | Modbus TCP(502)、S7(102)、FINS(6000)、CIP(44818)、MQTT(1883) |
| 第3层 网络层 | IP | 所有基于以太网的协议共用 |
| 第2层 数据链路层 | Ethernet | 工业以太网、Profinet、EtherNet/IP |
| 第1层 物理层 | 铜缆/光纤 | RS232、RS485、RS422、以太网物理层 |

> **实践提示**：在工业现场，80%的通信问题出在第1层（物理层）和第2层（数据链路层）。检查接线、终端电阻、波特率匹配是排障的第一步。

### 串口协议 vs 以太网协议

```
串口通信(RS232/RS485)              以太网通信
┌─────────────┐              ┌───────────────────┐
│ 应用层       │              │ 应用层             │
│ (Modbus RTU) │              │ (Modbus TCP/S7/OPC)│
├─────────────┤              ├───────────────────┤
│ 数据链路层   │              │ TCP / UDP          │
│ (异步串行)   │              ├───────────────────┤
├─────────────┤              │ IP                 │
│ 物理层       │              ├───────────────────┤
│ (RS232/485)  │              │ Ethernet           │
└─────────────┘              └───────────────────┘
```

## IoTGateway的驱动架构

IoTGateway采用**插件化驱动架构**，每种协议实现为一个独立的DLL插件，通过反射动态加载。这种设计使得添加新协议无需修改核心代码。

### 驱动接口 IDriver

所有驱动插件都实现统一的 `IDriver` 接口：

```csharp
// Plugins/PluginInterface/IDriver.cs
public interface IDriver : IDisposable
{
    public string DeviceId { get; }
    public bool IsConnected { get; }
    public int Timeout { get; }
    public uint MinPeriod { get; }

    public ILogger _logger { get; set; }

    // 建立连接
    public bool Connect();

    // 关闭连接
    public bool Close();

    // 标准数据读取
    public DriverReturnValueModel Read(DriverAddressIoArgModel ioArg);

    // Rpc写入（远程过程调用）
    public Task<RpcResponse> WriteAsync(string RequestId, string Method,
        DriverAddressIoArgModel ioArg);
}
```

这个接口定义了驱动的生命周期（Connect/Close/Dispose）和数据操作（Read/WriteAsync）。详细的接口设计和属性系统将在[[自定义驱动开发指南]]中深入讲解。

### 属性驱动的自动配置

IoTGateway通过自定义Attribute实现驱动参数的自动发现和UI生成：

```csharp
// 类级别 - 声明驱动支持的设备类型
[DriverSupported("TCP")]
[DriverSupported("Rtu")]

// 类级别 - 驱动元信息
[DriverInfo("ModBusMaster", "V1.0.0", "Copyright IoTGateway.net 20230220")]

// 属性级别 - 配置参数自动映射到Web UI
[ConfigParameter("IP地址")] public string IpAddress { get; set; } = "127.0.0.1";

// 方法级别 - 暴露可读方法给上层调用
[Method("功能码:03", description: "HoldingRegisters读保持寄存器")]
public DriverReturnValueModel HoldingRegisters(DriverAddressIoArgModel ioArg)
```

## 通信可靠性设计

在工业现场，通信可靠性是上位机开发的核心挑战。以下是IoTGateway采用的关键策略：

### 1. 超时与重试

每个驱动都配置了超时时间和最小通信周期：

```csharp
[ConfigParameter("超时时间ms")] public int Timeout { get; set; } = 3000;
[ConfigParameter("最小通讯周期ms")] public uint MinPeriod { get; set; } = 3000;
```

### 2. 连接状态检测

所有驱动都实现了 `IsConnected` 属性，通过实际探测判断连接是否存活：

```csharp
// Modbus - 根据主站类型检测不同传输层
public bool IsConnected
{
    get
    {
        switch (MasterType)
        {
            case MasterType.Tcp:
                return _tcpClient != null && _master != null && _tcpClient.Connected;
            case MasterType.Rtu:
                return _serialPort != null && _master != null && _serialPort.IsOpen;
            // ...
        }
    }
}

// S7 - 直接检查PLC对象状态
public bool IsConnected => _plc is { IsConnected: true };
```

### 3. 差异化上报

MessageService实现了数据变化检测，仅在数据变化或超时后才上报云端，减少网络流量：

```csharp
// MessageService.cs
private bool CanPubTelemetry(string deviceName, Device device,
    Dictionary<string, List<PayLoad>> sendModel)
{
    if (device.CgUpload) // 启用差异检测
    {
        bool isTimeExceeded = (newPayload.TS - lastPayload.TS) > device.EnforcePeriod;
        bool isValueChanged = !newPayload.Values.SequenceEqual(lastPayload.Values);
        return isTimeExceeded || isValueChanged;
    }
    return true;
}
```

## 各协议概述

以下各节对每种协议做简要介绍，详细内容请参阅对应的专题文章。

### Modbus - 工业通信的"通用语"

Modbus是应用最广泛的工业通信协议，几乎所有PLC和仪表都支持。IoTGateway支持8种Modbus变体（TCP/UDP/RTU/ASCII及其组合）。

- 详细协议解析与代码实现 → [[Modbus协议详解]]
- 串口物理层基础 → [[串口通信基础]]

### Siemens S7 - 西门子PLC专用协议

S7协议是西门子PLC的专有通信协议，支持S7-200/300/400/1200/1500/200Smart全系列。基于ISO-on-TCP（RFC 1006），默认端口102。

- 详细协议解析与代码实现 → [[Siemens-S7协议]]

### OPC UA / OPC DA - 统一架构标准

OPC（Open Platform Communications）是工业通信的国际标准。OPC DA基于Windows COM/DCOM，OPC UA则跨平台并内置安全机制。

- 详细协议对比与代码实现 → [[OPC标准与实现]]

### MQTT - 物联网通信协议

MQTT是轻量级的发布/订阅消息协议，IoTGateway使用MQTT作为北向通信协议，将采集的数据上报到ThingsBoard、IoTSharp等物联网平台。

- 详细协议解析与平台对接 → [[MQTT协议与物联网通信]]

### 三菱 Melsec MC / 欧姆龙 FINS / AB CIP

三种主流PLC厂商的专有协议，IoTGateway通过IoTClient NuGet库统一对接。

- 三种协议的实现模式 → [[其他PLC协议]]

### Fanuc FOCAS / MTConnect - 数控机床通信

Fanuc FOCAS是Fanuc CNC系统的专用通信库，MTConnect是机床行业的开放标准。

- 详细协议解析与数据采集 → [[CNC系统通信]]

## 协议选择的实践建议

### 新建项目

如果你的项目是全新规划的，推荐以下技术栈：

1. **设备层**：优先选择支持以太网通信的PLC（西门子S7-1200/1500、三菱iQ-R等）
2. **协议层**：PLC用原生协议（S7/MC），第三方设备用Modbus TCP
3. **统一接入层**：如果有多种PLC混用，考虑OPC UA做统一中间层
4. **云端上报**：MQTT，搭配ThingsBoard或IoTSharp

### 改造项目

老旧设备改造通常面临更多限制：

1. **串口设备**：通过RS485总线 + Modbus RTU采集，或用串口转以太网模块
2. **老PLC**：S7-200用PPI转Modbus，S7-300用MPI转以太网
3. **老OPC DA**：通过IoTGateway桥接为MQTT或OPC UA
4. **无线需求**：增加4G/WiFi DTU，透传Modbus RTU

### 性能参考

| 场景 | 推荐协议 | 典型点位数 | 轮询周期 |
|------|---------|-----------|---------|
| 小型设备（<100点） | Modbus RTU | 100 | 500ms-1s |
| 中型产线（100-1000点） | Modbus TCP / S7 | 1000 | 100-500ms |
| 大型工厂（>1000点） | OPC UA | 10000+ | 50-200ms |
| 高速采集（>10000点） | S7 + 批量读取 | 50000+ | 10-50ms |

## 开发环境准备

### 必备工具

1. **Visual Studio 2022** 或 **VS Code** + C# Dev Kit
2. **.NET 8 SDK**（IoTGateway基于.NET 8）
3. **Wireshark** - 协议抓包分析利器
4. **Modbus Poll / Modbus Slave** - Modbus调试工具
5. **MQTTX** - MQTT客户端调试工具
6. **UaExpert** - OPC UA客户端调试工具

### IoTGateway项目编译

```bash
git clone https://github.com/iioter/iotgateway.git
cd iotgateway
dotnet restore
dotnet build
cd IoTGateway
dotnet run
```

启动后访问 `http://localhost:5188` 进入Web管理界面，内置MQTT Broker运行在端口1888。
