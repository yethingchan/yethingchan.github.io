## 驱动插件架构

IoTGateway的核心设计思想是**插件化驱动架构**——每种工业协议的实现都是一个独立的DLL文件，运行时通过反射（Reflection）动态加载。这种架构使得添加新协议支持无需修改核心代码，实现了真正的**开放封闭原则**（Open/Closed Principle）。

## DriverService - 驱动管理核心

DriverService是IoTGateway的驱动管理中枢，负责驱动DLL的扫描、加载和配置提取。

### 初始化流程

```csharp
// DriverService.cs
public class DriverService
{
    private readonly string _driverPath;
    private readonly string[] _driverFiles;
    private readonly List<DriverInfo> _driverInfos = new();
    
    public IReadOnlyList<DriverInfo> DriverInfos => _driverInfos.AsReadOnly();

    public DriverService(IConfiguration configRoot, ILogger<DriverService> logger)
    {
        _logger = logger;
        
        // 驱动目录: 应用根目录/drivers/net8.0/
        _driverPath = Path.Combine(
            AppDomain.CurrentDomain.BaseDirectory, "drivers/net8.0");

        // 1. 扫描目录下所有DLL文件
        _driverFiles = Directory.GetFiles(_driverPath, "*.dll");
        
        // 2. 加载所有驱动
        LoadAllDrivers();
    }
}
```

### 驱动扫描与加载

```csharp
// LoadAllDrivers - 遍历所有DLL，查找实现了IDriver的类
private void LoadAllDrivers()
{
    foreach (var file in _driverFiles)
    {
        try
        {
            // 动态加载DLL为程序集
            var dll = Assembly.LoadFrom(file);
            
            // 查找所有实现了IDriver接口的类
            foreach (var type in dll.GetTypes()
                .Where(x => typeof(IDriver).IsAssignableFrom(x) && x.IsClass))
            {
                _driverInfos.Add(new DriverInfo
                {
                    FileName = Path.GetFileName(file),  // DLL文件名
                    Type = type                          // 驱动类型
                });
                _logger.LogInformation(
                    $"LoadAllDrivers: {Path.GetFileName(file)} loaded.");
            }
        }
        catch (Exception ex)
        {
            // 某些DLL可能不是驱动（如依赖库），忽略加载错误
            _logger.LogError(ex, $"LoadAllDrivers Error for file {file}");
        }
    }
}
```

### 反射发现机制详解

```
DriverService 的驱动发现流程:

1. 扫描 drivers/net8.0/ 目录下所有 *.dll 文件

2. 对每个DLL:
   Assembly.LoadFrom(file)          ← 加载程序集到内存
   │
   └─→ dll.GetTypes()               ← 获取所有类型
       │
       └─→ Where(x => 
              typeof(IDriver).IsAssignableFrom(x)  ← 实现了IDriver
              && x.IsClass                          ← 是类（非接口/抽象类）
           )
           │
           └─→ 添加到 _driverInfos 列表

3. 最终得到所有可用驱动的类型信息
```

> **关键API**: `typeof(IDriver).IsAssignableFrom(x)` 是.NET反射中判断类型继承关系的标准方法。如果类 `x` 实现了 `IDriver` 接口，则返回 `true`。

### 驱动信息结构

```csharp
// DriverInfo.cs - 驱动信息内部模型
public class DriverInfo
{
    public string FileName { get; set; }  // DLL文件名
    public Type Type { get; set; }        // 驱动类型（反射Type对象）
}
```

## 驱动实例化与配置

### 获取可用驱动列表

Web UI在创建新设备时需要显示可用的驱动列表：

```csharp
public List<ComboSelectListItem> GetAllDrivers()
{
    var driverFilesComboSelect = new List<ComboSelectListItem>();
    
    // 查询已注册的驱动（防止重复注册）
    using var dc = new DataContext(...);
    var drivers = dc.Set<Driver>().AsNoTracking().ToList();

    foreach (var file in _driverFiles)
    {
        var dll = Assembly.LoadFrom(file);
        
        // 只列出包含IDriver实现的DLL
        if (dll.GetTypes().Any(x => typeof(IDriver).IsAssignableFrom(x) && x.IsClass))
        {
            var fileName = Path.GetFileName(file);
            driverFilesComboSelect.Add(new ComboSelectListItem
            {
                Text = fileName,
                Value = fileName,
                // 已注册的驱动标记为禁用
                Disabled = drivers.Any(x => x.FileName == fileName)
            });
        }
    }

    return driverFilesComboSelect;
}
```

### 自动提取配置参数

当用户在Web UI中选择一个驱动后，DriverService会通过反射自动提取该驱动的所有配置参数，并写入数据库：

```csharp
public void AddConfigs(Guid? deviceId, Guid? driverId)
{
    // 1. 查找驱动类型信息
    var driverInfo = _driverInfos.SingleOrDefault(
        x => x.Type.FullName == driver.AssembleName);

    // 2. 通过反射创建驱动实例（获取默认值）
    var constructor = driverInfo.Type.GetConstructor(
        new[] { typeof(string), typeof(ILogger) });
    var instance = constructor.Invoke(
        new object[] { device?.DeviceName, _logger }) as IDriver;

    // 3. 遍历驱动类的所有属性
    foreach (var property in driverInfo.Type.GetProperties())
    {
        // 4. 查找带有[ConfigParameter]特性的属性
        var configAttribute = property.GetCustomAttribute<ConfigParameterAttribute>();
        if (configAttribute != null)
        {
            // 5. 获取属性的默认值
            var value = property.GetValue(instance)?.ToString();
            
            // 6. 创建数据库记录
            var deviceConfig = new DeviceConfig
            {
                ID = Guid.NewGuid(),
                DeviceId = deviceId,
                DeviceConfigName = property.Name,       // 属性名
                Description = configAttribute.Description, // 描述
                Value = value                            // 默认值
            };

            // 7. 如果是枚举类型，额外保存枚举信息
            if (property.PropertyType.IsEnum)
            {
                var enumValues = Enum.GetValues(property.PropertyType)
                    .Cast<object>()
                    .ToDictionary(
                        val => Enum.GetName(property.PropertyType, val), 
                        val => (int)val);
                deviceConfig.EnumInfo = JsonSerializer.Serialize(enumValues);
            }

            dc.Set<DeviceConfig>().Add(deviceConfig);
        }
    }

    dc.SaveChanges();
}
```

### 配置提取流程图

```
用户选择驱动 → AddConfigs() 被调用

1. 反射创建驱动实例
   constructor.Invoke({ deviceName, logger })
   → DeviceModBusMaster("设备1", logger)
   → 所有[ConfigParameter]属性获得默认值

2. 遍历属性，提取配置
   foreach property in Type.GetProperties()
   │
   ├─ 有[ConfigParameter]? ──No──→ 跳过
   │
   └─ Yes
      │
      ├─ property.Name → "IpAddress"
      ├─ configAttribute.Description → "IP地址"
      ├─ property.GetValue(instance) → "127.0.0.1" (默认值)
      │
      ├─ property.PropertyType.IsEnum?
      │   ├─ No → 创建普通配置项
      │   └─ Yes → 额外保存枚举值列表
      │
      └─ 写入数据库 DeviceConfig 表

3. Web UI 自动渲染配置表单
   文本框: IP地址 = "127.0.0.1"
   文本框: 端口号 = "502"
   下拉框: 主站类型 = TCP/UDP/RTU/...
   文本框: 从站号 = "1"
   ...
```

## 驱动实例的生命周期

### 从加载到运行

```
IoTGateway 启动流程:

1. IoTBackgroundService.OnStarted()
   → 创建 DeviceService 实例
   
2. DeviceService 构造函数
   → 创建 DriverService（加载所有驱动DLL）
   → 创建 MessageService（连接MQTT Broker）
   
3. DeviceService 遍历数据库中的设备配置
   → 对每个启用的设备:
     a. 根据设备关联的驱动DLL名，找到驱动类型
     b. 通过反射创建驱动实例
     c. 从数据库读取用户配置的参数，通过反射设置属性值
     d. 调用 Connect() 建立连接
     e. 创建 DeviceThread 进行周期性数据采集
     
4. DeviceThread 运行循环
   → 每隔 MinPeriod 毫秒:
     a. 遍历设备的变量列表
     b. 根据变量配置的[Method]，通过反射调用对应的读取方法
     c. 收集数据，发送给 MessageService
     d. MessageService 通过 MQTT 上报到物联网平台
```

### 驱动调用时序

```
DeviceThread 采集数据的调用流程:

DeviceThread                    Driver(IDriver)              设备(PLC)
    │                                │                          │
    │── 读取变量1 ──────────────────→│                          │
    │   反射调用 [Method("功能码:03")]│── Modbus请求 ──────────→│
    │                                │←─ 寄存器数据 ───────────│
    │   DriverReturnValueModel       │                          │
    │←─ { Value=25.3, Status=Good } ─│                          │
    │                                │                          │
    │── 读取变量2 ──────────────────→│                          │
    │   反射调用 [Method("功能码:03")]│── Modbus请求 ──────────→│
    │                                │←─ 寄存器数据 ───────────│
    │←─ { Value=100, Status=Good } ──│                          │
    │                                │                          │
    │   (等待MinPeriod毫秒)           │                          │
    │                                │                          │
    │── 下一轮采集... ──────────────→│                          │
```

### Method Attribute的运行时使用

DeviceThread通过反射查找并调用标记了[Method]的方法：

```csharp
// 伪代码：DeviceThread中的方法调用逻辑
foreach (var variable in device.Variables)
{
    // variable.MethodName 存储了方法名，如 "HoldingRegisters"
    
    // 1. 通过反射查找方法
    var method = driver.GetType().GetMethod(variable.MethodName);
    
    // 2. 构建参数
    var ioArg = new DriverAddressIoArgModel
    {
        ID = variable.ID,
        Address = variable.Address,
        ValueType = variable.ValueType,
        EndianType = variable.EndianType
    };
    
    // 3. 反射调用方法
    var result = method.Invoke(driver, new object[] { ioArg }) 
        as DriverReturnValueModel;
    
    // 4. 处理结果
    if (result.StatusType == VaribaleStatusTypeEnum.Good)
    {
        // 收集数据，准备上报
        payload.Values.Add(new ValueItem
        {
            Name = variable.Name,
            Value = result.Value,
            Timestamp = DateTime.UtcNow
        });
    }
}
```

## DLL热加载机制

### 当前机制

IoTGateway当前的驱动加载是在启动时一次性完成的：

```csharp
// 启动时加载
public DriverService(IConfiguration configRoot, ILogger<DriverService> logger)
{
    _driverFiles = Directory.GetFiles(_driverPath, "*.dll");
    LoadAllDrivers();
}
```

这意味着：
- **添加新驱动**：需要重启IoTGateway
- **更新驱动**：需要停止IoTGateway → 替换DLL → 重启IoTGateway
- **删除驱动**：在Web UI中删除驱动记录 → 重启IoTGateway

### 未来可能的热加载方案

```
热加载方案（概念设计）:

方案1: FileSystemWatcher 监控
  var watcher = new FileSystemWatcher(_driverPath, "*.dll");
  watcher.Created += OnDllAdded;    // 新DLL出现
  watcher.Deleted += OnDllRemoved;  // DLL被删除
  watcher.Changed += OnDllChanged;  // DLL被更新

方案2: AssemblyLoadContext (.NET Core)
  // 使用可卸载的AssemblyLoadContext
  var context = new AssemblyLoadContext("DriverContext", isCollectible: true);
  var assembly = context.LoadFromAssemblyPath(dllPath);
  
  // 卸载时
  context.Unload();
  // GC回收后重新加载新版本

方案3: 插件商店
  Web UI → 上传DLL → 动态加载 → 即时可用
```

## 性能优化

### 驱动加载性能

```
启动时加载优化:
1. 只扫描 drivers/net8.0/ 目录下的DLL
2. 使用 Assembly.LoadFrom() 而非 Assembly.Load()
   (LoadFrom不需要程序集在GAC中)
3. 对非驱动DLL（如依赖库）的加载异常直接忽略
4. 所有驱动信息缓存到内存列表，后续查找O(1)
```

### 运行时性能

```
反射调用优化:
1. 驱动实例长期驻留内存，不重复创建
2. MethodInfo在启动时获取并缓存
3. 配置参数通过属性直接访问（非反射）
4. [Method]方法在DeviceThread初始化时缓存

数据流优化:
1. 批量读取减少通信次数（Modbus ReadMultiple）
2. 差异化上报减少MQTT消息量
3. ConcurrentDictionary保证线程安全
```

## 扩展驱动架构

### 添加新协议的标准流程

```
步骤1: 创建驱动项目
  mkdir Plugins/Drivers/PLC.MyProtocol
  dotnet new classlib -n PLC.MyProtocol -f net8.0

步骤2: 添加引用
  dotnet add reference PluginInterface.csproj

步骤3: 实现IDriver接口
  创建 DeviceMyProtocol.cs
  添加 [DriverSupported] [DriverInfo] [ConfigParameter] [Method]

步骤4: 编译
  dotnet build -c Release

步骤5: 部署
  将输出DLL复制到 drivers/net8.0/ 目录

步骤6: 重启IoTGateway
  新驱动自动被DriverService发现和加载

步骤7: Web UI配置
  驱动管理 → 注册新驱动
  设备管理 → 创建设备 → 选择新驱动
  变量管理 → 配置变量地址和读取方法
```

### 第三方开发者贡献驱动

IoTGateway的插件架构使得第三方开发者可以独立开发和分发驱动：

```
第三方驱动开发流程:

1. Fork IoTGateway 源码
2. 参考现有驱动（如PLC.OmronFins）创建新项目
3. 实现IDriver接口
4. 编译为独立DLL
5. 用户只需将DLL放入drivers/net8.0/即可使用
6. 无需修改IoTGateway核心代码
```

## 小结

| 概念 | 实现方式 |
|------|---------|
| 驱动发现 | `Directory.GetFiles` + `Assembly.LoadFrom` + `typeof(IDriver).IsAssignableFrom` |
| 配置提取 | 反射遍历属性 + `[ConfigParameter]` Attribute + 默认值获取 |
| 枚举支持 | `property.PropertyType.IsEnum` + `Enum.GetValues` → JSON序列化 |
| 方法调用 | 反射查找`[Method]`方法 + `MethodInfo.Invoke()` |
| 实例创建 | `type.GetConstructor(typeof(string), typeof(ILogger))` |
| 驱动部署 | 复制DLL到 `drivers/net8.0/` 目录，重启生效 |
| 线程模型 | 每个设备一个DeviceThread，调用驱动的Read方法 |
