## 数据库迁移实践

### 什么是数据库迁移

数据库迁移（Migration）是 EF Core 的核心功能之一：当你修改了 C# 实体模型（添加字段、修改类型、添加索引等），EF Core 可以自动生成对应的 SQL 脚本来更新数据库结构，而不需要手动编写 ALTER TABLE 语句。

迁移的价值在于：

- **版本控制**：每次迁移都有时间戳标记，可以追溯数据库结构的变更历史
- **团队协作**：迁移文件可以提交到 Git，团队成员共享数据库变更
- **多环境一致**：开发、测试、生产环境的数据库结构通过迁移保持同步

### IoTGateway 的迁移文件结构

```
IoTGateway.DataAccess/
├── DataContext.cs
└── Migrations/
    ├── 20250404155722_Init.cs               # 初始迁移
    ├── 20250404155722_Init.Designer.cs      # 设计器快照
    ├── 20250404160000_CommentAndIndex.cs    # 添加注释和索引
    ├── 20250404160000_CommentAndIndex.Designer.cs
    └── DataContextModelSnapshot.cs          # 当前模型快照
```

每个迁移包含两个文件：
- `*.cs`：实际的迁移代码（Up 和 Down 方法）
- `*.Designer.cs`：设计器文件，记录迁移时的模型快照

### DesignTimeFactory：迁移的桥梁

EF Core 迁移工具在设计时需要创建 `DataContext` 实例来对比模型差异。`DataContextFactory` 提供了这个能力：

```csharp
public class DataContextFactory : IDesignTimeDbContextFactory<DataContext>
{
    public DataContext CreateDbContext(string[] args)
    {
        return new DataContext(
            "Data Source = ../IoTGateway/data/iotgateway.db",
            DBTypeEnum.SQLite);
    }
}
```

> **路径说明**：`../IoTGateway/data/iotgateway.db` 是相对于 `IoTGateway.DataAccess` 项目目录的路径。迁移工具在 DataAccess 项目目录下运行时，这个路径指向 Web 项目的 data 目录。

### 创建迁移

#### 命令方式

```bash
# 在解决方案根目录执行
dotnet ef migrations add <MigrationName> \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway

# 示例：添加新的字段后创建迁移
dotnet ef migrations add AddDeviceCmdPeriod \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway
```

#### Package Manager Console 方式（Visual Studio）

```powershell
# 在 Package Manager Console 中执行
Add-Migration AddDeviceCmdPeriod -Project IoTGateway.DataAccess -StartupProject IoTGateway
```

#### 迁移命名建议

| 场景 | 建议命名 | 说明 |
|------|---------|------|
| 初始迁移 | `Init` | 首次创建数据库结构 |
| 添加字段 | `AddXxxField` | 如 AddDeviceCmdPeriod |
| 修改字段 | `ModifyXxxField` | 如 ModifyDeviceNameLength |
| 删除字段 | `RemoveXxxField` | 如 RemoveDeviceOldFlag |
| 添加索引 | `AddXxxIndex` | 如 AddDeviceAutoStartIndex |
| 添加注释 | `CommentAndIndex` | 批量添加注释和索引 |

### 迁移文件内容解析

一个典型的迁移文件包含 `Up`（升级）和 `Down`（回滚）两个方法：

```csharp
public partial class CommentAndIndex : Migration
{
    protected override void Up(MigrationBuilder migrationBuilder)
    {
        // 添加表注释
        migrationBuilder.AlterTable(
            name: "Devices",
            comment: "设备维护");

        // 添加列注释
        migrationBuilder.AlterColumn<string>(
            name: "DeviceName",
            table: "Devices",
            comment: "名称");

        // 添加索引
        migrationBuilder.CreateIndex(
            name: "IX_Devices_DeviceName",
            table: "Devices",
            column: "DeviceName");

        migrationBuilder.CreateIndex(
            name: "IX_Devices_AutoStart",
            table: "Devices",
            column: "AutoStart");
    }

    protected override void Down(MigrationBuilder migrationBuilder)
    {
        // 回滚操作
        migrationBuilder.DropIndex(
            name: "IX_Devices_DeviceName",
            table: "Devices");

        migrationBuilder.DropIndex(
            name: "IX_Devices_AutoStart",
            table: "Devices");
    }
}
```

### 应用迁移

#### 自动迁移（SQLite）

IoTGateway 在 `IoTBackgroundService` 中为 SQLite 数据库实现了自动迁移：

```csharp
if (DbType == DBTypeEnum.SQLite)
{
    using var dc = new DataContext(connnectSetting, DbType);
    if (dc.Database.GetPendingMigrations().Any())
    {
        dc.Database.Migrate();
    }
}
```

这意味着 SQLite 用户只需更新代码并重启应用，数据库结构会自动更新。

#### 手动迁移（其他数据库）

对于 MySQL、PostgreSQL、SQL Server 等数据库，需要手动执行迁移：

```bash
# 应用所有未执行的迁移
dotnet ef database update \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway

# 指定迁移到特定版本
dotnet ef database update Init \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway
```

#### 生成 SQL 脚本（推荐生产环境）

在生产环境中，建议先生成 SQL 脚本再手动执行：

```bash
# 生成从初始状态到最新的完整SQL脚本
dotnet ef migrations script \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway \
    --output migration.sql

# 生成从特定版本到最新的增量SQL脚本
dotnet ef migrations script Init \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway \
    --output migration_incremental.sql

# 生成幂等脚本（可重复执行）
dotnet ef migrations script \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway \
    --idempotent \
    --output migration_idempotent.sql
```

### 回滚迁移

当迁移出现问题时，可以回滚到之前的版本：

```bash
# 回滚到特定迁移版本
dotnet ef database update CommentAndIndex \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway

# 回滚所有迁移（危险！会删除所有表）
dotnet ef database update 0 \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway
```

> **警告**：回滚操作会执行迁移的 `Down` 方法，可能导致数据丢失。在生产环境中回滚前务必备份数据库。

### 移除未应用的迁移

如果创建了迁移但还未应用到数据库，可以移除它：

```bash
# 移除最后一个未应用的迁移
dotnet ef migrations remove \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway
```

### 多数据库迁移注意事项

由于 IoTGateway 支持多种数据库，迁移时需要注意：

#### 1. 迁移文件是通用的

EF Core 生成的迁移文件使用抽象的 `MigrationBuilder` API，不直接包含特定数据库的 SQL。EF Core 在运行时会根据目标数据库自动转换为对应的 SQL 方言。

```csharp
// 迁移文件中的抽象操作
migrationBuilder.AddColumn<uint>(
    name: "CmdPeriod",
    table: "Devices",
    defaultValue: 0u);

// SQLite 生成: ALTER TABLE "Devices" ADD COLUMN "CmdPeriod" INTEGER NOT NULL DEFAULT 0;
// MySQL 生成:   ALTER TABLE `Devices` ADD COLUMN `CmdPeriod` INT UNSIGNED NOT NULL DEFAULT 0;
// PgSql 生成:   ALTER TABLE "Devices" ADD COLUMN "CmdPeriod" INTEGER NOT NULL DEFAULT 0;
```

#### 2. 某些功能可能有差异

| 功能 | SQLite | MySQL | PostgreSQL | SQL Server |
|------|--------|-------|-----------|-----------|
| ALTER COLUMN | 不支持（需重建表） | 部分支持 | 完全支持 | 完全支持 |
| 表注释 | 不支持 | 支持 | 支持 | 支持 |
| 列注释 | 不支持 | 支持 | 支持 | 支持 |
| 索引 | 支持 | 支持 | 支持 | 支持 |

> **SQLite 限制**：SQLite 不支持 `ALTER COLUMN` 操作。如果需要修改列类型，EF Core 会创建新表、迁移数据、删除旧表、重命名新表。这个过程在大量数据时可能较慢。

#### 3. 注释和索引迁移

IoTGateway 的 `CommentAndIndex` 迁移专门处理 `[Comment]` 和 `[Index]` 注解生成的数据库注释和索引。这些在 SQLite 中可能不生效，但在 MySQL/PostgreSQL 中会正确创建。

### 迁移工作流总结

```
1. 修改实体模型
   ├── 添加/修改/删除字段
   ├── 添加 [Index] 注解
   └── 添加 [Comment] 注解
       │
2. 创建迁移
   └── dotnet ef migrations add <Name>
       │
3. 验证迁移文件
   ├── 检查 Up() 方法是否符合预期
   └── 检查 Down() 方法是否正确回滚
       │
4. 应用迁移
   ├── SQLite: 自动（应用启动时）
   ├── 开发环境: dotnet ef database update
   └── 生产环境: 生成SQL脚本 → DBA审核 → 手动执行
```

### 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 找不到 DataContextFactory | 设计时工厂未正确配置 | 确保 DataContextFactory 在 DataAccess 项目中 |
| 迁移命令报错"Unable to create" | 连接字符串路径错误 | 检查 DataContextFactory 中的相对路径 |
| 迁移后表结构未变 | 未执行 database update | 运行 `dotnet ef database update` |
| 回滚后迁移文件丢失 | 使用了 migrations remove | 用 `git checkout` 恢复文件 |
