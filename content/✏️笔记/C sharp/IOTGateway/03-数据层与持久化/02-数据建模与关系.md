## 数据建模与关系

### 工业上位机的数据模型

在工业上位机系统中，数据模型的核心围绕"设备"展开。一个网关管理多个设备，每个设备由一个驱动控制，每个设备有多个变量和配置参数。IoTGateway 的数据模型精确地映射了这种工业场景的层级关系。

### 实体关系总览

```
SystemConfig (1)          Driver (1)
 传输配置                    驱动定义
     │                        │
     │                        │ (1:N)
     │                        ▼
     │                   Device (N)
     │                   设备/设备组
     │                   ┌────┴────┐
     │                   │         │
     │              (1:N)│    (1:N)│
     │                   ▼         ▼
     │            DeviceConfig   DeviceVariable
     │            通讯配置        变量定义
     │
     │              Device (1)
     │                   │
     │              (1:N)│
     │                   ▼
     └──────────→  RpcLog
                    RPC日志
```

### Device：树形设备模型

`Device` 是最核心的实体，它使用 WTM 框架的 `TreePoco<T>` 基类实现树形结构，既表示设备组又表示具体设备：

```csharp
[Comment("设备维护")]
[Index(nameof(DeviceName))]
[Index(nameof(AutoStart))]
[Index(nameof(DeviceTypeEnum))]
public class Device : TreePoco<Device>, IBasePoco
{
    [Comment("名称")]
    public string DeviceName { get; set; }

    [Comment("排序")]
    public uint Index { get; set; }

    [Comment("描述")]
    public string Description { get; set; }

    [Comment("驱动")]
    public Guid? DriverId { get; set; }
    public Driver Driver { get; set; }

    [Comment("启动")]
    public bool AutoStart { get; set; }

    [Comment("变化上传")]
    public bool CgUpload { get; set; }

    [Comment("归档周期ms")]
    public uint EnforcePeriod { get; set; }

    [Comment("指令间隔ms")]
    public uint CmdPeriod { get; set; }

    [Comment("类型(组或设备)")]
    public DeviceTypeEnum DeviceTypeEnum { get; set; }

    // 审计字段
    public DateTime? CreateTime { get; set; }
    public string CreateBy { get; set; }
    public DateTime? UpdateTime { get; set; }
    public string UpdateBy { get; set; }

    // 导航属性
    public List<DeviceConfig> DeviceConfigs { get; set; }
    public List<DeviceVariable> DeviceVariables { get; set; }
}
```

#### TreePoco 树形结构

`TreePoco<T>` 提供了父子关系的自动管理：

```csharp
// TreePoco<T> 内置字段（WTM框架提供）
public class TreePoco<T> where T : TreePoco<T>
{
    public Guid? ParentId { get; set; }    // 父节点ID
    public T Parent { get; set; }          // 父节点导航
    public List<T> Children { get; set; }  // 子节点列表
    public int Level { get; set; }         // 层级深度
}
```

设备树的使用方式：

```
设备组: "车间A"           (DeviceTypeEnum.Group, ParentId = null)
    ├── 设备: "1号PLC"     (DeviceTypeEnum.Device, ParentId = 车间A.ID)
    ├── 设备: "2号PLC"     (DeviceTypeEnum.Device, ParentId = 车间A.ID)
    └── 设备: "温湿度仪"   (DeviceTypeEnum.Device, ParentId = 车间A.ID)

设备组: "车间B"           (DeviceTypeEnum.Group, ParentId = null)
    ├── 设备: "3号PLC"     (DeviceTypeEnum.Device, ParentId = 车间B.ID)
    └── 设备: "电能表"     (DeviceTypeEnum.Device, ParentId = 车间B.ID)
```

> **索引优化**：`DeviceName`、`AutoStart`、`DeviceTypeEnum` 三个字段都添加了 `[Index]` 注解，因为它们是高频查询条件——按名称搜索、筛选自启动设备、区分设备组和设备。

### Driver：驱动定义

```csharp
[Comment("驱动管理")]
public class Driver : BasePoco
{
    [Comment("驱动名")]
    public string DriverName { get; set; }

    [Comment("文件名")]
    public string FileName { get; set; }

    [Comment("程序集名")]
    public string AssembleName { get; set; }

    [Comment("剩余授权数")]
    public int AuthorizesNum { get; set; }
}
```

| 字段 | 说明 | 示例值 |
|------|------|--------|
| `DriverName` | 驱动显示名 | "Modbus TCP Master" |
| `FileName` | DLL文件名 | "PLC.ModBusMaster.dll" |
| `AssembleName` | 完整类名 | "IoTGateway.Plugin.ModBusMaster" |
| `AuthorizesNum` | 授权设备数 | 10 |

> **AssembleName 的作用**：`DeviceService` 通过 `device.Driver.AssembleName` 在已加载的驱动列表中找到对应的 `Type`，然后通过反射创建实例。

### DeviceVariable：变量定义

```csharp
[Comment("变量配置")]
[Index(nameof(Name))]
[Index(nameof(Method))]
[Index(nameof(DeviceAddress))]
[Index(nameof(DataType))]
public class DeviceVariable : TopBasePoco, IVariable
{
    // === 持久化字段 ===
    public string Name { get; set; }          // 变量名
    public string Description { get; set; }   // 描述
    public string Method { get; set; }        // 读取方法名
    public string DeviceAddress { get; set; } // 设备地址（如 "40001"）
    public DataTypeEnum DataType { get; set; } // 数据类型
    public bool IsTrigger { get; set; }       // 是否触发变量
    public EndianEnum EndianType { get; set; } // 字节序
    public string Expressions { get; set; }   // 计算表达式
    public bool IsUpload { get; set; }        // 是否上传
    public ProtectTypeEnum ProtectType { get; set; } // 读写权限
    public uint Index { get; set; }           // 排序
    public string Alias { get; set; }         // 别名（子设备名）
    public Guid? DeviceId { get; set; }       // 外键

    // === 运行时字段（[NotMapped]）===
    [NotMapped] public object Value { get; set; }
    [NotMapped] public object CookedValue { get; set; }
    [NotMapped] public string Message { get; set; }
    [NotMapped] public DateTime Timestamp { get; set; }
    [NotMapped] public VaribaleStatusTypeEnum StatusType { get; set; }
    [NotMapped] public object[] Values { get; set; } = new object[3];
    [NotMapped] public object[] CookedValues { get; set; } = new object[3];
}
```

#### 环形缓冲区设计

`DeviceVariable` 使用长度为3的数组实现环形缓冲区，记录最近三次的原值和计算后的值：

```csharp
[NotMapped]
public object[] Values { get; set; } = new object[3];

public void EnqueueVariable(object value)
{
    Values[2] = Values[1];  // 旧值后移
    Values[1] = Values[0];
    Values[0] = value;      // 新值插入
}
```

```
时间线: t0 → t1 → t2 → t3

Values数组状态:
t0: [val0, null, null]
t1: [val1, val0, null]
t2: [val2, val1, val0]
t3: [val3, val2, val1]

用途:
- Values[0] vs Values[1]: 变化检测（当前值 vs 上次值）
- Values[0..2]: 趋势分析（最近三次变化方向）
- 表达式计算: 可使用 history[0], history[1], history[2] 引用历史值
```

#### DataSide 枚举

`DataSide` 用于标识配置属性的归属侧，在 IoT 平台对接中非常重要：

```csharp
public enum DataSide
{
    AnySide = 0,      // 任意侧（客户端和服务端都可用）
    ClientSide = 2    // 客户端侧（设备端属性）
}
```

#### EnumInfo：枚举值的JSON序列化

当驱动配置属性是枚举类型时，`EnumInfo` 存储该枚举的所有可选值：

```csharp
// DriverService.AddConfigs() 中生成
if (property.PropertyType.IsEnum)
{
    var enumValues = Enum.GetValues(property.PropertyType)
        .Cast<object>()
        .ToDictionary(
            val => Enum.GetName(property.PropertyType, val),
            val => (int)val);
    deviceConfig.EnumInfo = JsonSerializer.Serialize(enumValues);
}
```

生成的 JSON 格式如：`{"Tcp":0, "Udp":1, "Serial":2}`

### 基类体系

所有实体都继承自 WTM 框架的基类体系：

```
TopBasePoco
├── ID: Guid（主键）
│
BasePoco : TopBasePoco
├── CreateTime, CreateBy
├── UpdateTime, UpdateBy
│
TreePoco<T> : BasePoco
├── ParentId: Guid?
├── Parent: T
├── Children: List<T>
├── Level: int
```

| 实体 | 继承基类 | 说明 |
|------|---------|------|
| Device | TreePoco | 树形结构，支持分组 |
| Driver | BasePoco | 带审计字段 |
| DeviceConfig | BasePoco | 带审计字段 |
| DeviceVariable | TopBasePoco | 仅ID，无审计字段 |
| SystemConfig | BasePoco | 带审计字段 |
| RpcLog | TopBasePoco | 仅ID，自带时间字段 |

### 外键关系总结

| 关系 | 类型 | 外键字段 | 说明 |
|------|------|---------|------|
| Device → Driver | 多对一 | Device.DriverId | 一个设备使用一个驱动 |
| Device → DeviceConfig | 一对多 | DeviceConfig.DeviceId | 一个设备多个配置 |
| Device → DeviceVariable | 一对多 | DeviceVariable.DeviceId | 一个设备多个变量 |
| Device → RpcLog | 一对多 | RpcLog.DeviceId | 一个设备多条RPC日志 |
| Device → Device (自关联) | 多对一 | Device.ParentId | 设备组-设备层级 |

### 实体设计在工业场景的考量

1. **GUID 主键**：所有实体使用 `Guid` 作为主键，支持离线创建和分布式合并
2. **可空外键**：`DriverId` 为 `Guid?` 可空类型，因为设备组（Group）不需要驱动
3. **字符串配置值**：`DeviceConfig.Value` 统一使用 `string` 类型，通过 `ConvertSettingValue` 运行时转换
4. **运行时与持久化分离**：`DeviceVariable` 的运行时数据使用 `[NotMapped]` 标注，不写入数据库
