## 多数据库支持

### 为什么需要多数据库支持

在工业项目中，数据库的选择往往不是开发者能决定的。小型项目可能用 SQLite（零配置），中型项目用 MySQL（免费开源），大型企业可能要求 SQL Server 或 Oracle。国产化项目中还可能用到达梦数据库（DaMeng）。

IoTGateway 通过 WTM 框架和 EF Core 的抽象层，实现了一套代码支持六种数据库：

| 数据库 | 适用场景 | 配置标识 |
|--------|---------|---------|
| SQLite | 开发调试、单机部署、嵌入式 | `sqlite` |
| MySQL | 中小型项目、Linux服务器 | `mysql` |
| PostgreSQL | 中大型项目、GIS数据 | `pgsql` |
| SQL Server | 微软生态、企业级 | `sqlserver` |
| Oracle | 大型企业、金融行业 | `oracle` |
| 达梦（DaMeng） | 国产化项目、政府项目 | `dameng` |

### 配置文件中的数据库选择

在 `appsettings.json` 中，通过 `DBType` 字段指定数据库类型：

```json
{
  "Connections": [
    {
      "Key": "default",
      "Value": "Data Source = ./data/iotgateway.db",
      "DbContext": "DataContext",
      "DBType": "SQLite"
    }
  ]
}
```

不同数据库的连接字符串格式：

```json
// SQLite
"Value": "Data Source = ./data/iotgateway.db"

// MySQL
"Value": "Server=localhost;Port=3306;Database=iotgateway;Uid=root;Pwd=123456;"

// PostgreSQL
"Value": "Host=localhost;Port=5432;Database=iotgateway;Username=postgres;Password=123456;"

// SQL Server
"Value": "Server=localhost;Database=iotgateway;User Id=sa;Password=123456;TrustServerCertificate=true;"

// Oracle
"Value": "Data Source=(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=localhost)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=orcl)));User Id=system;Password=123456;"

// 达梦
"Value": "Server=localhost;Database=iotgateway;UserId=SYSDBA;Password=SYSDBA;"
```

### DBTypeEnum：数据库类型枚举

WTM 框架定义了 `DBTypeEnum` 枚举来标识数据库类型：

```csharp
// WTM 框架内置枚举
public enum DBTypeEnum
{
    SqlServer,
    MySql,
    PgSql,
    SQLite,
    Oracle,
    Memory,
    DaMeng
}
```

### IoTBackgroundService 中的数据库初始化

`IoTBackgroundService` 在启动时解析配置，将字符串类型的数据库标识转换为 `DBTypeEnum`：

```csharp
public class IoTBackgroundService : BackgroundService
{
    public static DBTypeEnum DbType;
    public static string connnectSetting;

    public IoTBackgroundService(IConfiguration configRoot, ...)
    {
        var connnectSettings = new List<ConnnectSettingsModel>();
        configRoot.Bind("Connections", connnectSettings);
        connnectSetting = connnectSettings[0].Value;

        switch (connnectSettings[0].DbType?.Trim().ToLower())
        {
            case "oracle":  DbType = DBTypeEnum.Oracle;  break;
            case "mysql":   DbType = DBTypeEnum.MySql;   break;
            case "pgsql":   DbType = DBTypeEnum.PgSql;   break;
            case "sqlite":  DbType = DBTypeEnum.SQLite;  break;
            case "memory":  DbType = DBTypeEnum.Memory;  break;
            case "dameng":  DbType = DBTypeEnum.DaMeng;  break;
        }

        // SQLite 自动迁移
        if (DbType == DBTypeEnum.SQLite)
        {
            using var dc = new DataContext(connnectSetting, DbType);
            if (dc.Database.GetPendingMigrations().Any())
                dc.Database.Migrate();
        }
    }
}
```

> **SQLite 自动迁移**：SQLite 是默认的开发数据库，因此 `IoTBackgroundService` 会在启动时自动检查并应用 Pending Migrations。其他数据库需要手动执行迁移命令。

### WTM FrameworkContext 的多数据库支持

`FrameworkContext` 基类内部根据 `DBTypeEnum` 自动选择正确的 EF Core Provider：

```csharp
// FrameworkContext 内部逻辑（简化）
protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
{
    switch (_dbType)
    {
        case DBTypeEnum.SQLite:
            optionsBuilder.UseSqlite(_cs);
            break;
        case DBTypeEnum.MySql:
            optionsBuilder.UseMySql(_cs, ServerVersion.AutoDetect(_cs));
            break;
        case DBTypeEnum.PgSql:
            optionsBuilder.UseNpgsql(_cs);
            break;
        case DBTypeEnum.SqlServer:
            optionsBuilder.UseSqlServer(_cs);
            break;
        case DBTypeEnum.Oracle:
            optionsBuilder.UseOracle(_cs);
            break;
        case DBTypeEnum.DaMeng:
            optionsBuilder.UseDm(_cs); // 达梦EF Core Provider
            break;
    }
}
```

这意味着开发者不需要关心底层数据库的 SQL 方言差异，EF Core 会自动处理：

| 功能 | SQLite | MySQL | PostgreSQL | SQL Server |
|------|--------|-------|-----------|-----------|
| 自增ID | `INTEGER PRIMARY KEY AUTOINCREMENT` | `AUTO_INCREMENT` | `SERIAL` | `IDENTITY` |
| 字符串类型 | `TEXT` | `VARCHAR` | `TEXT` | `NVARCHAR` |
| 日期类型 | `TEXT` | `DATETIME` | `TIMESTAMP` | `DATETIME2` |
| GUID | `TEXT` | `CHAR(36)` | `UUID` | `UNIQUEIDENTIFIER` |
| JSON | `TEXT` | `JSON` | `JSONB` | `NVARCHAR(MAX)` |

### 运行时 DataContext 创建

在后台服务中，`DataContext` 使用连接字符串和数据库类型手动创建：

```csharp
// DeviceService 中
using var dc = new DataContext(
    IoTBackgroundService.connnectSetting,
    IoTBackgroundService.DbType);

var devices = dc.Set<Device>()
    .Where(x => x.DeviceTypeEnum == DeviceTypeEnum.Device)
    .Include(x => x.Driver)
    .AsNoTracking()
    .ToList();
```

在 `DeviceThread` 的 RPC 处理中同样如此：

```csharp
// DeviceThread 中记录RPC日志
await using var dc = new DataContext(
    IoTBackgroundService.connnectSetting,
    IoTBackgroundService.DbType);
dc.Set<RpcLog>().Add(rpcLog);
await dc.SaveChangesAsync();
```

> **注意 `using` vs `await using`**：在异步方法中使用 `await using` 确保 DataContext 在异步操作完成后才被释放。

### PostgreSQL 的特殊处理

IoTGateway 在 `Startup` 构造函数中添加了一行针对 PostgreSQL 的兼容配置：

```csharp
public Startup(IWebHostEnvironment env, IConfiguration config)
{
    // 解决 Npgsql 6.0+ 的时戳行为变更
    AppContext.SetSwitch("Npgsql.EnableLegacyTimestampBehavior", true);
    ConfigRoot = config;
}
```

Npgsql 6.0 开始默认使用 UTC 时间戳，而 IoTGateway 中的 `DateTime` 字段使用本地时间。这行代码恢复了旧版行为，避免时间转换错误。

### 迁移策略差异

不同数据库的迁移处理方式不同：

| 数据库 | 迁移方式 | 说明 |
|--------|---------|------|
| SQLite | 自动迁移 | `IoTBackgroundService` 启动时自动应用 |
| MySQL | 手动迁移 | `dotnet ef database update` |
| PostgreSQL | 手动迁移 | `dotnet ef database update` |
| SQL Server | 手动迁移 | `dotnet ef database update` |
| Oracle | 手动迁移 | `dotnet ef database update` |
| 达梦 | 手动迁移 | `dotnet ef database update` |

迁移文件的生成是数据库无关的（EF Core 自动生成对应 SQL），但需要注意不同数据库的迁移文件可能略有差异。详见 [[03-数据库迁移实践]]。

### 多数据库部署检查清单

部署到不同数据库环境时，需要检查以下事项：

1. **连接字符串**：确认格式正确，数据库已创建
2. **字符集**：MySQL 建议使用 `utf8mb4`，PostgreSQL 使用 `UTF8`
3. **迁移**：非 SQLite 数据库需要手动执行 `dotnet ef database update`
4. **时间处理**：PostgreSQL 需要启用 `Npgsql.EnableLegacyTimestampBehavior`
5. **NuGet 包**：确保对应数据库的 EF Core Provider 已安装
6. **权限**：数据库用户需要有 CREATE TABLE、INSERT、UPDATE、DELETE 权限

### 从 SQLite 切换到 MySQL 的完整步骤

```bash
# 1. 安装 MySQL
sudo apt install mysql-server

# 2. 创建数据库
mysql -u root -p -e "CREATE DATABASE iotgateway CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 3. 修改 appsettings.json
# "DBType": "MySQL"
# "Value": "Server=localhost;Port=3306;Database=iotgateway;Uid=root;Pwd=123456;"

# 4. 执行迁移
dotnet ef database update --project IoTGateway.DataAccess --startup-project IoTGateway

# 5. 启动应用
dotnet IoTGateway.dll
```
