## 数据初始化与种子数据

### 为什么需要种子数据

一个全新的 IoTGateway 部署后，数据库是空的——没有用户、没有设备、没有配置。如果每次部署都需要手动创建管理员账户、手动配置基础数据，既费时又容易出错。

种子数据（Seed Data）机制解决了这个问题：**在数据库首次创建时，自动填充必要的基础数据**。

### IoTGateway 的 DataInit 方法

`DataContext` 重写了 `FrameworkContext` 的 `DataInit` 方法，在首次创建数据库时自动添加管理员用户：

```csharp
public class DataContext : FrameworkContext
{
    public override async Task<bool> DataInit(object allModules, bool IsSpa)
    {
        // 1. 先调用基类的 DataInit（创建框架表结构和数据）
        var state = await base.DataInit(allModules, IsSpa);

        // 2. 检查是否为空数据库
        bool emptydb = false;
        try
        {
            emptydb = Set<FrameworkUser>().Count() == 0
                   && Set<FrameworkUserRole>().Count() == 0;
        }
        catch { }

        // 3. 首次创建或空库时，插入种子数据
        if (state == true || emptydb == true)
        {
            // 创建管理员用户
            var user = new FrameworkUser
            {
                ITCode = "admin",
                Password = Utils.GetMD5String("iotgateway.net"),
                IsValid = true,
                Name = "Admin"
            };

            // 创建用户角色关联
            var userrole = new FrameworkUserRole
            {
                UserCode = user.ITCode,
                RoleCode = "001"
            };

            Set<FrameworkUser>().Add(user);
            Set<FrameworkUserRole>().Add(userrole);
            await SaveChangesAsync();
        }

        return state;
    }
}
```

### DataInit 触发时机

```
应用启动
    │
    ▼
Startup.Configure() → app.UseWtmContext()
    │
    ▼
WTM 框架检查数据库是否存在
    │
    ├── 数据库不存在 → 创建数据库 + 执行迁移
    │   └── DataInit() 被调用 (state = true)
    │       ├── base.DataInit(): 创建框架表
    │       └── 自定义种子数据: 创建admin用户
    │
    ├── 数据库存在但为空 → DataInit() 被调用 (emptydb = true)
    │   └── 同上
    │
    └── 数据库存在且有数据 → DataInit() 可能仍被调用 (state = false)
        └── 条件不满足，跳过种子数据创建
```

### 种子数据详解

#### 管理员账户

```csharp
var user = new FrameworkUser
{
    ITCode = "admin",                              // 登录账号
    Password = Utils.GetMD5String("iotgateway.net"), // MD5加密密码
    IsValid = true,                                 // 账户有效
    Name = "Admin"                                  // 显示名称
};
```

| 字段 | 值 | 说明 |
|------|-----|------|
| ITCode | `admin` | 登录用户名 |
| Password | MD5(`iotgateway.net`) | 默认密码为 `iotgateway.net` |
| IsValid | `true` | 账户立即可用 |
| Name | `Admin` | 界面显示的管理员名称 |

> **安全提醒**：默认密码 `iotgateway.net` 仅用于首次登录，部署到生产环境后应立即修改密码。

#### 用户角色

```csharp
var userrole = new FrameworkUserRole
{
    UserCode = user.ITCode,  // "admin"
    RoleCode = "001"          // 管理员角色代码
};
```

`RoleCode = "001"` 是 WTM 框架约定的超级管理员角色代码。拥有此角色的用户可以访问系统的所有功能模块。

### FrameworkContext 基类的 DataInit

`base.DataInit()` 负责创建 WTM 框架所需的基础数据，包括：

| 数据类型 | 说明 |
|---------|------|
| 菜单数据 | 根据 Controller/Action 自动扫描生成菜单 |
| 操作权限 | 根据 `[ActionPermission]` 等注解生成权限项 |
| 默认角色 | 创建管理员角色 "001" |
| 页面权限 | 将菜单和操作权限关联到角色 |

这意味着调用 `base.DataInit()` 后，系统已经具备了完整的菜单和权限体系。

### 扩展种子数据

如果需要添加更多的种子数据（如默认设备组、默认系统配置），可以在 `DataInit` 中扩展：

```csharp
public override async Task<bool> DataInit(object allModules, bool IsSpa)
{
    var state = await base.DataInit(allModules, IsSpa);
    bool emptydb = false;
    try
    {
        emptydb = Set<FrameworkUser>().Count() == 0
               && Set<FrameworkUserRole>().Count() == 0;
    }
    catch { }

    if (state == true || emptydb == true)
    {
        // === 管理员用户 ===
        var user = new FrameworkUser
        {
            ITCode = "admin",
            Password = Utils.GetMD5String("iotgateway.net"),
            IsValid = true,
            Name = "Admin"
        };
        var userrole = new FrameworkUserRole
        {
            UserCode = user.ITCode,
            RoleCode = "001"
        };
        Set<FrameworkUser>().Add(user);
        Set<FrameworkUserRole>().Add(userrole);

        // === 默认系统配置（扩展示例）===
        var systemConfig = new SystemConfig
        {
            GatewayName = "IoTGateway-001",
            MqttIp = "127.0.0.1",
            MqttPort = 1883,
            IoTPlatformType = IoTPlatformType.ThingsBoard
        };
        Set<SystemConfig>().Add(systemConfig);

        // === 默认设备组（扩展示例）===
        var defaultGroup = new Device
        {
            DeviceName = "默认设备组",
            DeviceTypeEnum = DeviceTypeEnum.Group,
            Index = 0
        };
        Set<Device>().Add(defaultGroup);

        await SaveChangesAsync();
    }

    return state;
}
```

### SQLite 自动迁移与种子数据的关系

在 `IoTBackgroundService` 中，SQLite 数据库的迁移和种子数据初始化是分开执行的：

```
IoTBackgroundService 构造函数
    │
    ├── 解析 DBType 和连接字符串
    │
    ├── if SQLite:
    │   ├── new DataContext(connnectSetting, DbType)
    │   ├── GetPendingMigrations().Any()
    │   └── Database.Migrate()    ← 执行迁移，创建/更新表结构
    │
    ▼
app.UseWtmContext() (在 Startup.Configure 中)
    │
    └── DataInit() 被调用          ← 创建种子数据
```

> **注意**：`Database.Migrate()` 只负责结构变更（建表、加字段等），不负责种子数据。种子数据由 WTM 框架在 `UseWtmContext()` 中间件初始化时调用 `DataInit()` 来创建。

### 种子数据的安全性

DataInit 方法中有两层保护，确保种子数据不会被重复创建：

```csharp
// 第一层：base.DataInit 返回值
var state = await base.DataInit(allModules, IsSpa);

// 第二层：检查数据库中是否已有用户数据
bool emptydb = false;
try
{
    emptydb = Set<FrameworkUser>().Count() == 0
           && Set<FrameworkUserRole>().Count() == 0;
}
catch { }

// 只有在首次创建或空库时才执行
if (state == true || emptydb == true)
{
    // 插入种子数据...
}
```

| 条件 | state | emptydb | 是否创建种子数据 |
|------|-------|---------|----------------|
| 首次创建数据库 | true | true | 是 |
| 数据库已存在但无用户 | false | true | 是 |
| 数据库已存在且有用户 | false | false | 否 |
| 异常（表不存在） | false | catch → false | 否 |

### 密码加密方式

IoTGateway 使用 MD5 对密码进行加密存储：

```csharp
Password = Utils.GetMD5String("iotgateway.net")
```

`Utils.GetMD5String` 是 WTM 框架提供的工具方法，将明文密码转换为 MD5 哈希值。

> **生产环境建议**：MD5 是一种较弱的哈希算法。在对安全性要求较高的场景中，建议通过 WTM 框架的配置切换到更强的加密方式（如 PBKDF2 或 bcrypt）。

### 重置数据库与种子数据

如果需要完全重置数据库（开发调试时常用）：

```bash
# 1. 删除数据库文件（仅 SQLite）
rm IoTGateway/data/iotgateway.db

# 2. 重启应用
# → IoTBackgroundService 自动创建数据库并迁移
# → UseWtmContext 自动调用 DataInit 创建种子数据
# → 管理员账户: admin / iotgateway.net
```

对于其他数据库：

```bash
# 1. 回滚所有迁移（会删除所有表和数据）
dotnet ef database update 0 \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway

# 2. 重新应用所有迁移
dotnet ef database update \
    --project IoTGateway.DataAccess \
    --startup-project IoTGateway

# 3. 重启应用（DataInit 会创建种子数据）
```

### 种子数据在上位机项目中的最佳实践

1. **最小化种子数据**：只创建系统运行所必需的数据（管理员账户），其他数据通过界面创建
2. **幂等性**：确保种子数据代码可以重复执行而不产生重复记录
3. **密码安全**：默认密码应在首次部署后立即修改
4. **环境区分**：开发环境和生产环境可能需要不同的种子数据，可通过 `IWebHostEnvironment.IsDevelopment()` 判断
5. **文档化**：将默认账户信息记录在部署文档中，方便运维人员查阅
