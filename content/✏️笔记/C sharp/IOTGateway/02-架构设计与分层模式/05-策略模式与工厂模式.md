## 策略模式与工厂模式

### 多平台适配的挑战

在工业物联网项目中，数据采集只是第一步，更关键的是将采集到的数据上报到 IoT 云平台。然而不同的客户可能使用不同的云平台：ThingsBoard、IoTSharp、ThingsCloud、ThingsPanel... 每个平台的 MQTT Topic 格式、数据格式、RPC 协议都不同。

如果在 `MessageService` 中用 `if-else` 来判断平台类型，代码会迅速膨胀且难以维护。IoTGateway 通过**策略模式 + 工厂模式**的组合优雅地解决了这个问题。

### IPlatformHandler：策略接口

`IPlatformHandler` 定义了所有平台处理器必须实现的能力集：

```csharp
public interface IPlatformHandler
{
    IManagedMqttClient MqttClient { get; }
    ILogger<MessageService> Logger { get; }

    // RPC事件（每个平台处理器都会触发此事件）
    event EventHandler<RpcRequest> OnExcRpc;

    // MQTT连接成功后的订阅操作
    Task ClientConnected();

    // 接收并解析RPC消息
    void ReceiveRpc(MqttApplicationMessageReceivedEventArgs e);

    // 响应RPC结果
    Task ResponseRpcAsync(RpcResponse rpcResponse);

    // 发布遥测数据
    Task PublishTelemetryAsync(string deviceName, Device device,
        Dictionary<string, List<PayLoad>> sendModel);

    // 上传客户端属性
    Task UploadAttributeAsync(string deviceName, object obj);

    // 请求共享/客户端属性
    Task RequestAttributes(string deviceName, bool anySide, params string[] args);

    // 设备上下线通知
    Task DeviceConnected(string deviceName, Device device);
    Task DeviceDisconnected(string deviceName, Device device);

    // 设备增删通知
    Task DeviceAdded(Device device);
    Task DeviceDeleted(Device device);
}
```

#### 接口设计原则

| 方法 | 职责 | 平台差异示例 |
|------|------|-------------|
| `ClientConnected()` | 连接后订阅Topic | ThingsBoard: `v1/gateway/rpc`; IoTSharp: `devices/{id}/rpc` |
| `ReceiveRpc()` | 解析RPC消息 | 各平台JSON格式不同 |
| `PublishTelemetryAsync()` | 发布遥测 | Topic格式、JSON结构各异 |
| `UploadAttributeAsync()` | 上传属性 | 客户端属性 vs 共享属性 |
| `DeviceConnected()` | 设备上线通知 | 部分平台需要，部分不需要 |

### PlatformHandlerFactory：工厂类

工厂类根据配置中的平台类型枚举，创建对应的处理器实例：

```csharp
public static class PlatformHandlerFactory
{
    public static IPlatformHandler CreateHandler(
        IoTPlatformType platform,
        IManagedMqttClient mqttClient,
        ILogger<MessageService> logger,
        EventHandler<RpcRequest> onExcRpc)
    {
        switch (platform)
        {
            case IoTPlatformType.ThingsBoard:
                return new ThingsBoardHandler(mqttClient, logger, onExcRpc);
            case IoTPlatformType.ThingsCloud:
                return new ThingsCloudHandler(mqttClient, logger, onExcRpc);
            case IoTPlatformType.ThingsPanel:
                return new ThingsPanelHandler(mqttClient, logger, onExcRpc);
            case IoTPlatformType.IoTSharp:
            default:
                return new IoTSharpHandler(mqttClient, logger, onExcRpc);
        }
    }
}
```

### 策略模式在 MessageService 中的应用

`MessageService` 作为策略模式的**上下文（Context）**，持有一个 `IPlatformHandler` 引用，将所有平台相关的操作委托给具体的策略实现：

```csharp
public class MessageService
{
    private IPlatformHandler _platformHandler;

    public event EventHandler<RpcRequest>? OnExcRpc;

    public async Task StartClientAsync()
    {
        // 从数据库读取系统配置
        _systemConfig = await dc.Set<SystemConfig>().FirstOrDefaultAsync();

        // 工厂模式：根据配置创建平台处理器
        _platformHandler = PlatformHandlerFactory.CreateHandler(
            _systemConfig.IoTPlatformType,
            Client, _logger, OnExcRpc);

        // 转发RPC事件
        _platformHandler.OnExcRpc += (sender, request) =>
            OnExcRpc?.Invoke(sender, request);
    }

    // 以下所有方法都直接委托给 _platformHandler

    public async Task PublishTelemetryAsync(string deviceName, Device device,
        Dictionary<string, List<PayLoad>> sendModel)
    {
        if (CanPubTelemetry(deviceName, device, sendModel))
            await _platformHandler.PublishTelemetryAsync(deviceName, device, sendModel);
    }

    public async Task UploadAttributeAsync(string deviceName, object obj) =>
        await _platformHandler.UploadAttributeAsync(deviceName, obj);

    public async Task DeviceConnected(string deviceName, Device device) =>
        await _platformHandler.DeviceConnected(deviceName, device);

    public async Task DeviceDisconnected(string deviceName, Device device) =>
        await _platformHandler.DeviceDisconnected(deviceName, device);

    public async Task ResponseRpcAsync(RpcResponse rpcResponse) =>
        await _platformHandler.ResponseRpcAsync(rpcResponse);
}
```

### 变化上传策略

`MessageService` 还实现了一个重要的业务策略——**变化上传**（Change-on-Update），只在数据发生变化或超过规定时间时才发布数据：

```csharp
private bool CanPubTelemetry(string deviceName, Device device,
    Dictionary<string, List<PayLoad>> sendModel)
{
    var newPayload = sendModel[deviceName][0];

    if (!_lastTelemetrys.TryGetValue(deviceName, out var lastTelemetry))
    {
        _lastTelemetrys[deviceName] = sendModel[deviceName];
        return true; // 首次数据，直接发布
    }

    if (device.CgUpload) // 启用变化上传
    {
        bool isTimeExceeded = (newPayload.TS - lastPayload.TS) > device.EnforcePeriod;
        bool isValueChanged = !newPayload.Values.SequenceEqual(lastPayload.Values);

        if (isTimeExceeded || isValueChanged)
        {
            _lastTelemetrys[deviceName] = sendModel[deviceName];
            return true;
        }
        return false; // 无变化且未超时，不发布
    }

    return true; // 未启用变化检测，每次都发布
}
```

### 扩展新平台的步骤

当需要对接一个新的 IoT 平台时，只需三步：

```
1. 创建新的 Handler 类
   ┌─────────────────────────────────────────┐
   │  public class MyNewPlatformHandler :     │
   │      IPlatformHandler                     │
   │  {                                        │
   │    // 实现所有接口方法                      │
   │    // 定义该平台特有的 Topic 和 JSON 格式   │
   │  }                                        │
   └─────────────────────────────────────────┘

2. 在 IoTPlatformType 枚举中添加新项
   ┌─────────────────────────────────────────┐
   │  [Display(Name = "MyNewPlatform")]       │
   │  MyNewPlatform = 10                      │
   └─────────────────────────────────────────┘

3. 在 PlatformHandlerFactory 中添加分支
   ┌─────────────────────────────────────────┐
   │  case IoTPlatformType.MyNewPlatform:     │
   │    return new MyNewPlatformHandler(...); │
   └─────────────────────────────────────────┘
```

### 策略模式 vs if-else

| 对比维度 | if-else 方案 | 策略模式方案 |
|---------|-------------|-------------|
| 新增平台 | 修改 MessageService，添加 if 分支 | 新增一个 Handler 类，工厂添加一行 |
| 代码复杂度 | 所有平台逻辑混在一个类中 | 每个平台一个独立文件 |
| 可测试性 | 难以单独测试某个平台的逻辑 | 可以单独实例化 Handler 进行测试 |
| 开闭原则 | 违反（修改已有代码） | 遵守（扩展新代码） |
| 出错影响 | 修改一个平台可能影响其他 | 各平台完全隔离 |

### 工厂模式的两种实现对比

IoTGateway 中使用的是**简单工厂**（静态方法），适用于平台数量有限的场景。如果平台处理器需要复杂初始化，可以升级为**抽象工厂**：

```csharp
// 简单工厂（当前实现）
public static IPlatformHandler CreateHandler(IoTPlatformType platform, ...)

// 抽象工厂（可扩展方向）
public interface IPlatformHandlerFactory
{
    IPlatformHandler Create(IManagedMqttClient client, ILogger logger);
}
```

### 工业上位机中的策略模式应用场景

除了 IoT 平台适配，策略模式在上位机开发中还有广泛的应用场景：

1. **数据存储策略**：本地存储 vs 云端存储 vs 边缘计算
2. **报警策略**：邮件报警 vs 短信报警 vs 声光报警
3. **协议转换策略**：Modbus → JSON vs Modbus → OPC UA
4. **日志策略**：文件日志 vs 数据库日志 vs 远程日志
