## 依赖注入与服务管理

### 依赖注入是什么

依赖注入（Dependency Injection, DI）是 ASP.NET Core 的核心设计模式。简单来说：**对象不自己创建依赖，而是由外部"注入"进来**。

在传统开发中，你可能会这样写：

```csharp
// 传统方式：自己创建依赖（紧耦合）
public class DeviceController : Controller
{
    private DataContext _context = new DataContext("connection string");
    private DeviceService _service = new DeviceService();
}
```

而使用 DI 后：

```csharp
// DI方式：依赖由容器注入（松耦合）
public class DeviceController : Controller
{
    private readonly DataContext _context;
    private readonly DeviceService _service;

    public DeviceController(DataContext context, DeviceService service)
    {
        _context = context;
        _service = service;
    }
}
```

### IoTGateway 的服务注册

IoTGateway 在 `Startup.ConfigureServices()` 中注册了大量服务，涵盖了 WTM 框架服务、业务服务和基础设施服务：

```csharp
public void ConfigureServices(IServiceCollection services)
{
    // ========== WTM 框架服务 ==========
    services.AddDistributedMemoryCache();
    services.AddWtmSession(360000, ConfigRoot);
    services.AddWtmCrossDomain(ConfigRoot);
    services.AddWtmAuthentication(ConfigRoot);
    services.AddWtmHttpClient(ConfigRoot);
    services.AddWtmSwagger();
    services.AddWtmMultiLanguages(ConfigRoot);

    // ========== MVC 配置 ==========
    services.AddMvc(options => { options.UseWtmMvcOptions(); })
        .AddJsonOptions(options => { options.UseWtmJsonOptions(); })
        .AddViewLocalization(LanguageViewLocationExpanderFormat.Suffix)
        .AddWtmDataAnnotationsLocalization(typeof(Program));

    // ========== WTM Context（含 DataContext 注册）==========
    services.AddWtmContext(ConfigRoot, (options) =>
    {
        options.DataPrivileges = DataPrivilegeSettings();
        options.CsSelector = CSSelector;
        options.FileSubDirSelector = SubDirSelector;
        options.ReloadUserFunc = ReloadUser;
    });

    // ========== MQTT Server ==========
    services.AddHostedMqttServer(mqttServer =>
        mqttServer.WithoutDefaultEndpoint())
        .AddMqttConnectionHandler()
        .AddConnections();

    // ========== IoT 业务服务 ==========
    services.AddHostedService<IoTBackgroundService>();
    services.AddSingleton<DeviceService>();
    services.AddSingleton<DriverService>();
    services.AddSingleton<MessageService>();
    services.AddSingleton<ModbusSlaveService>();
    services.AddSingleton<MQTTService>();
}
```

### 服务生命周期详解

ASP.NET Core DI 提供了三种服务生命周期，IoTGateway 中都有涉及：

#### Transient（瞬时）

每次请求都创建新实例。适用于无状态的轻量级服务。

```
Controller 请求 → 创建实例 → 使用 → 销毁
Controller 请求 → 创建新实例 → 使用 → 销毁
```

WTM 框架内部的一些服务（如 `WTMContext`）使用 Transient 生命周期。

#### Scoped（作用域）

在同一个 HTTP 请求中共享实例。适用于需要在单次请求中保持状态的服务。

```
HTTP 请求开始
    ├── Controller 获取实例A
    ├── ViewModel 获取同一个实例A
    └── 请求结束 → 销毁实例A

下一个HTTP请求开始
    ├── Controller 获取新实例B
    └── ...
```

`DataContext`（EF Core 的 DbContext）通常以 Scoped 方式注册，确保一次请求中的所有数据库操作使用同一个 DbContext 实例。

#### Singleton（单例）

整个应用生命周期中只有一个实例。IoTGateway 的核心运行时服务全部使用单例：

```csharp
services.AddSingleton<DeviceService>();    // 设备线程管理
services.AddSingleton<DriverService>();    // 驱动加载管理
services.AddSingleton<MessageService>();   // MQTT通信
services.AddSingleton<ModbusSlaveService>(); // Modbus从站
```

> **为什么这些服务必须是单例？** 因为 `DeviceService` 管理着所有 `DeviceThread`，`MessageService` 维护着 MQTT 连接。如果每个请求创建新实例，就会导致采集线程重复创建、MQTT 连接冲突等问题。

### 生命周期对比图

```
┌──────────────────────────────────────────────────────────┐
│                    应用启动                               │
│                                                          │
│  Singleton 服务（创建一次，全局共享）：                     │
│  ┌────────────────────────────────────────────────────┐  │
│  │  DeviceService   → List<DeviceThread>              │  │
│  │  DriverService   → List<DriverInfo>                │  │
│  │  MessageService  → IManagedMqttClient              │  │
│  │  ModbusSlaveService → ModbusTcpSlave               │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  ┌─ HTTP请求1 ──────────────────────────────────────┐    │
│  │  Scoped 服务（请求内共享）：                       │    │
│  │  ┌────────────────────────────────────────────┐   │    │
│  │  │  DataContext → EF Core DbContext           │   │    │
│  │  │  WTMContext  → 用户会话信息                  │   │    │
│  │  └────────────────────────────────────────────┘   │    │
│  │                                                    │    │
│  │  Transient 服务（每次注入创建新实例）：              │    │
│  │  ┌────────┐ ┌────────┐ ┌────────┐                │    │
│  │  │ VM实例1 │ │ VM实例2 │ │ VM实例3 │                │    │
│  │  └────────┘ └────────┘ └────────┘                │    │
│  └──────────────────────────────────────────────────┘    │
│                                                          │
│  ┌─ HTTP请求2 ──────────────────────────────────────┐    │
│  │  （新的Scoped和Transient实例，但Singleton不变）     │    │
│  └──────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────┘
```

### HostedService vs Singleton

IoTGateway 中同时使用了 `AddHostedService` 和 `AddSingleton`，两者有重要区别：

```csharp
// BackgroundService：框架自动管理生命周期
services.AddHostedService<IoTBackgroundService>();

// Singleton：手动通过ServiceProvider获取
services.AddSingleton<DeviceService>();
```

| 特性 | AddHostedService | AddSingleton |
|------|-----------------|-------------|
| 生命周期 | 应用启动时创建，关闭时销毁 | 同上 |
| 接口要求 | 必须实现 IHostedService | 无要求 |
| 可被DI注入 | 不能直接注入到其他服务 | 可以注入到任何服务 |
| 可被ServiceProvider获取 | 不能（不暴露在DI容器中） | 可以 |

> **关键差异**：`DeviceService` 需要被 ViewModel 层通过 `Wtm.ServiceProvider.GetService(typeof(DeviceService))` 获取，因此必须使用 `AddSingleton` 而非 `AddHostedService`。

### 静态变量共享数据库配置

`IoTBackgroundService` 使用了两个静态变量来共享数据库连接信息：

```csharp
public class IoTBackgroundService : BackgroundService
{
    public static DBTypeEnum DbType;
    public static string connnectSetting;
}
```

这些静态变量在构造函数中初始化，然后被 `DeviceService`、`DeviceThread` 等运行时服务直接使用：

```csharp
// DeviceService 中使用
public class DeviceService
{
    private readonly string _connectSetting = IoTBackgroundService.connnectSetting;
    private readonly DBTypeEnum _dbType = IoTBackgroundService.DbType;

    // 创建 DataContext 时使用
    using var dc = new DataContext(_connectSetting, _dbType);
}

// DeviceThread 中使用
await using var dc = new DataContext(
    IoTBackgroundService.connnectSetting,
    IoTBackgroundService.DbType);
```

> **为什么用静态变量而非 DI？** 因为 `DataContext` 在这些服务中是按需创建的（`using var dc = new DataContext(...)`），而非通过 DI 容器注入。每次创建时需要传入连接字符串，静态变量是最简单直接的共享方式。

### WTM Context 配置

`AddWtmContext` 是 WTM 框架的核心配置入口，它负责：

```csharp
services.AddWtmContext(ConfigRoot, (options) =>
{
    // 数据权限设置
    options.DataPrivileges = DataPrivilegeSettings();

    // 动态连接字符串选择器（多租户场景）
    options.CsSelector = CSSelector;

    // 文件上传子目录选择器
    options.FileSubDirSelector = SubDirSelector;

    // 用户信息缓存失效时的重载方法
    options.ReloadUserFunc = ReloadUser;
});
```

#### CSSelector：动态数据源切换

```csharp
public string CSSelector(ActionExecutingContext context)
{
    // 可根据请求上下文返回不同的连接字符串Key
    // 用于多租户场景下不同租户使用不同数据库
    return null; // 默认使用 appsettings.json 中的默认连接
}
```

### 中间件管道

`Startup.Configure()` 方法定义了 HTTP 请求的处理管道：

```csharp
public void Configure(IApplicationBuilder app, IOptionsMonitor<Configs> configs)
{
    IconFontsHelper.GenerateIconFont();

    // 异常处理
    app.UseExceptionHandler(configs.CurrentValue.ErrorHandler);

    // 静态文件
    app.UseStaticFiles(new StaticFileOptions { ServeUnknownFileTypes = true });
    app.UseWtmStaticFiles();

    // 路由
    app.UseRouting();

    // 国际化
    app.UseWtmMultiLanguages();

    // 跨域
    app.UseWtmCrossDomain();

    // 认证与授权
    app.UseAuthentication();
    app.UseAuthorization();

    // 会话
    app.UseSession();

    // Swagger
    app.UseWtmSwagger();

    // WTM 框架
    app.UseWtm();

    // 端点路由
    app.UseEndpoints(endpoints =>
    {
        endpoints.MapMcp();          // MCP端点
        endpoints.MapMqtt("/mqtt");  // MQTT WebSocket端点
        endpoints.MapControllerRoute(
            name: "areaRoute",
            pattern: "{area:exists}/{controller=Home}/{action=Index}/{id?}");
        endpoints.MapControllerRoute(
            name: "default",
            pattern: "{controller=Home}/{action=Index}/{id?}");
    });

    // WTM Context 和 MQTT Server 初始化
    app.UseWtmContext();
    app.UseMqttServer();
}
```

### 中间件执行顺序

```
HTTP 请求 →
  ExceptionHandler → StaticFiles → Routing → MultiLanguages →
  CrossDomain → Authentication → Authorization → Session →
  Swagger → WTM → Endpoints → 响应
```

> **顺序很重要**：认证（Authentication）必须在授权（Authorization）之前，会话（Session）必须在端点路由之前。错误的顺序会导致功能异常。

### ViewModel 中的服务获取

由于 WTM 的 ViewModel 不是通过 DI 容器创建的（而是通过 `new` 关键字），它们不能直接通过构造函数注入服务。WTM 提供了 `Wtm.ServiceProvider` 作为解决方案：

```csharp
public override void DoAdd()
{
    base.DoAdd();

    // 通过 ServiceProvider 获取 Singleton 服务
    var deviceService = Wtm.ServiceProvider
        .GetService(typeof(DeviceService)) as DeviceService;
    var messageService = Wtm.ServiceProvider
        .GetService(typeof(MessageService)) as MessageService;

    deviceService.DriverManager.AddConfigs(Entity.ID, Entity.DriverId);
    messageService.DeviceAdded(device);
}
```

### 服务注册的最佳实践

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 数据库上下文 | Scoped (AddWtmContext) | 请求内共享，请求后释放 |
| 采集线程管理 | Singleton | 全局唯一，长期运行 |
| MQTT连接 | Singleton | 连接复用，避免重复建连 |
| ViewModel | Transient (new) | 每次请求创建新实例 |
| 配置选项 | Singleton (IOptions) | 配置不变，全局共享 |
