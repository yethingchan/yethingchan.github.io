## IoTGateway 架构总览

### 项目简介

IoTGateway 是一个基于 .NET 8.0 和 ASP.NET Core 构建的工业物联网网关上位机系统。它面向工业自动化领域，提供了从底层设备数据采集到上层云平台对接的完整解决方案。

对于工控工程师来说，理解这个项目的架构设计，不仅能帮助你快速上手二次开发，更能为构建自己的上位机系统提供宝贵的架构参考。

### 技术栈概览

| 技术层面 | 技术选型 | 说明 |
|---------|---------|------|
| 运行时 | .NET 8.0 | 长期支持版本（LTS） |
| Web框架 | ASP.NET Core | 跨平台Web应用框架 |
| MVVM框架 | WalkingTec.Mvvm (WTM) | 提供CRUD脚手架和LayUI组件 |
| ORM | Entity Framework Core 8.0.3 | 多数据库支持 |
| MQTT通信 | MQTTnet | 内置MQTT Broker + 客户端 |
| 日志 | NLog | 结构化日志记录 |
| 表达式引擎 | DynamicExpresso | 动态表达式计算 |
| 前端 | LayUI + Razor | 传统Web UI方案 |

### 分层架构设计

IoTGateway 采用了经典的四层架构，每一层都有明确的职责边界：

```
┌─────────────────────────────────────────────────────┐
│                   IoTGateway (Web App)               │
│         Controllers / Views / Program.cs             │
│              (表现层 + 应用入口)                       │
├─────────────────────────────────────────────────────┤
│              IoTGateway.ViewModel                     │
│       BaseCRUDVM / BasePagedListVM / Searcher         │
│                (视图模型层)                            │
├─────────────────────────────────────────────────────┤
│             IoTGateway.DataAccess                     │
│          DataContext / EF Core / Migrations           │
│               (数据访问层)                             │
├─────────────────────────────────────────────────────┤
│              IoTGateway.Model                         │
│     Device / Driver / DeviceVariable / SystemConfig   │
│                (实体模型层)                            │
└─────────────────────────────────────────────────────┘
```

**依赖方向**：上层依赖下层，下层不依赖上层。ViewModel 可以引用 Model，但 Model 不引用 ViewModel。

### 插件子系统

插件系统是整个架构中最具工业设计感的部分。它实现了驱动的热插拔和协议的可扩展性：

```
┌──────────────────────────────────────────────────┐
│              PluginInterface (契约层)              │
│   IDriver / ConfigParameterAttribute / MethodAttribute  │
│          (定义驱动必须遵守的接口)                    │
├──────────────────────────────────────────────────┤
│              Plugin (运行时引擎)                    │
│  DeviceService / DeviceThread / DriverService      │
│  MessageService / IoTBackgroundService             │
│        (驱动生命周期管理 + 通信调度)                 │
├──────────────────────────────────────────────────┤
│              Drivers (协议驱动实现)                  │
│   PLC.ModBusMaster / PLC.SiemensS7 / OPC.UaClient   │
│         (各自实现 IDriver 接口)                      │
└──────────────────────────────────────────────────┘
```

> **关键设计原则**：`PluginInterface` 是驱动开发者唯一需要引用的程序集。驱动开发者不需要了解 `Plugin` 运行时的内部实现。

### 核心数据流

在工业上位机系统中，数据流是最核心的关注点。IoTGateway 的数据流可以分为以下几条路径：

**采集上行链路（数据采集 -> 云平台）：**

```
PLC/传感器
    │
    ▼
IDriver.Read()         ← 驱动层：协议解析、字节读取
    │
    ▼
DeviceThread           ← 调度层：轮询调度、表达式计算
    │
    ▼
MessageService         ← 通信层：数据封装、变化检测
    │
    ▼
IPlatformHandler       ← 平台层：协议适配、MQTT发布
    │
    ▼
MQTT Broker / IoT平台   ← 目标平台：ThingsBoard/IoTSharp等
```

**控制下行链路（云平台 -> 设备写入）：**

```
IoT平台 / Web UI
    │
    ▼
MQTT Subscribe         ← 接收RPC指令
    │
    ▼
IPlatformHandler.ReceiveRpc()  ← 解析平台特定协议
    │
    ▼
MessageService.OnExcRpc 事件    ← 事件广播
    │
    ▼
DeviceThread.MyMqttClient_OnExcRpc()  ← 匹配设备、暂停采集
    │
    ▼
IDriver.WriteAsync()   ← 驱动层：协议写入
    │
    ▼
PLC/执行器
```

### 关键设计模式

在整个项目中，使用了多种经典的设计模式：

| 设计模式 | 应用位置 | 解决的问题 |
|---------|---------|-----------|
| 策略模式 | PlatformHandlerFactory | 多IoT平台适配 |
| 工厂模式 | PlatformHandlerFactory.CreateHandler() | 根据配置创建不同处理器 |
| 观察者模式 | MessageService.OnExcRpc | RPC指令分发到各设备线程 |
| 模板方法 | BaseCRUDVM / BasePagedListVM | 统一CRUD流程 |
| 依赖注入 | ASP.NET Core DI | 服务生命周期管理 |
| 插件模式 | IDriver + 反射加载 | 协议驱动可扩展 |

### 启动流程

理解应用的启动流程对于排查问题至关重要：

```
Program.Main()
    │
    ├── CreateWebHostBuilder()
    │   ├── Host.CreateDefaultBuilder()
    │   ├── ConfigureAppConfiguration()   ← 注入HostRoot
    │   ├── ConfigureLogging()            ← NLog + Console + WTM
    │   └── ConfigureWebHostDefaults()
    │       ├── UseStartup<Startup>()
    │       └── UseKestrel()              ← 监听 518(HTTP) + 1888(MQTT)
    │
    └── Build().Run()

Startup.ConfigureServices()
    │
    ├── AddWtmSession / Authentication / Swagger  ← WTM框架服务
    ├── AddWtmContext()                            ← DataContext注册
    ├── AddHostedMqttServer()                      ← 内置MQTT Broker
    ├── AddSingleton<DeviceService>()              ← 设备管理
    ├── AddSingleton<DriverService>()              ← 驱动管理
    ├── AddSingleton<MessageService>()             ← 消息通信
    ├── AddSingleton<ModbusSlaveService>()         ← Modbus从站模拟
    └── AddHostedService<IoTBackgroundService>()   ← 后台服务入口
```

`IoTBackgroundService` 在应用启动后会：

1. 解析数据库类型（SQLite/MySQL/PgSQL等）
2. 执行数据库迁移（仅SQLite模式自动迁移）
3. 触发 `DeviceService` 初始化，加载所有设备并创建 `DeviceThread`

### 项目引用关系

```
IoTGateway (Web App)
    ├── IoTGateway.ViewModel
    │   ├── IoTGateway.DataAccess
    │   │   └── IoTGateway.Model
    │   ├── IoTGateway.Model
    │   └── Plugin (引用运行时引擎)
    ├── IoTGateway.DataAccess
    ├── IoTGateway.Model
    ├── Plugin
    └── PluginInterface

Plugin (运行时引擎)
    ├── IoTGateway.DataAccess
    ├── IoTGateway.Model
    └── PluginInterface

Drivers (如 PLC.ModBusMaster)
    └── PluginInterface (仅引用契约层!)
```

> **注意**：驱动项目只引用 `PluginInterface`，这是插件化架构的核心约束。驱动开发者不需要知道运行时的实现细节。

### 配置文件结构

项目使用 `appsettings.json` 进行配置管理：

```json
{
  "Connections": [
    {
      "Key": "default",
      "Value": "Data Source = ./data/iotgateway.db",
      "DbContext": "DataContext",
      "DBType": "SQLite"
    }
  ],
  "PageMode": "Tab",
  "Languages": "zh,en"
}
```

数据库连接字符串支持运行时切换，通过 `CSSelector` 方法实现多租户场景下的动态数据源选择。

### 端口规划

| 端口 | 用途 | 协议 |
|-----|------|------|
| 518 | Web管理界面 | HTTP |
| 1888 | 内置MQTT Broker | MQTT |
| 503 | Modbus TCP Slave（模拟器） | Modbus TCP |

### 对上位机开发的启示

1. **分层清晰**：Model/Access/ViewModel/View 各管一摊，修改驱动不影响UI，修改UI不影响数据采集
2. **插件化设计**：通过 `IDriver` 接口约束，新协议只需实现接口+编译DLL，无需修改主程序
3. **多平台适配**：工厂+策略模式让对接新IoT平台只需新增一个 Handler 类
4. **事件驱动**：RPC指令通过事件机制分发，采集线程与控制线程通过 `ManualResetEventSlim` 协调
