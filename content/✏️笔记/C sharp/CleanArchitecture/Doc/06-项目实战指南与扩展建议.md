## 项目实战指南与扩展建议

> 本文是 CleanArchitecture 深度教程的最后一篇，介绍如何基于此项目启动自己的项目，以及进一步的扩展方向。

---

### 一、快速启动：从零开始创建自己的项目

#### 1.1 使用 .NET 模板

CleanArchitecture 提供了 .NET 项目模板，可以一键生成完整的项目脚手架：

```bash
# 安装模板
dotnet new install Clean.Architecture.Solution.Template

# 创建新项目
dotnet new ca-sln -n MyProject

# 选择前端框架（可选）
dotnet new ca-sln -n MyProject --use-ang   # Angular
dotnet new ca-sln -n MyProject --use-react  # React
dotnet new ca-sln -n MyProject              # 不包含前端
```

生成的项目会自动替换所有 "CleanArchitecture" 命名空间为 "MyProject"，并配置好所有的基础设施。

#### 1.2 从模板理解到实战

使用模板生成项目后，你应该：

1. 先通读 `DependencyInjection.cs`（每层各一个），理解服务注册的全貌
2. 运行 `dotnet run` 启动项目，通过 Scalar API 文档测试现有端点
3. 执行 EF Core 迁移，确保数据库初始化成功
4. 跑一遍所有测试，确认环境正常

```bash
# 运行项目
cd src/Web
dotnet run

# 应用数据库迁移
dotnet ef database update --project src/Infrastructure --startup-project src/Web

# 运行测试
dotnet test
```

### 二、添加新功能的标准流程

以"添加产品管理功能"为例，演示如何按照 CleanArchitecture 的模式添加新功能。

#### 2.1 Step 1：Domain 层 — 定义实体和值对象

```csharp
// src/Domain/Entities/Product.cs
public class Product : BaseAuditableEntity
{
    public string Name { get; set; } = string.Empty;
    public string? Description { get; set; }
    public decimal Price { get; set; }
    public Money UnitPrice => new(Currency.CNY, Price);  // 值对象
    public int CategoryId { get; set; }
    public Category Category { get; set; } = null!;
    public bool IsActive { get; set; } = true;
}

// src/Domain/Entities/Category.cs
public class Category : BaseAuditableEntity
{
    public string Name { get; set; } = string.Empty;
    public IList<Product> Products { get; set; } = new List<Product>();
}

// src/Domain/Enums/Currency.cs
public enum Currency { CNY, USD, EUR }

// src/Domain/Events/ProductCreatedEvent.cs
public class ProductCreatedEvent : BaseEvent
{
    public ProductCreatedEvent(Product product) => Product = product;
    public Product Product { get; }
}
```

然后在 `IApplicationDbContext` 中添加新的 DbSet：

```csharp
public interface IApplicationDbContext
{
    DbSet<TodoList> TodoLists { get; }
    DbSet<TodoItem> TodoItems { get; }
    DbSet<Product> Products { get; }        // 新增
    DbSet<Category> Categories { get; }     // 新增

}
```

在 `ApplicationDbContext` 中实现并配置：

```csharp
public DbSet<Product> Products => Set<Product>();
public DbSet<Category> Categories => Set<Category>();
```

创建 EF Core 迁移：

```bash

    --project src/Infrastructure \
    --startup-project src/Web
```

#### 2.2 Step 2：Application 层 — 编写 Command 和 Query

```
src/Application/Products/
├── Commands/
│   ├── CreateProduct/
│   │   └── CreateProductCommand.cs     ← Command + Validator + Handler
│   ├── UpdateProduct/
│   │   └── UpdateProductCommand.cs
│   └── DeleteProduct/
│       └── DeleteProductCommand.cs
├── Queries/
│   └── GetProducts/
│       ├── GetProductsQuery.cs
│       └── ProductsVm.cs              ← 视图模型
└── EventHandlers/
    └── ProductCreatedEventHandler.cs
```

遵循项目约定，Command + Validator + Handler 放在同一个文件中：

```csharp
// CreateProductCommand.cs
public record CreateProductCommand : IRequest<int>
{
    public string Name { get; init; } = string.Empty;
    public string? Description { get; init; }
    public decimal Price { get; init; }
    public int CategoryId { get; init; }
}

public class CreateProductCommandValidator : AbstractValidator<CreateProductCommand>
{
    public CreateProductCommandValidator(IApplicationDbContext context)
    {
        RuleFor(v => v.Name)
            .NotEmpty().WithMessage("产品名称不能为空。")
            .MaximumLength(100).WithMessage("产品名称不能超过100个字符。")
            .MustAsync(BeUniqueName(context))
                .WithMessage("产品名称必须唯一。")
                .WithErrorCode("UNIQUE_NAME");

        RuleFor(v => v.Price)
            .GreaterThan(0).WithMessage("价格必须大于0。");

        RuleFor(v => v.CategoryId)
            .GreaterThan(0).WithMessage("请选择有效的分类。")
            .MustAsync(BeValidCategory(context))
                .WithMessage("所选分类不存在。");
    }

    private static Func<string, CancellationToken, Task<bool>> BeUniqueName(
        IApplicationDbContext context) =>
        async (name, ct) => !await context.Products.AnyAsync(p => p.Name == name, ct);

    private static Func<int, CancellationToken, Task<bool>> BeValidCategory(
        IApplicationDbContext context) =>
        async (id, ct) => await context.Categories.AnyAsync(c => c.Id == id, ct);
}

public class CreateProductCommandHandler 
    : IRequestHandler<CreateProductCommand, int>
{
    private readonly IApplicationDbContext _context;

    public CreateProductCommandHandler(IApplicationDbContext context) 
        => _context = context;

    public async Task<int> Handle(CreateProductCommand request, 
        CancellationToken cancellationToken)
    {
        var entity = new Product
        {
            Name = request.Name,
            Description = request.Description,
            Price = request.Price,
            CategoryId = request.CategoryId
        };

        entity.AddDomainEvent(new ProductCreatedEvent(entity));

        _context.Products.Add(entity);
        await _context.SaveChangesAsync(cancellationToken);

        return entity.Id;
    }
}
```

#### 2.3 Step 3：Web 层 — 创建端点

```csharp
// src/Web/Endpoints/Products.cs
public class Products : IEndpointGroup
{
    public static void Map(RouteGroupBuilder groupBuilder)
    {
        groupBuilder.RequireAuthorization();

        groupBuilder.MapGet(GetProducts);
        groupBuilder.MapPost(CreateProduct);
        groupBuilder.MapPut(UpdateProduct, "{id}");
        groupBuilder.MapDelete(DeleteProduct, "{id}");
    }

    [EndpointSummary("获取所有产品")]
    public static async Task<Ok<ProductsVm>> GetProducts(ISender sender)
    {
        var vm = await sender.Send(new GetProductsQuery());
        return TypedResults.Ok(vm);
    }

    [EndpointSummary("创建产品")]
    public static async Task<Created<int>> CreateProduct(
        ISender sender, CreateProductCommand command)
    {
        var id = await sender.Send(command);
        return TypedResults.Created($"/api/Products/{id}", id);
    }

    [EndpointSummary("更新产品")]
    public static async Task<Results<NoContent, BadRequest>> UpdateProduct(
        ISender sender, int id, UpdateProductCommand command)
    {
        if (id != command.Id) return TypedResults.BadRequest();
        await sender.Send(command);
        return TypedResults.NoContent();
    }

    [EndpointSummary("删除产品")]
    public static async Task<NoContent> DeleteProduct(ISender sender, int id)
    {
        await sender.Send(new DeleteProductCommand(id));
        return TypedResults.NoContent();
    }
}
```

无需修改路由配置或启动代码——端点发现系统会自动注册 `/api/Products` 路由组。

#### 2.4 Step 4：Infrastructure 层 — 配置映射

```csharp
// src/Infrastructure/Data/Configurations/ProductConfiguration.cs
public class ProductConfiguration : IEntityTypeConfiguration<Product>
{
    public void Configure(EntityTypeBuilder<Product> builder)
    {
        builder.Property(p => p.Name)
            .HasMaxLength(100)
            .IsRequired();

        builder.Property(p => p.Price)
            .HasPrecision(18, 2);

        builder.HasOne(p => p.Category)
            .WithMany(c => c.Products)
            .HasForeignKey(p => p.CategoryId)
            .OnDelete(DeleteBehavior.Restrict);
    }
}
```

### 三、常见扩展方向

#### 3.1 添加分页查询

使用 EF Core 的 `Skip` + `Take` 实现分页：

```csharp
public record GetProductsQuery : IRequest<PaginatedResult<ProductDto>>
{
    public int Page { get; init; } = 1;
    public int PageSize { get; init; } = 20;
    public string? SearchTerm { get; init; }
}
```

推荐使用 `Microsoft.EntityFrameworkCore.Pagination` 或自定义扩展方法封装分页逻辑。

#### 3.2 添加缓存

使用 `IMemoryCache` 或分布式缓存（Redis）：

```csharp
public class GetProductsQueryHandler : IRequestHandler<GetProductsQuery, ProductsVm>
{
    private readonly IApplicationDbContext _context;
    private readonly IMemoryCache _cache;

    public async Task<ProductsVm> Handle(GetProductsQuery request, CancellationToken ct)
    {
        return await _cache.GetOrCreateAsync("products", async entry =>
        {
            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
            // 查询数据库...
        });
    }
}
```

或者使用 MediatR 的 `IPipelineBehavior` 实现通用的缓存行为。

#### 3.3 添加 SignalR 实时通知

当领域事件触发时，通过 SignalR 推送给前端：

```csharp
public class ProductCreatedEventHandler : INotificationHandler<ProductCreatedEvent>
{
    private readonly IHubContext<ProductHub> _hubContext;

    public async Task Handle(ProductCreatedEvent notification, CancellationToken ct)
    {
        await _hubContext.Clients.All.SendAsync("ProductCreated", 
            new { notification.Product.Id, notification.Product.Name }, ct);
    }
}
```

#### 3.4 添加文件上传

在 Infrastructure 层实现 `IFileStorageService` 接口，支持本地存储或云存储（Azure Blob、AWS S3、阿里云 OSS）。

#### 3.5 添加审计日志

扩展 `AuditableEntityInterceptor` 或在管道行为中添加操作日志记录，将用户的每一步操作都持久化到独立的审计表中。

### 四、部署与运维

#### 4.1 Docker 容器化

```dockerfile
FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS base
WORKDIR /app
EXPOSE 8080

FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY . .
RUN dotnet restore "src/Web/Web.csproj"
RUN dotnet publish "src/Web/Web.csproj" -c Release -o /app/publish

FROM base AS final
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "CleanArchitecture.Web.dll"]
```

#### 4.2 环境配置

使用 ASP.NET Core 的多环境配置：

```
appsettings.json              ← 通用配置
appsettings.Development.json  ← 开发环境（本地 SQL Server）
appsettings.Staging.json      ← 预发布环境
appsettings.Production.json   ← 生产环境
```

#### 4.3 健康检查

项目通过 .NET Aspire ServiceDefaults 自动配置了健康检查端点：

- `/health` — 完整健康检查（含数据库连接）
- `/alive` — 存活检查（仅检查进程是否运行）

Kubernetes 或 Docker Swarm 可以使用这些端点进行就绪性/存活性探测。

### 五、性能优化建议

#### 5.1 避免 N+1 查询

在 Query Handler 中使用 `Include` 加载关联数据：

```csharp
var products = await _context.Products
    .Include(p => p.Category)
    .Select(p => new ProductDto
    {
        Id = p.Id,
        Name = p.Name,
        CategoryName = p.Category.Name  // 投影，不会产生 N+1
    })
    .ToListAsync(cancellationToken);
```

#### 5.2 使用 AsNoTracking

对于只读查询，添加 `AsNoTracking()` 避免 EF Core 的变更追踪开销：

```csharp
var products = await _context.Products
    .AsNoTracking()
    .ToListAsync(cancellationToken);
```

#### 5.3 异步最佳实践

所有数据库操作都应该使用异步方法（`ToListAsync`、`FirstOrDefaultAsync`、`SaveChangesAsync`），避免在 ASP.NET Core 中使用同步方法导致线程池饥饿。

### 七、与其他 .NET 架构模板的对比

| 维度 | CleanArchitecture | eShop (Microsoft) | ABP Framework |
|------|-------------------|--------------------|----|
| Stars | 20,000+ | 24,000+ | 13,000+ |
| 定位 | 单体后端参考实现 | 微服务参考架构 | 完整应用框架 |
| 复杂度 | 中等，易上手 | 高，微服务+Docker | 高，框架约定多 |
| 适合场景 | 中小型项目起步 | 大型微服务系统 | 企业级多租户应用 |
| 学习曲线 | 平缓 | 陡峭 | 中等 |
| 自由度 | 高，无框架绑定 | 中 | 低，需遵循框架约定 |

选择建议：如果你正在启动一个新项目，需要快速上手且不想引入太多框架约定，CleanArchitecture 是最好的起点。如果你需要微服务，看 eShop。如果你需要开箱即用的多租户、权限管理等企业级功能，考虑 ABP。

### 八、持续学习路径

掌握 CleanArchitecture 之后，建议按以下路径继续深入：

1. **深入 DDD**：阅读 Eric Evans 的《Domain-Driven Design》，理解战略设计（限界上下文、上下文映射）
2. **事件驱动架构**：学习 Event Sourcing 和 CQRS 的高级形式，参考 MassTransit 和 Rebus
3. **微服务**：从 CleanArchitecture 的单体模式演进到微服务，参考 eShop 和 Dapr
4. **性能调优**：学习 .NET 性能分析工具（dotTrace、dotMemory、BenchmarkDotNet）
5. **安全**：深入学习 ASP.NET Core 的安全模型，OAuth2 / OpenID Connect
6. **可观测性**：OpenTelemetry、Prometheus、Grafana 的集成实践
