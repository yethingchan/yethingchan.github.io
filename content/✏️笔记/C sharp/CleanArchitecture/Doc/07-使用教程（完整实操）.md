## CleanArchitecture 使用教程

> 从零到一的完整实操指南。每一步都有可复制的命令和预期结果。
> 项目地址：https://github.com/jasontaylordev/CleanArchitecture

---

### 一、环境准备

#### 1.1 安装 .NET 10 SDK

在终端（PowerShell 或 CMD）运行：

```bash
dotnet --version
```

如果版本号低于 10.0 或未安装，前往 https://dotnet.microsoft.com/download/dotnet/10.0 下载安装。安装后重新验证：

```bash
dotnet --version
# 预期输出：10.0.xxx
```

#### 1.2 安装 EF Core 工具

```bash
dotnet tool install --global dotnet-ef
dotnet ef --version
# 预期输出：Entity Framework Core .NET Command-line Tools 10.x.x
```

如果已安装但版本过旧，更新：

```bash
dotnet tool update --global dotnet-ef
```

#### 1.3 安装 .NET Aspire 工作负载

```bash
dotnet workload install aspire
```

Aspire 是这个项目的服务编排工具，负责管理数据库容器和可观测性。

#### 1.4 Node.js（仅前端需要）

如果你打算运行 Angular 或 React 前端，安装 Node.js 18+：https://nodejs.org

只做后端 API 开发则不需要。

### 二、创建项目

你有两种方式获取这个项目。

#### 方式 A：直接 clone（用于学习源码）

```bash
git clone https://github.com/jasontaylordev/CleanArchitecture.git
cd CleanArchitecture
```

#### 方式 B：使用 .NET 模板（用于创建自己的项目）

```bash
# 安装模板
dotnet new install Clean.Architecture.Solution.Template

# 创建新项目（三选一）
dotnet new ca-sln -n MyProject                          # 纯 API + SQLite（最简单）
dotnet new ca-sln -n MyProject -db sqlserver            # 纯 API + SQL Server
dotnet new ca-sln -n MyProject -db postgresql           # 纯 API + PostgreSQL
dotnet new ca-sln -n MyProject -cf angular              # Angular 前端 + SQLite
dotnet new ca-sln -n MyProject -cf react -db sqlserver  # React 前端 + SQL Server
```

推荐先用**方式 B 创建纯 API + SQLite** 版本来上手，不需要安装 Docker 或数据库。

### 三、启动项目

#### 3.1 最简单的方式：SQLite + 直接启动

进入项目根目录，执行：

```bash
dotnet run --project src/AppHost
```

这条命令会：

1. 编译整个解决方案
2. 通过 .NET Aspire 启动 Web 应用
3. 自动创建 SQLite 数据库文件（`CleanArchitecture.db`）
4. 自动应用 EF Core 迁移（创建表结构）
5. 自动填充种子数据（管理员账户）
6. 打开 Aspire Dashboard 网页

启动成功后，终端会输出类似：

```
Now listening on: https://localhost:5001
info: Aspire.Hosting...
```

#### 3.2 如果不使用 Aspire

如果你不想用 Aspire，也可以直接启动 Web 项目：

```bash
dotnet run --project src/Web
```

首次启动时，因为 `Program.cs` 中有这段代码：

```csharp
if (app.Environment.IsDevelopment())
{
    await app.InitialiseDatabaseAsync();
}
```

它会自动检测并应用数据库迁移、填充种子数据。所以你不需要手动运行 `dotnet ef database update`。

#### 3.3 访问 API 文档

浏览器打开：

```
https://localhost:5001/scalar
```

这是 Scalar API 文档界面（替代了传统 Swagger UI）。你会看到所有 API 端点的列表，可以直接在页面上测试接口。

#### 3.4 查看 Aspire Dashboard

如果通过 `AppHost` 启动，终端会输出 Aspire Dashboard 的地址（通常是 `http://localhost:18888` 或类似端口）。打开这个地址可以看到：

- **Resources**：所有运行的服务状态
- **Console logs**：各服务的实时日志
- **Structured logs**：结构化日志
- **Traces**：分布式追踪（可以看到一个请求经过了哪些组件）
- **Metrics**：性能指标

### 五、理解请求的完整生命周期

当你在上面发送 `POST /api/TodoLists` 创建待办列表时，请求经历了以下完整路径：

```
你的 HTTP 请求
    │
    ▼
[1] ASP.NET Core 中间件管道
    │  → HTTPS 重定向
    │  → CORS 处理
    │  → 异常处理（ProblemDetailsExceptionHandler）
    │  → JWT Token 验证（Bearer Authentication）
    │
    ▼
[2] 端点路由（Endpoints/TodoLists.cs）
    │  静态方法 CreateTodoList(ISender sender, CreateTodoListCommand command)
    │  ASP.NET Core 自动将 JSON body 反序列化为 CreateTodoListCommand
    │
    ▼
[3] MediatR 管道开始
    │
    ├─→ [3.1] LoggingBehaviour          ← 记录请求名称和参数
    ├─→ [3.2] UnhandledExceptionBehaviour ← try-catch 包裹
    ├─→ [3.3] AuthorizationBehaviour    ← 检查 [Authorize] 特性
    ├─→ [3.4] ValidationBehaviour       ← 执行 CreateTodoListCommandValidator
    │     → Title 非空？长度 ≤ 200？标题是否唯一（查数据库）？
    ├─→ [3.5] PerformanceBehaviour      ← 开始计时
    │
    ▼
[4] CreateTodoListCommandHandler.Handle()
    │  → new TodoList { Title = "购物清单" }
    │  → _context.TodoLists.Add(entity)
    │  → _context.SaveChangesAsync()
    │
    ▼
[5] EF Core SaveChanges 拦截器链
    │
    ├─→ [5.1] AuditableEntityInterceptor.SavingChangesAsync
    │     → entry.Entity.CreatedBy = "当前用户ID"
    │     → entry.Entity.Created = 当前 UTC 时间
    │
    ├─→ [5.2] EF Core 执行 INSERT SQL
    │     → INSERT INTO TodoLists (Title, Colour_Code, Created, CreatedBy, ...)
    │     → VALUES ('购物清单', '#000000', '2026-06-19T...', 'user-id-guid', ...)
    │
    ├─→ [5.3] DispatchDomainEventsInterceptor.SavedChangesAsync
    │     → 检查实体是否有 DomainEvents（新建 TodoList 没有，所以跳过）
    │
    ▼
[6] Handler 返回 entity.Id（如 1）
    │
    ▼
[7] PerformanceBehaviour 停止计时
    │  → 如果 > 500ms，输出警告日志
    │
    ▼
[8] 端点方法返回 TypedResults.Created("/api/TodoLists/1", 1)
    │
    ▼
[9] HTTP 响应：201 Created
    Body: 1
    Location: /api/TodoLists/1
```

这就是 Clean Architecture 的核心价值：每一层只做自己的事，层与层之间通过明确的契约通信。你在 Handler 中写业务逻辑时，不需要关心验证、授权、日志、性能监控——这些由管道行为自动处理。

#### 7.2 第二步：Infrastructure 层 —— 配置数据库映射

```csharp
using CleanArchitecture.Domain.Entities;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace CleanArchitecture.Infrastructure.Data.Configurations;

public class ProductConfiguration : IEntityTypeConfiguration<Product>
{
    public void Configure(EntityTypeBuilder<Product> builder)
    {
        builder.Property(p => p.Name)
            .HasMaxLength(100)
            .IsRequired();

        builder.Property(p => p.Description)
            .HasMaxLength(500);

        builder.Property(p => p.Price)
            .HasPrecision(18, 2);

        builder.HasOne(p => p.Category)
            .WithMany(c => c.Products)
            .HasForeignKey(p => p.CategoryId)
            .OnDelete(DeleteBehavior.Restrict);

        builder.HasIndex(p => p.Name)
            .IsUnique();
    }
}
```

#### 7.3 第三步：Application 层 —— 编写 Command 和 Query

在 `src/Application/` 下创建 `Products/Commands/CreateProduct/CreateProductCommand.cs`：

```csharp
using CleanArchitecture.Application.Common.Interfaces;
using CleanArchitecture.Domain.Entities;
using CleanArchitecture.Domain.Events;
using FluentValidation;
using MediatR;

namespace CleanArchitecture.Application.Products.Commands.CreateProduct;

// ========== Command 定义 ==========
public record CreateProductCommand : IRequest<int>
{
    public string Name { get; init; } = string.Empty;
    public string? Description { get; init; }
    public decimal Price { get; init; }
    public int CategoryId { get; init; }
}

// ========== Validator ==========
public class CreateProductCommandValidator : AbstractValidator<CreateProductCommand>
{
    public CreateProductCommandValidator(IApplicationDbContext context)
    {
        RuleFor(v => v.Name)
            .NotEmpty().WithMessage("产品名称不能为空。")
            .MaximumLength(100).WithMessage("产品名称不能超过100个字符。")
            .MustAsync(BeUniqueName(context))
                .WithMessage("产品名称 '{PropertyValue}' 已存在。")
                .WithErrorCode("UNIQUE_NAME");

        RuleFor(v => v.Price)
            .GreaterThan(0).WithMessage("价格必须大于 0。");

        RuleFor(v => v.CategoryId)
            .GreaterThan(0).WithMessage("请选择有效的产品分类。")
            .MustAsync(BeValidCategory(context))
                .WithMessage("所选分类不存在。");
    }

    private static Func<string, CancellationToken, Task<bool>> BeUniqueName(
        IApplicationDbContext context) =>
        async (name, ct) => !await context.Products.AnyAsync(p => p.Name == name, ct);

    private static Func<int, CancellationToken, Task<bool>> BeValidCategory(
        IApplicationDbContext context) =>
        async (id, ct) => await context.Categories.AnyAsync(c => c.Id == id, ct);
}

// ========== Handler ==========
public class CreateProductCommandHandler : IRequestHandler<CreateProductCommand, int>
{
    private readonly IApplicationDbContext _context;

    public CreateProductCommandHandler(IApplicationDbContext context)
    {
        _context = context;
    }

    public async Task<int> Handle(CreateProductCommand request, CancellationToken cancellationToken)
    {
        var entity = new Product
        {
            Name = request.Name,
            Description = request.Description,
            Price = request.Price,
            CategoryId = request.CategoryId
        };

        entity.AddDomainEvent(new ProductCreatedEvent(entity));

        _context.Products.Add(entity);
        await _context.SaveChangesAsync(cancellationToken);

        return entity.Id;
    }
}
```

创建 Query `src/Application/Products/Queries/GetProducts/GetProductsQuery.cs`：

```csharp
using CleanArchitecture.Application.Common.Interfaces;
using MediatR;
using Microsoft.EntityFrameworkCore;

namespace CleanArchitecture.Application.Products.Queries.GetProducts;

public record GetProductsQuery : IRequest<ProductsVm>
{
}

public class ProductsVm
{
    public IList<ProductDto> Products { get; set; } = new List<ProductDto>();
}

public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public string? Description { get; set; }
    public decimal Price { get; set; }
    public string CategoryName { get; set; } = string.Empty;
    public bool IsActive { get; set; }
}

public class GetProductsQueryHandler : IRequestHandler<GetProductsQuery, ProductsVm>
{
    private readonly IApplicationDbContext _context;

    public GetProductsQueryHandler(IApplicationDbContext context)
    {
        _context = context;
    }

    public async Task<ProductsVm> Handle(GetProductsQuery request, CancellationToken cancellationToken)
    {
        var products = await _context.Products
            .AsNoTracking()
            .Include(p => p.Category)
            .OrderBy(p => p.Name)
            .Select(p => new ProductDto
            {
                Id = p.Id,
                Name = p.Name,
                Description = p.Description,
                Price = p.Price,
                CategoryName = p.Category.Name,
                IsActive = p.IsActive
            })
            .ToListAsync(cancellationToken);

        return new ProductsVm { Products = products };
    }
}
```

### 十、常见问题排查

#### Q1：启动报错 "Connection string 'CleanArchitectureDb' not found"

原因：`appsettings.json` 中的连接字符串缺失。

解决：确认 `src/Web/appsettings.json` 中有：
```json
{
  "ConnectionStrings": {
    "CleanArchitectureDb": "DataSource=CleanArchitecture.db;Cache=Shared"
  }
}
```

#### Q2：启动报错 "dotnet-ef tool not found"

解决：
```bash
dotnet tool install --global dotnet-ef
```

#### Q3：Aspire 启动失败

原因：Docker 未运行（Aspire 需要 Docker 来运行 SQL Server/PostgreSQL 容器）。

解决 A：安装并启动 Docker Desktop。
解决 B：不用 Aspire，直接 `dotnet run --project src/Web`（使用 SQLite 不需要 Docker）。

#### Q4：API 返回 401 Unauthorized

原因：请求没有携带有效的 Bearer Token。

解决：先调用 `/api/Users/login` 获取 token，然后在请求头中加上 `Authorization: Bearer <token>`。

#### Q5：API 返回 400 并包含验证错误

原因：请求数据不满足 Validator 的规则。

响应示例：
```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
    "Title": ["'Title' must be unique."]
  }
}
```

这说明你创建的 TodoList 标题和已有的重复了。换一个标题试试。

#### Q6：NuGet 包恢复失败

```bash
# 清除 NuGet 缓存后重试
dotnet nuget locals all --clear
dotnet restore
```

#### Q7：测试中 FunctionalTests 失败

原因：FunctionalTests 需要真实的数据库环境。

解决：确保数据库已初始化，或者只运行 UnitTests：
```bash
dotnet test tests/Domain.UnitTests
dotnet test tests/Application.UnitTests
```

#### Q8：想用 SQL Server 代替 SQLite

1. 确保安装了 SQL Server LocalDB（Visual Studio 自带）
2. 修改 `src/Web/appsettings.json`：

```json
{
  "ConnectionStrings": {
    "CleanArchitectureDb": "Server=(localdb)\\mssqllocaldb;Database=CleanArchitectureDb;Trusted_Connection=True;MultipleActiveResultSets=true"
  }
}
```

3. 删除旧的 SQLite 数据库文件和 Migrations 目录，重新生成迁移：

```bash
dotnet ef migrations add InitialCreate --project src/Infrastructure --startup-project src/Web
dotnet ef database update --project src/Infrastructure --startup-project src/Web
```
