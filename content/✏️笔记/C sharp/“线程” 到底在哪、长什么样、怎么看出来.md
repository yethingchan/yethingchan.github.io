你现在卡的点是：**不知道“线程”到底在哪、长什么样、怎么看出来**。

---

# 1. 最重要的一句话（背下来）
### **方法 ≠ 线程**
### **类 ≠ 线程**

### **线程 = 执行代码的“一条流水线”**
代码是死的，**线程是活的、跑代码的东西**。

你写的 `class A`、`Result`、`DoSomething`
**都不是线程！它们只是被线程跑的代码！**

---

# 2. 线程到底在哪？
线程不是你写出来的，**是系统创建出来跑你代码的“执行者”**。

你平时写的程序，一运行就自带 **1 个主线程**（UI线程）。

如果想有 **多个线程**，必须**手动创建**，比如：
```csharp
// 这才是创建新线程！
Thread t1 = new Thread(MyWork);
t1.Start();

Thread t2 = new Thread(MyWork);
t2.Start();
```

只有看到这种代码，**才会出现多线程并发**。

---

# 3. 用最形象的比喻理解
- **类 / 方法 = 菜谱**
- **线程 = 厨师**
- **CPU = 灶台**

菜谱（代码）不是厨师（线程）。
**厨师拿着菜谱做菜，这才叫线程在执行代码。**

---

# 4. 你那段代码里，线程在哪里？
你给的代码：
```csharp
class A
{
   int _a1,_a2;
   object _syncObj;
   
   public int Result { get {...} }
   public void DoSomething(...) {...}
}
```
这段代码 **完全没有创建线程**！
它只是一个**工具类**，**谁调用它，谁就是线程**。

---

# 5. 多线程什么时候出现？
**必须有人调用它，才会出现线程！**

比如：
```csharp
A a = new A();

// 线程1
new Thread(() => {
   a.DoSomething(10, 2);
   a.Result;
}).Start();

// 线程2
new Thread(() => {
   a.DoSomething(10, 0);
   a.Result;
}).Start();
```

现在才是：
**两个线程同时访问同一个对象 a**
这才会出现并发问题！

---

# 6. 线程的 4 个特征（一眼识别）
只要看到下面任意一种，就是**多线程**：

1. **`new Thread(...)`**
2. **`Task.Run(...)`**
3. **`async/await`**
4. **`BackgroundWorker`**
5. **系统自动开的线程（如定时器、事件）**

只要代码里**没有这些**，就是 **单线程**！

---

# 7. 如何一眼分辨“是不是多线程”？
超级简单规则：

### 看代码里有没有：
- 启动线程的关键字
- 异步方法
- 后台任务

如果 **没有** → 单线程
如果 **有** → 多线程

---

# 8. 回到你最开始的疑问
你问：
**为什么那段代码要加 lock？**

答案：
**不是因为代码自己会多线程，而是怕别人用多线程调用它！**

`class A` 是一个**共享工具**，
如果别人用 **两个线程同时调用它**，就会崩溃。
所以加 `lock` 保证安全。

---

# 9. 终极总结（最关键）
- **类不是线程**
- **方法不是线程**
- **线程是跑代码的“执行者”**
- **多线程 = 多个人同时读/写同一个数据**
- **lock = 只允许一个人操作，防止冲突**
