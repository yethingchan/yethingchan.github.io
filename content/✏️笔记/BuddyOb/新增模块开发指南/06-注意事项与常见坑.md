# 06 · 注意事项与常见坑

> 本项目特有的约定、易错点，以及一份"加完模块不生效"时的排错清单。
> 遇到问题先来这里对号入座。

---

## 一、本项目特有约定（和很多教程不一样）

| 约定 | 说明 | 别踩的坑 |
| --- | --- | --- |
| **Service 无接口无 Impl** | 直接一个 `@Service` 普通类 | 别去建 `XxxServiceImpl` + 接口 |
| **无 XML Mapper** | 纯 MyBatis-Plus，`BaseMapper` 自动生成 SQL | 别去 `resources/mapper` 建 XML（除非复杂联表） |
| **构造器注入** | `@RequiredArgsConstructor` + `final` | 别混用 `@Autowired` 字段注入 |
| **前端路由动态下发** | 菜单来自 `sys_menu` + `/getRouters` | 别去 `router/index.js` 写死路由 |
| **权限串三处一致** | Controller / DB / 前端 | 大小写、冒号、拼写必须完全相同 |
| **删除用数组参数** | `?ids=1&ids=2` | 别用 `?id=1`（除非仿 role/menu 的路径变量风格） |

---

## 二、权限字符串：最容易错的地方

权限串 `business:goods:add` 出现在**三个地方**，必须一字不差：

```
后端 Controller：  @PreAuthorize("@ps.hasPermi('business:goods:add')")
数据库 sys_menu：  perms = 'business:goods:add'
前端页面：         v-hasPermi="'business:goods:add'"
```

常见错误：
- ❌ 后端写 `business:goods:add`，数据库写 `business:goods:insert` → 权限对不上，接口 403。
- ❌ 大小写不一致：`Business:Goods:Add` vs `business:goods:add`。
- ❌ 前端漏了内层单引号：`v-hasPermi="business:goods:add"`（错），应为 `v-hasPermi="'business:goods:add'"`。

---

## 三、component 路径对齐：菜单不显示的头号原因

后端菜单 `component` 字段 = `src/views/` 之后的路径，去掉 `.vue`：

```
文件：src/views/business/goods/index.vue
配置：component = 'business/goods/index'   ✅
```

常见错误：
- ❌ 带了 `.vue` 后缀：`business/goods/index.vue`
- ❌ 带了 `views/` 前缀：`views/business/goods/index`
- ❌ 大小写和文件夹不一致：`Business/Goods/Index`
- ❌ 文件夹路径和配置不匹配（文件放 `views/goods/`，却配 `business/goods/index`）

`utils/route.js` 里 `loadView` 找不到对应 `.vue` 时会**兜底成 404 页面**，表现为"点菜单进去是 404"。

---

## 四、menu_id 冲突

`sys_menu` / `sys_dict_*` 的主键是**手动指定**的。新增记录前：

- 先查现有最大 ID：`SELECT MAX(menu_id) FROM sys_menu;`
- 新 ID 往后排，别和公告模块（30、45~49）等已有记录撞车。
- 撞车表现：`source data.sql` 时报 `Duplicate entry ... for key PRIMARY`。

---

## 五、data.sql 不能整份重跑

`data.sql` 全是 `INSERT`，**没有幂等处理**（不是 `INSERT IGNORE` 或 `REPLACE`）。

- 数据库已初始化过后，**只执行你新增的那几条 INSERT**，别 `source data.sql` 整个文件。
- 否则第一条老数据就会主键冲突报错。

---

## 六、改了菜单/权限，必须重新登录

菜单和权限是**登录时一次性加载**进 `LoginUser` 和前端 store 的。

- 改了 `sys_menu` / `sys_role_menu` 后，当前已登录的会话**不会自动刷新**。
- 必须**退出重新登录**，才会重新调 `/getInfo` 和 `/getRouters` 拉取最新菜单权限。
- 排查"菜单没出现"时，先确认是不是没重新登录。

---

## 七、分页不生效

如果列表返回了全部数据、没分页：

- 确认 `MybatisPlusConfig` 里的分页拦截器 Bean 存在（本项目已配好，正常不用动）。
- 确认 Service 用的是 `selectPage(page, wrapper)`，而不是 `selectList`。
- 确认 Controller 把 `pageNum/pageSize` 正确包成了 `new Page<>(pageNum, pageSize)`。

---

## 八、字段映射（驼峰 ↔ 下划线）

- 实体字段 `goodsName`（驼峰）↔ 表列 `goods_name`（下划线），MyBatis-Plus 自动映射（已配 `map-underscore-to-camel-case: true`）。
- 如果字段查不出值（为 null）：
  - 检查表列名是否是标准下划线格式。
  - 特殊字段名（如缩写）可用 `@TableField("列名")` 显式指定。

---

## 九、@Log 注解只加在写操作上

- `@Log(title=..., businessType=...)` 加在 **add / edit / remove** 上，不用加在 list / get 查询上（查询没必要记日志）。
- `businessType`：1=新增，2=修改，3=删除，0=其它。
- 日志会自动写进 `sys_oper_log`，在"操作日志"页面可查。

---

## 十、前后端接口路径 & 代理

- 前端 `api` 里写 `/business/goods/list`，实际请求 `/api/business/goods/list`（`request.js` 的 `baseURL='/api'`）。
- Vite 代理（`vite.config.js`）把 `/api` 去掉转发到 `http://localhost:8080`，所以后端 Controller 路径是 `/business/goods/list`（不带 `/api`）。
- 如果 404：检查前后端路径是否对齐、后端服务是否在 8080、Vite 代理是否生效。

## 十一、排错清单（加完模块不工作时按顺序查）

### 现象：侧边栏没有新菜单
1. 是否**重新登录**了？（菜单登录时加载）
2. `sys_menu` 里菜单记录（C 类型）插了吗？`status='0'`（正常）吗？
3. `sys_role_menu` 给当前用户的角色授权该 menu_id 了吗？
4. `component` 路径对不对（不带 `.vue`、不带 `views/`）？

### 现象：点菜单进去是 404
1. `component` 路径和实际 `.vue` 文件位置是否完全一致（含大小写）？
2. `.vue` 文件真的建了吗、路径对吗？

### 现象：按钮不显示
1. 是否重新登录？
2. `v-hasPermi` 的权限串和数据库 `sys_menu.perms`（F 类型）一致吗？
3. 该 F 按钮记录在 `sys_role_menu` 里授权给当前角色了吗？

### 现象：接口返回 403
1. Controller 的 `@PreAuthorize` 权限串和数据库 `perms` 一致吗？
2. 当前用户角色授权了这个权限（F 按钮）吗？
3. 用 admin 账号测试（admin 短路放行），能过说明是权限配置问题。

### 现象：接口返回 401
1. token 过期或没登录，重新登录。

### 现象：列表报错 / 查不到数据
1. 表建了吗？表名和 `@TableName` 一致吗？
2. 数据库连接对吗（`application.yml` 的 datasource）？
3. 字段映射对吗（驼峰↔下划线）？

### 现象：启动就报错
1. Bean 冲突：Service 类名、Mapper 是否重复。
2. Lombok 未生效："找不到符号 getXxx()" → 确认 `pom.xml` 的 `annotationProcessorPaths` 有 Lombok（本项目已配）。

## 十二、进阶：需要自定义 SQL 时

普通 CRUD 不用写 SQL。但遇到**联表查询、复杂统计**，`BaseMapper` 满足不了时：

**方式 A：Mapper 接口里用 `@Select` 注解**（仿 `SysMenuMapper`）

```java
@Select("<script>" +
        "SELECT g.* FROM biz_goods g " +
        "JOIN biz_category c ON g.category_id = c.id " +
        "WHERE g.status = #{status}" +
        "</script>")
List<Goods> selectWithCategory(@Param("status") String status);
```

> 注意：`@Select` 里的 `<`、`&` 等字符要转义（`&lt;`、`&amp;`），或用 `<script>` 包裹动态 SQL。

**方式 B：新建 XML Mapper**

在 `resources/mapper/` 建 `GoodsMapper.xml`（`application.yml` 已配 `mapper-locations: classpath*:mapper/*.xml`），写 namespace 对应接口全限定名，再在接口声明方法。适合超复杂 SQL。

---

## 小结：新增模块黄金法则

1. **后端四件套**：Entity / Mapper / Service / Controller，照模板抄。
2. **两条 SQL**：建表 + 菜单/权限/授权 INSERT。
3. **前端两文件**：`api/*.js` + `views/**/index.vue`。
4. **权限串三处一致**：Controller / DB / 前端。
5. **component 路径对齐**：`business/goods/index`。
6. **改完重新登录**才生效。
