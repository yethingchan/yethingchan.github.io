# 01 · 架构与数据流总览

> 在动手写代码前，先把"一次请求怎么从浏览器流到数据库再流回来""菜单和权限怎么串起来"搞明白。
> 理解了这张全景图，后面每一层要写什么就会非常清晰。

## 一、技术栈分层

```
┌─────────────────────────────────────────────────────────┐
│  前端 Vue3 + Vite + Element Plus + Pinia + vue-router4    │
│                                                          │
│  views/**/index.vue  ──调用──▶  api/**/*.js              │
│         页面组件                    请求封装               │
│                                        │                 │
│                                utils/request.js          │
│                              (axios: /api 前缀 + Bearer) │
└────────────────────────────────────────┼────────────────┘
                                          │  Vite 代理 /api → :8080
                                          ▼
┌─────────────────────────────────────────────────────────┐
│  后端 Spring Boot 3 + Spring Security 6 + MyBatis-Plus   │
│                                                          │
│  Controller  ──▶  Service  ──▶  Mapper  ──▶  MySQL       │
│  (@RestController) (@Service)  (BaseMapper)    (表)       │
│       │                                                  │
│  @PreAuthorize("@ps.hasPermi('业务:模块:动作')")          │
└─────────────────────────────────────────────────────────┘
```

**关键分层职责：**

| 层 | 职责 | 本项目约定 |
| --- | --- | --- |
| 页面组件 `views` | 界面、交互、表格/表单/弹窗 | 每个模块一个 `index.vue` |
| API 封装 `api` | 把后端接口包成函数 | 每个模块一个 `.js`，导出 5 个函数 |
| 请求基础设施 `utils/request.js` | axios 实例、token、错误处理 | **全局唯一，不用改** |
| Controller | 收请求、校验权限、返回统一结构 | `@RestController` + `@PreAuthorize` |
| Service | 业务逻辑、构造查询条件 | **普通 `@Service` 类，无接口无 Impl** |
| Mapper | 数据库 CRUD | **空接口继承 `BaseMapper`，无 XML** |
| Entity | 表 ↔ 对象映射 | `@Data @TableName("表名")` |

## 二、一次列表查询的完整链路

以"公告列表"为例，看数据怎么流动：

```
① 浏览器：用户打开公告页
        │
② views/business/notice/index.vue 的 load()
        │  调用 listNotice({pageNum:1, pageSize:10, title:'xxx'})
        ▼
③ api/business/notice.js
        │  request({ url:'/business/notice/list', method:'get', params })
        ▼
④ utils/request.js（axios）
        │  加 Authorization: Bearer <token>
        │  baseURL='/api' → 实际请求 /api/business/notice/list
        ▼
⑤ Vite 代理（vite.config.js）
        │  /api/business/notice/list → http://localhost:8080/business/notice/list
        ▼
⑥ SysNoticeController.list()
        │  @PreAuthorize 先校验权限（见下方权限旁路）
        │  构造 Page<>(pageNum, pageSize)，调用 service
        ▼
⑦ NoticeService.list(page, title, type)
        │  用 LambdaQueryWrapper 拼动态条件
        ▼
⑧ SysNoticeMapper.selectPage(page, wrapper)
        │  分页拦截器自动拼 LIMIT + COUNT
        ▼
⑨ MySQL：sys_notice 表
        │
        ▼ 结果沿原路返回
⑩ Controller 包成 AjaxResult.success(rows, total)
        │  { code:200, rows:[...], total: 26 }
        ▼
⑪ request.js 拦截器：code===200 → 返回 res
        ▼
⑫ 页面：rows.value = res.rows; total.value = res.total
        │  el-table 渲染
```

**记住三个返回字段：**
- `res.rows` —— 列表数据（数组）
- `res.total` —— 总条数（分页用）
- `res.data` —— 单条数据（查详情用）

## 三、权限是怎么校验的（并行旁路）

权限校验发生在第 ⑥ 步 Controller 方法进入之前：

```
@PreAuthorize("@ps.hasPermi('business:notice:list')")
        │
        │ Spring EL 解析 @ps = 容器里名为 "ps" 的 Bean = PermissionService
        ▼
PermissionService.hasPermi("business:notice:list")
        │
        ├── SecurityUtils.isAdmin() ?  → 是管理员：直接放行 ✅
        │
        └── 否则：loginUser.getPermissions().contains("business:notice:list") ?
                  │
                  │ permissions 从哪来？登录时加载的：
                  ▼
            UserDetailsServiceImpl.loadUserByUsername()
                  │  SysMenuMapper.selectPermsByUserId(userId)
                  ▼
            SQL 联表查询：
              sys_menu.perms  ←JOIN→  sys_role_menu  ←JOIN→  sys_user_role
              （只查 menu_type='F' 按钮行、perms 非空的记录）
```

**核心结论：**
- 权限字符串（`business:notice:list`）**存在数据库 `sys_menu.perms` 字段**，只在按钮（`menu_type='F'`）行上有值。
- 用户登录时，根据"用户→角色→菜单"的关联，把该用户能用的所有权限串查出来，放进 `LoginUser.permissions`。
- 每次访问接口，`@PreAuthorize` 比对当前用户是否拥有该权限串。
- **管理员（admin 角色）短路放行**，无需逐个配权限。

## 四、前端菜单和路由怎么"动态"出现（本项目重点）

这是本项目和很多教程不一样的地方：**前端不写死路由，菜单从后端数据库动态下发。**

```
① 登录成功 → 存 token
        │
② 首次进入受保护页面 → 路由守卫（router/index.js beforeEach）
        │  发现 store 里 roles 为空，触发加载
        ▼
③ getInfo()  → 拿到 { user, roles, permissions }
   getRouters() → 拿到后端根据当前角色拼好的菜单树 VO
        ▼
④ utils/route.js 的 generateRoutes(VO)
        │  把后端菜单 VO 转成 vue-router 的 RouteRecord
        │  component 字段（如 'business/notice/index'）
        │    → import.meta.glob 映射到真实 .vue 文件懒加载
        ▼
⑤ router.addRoute(route) 逐个动态挂载
   userStore.setMenus(routes) 存进 store
        ▼
⑥ layout/index.vue 读 userStore.menus → 侧边栏渲染菜单
   sidebarItem.vue 递归渲染，图标/标题取自 meta
```

**这意味着：**
- 你新增一个前端页面，**不用改 `router/index.js`**。
- 你只需在后端"菜单管理"里加一条菜单记录（`component` 填视图路径），刷新后菜单自动出现。
- `component` 字段的值 = `src/views/` 后面那段路径，去掉 `.vue`。
  - 例：`src/views/business/notice/index.vue` → `component = business/notice/index`

## 五、按钮级权限怎么控制显隐

```
页面里：<el-button v-hasPermi="'business:notice:add'">新增</el-button>
        │
        ▼
directive/hasPermi.js（自定义指令）
        │  mounted 时调用 utils/permission.js 的 hasPermi()
        ▼
hasPermi('business:notice:add')
        │  return userStore.permissions.includes('business:notice:add')
        │
        └── 没有该权限 → 直接把这个按钮的 DOM 移除（比 v-if 更彻底）
```

**前后端权限串必须一致**：
- 前端 `v-hasPermi="'business:notice:add'"`
- 后端 `@PreAuthorize("@ps.hasPermi('business:notice:add')")`
- 数据库 `sys_menu.perms = 'business:notice:add'`

三处一字不差，才能正确联动。

## 六、全局基础设施（复用，不用动）

新增模块时，下面这些是**现成的、直接用、不用改**：

| 基础设施 | 位置 | 作用 |
| --- | --- | --- |
| `AjaxResult` | `common/AjaxResult.java` | 统一返回结构 |
| `PermissionService`（`@ps`） | `security/PermissionService.java` | 权限校验 |
| `SecurityUtils` | `common/utils/SecurityUtils.java` | 取当前登录用户 |
| `@Log` + `LogAspect` | `annotation/` + `aspect/` | 操作日志（贴注解即用） |
| `MybatisPlusConfig` | `config/MybatisPlusConfig.java` | 分页拦截器（全局一次配好） |
| `@MapperScan` + `@EnableMethodSecurity` | `AdminApplication.java` | 已开启，新 Mapper / 新 `@PreAuthorize` 自动生效 |
| `request.js` | `utils/request.js` | axios 门面，token/错误/数组序列化 |
| `directive/hasPermi` | `directive/` | 按钮权限指令 |
| `utils/route.js` | `utils/route.js` | 动态路由生成 |

---

## 小结

- **一次请求**：页面 → api → request.js → 代理 → Controller → Service → Mapper → 表，再原路返回。
- **权限**：存在 `sys_menu.perms`，登录时加载进 `LoginUser`，`@PreAuthorize` 校验，前端 `v-hasPermi` 控制显隐，三处字符串必须一致。
- **菜单/路由**：后端数据库动态下发，前端不写死路由。
- **新增模块**：后端加"四件套 + SQL"，前端加"两文件"，再在菜单/角色里配好即可。
