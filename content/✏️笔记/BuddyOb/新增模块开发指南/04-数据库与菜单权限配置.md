# 04 · 数据库与菜单权限配置

> 代码写完还差最后一环：**建表** + **配菜单/权限**。
> 只有把菜单和权限数据插进数据库，前端菜单才会出现、按钮才会显示、接口才能通过鉴权。

---

## 一、建业务表

在 `backend/src/main/resources/schema-mysql.sql` 里追加建表语句（以商品为例）：

```sql
CREATE TABLE IF NOT EXISTS `biz_goods` (
  `goods_id`    BIGINT NOT NULL AUTO_INCREMENT,
  `goods_name`  VARCHAR(100) DEFAULT '',
  `goods_code`  VARCHAR(50)  DEFAULT '',
  `stock`       INT          DEFAULT 0,
  `status`      CHAR(1)      DEFAULT '0',
  `create_by`   VARCHAR(50)  DEFAULT '',
  `create_time` DATETIME,
  `remark`      VARCHAR(500) DEFAULT '',
  PRIMARY KEY (`goods_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**要点：**
- 列名用**下划线**（`goods_name`），与实体驼峰字段（`goodsName`）自动映射。
- 主键 `AUTO_INCREMENT`，对应实体 `@TableId(type = IdType.AUTO)`。
- 引擎和字符集统一 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`。
- 用 `CREATE TABLE IF NOT EXISTS`，避免重复执行报错。

> 如果你还在用 H2（默认 profile 未切 MySQL），对应改的是 `schema.sql`（H2 语法，无反引号、无 `ENGINE`）。当前项目默认已切 MySQL，改 `schema-mysql.sql` 即可。

## 二、理解 sys_menu 表（菜单/权限都存这）

`sys_menu` 是整个权限系统的核心表，**菜单、按钮、权限字符串全在这张表**，靠 `menu_type` 区分：

| menu_type | 含义 | 有无 perms | component 字段 |
| --- | --- | --- | --- |
| `M` | 目录（一级分组，如"系统管理"） | 无 | 空（前端识别为 Layout） |
| `C` | 菜单（真正的页面，如"商品管理"） | 无 | 视图路径，如 `business/goods/index` |
| `F` | 按钮（权限点，如"新增""删除"） | **有** | 空 |

关键字段：

| 字段 | 说明 |
| --- | --- |
| `menu_id` | 主键，手动指定（注意别和已有 ID 冲突） |
| `parent_id` | 父菜单 ID，顶级为 0 |
| `order_num` | 同级排序 |
| `menu_name` | 显示名称 |
| `path` | 路由地址（C 类型用） |
| `component` | 前端组件路径（C 类型填 `business/goods/index`） |
| `menu_type` | M/C/F |
| `perms` | 权限字符串（**仅 F 类型有值**） |
| `icon` | 图标名（Element Plus 图标名，如 `Goods`） |

## 三、配置菜单和权限（data.sql）

在 `backend/src/main/resources/data.sql` 追加以下 INSERT。

> **先查一下现有最大 menu_id**，新记录的 ID 往后排，避免冲突。当前项目公告模块占用到 30、45~49，本例用 31（菜单）和 50~54（按钮）演示。

### 3.1 挂在哪个目录下？

本项目已有三个目录（M）：
- `menu_id=1` 系统管理（`system`）
- `menu_id=2` 系统监控（`monitor`）
- `menu_id=3` 业务模块（`business`）

商品管理属于业务，挂在 `menu_id=3`（业务模块）下即可。

### 3.2 插入菜单（C 类型）

```sql
-- 商品管理菜单（挂在"业务模块"目录 id=3 下）
INSERT INTO sys_menu(menu_id, parent_id, order_num, menu_name, path, component, query, menu_type, perms, icon, status, create_time) VALUES
(31, 3, 2, '商品管理', 'goods', 'business/goods/index', '', 'C', '', 'Goods', '0', '2024-01-01 00:00:00');
```

字段解释：
- `parent_id=3` → 挂在"业务模块"下。
- `path='goods'` → 路由地址。
- `component='business/goods/index'` → **对应 `src/views/business/goods/index.vue`**（去 `src/views/` 前缀、去 `.vue` 后缀）。
- `menu_type='C'` → 是个菜单页面。
- `icon='Goods'` → Element Plus 图标名（可选 `Goods`、`ShoppingCart` 等）。

### 3.3 插入按钮权限（F 类型）

```sql
-- 商品管理的 5 个按钮权限（parent_id=31，即挂在商品菜单下）
INSERT INTO sys_menu(menu_id, parent_id, order_num, menu_name, path, component, query, menu_type, perms, icon, status, create_time) VALUES
(50, 31, 1, '商品查询', '', '', '', 'F', 'business:goods:list',   '#', '0', '2024-01-01 00:00:00'),
(51, 31, 2, '商品查看', '', '', '', 'F', 'business:goods:query',  '#', '0', '2024-01-01 00:00:00'),
(52, 31, 3, '商品新增', '', '', '', 'F', 'business:goods:add',    '#', '0', '2024-01-01 00:00:00'),
(53, 31, 4, '商品修改', '', '', '', 'F', 'business:goods:edit',   '#', '0', '2024-01-01 00:00:00'),
(54, 31, 5, '商品删除', '', '', '', 'F', 'business:goods:remove', '#', '0', '2024-01-01 00:00:00');
```

> 这 5 个 `perms` 值必须和 Controller 的 `@PreAuthorize` 及前端 `v-hasPermi` **完全一致**。

### 3.4 给角色授权（sys_role_menu）

光插菜单还不够，得把菜单**分配给角色**，用户才能看到、用到。

```sql
-- 超级管理员(role_id=1) 授权：菜单31 + 按钮50~54
INSERT INTO sys_role_menu(role_id, menu_id) VALUES
(1, 31), (1, 50), (1, 51), (1, 52), (1, 53), (1, 54);

-- 普通操作员(role_id=2) 授权（按需，比如只给查看+新增+修改，不给删除）
INSERT INTO sys_role_menu(role_id, menu_id) VALUES
(2, 31), (2, 50), (2, 51), (2, 52), (2, 53);
```

> 提示：admin 角色在 `PermissionService.hasPermi` 里是**短路放行**的，理论上不配也能访问接口；但**菜单显示**仍依赖 `sys_role_menu` 关联（`/getRouters` 按角色查菜单）。所以为了让 admin 侧边栏能看到菜单，仍建议给 admin 配上菜单关联。

### 3.5（可选）配字典

如果页面用到字典下拉（如商品状态的中文映射），追加：

```sql
INSERT INTO sys_dict_type(dict_id, dict_name, dict_type, status, remark) VALUES
(4, '商品状态', 'sys_goods_status', '0', '正常/停用');

INSERT INTO sys_dict_data(dict_code, dict_type, dict_label, dict_value, dict_sort, status, remark) VALUES
(7, 'sys_goods_status', '正常', '0', 1, '0', ''),
(8, 'sys_goods_status', '停用', '1', 2, '0', '');
```

前端用 `dictDataByType('sys_goods_status')` 拉取。简单选项也可直接写死 `<el-option>`，不强制走字典。

## 四、菜单/权限/路由怎么串起来（回顾）

```
sys_menu 表
  ├─ M 目录 (business, id=3)
  │    └─ C 菜单 (goods, id=31, component='business/goods/index')
  │          ├─ F 按钮 (business:goods:list, id=50)
  │          ├─ F 按钮 (business:goods:add,  id=52)
  │          └─ ...
  │
sys_role_menu：role_id ←→ menu_id （角色能用哪些菜单/按钮）
sys_user_role：user_id ←→ role_id （用户属于哪些角色）

登录后：
  /getRouters → 按用户角色查出 C 菜单树 → 前端动态生成路由 → 侧边栏显示
  /getInfo    → 按用户角色查出 F 按钮 perms → permissions 数组 → v-hasPermi 控制按钮
  接口调用    → @PreAuthorize 校验 perms
```

## 五、让改动生效

改完 SQL 后需要让数据库真正建表 + 插数据。

**方式 A：手动在 MySQL 执行（推荐，符合当前默认配置）**

```sql
USE ruoyi;
source schema-mysql.sql;   -- 建表（IF NOT EXISTS，已有表不受影响）
source data.sql;           -- 插菜单/权限数据
```

> ⚠️ `data.sql` 都是 `INSERT`，重复整份执行会主键冲突。若数据库已初始化过，**只手动执行你新增的那几条 INSERT** 即可，不要重跑整个文件。

**方式 B：重建数据库（开发期图省事）**

删库重建，再完整 source 两个文件。仅限没有重要数据的开发环境。

改完重启后端、前端重新登录，新菜单和按钮就会出现。
