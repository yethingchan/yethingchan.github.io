# 04-批量与性能优化 · 性能陷阱（N+1 / 类型开销 / 隐式转换）

> 前置：[[MyBatis Mapper XML/进阶专题/04-批量与性能优化/00-索引]] ｜ 关联：[[MyBatis Mapper XML/进阶专题/02-高级结果映射/02-collection一对多与嵌套查询vs结果]]

## 陷阱 1：N+1（最经典）

```xml
<resultMap id="roleLazy" type="SysRole">
  <collection property="menus" ofType="SysMenu"
    select="com.x.SysMenuMapper.byRole" fetchType="lazy"/>
</resultMap>
```
查 100 个角色 → 1 条查角色 + 100 条查菜单 = **101 条 SQL**。循环遍历即雪崩。

**解法**：改用"嵌套结果（JOIN + `<id>` 去重）"（见 02），一条 SQL 搞定。

## 陷阱 2：类型隐式转换（索引失效，MySQL 层）

```xml
<select id="byPhone" resultType="User">
  SELECT * FROM sys_user WHERE phone = #{phone}
</select>
```
若 `phone` 列是 `VARCHAR` 但传入参数是 `Long`/`int`：
- `#{}` 会按 Java 类型设参 → JDBC `setLong` → MySQL 把列 `CAST` 成数字比较 → **索引失效，全表扫描**。
- 现象：SQL 慢、EXPLAIN 显示 `type=ALL`。

**解法**：
- Mapper 方法参数类型与列类型一致（手机号用 `String`）。
- 或用 `CAST(#{phone} AS CHAR)` 强制同类型（不推荐，影响可读）。
- 核心：**`#{}` 是类型安全的占位，但"Java 参数类型"与"列类型"不匹配仍会触发 MySQL 隐式转换**。

> 延伸：这是 MySQL 索引失效的同源问题，详见 [[MySQL/进阶专题/02-索引底层与优化器执行计划/05-索引失效全场景]]。

## 陷阱 3：回表与 `SELECT *`

```xml
<select id="list" resultType="User"> SELECT * FROM sys_user ... </select>
```
- `SELECT *` 拿全部列，若走二级索引还需**回表**取其他列 → 多一次 IO。
- 大宽表尤其明显。
- 解法：只 `SELECT` 需要的列；配合**覆盖索引**避免回表。

## 陷阱 4：懒加载对象被序列化（隐式触发 N+1）

```java
User u = mapper.selectUserLazy(1);
return AjaxResult.success(u);   // JSON 序列化 → 调 getDept()/getMenus() → 触发懒加载
```
- 序列化框架（Jackson）会遍历 getter → 触发 `association`/`collection` 的懒加载 SQL。
- 本应在事务/Session 内触发，或导致 `LazyInitializationException`，或 N+1 放大。

**解法**：
- 返回前用 **VO/DTO 拷贝**（只拷扁平字段）。
- 或用 `@JsonIgnore` 排除关联属性。
- 本仓库 RuoYi 的 `SysUser` 转 `SysUserVO` 即此思路（见 [[RuoYi-Analysis/07-后端-系统业务层]]）。

## 陷阱 5：不合理的事务粒度

```java
@Transactional
public void importUsers(List<User> list) {
    for (User u : list) userMapper.insert(u);  // 整个方法一个长事务
}
```
- 10 万行一个事务 → undo log 暴涨、锁表时间长、回滚代价大。
- 解法：**分批 + 每批独立小事务**（或 BATCH 执行器 + 定时 commit，见 02）。

## 陷阱 6：`#{}` vs `${}` 用错导致注入/报错

- `${}` 拼接 → SQL 注入（用户输入列名/排序）。
- 误用 `${}` 拼数值 → 报错或注入。
- 详见 [[MyBatis Mapper XML/进阶专题/06-企业实战与疑难排查/04-诡异Bug排查与Locations坑根源]]。

## 排查清单（遇到慢查询时）

```
1. 是不是 N+1？→ 看日志 SQL 条数，换嵌套结果 JOIN
2. EXPLAIN 是否 ALL/没走索引？→ 类型隐式转换 / 函数包裹 / 前缀模糊
3. 是否 SELECT *？→ 收窄列 + 覆盖索引
4. 是否大事务？→ 分批提交
5. 是否序列化触发懒加载？→ VO 拷贝 / JsonIgnore
```
