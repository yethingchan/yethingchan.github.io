# 04-批量与性能优化 · 流式查询与大结果集

> 前置：[[MyBatis Mapper XML/进阶专题/04-批量与性能优化/00-索引]]

## 问题：一次查 1000 万行会 OOM

`List<User> list = mapper.selectAll();` 会把**所有行一次性加载进 JVM 堆** → 内存爆炸。大结果集必须**流式/游标**逐行处理。

## 方案 1：`ResultHandler` 逐行回调（推荐）

```java
try (SqlSession session = sqlSessionFactory.openSession()) {
    UserMapper mapper = session.getMapper(UserMapper.class);
    mapper.selectAll(resultContext -> {
        User u = resultContext.getResultObject();
        // 每行即时处理，不累积
        process(u);
    });
}
```
- `ResultHandler.handleResult` 对每行调用一次。
- **不攒 List**，内存恒定。
- Mapper 方法签名：`void selectAll(ResultHandler<User> handler);`（返回 void）。

XML 无需特殊处理，正常写 `select`。

## 方案 2：JDBC `fetchSize`（减少往返）

无论流式与否，`fetchSize` 控制 JDBC 每次从服务端拉多少行：

```yaml
mybatis:
  configuration:
    default-fetch-size: 1000   # 每次从 MySQL 拉 1000 行
```
或语句级：
```xml
<select id="selectAll" resultType="User" fetchSize="1000"> ... </select>
```
- MySQL 默认 `fetchSize=0` 是"一次性全拉"。设正数才分批拉。
- Oracle/PostgreSQL 对 `fetchSize` 敏感；MySQL 需配合 `useCursorFetch=true` 才真正游标化：
  ```yaml
  url: jdbc:mysql://...?useCursorFetch=true&defaultFetchSize=1000
  ```

## 方案 3：MyBatis Cursor（类型友好版）

```java
try (SqlSession session = sqlSessionFactory.openSession()) {
    UserMapper mapper = session.getMapper(UserMapper.class);
    try (Cursor<User> cursor = mapper.selectAllCursor()) {
        for (User u : cursor) {     // 迭代即逐行拉取
            process(u);
        }
    }
}
```
- Mapper 方法返回 `Cursor<User>`。
- 必须在 **原 SqlSession 未关** 时遍历（所以 try-with-resources 包住 session）。
- 比 `ResultHandler` 更面向对象，可用 for-each。

## 导出大文件（流式中转）

典型场景：导出 50 万行 Excel。若全加载再写，OOM。

```java
try (SqlSession s = factory.openSession();
     Cursor<Order> cursor = orderMapper.cursorAll();
     ExcelWriter writer = ...) {
    for (Order o : cursor) {
        writer.writeRow(o);   // 边查边写，内存恒定
    }
}
```
> 本仓库若用 EasyExcel，可直接 `ExcelWriter` 流式写出（见 [[MyBatis Mapper XML/进阶专题/06-企业实战与疑难排查/02-注解XML混合与复杂报表SQL]] 提及的报表导出）。

## 注意事项

1. **流式/游标必须原 Session 活着**：在 `@Transactional` 外或提前关 Session 会 `Cursor closed`。
2. **流式里别再发同 Session 查询**（可能导致结果集错乱），需另开 Session。
3. `fetchSize` 只对真正支持游标的驱动有效（MySQL 需 `useCursorFetch`）。
4. 处理完及时 `commit`/释放，别让长事务占锁。

## 结论

- 大结果集：**`ResultHandler` 或 `Cursor` + `fetchSize`**，边查边处理，内存恒定。
- 不用的写法：`List` 一把全加载。
