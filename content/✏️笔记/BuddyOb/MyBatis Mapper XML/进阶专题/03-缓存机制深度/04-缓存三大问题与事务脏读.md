# 03-缓存机制深度 · 缓存三大问题与事务脏读

> 前置：[[MyBatis Mapper XML/进阶专题/03-缓存机制深度/00-索引]]

无论用二级缓存还是 Redis 业务缓存，都会遇到经典三大问题。加上 MyBatis 特有的"事务脏读"，共四类。

## 1) 缓存穿透（查不存在的数据）

**现象**：请求一个 DB 和缓存里都**没有**的 key（如 `id=-1`、`id=超大`），每次都穿透到 DB。
**危害**：被恶意刷不存在的 id → DB 被打挂。

**解决**：
- **空值缓存**：查不到也写 `null` 进缓存（短 TTL），下次直接命中空值。
  ```java
  Object v = redis.get(key);
  if (v == null) {
      v = mapper.selectById(id);
      redis.set(key, v != null ? v : NULL_OBJ, 5, MINUTES); // 空值也缓存
  }
  ```
- **布隆过滤器（Bloom Filter）**：在缓存前加一层，先判"这个 id 可能存在吗"，不存在直接拦。

## 2) 缓存击穿（热点 key 过期瞬间）

**现象**：某个**热点 key**（如首页配置）刚好过期，此时海量并发同时打到 DB。
**区别**：穿透是"永远没有"，击穿是"曾经有、刚过期"。

**解决**：
- **互斥锁（singleflight）**：只有一个线程去查 DB，其他线程等它回填。
  ```java
  if ((v = redis.get(key)) == null) {
      if (redis.setIfAbsent(lockKey, "1", 3, SECONDS)) {
          try { v = loadFromDb(); redis.set(key, v, 30, MINUTES); }
          finally { redis.delete(lockKey); }
      } else { Thread.sleep(50); return get(key); } // 重试取缓存
  }
  ```
- **热点 key 不过期**：逻辑过期（存 `expire` 字段，异步刷新）。

## 3) 缓存雪崩（大量 key 同时过期）

**现象**：一大批 key 在同一时刻失效（如初始化时统一设 30 分钟），瞬间全部打 DB。
**解决**：
- **TTL 加随机抖动**：`30min + random(0, 10min)`。
- **多级缓存**：本地 Caffeine + Redis，Redis 挂了还有本地。
- **Redis 高可用**：集群 + 哨兵，避免 Redis 整体宕机。

## 4) MyBatis 二级缓存的"事务脏读"陷阱

这是 Mapper 二级缓存**独有的**问题：

**场景**：
```
事务 A：update sys_user set name='新' where id=1  → 提交
事务 B（已开启）：之前查过 id=1 → 命中二级缓存，读到'旧'（因为 B 的 localCache/二级已缓存）
```
更严重的是**跨 Mapper 写同一张表**：
```
DictMapper 缓存了 sys_config 全表
ConfigMapper.update 改了 sys_config 一行 → 只清 ConfigMapper 的缓存，DictMapper 的没清
→ DictMapper 继续返回旧配置（脏读）
```
**根本原因**：二级缓存按 `namespace` 隔离，而**数据是按表分布的**，namespace ≠ 表，于是"写 A 表 → B 缓存不失效"。

**解决**：
- 多表关联/强一致业务**干脆别开 Mapper 二级缓存**。
- 或所有读写同一表的 Mapper 用 `<cache-ref>` 共享同一块缓存。
- 或用 Redis 业务缓存，并在**所有写操作后显式 `redis.delete(prefix)`**（RuoYi 的做法：`DictUtils.clearDictCache()` 在增删改后调用）。

## 总结对照

| 问题 | 触发 | 解法 |
|------|------|------|
| 穿透 | 查不存在的 key | 空值缓存 / 布隆过滤器 |
| 击穿 | 热点 key 刚过期 | 互斥锁 / 逻辑过期 |
| 雪崩 | 大量 key 同过期 | TTL 抖动 / 多级 / 集群 |
| 脏读 | 跨 Mapper 写同表 | 关二级缓存 / cache-ref / 显式清 |
