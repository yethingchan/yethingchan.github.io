# 05-插件与拦截器 · 分页插件原理对比

> 前置：[[MyBatis Mapper XML/进阶专题/05-插件与拦截器/01-Interceptor四大拦截点原理]]

## 分页的本质

MySQL 分页靠 `LIMIT ?, ?`。MyBatis 本身不内置分页，于是有了分页插件——在 `Executor.query` 或 `StatementHandler` 层**自动拼 `LIMIT` 并补一条 `COUNT(*)`**。

## PageHelper（最老牌）

原理：`PageHelper.startPage(pageNum, pageSize)` 把分页参数存进 **`ThreadLocal`**，拦截器在 query 前读它，改写 SQL + 发 count。

```java
PageHelper.startPage(1, 10);
List<User> list = userMapper.selectList();
PageInfo<User> page = new PageInfo<>(list);  // 从 ThreadLocal 取 total
```
- **致命约束**：`startPage` 后**紧跟的第一条查询**才被分页。中间插了别的查询 → 分页错乱。
- 是基于 `Executor` 拦截 + `ThreadLocal`，与事务/异步线程容易串。

## MyBatis-Plus `PaginationInnerInterceptor`（本仓库风格）

MP 的分页是 `InnerInterceptor`，挂在 `MybatisPlusInterceptor` 上：

```java
@Bean
public MybatisPlusInterceptor mpInterceptor() {
    MybatisPlusInterceptor i = new MybatisPlusInterceptor();
    i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
    return i;
}
```
```java
Page<User> page = new Page<>(1, 10);
userMapper.selectPage(page, Wrappers.emptyWrapper());
// page.getRecords() / page.getTotal() 已填充
```
- 基于**分页对象 `Page` 入参**判断要不要分页（而非 ThreadLocal），更显式、更安全。
- `InnerInterceptor` 还能同时挂 `OptimisticLocker`（乐观锁）、`BlockAttack`（防全表）、`TenantLine`（多租户）——**一套链完成多个拦截**（见 03/04）。

## 两者对比

| 维度 | PageHelper | MP PaginationInnerInterceptor |
|------|-----------|------------------------------|
| 触发方式 | ThreadLocal `startPage` | `Page` 对象入参 |
| 线程安全 | 弱（ThreadLocal 串味） | 强（显式参数） |
| 与 MP 生态 | 独立 | 原生融合（乐观锁/租户/防全表） |
| count 优化 | 自动 count | 自动 count，可 `@InterceptorIgnore` 关 |
| 本仓库 | 本仓库 RuoYi 用的是 PageHelper（分析见 [[RuoYi-Analysis/19-前端-视图与API分层]] 中的分页传参） | 进阶教程 [[MyBatisPlus/09-分页插件]] 用 MP |

## count 是怎么来的

两个插件都会：**复制原 MappedStatement，把 SQL 包成 `SELECT COUNT(*) FROM (原SQL) tmp`**，单独执行拿总数。所以复杂 SQL 的分页会发**两条** SQL（你能在日志看到 count 那条）。

## 性能注意

- 深度分页 `LIMIT 1000000, 10` 很慢（要扫 100 万行再丢）。解法：
  - **游标/延迟关联**：`WHERE id > ? LIMIT 10` + 上一页最大 id。
  - **覆盖索引**先取 id 再 JOIN。
- 见 [[MySQL/进阶专题/02-索引底层与优化器执行计划/05-索引失效全场景]] 深分页部分。

## 结论

- 老项目（如本仓库 RuoYi）用 PageHelper，注意 `startPage` 后紧跟查询。
- 新项目/MP 项目用 `PaginationInnerInterceptor`，显式 `Page` 更安全，且能一条链挂多个 InnerInterceptor。
