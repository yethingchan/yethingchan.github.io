# 02 硬件通信核心模块（上位机独有）

> 代码：`Hardware/SerialManager.cs`、`Hardware/TcpManager.cs`、`Hardware/PlcDriver.cs`、`Hardware/DeviceCapture.cs`
> 首页 → [[C#上位机从0到1/00-总览]]

本模块是上位机区别于普通 MIS 的核心。**所有通信都走独立线程 + 事件回调 + 日志**，UI 不阻塞。无真实设备时用内置**模拟通道/模拟器**即可跑通全流程。

## 一、串口通信管理（RS232/485）

`SerialManager` 封装 `System.IO.Ports.SerialPort`：

```csharp
var mgr = new SerialManager {
    PortName = ParamService.Get("serial_port") ?? "COM1",
    BaudRate = int.Parse(ParamService.Get("serial_baud") ?? "9600"),
    DataBits = 8, Parity = Parity.None, StopBits = StopBits.One
};
mgr.Connect();                       // 打开并订阅 DataReceived
mgr.Send("AT+RST\r\n");            // 文本
mgr.SendHex("AA 01 02 FF 55");       // 十六进制
mgr.EnableAutoReconnect(5000);      // 断开自动重连
mgr.DataReceived += line => { /* 收到的一行 */ };
```

- **自动扫描**：`SerialManager.ScanPorts()` 返回 `SerialPort.GetPortNames()`；`Connect()` 前校验端口存在，否则友好报错（而非崩溃）。
- **收发报文实时日志**：所有发送/接收都经 `Logger.LogComm("SEND"/"RECV", channel, hex)`，按**日期分文件**写到 `logs/comm_yyyyMMdd.log`（满足"日志按日期自动分文件保存"）。
- **自动重发**：业务层把指令入队，`SerialManager` 后台按策略重发（示例为连接级重连，指令级重发在 `TcpManager` 的发送队列实现）。
- **多串口同时独立通信**：每路设备建一个 `SerialManager` 实例，各自线程，互不阻塞。

无硬件演示：`SimSerialChannel`（同样的 `ISerialChannel` 接口）定时吐样例条码/重量，业务层**零改动**。

## 二、TCP 客户端通信（PLC / WCS / 立体库）

`TcpManager` 实现自定义协议 + 健壮传输：

```csharp
var tcp = new TcpManager {
    Host = ParamService.Get("plc_ip") ?? "127.0.0.1",
    Port = int.Parse(ParamService.Get("plc_port") ?? "502"),
    HeartbeatMs = 3000
};
tcp.FrameReceived += payload => { /* 完整帧负载 */ };
tcp.Connect();
tcp.Enqueue(Encoding.ASCII.GetBytes("READ DB1.0"));  // 自动封帧入队发送
```

关键设计：
- **自定义帧协议**：`[0xAA][长度2字节大端][负载][0x55]`，`BuildFrame()` 负责封帧。
- **粘包/分包处理**：`OnRead` 把字节累加进 `_buf`，`ExtractFrames()` 按头尾切分完整帧；不足一帧时**保留残留**等下次数据（`i>0` 时把残留前移），彻底解决 TCP 流式拆包问题。
- **心跳包检测**：`HeartbeatMs` 定时器周期 `Enqueue("PING")`。
- **断线自动重连**：`TryReconnect` 后台定时探测，断开即重连并记日志。
- **发送指令队列 + 异步收发**：`_sendQ`（ConcurrentQueue）+ `Flush()`，UI 线程只入队，发送在 IO 线程，超时/异常不卡 UI。

## 三、PLC 寄存器读写（汇川/西门子/三菱）

统一抽象 `IPlcDriver`，上层业务**不感知品牌**：

```csharp
IPlcDriver drv = PlcDriverFactory.Create(ParamService.Get("plc_type")); // inovance/siemens/mitsubishi
int  speed = drv.ReadInt("DB2.0");         // 读运行速度
drv.WriteBool("DB1.0", true);                // 位操作（开关信号）
short sw = drv.SwapBytes((short)value);        // 高低字节互换
var map = new RegisterMap(drv);              // 绑定寄存器映射表
var vals = map.ReadAll();                     // 一键批量读全部点位
```

- **批量读 DB 区 / MD/VD / X/Y**：三个品牌驱动各自 `Normalize()` 把地址归一成模拟键（`INO:`/`SI:`/`MI:`），真实部署时把"访问模拟存储"替换为经 `TcpManager`/`SerialManager` 发送协议报文即可，**业务代码不动**。
- **数值转换（高低字节互换）**：`SwapBytes()` 处理字寄存器字节序。
- **寄存器映射配置表，一键导入导出**：`PlcPointService` 把 `plc_point` 表导成 CSV（`ExportCsv`）/导入（`ImportCsv`），`RegisterMap` 按设备分组批量读写。**调试用 `FrmPlcSim` 不接真机即可读写寄存器**。

## 四、扫码枪 / 称重仪表对接

`DeviceCapture` 包一层 `ISerialChannel`，把串口流解析成业务事件：

```csharp
var scan = new DeviceCapture(new SimSerialChannel { Device = "SCANNER" }, "SCANNER");
scan.BarcodeScanned += code => { /* 扫码自动填充入库表单，无需手动输入 */ };
scan.Open();

var scale = new DeviceCapture(new SimSerialChannel { Device = "SCALE" }, "SCALE");
scale.WeightReceived += w => { /* 重量自动读数 */ };
scale.Open();
```

- 扫码以 `\r\n` 为界切行；称重解析 `WEIGHT:xx.x` 正则取数值。
- 窗体订阅事件即"自动捕获物料条码/重量"，直接回填表单（见 [[C#上位机从0到1/03-库存与单据业务]] 的扫码入库）。
