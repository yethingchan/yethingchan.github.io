## 八、UI 通用基础

### 8.1 GridPager —— DataGridView 通用封装
业务窗体（用户、物料、库存、单据…）本质上都是"表格 + 增删改查"。
把分页、列隐藏、异常行标红、双击弹窗、关键字过滤全部收进 `UI\GridPager.cs` 一个 `UserControl`，
各窗体拖一个 `GridPager` 即可，**避免 12 个窗体各写一遍**。

```csharp
// UI/GridPager.cs（节选：对外 API）
public class GridPager : UserControl
{
    public DataGridView Grid => _gv;
    public event Action<DataRow> RowDoubleClick;     // 双击某行 -> 打开编辑窗

    public void SetData(DataTable dt) => Goto(0);     // 绑定整表，内部做内存分页
    public void HideColumns(params string[] cols)      // 隐藏内部 id 等列
    public void AutoSizeColumns()
    public void MarkRows(Func<DataRow,bool> pred, Color color)  // 异常行标红
    public DataTable CurrentFull() => _full;          // 给"导出当前表"用
}
```

- **分页**：`_pageSize = 50`，`Goto(page)` 用 `ImportRow` 只取本页行，`_lblPage` 显示"第 X / Y 页（共 N 条）"。
- **列隐藏**：`HideColumns("id","doc_id")` 把主键列藏掉，界面只给人看业务字段。
- **异常行标红**：`MarkRows(r => (int)r["qty"] < 0, Color.LightPink)` —— 库存预警、负值差异行一目了然。
- **双击弹窗**：`CellDoubleClick` 把 `DataRowView.Row` 抛给订阅者，业务窗体据此打开 `FrmXxxEdit`。
- **过滤**：顶部 `TextBox` + "搜索"，对字符串列拼 `LIKE '%kw%'` 的 `DataView.RowFilter`。

> 对应需求："分页、列隐藏、行颜色标记（异常行标红）、单元格双击弹窗"。

```csharp
private void OpenForm(string formType, string title)
{
    var t = Type.GetType(formType);                 // 例如 "Host.UI.FrmStock"
    if (_tabs.TabPages.Cast<TabPage>().Any(p => p.Tag is Type tt && tt == t))
    { _tabs.SelectedTab = ...; return; }            // 已打开则切到该页，不重复开
```

### 8.5 通信日志滚动（不阻塞通信线程）
全工程所有串口/TCP/PLC 收发都经 `Logger.LogComm(...)`，它**同步写文件 + 异步推事件**；主窗体订阅事件后用 `SafeUi.Invoke` 回到 UI 线程追加文本，所以**通信线程永远不被 UI 卡住**。

```csharp
// Common/Logger.cs
public static void LogComm(string direction, string channel, string content)
{
    var entry = new CommLogEntry { Time=DateTime.Now, Direction=direction, Channel=channel, Content=content };
    WriteFile(Path.Combine(LogDir, $"comm_{DateTime.Now:yyyyMMdd}.log"), line); // 按日分文件
    try { OnComm?.Invoke(entry); } catch { }   // 推给主窗体，失败不影响业务
}
// 主窗体
Logger.OnComm += OnComm;
private void OnComm(CommLogEntry e)
{
    _commBuf.Add(e);                              // 内存缓冲（上限 5000 条）
    SafeUi.Invoke(_commLog, () =>                // 关键：切回 UI 线程
        SafeUi.AppendLine(_commLog, $"[{e.Time:HH:mm:ss}] {e.Direction} [{e.Channel}] {e.Content}"));
}
```
底部还有"过滤：全部/仅发送/仅接收"下拉，点一下 `RebuildComm()` 重建文本框内容；"日志清空"调 `Logger.ClearCommLog(day)`。

> 对应需求："全局日志文本框实时滚动刷新，不阻塞通信线程""日志按日期自动分文件保存，支持回溯查询""日志清空、日志过滤（只看发送/接收报文）"。

## 九、安全与运维

### 9.1 全局异常捕获（不闪退）
`Program.cs` 在 `Main` 最开头挂上两层兜底，**任何未处理异常都弹窗提示而不是崩溃退出**：

```csharp
[STAThread] static void Main(string[] args)
{
    Application.EnableVisualStyles();
    // 1) UI 线程异常
    Application.ThreadException += (s, e) => GlobalExceptionHandler(e.Exception);
    // 2) 非 UI 线程（通信/定时器/线程池）异常
    AppDomain.CurrentDomain.UnhandledException += (s, e) =>
        GlobalExceptionHandler(e.ExceptionObject as Exception);

    // 单实例：避免重复开多个上位机抢串口
    _mutex = new Mutex(true, "Global\\CSharpHostUpperComputer", out bool createdNew);
    if (!createdNew) { MessageBox.Show("程序已经在运行。"); return; }

    DbHelper.EnsureDb();            // 首次运行建库建表
    BLL.AuthService.EnsureAdmin(); // 种子 admin 账号
    Application.Run(new UI.LoginForm(autoStart));
}
private static void GlobalExceptionHandler(Exception ex)
{
    Logger.LogApp("全局未处理异常：" + ex.Message + "\n" + ex.StackTrace);
    MessageBox.Show("程序遇到异常（已捕获，不会退出）：\n" + ex.Message +
                    "\n\n详细信息已写入日志。", "运行异常", MessageBoxButtons.OK, MessageBoxIcon.Warning);
}
```

> 对应需求："程序异常全局捕获，弹窗提示错误信息，不直接崩溃闪退"。

### 9.2 操作日志不可删除
- 入库/出库/调拨/盘点所有动作都经 `LogService.Operate(module, action, detail)`，写入 `sys_log_operate`。
- 登录成功写 `sys_log_login`。
- **代码里没有任何删除这两张表的接口**（BackUpService 的清理只针对 `comm/app` 文本日志与 `cancel` 单据，碰不到操作日志表），从根本上保证"操作日志永久留存、不可删除"。
- 查询在 `FrmAlarm`/`FrmDocQuery` 旁的操作日志页通过 `LogService.QueryOperate/QueryLogin` 只读展示。

> 对应需求："操作日志不可删除，永久留存"。

### 9.3 事务与自动回滚
这是"防止库存错乱"的核心。所有库存变更都包在 `DbHelper.Tx` 里，**事务内任意一步抛异常 → 自动 `Rollback` → 异常继续向上抛 → UI 弹窗**。

```csharp
// Data/DbHelper.cs
public static void Tx(Action<SQLiteConnection> action)
{
    using (var c = Open())
    using (var tx = c.BeginTransaction())
    {
        try { action(c); tx.Commit(); }
        catch { tx.Rollback(); throw; }   // 回滚后把异常抛给调用方
    }
}
```
`BLL\DocService.cs` 的每个提交方法都用它，例如**出库 FIFO + 库存不足拦截**：

```csharp
public static void SubmitOutbound(int docId)
{
    DbHelper.Tx(c =>
    {
        var items = QueryOutItems(c, "SELECT * FROM doc_out_item WHERE doc_id=@d", ("@d", docId));
        foreach (var need in items)
        {
            // FIFO：同物料按 produce_date 升序、batch 升序取库存批次
            var stocks = DbHelper.QueryOn(c,
                "SELECT s.material_code,s.batch,s.location_code,s.qty FROM mat_stock s " +
                "JOIN mat_material m ON s.material_code=m.code " +
                "WHERE s.material_code=@m AND s.qty>0 " +
                "ORDER BY (CASE WHEN s.produce_date='' THEN '9999' ELSE s.produce_date END) ASC, s.batch ASC",
                ("@m", need.MaterialCode));
            double totalAvail = stocks.Rows.Cast<DataRow>().Sum(r => Convert.ToDouble(r["qty"]));
            if (totalAvail < need.Qty)
                throw new Exception($"物料 {need.MaterialCode} 库存不足：需 {need.Qty}，可用 {totalAvail}（禁止超领）");
            // 逐批次扣减，直到满足需求
            double remain = need.Qty;
            foreach (DataRow r in stocks.Rows)
            {
                if (remain <= 0) break;
                double take = Math.Min(Convert.ToDouble(r["qty"]), remain);
                SubStock(c, r["material_code"].ToString(), r["batch"].ToString(), r["location_code"].ToString(), take);
                remain -= take;
            }
        }
        DbHelper.NonQuery(c, "UPDATE doc_out SET status='done' WHERE id=@i", ("@i", docId));
    });
    LogService.Operate("出库", "提交", $"单号#{docId}");
}
```
调拨/盘点同理：先校验库存足够或计算差异，再在同一事务里 `SubStock`/`AddStock`/`AdjustStock`，**要么全成、要么全不成**。

> 对应需求："数据库操作事务，单据保存失败自动回滚，防止库存错乱""按 FIFO 自动分配批次物料""出库校验库存不足弹窗报警、禁止超领"。

### 9.4 断线缓存 + 重连补发
TCP 通信（`Hardware\TcpManager.cs`）用**发送队列 + 异步读写 + 定时重连**，天然实现"断线缓存单据、重连后自动补发"：

```csharp
private readonly ConcurrentQueue<byte[]> _sendQ = new ConcurrentQueue<byte[]>();

public void Enqueue(byte[] payload)
{
    _sendQ.Enqueue(BuildFrame(payload));
    Flush();
}
private void Flush()
{
    if (_stream == null || !IsConnected) return;   // 断线时：帧留在队列里，不丢
    while (_sendQ.TryDequeue(out var frame)) { _stream.Write(frame,0,frame.Length); Logger.LogComm("SEND","TCP",ToHex(frame)); }
}
// 读到 0 字节或异常 -> 5 秒后 TryReconnect -> Disconnect + Connect
// 重连成功后，下一次 Enqueue/心跳会触发 Flush，把队列里滞留的帧一次性补发
```
要点：**断线期间发出的指令不会丢失**，它们堆在 `_sendQ`；链路恢复后 `Flush` 自动把积压帧发出去。PLC 驱动层也内置 `PlcSimulator`，无真实设备也能跑通整条"读寄存器→业务处理"链路。

> 对应需求："通信断线自动缓存单据，重连后自动补发""断线自动重连""心跳包检测"。

### 9.5 开机自启 + 托盘后台

### 9.6 多线程隔离
三套职责互不阻塞：
| 线程 | 载体 | 说明 |
|------|------|------|
| 通信线程 | `TcpClient.BeginRead` / `SerialPort.DataReceived` / `Timer` | 异步收发、粘包解析、心跳，**不碰 UI** |
| UI 线程 | `Application.Run` 主消息循环 | 所有控件更新经 `SafeUi.Invoke` 切回 |
| 数据库线程 | `DbHelper.Open()` 每次新建连接（连接池 Max 20） | 事务内同步读写，调用方在业务线程 |

`Common\SafeUi.cs` 统一封装 `Invoke/AppendLine/SetText`，杜绝"跨线程操作控件"异常。

> 对应需求："多线程隔离：通信线程、UI 线程、数据库线程互不阻塞"。
