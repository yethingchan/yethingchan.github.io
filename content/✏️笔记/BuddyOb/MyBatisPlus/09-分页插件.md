# 09 分页插件（PaginationInnerInterceptor）

> 上接：[[08-动态条件与自定义SQL]]
> 分页是后台最高频操作。MP 用**拦截器**自动改写 `selectPage`：先 count 再 limit，你只管传 `Page`。

## 9.1 注册拦截器（Spring 配置）

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 分页插件（可指定数据库类型，不指定 MP 自动识别）
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        // 顺带加：防全表更新/删除（[[03-BaseMapper的CRUD]] 3.6）
        interceptor.addInnerInterceptor(new BlockAttackInnerInterceptor());
        return interceptor;
    }
}
```
> 本 Spring 教程的 `MyBatisPlusConfig` 就是这个（见 [[../SpringBoot+Vue3后台搭建/03-后端基础框架/02-MyBatisPlus与Redis配置]]）。**不加这个 Bean，`selectPage` 不会分页**，会查出全表。

## 9.2 用法：传 Page，拿 IPage

```java
// ① 构造 Page（第1页，每页10条）
Page<User> page = new Page<>(1, 10);

// ② selectPage(page, wrapper) —— 会自动做两件事：
//    a) 先 SELECT COUNT(*) 拿总数（写入 page.total）
//    b) 改写 SQL 加 LIMIT 拿本页
LambdaQueryWrapper<User> lw = Wrappers.lambdaQuery(User.class)
    .eq(User::getStatus, "0");
Page<User> result = userMapper.selectPage(page, lw);

// ③ 取结果
long total = result.getTotal();       // 总条数（MP 自动 count）
List<User> rows = result.getRecords(); // 本页数据
```

## 9.3 和统一返回 R<T> 接上（前端 el-table）

本教程的 `R.ok(page)` 正好吃 `IPage`：
```java
@GetMapping("/list")
public R<SysUser> list(SysUser q, PageQuery pq) {
    Page<SysUser> page = userService.page(
        new Page<>(pq.getPageNum(), pq.getPageSize()),
        Wrappers.lambdaQuery(q).orderByDesc(SysUser::getCreateTime));
    return R.ok(page);   // → 前端 {code:200, rows:[...], total:100}
}
```
> 前端 `:data="tableData.rows"` + `el-pagination :total="tableData.total"`，见 [[../SpringBoot+Vue3后台搭建/08-前端通用封装/01-表格与表单通用组件]]。

## 9.4 关闭 count / 多排序

```java
Page<User> page = new Page<>(1, 10);
page.setSearchCount(false);          // 不查总数（已知不需要 total 时提速）
page.addOrder(OrderItem.desc("age"));  // 代码里加排序（也可在 wrapper 里 orderBy）
```

## 9.5 联表分页（手写 count）

`selectPage` 对**手写 JOIN SQL** 的 count 可能算错（它默认套 `SELECT COUNT(*) FROM (你的SQL)`）。稳妥做法：
```java
// Mapper 里自己写两个：list（LIMIT 由 MP 加）+ count
@Select("SELECT u.* FROM sys_user u LEFT JOIN sys_dept d ON ... ${ew.customSqlSegment}")
List<User> selectUserJoinDept(IPage<User> page, @Param("ew") Wrapper<User> w);

// 调用：MP 对 IPage 第一参会自动分页；count 用 Wrapper 单独算
IPage<User> page = new Page<>(1,10);
userMapper.selectUserJoinDept(page, wrapper);   // 自动 LIMIT
long total = userMapper.selectCount(wrapper);     // 自己补 count
```
> 复杂 JOIN 分页的 count 若 MP 自动生成不准，**自己写 count 方法**最稳。

## 验证清单

- [ ] 注册 `MybatisPlusInterceptor` + `PaginationInnerInterceptor` 后，`selectPage` 返回 `total` 正确且只查本页。
- [ ] 没注册分页插件时，`selectPage` 把全表返回（对比验证）。
- [ ] `R.ok(page)` 后前端 `rows`/`total` 直接绑定 `el-table` + `el-pagination`。
- [ ] 联表分页的 count 不准时，已用独立 `selectCount` 兜底。
