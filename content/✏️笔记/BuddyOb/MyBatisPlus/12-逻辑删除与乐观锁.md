# 12 逻辑删除与乐观锁

> 上接：[[MyBatisPlus/11-自动填充MetaObjectHandler]]
> 两个"防出事"的企业必备能力：**逻辑删除**（删了还能恢复）和**乐观锁**（并发改同一行不互相覆盖）。

## 12.1 逻辑删除（@TableLogic）

**物理删除**直接 `DELETE FROM`，数据没了救不回。**逻辑删除**是 `UPDATE del_flag=2`，查询自动过滤掉。

### 全局配置（推荐，一劳永逸）
```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: delFlag        # 所有实体这个字段名
      logic-delete-value: "2"            # 删除标记
      logic-not-delete-value: "0"        # 未删标记
```

### 实体标注
```java
public class SysUser {
    @TableLogic
    private String delFlag;   // 不写全局配置时，可 @TableLogic(value="2", delval="0")
}
```

### 效果（全自动，你无感）
```java
userService.removeById(1L);
// 实际执行：UPDATE sys_user SET del_flag='2' WHERE user_id=1 AND del_flag='0'

userService.list();   // 自动带：WHERE del_flag='0'（删过的查不出）
userService.selectCount(...);  // count 也只数未删的
```
> ⚠️ **坑**：逻辑删除后，**手写 XML/注解 SQL 不会自动带 `del_flag='0'`**——你手写的 SQL 得自己加条件。只有 MP 的 Wrapper/BaseMapper 方法才自动过滤。

## 12.2 乐观锁（@Version）

**场景**：A、B 同时读库存=100；A 改成 80 提交，B 也基于 100 改成 90 提交 → 覆盖成 90，A 的更新丢。
**乐观锁**：加版本号，提交时校验"我读的是不是最新版"，不是就失败重试。

### 实体 + 配置
```java
public class WmsInventory {
    @Version
    private Integer version;   // 每次更新自动 +1，且 WHERE 带 version=?
}

@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor i = new MybatisPlusInterceptor();
    i.addInnerInterceptor(new OptimisticLockerInnerInterceptor()); // 乐观锁拦截器
    i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
    return i;
}
```

### SQL 真相
```java
// A 读 version=1，改完提交：
// UPDATE wms_inventory SET qty=80, version=2 WHERE id=? AND version=1
// 若期间 B 已改成 version=2，A 的 WHERE version=1 命中 0 行 → MP 抛
//   OptimisticLockException（或更新条数=0，需你判断重试）
```
> **必须**：version 字段在 `update` 时要有值（查询出来的实体自带）；更新失败要**捕获后重试**，否则丢更新。

## 12.3 对比

| 能力 | 注解 | 拦截器 | 防什么 |
|------|------|---------|---------|
| 逻辑删除 | `@TableLogic` | （全局配置即可） | 误删不可恢复 |
| 乐观锁 | `@Version` | `OptimisticLockerInnerInterceptor` | 并发更新互相覆盖 |

## 验证清单

- [ ] `removeById` 执行的是 `UPDATE ... SET del_flag='2'`，不是 DELETE。
- [ ] 逻辑删除后，`list()` 查不出被删的记录（WHERE 自动带 `del_flag='0'`）。
- [ ] 两个线程同时改同一行，`version` 机制让后提交的那个失败（而非静默覆盖）。
- [ ] 手写 XML SQL 已**手动**加上 `del_flag='0'` 过滤（MP 不会替你加）。
