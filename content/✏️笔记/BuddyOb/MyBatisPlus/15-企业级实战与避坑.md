# 15 企业级实战与避坑（收官）

> 上接：[[MyBatis-Plus/14-多租户与JSON类型处理器]]
> 把生产环境最容易翻车的点一次列清。配合 [[MyBatis-Plus/00-总览与学习路线]] 的清单自测。

## 15.1 防全表更新/删除（Top1 事故）

```java
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor i = new MybatisPlusInterceptor();
    i.addInnerInterceptor(new BlockAttackInnerInterceptor());  // 空 wrapper 全表操作直接抛异常
    i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
    i.addInnerInterceptor(new OptimisticLockerInnerInterceptor()); // 乐观锁
    return i;
}
```
> 任何 `delete(wrapper)` / `update(null, wrapper)` **先确认 WHERE 非空**。空 wrapper 误操作 = 删库。详见 [[MyBatis-Plus/03-BaseMapper的CRUD]] 3.6。

## 15.2 SQL 注入（只有一处允许 ${}）

| 用法 | 安全？ |
|------|--------|
| `#{}` / Wrapper 参数（eq/like/apply("{0}"...)） | ✅ 预编译 |
| `${ew.customSqlSegment}` | ✅ MP 内部已参数化（**唯一**允许 `${}` 处） |
| `${}` 拼任何用户输入（列名/值/表名） | ❌ **注入** |

> 动态列名（前端传 `sortBy`）必须先过**白名单**再拼，绝不裸接。详见 [[MyBatis-Plus/08-动态条件与自定义SQL]] 8.4。

## 15.3 大批量插入性能

| 方式 | 问题 |
|------|------|
| 循环 `save(entity)` | N 次网络往返，极慢 |
| `saveBatch(list)` | **✅ 分批提交**（默认 1000/批） |
| 手写 `foreach` 单条巨 SQL | SQL 过长、易超 `max_allowed_packet` |

```java
userService.saveBatch(hugeList, 1000);   // 每 1000 一条多值 INSERT
```
> 超大数据量（十万级）用**并行 `saveBatch`** 或直连 JDBC `rewriteBatchedStatements=true`。

## 15.4 逻辑删除 / 租户 / 乐观锁的"手写 SQL 盲区"

三者都**只自动作用于 MP 的 Wrapper/BaseMapper**。**你手写的 XML/注解 SQL 不会**自动加：
- 逻辑删除 → 手写 SQL 要自己 `AND del_flag='0'`
- 多租户 → 手写 SQL 要自己 `AND tenant_id=#{tenantId}`
- 乐观锁 → 手写 SQL 要自己 `WHERE version=#{version}`

> 这也是为什么**单表 CRUD 尽量交给 MP**，少手写 SQL 少踩盲区。

## 15.5 count 优化（联表分页）

MP 自动 `SELECT COUNT(*) FROM (你的JOIN SQL)` 对联表**常算错/很慢**。复杂报表分页，自己写精准 count（[[MyBatis-Plus/09-分页插件]] 9.5）。

## 15.6 主键 Long → 前端精度丢失

雪花 19 位 Long 超出 JS `Number` 安全整数 `2^53`。实体 ID 字段加：
```java
@JsonSerialize(using = ToStringSerializer.class)  // Long → 字符串传前端
private Long userId;
```
> 否则前端拿到末几位变 0，回传更新时"找不到 ID"。见 [[MyBatis-Plus/10-主键策略与雪花算法]] 10.3。

## 15.7 字段策略（updateById 不冲掉 null）

`updateById` 只改**非 null** 字段。若需"把某列显式置 null"要：
```java
@TableField(updateStrategy = FieldStrategy.IGNORED)  // 该字段 update 时忽略判空
private String remark;
```
或 `UpdateWrapper.set("remark", null)` 直接写。

## 15.8 联表查询不擅长 Wrapper

Wrapper 是**单表**条件构造器。多表 JOIN 用：
- Mapper 里写 XML/注解 SQL + `${ew.customSqlSegment}` 接 Wrapper 管 WHERE（[[MyBatis-Plus/08-动态条件与自定义SQL]] 8.4）
- 或返回 `Map`/`VO`（非实体）接收多表列

## 15.9 生产配置建议

```yaml
mybatis-plus:
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl  # 仅开发！生产关掉（刷屏+泄漏SQL）
  global-config:
    banner: false        # 关 MP 启动 banner
```

## 一张图收尾

```
你写： entity(注解) + mapper(继承) + Wrapper(拼条件)
  │
  ▼ MP 拦截器链：BlockAttack(防全表) → Pagination(分页) → OptimisticLock(乐观锁) → TenantLine(租户)
  │
  ▼ 自动注入：MetaObjectHandler(填充时间/人) + 逻辑删除(转UPDATE) + 雪花(主键)
  │
  ▼ 执行：BaseMapper / IServer 方法 → 数据库
```
> 这就是 MP "少写 SQL 多写配置" 的威力。**Wrapper 是日常 80% 查询的归宿**，务必把 [[MyBatis-Plus/05-QueryWrapper详解]] 的速查表背熟。
