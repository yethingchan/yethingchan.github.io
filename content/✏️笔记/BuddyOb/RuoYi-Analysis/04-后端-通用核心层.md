# 04 · 后端-通用核心层（ruoyi-common）

> 对应清单：入门第 5～7 条、`BaseEntity`/`AjaxResult`/`R`；高级第 20 条（XSS）。
> `common` 不依赖任何内部模块，是**最底层、被全工程高频调用**的工具箱。本文精讲 3 个核心类，其余列职责。

## 一、AjaxResult —— 所有接口的"统一话术"

```java
public class AjaxResult extends HashMap<String, Object> {
    public static final String CODE_TAG = "code";
    public static final String MSG_TAG  = "msg";
    public static final String DATA_TAG = "data";

    // 成功：带数据
    public static AjaxResult success(Object data) {
        return AjaxResult.success("操作成功", data);
    }
    // 失败
    public static AjaxResult error(String msg) {
        return AjaxResult.error(msg, null);
    }
    // 链式 put（关键！）
    @Override
    public AjaxResult put(String key, Object value) {
        super.put(key, value);
        return this;          // 返回 this，可 .put().put()
    }
    public boolean isSuccess() {
        return Objects.equals(HttpStatus.SUCCESS, this.get(CODE_TAG));
    }
}
```

**逐行解释：**
- `extends HashMap<String,Object>`：<u>它本质就是个 Map</u>。`return AjaxResult.success("操作成功", data)` 等价于返回 `{"code":200,"msg":"操作成功","data":{...}}`。前端 `res.code === 200` 就是读这个 Map 的 `code` 键。
- `success/error/warn` 是**静态工厂方法**，Controller 里直接 `return AjaxResult.success(list)` 即可，不用 `new`。
- **`put()` 重写返回 `this`**：这是链式调用的关键。`SysUserController.getInfo()` 里 `ajax.put("postIds",...).put("roleIds",...)` 能连写，因为每次 `put` 都返回自己。
- `HttpStatus.SUCCESS` 是 `200`（见下文常量）。`isSuccess()` 给后端自己判断用。
- **设计要点**：用 Map 而非固定 POJO，是为了**灵活塞任意额外字段**（如上面 `postIds`/`roleIds`）。代价是前端拿 `data` 是弱类型 `any`。

## 二、R<T> —— 强类型的另一种返回

```java
public class R<T> implements Serializable {
    public static final int SUCCESS = HttpStatus.SUCCESS; // 200
    public static final int FAIL    = HttpStatus.ERROR;   // 500
    private int code;
    private String msg;
    private T data;
    public static <T> R<T> ok(T data) { return restResult(data, SUCCESS, "操作成功"); }
    public static <T> R<T> fail(String msg) { return restResult(null, FAIL, msg); }
}
```

**解释：** 和 `AjaxResult` 二选一。`R<T>` 用**泛型 `T data`**，编译期就知道返回什么类型，适合"纯数据类型接口"（如监控数据、字典列表）。`AjaxResult` 更灵活，适合"要顺带一堆杂字段"的页面接口。本项目 Controller 多用 `AjaxResult` 和 `TableDataInfo`。

## 三、BaseEntity —— 所有数据库实体的"公共字段基类"

```java
public class BaseEntity implements Serializable {
    @JsonIgnore                      // ① 序列化时忽略（不传给前端）
    private String searchValue;

    private String createBy;          // ② 创建者
    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private Date createTime;          // ③ 创建时间
    private String updateBy;
    private Date updateTime;
    private String remark;

    @JsonInclude(JsonInclude.Include.NON_EMPTY)  // ④ 空 Map 不序列化
    private Map<String, Object> params;   // ⑤ 扩展参数袋（数据权限 SQL 就藏这）

    public Map<String, Object> getParams() {
        if (params == null) params = new HashMap<>();
        return params;
    }
}
```

**逐行解释（这个类的 `params` 是数据权限的命门）：**
1. `@JsonIgnore`：`searchValue`（前端搜索框值）只在查库时用，没必要回传前端，忽略掉减小流量。
2. `createBy/createTime/updateBy/updateTime`：<u>每张业务表都有这 4 个审计字段</u>。Insert/Update 时由 MyBatis 的 `MetaObjectHandler`（或 Service 手动）自动填当前登录人（见 [[07-后端-系统业务层]]）。
3. `@JsonFormat`：Date → 字符串的格式，`"2026-07-19 14:25:27"`。
4. `@JsonInclude(NON_EMPTY)`：`params` 为空 Map 时不出现在 JSON 里，干净。
5. **`params` 是"数据权限"的载体**：`DataScopeAspect` 把拼好的 `AND (dept_id IN (...))` 放进 `params.dataScope`，Mapper XML 用 `${params.dataScope}` 取出来拼到 SQL（见 [[06-后端-AOP与拦截器]]）。所以 `SysUser` 等实体都 `extends BaseEntity`，自动拥有这个"扩展袋"。

> 配套还有 `TreeEntity`（带 `parentId/ancestors/orderNum` 的树形基类）和 `TreeSelect`（前端树下拉的 VO），用于部门/菜单这种层级数据。

## 四、常量、枚举、异常（知道存在即可）

- **常量** `com.ruoyi.common.constant`：
  - `HttpStatus`：`SUCCESS=200 / ERROR=500 / WARN=601 / FORBIDDEN=403 / UNAUTHORIZED=401`。
  - `CacheConstants`：所有 Redis key 前缀，如 `LOGIN_TOKEN_KEY`（`login_tokens:`）、`CAPTCHA_CODE_KEY`（`captcha_codes:`）、`PWD_ERR_CNT_KEY`（`pwd_err_cnt:`）。
  - `Constants`：`TOKEN_PREFIX=("Bearer ")`、`LOGIN_USER_KEY`、`JWT_USERNAME`、`Dept.DATA_SCOPE_*` 数据权限枚举值。
  - `UserConstants`：`ROLE_NORMAL/ROLE_DISABLE`、`PASSWARD_MIN/MAX_LENGTH`、`USERNAME_MIN/MAX_LENGTH`。
  - `GenConstants`、`ScheduleConstants`：代码生成 / 定时任务的常量。
- **枚举** `com.ruoyi.common.enums`：`BusinessType`（INSERT/UPDATE/DELETE/GRANT/EXPORT/IMPORT/LOGIN… 操作日志类型）、`BusinessStatus`、`UserStatus`（OK/ DISABLE/DELETED）、`HttpMethod`、`LimitType`、`OperatorType`、`DataSourceType`、`DesensitizedType`。
- **异常体系** `com.ruoyi.common.exception`：
  ```
  BaseException(抽象)
   ├─ ServiceException            // 业务异常，带 code/msg，被 GlobalExceptionHandler 接住
   ├─ DemoModeException
   ├─ user/* : UserException → UserNotExistsException / UserPasswordNotMatchException
   │           / UserPasswordRetryLimitExceedException / CaptchaException / BlackListException
   └─ file/* : FileException → FileSizeLimitExceededException / InvalidExtensionException
  ```
  Controller/Service 里 `throw new ServiceException("xxx")`；`@RestControllerAdvice` 统一转成 `AjaxResult.error(code,msg)`（见 [[08-后端-控制层与统一异常]]）。

## 五、XSS 防护（高级第 20 条）

```
com.ruoyi.common.xss
  ├─ Xss            // 注解：标在实体字段上，表示"这个字段要 XSS 过滤"
  ├─ XssValidator  // 校验器：配合 JSR-303，校验值是否含恶意脚本
com.ruoyi.common.filter
  ├─ XssFilter                     // 过滤器：匹配 urlPatterns，对请求做 XSS 清洗
  └─ XssHttpServletRequestWrapper   // 包装原 request，重写 getParameter* 做转义
com.ruoyi.common.utils.html
  ├─ EscapeUtil    // 转义 < > " ' & 等
  └─ HTMLFilter     // 白名单过滤 HTML 标签/属性（防 <script> 注入）
```

**解释：** `application.yml` 里 `xss.enabled: true` + `urlPatterns: /system/*,/monitor/*,/tool/*` 打开后，`XssFilter` 会对这些路径的请求参数做一次 HTML 清洗（用 `HTMLFilter` 白名单），<u>从入口堵住存储型 XSS</u>。注意它和前端 `v-html` 风险是两层防护（前端见 [[19-前端-视图与API分层]]）。
