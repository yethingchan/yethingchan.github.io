# 14 · 前端-路由与权限守卫

> 对应清单：进阶第 14 条（permission.js 守卫）、进阶第 12 条（GenerateRoutes）、高级第 15 条（菜单→动态路由）。
> 这是前端最硬核的一环：**菜单不是前端写死的，而是后端下发的**。本文把"登录后怎么拿到路由、怎么动态加进去"讲透。

## 一、router/index.js —— 两类路由（真实）

```js
Vue.use(Router)
import Layout from '@/layout'

// ① 常量路由：所有人（登录与否）都有的，写死在前端
export const constantRoutes = [
  { path: '/redirect', component: Layout, hidden: true, children: [/* ... */] },
  { path: '/login', component: () => import('@/views/login'), hidden: true },
  { path: '/404', component: () => import('@/views/error/404'), hidden: true },
  { path: '', component: Layout, redirect: 'index', children: [
      { path: 'index', component: () => import('@/views/index'), name: 'Index',
        meta: { title: '首页', icon: 'dashboard', affix: true } }
  ]},
  { path: '/user', component: Layout, hidden: true, children: [
      { path: 'profile', component: () => import('@/views/system/user/profile/index'),
        name: 'Profile', meta: { title: '个人中心' } }
  ]}
]

// ② 动态路由：需要特定权限才加（写在前端，但按权限过滤后才 addRoutes）
export const dynamicRoutes = [
  { path: '/system/user-auth', component: Layout, hidden: true,
    permissions: ['system:user:edit'],          // ③ 要这个权限才加
    children: [{ path: 'role/:userId(\\d+)', component: () => import('@/views/system/user/authRole'),
      name: 'AuthRole', meta: { title: '分配角色', activeMenu: '/system/user' } }] },
  // .../system/role-auth、/system/dict-data、/monitor/job-log、/tool/gen-edit 同理
]

export default new Router({
  mode: 'history',                  // ④ URL 不带 #（Nginx 需配 history 回退）
  scrollBehavior: () => ({ y: 0 }),
  routes: constantRoutes            // ⑤ 初始只装常量路由
})
```

**解释：**
- ① **`constantRoutes`**：登录页、首页、404、个人中心——这些不依赖权限，启动时就有。
- ② **`dynamicRoutes`**：那些"嵌套在菜单下的子页"（分配角色、分配用户、字典数据…），它们的 `permissions: ['system:user:edit']` 是**前端侧的二次过滤条件**。
- ④ **`mode:'history'`**：URL 干净（`/system/user` 而非 `/#/system/user`）。代价：刷新非根路由时浏览器直接请求该路径，Nginx/后端需配置"全部回退到 index.html"，否则 404。
- ⑤ **初始只装常量路由**；动态路由在**登录后由 `GenerateRoutes` 加进来**（见第三节）。

## 二、permission.js —— 路由守卫（真实，根目录）

```js
import router from './router'
import store from './store'
import { getToken } from '@/utils/auth'
import { isRelogin } from '@/utils/request'

const whiteList = ['/login', '/register']
router.beforeEach((to, from, next) => {
  NProgress.start()
  if (getToken()) {                                  // ① 有 token
    to.meta.title && store.dispatch('settings/setTitle', to.meta.title)
    if (to.path === '/login') { next({ path: '/' }); NProgress.done() }
    else if (store.getters.roles.length === 0) {      // ② 还没拉过用户信息
      isRelogin.show = true
      store.dispatch('GetInfo').then(() => {              // ③ 拉用户信息+权限
        isRelogin.show = false
        store.dispatch('GenerateRoutes').then(accessRoutes => {  // ④ 生成动态路由
          router.addRoutes(accessRoutes)               // ⑤ 加进路由表
          next({ ...to, replace: true })                   // ⑥ 重进一次，确保加完
        })
      }).catch(err => {
        store.dispatch('LogOut').then(() => { Message.error(err); next({ path: '/' }) })
      })
    } else { next() }                              // ⑦ 已登录已拉取，直接放行
  } else {                                          // ⑧ 无 token
    if (whiteList.some(p => isPathMatch(p, to.path))) next()
    else next(`/login?redirect=${encodeURIComponent(to.fullPath)}`)  // 跳登录并带 redirect
  }
})
router.afterEach(() => NProgress.done())
```

**逐行解释（这是"登录态下每次跳转"都跑的守门员）：**
1. 有 token 才进里层；否则跳登录（带 `redirect`，登录完跳回原页）。
2. **`roles.length === 0` 是"首次进入"的标志**：刚刷新页面时 Vuex 是空的，需要先拉一次用户信息。
3. **`GetInfo`**（store/user.js，见 [[15-前端-Vuex状态管理]]）：调 `/getInfo` 拿 `user` + `roles` + `permissions`，存入 Vuex。
4. **`GenerateRoutes`**（store/permission.js，见下节）：**后端下发菜单 → 生成路由**。
5. **`router.addRoutes(accessRoutes)`**：把生成的路由**动态加进路由表**——这是 `dynamicRoutes` 之外、更重要的"动态"（因为大多数菜单路由来自后端，不在 `dynamicRoutes` 里）。
6. **`next({ ...to, replace: true })`**：加完路由后"重进一次"目标页，否则第一次会白屏（经典 RuoYi hack）。
7. 已登录且已拉取 → 直接 `next()`，不重复拉。

## 三、store/permission.js —— 菜单 → 路由的"翻译机"（真实）

```js
import { getRouters } from '@/api/menu'
import Layout from '@/layout/index'
import ParentView from '@/components/ParentView'
import InnerLink from '@/layout/components/InnerLink'

GenerateRoutes({ commit }) {
  return new Promise(resolve => {
    getRouters().then(res => {                 // ① 调后端 /system/menu/getRouters
      const sidebarRoutes = filterAsyncRouter(JSON.parse(JSON.stringify(res.data)))
      const rewriteRoutes = filterAsyncRouter(JSON.parse(JSON.stringify(res.data)), false, true)
      const asyncRoutes = filterDynamicRoutes(dynamicRoutes)   // ② 前端 dynamicRoutes 按权限过滤
      rewriteRoutes.push({ path: '*', redirect: '/404', hidden: true })
      router.addRoutes(asyncRoutes)
      commit('SET_ROUTES', rewriteRoutes)
      commit('SET_SIDEBAR_ROUTERS', constantRoutes.concat(sidebarRoutes))
      resolve(rewriteRoutes)
    })
  })
}

// ③ 把后端给的"组件字符串"换成真实组件
function filterAsyncRouter(asyncRouterMap, lastRouter = false, type = false) {
  return asyncRouterMap.filter(route => {
    if (route.component) {
      if (route.component === 'Layout')       route.component = Layout
      else if (route.component === 'ParentView') route.component = ParentView
      else if (route.component === 'InnerLink')  route.component = InnerLink
      else route.component = loadView(route.component)    // "system/user/index" → import
    }
    if (route.children != null && route.children.length)
      route.children = filterAsyncRouter(route.children, route, type)
    else { delete route['children']; delete route['redirect'] }
    return true
  })
}
// ④ 懒加载：开发用 require，生产用 import
export const loadView = (view) => {
  if (process.env.NODE_ENV === 'development')
    return (resolve) => require([`@/views/${view}`], resolve)
  return () => import(`@/views/${view}`)
}
```

**逐行解释（前后端解耦的关键一步）：**
- ① `getRouters()` 调后端 `SysMenuServiceImpl.buildMenus` 的结果（见 [[07-后端-系统业务层]]）——**后端返回的是 `component: "system/user/index"` 这种字符串**。
- ③ `filterAsyncRouter`：**把字符串翻译成组件**。`"Layout"`→`Layout` 组件；`"system/user/index"`→`() => import('@/views/system/user/index')` 懒加载。这样**前端无需为每个菜单写死 import**，后端加菜单前端自动有页面。
- ④ `loadView`：开发环境用 `require`（热更新快），生产用动态 `import`（代码分割）。
- ② `filterDynamicRoutes(dynamicRoutes)`：前端 `dynamicRoutes` 里那些带 `permissions` 的项，按当前用户权限过滤后才 `addRoutes`。

> **闭环总结（高级第 15 条，务必背下）**：
> 后端 `sys_menu` 表 → `SysMenuServiceImpl.buildMenus` 转 `RouterVo(component字符串)` → 前端 `/system/menu/getRouters` → `filterAsyncRouter` 把字符串换成 `import` → `router.addRoutes` → 左侧菜单 + 可访问路由同时出现。**前端永远不写业务菜单，菜单是"数据"**。
