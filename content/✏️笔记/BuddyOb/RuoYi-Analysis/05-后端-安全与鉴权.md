# 05 · 后端-安全与鉴权

> 对应清单：进阶第 1～6 条、高级第 15 条（RBAC 方法级鉴权）。
> 这是整个项目的"锁"。本文所有代码均来自 `ruoyi-framework`。`SecurityConfig` 已在 [[03-后端-配置层]] 讲，本文专注"token 怎么验、登录怎么走、密码怎么守"。

## 一、JWT 过滤器 —— 每个请求的身份核验

```java
@Component
public class JwtAuthenticationTokenFilter extends OncePerRequestFilter {
    @Autowired private TokenService tokenService;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
            throws ServletException, IOException {
        LoginUser loginUser = tokenService.getLoginUser(request);   // ① 从 token 取 LoginUser
        if (StringUtils.isNotNull(loginUser) && StringUtils.isNull(SecurityUtils.getAuthentication())) {
            tokenService.verifyToken(loginUser);                       // ② 快过期就续期
            // ③ 把用户塞进 Spring Security 上下文
            UsernamePasswordAuthenticationToken authenticationToken =
                new UsernamePasswordAuthenticationToken(loginUser, null, loginUser.getAuthorities());
            authenticationToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
            SecurityContextHolder.getContext().setAuthentication(authenticationToken);
        }
        chain.doFilter(request, response);                         // ④ 放行
    }
}
```

**逐行解释：**
1. `getLoginUser(request)`：从请求头 `Authorization: Bearer xxx` 取 token → 解析出 JWT 里的 uuid → 用 `redisCache.getCacheObject("login_tokens:" + uuid)` 取回 `LoginUser`（用户 + 权限）。
2. `verifyToken`：若距过期不足 20 分钟，自动 `refreshToken` 把 Redis 过期时间续到 30 分钟，实现"一直用就一直活"。
3. **关键一步**：把 `LoginUser` 包成 `UsernamePasswordAuthenticationToken` 放进 `SecurityContextHolder`。之后Controller 里 `@PreAuthorize`、Service 里 `SecurityUtils.getLoginUser()` 都靠这个上下文拿到"我是谁"。
4. 无论成功失败都 `chain.doFilter` 放行——**它只负责"认出你是谁"，不负责"准不准进"**（准不准进由 `SecurityConfig` 的 `authorizeHttpRequests` + `@PreAuthorize` 决定）。

> 回忆 [[03-后端-配置层]]：`addFilterBefore(authenticationTokenFilter, UsernamePasswordAuthenticationFilter.class)` 让这个过滤器排在最前，所以每次请求**最先**被它处理。

## 二、TokenService —— token 的签发、解析、续期

```java
@Component
public class TokenService {
    @Value("${token.header}")   private String header;     // "Authorization"
    @Value("${token.secret}")  private String secret;    // JWT 签名密钥
    @Value("${token.expireTime}") private int expireTime;  // 30(分)
    @Autowired private RedisCache redisCache;

    // 创建 token：uuid 当"钥匙"，JWT 只存 uuid + 用户名
    public String createToken(LoginUser loginUser) {
        String token = IdUtils.fastUUID();          // 随机 uuid
        loginUser.setToken(token);
        setUserAgent(loginUser);                    // 记录 IP/浏览器/归属地
        refreshToken(loginUser);                    // 写入 Redis
        Map<String, Object> claims = new HashMap<>();
        claims.put(Constants.LOGIN_USER_KEY, token);          // 把 uuid 放进 JWT
        claims.put(Constants.JWT_USERNAME, loginUser.getUsername());
        return createToken(claims);
    }

    // 真正用 jjwt 0.9.1 旧 API 签名（注意不是 0.12 的 Jwts.SIG.HS256）
    private String createToken(Map<String, Object> claims) {
        return Jwts.builder()
                .setClaims(claims)
                .signWith(SignatureAlgorithm.HS512, secret).compact();
    }

    // 从请求取 LoginUser（JWT 解析 → Redis 取对象）
    public LoginUser getLoginUser(HttpServletRequest request) {
        String token = getToken(request);          // 去 "Bearer " 前缀
        if (StringUtils.isNotEmpty(token)) {
            Claims claims = parseToken(token);
            String uuid = (String) claims.get(Constants.LOGIN_USER_KEY);
            return redisCache.getCacheObject(getTokenKey(uuid));   // "login_tokens:" + uuid
        }
        return null;
    }

    // 距过期 20 分钟内自动续期
    public void verifyToken(LoginUser loginUser) {
        if (loginUser.getExpireTime() - System.currentTimeMillis() <= MILLIS_MINUTE_TWENTY)
            refreshToken(loginUser);
    }

    // 角色权限变更后，刷新所有持有该角色的在线用户
    public void refreshPermissionByRoleId(Long roleId, SysPermissionService permissionService) {
        for (String key : redisCache.keys(CacheConstants.LOGIN_TOKEN_KEY + "*")) {
            LoginUser u = redisCache.getCacheObject(key);
            if (u == null || u.getUser() == null || u.getUser().isAdmin()) continue;
            boolean has = u.getUser().getRoles().stream().anyMatch(r -> roleId.equals(r.getRoleId()));
            if (!has) continue;
            u.setPermissions(permissionService.getMenuPermission(u.getUser()));  // 重算权限
            refreshToken(u);
        }
    }
}
```

**解释（几个反直觉的点）：**
- **JWT 里几乎不存业务数据**，只存一个随机 `uuid`。真正的 `LoginUser`（含菜单权限）存在 **Redis** `login_tokens:<uuid>`。好处：改了用户权限，只需更新 Redis，下次请求自然生效（`refreshPermissionByRoleId` 就是批量刷 Redis）。
- **jjwt 0.9.1 旧 API**：`Jwts.builder().signWith(SignatureAlgorithm.HS512, secret)`。这和我们另一个 Vue3 教程里 jjwt 0.12 的 `Jwts.SIG.HS256.signWith(key)` 写法不同——**别混用**，依赖版本决定写法（见 [[02-后端-工程与启动]] pom）。
- `HS512` 是对称签名：服务端用同一把 `secret` 签和验。**secret 一旦泄露任何人可伪造 token**，所以 `application.yml` 里那串 `abcdefghijklmnopqrstuvwxyz` 生产必须换。
- 前端 `request.js` 里 `config.headers['Authorization'] = 'Bearer ' + getToken()` 的 `Bearer ` 前缀，正是这里 `getToken()` 用 `Constants.TOKEN_PREFIX` 去掉的那段。

## 三、UserDetailsServiceImpl —— Spring Security 的"用户加载器"

```java
@Service
public class UserDetailsServiceImpl implements UserDetailsService {
    @Autowired private ISysUserService userService;
    @Autowired private SysPasswordService passwordService;
    @Autowired private SysPermissionService permissionService;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        SysUser user = userService.selectUserByUserName(username);
        if (user == null) throw new ServiceException(MessageUtils.message("user.not.exists"));
        if (UserStatus.DELETED.getCode().equals(user.getDelFlag())) throw new ServiceException("已被删除");
        if (UserStatus.DISABLE.getCode().equals(user.getStatus()))  throw new ServiceException("已被停用");
        passwordService.validate(user);                       // ① 密码错误次数校验
        return createLoginUser(user);
    }
    public UserDetails createLoginUser(SysUser user) {
        return new LoginUser(user.getUserId(), user.getDeptId(), user,
                permissionService.getMenuPermission(user));   // ② 算出该用户的权限字符串集合
    }
}
```

**解释：**
- 这是 Spring Security 的**标准扩展点**：登录时 `AuthenticationManager.authenticate()` 会回调它，按用户名查出用户、算权限。
- ① `passwordService.validate(user)`：内部从 `AuthenticationContextHolder` 取前端传的明文密码，和库里 BCrypt 密文比对；顺便做"错误次数 Redis 锁"（见第五节）。
- ② `getMenuPermission(user)`：拼出 `Set<String>` 形如 `{"system:user:list","system:user:add",...}`，存进 `LoginUser.permissions`。**这串就是 `@PreAuthorize("@ss.hasPermi('system:user:list')")` 比对的对象**——后端方法级权限的"真相源"。

## 四、SysLoginService —— 一条完整登录链路

```java
@Component
public class SysLoginService {
    @Autowired private TokenService tokenService;
    @Resource  private AuthenticationManager authenticationManager;
    @Autowired private ISysUserService userService;
    @Autowired private ISysConfigService configService;

    public String login(String username, String password, String code, String uuid) {
        validateCaptcha(username, code, uuid);     // ① 验证码
        loginPreCheck(username, password);          // ② 前置校验（长度 + IP 黑名单）
        Authentication authentication = null;
        try {
            // ③ 交给 Spring Security 认证（内部回调 UserDetailsServiceImpl）
            authentication = authenticationManager.authenticate(
                new UsernamePasswordAuthenticationToken(username, password));
        } catch (Exception e) {
            if (e instanceof BadCredentialsException) {
                AsyncManager.me().execute(AsyncFactory.recordLogininfor(username, LOGIN_FAIL, "密码错误"));// ④ 异步记失败日志
                throw new UserPasswordNotMatchException();
            }
            throw new ServiceException(e.getMessage());
        } finally { AuthenticationContextHolder.clearContext(); }
        AsyncManager.me().execute(AsyncFactory.recordLogininfor(username, LOGIN_SUCCESS, "登录成功"));
        LoginUser loginUser = (LoginUser) authentication.getPrincipal();
        recordLoginInfo(loginUser.getUserId());      // ⑤ 写最后登录 IP/时间
        return tokenService.createToken(loginUser);    // ⑥ 发 token
    }

    public void loginPreCheck(String username, String password) {
        if (isEmpty(username) || isEmpty(password)) throw new UserNotExistsException();
        if (password.length() < PASSWORD_MIN_LENGTH || password.length() > PASSWORD_MAX_LENGTH)
            throw new UserPasswordNotMatchException();   // 长度策略
        if (username.length() < USERNAME_MIN_LENGTH || username.length() > USERNAME_MAX_LENGTH)
            throw new UserPasswordNotMatchException();
        String blackStr = configService.selectConfigByKey("sys.login.blackIPList");
        if (IpUtils.isMatchedIp(blackStr, IpUtils.getIpAddr()))
            throw new BlackListException();              // ⑦ IP 黑名单
    }
}
```

**逐段解释：**
- ① `validateCaptcha`：从 Redis `captcha_codes:<uuid>` 取正确验证码比对，错/过期都抛异常。**这步在认证前**，所以机器人爆破要先过验证码。
- ② ⑦ `loginPreCheck`：密码/用户名长度限制 + **IP 黑名单**（`sys_config` 表里的 `sys.login.blackIPList`，支持 `*` 通配）。黑名单在**认证之前**就拦，省资源。
- ③ `authenticationManager.authenticate(...)`：Spring Security 的认证入口，内部走 `UserDetailsServiceImpl` + `SysPasswordService.validate`。
- ④ `AsyncManager.me().execute(...)`：**异步**写登录日志到 `sys_logininfor` 表（用 [[03-后端-配置层]] 的线程池，不阻塞主流程）。
- ⑥ 认证通过拿到 `LoginUser`，`createToken` 发 UUID-token。前端拿到后存 cookie（`utils/auth.js`），后续请求自动带。

## 五、SysPasswordService —— 密码安全三连

```java
@Component
public class SysPasswordService {
    @Value("${user.password.maxRetryCount}") private int maxRetryCount; // 5
    @Value("${user.password.lockTime}")     private int lockTime;       // 10(分)
    @Autowired private RedisCache redisCache;

    public void validate(SysUser user) {
        String username = AuthenticationContextHolder.getContext().getName();
        String password = AuthenticationContextHolder.getContext().getCredentials().toString();
        Integer retryCount = redisCache.getCacheObject(getCacheKey(username)); // "pwd_err_cnt:用户名"
        if (retryCount == null) retryCount = 0;
        if (retryCount >= maxRetryCount)                         // ① 已达上限 → 锁
            throw new UserPasswordRetryLimitExceedException(maxRetryCount, lockTime);
        if (!matches(user, password)) {                          // ② BCrypt 比对
            retryCount++;
            redisCache.setCacheObject(getCacheKey(username), retryCount, lockTime, TimeUnit.MINUTES);
            throw new UserPasswordNotMatchException();
        } else {
            clearLoginRecordCache(username);                     // ③ 成功清零计数
        }
    }
    public boolean matches(SysUser user, String rawPassword) {
        return SecurityUtils.matchesPassword(rawPassword, user.getPassword()); // BCryptPasswordEncoder.matches
    }
}
```

**解释：**
- ① **防暴破**：连续错 5 次（`maxRetryCount`，yml 配），该用户名锁定 10 分钟（`lockTime`）。计数存在 Redis `pwd_err_cnt:<用户名>`，带 10 分钟过期——超时自动解锁。
- ② **BCrypt**：`matches(raw, encoded)` 用 `BCryptPasswordEncoder` 比对。**BCrypt 每次加密同明文得到不同密文**（自带随机盐），所以库里只存密文，比对靠 `matches` 而非相等判断。改密码时也用 `encode()`。
- ③ 登录成功立刻清计数，避免"差一次就锁"的误伤。

## 六、配套的安全件（知道存在即可）

| 类 | 职责 |
|---|---|
| `security/handle/AuthenticationEntryPointImpl` | 未登录/ token 失效访问受保护资源 → 返回 401（`code=401, msg=请登录`）。前端 `request.js` 的 401 弹窗源头 |
| `security/handle/LogoutSuccessHandlerImpl` | `/logout` 成功 → 清 Redis token + 返回成功 |
| `security/context/AuthenticationContextHolder` | 线程级存"本次认证的账号/密码"，供 `SysPasswordService.validate` 取明文比对（避免层层传参） |
| `security/context/PermissionContextHolder` | 线程级存当前权限字符，供 `DataScopeAspect` 用 |
| `web/service/PermissionService` (`@ss`) | 实现 `hasPermi('x:y:z')` / `hasRole` / `hasPermission`。`@PreAuthorize("@ss.hasPermi(...)")` 中的 `@ss` 就是它 |
| `web/service/SysPermissionService` | `getMenuPermission(user)`：把用户菜单权限拼成字符串集合 |

> **RBAC 方法级鉴权闭环**：Controller `@PreAuthorize("@ss.hasPermi('system:user:list')")` → `PermissionService.hasPermi` 比对 `LoginUser.permissions`（来自 `getMenuPermission`）→ 命中才放行。前端 `v-hasPermi="['system:user:list']"` 用**同一串字符**做按钮显隐（见 [[17-前端-权限指令与通用组件]]）。前后端权限字符**必须一一对应**，这是 RuoYi RBAC 的精髓。
