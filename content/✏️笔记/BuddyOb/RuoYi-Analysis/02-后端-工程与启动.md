# 02 · 后端-工程与启动

> 对应清单：入门第 2 条 + 高级第 17 条（test-module 接入）。本文看"工程怎么组织、应用怎么起来、你的模块怎么被带进来"。

## 一、Maven 多模块（pom.xml 根）

```xml
<groupId>com.ruoyi</groupId>
<artifactId>ruoyi</artifactId>
<version>3.9.2</version>
...
<properties>
    <java.version>17</java.version>
    <spring-boot.version>4.0.6</spring-boot.version>
    <mybatis-spring-boot.version>4.0.1</mybatis-spring-boot.version>
    <druid.version>1.2.28</druid.version>
    <jwt.version>0.9.1</jwt.version>
    <fastjson.version>2.0.62</fastjson.version>
    <springdoc.version>3.0.3</springdoc.version>
    <pagehelper.boot.version>4.1.0</pagehelper.boot.version>
</properties>
<modules>
    <module>ruoyi-admin</module>
    <module>ruoyi-framework</module>
    <module>ruoyi-system</module>
    <module>ruoyi-quartz</module>
    <module>ruoyi-generator</module>
    <module>ruoyi-common</module>
    <module>test-module</module>   <!-- 你的扩展模块 -->
</modules>
```

**解释：**
- 这是**聚合工程（aggregator）**：根 `pom` 只做版本管理与模块声明，`packaging=pom`。真正的代码在各子模块。
- 所有Spring 相关版本被**锁死**在 `spring-boot.version=4.0.6`——注意这是 **Spring Boot 4** + **Java 17**，意味着代码用的是 `jakarta.*` 命名空间（不是旧的 `javax.*`）。这是本仓库和你印象里"官方 RuoYi"最大的差异。
- `jwt.version=0.9.1` 很关键：它用的是 **jjwt 旧 API**（`Jwts.builder().setClaims()...`），和我们另一个教程里写的 jjwt 0.12 新 API 写法不同（见 [[05-后端-安全与鉴权]] 的 TokenService）。
- `test-module` 赫然在 `<modules>` 里——**你的私有模块已被纳入统一构建**。

## 二、启动类（RuoYiApplication.java）

```java
@SpringBootApplication(exclude = { DataSourceAutoConfiguration.class })
@ComponentScan(basePackages = {"cn.yething","com.ruoyi"})
@MapperScan("cn.yething.test.mapper")
public class RuoYiApplication {
    public static void main(String[] args) {
        SpringApplication.run(RuoYiApplication.class, args);
        System.out.println("... 若依启动成功 ...");
    }
}
```

**逐行解释（这几行就是你最初那个 `Could not resolve type alias 'Locations'` 报错的根源所在）：**
- `@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)`：<u>关掉 Spring Boot 自带的数据源自动配置</u>，改用 RuoYi 自己的 `DruidConfig` 自定义多数据源（见 [[03-后端-配置层]]）。
- `@ComponentScan({"cn.yething","com.ruoyi"})`：<u>扫描两个包</u>。没有这行，`cn.yething.test` 下的 `LocationsController` 等根本不会被 Spring 识别。
- `@MapperScan("cn.yething.test.mapper")`：<u>只扫你 test-module 的 Mapper</u>。主工程的 Mapper 由 `MyBatisConfig` 里的 `MapperScan`/自动扫描接管。

> 呼应最早的诊断：你新建 `test-module` 后启动报 `Could not resolve type alias 'Locations'`，根因是 MyBatis 的 `typeAliasesPackage` 没覆盖 `cn.yething.**.domain`。现在已经修好——`application.yml` 里写成 `com.ruoyi.**.domain,cn.yething.**.domain`（见 [[03-后端-配置层]] 与 [[11-后端-你的test-module与集成]]）。

## 三、Servlet 初始化器（RuoYiServletInitializer.java）

```java
public class RuoYiServletInitializer extends SpringBootServletInitializer {
    @Override
    protected SpringApplicationBuilder configure(SpringApplicationBuilder application) {
        return application.sources(RuoYiApplication.class);
    }
}
```

**解释：** 这个类只在**打成 `war` 包、丢进外置 Tomcat** 时才生效。它让外置容器知道"我的启动类是 `RuoYiApplication`"。如果你用 `java -jar` 或 `ruoyi-admin` 里的 `spring-boot-maven-plugin` 直接跑，**用不到它**——`main()` 方法就够了。RuoYi 默认是 `jar` 启动，所以这个类多数时候是"备胎"。

## 四、模块依赖关系（为什么 common 在最底层）

- `ruoyi-admin` 的 `pom` 里 `dependency` 引入 `framework` / `system` / `generator` / `quartz` / `common`。
- `framework`、`system` 等又都依赖 `common`。
- `common` **不依赖任何 ruoyi 内部模块**（只依赖第三方库）。

这保证了：`common`（返回对象、工具类、异常）可以被所有人安全复用，不会出现循环依赖。

> 学完本章，你应该清楚：要往这个工程加一个全新业务模块，至少要在 `pom.xml` 的 `<modules>` 注册、写 `@SpringBootApplication` 同级包、并在需要时调整 `@ComponentScan`/`@MapperScan`/`typeAliasesPackage`。这正是你 test-module 已经做对的事。
