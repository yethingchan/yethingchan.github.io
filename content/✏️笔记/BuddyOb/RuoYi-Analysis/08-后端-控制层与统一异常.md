# 08 · 后端-控制层与统一异常

> 对应清单：入门第 6 条（Controller 套路）、进阶第 10 条（GlobalExceptionHandler）、高级第 22 条（监控/上传/验证码）、高级第 23 条（字典/参数）。
> Controller 只做"收参、调 Service、包返回"，不含业务。本文以 `SysUserController` 为标本，再讲统一异常与监控/工具类 Controller。

## 一、BaseController —— 所有 Controller 的父类

```java
public class BaseController {
    protected void startPage() {
        PageDomain pageDomain = TableSupport.buildPageRequest();   // 从 request 取 pageNum/pageSize/orderBy
        Integer pageNum = pageDomain.getPageNum();
        Integer pageSize = pageDomain.getPageSize();
        if (pageNum != null && pageSize != null)
            PageHelper.startPage(pageNum, pageSize, pageDomain.getOrderBy()); // ① 告诉 PageHelper
    }
    @SuppressWarnings({"rawtypes","unchecked"})
    protected TableDataInfo getDataTable(List<?> list) {
        TableDataInfo rspData = new TableDataInfo();
        rspData.setCode(HttpStatus.SUCCESS);
        rspData.setMsg("查询成功");
        rspData.setRows(list);                              // ② 当前页数据
        rspData.setTotal(new PageInfo(list).getTotal());   // ③ 用 PageInfo 取总条数
        return rspData;
    }
}
```

**解释：**
- ① `PageHelper.startPage(pageNum, pageSize)`：PageHelper 会把**紧随其后的第一条 SQL** 自动改写加 `LIMIT`，并统计总数。所以 Controller 里**必须先 `startPage()` 再调 Service 查 list**。
- ② ③ `getDataTable` 把 list 包成 `{code:200, msg, rows:[...], total:N}`——前端 `request.js` 拿到后 `res.rows` 是数据、`res.total` 是总数，喂给 `Pagination` 组件。

## 二、SysUserController —— 标准 Controller 标本（节选）

```java
@RestController
@RequestMapping("/system/user")
public class SysUserController extends BaseController {
    @Autowired private ISysUserService userService;
    @Autowired private ISysRoleService roleService;

    @PreAuthorize("@ss.hasPermi('system:user:list')")   // ① 后端方法级权限
    @GetMapping("/list")
    public TableDataInfo list(SysUser user) {
        startPage();
        List<SysUser> list = userService.selectUserList(user);
        return getDataTable(list);
    }

    @Log(title = "用户管理", businessType = BusinessType.EXPORT)  // ② 操作日志注解
    @PreAuthorize("@ss.hasPermi('system:user:export')")
    @PostMapping("/export")
    public void export(HttpServletResponse response, SysUser user) {
        List<SysUser> list = userService.selectUserList(user);
        ExcelUtil<SysUser> util = new ExcelUtil<>(SysUser.class); // ③ @Excel 驱动导出
        util.exportExcel(response, list, "用户数据");
    }

    @PreAuthorize("@ss.hasPermi('system:user:query')")
    @GetMapping(value = { "/", "/{userId}" })               // ④ 路径变量
    public AjaxResult getInfo(@PathVariable(value = "userId", required = false) Long userId) {
        AjaxResult ajax = AjaxResult.success();
        if (userId != null) {
            userService.checkUserDataScope(userId);          // ⑤ 数据权限二次校验
            ajax.put("data", userService.selectUserById(userId));
        }
        ajax.put("roles", roleService.selectRoleAll());
        return ajax;
    }

    @PreAuthorize("@ss.hasPermi('system:user:add')")
    @Log(title = "用户管理", businessType = BusinessType.INSERT)
    @PostMapping
    public AjaxResult add(@Validated @RequestBody SysUser user) { // ⑥ 校验入参
        if (!userService.checkUserNameUnique(user)) { ... }
        userService.insertUser(user);
        return success();
    }
}
```

**逐行解释（这就是 RuoYi 一个标准 CRUD Controller 的全套套路）：**
1. **`@PreAuthorize("@ss.hasPermi('system:user:list')")`**：方法级 RBAC 鉴权。`@ss` 指向 `PermissionService`（见 [[05-后端-安全与鉴权]]）。字符串 `system:user:list` 与前端 `v-hasPermi` 用的是**同一套编码**——缺一个，按钮或接口就失灵。
2. **`@Log(title=..., businessType=EXPORT)`**：打标后，`LogAspect` 自动在方法成功/失败后写一条 `sys_oper_log`（见 [[06-后端-AOP与拦截器]]）。`title`/`businessType` 来自注解，零侵入。
3. **导出**：`ExcelUtil<SysUser>` + 实体上的 `@Excel(name="用户名称")` 注解，自动把 list 写成 Excel 流给前端下载（见 [[19-前端-视图与API分层]] 的导出按钮）。
4. **`@GetMapping(value={"/","/{userId}"})`**：同一方法既支持 `/system/user`（列表页用）又支持 `/system/user/1`（编辑弹窗用），靠 `required=false` 的 `userId` 区分。
5. **`checkUserDataScope(userId)`**：即便过了 `@PreAuthorize`，仍要确认"这个 userId 在你数据权限范围内"——**双保险**，防止越权改别人的数据。
6. **`@Validated @RequestBody`**：Spring 校验（配合实体上的 `@NotBlank` 等），失败抛 `MethodArgumentNotValidException`，被全局异常接住。

## 四、GlobalExceptionHandler —— 全局异常兜底（进阶第 10 条）

```java
@RestControllerAdvice                                  // ① 专抓 Controller 抛的异常
public class GlobalExceptionHandler {
    @ExceptionHandler(AccessDeniedException.class)   // ② 没权限
    public AjaxResult handleAccessDeniedException(AccessDeniedException e, HttpServletRequest request) {
        return AjaxResult.error(HttpStatus.FORBIDDEN, "没有权限，请联系管理员授权"); // 403
    }
    @ExceptionHandler(ServiceException.class)        // ③ 业务异常（我们主动 throw 的）
    public AjaxResult handleServiceException(ServiceException e, HttpServletRequest request) {
        Integer code = e.getCode();
        return code != null ? AjaxResult.error(code, e.getMessage())
                             : AjaxResult.error(e.getMessage());
    }
    @ExceptionHandler(MethodArgumentNotValidException.class) // ④ @Validated 校验失败
    public AjaxResult handleMethodArgumentNotValid(...) { ... 返回字段错误 ... }
    @ExceptionHandler(HttpRequestMethodNotSupportedException.class) // ④ GET 打到了 POST
    public AjaxResult handleHttpRequestMethodNotSupported(...) { ... }
}
```

**逐行解释：**
- ① `@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody`：统一拦截所有 Controller 抛出的异常，转成 `AjaxResult` JSON，前端 `request.js` 的响应拦截器就能统一弹错。
- ② `AccessDeniedException`：没过 `@PreAuthorize` 时 Spring Security 抛的，这里转成 403 文案。
- ③ `ServiceException`：你在 Service 里 `throw new ServiceException("库存不足")` 这种**业务异常**，被这里接住返回，不会变 500 堆栈。
- ④ 各种参数/方法异常分别处理，给友好文案。

> **异常处理的"三道防线"**：业务里 `throw ServiceException` → `GlobalExceptionHandler` 转 `AjaxResult.error` → 前端 `request.js` 按 `code` 弹 `Message`/`Notification`。这样全工程报错口径一致。

## 五、TableDataInfo / AjaxResult 在前端的对应

- `getDataTable(list)` → `{code:200, rows:[...], total:N}` → 前端 `request.js` 返回 `res.data`，视图里 `this.total = res.total; this.userList = res.rows`。
- `AjaxResult.success(data)` → `{code:200, msg, data}` → 前端 `res.data` 或 `res.msg`。
