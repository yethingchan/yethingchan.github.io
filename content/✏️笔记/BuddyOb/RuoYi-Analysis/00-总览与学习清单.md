## 一、先看清这个项目的"真实身份"

这不是一份标准官方 RuoYi（官方 RuoYi-Vue 仍是 Spring Boot 2.x + Vue 2）。**你这份是已被大幅升级/魔改的 fork**，关键证据（全部来自仓库真实文件）：

| 维度 | 真实版本（本仓库） | 说明 |
|---|---|---|
| 后端核心 | **Spring Boot 4.0.6** | `pom.xml` 中 `<spring-boot.version>4.0.6</spring-boot.version>` |
| JDK | **Java 17** | `<java.version>17</java.version>` |
| 命名空间 | **Jakarta EE**（`jakarta.servlet.*`） | 所有 Filter/HttpServletRequest 都来自 `jakarta`，不是 `javax` |
| 安全框架 | **Spring Security 6 风格** | `SecurityFilterChain` + `@EnableMethodSecurity`（非旧 `WebSecurityConfigurerAdapter`） |
| JWT 库 | **jjwt 0.9.1（旧 API）** | `Jwts.builder().setClaims().signWith(SignatureAlgorithm.HS512, secret)` |
| 持久层 | MyBatis（手写 XML）+ PageHelper | `mybatis.typeAliasesPackage` 含 `cn.yething.**.domain` |
| 前端 | **Vue 2.6.12 + Element UI 2.15** | `package.json`；构建器是 **vue-cli**（`vue.config.js`，非 Vite） |
| 前端路由/状态 | vue-router **3.4.9** / vuex **3.6.0** / axios 0.30.3 | 属 Vue2 生态 |
| 你的扩展 | **test-module（包 `cn.yething.test`）** | 已直接接入主启动类，见 [[11-后端-你的test-module与集成]] |

> ⚠️ **最重要的一个认知**：后端的鉴权 token、菜单、权限字符串、数据范围 SQL 全部存于 **Redis**；前端的路由是**后端下发菜单动态生成**的，不是前端写死的。理解这一点，才理解整个项目。

## 二、整体架构（一张图看懂）

```
┌──────────────────────────────────────────────────────────────────┐
│ 浏览器 / 前端 ruoyi-ui (Vue 2 + Element UI, 端口 80/自定义)      │
│  main.js → router → permission守卫 → element-ui → 组件/视图        │
│  utils/request.js 统一 axios（自动带 Authorization Bearer token）   │
└───────────────┬──────────────────────────────────────────────────┘
                  │  HTTP  /dev-api  →  (vue.config.js 代理到 :8080)
┌─────────────────▼──────────────────────────────────────────────────┐
│ 后端 ruoyi-admin (Spring Boot 4, 端口 8080)                    │
│  ├─ JwtAuthenticationTokenFilter  (每次请求校验 token)            │
│  ├─ SecurityConfig  SecurityFilterChain (CSRF关/Session无态/CORS) │
│  ├─ Controller  (@PreAuthorize("@ss.hasPermi('x:y:z')"))         │
│  ├─ Service  → Mapper(手写XML) → MySQL                          │
│  ├─ AOP: DataScopeAspect(数据权限) / LogAspect(操作日志)         │
│  └─ Redis (token/权限/缓存/限流/防暴破计数)                     │
└─────────────────┬──────────────────────────────────────────────────┘
                  │
            MySQL 8 + Redis 7 + Druid连接池 + Quartz + 代码生成器
```

**一次请求的生命周期（记住这条线，后面每章都在讲它的一部分）：**
1. 前端 `request.js` 拦截器给请求头加 `Authorization: Bearer <token>`；
2. 后端 `JwtAuthenticationTokenFilter` 解析 token → 从 Redis 取 `LoginUser` → 写入 `SecurityContext`；
3. `SecurityConfig` 的 `SecurityFilterChain` 决定该 URL 是否需要鉴权（白名单 `permitAll`）；
4. 命中 `@PreAuthorize("@ss.hasPermi(...)")` → 交给 `PermissionService` 校验权限字符串；
5. `DataScopeAspect` 在 Service 执行前，把"数据权限 SQL 片段"塞进 `BaseEntity.params.dataScope`；
6. Mapper XML 用 `${params.dataScope}` 拼接到 `WHERE` 后，查 MySQL；
7. 结果经 `AjaxResult`/`R<T>` 统一包装返回；`@Log` 切面异步写操作日志到 MySQL。

## 三、后端模块职责（6 个 Maven 模块 + 你的 test-module）

| 模块 | 包名 | 职责 | 代表文件 |
|---|---|---|---|
| **ruoyi-admin** | `com.ruoyi.web` | 启动类 + 所有 Controller + Swagger 配置 | `RuoYiApplication`、`SysUserController`、`SwaggerConfig` |
| **ruoyi-framework** | `com.ruoyi.framework` | 框架核心：安全/配置/AOP/拦截器/Manager | `SecurityConfig`、`TokenService`、`DataScopeAspect` |
| **ruoyi-system** | `com.ruoyi.system` | 业务实体/ Mapper / Service（用户/角色/菜单/部门/字典/日志） | `SysUserServiceImpl`、`SysMenuServiceImpl` |
| **ruoyi-common** | `com.ruoyi.common` | 通用：返回对象/工具/注解/异常/常量/枚举/XSS | `AjaxResult`、`RedisCache`、`StringUtils` |
| **ruoyi-generator** | `com.ruoyi.generator` | 代码生成器（读 information_schema + Velocity） | `GenTableServiceImpl`、`VelocityUtils` |
| **ruoyi-quartz** | `com.ruoyi.quartz` | 定时任务（Quartz 调度） | `ScheduleUtils`、`JobInvokeUtil` |
| **test-module**（你的） | `cn.yething.test` | 你自己的业务（Locations 物料/库位） | `LocationsController`、`LocationsMapper` |

依赖方向：`admin` → `framework`/`system`/`generator`/`quartz` → `common`。`common` 谁都不依赖（最底层）。
