# 07 · 后端-系统业务层（ruoyi-system）

> 对应清单：入门第 5～6 条、进阶第 13 条（SysMenuServiceImpl 菜单树）、高级第 15 条（RBAC 实体）、高级第 23 条（字典）。
> 业务层 = `domain`(实体) + `mapper`(接口) + `service`(接口+impl)。本文讲实体关系、Service 套路，并以**菜单树**为重点（它是前端动态路由的数据源）。

## 一、RBAC 五元组实体（高级第 15 条）

```
sys_user ──< sys_user_role >── sys_role ──< sys_role_menu >── sys_menu
   │                                              │
   └──< sys_user_post >── sys_post            └──< sys_role_dept >── sys_dept
```
- **用户 / 角色 / 菜单 / 部门 / 岗位** 五张主表，靠 3 张关系表（`sys_user_role`/`sys_user_post`/`sys_role_menu`）+ `sys_role_dept` 连起来。
- 这些实体都在 `com.ruoyi.common.core.domain.entity`（注意**不在 ruoyi-system 里**——因为 `common` 是最底层，前端 DTO 也复用这些类）。你在 [[02-后端-工程与启动]] 看到 `typeAliasesPackage` 扫的就是 `com.ruoyi.**.domain`。
- `SysUser extends BaseEntity`：`BaseEntity` 提供 `createBy/createTime/params`（见 [[04-后端-通用核心层]]）。额外有 `roles`(List<SysRole>)、`dept`、`postIds` 等关联属性（非表字段，靠额外 SQL 填）。

## 二、Mapper —— 只有接口，XML 在 resources

```java
public interface SysUserMapper {
    List<SysUser> selectUserList(SysUser user);
    SysUser selectUserByUserName(String userName);
    int insertUser(SysUser user);
    int updateUser(SysUser user);
    int deleteUserById(Long userId);
}
```
- 接口在 `com.ruoyi.system.mapper`；**实现由 MyBatis 运行时生成**，SQL 写在 `resources/mapper/system/SysUserMapper.xml`（由 `mapperLocations=classpath*:mapper/**/*Mapper.xml` 加载，见 [[03-后端-配置层]]）。
- `SysUser` 作入参：MyBatis 会把 `userName!=null` 的字段当成查询条件（配合 XML 里 `<if test="userName != null">`）。

## 三、Service 接口 + Impl —— 业务逻辑的家

```java
// 接口（定义契约）
public interface ISysUserService {
    List<SysUser> selectUserList(SysUser user);
    SysUser selectUserByUserName(String userName);
    int insertUser(SysUser user);
    boolean checkUserNameUnique(SysUser user);
}
// 实现（@Service 交给 Spring）
@Service
public class SysUserServiceImpl implements ISysUserService {
    @Autowired private SysUserMapper userMapper;
    @Autowired private ISysRoleService roleService;   // 跨 service 注入
    public List<SysUser> selectUserList(SysUser user) {
        return userMapper.selectUserList(user);          // 委托 Mapper
    }
    @Transactional                                   // ① 多表操作加事务
    public int insertUser(SysUser user) {
        userMapper.insertUser(user);
        // ② 顺便写关系表
        insertUserRole(user);
        return 1;
    }
}
```
- ① `@Transactional`：插入用户 + 插入用户角色关系，要么全成要么全回滚。
- ② Service 之间互相 `@Autowired` 另一个 Service 接口（如用户服务调角色服务），**永远注入接口不是 impl**。

## 四、★ SysMenuServiceImpl —— 菜单树 → 前端路由的数据源（进阶第 13 条 / 高级第 15 条）

前端左侧菜单、动态路由，数据全来自这里。两个核心方法：

```java
// ① 取出"当前用户能看的菜单树"
@Override
public List<SysMenu> selectMenuTreeByUserId(Long userId) {
    List<SysMenu> menus;
    if (SecurityUtils.isAdmin(userId))
        menus = menuMapper.selectMenuTreeAll();        // 管理员：全部
    else
        menus = menuMapper.selectMenuTreeByUserId(userId); // 普通用户：按角色关联的菜单
    return getChildPerms(menus, MENU_ROOT_ID);    // ② 递归组装成树
}

// ③ 把菜单树转成前端 RouterVo（组件字符串 + meta）
@Override
public List<RouterVo> buildMenus(List<SysMenu> menus) {
    List<RouterVo> routers = new LinkedList<>();
    for (SysMenu menu : menus) {
        RouterVo router = new RouterVo();
        router.setHidden("1".equals(menu.getVisible()));   // 是否隐藏
        router.setName(getRouteName(menu));
        router.setPath(getRouterPath(menu));
        router.setComponent(getComponent(menu));            // ④ "system/user/index" 这类字符串
        router.setMeta(new MetaVo(menu.getMenuName(), menu.getIcon(),
                "1".equals(menu.getIsCache()), menu.getPath()));
        List<SysMenu> cMenus = menu.getChildren();
        if (cMenus != null && UserConstants.TYPE_DIR.equals(menu.getMenuType())) {
            router.setAlwaysShow(true);
            router.setRedirect("noRedirect");
            router.setChildren(buildMenus(cMenus));        // ⑤ 递归子菜单
        }
        routers.add(router);
    }
    return routers;
}
```

**逐行解释（理解它，就理解了"菜单怎么变路由"）：**
- ② `getChildPerms(menus, 0)`：用 `parentId` 把扁平菜单列表递归拼成树（`children` 字段），和前端的 `handleTree` 是镜像操作。
- ③ `buildMenus`：把 `SysMenu` 转成 `RouterVo`（`com.ruoyi.system.domain.vo`）。`RouterVo` 字段：`hidden/name/path/component/query/meta/alwaysShow/redirect/children`，**和前端 vue-router 的 route 配置项几乎一模一样**。
- ④ `getComponent(menu)` 返回**字符串**如 `"system/user/index"`、`"Layout"`、`"ParentView"`、`"InnerLink"`——注意是字符串，不是组件对象！前端 `filterAsyncRouter` 再把它换成真实 import（见 [[14-前端-路由与权限守卫]]）。这就是"前后端解耦"的关键：后端只给路径串。
- ⑤ 递归 `buildMenus(cMenus)`：目录（TYPE_DIR）套子路由。
- `MetaVo` 字段：`title/icon/noCache/link`——对应前端 `meta: { title, icon, noCache }`。

> **整条链路预告**：`/system/menu/getRouters`(Controller) → `SysMenuServiceImpl.selectMenuTreeByUserId + buildMenus` → 前端 `permission.js` 的 `GenerateRoutes` 把 `component` 字符串换成 `() => import('@/views/system/user/index')` → `router.addRoutes`。这就是 RuoYi "菜单即路由" 的实现。

## 五、其它 Service 一览（知道干什么）

| Service | 关键职责 | 笔记 |
|---|---|---|
| `SysUserServiceImpl` | 用户增删改查、导入导出、分配角色、改密码 | `checkUserNameUnique` 防重名 |
| `SysRoleServiceImpl` | 角色 CRUD、角色绑菜单/部门（`sys_role_menu`/`sys_role_dept`） | 改角色后调 `TokenService.refreshPermissionByRoleId` 刷新在线用户（见 [[05-后端-安全与鉴权]]） |
| `SysDeptServiceImpl` | 部门树、祖级列表 `ancestors`（用于数据权限的 `find_in_set`） | `ancestors` 是逗号拼接的祖先链 |
| `SysPostServiceImpl` | 岗位 CRUD | 简单 |
| `SysMenuServiceImpl` | 菜单树 + `buildMenus` 路由 | 见上 |
| `SysDictTypeServiceImpl` / `SysDictDataServiceImpl` | 字典类型 + 字典数据 | 前端下拉的数据源（高级第 23 条） |
| `SysConfigServiceImpl` | 参数配置（`sys_config` 表，KV 缓存到 Redis） | `selectConfigByKey("sys.login.blackIPList")` 就是这里 |
| `SysNoticeServiceImpl` / `SysLogininforServiceImpl` / `SysOperLogServiceImpl` | 通知公告 / 登录日志 / 操作日志 | 被 AOP 与 Controller 写 |
| `SysUserOnlineServiceImpl` | 在线用户（扫 Redis `login_tokens:*`） | 监控页用 |
