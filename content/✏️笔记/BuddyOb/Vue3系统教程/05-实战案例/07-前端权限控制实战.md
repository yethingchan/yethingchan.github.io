# 07 · 前端权限控制实战

前端权限有**两层**：菜单可见性（动态路由）+ 按钮可见性（`v-hasPermi`）。

## 第一层：菜单可见性（动态路由）

- 后端按角色返回菜单树 → 前端 `getRouters` → `addRoute`。
- 没权限的菜单根本不会出现在侧边栏，也打不开对应路由。
- 这是"看不看得到"的控制。

## 第二层：按钮可见性（v-hasPermi）

- 即使菜单可见，页面内的"新增/删除"按钮按 `permissions` 控制显隐。
- 无权限直接移除 DOM 节点。

```vue
<el-button v-hasPermi="'system:user:add'">新增</el-button>
```

## 权限串来源链

```
sys_menu.perms (数据库)
  → 登录时后端汇总进 permissions
  → getInfo 返回前端
  → userStore.permissions
  → v-hasPermi 读取判断
  ↘ 后端 @PreAuthorize 也校验（真防线）
```

## 常见故障排查

| 现象 | 原因 |
|------|------|
| 全站按钮不显示 | `/getInfo` 没返回 `permissions` |
| 某按钮不显示 | 数据库该 `perms` 没配 / 角色未授权 |
| 按钮显示但点击 403 | 后端 `@PreAuthorize` 权限串与库不一致 |
| 菜单看不到 | 角色未授权该菜单 / `component` 路径错 |

## 安全提醒

> 前端权限只是"体验层"。**真正的安全靠后端 `@PreAuthorize`**。任何人都能用 Postman 直接调接口，后端必须校验，否则前端隐藏按钮形同虚设。

## 小结

前端权限两层：动态路由控制菜单、v-hasPermi 控制按钮。最终防线永远是后端注解。
