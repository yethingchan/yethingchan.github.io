# 03 · 角色权限模块解析

角色是"权限的集合"，是用户与权限之间的桥梁。

## 关系模型

```
用户 ──(多对多)──> 角色 ──(多对多)──> 菜单/权限
        sys_user_role      sys_role_menu
```

- 一个用户可有多个角色；一个角色可有多个权限（菜单）。
- 登录时：用户 → 角色 → 汇总所有菜单的 `perms` → 返回 `permissions` 给前端。

## 后端关键接口

| 接口 | 说明 |
|------|------|
| `GET /system/role/list` | 角色列表 |
| `POST /system/role` | 新增角色（同时写角色-菜单关联） |
| `GET /system/menu/role/{roleId}` | 该角色已分配的菜单 ID 树（用于回显） |

## 数据权限（进阶）

RuoYi 体系里角色还带"数据权限"（全部/自定义部门/仅本人）。本项目若未实现可忽略；实现时在 SQL 里加 `dept_id` 过滤。

## 前端要点

- 角色管理页：树形勾选菜单（`el-tree`），保存时把勾选的菜单 ID 发给后端。
- 角色决定了用户登录后能看到哪些菜单、哪些按钮。

## 为什么改角色要重登

用户 `permissions` / `menus` 是登录时拉取的，存在 Pinia 和路由里。改了角色权限后，需**重新登录**或刷新页面（`getInfo`+`getRouters` 重拉）才生效。

## 小结

角色 = 权限集合，桥接用户与菜单。改角色后需重登生效。菜单勾选在角色管理页完成。
