# 13 · 错误码与异常处理

## 约定错误码

| code | 含义 | 前端行为 |
|------|------|----------|
| 200 | 成功 | 返回数据 |
| 401 | 未登录/过期 | 清 token，跳登录 |
| 403 | 无权限 | 弹错（按钮已被 v-hasPermi 隐藏，多为直接调接口） |
| 500 | 服务器错误 | 弹错 |

> 本项目用业务 `code`，HTTP 状态码通常恒 200。

## 后端统一异常

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(Exception.class)
    public AjaxResult handle(Exception e) {
        return AjaxResult.error(500, e.getMessage());
    }
    @ExceptionHandler(BusinessException.class)
    public AjaxResult handleBiz(BusinessException e) {
        return AjaxResult.error(e.getCode(), e.getMessage());
    }
}
```

- 所有未捕获异常都包成 `AjaxResult`，不会返回非 JSON 或 500 裸页面。
- 业务异常用自定义 `BusinessException`（带 code/msg）。

## 校验失败

```java
@NotBlank(message = "用户名不能为空")
private String userName;
// 触发 MethodArgumentNotValidException → 返回 code=500 + msg
```

## 前端如何感知

响应拦截器统一：非 200 弹 `res.msg`，401/403 跳登录。业务代码一般 `try/catch` 即可：

```js
try {
  await addUser(form)
  ElMessage.success('新增成功')
  getList()
} catch (e) {
  // e.message 已是后端 msg，拦截器已弹过，这里可不做
}
```

## 小结

后端用 `@RestControllerAdvice` 把异常包成 `AjaxResult`；前端按 `code` 统一处理。自定义 `BusinessException` 带业务 code/msg。
