# 06 · 请求拦截器与响应拦截器

`request.js` 用 axios 拦截器做"全局前置/后置处理"。

## 请求拦截器（发请求前）

```js
service.interceptors.request.use(config => {
  const token = getToken()
  if (token) config.headers['Authorization'] = 'Bearer ' + token
  return config
})
```

职责：
- 自动带 token（业务代码无需每个请求手动加）。
- 可统一加 `Content-Type`、语言头、请求 ID 等。

## 响应拦截器（收响应后）

```js
service.interceptors.response.use(
  response => {
    const res = response.data
    if (res.code === 200) return res            // 成功：返回 res 给业务
    ElMessage.error(res.msg || '操作失败')       // 失败：弹错
    if (res.code === 401 || res.code === 403) {  // 未登录/无权限
      removeToken()
      if (location.pathname !== '/login') location.href = '/login'
    }
    return Promise.reject(new Error(res.msg))
  },
  error => {                                     // 网络错误/HTTP 5xx
    ElMessage.error(error.message || '网络异常')
    return Promise.reject(error)
  }
)
```

## 拦截器带来的便利

- 业务代码零关心 token、401 跳转——全在拦截器。
- `return res` 让业务直接 `res.data` 取数。
- 统一错误提示，避免到处写 `ElMessage`。

## ⚠️ 注意点

- 返回的是**整个 `res`**（含 code/msg/data），业务取 `res.data`。
- 401/403 用 `window.location.href` 硬刷新跳转（非 `router.push`），会整页刷新——功能正常但可优化为 `router.push`。
- 若某接口需要"非 200 也当成功处理"（如验证码错误但 HTTP 200），业务侧需自行判断 `res.code`。

## 小结

拦截器 = 请求前置加 token、响应后置判 `code` 并统一报错/跳登录。业务代码因此极简。
