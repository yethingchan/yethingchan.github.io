# 25 · 前端开发调试技巧

## 1. 开发服务器热更新

```bash
npm run dev     # 改代码自动刷新，端口 3000
```

## 2. 浏览器开发者工具

- **Network**：看每个 `/api` 请求的状态码、请求头（Authorization）、响应体（code/msg/data）。
- **Console**：看报错、`console.log` 输出。
- **Vue DevTools**：装浏览器插件，看组件树、Pinia 状态、路由。

## 3. 断点调试

在 VS Code 里给 `.vue` 的 `<script setup>` 打断点，或用浏览器 Sources 面板。

## 4. 常见排查清单

| 现象 | 可能原因 |
|------|----------|
| 请求 404 | Vite 代理没配 `/api`，或后端路由带了 `/api` 前缀 |
| 一直跳登录页 | `/getInfo` 返回 401，或 `permissions` 字段缺失 |
| 菜单不显示 | `/getRouters` 没返回，或 `meta.title/icon` 缺失 |
| 表格无数据 | 取了 `res.rows` 而非 `res.data.rows` |
| 按钮不显示 | `v-hasPermi` 权限串与后端 `perms` 不一致 |
| 刷新子路由 404 | 生产 Nginx 没配 `try_files` |

## 5. 临时改后端地址

开发态改 `vite.config.js` 的 `proxy.target`；生产改 Nginx 或加 `.env.production`。

## 6. Mock 数据（联调前）

后端没好时，可在 `request.js` 临时返回假数据，或用 Vite 的 `mock` 插件。详见 03 分册 14 篇。

## 7. 构建后本地预览

```bash
npm run build
npm run preview    # 端口 4173，验证 dist 是否正常
```

## 小结

调试三板斧：Network 看请求、Vue DevTools 看状态、对照"常见排查清单"定位。
