# 23 · 环境变量与多环境配置

## 本项目的现状（重要）

**本项目目前没有 `.env` 文件**，`baseURL` 硬编码在 `src/utils/request.js` 的 `/api`。这对多环境（开发/测试/生产）不够灵活。

## 标准做法（推荐改造）

Vite 支持 `.env` 文件，以 `VITE_` 开头的变量会注入 `import.meta.env`：

```
.env                # 所有环境共有
.env.development    # npm run dev 时
.env.production     # npm run build 时
```

`.env.production` 示例：

```
VITE_APP_BASE_API = 'http://192.168.1.100:8080'
```

改造 `request.js`：

```js
const service = axios.create({
  baseURL: import.meta.env.VITE_APP_BASE_API || '/api',
  timeout: 10000
})
```

这样：
- 开发：`.env.development` 不设 → 走 `/api` + Vite 代理。
- 生产：`.env.production` 设真实地址 → 直连后端（或继续用 `/api` 让 Nginx 反代）。

## 当前生产部署怎么配

既然没有 `.env`，生产部署靠 **Nginx 反代 `/api`**（不改前端代码）：

```nginx
location /api/ {
    proxy_pass http://后端IP:8080/;
}
```

前端代码零改动，最省事。

## 要不要改造？

- 简单部署：保持现状 + Nginx 反代，最省心。
- 多后端/多域名：建议加 `.env.production` + 改造 `request.js`。

## 小结

本项目暂无 `.env`，`baseURL` 硬编码 `/api`；生产靠 Nginx 反代。需要多环境时加 `.env` 并改用 `import.meta.env.VITE_APP_BASE_API`。
