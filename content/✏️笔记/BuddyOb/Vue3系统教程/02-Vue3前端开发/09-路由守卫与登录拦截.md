# 09 · 路由守卫与登录拦截

路由守卫（`beforeEach`）在"跳转前"做拦截——本项目用它实现**登录校验 + 动态路由挂载**。

## 守卫逻辑（src/router/index.js）

```js
router.beforeEach(async (to, from, next) => {
  const token = getToken()
  // 1. 没 token → 去登录页（除非本来就在登录页）
  if (!token) {
    if (to.path === '/login') next()
    else next('/login')
    return
  }
  // 2. 有 token 却访问登录页 → 直接进首页
  if (to.path === '/login') { next('/'); return }

  const userStore = useUserStore()
  // 3. 已登录但还没拉用户信息 → 拉取并挂载动态路由
  if (!userStore.roles || userStore.roles.length === 0) {
    try {
      await userStore.getInfo()          // 拿 roles / permissions / userInfo
      const rawRouters = await userStore.getRouters()  // 拿菜单树
      const asyncRoutes = generateRoutes(rawRouters)
      userStore.setMenus(asyncRoutes)
      asyncRoutes.forEach((r) => router.addRoute(r))
      next({ ...to, replace: true })     // 4. 重新进入目标，确保动态路由生效
    } catch (e) {
      await userStore.logout()
      next('/login')
    }
  } else {
    next()
  }
})
```

## 关键点

### `next({ ...to, replace: true })`
动态路由是**异步挂载**的。第一次进入目标路由时，路由还没加完，`next()` 会找不到页面。所以要 `next({ ...to, replace: true })` 让路由"重走一遍"，此时路由已就绪。

### token 从哪来
`getToken()` 读 `localStorage['admin_token']`（见 `utils/auth.js`）。刷新页面不丢登录态。

### 拉取失败
`getInfo` / `getRouters` 报错 → `logout()` 清态 → 回登录页。

## 本项目与 RuoYi 官方差异

- 本项目守卫逻辑**直接写在 `router/index.js`**，没有独立的 `src/permission.js`。
- 按钮级权限判断在 `src/utils/permission.js` 的 `hasPermi`（见 18 篇），不是路由守卫。

## 小结

路由守卫 = 登录拦截 + 动态路由挂载。无 token 跳登录；有 token 首次进拉信息、挂路由、重进目标。
