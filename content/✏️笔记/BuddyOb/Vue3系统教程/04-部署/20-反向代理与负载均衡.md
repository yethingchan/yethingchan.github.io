# 20 · 反向代理与负载均衡

## 反向代理（已用）

Nginx 把外部请求转发给内部后端，外部不知道后端真实地址/端口。本项目 `/api/` → `127.0.0.1:8080` 就是反向代理。

好处：隐藏后端、统一入口、可做 SSL 终结、限流。

## 负载均衡（多后端实例）

当单机扛不住，起多个后端 jar（不同端口或不同机），Nginx 用 `upstream` 分发：

```nginx
upstream backend_cluster {
    # ip_hash;        # 按 IP 粘会话（有状态时需要）
    server 127.0.0.1:8080 weight=1;
    server 127.0.0.1:8081 weight=1;
    # server 10.0.0.2:8080;   # 其它机器
}

server {
    location /api/ {
        proxy_pass http://backend_cluster/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

- `weight`：权重，分配流量比例。
- `ip_hash`：同一 IP 总到同一后端（解决会话粘连；本项目 JWT 无状态，一般不需要）。
- `least_conn`：谁闲给谁。

## 健康检查

```nginx
upstream backend_cluster {
    server 127.0.0.1:8080 max_fails=3 fail_timeout=30s;
    server 127.0.0.1:8081 max_fails=3 fail_timeout=30s;
}
```

某后端连续 3 次失败，30 秒内不再转发。

## 本项目是否要用

- 学习/小团队：单实例 8080 足够，不需要负载均衡。
- 高并发/高可用：多实例 + upstream。

## 小结

反向代理隐藏后端；负载均衡用 `upstream` 把流量分给多个后端。小项目单实例即可。
