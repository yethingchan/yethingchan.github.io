# 21 · 部署排错与日志查看

## 排错决策树

```
白屏（无界面）
  ├─ 检查 Nginx 是否起：systemctl status nginx
  ├─ 检查 root 路径对不对、dist 是否拷全
  └─ 看 error.log：sudo tail /var/log/nginx/error.log

刷新子路由 404
  └─ Nginx 漏 try_files → 补 try_files $uri $uri/ /index.html

登录页在，但登录失败 / 一直转圈
  ├─ 后端 8080 起来没：curl http://localhost:8080/captcha
  ├─ /api 反代对不对：nginx -t + 看反代配置
  └─ 后端连 MySQL 没：看后端日志（连接拒绝/库不存在）

后端起不来
  ├─ MySQL 没起 / 库没建 / 没 source SQL
  ├─ application.yml 账号密码错
  └─ 端口被占：lsof -i:8080

接口 404
  ├─ proxy_pass 末尾漏 / → 转发成 /api/xxx
  └─ 后端路由本身不带 /api（确认）
```

## 各层日志位置

| 层 | 日志 |
|----|------|
| Nginx | `/var/log/nginx/error.log`、`access.log` |
| 后端（systemd） | `journalctl -u admin-backend -f` |
| 后端（前台） | 控制台输出 |
| 后端（文件） | `application.yml` 配的 `logging.file.name` |
| MySQL | `/var/log/mysql/error.log` |

## 常用命令

```bash
# Nginx
sudo nginx -t
sudo systemctl reload nginx
sudo tail -f /var/log/nginx/error.log

# 后端
sudo systemctl status admin-backend
sudo journalctl -u admin-backend -f

# 端口
sudo ss -tlnp | grep -E ':80|:443|:8080'

# 进程
ps aux | grep java
```

## 前端构建类错误

- `out of memory`：Node 内存不足，`NODE_OPTIONS=--max-old-space-size=4096 npm run build`。
- 白屏但无报错：多半 `dist` 没传全或 `index.html` 路径引用错（base 问题）。

## 小结

排错按"前端白屏→Nginx→反代→后端→MySQL"逐层定位；日志是钥匙：`nginx -t`、`journalctl`、error.log。
