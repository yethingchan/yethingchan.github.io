# 22 · 持续集成与自动化部署

把"构建→部署"自动化，提交代码即自动打包上线，减少手工出错。

## 方案：GitHub Actions（示例）

`.github/workflows/deploy.yml`（放在仓库根）：

```yaml
name: build-and-deploy
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      - run: cd frontend && npm install && npm run build
      - uses: actions/setup-java@v4
        with: { java-version: '17', distribution: 'temurin' }
      - run: cd backend && mvn clean package -DskipTests
      # 上传产物
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: frontend/dist
      - uses: actions/upload-artifact@v4
        with:
          name: jar
          path: backend/target/*.jar
```

## 自动部署到服务器（scp + ssh）

在同一 workflow 增加 deploy 步骤（用 `appleboy/ssh-action` 或 `scp-action`）：

```yaml
  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: appleboy/scp-action@master
        with:
          host: ${{ secrets.HOST }}
          username: ${{ secrets.USER }}
          key: ${{ secrets.KEY }}
          source: "frontend/dist/*,backend/target/*.jar"
          target: "/opt/admin"
      - uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.HOST }}
          username: ${{ secrets.USER }}
          key: ${{ secrets.KEY }}
          script: |
            sudo systemctl restart admin-backend
            sudo systemctl reload nginx
```

> 凭据放仓库 Secrets（`HOST`/`USER`/`KEY`），不写死在文件里。

## 更轻量：服务器拉代码自构建

```bash
# 服务器上放一个 deploy.sh
git pull
cd frontend && npm install && npm run build && cp -r dist/* /opt/admin/frontend/
cd ../backend && mvn clean package -DskipTests && cp target/*.jar /opt/admin/backend/
sudo systemctl restart admin-backend
```

配合 crontab 或手动 `./deploy.sh`。

## 本项目当前状态

仓库**没有** `.github/workflows`，CI/CD 需自行补充。上面模板可直接用。

## 小结

CI/CD = 提交即自动构建+部署。GitHub Actions 跑构建，scp/ssh 推到服务器并重启服务。凭据走 Secrets。
