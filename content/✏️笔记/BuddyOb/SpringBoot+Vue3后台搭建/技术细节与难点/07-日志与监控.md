# 07 日志与监控 · 技术细节与难点

> 配套原教程：[[../07-日志与监控/00-索引]]（操作/登录日志 / 监控与缓存备份）
> 本篇讲**AOP 记日志怎么不吞异常、参数怎么脱敏、切面与事务谁先谁后、监控数据怎么实时**。

## 一、技术细节

### 7.1 操作日志 AOP
- 自定义 `@Log(title, businessType)` 注解 + 切面（环绕/后置）。
- 记录：方法名、入参、耗时、操作人（`SecurityUtils.getUsername()` 从 `SecurityContext` 取）、IP、结果。
- **`try/proceed/finally`**：先让业务跑，成功失败都进 `finally` 留痕，但异常**继续上抛**（不能因记日志把异常吞了）。
- 没加 `@Log` 的接口不记——精准控制哪些操作要审计（呼应 [[技术细节与难点/10-安全防护]] 的"不可删日志"）。

### 7.2 登录日志
登录成功/失败都记 `sys_login_log`（含 IP/UA/设备/状态）。失败计数 → 暴破预警。

### 7.3 监控
用 **OSHI** 库读 CPU/内存/JVM/磁盘/网卡。实时数据前端**定时拉**（5s）或 WebSocket 推。Redis `INFO` 读缓存命中率/内存。  

### 7.4 缓存与备份
Redis 信息面板；数据库备份用 `mysqldump` 脚本/命令。

## 二、技术难点

1. **切面与事务顺序（最易错）**：`@Log` 切面若 `@Order` 排得比 `@Transactional` **高（更外层）**，可能记到"事务还没提交/已回滚"的中间态。本项目的做法——日志保存用 **`@Async` + `REQUIRES_NEW` 独立事务**，主事务回滚不影响日志落库。
2. **参数敏感脱敏**：密码、身份证、token 不能原样进 `sys_oper_log.oper_param`。切面里对特定参数（或 `@Sensitive` 注解字段）**脱敏成 `***`** 再序列化；超长（>2000 字符，`VARCHAR(2000)`）要 `substring`。
3. **同步写日志拖慢主流程**：每个接口都同步 `INSERT` 日志 → 高并发下 RT 涨。解法：**`@Async` 异步写**（本项目的 `save` 就是 `@Async` + `REQUIRES_NEW`）。
4. **监控实时性**：OSHI 每次拉全量指标有开销。前端**定时（如 5s）拉 + 后端缓存最近一次值**，不要每次实时算。
5. **暴破预警**：定时查 `sys_login_log WHERE status=1 AND user_name=? AND login_time > 5分钟前`，>5 次 → 锁账号（联动 [[技术细节与难点/10-安全防护]] 的防暴破）。
6. **异常不能吞**：`@Log` 的 `finally` 里记完日志后，**异常必须 `throw` 出去**，否则调用方以为成功了。

## 三、本项目的解法

| 难点 | 本项目做法 |
|------|--------------|
| 切面 vs 事务 | 日志 `save` 用 `@Async` + `REQUIRES_NEW` 独立事务，主事务回滚不影响 |
| 参数脱敏 | 切面里敏感字段 `***` 化 + 超长 `substring(2000)` |
| 拖慢主流程 | `@Async` 异步写，启动类加 `@EnableAsync` |
| 监控实时 | 前端 5s 定时拉 + 后端缓存最近值 |
| 暴破 | 登录失败计数预警 → 锁账号/IP |
| 异常不吞 | `finally` 记完日志后 `throw` 原异常 |

> 一句话：**日志难在"切面顺序"和"脱敏"——本项目用 `@Async+REQUIRES_NEW` 把日志从事务里摘出来独立落库，参数脱敏后才进表，异常绝不吞。**
