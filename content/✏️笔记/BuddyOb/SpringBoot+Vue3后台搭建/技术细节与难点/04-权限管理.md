# 04 权限管理 · 技术细节与难点

> 配套原教程：[[../04-权限管理模块/00-索引]]（用户/角色/菜单/部门岗位/数据权限/在线用户）
> 本篇讲**动态菜单怎么和前端路由接通、数据权限怎么拼 SQL 才不注入、按钮级为什么必须前后端双保险**。

## 一、技术细节

### 4.1 用户 / 角色 / 菜单 的关系
- 用户↔角色：`sys_user_role`（多对多），一个用户多角色，权限取**并集**。
- 角色↔菜单：`sys_role_menu`（多对多），勾选菜单树赋权，`perms` 权限串随菜单带出。
- 密码 **BCrypt** 加密存储（自带盐），绝不存明文；重置密码即重新 `encode`。

### 4.2 动态菜单 → 前端路由（核心联动）
登录后后端按权限查 `sys_menu`（含 `path` + `component` 路由地址/组件路径），返回树。前端 `permission store` 里 `GenerateRoutes` 用 `component` 字符串 → `import(\`@/views/${component}\`)` 动态 `addRoute`。

### 4.3 数据权限（最危险的一处）
`@DataScope` 注解 + `DataScopeAspect` 切面 + MP `InnerInterceptor`，在业务 SQL 后面拼 `AND dept_id IN (当前用户部门及其子部门 id...)`。
**关键安全点**：拼进去的**列名 `dept_id` 来自注解的固定属性（白名单），绝不来自前端参数**——否则就是 SQL 注入口。

### 4.4 在线用户 / 踢人
Redis 存 `token → LoginUser` 映射。列表直接读 Redis；"踢人"= 删该 key，下次请求被 JWT 过滤器判失效 → 401。

## 二、技术难点

1. **刷新页面路由丢失（最高频）**：`vue-router` 的动态路由在**内存**里。刷新 → Pinia 清空 → 动态加的路由没了 → 白屏或跳登录。**解法**：刷新后从 `localStorage` 恢复 token，在 `router.beforeEach` 里**重新拉菜单 `addRoute` 再 `next()`**；或把路由表持久化。
2. **数据权限 SQL 注入**：切面若把"排序列名"做成可传参（前端传 `orderBy=dept_id`），恶意传 `dept_id; DROP TABLE` 就完蛋。**本项目用注解固定列名**（白名单），注入面被堵死。
3. **按钮级权限必须双保险**：前端 `v-hasPermi` 只是"体验"（无权限移除 DOM），**真正防线是后端 `@PreAuthorize("hasPermi('system:user:add')")`**。两者权限串必须完全一致——本项目已逐处校验（`system:user:add/edit/remove/export`、`monitor:online:*`、`wms:location:*` 均配对）。
4. **权限变更实时生效**：改了角色权限，已登录用户的权限是**缓存**的（Redis/内存 Set）。不处理就"改了不生效"。**解法**：改权限时清对应缓存，或强制相关用户重登。
5. **在线强踢实时性**：删 Redis key 后，旧端要等"下次请求"才 401，不是瞬间掉线。要瞬间踢需 **WebSocket 主动推"你被踢了"**。
6. **多对多赋权残留**：角色改菜单，只插不删 → 旧权限删不掉（见 [[技术细节与难点/02-数据库与RBAC]] 难点 2）。

## 三、本项目的解法

| 难点 | 本项目做法 |
|------|--------------|
| 刷新丢路由 | 路由守卫重拉菜单 `addRoute` + `useUserStore` 持久化 token |
| 数据权限注入 | `@DataScope` 注解**固定列名白名单**，切面拼 `dept_id IN(...)` |
| 按钮级 | 后端 `@PreAuthorize` 硬拦 + 前端 `v-hasPermi` 隐藏，串同源 |
| 权限变更 | 改角色权限清 Redis 权限缓存 |
| 踢人 | 删 token→Redis，下次请求 401；实时踢走 WebSocket |
| 密码 | `BCryptPasswordEncoder` 自带盐，不存明文 |

> 一句话：**权限管理的难点是"动态"二字——动态菜单要接通前端路由、动态数据权限要把列名焊死在白名单、动态变更要能清缓存生效。**
