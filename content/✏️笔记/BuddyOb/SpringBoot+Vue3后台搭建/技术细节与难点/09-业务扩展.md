# 09 业务扩展 · 技术细节与难点

> 配套原教程：[[../09-业务扩展/00-索引]]（物料与库位 / 库存单据与预警 / 报表与第三方对接）
> 本篇把前 8 章的"框架能力"真正用起来——讲**库存怎么不超卖、单据状态机怎么不跳变、FIFO 怎么实现、第三方回调怎么幂等**。

## 一、技术细节

### 9.1 物料 / 库位（`Locations`）
- 物料：`code/name/spec/unit/batchCtrl/expiryCtrl/type`，支持批次管控、效期管控。
- 库位树：库区→库位→料斗，`parent_id` 三级。**本项目直接对接你已有的 `test-module` 真实实体 `Locations`**（`cn.yething.test.domain`）——呼应最初 RuoYi 启动的 **`type-alias` 报错根因**：`mybatis.typeAliasesPackage` 必须覆盖 `cn.yething.**.domain`，否则 `LocationsMapper.xml` 里的 `type="Locations"` 找不到类。
- 条码生成、打印标签。

### 9.2 库存单据（状态机 + 事务）
- 入/出/调拨/盘点四类单；**状态机 `draft → submitted → done` / `cancel`**。
- 所有库存变更都在 **`@Transactional`** 内；草稿可改，提交后锁，已完成不可撤。
- **FIFO 出库**：同物料按 `produce_date ASC, batch ASC` 分配，逐批扣减。

### 9.3 预警
库存低于阈值、效期临近 → 预警（联动 [[技术细节与难点/07-日志与监控]] 的预警机制）。

### 9.4 报表与第三方
- ECharts 柱状/折线/饼；导出 Excel。
- 第三方（WCS/PLC）：REST/WebSocket/OPC；**回调要幂等**（网络重发会重复推）。

## 二、技术难点

1. **库存一致性与超卖/超领**：高并发下"查余量→扣减"非原子 → 超卖。**解法**：`@Transactional` + **行锁 `SELECT ... FOR UPDATE`** 或乐观锁 `@Version` 或 Redis 分布式锁；本项目用 MP 事务 + 提交前**校验库存足够**（不足直接抛，禁止超领）。
2. **单据状态机非法跳变**：草稿能改、提交后锁、已完成不能撤；状态散落各处 `if` 易出"已完成→退回草稿"这类非法迁移。**解法**：状态迁移集中管控（本项目用 `status` 字段 + 校验：已完成 `cancel` 直接抛"已完成的单据不能撤销"）。
3. **FIFO 实现**：同物料多批，要"先进先出"。**解法**：`ORDER BY produce_date ASC, batch ASC`，游标式逐批扣到满足需求（`remain`），不足则整单失败回滚。
4. **ECharts 大数据**：万级点渲染卡。**解法**：服务端聚合/降采样/分页，前端不渲全量。
5. **第三方回调幂等**：对方网络重发 → 同一单被处理两次。**解法**：**幂等键**（账单 `billId` / `nonce`）存 Redis `SETNX`，重复回调直接返回已处理。
6. **`Locations` 跨模块实体**：`type-alias` 不覆盖 `cn.yething.**.domain` → 启动 `ClassNotFoundException`。（已在 [[../02-数据库与RBAC/01-RBAC核心表SQL]] 的排查历史里根因定位。）

## 三、本项目的解法

| 难点 | 本项目做法 |
|------|--------------|
| 超卖/超领 | MP 事务 + 提交前校验库存足够，不足抛异常禁止超领 |
| 状态机 | `status` 集中 + 迁移校验（已完成不可撤） |
| FIFO | `ORDER BY produce_date,batch ASC` 逐批扣减 |
| 大数据报表 | 服务端聚合 + ECharts 前端渲染 |
| 回调幂等 | 幂等键 `SETNX` 去重 |
| 跨模块实体 | `typeAliasesPackage` 覆盖 `cn.yething.**.domain` |

> 一句话：**业务扩展的难点是"一致性"和"幂等"——库存用事务+行锁、单据用状态机、回调用幂等键，本项目全部落地。**
