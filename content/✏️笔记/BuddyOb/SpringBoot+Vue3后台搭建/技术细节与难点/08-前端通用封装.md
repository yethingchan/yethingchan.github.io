# 08 前端通用封装 · 技术细节与难点

> 配套原教程：[[../08-前端通用封装/00-索引]]（表格表单 / 路由权限与按钮指令 / 缓存主题与树形导入导出）
> 本篇讲**动态路由刷新为什么白屏、request.js 拦截器怎么统一、keep-alive 缓存怎么对上号、v-hasPermi 和后端怎么同源**。

## 一、技术细节

### 8.1 通用表格/表单组件
封装 `el-table` + 分页 + 搜索 + 增删改弹窗。业务页只传**列配置 + 接口地址**，少写 200 行重复代码。

### 8.2 `request.js`（统一门面）
- 请求拦截器：自动加 `Authorization: Bearer <token>`（后端 `JwtAuthenticationTokenFilter.parseBearer` 取它）。
- 响应拦截器：认 `code`——200 取 `data`；非 200 `message` 弹错；**401 清 token 跳登录**。

### 8.3 路由权限
- `router.beforeEach` 全局守卫：未登录 → `/login`。
- 登录后按菜单**动态 `addRoute`**（见 [[技术细节与难点/04-权限管理]]）。

### 8.4 按钮指令 `v-hasPermi`
自定义指令，无权限时**移除 DOM**（比 `v-if` 更彻底）。只是体验层，**真正防线是后端 `@PreAuthorize`**。

### 8.5 Pinia `useUserStore`
存 `userInfo / permissions / roles / token`；`localStorage` 持久化。

### 8.6 keep-alive
页面缓存（`include/exclude`），配合路由 `name`。

## 二、技术难点

1. **刷新页面路由丢失（最高频）**：动态路由在**内存**。刷新 → Pinia 清空 → 动态加的路由没了 → 白屏/跳登录。**解法**：刷新后从 `localStorage` 恢复 token，在路由守卫里**重新拉菜单 `addRoute` 再 `next()`**；或持久化 store。
2. **`v-hasPermi` vs `v-if`**：指令移除 DOM 更彻底；但动态权限变更需**重新渲染**（指令 `inserted` 钩子触发）。两者都只是前端体验。
3. **keep-alive 对不上号**：`include` 需组件 `name` 匹配**路由 `name`**；动态路由组件 `name` 设错 → 缓存失效。
4. **axios 拦截器与 Refresh Token**：token 过期用 refresh token 换，并发请求会**多个 401 同时触发刷新** → 需队列化（同一时刻只刷一次，其余挂起等结果）。
5. **权限码前后端一致**：`v-hasPermi="'system:user:add'"` 必须和后端 `@PreAuthorize("hasPermi('system:user:add')")` **同串**。本项目已逐处校验一致。
6. **history 刷新 404**：见 [[技术细节与难点/01-工程初始化]] 难点 4（Nginx `try_files` 兜底）。

## 三、本项目的解法

| 难点 | 本项目做法 |
|------|--------------|
| 刷新丢路由 | 路由守卫拉菜单重 `addRoute` + `useUserStore` 持久化 token |
| 按钮权限 | 后端 `@PreAuthorize` 硬拦 + 前端 `v-hasPermi` 隐藏，串同源 |
| keep-alive | 动态组件 `name` 对齐路由 `name`，`include` 精确 |
| Refresh Token | 拦截器队列化并发刷新（单例刷新中，其余等待） |
| 统一请求 | `request.js` 请求加 Bearer、响应认 code、401 跳登录 |

> 一句话：**前端封装的难点是"状态持久化"——token/路由/权限都在内存，刷新就丢；本项目用 `localStorage` + 守卫重拉菜单化解白屏。**
