# 01 工程初始化 · 技术细节与难点

> 配套原教程：[[../01-工程初始化/00-索引与项目结构]]（后端空壳 + 前端空壳 + 联调）
> 本篇只讲**为什么这一步容易卡、底层怎么动、本项目怎么解**。

## 一、技术细节（底层机制）

### 1.1 Maven 单模块 + 包分层
Spring Boot 3 的 `pom.xml` 用 `spring-boot-starter-parent` 作 parent，它带来两件事：① BOM（Bill of Materials）统一管理所有 starter 的版本，你不用写 `<version>`；② 绑定 Java 17 编译基线。
本项目**刻意用单模块 + `com.example.admin` 包分层**（`controller / service / mapper / domain / config`），而不是拆 `common / system / generator` 多模块。原因：从 0 到 1 先把一条线走通，多模块是后期为"拆分微服务"才需要的事，过早拆只会让你在 `dependencyManagement` 和模块间依赖里绕晕。

### 1.2 自动配置原理
`@SpringBootApplication` = `@EnableAutoConfiguration` + `@ComponentScan` + `@Configuration` 三合一。
- Spring Boot 3 的自动配置注册机制已从老式的 `META-INF/spring.factories` 改为 **`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`**（一份类名清单）。所以你看见 `spring-boot-autoconfigure` 包里再没有 `spring.factories` 了——这是 2.7→3.0 的硬变化。
- 内嵌 Tomcat 由 `spring-boot-starter-web` 带进来；默认端口 8080，由 `server.port` 控制。

### 1.3 前端 Vite 工程机制
- `package.json` 的 `dev/build/preview` 脚本；`vite.config.ts` 里 `server.proxy` 把前端 `/dev-api` 代理到 `http://localhost:8080`，**开发期靠它绕过跨域**（浏览器只看到同源的 5173，跨域发生在 Node 代理内部，不受浏览器 CORS 限制）。
- `main.js` 里 `createApp(App).use(router).use(pinia).use(ElementPlus)` 完成统一挂载；Vue 3 用 `<script setup>` 单文件组件。

### 1.4 Jakarta 命名空间（Spring Boot 3 的生死线）
Spring Boot 3 基于 **Jakarta EE 9+**，所有 `javax.*` 包被整体重命名为 `jakarta.*`：
`javax.servlet.*` → `jakarta.servlet.*`、`javax.validation` → `jakarta.validation`、`javax.annotation` → `jakarta.annotation`。这不是改名，是换了个 Java 标准组织（Oracle→Eclipse），字节码层面包名全变。

## 二、技术难点（为什么卡）

1. **Jakarta 迁移坑（最常见炸点）**：任何还依赖 `javax.servlet` 的老组件（老版 Shiro、老版 springfox-swagger、自己写的 `javax.servlet.Filter` 实现）在 Boot 3 下直接 `ClassNotFoundException` / `NoClassDefFoundError`。网上 80% 的 Spring Security / Swagger 例子仍是 `javax` 写法，照搬必挂。
2. **Vite 代理路径 vs 后端 context-path 不一致**：若后端设了 `server.servlet.context-path=/api`，那 Vite 代理的 target 也得拼上 `/api`，否则前端 `/dev-api/user/list` 代理到 `8080/user/list` 会 404。本项目约定**后端无 context-path**，代理直转 8080，最省事。
3. **CORS 预检（OPTIONS）被拦截**：带 `Authorization` 头的非简单请求，浏览器先发一个 `OPTIONS` 预检。若后端 Security 在过滤器链里把 OPTIONS 也拦了，预检失败 → 浏览器报 CORS 红字。必须在过滤链**最前面**对 OPTIONS `permitAll` 并正确回 CORS 头。
4. **history 路由刷新 404**：前端用 `createWebHistory`（history 模式）时，直接访问 `/system/user` 或刷新页面，浏览器向服务器要这个路径，而服务器只有 `/` 和 API——Nginx/后端需配 `try_files` 或 fallback 把未知路径都返 `index.html`。
5. **端口占用**：8080 被别的程序占了，启动报 `Port 8080 was already in use`——改 `server.port` 即可。

## 三、本项目的解法（代码落点）

| 难点 | 本项目做法 |
|------|--------------|
| Jakarta | 全程用 Boot 3 + `jakarta.*`；Swagger 用 **springdoc-openapi**（不是老 springfox），天然 Jakarta 兼容 |
| 联调跨域 | 开发期 Vite `proxy` `/dev-api → 8080`；生产期 Nginx 反代统一域名，根上就没有跨域 |
| context-path | 约定不配，前后端路径直接对齐 `localhost:8080` |
| 预检 | `SecurityFilterChain` 中 `requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()` + `CorsConfigurationSource` 允许凭据与 origins |
| history 404 | 生产 Nginx `try_files $uri /index.html`；开发期 Vite 已处理 |
| 启动类 | 单 `@SpringBootApplication` + `@MapperScan("com.example.admin.mapper")` + `@EnableAsync`（日志异步用）|

> 一句话：**工程初始化的核心难点就是"Jakarta 迁移"和"联调跨域"两件事**，本项目用 Boot 3 原生 + Vite 代理把它们压到最低。
