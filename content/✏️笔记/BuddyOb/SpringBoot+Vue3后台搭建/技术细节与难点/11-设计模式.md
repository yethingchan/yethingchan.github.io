# 11 设计模式 · 本工程用到的 12 个模式

> 这是深挖本的**横向收尾**——前面 01~10 是按"工程模块"切的，这章按"设计模式"切，把散落各处的同一思想串起来。
> 每个模式都给**本工程的真实落点**（对照 [[../00-总览与搭建路线]] 的约定：`com.example.admin`、统一返回 `AjaxResult`/`R<T>`、`hasPermi('模块:业务:动作')`）。

## 为什么讲模式
企业后台的代码量不在"功能"，在"怎么组织才不烂"。本工程里大量"看似啰嗦"的封装（统一返回、切面、拦截器、注解）本质都是经典模式。看懂模式，你就能**照猫画虎**写出可维护的代码，而不是堆 if/else。

---

## 1. 分层架构（Layered Architecture）—— 全局骨架
- **落点**：`controller / service / mapper / domain / config` 包分层；前端 `views/components/store/router/utils`。
- **讲**：每层只管自己的事——Controller 只接参返 `AjaxResult`，Service 写业务，Mapper 只拼 SQL。请求生命周期（见 [[../11-极简分层总结]]）就是分层在跑。
- **为什么**：关注点分离，改 UI 不动 SQL，改 SQL 不动权限。

## 2. 门面 / 外观（Facade）—— 统一入口
- **落点**：前端 `utils/request.js`（所有请求的唯一门面，统一加 token、认 code、401 跳登录）；后端 `AjaxResult.success/error` 统一包装。
- **讲**：外部（浏览器/其他服务）只跟"门面"打交道，看不到内部一堆零散方法。
- **反例**：业务代码里到处手写 `new OkHttpClient()`、各处拼 JSON → 门面缺失的典型症状。

## 3. 工厂（Factory）—— 策略对象的生产
- **落点**：文件存储 `本地 vs OSS` 两种实现用工厂选；JWT `Jwts.builder()` 造 token、`Jwts.parser()` 造解析器（建造者+工厂结合）；验证码 `算术/图形` 类型工厂。
- **讲**：调用方只说"我要个存文件的"，工厂按配置返回本地或 OSS 实现，**调用方不 new 具体类**。
- **价值**：换存储（本地→阿里云）只改工厂，业务代码零改（呼应 [[技术细节与难点/06-系统工具]] 的上传）。

## 4. 策略（Strategy）—— 算法可替换
- **落点**：限流 `令牌桶 vs 漏桶`；数据权限 SQL 拼接（不同部门范围策略）；密码算法 `BCrypt vs Argon2` 可配；验证码类型。
- **讲**：同一件事有多种做法，运行时按配置/注解**选一种**，调用方代码不变。
- **反例**：`if (type==1) {...} else if (type==2) {...}` 一堆分支 → 应抽成策略接口。

## 5. 模板方法（Template Method）—— 骨架固定、细节留钩子
- **落点**：MyBatis-Plus 的 `ServiceImpl`（`save/batch/page` 骨架已写好，你只填实体）；代码生成器的 **Velocity 模板**（骨架 `${tableName}`/`$columns` 固定，数据灌进去）；统一返回 `R<T>` 的 `rows/total` 包装。
- **讲**：父类/模板定"流程顺序"，子类/数据填"具体一格"。生成器最典型——一份模板产出 5 类文件。

## 6. 单例（Singleton）—— 全局唯一
- **落点**：Spring Bean **默认单例**（`RedisTemplate`、`SecurityFilterChain`、`ObjectMapper`、各 `Service`）；前端 `useUserStore`（Pinia 单例）。
- **讲**：整个应用共用一份，避免重复创建连接/配置。
- **注意**：单例里**不能存请求级状态**（如把当前用户名塞进单例字段 → 并发串号）。有状态用 `requestScope` 或 `ThreadLocal`（JWT 过滤器就用 `SecurityContext`/`ThreadLocal` 存当前用户）。

## 7. 观察者（Observer）—— 事件解耦
- **落点**：Spring `ApplicationEvent`——登录成功发事件，日志/通知监听器各自响应（不阻塞主流程）；前端事件总线。
- **讲**："做了件事"和"这件事要触发啥"解耦。登录逻辑不关心"要不要记日志/发通知"，只发个事件，监听器们各管各的。
- **价值**：加一个"登录送积分"只需新加监听器，不动登录代码（开闭原则）。

## 8. 代理 / AOP（Proxy）—— 横切关注点
- **落点**：**Spring AOP** 实现 `@Log`（操作日志）、`@Transactional`（事务）、`@DataScope`（数据权限）；JDK 动态代理（接口）/ CGLIB（类）。
- **讲**：日志、事务、权限这些"每个方法都要、但又不属业务逻辑"的东西，用代理**织入**到目标方法前后，业务代码干干净净。
- **难点**：代理顺序（日志切面 vs 事务切面谁外谁内）——见 [[技术细节与难点/07-日志与监控]] 难点 1；Filter 层异常不走 AOP → [[技术细节与难点/03-后端基础框架]]。

## 9. 适配器（Adapter）—— 不兼容接口转接
- **落点**：Spring Security 的 `UserDetails` / `UserDetailsService` 把你的 `SysUser` 适配成 Security 要的接口；`HandlerExceptionResolver` 把异常适配成响应。
- **讲**：第三方/框架要的接口和你自己的模型对不上，写个适配器转一下，**不改自己的模型**。

## 10. 建造者（Builder）—— 复杂对象分步拼
- **落点**：JWT `Jwts.builder().signWith(key).setSubject(...).compact()`；`AjaxResult` 的链式构建；Lombok `@Builder`（实体分步设值）。
- **讲**：一个对象字段多、构造复杂时，用 builder 链式设值，比一堆重载构造器清爽。

## 11. 责任链（Chain of Responsibility）—— 一环扣一环
- **落点**：**Spring Security 过滤器链**（`CORS → XSS(Wrapper) → SqlInjection → IpBlacklist → JwtFilter`，见 [[../11-极简分层总结]] 图①）；拦截器链；XSS/SQL 注入过滤器链。
- **讲**：请求像流水，经过一串处理器，每个决定"放行/拦截/改一下再传下家"。加一个安全过滤器 = 往链上加一环，不动其他环。
- **顺序敏感**：CORS 必须最前（预检先放行），鉴权在后——见 [[技术细节与难点/03-后端基础框架]] 难点 6。

## 12. 装饰器（Decorator）—— 不改原物、外包一层增强
- **落点**：XSS 防护的 **`HttpServletRequestWrapper`**——包住原始 request，重写 `getParameter/getHeader` 做 HTML 编码，原 request 一字不改，外面套了层"净化壳"。
- **讲**：和代理像，但装饰器**强调"功能增强且可多层嵌套"**（先 XSS 装饰、再 SQL 装饰），代理强调"访问控制/织入"。IO 流的 `BufferedInputStream` 也是装饰器。

## 13. 命令（Command）—— 请求即对象
- **落点**：**Quartz `Job`**（`executeInternal` 把"一次定时要做的事"封装成对象，调度器随时执行/撤销/重排）。
- **讲**：把"要做的事"变成对象，就能存起来、排队、定时、撤销——和策略的区别是命令**连"动作+参数"一起打包**。
