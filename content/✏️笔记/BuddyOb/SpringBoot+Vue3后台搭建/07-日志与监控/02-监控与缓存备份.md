## 2.1 服务器监控（JVM / CPU / 内存 / 磁盘）

```java
@RestController
@RequestMapping("/monitor/server")
public class ServerController {

    @GetMapping
    public AjaxResult info() throws Exception {
        // Hutool 的 SystemInfo 一把梭：CPU/内存/JVM/磁盘全拿到
        cn.hutool.system.osinfo.SystemInfo si = new cn.hutool.system.osinfo.SystemInfo();
        Map<String,Object> data = new HashMap<>();
        data.put("cpu",   Map.of("rate", si.getCpuInfo().getUsedPercent())); // 使用率%
        data.put("mem",   Map.of("total", si.getMemoryInfo().getTotal(),
                                   "used",  si.getMemoryInfo().getUsed()));  // 字节
        data.put("jvm",   Map.of("total", si.getJvmInfo().getTotal(),
                                   "used",  si.getJvmInfo().getUsed(),
                                   "name",  ManagementFactory.getRuntimeMXBean().getVmName()));
        data.put("sys",   Map.of("osName", si.getOsInfo().getName(),
                                   "arch",   si.getOsInfo().getArch()));
        data.put("disk",  List.of(                            // 每块盘的使用率
            Map.of("dir", "C:\\", "rate", si.getDiskInfo().getUsedPercent())));
        return AjaxResult.success(data);
    }
}
```
**讲解**：`Hutool.SystemInfo` 底层是 `OperatingSystemMXBean` + `Runtime` 封装，省去自己读 MXBean。前端用 **ECharts 仪表盘**画 CPU/内存百分比（[[../08-前端通用封装/01-表格与表单通用组件]] 的图表略提，细节见 ECharts 文档）。

## 2.2 Redis 监控

```java
@GetMapping("/monitor/redis")
public AjaxResult redisInfo(LettuceConnectionFactory factory) {
    // 用 RedisTemplate 取 INFO 原始串，解析关键项
    Properties props = factory.getConnection().serverCommands().info();
    Map<String,Object> m = new HashMap<>();
    m.put("usedMemory", props.getProperty("used_memory_human")); // 如 "12.3M"
    m.put("connectedClients", props.getProperty("connected_clients"));
    m.put("instantaneousOps", props.getProperty("instantaneous_ops_per_sec"));
    m.put("hitRate", computeHitRate(props));   // (keyspace_hits)/(hits+misses)
    return AjaxResult.success(m);
}
```
**讲解**：`INFO` 是 Redis 自带诊断命令，返回 `used_memory`/`connected_clients`/`keyspace_hits` 等。**命中率**最有用——低说明缓存设计有问题（热点没命中）。

## 2.3 数据库监控（Druid 自带）

Druid starter 默认暴露 `/druid/stat` 端点。在 `application.yml` 开：
```yaml
spring:
  datasource:
    druid:
      stat-view-servlet:
        enabled: true
        url-pattern: /druid/*
        login-username: admin
        login-password: admin123
      filter:
        stat:
          enabled: true
          log-slow-sql: true
          slow-sql-millis: 1000    # >1s 记慢 SQL
```
访问 `http://localhost:8080/druid/` 登录后能看到：**SQL 执行次数/耗时、慢 SQL 列表、活跃连接数**。这就是"线上慢 SQL 排查"的入口。`SecurityConfig` 里要把 `/druid/**` 加进 `permitAll()`。

## 2.4 缓存管理（Redis key 查看 / 删除 / 清）

```java
@RestController
@RequestMapping("/monitor/cache")
public class CacheController {
    @Resource private RedisCache redisCache;

    /** 查看所有业务 key（用 SCAN 游标，别用 KEYS 阻塞） */
    @GetMapping("/list")
    public AjaxResult list(@RequestParam String pattern) {
        Set<String> keys = redisTemplate.scan(pattern); // 封装 SCAN
        List<Map<String,Object>> rows = keys.stream().limit(200).map(k -> Map.of(
            "key", k, "value", redisCache.getCacheObject(k))).toList();
        return AjaxResult.success(rows);
    }

    /** 删单个 */
    @DeleteMapping("/{key}") public AjaxResult del(@PathVariable String key) {
        redisCache.deleteObject(key); return AjaxResult.success();
    }

    /** 清全部业务缓存（菜单/字典/参数） */
    @DeleteMapping("/clear")
    public AjaxResult clear() {
        redisCache.deleteObjectByPattern("dict:*");
        redisCache.deleteObjectByPattern("menu:*");
        redisCache.deleteObjectByPattern("config:*");
        return AjaxResult.success("已刷新缓存");
    }
}
```
**讲解**：**绝不能用 `KEYS *`**——生产库 key 百万级时会阻塞 Redis 几十秒，全站卡死。必须用 `SCAN` 游标分批。清缓存常用于"改了字典/菜单，前端没更新"的救急（见 [[../05-字典与基础数据/01-字典管理]]）。

## 2.5 数据备份与恢复（MySQL）

**一键备份（调 mysqldump）**：
```java
@GetMapping("/monitor/db/backup")
public void backup(HttpServletResponse resp) throws IOException {
    String cmd = String.format(
        "mysqldump -u%s -p%s %s > D:/backup/admin_%s.sql",
        dbUser, dbPwd, "admin", LocalDate.now());
    Process p = Runtime.getRuntime().exec(new String[]{"cmd","/c",cmd});
    p.waitFor();
    // 读文件流给前端下载
    Files.copy(Path.of("D:/backup/admin_"+LocalDate.now()+".sql"), resp.getOutputStream());
}
```
**恢复**：`mysql -u root -p admin < backup.sql`。

**关键点**：
- 生产建议**定时备份**：用 [[../06-系统工具/03-Swagger接口文档与Quartz定时任务]] 的 Quartz 每天 3 点跑一次备份 Job。
- **3-2-1 原则**：3 份副本、2 种介质、1 份异地。
- **备份文件管理**：`sys_backup` 表记（文件名/大小/时间），过期自动清理。
- 凭据别硬编码——放配置中心/环境变量。
