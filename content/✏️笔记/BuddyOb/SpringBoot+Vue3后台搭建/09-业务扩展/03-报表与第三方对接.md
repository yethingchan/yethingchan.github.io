# 09-3 报表（ECharts）+ 第三方对接（WCS / PLC / REST）

> 上接：[[SpringBoot+Vue3后台搭建/09-业务扩展/02-库存单据与预警]]
> 老板/现场要的不是表格，是**图**和**和设备的联动**。本文件给：① ECharts 出入库趋势/库存结构报表；② 工业系统最常见的第三方对接——WCS（仓库控制系统）、PLC（通过 REST/OPC 网关）、外部 REST API。

## 3.1 后端：报表聚合接口

报表数据靠 SQL 聚合，不在 Java 里循环算。用 MP 的 `selectMaps`（返回 `Map`）或直接写 `group by`：

```java
@RestController
@RequestMapping("/wms/report")
public class WmsReportController {
    @Resource private InventoryMapper invMapper;
    @Resource private StockBillMapper billMapper;

    /** 近 N 天出入库趋势（给 ECharts 柱状图） */
    @PreAuthorize("hasPermi('wms:report:view')")
    @GetMapping("/trend")
    public AjaxResult trend(@RequestParam(defaultValue="7") int days) {
        List<Map<String,Object>> rows = billMapper.selectTrend(days);
        // 返回 [{date:'07-13', inQty:120, outQty:90}, ...]
        return AjaxResult.success(rows);
    }

    /** 库存结构（按仓库聚合，给饼图） */
    @PreAuthorize("hasPermi('wms:report:view')")
    @GetMapping("/structure")
    public AjaxResult structure() {
        List<Map<String,Object>> rows = invMapper.selectByWarehouse();
        return AjaxResult.success(rows);
    }
}
```

`StockBillMapper.java`（接口 + 注解 SQL，简单聚合不必写 XML）

```java
public interface StockBillMapper extends BaseMapper<WmsStockBill> {
    @Select("""
        SELECT DATE(create_time) AS date,
               SUM(CASE WHEN bill_type='1' THEN 1 ELSE 0 END) AS inQty,
               SUM(CASE WHEN bill_type='2' THEN 1 ELSE 0 END) AS outQty
        FROM wms_stock_bill
        WHERE create_time >= DATE_SUB(CURDATE(), INTERVAL #{days} DAY)
        GROUP BY DATE(create_time) ORDER BY date
        """)
    List<Map<String,Object>> selectTrend(@Param("days") int days);
}
```

> 多库/大数据量时，把聚合下沉到**数仓或定时预汇总表**，前端只查预汇总结果——这是企业报表的常规演进路径。

## 3.2 前端：ECharts 画图

`src/views/wms/report/index.vue`
```vue
<template>
  <div>
    <el-card>
      <div ref="trendRef" style="height:340px"></div>
    </el-card>
    <el-card style="margin-top:16px">
      <div ref="pieRef" style="height:340px"></div>
    </el-card>
  </div>
</template>
<script setup>
import { ref, onMounted, nextTick } from 'vue'
import * as echarts from 'echarts'
import { reportTrend, reportStructure } from '@/api/wms/report'

const trendRef = ref(), pieRef = ref()

async function initCharts() {
  const trend = await reportTrend(7)
  const pie = await reportStructure()

  // ① 柱状图：出入库趋势
  const t = echarts.init(trendRef.value)
  t.setOption({
    title:{ text:'近7天出入库趋势' },
    tooltip:{ trigger:'axis' },
    legend:{ data:['入库','出库'] },
    xAxis:{ type:'category', data: trend.map(d=>d.date) },
    yAxis:{ type:'value' },
    series:[
      { name:'入库', type:'bar', data: trend.map(d=>d.inQty) },
      { name:'出库', type:'bar', data: trend.map(d=>d.outQty) }
    ]
  })

  // ② 饼图：库存结构
  const p = echarts.init(pieRef.value)
  p.setOption({
    title:{ text:'各仓库库存占比' },
    series:[{
      type:'pie', radius:'55%',
      data: pie.map(d=>({ name:d.warehouse, value:d.totalQty }))
    }]
  })
}
onMounted(()=> nextTick(initCharts))
</script>
```

`src/api/wms/report.js`
```js
import request from '@/utils/request'
export function reportTrend(days){ return request({ url:'/wms/report/trend', method:'get', params:{days} }) }
export function reportStructure(){ return request({ url:'/wms/report/structure', method:'get' }) }
```

> `echarts.init` 必须在 DOM 渲染后调用（所以 `onMounted`+`nextTick`），否则拿不到容器尺寸画不出——新手高频坑。窗口缩放记得 `chart.resize()`。

## 3.3 第三方对接：WCS / PLC / 外部 REST

工业 WMS 常要把"上架任务"下发给 **WCS（仓库控制系统）**，或从小车/PLC 读状态。现代做法：设备侧暴露 REST/WebSocket/OPC-UA 网关，后端当**客户端**去调。

### 3.3.1 用 RestClient（Spring 6 推荐）调外部

```java
@Configuration
public class RestClientConfig {
    @Bean
    public RestClient restClient() {
        return RestClient.builder()
            .baseUrl("http://wcs-gateway:8088")   // WCS/网关地址，放配置中心
            .defaultHeader("Content-Type", "application/json")
            .build();
    }
}
```

```java
@Service
public class WcsSyncService {
    @Resource private RestClient restClient;

    /** 把入库任务下发给 WCS */
    public void pushTask(Long billId, List<WmsStockBillItem> items) {
        Map<String,Object> body = Map.of(
            "billId", billId,
            "items", items.stream().map(i -> Map.of(
                "matId", i.getMatId(), "locId", i.getLocId(), "qty", i.getQty()))
                .toList());
        try {
            restClient.post().uri("/api/tasks/inbound")
                .body(body).retrieve().toBodilessEntity();
        } catch (Exception e) {
            throw new BusinessException("下发 WCS 失败：" + e.getMessage());
        }
    }

    /** 从 PLC/网关拉实时库存（设备侧提供 REST） */
    public List<Map<String,Object>> pullPlcStock() {
        return restClient.get().uri("/api/plc/stock")
            .retrieve().body(new org.springframework.core.ParameterizedTypeReference<>() {});
    }
}
```

### 3.3.2 对接要点（企业级必须考虑）

| 关注点 | 做法 |
|--------|------|
| **超时** | `RestClient` 配 `connectTimeout`/`readTimeout`，别让设备卡死主线程 |
| **重试** | 网络抖动用 Spring Retry / 手动重试 2~3 次，指数退避 |
| **幂等** | 下发任务带 `billId` 当幂等键，WCS 重复收到也不重复执行 |
| **异步** | 大批量用 `@Async` 或消息队列（RabbitMQ/RocketMQ）解耦，别阻塞 HTTP 线程 |
| **鉴权** | 设备网关通常要 token/签名，`defaultHeader` 或 `ExchangeFilterFunction` 统一加 |
| **状态回写** | WCS 执行完通过**回调接口**（你暴露的 `/wms/callback`）或 WebSocket 推结果，更新单据状态 |

### 3.3.3 设备回调接口（你暴露给 WCS 调）

```java
@RestController
@RequestMapping("/wms/callback")
public class WcsCallbackController {
    @Resource private IStockBillService billService;
    @Resource private RedisCache redisCache;

    /** WCS 执行完成后回调 */
    @PostMapping("/task/done")
    public AjaxResult taskDone(@RequestBody Map<String,Object> body) {
        Long billId = ((Number) body.get("billId")).longValue();
        String sign = (String) body.get("sign");
        // 校验签名（和设备约定的密钥），防伪造回调 —— 对应 [[../10-安全防护/02-XSS与SQL注入过滤]] 的思想
        if (!verifySign(body, sign)) throw new BusinessException(ErrorCode.CAPTCHA_ERROR.getCode(), "回调签名错误");
        redisCache.deleteObject("wms:task:" + billId);  // 清除待回执
        billService.markDone(billId);
        return AjaxResult.success();
    }
}
```

> 工业对接没有"标准答案"：老 PLC 用 OPC/Modbus（靠 Kepware 之类网关转 REST），AGV 用 WebSocket，ERP 用 HTTP+XML。本教程给的 **REST 客户端 + 回调 + 幂等/超时/重试** 框架，能套到绝大多数场景。
