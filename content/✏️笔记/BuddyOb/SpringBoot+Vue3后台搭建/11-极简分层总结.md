## 三、一个请求的生命周期（面试/复盘常考）

```
1. 浏览器发请求，request.js 自动加 Authorization: Bearer xxx
2. 后端过滤链：CORS → XSS 净化参数 → SQL 注入关键词拦截 → IP 黑名单 → JwtFilter
3. JwtFilter：解析 token → 校验 → 从 Redis 取 LoginUser → 塞进 SecurityContext
4. authorizeHttpRequests：未登录 → 401
5. @PreAuthorize("hasPermi('system:user:list')")：无权限 → 403
6. Controller：只返回 AjaxResult / R<T>
7. Service：MP 的 QueryWrapper 拼条件（参数化，免疫注入）；@Transactional 保事务
8. 切面：LogAspect 记操作日志；DataScope 注入数据权限 SQL 片段
9. 返回 JSON → 前端响应拦截器认 code=200 → 渲染 el-table
```

> 记住这条链，你就能定位**任何**一个接口问题出在哪一层。

## 四、最重要的三条铁律

1. **前端不可信**：`v-hasPermi` 只管体验，真正防线是后端 `@PreAuthorize` + 参数校验 + 消毒。
2. **用户输入都是数据不是代码**：SQL 用 `#{}`/QueryWrapper 参数化；HTML 用 OWASP Encoder 按上下文编码；文件上传验 MIME + 随机名 + 存根外。
3. **事务与幂等**：改多行库存/金额用 `@Transactional(rollbackFor)`；对外接口用幂等键（billId/nonce）防重复。

## 五、下一步你可以做什么

- **套用自己的业务**：把 `modules/wms` 换成 `modules/erp` / `modules/crm`，骨架一模一样。
- **加工作流**：简单审批用"状态机 + 审批记录表"即可；复杂流程接 **Flowable/Activiti**（BPMN）。
- **上微服务**：单体现在够用；要拆分时，把 `Security/JWT/Redis` 抽到 `common` 模块，网关做统一鉴权与限流。
- **接真实设备**：WCS/PLC 走 REST/WebSocket/OPC（见 [[09-业务扩展/03-报表与第三方对接]] 3.3）。
