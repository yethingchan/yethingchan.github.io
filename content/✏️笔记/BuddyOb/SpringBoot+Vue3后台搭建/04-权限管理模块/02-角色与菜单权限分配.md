# 04-2 角色管理 + 菜单权限分配（RBAC 灵魂）

> 上接：[[SpringBoot+Vue3后台搭建/04-权限管理模块/01-用户管理]]

## 2.0 这一节是整个系统的"心脏"
用户不直接拿权限，**角色**拿权限，**用户挂角色**。前端菜单树 + 按钮权限，全靠"角色↔菜单"这张关系表驱动。

## 2.1 角色 CRUD（简单）

```java
@RestController
@RequestMapping("/system/role")
public class SysRoleController {
    @Resource private ISysRoleService roleService;

    @PreAuthorize("hasPermi('system:role:list')")
    @GetMapping("/list")
    public R<SysRole> list(SysRole role, PageQuery pq) {
        return R.ok(roleService.selectPage(new Page<>(pq.getPageNum(), pq.getPageSize()), role));
    }

    @PreAuthorize("hasPermi('system:role:add')")
    @PostMapping public AjaxResult add(@Valid @RequestBody SysRole role) {
        roleService.save(role); return AjaxResult.success();
    }
    // edit / remove / changeStatus 同用户管理套路，略
}
```

## 2.2 给角色授权菜单（核心写入）

```java
// 前端传：{ roleId: 5, menuIds: [2,3,4,10] }
@PreAuthorize("hasPermi('system:role:auth')")
@PutMapping("/auth")
public AjaxResult auth(@RequestBody AuthRole body) {
    roleService.authRole(body.getRoleId(), body.getMenuIds());
    // 授权后清菜单缓存（[[../05-字典与基础数据/01-字典管理]] 的缓存思路）
    menuCache.clearRoleMenu(body.getRoleId());
    return AjaxResult.success();
}
```
`ISysRoleService.authRole` 实现：
```java
@Override @Transactional
public void authRole(Long roleId, Long[] menuIds) {
    roleMenuMapper.delete(Wrappers.<SysRoleMenu>query().eq("role_id", roleId)); // 先清旧
    if (menuIds != null && menuIds.length > 0) {
        List<SysRoleMenu> list = Arrays.stream(menuIds)
                .map(mid -> new SysRoleMenu(roleId, mid)).toList();
        roleMenuMapper.insertBatchSomeColumn(list); // MP 批量插
    }
}
```
**讲解**：授权 = **先删后插**该角色的全部菜单关系。前端勾选树拿到所有选中节点（含半选父节点要不要存，见 2.4）。

## 2.3 登录时收集用户"所有权限串"

[[../03-后端基础框架/03-SpringSecurity与JWT鉴权]] 的 `UserDetailsServiceImpl` 里我们调了 `selectPermsByUserId`。SQL 这样写（多表 JOIN 去重）：

```sql
SELECT DISTINCT m.perms
FROM sys_user_role ur
JOIN sys_role_menu rm ON ur.role_id = rm.role_id
JOIN sys_menu m        ON rm.menu_id = m.menu_id
WHERE ur.user_id = #{userId} AND m.perms IS NOT NULL AND m.perms <> ''
```
**讲解**：一个用户可能挂多个角色 → 多个角色勾了不同菜单 → JOIN 求并集，**DISTINCT** 去重。`perms` 字段（如 `system:user:add`）就是最终写进 `SecurityContext` 的字符串，供 `@PreAuthorize("hasPermi(...)")` 校验。

## 2.4 前端：菜单树勾选（角色授权页核心）

```vue
<template>
  <el-tree ref="menuTree" :data="menuTreeData" :props="{label:'menuName'}"
    show-checkbox node-key="menuId" :default-checked-keys="checkedKeys" />
  <el-button type="primary" @click="submitAuth">保存授权</el-button>
</template>

<script setup>
import { ref } from 'vue'
import { treeselect, getRoleMenuIds, authRole } from '@/api/system/role'

const menuTreeData = ref([])
const checkedKeys = ref([])

// 拉全量菜单树 + 该角色已勾的 keys
async function init(roleId) {
  const [tree, ids] = await Promise.all([ treeselect(), getRoleMenuIds(roleId) ])
  menuTreeData.value = tree
  checkedKeys.value = ids           // 回显已授权
}
// 保存：getHalfCheckedKeys 把半选父节点也一起存，保证父子权限一致
async function submitAuth() {
  const keys = [...menuTreeRef.value.getCheckedKeys(),
                ...menuTreeRef.value.getHalfCheckedKeys()]
  await authRole({ roleId, menuIds: keys })
}
</script>
```
**讲解**：`node-key="menuId"` 让 `getCheckedKeys()` 直接返回 menuId 数组。**半选父节点也要存**——否则只存子节点，后端 `selectPermsByUserId` 因没父菜单记录而漏权限。这是 RBAC 授权页的标准坑。

## 2.5 菜单权限串如何驱动"前端按钮显示"

登录后前端拿到 `permissions` 数组（含 `system:user:add` 等），存 `store/user`。`v-hasPermi` 指令（[[../08-前端通用封装/02-路由权限与按钮指令]]）就是判断这个数组里有没有对应串。后端 `@PreAuthorize("hasPermi('system:user:add')")` 判断的是 **同一个** `Authentication.authorities`。**前后端用同一套 perms 字符串，双保险**。

## 2.6 开启方法级安全（别漏！）

[[../03-后端基础框架/03-SpringSecurity与JWT鉴权]] 的 `SecurityConfig` 必须加（Security 6 写法）：
```java
@EnableMethodSecurity   // 替代老版 @EnableGlobalMethodSecurity(prePostEnabled=true)
@EnableWebSecurity
public class SecurityConfig { ... }
```
不加这行，`@PreAuthorize` **完全不生效**，任何人都能调接口——这是新手最常踩的"权限形同虚设"坑。
