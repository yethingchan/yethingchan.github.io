# 04-5 数据权限实现（全部 / 本部门 / 仅本人）

> 上接：[[SpringBoot+Vue3后台搭建/04-权限管理模块/04-部门与岗位管理]]

## 5.0 什么是数据权限
菜单权限控制"能看哪个按钮"，**数据权限控制"同一张表，不同人看到不同行"**。例：仓库员 A 只能看自己部门的库存，总监能看全部。`sys_role.data_scope` 字段（1全部/3本部门/4本部门及子部门/5仅本人/2自定义）就是这个元信息。

## 5.1 整体设计（注解驱动 + MP 拦截器注入）

```
Service 方法上写 @DataScope(deptAlias="d", userAlias="u")
   │
   ▼ @Before 切面（DataScopeAspect）
   读当前登录人 + 其角色 data_scope
   拼出 SQL 片段：AND (d.dept_id IN (1,2,3) OR u.user_id=10)
   存进 ThreadLocal（DataScopeHolder）
   │
   ▼ MP InnerInterceptor（beforeQuery）
   从 ThreadLocal 取片段，注入到 MP 已拼好的 SELECT ... WHERE 之后
   │
   ▼ 最终 SQL：SELECT ... WHERE 1=1 AND (d.dept_id IN (...))
```

## 5.2 注解

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface DataScope {
    String deptAlias() default "";   // 部门字段的表别名，如 "d"
    String userAlias() default "";   // 用户字段的表别名，如 "u"
}
```

## 5.3 Service 方法打注解（拼表别名）

```java
@Service
public class SysUserServiceImpl extends ServiceImpl<SysUserMapper, SysUser>
        implements ISysUserService {

    @Override
    @DataScope(deptAlias = "d", userAlias = "u")   // ← 数据权限开启
    public List<SysUser> listScope(SysUser q) {
        return baseMapper.selectListScope(q);  // 这个 Mapper 方法 SQL 里表要起别名为 d(部门表)/u(用户表)
    }
}
```
> Mapper 对应 SQL 示例（用别名，否则片段里的 `d.dept_id` 无来源）：
> `SELECT u.* FROM sys_user u LEFT JOIN sys_dept d ON u.dept_id=d.dept_id WHERE u.del_flag='0' ${dataScope}`

## 5.4 ThreadLocal 载体

```java
public class DataScopeHolder {
    private static final ThreadLocal<String> TL = new ThreadLocal<>();
    public static void set(String s) { TL.set(s); }
    public static String get() { return TL.get(); }
    public static void clear() { TL.remove(); }
}
```

## 5.5 切面：按角色 data_scope 拼片段

```java
@Aspect
@Component
public class DataScopeAspect {

    @Before("@annotation(scope)")
    public void before(JoinPoint jp, DataScope scope) {
        LoginUser user = SecurityUtils.getLoginUser();   // 从 SecurityContext 取
        // 管理员 / data_scope=1 全部 → 不加限制
        if (user.isAdmin() || user.getDataScope() == 1) {
            DataScopeHolder.set(""); return;
        }
        String frag = switch (user.getDataScope()) {
            case 3 -> " AND (d.dept_id = " + user.getDeptId() + ")";        // 本部门
            case 4 -> " AND d.dept_id IN (" + user.getDeptAndChildren() + ")"; // 本部门及子部门
            case 5 -> " AND u.user_id = " + user.getUserId() + ")";            // 仅本人
            case 2 -> " AND d.dept_id IN (" + user.getCustomDeptIds() + ")"; // 自定义
            default -> "";
        };
        DataScopeHolder.set(frag);
    }
}
```
**讲解**：`user.getDeptAndChildren()` 调 [[../04-权限管理模块/04-部门与岗位管理]] 4.2 的"取部门及子孙 id"；`user.isAdmin()` 是超级管理员放行。**核心思想：权限判断在切面，SQL 拼接交给拦截器，业务代码零侵入**。

## 5.6 MP 拦截器：把片段注入 SQL

```java
@Component
public class DataScopeInnerInterceptor implements InnerInterceptor {

    @Override
    public void beforeQuery(Executor executor, MappedStatement ms, Object parameter,
                            RowBounds rb, ResultHandler rh, CacheKey ck, BoundSql bs) {
        String frag = DataScopeHolder.get();
        if (frag == null || frag.isEmpty()) return;   // 无数据权限的方法直接放过
        String sql = bs.getSql();                     // MP 已拼好的 SELECT
        if (!sql.toLowerCase().contains("where")) {
            sql = sql + " WHERE 1=1 " + frag;
        } else {
            sql = sql + frag;                          // 已有 WHERE，直接 AND
        }
        MetaObject mo = SystemMetaObject.forObject(bs);
        mo.setValue("sql", sql);                       // 改写 BoundSql
        DataScopeHolder.clear();                          // 用后清，防止串台
    }
}
```

## 5.7 注册（顺序很关键！）

在 [[../03-后端基础框架/02-MyBatisPlus与Redis配置]] 的 `MybatisPlusConfig` 里**先加 DataScope，后加分页**（让数据权限先拼 WHERE，分页再算 total/count 基于已收窄的数据）：

```java
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor i = new MybatisPlusInterceptor();
    i.addInnerInterceptor(new DataScopeInnerInterceptor());   // ← 先
    i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL)); // ← 后
    return i;
}
```
**坑**：若分页在前，会先给裸 SELECT 加 `LIMIT`，数据权限拦截器再把 `AND ...` 拼到 `LIMIT` **后面**，SQL 变 `... LIMIT ? AND (d.dept_id=..)`，直接报错。

## 5.8 前端：本部门用户无感
前端不需要改 SQL，只是某人登录后调同一个 `/system/user/list`，后端自动只返回他权限内的行。**这正是 RBAC 数据权限"无感隔离"的魅力**。
