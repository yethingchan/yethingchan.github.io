## 1.1 request.js（前后端契约的"翻译层"）

这是**整个前端的咽喉**：所有 HTTP 都过它，统一处理 token、code、401。

```js
import axios from 'axios'
import { ElMessage, ElMessageBox } from 'element-plus'
import { getToken, clearAuth } from '@/utils/auth'   // token 存 cookie（[[../03-后端基础框架/03-SpringSecurity与JWT鉴权]]）

const service = axios.create({
  baseURL: import.meta.env.VITE_APP_BASE_API || '/dev-api', // 见 [[../01-工程初始化/03-前后端联调与跨域]]
  timeout: 10000
})

// 请求拦截：自动带 token
service.interceptors.request.use(config => {
  const t = getToken()
  if (t) config.headers['Authorization'] = 'Bearer ' + t   // 后端 JwtFilter 读这个头
  return config
})

// 响应拦截：统一处理后端 AjaxResult
service.interceptors.response.use(
  resp => {
    const res = resp.data
    if (res.code === 200) return res            // 成功：直接返回 data 外层
    // 业务失败：弹错（code 非 200 都算失败）
    ElMessage.error(res.msg || '请求失败')
    return Promise.reject(res.msg)
  },
  error => {
    const status = error.response?.status
    if (status === 401) {                       // token 失效/未登录
      ElMessageBox.confirm('登录已过期，是否重新登录？').then(() => {
        clearAuth(); location.href = '/login'           // 清掉跳登录
      })
    } else if (status === 403) {
      ElMessage.error('没有权限访问该资源')
    } else {
      ElMessage.error(error.message)
    }
    return Promise.reject(error)
  }
)
export default service
```
**逐行解释**
- `baseURL='/dev-api'`：所有请求走代理（[[../01-工程初始化/03-前后端联调与跨域]]）。`import.meta.env.VITE_APP_BASE_API` 是 Vite 环境变量，可在 `.env` 配。
- **请求拦截**加 `Authorization: Bearer xxx`——后端 `JwtAuthenticationTokenFilter.parseBearer` 就取这个（见 [[../03-后端基础框架/03-SpringSecurity与JWT鉴权]] 3.3）。
- **响应拦截**是"契约"：后端 `AjaxResult` 约定 `code:200` 成功，所以这里**只把 `code===200` 当成功**，其余一律弹 `msg` 并 reject。前端业务代码就只需 `const res = await listUser()`，不用每个接口判 code。
- **401 自动跳登录**：token 过期时后端返回 401，这里统一处理，业务页不用各自判断。

## 1.2 通用表格（一个业务页的骨架）

几乎每个 CRUD 页都是"搜索框 + 表格 + 分页 + 增改弹窗"四件套。以 [[../04-权限管理模块/01-用户管理]] 的 `views/system/user/index.vue` 为模板，其余页**复制改字段**即可。核心套路回顾：

```vue
<script setup>
import { ref, reactive, onMounted } from 'vue'
import { listUser, addUser, updateUser, delUser } from '@/api/system/user'
const query = reactive({ pageNum:1, pageSize:10, userName:'', status:'' })
const table = ref({ rows:[], total:0 })
const loading = ref(false)

async function getList() {
  loading.value = true
  const res = await listUser(query)   // 后端 R.ok(page) → {rows,total}
  table.value = res; loading.value = false
}
onMounted(getList)

// 表单弹窗
const dialog = reactive({ open:false, title:'', form:{} })
function openAdd(){ dialog.title='新增'; dialog.form={}; dialog.open=true }
function submit(){ dialog.form.userId ? updateUser(dialog.form) : addUser(dialog.form) }
</script>
```
> 这就是"通用"的真相：**模式固定，只有字段/接口名不同**。封装成 `<CrudTable :api="..." :columns="...">` 组件可进一步提效，但先吃透这个套路。

## 1.3 表单校验（@Valid 的前端呼应）

```vue
<el-form :model="dialog.form" :rules="rules" ref="formRef">
  <el-form-item label="账号" prop="userName">
    <el-input v-model="dialog.form.userName" />
  </el-form-item>
</el-form>
<script setup>
const rules = {
  userName: [{ required:true, message:'账号不能为空', trigger:'blur' }],
  password: [{ min:6, max:20, message:'密码6-20位', trigger:'blur' }]
}
</script>
```
**讲解**：前端的 `rules` 和后端 DTO 的 `@NotBlank(message="账号不能为空")` **双重校验**——前端体验好（即时提示），后端兜底（绕前端直接调接口也拦，见 [[../03-后端基础框架/01-统一返回与全局异常]] 1.5）。

## 1.4 前端导出（用 xlsx）

后端导出走 blob（[[../04-权限管理模块/01-用户管理]] 1.4）；**纯前端也能导**（数据已在前端）：
```js
import * as XLSX from 'xlsx'
function exportFront(rows){
  const ws = XLSX.utils.json_to_sheet(rows)   // 数组→sheet
  const wb = XLSX.utils.book_new(); XLSX.utils.book_append_sheet(wb, ws, '用户')
  XLSX.writeFile(wb, 'user.xlsx')                    // 浏览器直接下
}
```
> 后端导出适合"按条件查全量再下"；前端导出适合"当前页/已加载数据"。两者都提供体验最佳。
