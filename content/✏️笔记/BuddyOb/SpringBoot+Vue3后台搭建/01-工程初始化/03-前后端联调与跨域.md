# 01-3 前后端联调与跨域

> 上接：[[SpringBoot+Vue3后台搭建/01-工程初始化/02-前端Vue3初始化]]

## 为什么有跨域
前端跑在 `localhost:80`（Vite），后端在 `localhost:8080`。**协议/域名/端口任一不同 = 跨域**。浏览器出于安全会拦截前端 JS 发起的跨域请求，除非后端显式允许（CORS 头）或用代理把请求"变成同源"。

## 方案 A：开发期 Vite 代理（推荐，已配）
[[../01-工程初始化/02-前端Vue3初始化]] 的 `vite.config.js` 已写 `proxy['/dev-api']`。前端这样发请求：

```js
// src/utils/request.js（骨架，完整在 [[../08-前端通用封装/01-表格与表单通用组件]]）
import axios from 'axios'
const service = axios.create({
  baseURL: '/dev-api',      // 关键：所有请求走 /dev-api，被 Vite 代理到 8080
  timeout: 10000
})
export default service
```
请求 `/dev-api/hello` → Vite 转成 `localhost:8080/hello` → **后端看来是同源**，无 CORS 问题。

## 方案 B：后端 CORS 配置（生产/接口直连时必需）
即便有代理，后端自己也要能处理跨域（比如别人直接调你 API、或生产 Nginx 没配好时）。写个配置类：

```java
package com.example.admin.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.cors.CorsConfiguration;
import org.springframework.web.cors.UrlBasedCorsConfigurationSource;
import org.springframework.web.filter.CorsFilter;

@Configuration
public class CorsConfig {

    @Bean
    public CorsFilter corsFilter() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowCredentials(true);              // 允许带 cookie/token
        config.addAllowedOriginPattern("*");        // 允许所有源（生产应写具体域名）
        config.addAllowedHeader("*");                // 允许所有请求头
        config.addAllowedMethod("*");                // 允许所有方法 GET/POST...
        config.setMaxAge(3600L);                   // 预检缓存 1 小时

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);  // 对所有路径生效
        return new CorsFilter(source);
    }
}
```

**解释**
- `setAllowCredentials(true)` + `addAllowedOriginPattern("*")`：注意**不能**同时用 `addAllowedOrigin("*")` + credentials，浏览器会拒。用 `Pattern` 版本才合法。
- `addAllowedMethod("*")`：包含 `OPTIONS`（浏览器预检请求 method）。
- 这是 **Filter 方式**（最早执行），比 `WebMvcConfigurer.addCorsMappings` 更稳（不会被 Security 拦截顺序影响）。

## 方案 C：生产 Nginx 反代（最终部署）
```nginx
server {
  listen 80;
  location / { proxy_pass http://localhost:80; }        # 前端静态
  location /prod-api/ {                              # 后端接口
    proxy_pass http://localhost:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```
前后端同域名 `example.com`，根本不存在跨域。

## 验证：前端真正打到后端
```js
// 临时在任一页面加
import request from '@/utils/request'
request.get('/hello').then(r => console.log(r))   // 应打印 "hello admin"
```
浏览器 Network 里：请求 URL 是 `localhost:80/dev-api/hello`，**Response** 来自 8080，无 CORS 红字。
