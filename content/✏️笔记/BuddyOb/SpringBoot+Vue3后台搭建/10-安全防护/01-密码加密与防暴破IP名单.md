# 10-1 密码加密 + 防暴破 + IP 黑名单

> 上接：[[SpringBoot+Vue3后台搭建/10-安全防护/00-索引]]
> 基础 BCrypt 已在 [[../03-后端基础框架/03-SpringSecurity与JWT鉴权]] 的 `SecurityConfig.passwordEncoder()` 埋好。这里讲"光加密还不够"的部分。

## 1.1 为什么必须用 BCrypt（而不是 MD5/SHA）

| 方案 | 问题 |
|------|------|
| 明文 | 库一泄露全完蛋 |
| MD5/SHA-1 | 无盐 + 快，**彩虹表**秒破 |
| **BCrypt** | 内置随机盐 + **自适应 cost**（算得慢，暴力破解成本极高） |

BCrypt 密文长这样：`$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy`。`$2a$` 是算法，`10` 是 cost（越大越慢）。**登录时 `passwordEncoder.matches(raw, encoded)` 比对，不用自己解**。

## 1.2 增强：密码策略 + 敏感字段加密

```java
// 注册/改密时校验强度（前端也校验，后端兜底）
public void validatePassword(String pwd) {
    if (pwd == null || pwd.length() < 8 || pwd.length() > 20)
        throw new BusinessException("密码需 8-20 位");
    if (!pwd.matches(".*[A-Za-z].*") || !pwd.matches(".*\\d.*"))
        throw new BusinessException("密码需含字母和数字");
}
```

> 身份证号、手机号等**敏感字段落库**要用 AES 对称加密（密钥放配置中心/KMS），不能明文。可用 Hutool `SecureUtil` 或 Spring `Encryptors`。

## 1.3 防暴破：登录失败计数锁账号

核心：用 Redis 记"某账号连续失败次数"，超阈值锁一段时间。在登录逻辑里接入：

```java
@Service
public class LoginAttemptService {
    @Resource private RedisCache redisCache;
    private static final int MAX_FAIL = 5;
    private static final long LOCK_SECONDS = 900; // 锁 15 分钟

    /** 登录失败时调用 */
    public void onFail(String username, String ip) {
        String key = "login:fail:" + username;
        Integer n = redisCache.getCacheObject(key);
        n = (n == null ? 0 : n) + 1;
        redisCache.setCacheObject(key, n, LOCK_SECONDS, TimeUnit.SECONDS);
        if (n >= MAX_FAIL) {
            redisCache.setCacheObject("login:lock:" + username, ip, LOCK_SECONDS, TimeUnit.SECONDS);
            // 记登录日志（[[../07-日志与监控/01-操作日志与登录日志]]），便于审计
            log.warn("账号 {} 连续失败{}次，已锁定，来源IP={}", username, n, ip);
        }
    }

    public void onSuccess(String username) {
        redisCache.deleteObject("login:fail:" + username);
        redisCache.deleteObject("login:lock:" + username);
    }

    /** 登录前检查是否锁定 */
    public void checkLocked(String username) {
        if (redisCache.hasKey("login:lock:" + username))
            throw new BusinessException("账号已被锁定，请 15 分钟后再试");
    }
}
```

接进 `LoginController.login`（在 `authenticationManager.authenticate` 前后）：

```java
loginAttemptService.checkLocked(body.getUsername());   // ① 先查锁
try {
    Authentication auth = authenticationManager.authenticate(...);
    loginAttemptService.onSuccess(body.getUsername());   // ② 成功清计数
    // ... 发 token
} catch (BadCredentialsException e) {
    loginAttemptService.onFail(body.getUsername(), getClientIp()); // ③ 失败累加
    throw new BusinessException(ErrorCode.PASSWORD_ERROR);
}
```

## 1.4 IP 黑名单（防批量暴破来源）

把"恶意 IP"放 Redis Set，用拦截器在**最前面**拦掉：

```java
@Component
public class IpBlacklistInterceptor implements HandlerInterceptor {
    @Resource private RedisCache redisCache;
    private static final String BLACK = "security:ip:blacklist";

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object h) {
        String ip = getClientIp(req);
        if (redisCache.getCacheSet(BLACK) != null
                && redisCache.getCacheSet(BLACK).contains(ip)) {
            res.setStatus(403);
            return false;   // 黑名单 IP 直接 403
        }
        return true;
    }
    // 运维接口可动态加黑：redisCache.setCacheSet(BLACK, ip)
}
```

> 生产更稳的做法是**在 Nginx/网关层**封 IP（L7 层挡掉，连 Tomcat 都不到）。应用内黑名单适合"运行时动态拉黑"场景。两者可叠加。

## 1.5 获取真实客户端 IP

反向代理（Nginx）后 `req.getRemoteAddr()` 拿到的是网关 IP，要从 `X-Forwarded-For` 取：

```java
public static String getClientIp(HttpServletRequest req) {
    String ip = req.getHeader("X-Forwarded-For");
    if (ip != null && !ip.isEmpty() && !"unknown".equalsIgnoreCase(ip))
        return ip.split(",")[0].trim();           // 取第一个（最原始客户端）
    ip = req.getHeader("X-Real-IP");
    return (ip != null && !ip.isEmpty()) ? ip : req.getRemoteAddr();
}
```
