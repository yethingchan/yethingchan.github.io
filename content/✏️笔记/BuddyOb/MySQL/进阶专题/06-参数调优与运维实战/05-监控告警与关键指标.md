# 06-参数调优 · 监控告警与关键指标

> 前置：[[MySQL/进阶专题/06-参数调优与运维实战/04-碎片整理与表空间]]

## 监控的目标

"数据库会不会挂、慢了没、有没有锁、连接够不够"——靠**指标 + 告警**提前发现，而不是等用户投诉。

## 采集：Prometheus + mysqld_exporter

```
mysqld_exporter（暴露 /metrics）──> Prometheus（拉取存储）──> Grafana（看板/告警）
```
- `mysqld_exporter` 连 MySQL 暴露几百个指标（连接、QPS、慢查询、InnoDB、复制延迟等）。
- 本仓库运维侧可照搬这套（和 RuoYi 的 Druid 监控互补：Druid 看连接池、exporter 看实例）。

## 必盯的关键指标

| 指标 | 含义 | 告警阈值（参考） |
|------|------|-------------------|
| `mysql_global_status_threads_connected` | 当前连接数 | > max_connections*0.8 |
| `mysql_global_status_threads_running` | 正在跑的 | 持续 > CPU 核数 → 慢/锁 |
| `mysql_global_status_slow_queries` | 慢查询计数 | 持续增长 → 有坏 SQL |
| `mysql_global_status_queries` | QPS | 突降/突增都异常 |
| `mysql_global_status_innodb_buffer_pool_reads` | 磁盘读次数 | 高 → 命中率低 |
| `mysql_global_status_innodb_row_lock_waits` | 行锁等待 | 高 → 锁冲突/死锁 |
| `mysql_slave_replica_lag_seconds` | 主从延迟 | > 5~10s 告警 |
| `mysql_global_status_aborted_connects` | 失败连接 | 突增 → 攻击/配置错 |
| `mysql_global_status_created_tmp_disk_tables` | 落盘临时表 | 高 → 缺索引/filesort |

## 慢查询日志（定位坏 SQL 的第一手）

```ini
slow_query_log = ON
long_query_time = 1          # 超 1 秒记慢日志
log_queries_not_using_indexes = ON   # 没走索引的也记（排查用）
slow_query_log_file = /var/log/mysql/slow.log
```
- 配套 `pt-query-digest` 汇总慢日志，找出"最耗时的 Top SQL"：
  ```bash
  pt-query-digest /var/log/mysql/slow.log | head -50
  ```
- 慢日志分析流程（见 [[MySQL/12-慢查询分析与调优]]）。

## 复制延迟监控

```sql
SHOW REPLICA STATUS\G     -- Seconds_Behind_Source 8.0 用 REPLICA，旧版 SLAVE
```
- exporter 暴露 `mysql_slave_replica_lag_seconds`。
- 告警：> 10s 持续 → 查从库负载/大事务（见 [[MySQL/进阶专题/04-高可用复制与集群/01-主从复制原理binlog三格式]]）。

## 锁与阻塞监控

```sql
SHOW PROCESSLIST;                       -- 看 State 卡在 'Sending data'/'Locked' 的
SELECT * FROM performance_schema.data_lock_waits;   -- 8.0 锁等待
SELECT * FROM performance_schema.metadata_locks;      -- 元数据锁（DDL 被 DML 阻塞常见）
```
> 长事务/锁等待 → 配合 [[MySQL/进阶专题/01-事务与锁深度/05-隔离级别实现与长事务危害]] 的 `innodb_trx` 监控。

## 资源监控（OS 层）

- **磁盘 IO**：`iostat -x 1` 看 `%util` / `await`。Buffer Pool 小、刷盘猛 → IO 100%。
- **内存**：`free -h`，确认给 MySQL 留够（别被 OS 缓存挤掉）。
- **CPU**：慢 SQL/大事务/Online DDL 排序会吃满 CPU。

## 告警分级

```
P0（立刻打电话）：
  - 主库宕机 / 连接数打满（Too many connections）
  - 主从延迟 > 60s / 复制断开
  - 磁盘空间 < 10%
P1（马上处理）：
  - 慢查询计数持续涨
  - 行锁等待高 / 死锁频繁
  - 复制延迟 10~60s
P2（关注）：
  - Buffer Pool 命中率下降
  - 碎片 data_free 偏大
  - 临时表落盘多
```

## Grafana 看板必备面板

1. **概览**：QPS、连接数、Threads_running、慢查询率。
2. **InnoDB**：Buffer Pool 命中率、脏页%、IO。
3. **复制**：延迟、IO/SQL 线程状态。
4. **锁**：行锁等待、长事务、死锁计数。
5. **资源**：CPU/内存/磁盘 IO。

## 结论

- 采集用 **mysqld_exporter + Prometheus + Grafana**（和 Druid 监控互补）。
- 必盯：连接数/Threads_running/慢查询/Buffer Pool 命中/行锁等待/主从延迟。
- 慢查询日志 + `pt-query-digest` 定位 Top 坏 SQL。
- 告警分级（P0/P1/P2），资源层 IO/内存/CPU 别漏。
