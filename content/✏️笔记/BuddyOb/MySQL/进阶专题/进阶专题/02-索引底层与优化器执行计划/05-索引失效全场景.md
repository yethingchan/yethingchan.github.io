# 02-索引底层 · 索引失效全场景

> 前置：[[MySQL/进阶专题/02-索引底层与优化器执行计划/04-EXPLAIN逐列精讲与key_len]] ｜ MyBatis 侧坑：[[MyBatis Mapper XML/进阶专题/04-批量与性能优化/04-性能陷阱N+1与类型开销]]

## 索引失效 = 明明有索引却走了 ALL

以下是**最常见**的失效场景，每个都能用 EXPLAIN 验证。

## 1) 隐式类型转换（最隐蔽）

```sql
-- phone 是 VARCHAR(20)
SELECT * FROM user WHERE phone = 13800000000;   -- 传了数字！
-- MySQL 把 phone 转成数字比较 → 索引失效，全扫
```
**规则**：索引列的类型 vs 传入参数类型不一致 → MySQL 对**列**做函数转换 → 索引用不上。
**解法**：参数类型与列一致（手机号用字符串 `'138...'`）。
> 这对应 MyBatis 里"`#{}` 参数类型与列类型不匹配"（见 MyBatis 04-04）。

## 2) 对索引列用函数 / 运算

```sql
SELECT * FROM user WHERE DATE(create_time) = '2026-01-01';  -- 函数包裹 → 失效
SELECT * FROM order WHERE amount * 1.1 > 100;              -- 运算 → 失效
```
**解法**：把运算移到参数侧：
```sql
SELECT * FROM user WHERE create_time >= '2026-01-01 00:00:00'
                          AND create_time <  '2026-01-02 00:00:00';
```

## 3) 前导模糊（最左 %）

```sql
SELECT * FROM user WHERE name LIKE '%张';   -- 前缀 % → 失效（全扫）
SELECT * FROM user WHERE name LIKE '张%';   -- 后缀 % 在右 → 能用索引（范围）
```
- `'张%'`：能定位 B+ 树前缀 → 走 `range`。
- `'%张'` / `'%张%'`：不知道开头 → 全扫。

## 4) 违反最左前缀

```sql
-- INDEX(a, b, c)
WHERE b=1 AND c=2;        -- 跳过 a → 失效
WHERE a=1 AND c=2;        -- a 用了，c 在 b 后断 → 只用到 a
```
**解法**：查询条件顺序要匹配索引最左；或调整索引顺序。

## 5) `OR` 连接非索引列

```sql
-- INDEX(age)，email 无索引
SELECT * FROM user WHERE age=20 OR email='a@x.com';
-- 因 email 无索引，OR 整体无法用 age 索引 → 全扫
```
**解法**：`OR` 两边都要有索引；或拆成 `UNION` 两个索引查询（见 Index Merge 02）。

## 6) 范围查询后面的列失效

```sql
-- INDEX(a, b, c)
WHERE a=1 AND b>10 AND c=2;
-- a 用上，b 是范围，b 之后（c）排序被打断 → c 用不上
```
**解法**：把"等值列"放范围列前面；或调整索引为 `(a, c, b)`（若 c 等值、b 范围）。

## 7) 优化器觉得"回表太贵"而弃用

```sql
-- INDEX(age)，但 SELECT *
SELECT * FROM user WHERE age BETWEEN 1 AND 99;
-- 命中 99% 行，优化器认为"几乎全表 + 每行回表"不如直接全扫 → 选 ALL
```
**解法**：缩小结果集，或建**覆盖索引**消除回表（见 02）。

## 8) 字符集 / 排序规则不一致

两表 JOIN，`utf8mb4_0900_ai_ci` vs `utf8mb4_general_ci` → 索引用不上。统一字符集/排序规则。

## 9) `NOT` / `!=` / `<>`

```sql
WHERE status != 0;   -- 多数情况索引失效（要扫除了 0 的所有）
```
个别情况优化器仍用范围，但一般不如等值。

## 排查口诀

```
失效先查：
  类型对不对？→ 隐式转换（传参类型）
  列被改没？→ 函数/运算/cast
  模糊怎么写？→ 前导 %
  顺序对不对？→ 最左前缀 / 范围断
  OR 了吗？→ 两边都要索引
  SELECT * 吗？→ 回表太贵被弃
```

## 结论

- 索引失效九成是**"对列做了转换/运算/模糊/顺序错"**。
- 每个场景都能用 `EXPLAIN type=ALL` + `key=NULL` 验证。
- 解法三板斧：参数类型对齐、函数移到参数侧、建覆盖/调整索引顺序。
