# 05 · 多表连接与子查询

> 进阶路线：[[00-总览与学习路线]] → L2 查询进阶 ｜ 前置：[[02-SQL分类与基础查询]]

实际业务几乎都要跨表。这一篇吃透 JOIN 与子查询。

## 1. JOIN 类型（重点记图）

```
   A ⋈ B (INNER)      A ⟕ B (LEFT)        A ⟖ B (RIGHT)
  两表交集           左全+右匹配(无则NULL)   右全+左匹配
```

```sql
-- 内连接：只返回两表都匹配的行
SELECT u.user_name, d.dept_name
FROM sys_user u
INNER JOIN sys_dept d ON u.dept_id = d.dept_id;

-- 左连接：以左表为准，右表无匹配补 NULL（最常用）
SELECT u.user_name, d.dept_name
FROM sys_user u
LEFT JOIN sys_dept d ON u.dept_id = d.dept_id;

-- 右连接（等价于调换左右表的 LEFT JOIN）
-- 全外连接 MySQL 不支持，用 UNION 模拟
```

> 经验：**优先用 LEFT JOIN**，可读性高；INNER 会悄悄过滤掉不匹配行，容易漏数据。

## 2. 多表连接 + 条件位置

```sql
SELECT ...
FROM A
LEFT JOIN B ON A.id = B.aid AND B.type = 1   -- 过滤放 ON：不匹配的 B 仍保留(NULL)
LEFT JOIN C ON A.id = C.aid
WHERE A.status = 0;                              -- 过滤放 WHERE：会过滤掉 NULL 行！
```

> ⚠️ **LEFT JOIN 的过滤条件放 `ON` 还是 `WHERE` 结果不同**：
> 放 `ON` 只影响右表匹配，左表行始终保留；放 `WHERE` 会把右表为 NULL 的左表行也删掉（退化成 INNER）。

## 3. 自连接

同一张表当两张用（树形/层级）：
```sql
SELECT e.user_name, m.user_name AS manager
FROM sys_user e
LEFT JOIN sys_user m ON e.manager_id = m.user_id;
```

## 4. 子查询

| 类型 | 位置 | 示例 |
|------|------|------|
| 标量子查询 | SELECT 列 | `SELECT (SELECT MAX(sal) FROM t2) AS mx` |
| 列子查询 | WHERE `IN` | `WHERE dept_id IN (SELECT dept_id FROM ...)` |
| 行子查询 | WHERE | `WHERE (a,b) = (SELECT a,b FROM ...)` |
| 表子查询 | FROM | `SELECT * FROM (SELECT ...) t` |

```sql
-- EXISTS：相关子查询，常用于"存在即..."（可用 JOIN 改写，通常更快）
SELECT * FROM sys_user u
WHERE EXISTS (SELECT 1 FROM sys_dept d WHERE d.dept_id = u.dept_id);
```

## 5. UNION / UNION ALL

```sql
SELECT col FROM t1
UNION ALL          -- ALL 不去重(快)；UNION 去重(排序代价)
SELECT col FROM t2;
```

> 列数、类型须一致；UNION 会去重（隐式 DISTINCT），不需要去重就用 `UNION ALL`。
