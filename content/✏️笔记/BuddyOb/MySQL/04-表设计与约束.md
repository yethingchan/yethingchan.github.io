# 04 · 表设计与约束

> 进阶路线：[[00-总览与学习路线]] → L1 基础 ｜ 上接：[[03-数据类型与字符集]]

## 1. CREATE TABLE 基本形态

```sql
CREATE TABLE sys_user (
  user_id    BIGINT       NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  user_name  VARCHAR(30)  NOT NULL DEFAULT '' COMMENT '用户名',
  dept_id    BIGINT       NULL COMMENT '部门',
  status     TINYINT      NOT NULL DEFAULT 0 COMMENT '状态 0正常 1禁用',
  create_time DATETIME     NULL COMMENT '创建时间',
  PRIMARY KEY (user_id),
  UNIQUE KEY uk_user_name (user_name),
  KEY idx_dept (dept_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

## 2. 六大约束

| 约束 | 关键字 | 作用 |
|------|--------|------|
| 主键 | `PRIMARY KEY` | 唯一且非空，一张表一个（可复合） |
| 唯一 | `UNIQUE [KEY]` | 值不重复（允许多个 NULL） |
| 非空 | `NOT NULL` | 禁止空值 |
| 默认 | `DEFAULT` | 未提供时填默认 |
| 外键 | `FOREIGN KEY ... REFERENCES` | 保证引用完整性 |
| 检查 | `CHECK (...)` | 8.0 生效，限制取值范围 |

```sql
-- 外键示例
ALTER TABLE sys_user
  ADD CONSTRAINT fk_user_dept FOREIGN KEY (dept_id)
  REFERENCES sys_dept(dept_id);
```

> **企业实践**：很多大厂**不用外键**，改由应用层保证（外键会拖慢写入、跨库难做）。但中小项目用外键更省心。

## 3. 自增主键 vs 业务主键 vs 雪花 ID

| 方案 | 优点 | 缺点 |
|------|------|------|
| `AUTO_INCREMENT` | 简单、连续、索引友好 | 暴露数量、分库分表难、单点 |
| 业务字段(如手机号) | 可读 | 易变、长、散列差 |
| **雪花算法 (BIGINT)** | 分布式唯一、趋势递增 | 依赖时钟、长度 18 位 |

> 结论：**默认用 `BIGINT` 自增或雪花 ID 做主键**；不要用 UUID 当聚簇主键（离散导致页分裂，详见 [[07-索引原理B+Tree]]）。

## 4. 存储引擎：InnoDB vs MyISAM

| 维度 | InnoDB（默认） | MyISAM |
|------|----------------|----------|
| 事务 | ✅ 支持 | ❌ |
| 行级锁 | ✅ | ❌（表锁） |
| 外键 | ✅ | ❌ |
| 崩溃恢复 | ✅（redo/undo） | ❌ |
| 全文索引 | ✅（8.0） | ✅ |
| 压缩/只读 | ❌ | ✅ 适合读多静态表 |

> **结论：无脑 InnoDB**。MyISAM 仅适合纯读、不更新的日志/报表场景。

## 5. 范式（设计理论，点到为止）

- **1NF**：字段原子不可再分。
- **2NF**：非主键字段完全依赖主键（消除部分依赖）。
- **3NF**：非主键字段不依赖其他非主键字段（消除传递依赖）。
- 实际常做**反范式**（冗余字段换查询快），用空间换时间。

## 6. 修改表结构（DDL）

```sql
ALTER TABLE sys_user ADD COLUMN age INT NULL;
ALTER TABLE sys_user MODIFY COLUMN user_name VARCHAR(50);
ALTER TABLE sys_user DROP COLUMN age;
ALTER TABLE sys_user ADD INDEX idx_status (status);
```

> ⚠️ 大表 `ALTER` 会锁表/重建，**生产用 `ONLINE DDL`（MySQL 8.0 多数 DDL 在线）或 pt-osc/gh-ost 工具**。
