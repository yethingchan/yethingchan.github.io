# 12 · 慢查询分析与调优

> 进阶路线：[[00-总览与学习路线]] → L3 性能原理 ｜ 前置：[[08-执行计划EXPLAIN]] ｜ [[09-索引设计与优化实战]] ｜ [[11-锁机制与并发控制]]

把前面知识落地成「线上排障 SOP」。

## 1. 开启慢查询日志

```sql
-- 配置文件 / my.cnf
slow_query_log = 1
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 1        -- 超过1秒记
log_queries_not_using_indexes = 1   -- 没用索引的也记
```

```sql
-- 运行时（会话级）
SET slow_query_log = 1;
SET long_query_time = 1;
```

## 2. 定位慢 SQL

- 看慢日志文件；
- 工具分析：`mysqldumpslow -s t /path/slow.log`（按时间排序）；
- Percona：`pt-query-digest slow.log`（更专业，出报表）。

## 3. 用 EXPLAIN 诊断（核心动作）

对慢 SQL 跑 `EXPLAIN`，按 [[08-执行计划EXPLAIN]] 看：
- `type=ALL` → 没用索引，全表扫 → 加索引。
- `key=NULL` → 优化器没选索引 → 检查隐式转换/函数（[[09-索引设计与优化实战]]）。
- `Extra: Using filesort / Using temporary` → 排序/分组无索引 → 建 `(过滤列, 排序列)` 组合索引。
- `rows` 巨大 → 扫描行多 → 索引选择性差或条件太宽。

## 4. 常见慢查询根因与对策

| 现象 | 根因 | 对策 |
|------|------|------|
| 全表扫 | 无索引 / 索引失效 | 建/修索引（避免函数、隐式转换） |
| 深度分页 `LIMIT 1000000,10` | 扫了 100 万行才取 | 游标分页：`WHERE id > ? LIMIT 10` |
| `LIKE '%xx%'` | 前导模糊无法用索引 | 改后缀模糊、`FULLTEXT`、或 ES |
| `SELECT *` | 无法覆盖索引、多回表、占带宽 | 只取所需列 |
| `COUNT(*)` 大表慢 | InnoDB 实时数 | 缓存计数 / 估算 |
| 联表无索引 | JOIN 字段无索引 | JOIN 字段加索引 |
| `Filesort` | ORDER BY 无索引 | 建 (WHERE列, ORDER BY列) |

```sql
-- 深分页改造（游标/游标分页）
SELECT * FROM orders WHERE id > 1000000 ORDER BY id LIMIT 10;
```

## 5. SHOW PROFILE（看耗时分布）

```sql
SET profiling = 1;
SELECT ...;              -- 执行目标 SQL
SHOW PROFILES;          -- 列出
SHOW PROFILE FOR QUERY 1;  -- 看各阶段(sending data/creating tmp)耗时
```

## 6. 调优的「三板斧」顺序

1. **改 SQL 写法**（避免 `SELECT *`、深分页、函数包裹列）。
2. **加/修索引**（覆盖、最左前缀、避免失效）。
3. **改结构/架构**（冗余字段反范式、分库分表，见 [[14-分库分表与高可用架构]]）。

> 永远先量后改：`EXPLAIN` 确认问题，改完再 `EXPLAIN` 验证，别盲猜。
