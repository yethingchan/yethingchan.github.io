# 04-2 自定义训练与调优

> 上接：[[halcon/进阶专题/04-深度学习进阶/00-索引]]

## 原理一句话
把 HALCON DL 跑起来只是开始。真正决定上线效果的是：**学习率/批次怎么设、类不平衡怎么处理、loss 不降怎么诊断、用什么指标评估**。这一篇讲"炼丹"的工程细节。

## 核心参数与诊断

```halcon
* 1) 学习率（最敏感的超参）
set_dl_model_param (DLModel, 'learning_rate', 0.0005)
*    太大→震荡不收敛；太小→训练极慢。用 'adaptive' 让它自动调度
set_dl_model_param (DLModel, 'lr_schedule', 'adaptive')

* 2) 批次大小（受 GPU 显存限制，越大越稳但越慢）
set_dl_model_param (DLModel, 'batch_size', 8)

* 3) 类不平衡：给稀有类更大权重（而非简单过采样）
*    class_weights 与样本数成反比
set_dl_model_param (DLModel, 'class_weights', [1.0, 5.0, 5.0])
*    假设 3 类，后两类样本极少 → 权重拉高，loss 更关注它们

* 4) 训练 + 监控
train_dl_model (DLModel, DLDataset, 100, \
                ['loss','accuracy'], \
                DLTrainResult, TrainInfos, _)
*    用 DLTrainResult 看每 epoch 的 loss/acc 曲线
```

**逐行解释**：
- `lr_schedule='adaptive'`：HALCON 在验证集 loss 停滞时自动降学习率（类似 ReduceLROnPlateau），新手友好。
- `class_weights`：直接修改 loss 中各类的贡献。**这是处理"坏样本极少"的正解**——否则网络为刷总准确率会直接"全预测为好件"。
- `train_dl_model` 返回的 `TrainInfos` 含逐 epoch 曲线，是诊断过拟合/欠拟合的第一手资料。

## 诊断清单（实战必背）
| 现象 | 可能原因 | 对策 |
|------|---------|------|
| loss 不降、acc 随机 | 学习率过大/数据没归一 | 降 lr、检查预处理 |
| train 降但 val 升 | 过拟合 | 增强、冻结层、早停、权重衰减 |
| 只预测多数类 | 类不平衡 | class_weights、过采样 minority |
| 推理慢 | batch/分辨率大 | 降分辨率、GPU、量化 |
| 漏检小目标 | 锚框/下采样 | 用实例分割、调 anchor |

## 评估指标
别只看 acc。工业要看：**精确率(P)、召回率(R)、F1、mAP**（检测/分割）、**ROC-AUC**（AD）。HALCON `evaluate_dl_model` 直接出这些，`gen_dl_model_heatmap` 还能可视化"网络在看哪"。
