# 06-3 并行与多线程节拍

> 上接：[[halcon/进阶专题/06-性能与工程化专题/00-索引]]

## 为什么单帧快还不够
产线节拍（如 200ms/件）要求的是**端到端吞吐**。单帧算法 50ms，但若"取图→算法→结果回传"串行且中间有等待，整体仍超节拍。要系统性优化。

## 三层次并行
```
① 算子内并行：set_system('parallelize_operators','true')
             HALCON 自动把可数据并行的算子用多核
② 图像级并行：把一张大图切成 N 块，N 线程各跑一块
             （适合超大图/卷材分块）
③ 工位/相机级并行：多相机/多工位各一线程，结果汇总
```

## C# 多线程骨架（工位级）
```csharp
// 每个相机一个线程，跑自己的 HDevEngine 实例（引擎非线程安全！）
Task[] tasks = cameras.Select(cam => Task.Run(() => {
    var eng = new HDevEngine();          // 每线程独立引擎
    eng.SetProcedurePath(procDir);
    RunInspect(cam, eng);                // 取图→算法→结果
})).ToArray();
Task.WaitAll(tasks);
```
> 注意：HDevEngine **每线程一个实例**（见 [[halcon/进阶专题/06-性能与工程化专题/01-HDevEngine嵌入]]），不可共享。

## 节拍优化清单
1. **流水化（pipeline）**：当前件做"算法"时，下一件同时"取图"——用双缓冲/生产者消费者队列重叠时间。
2. **ROI 限定**：`reduce_domain` 只算感兴趣区，省掉全图无用计算。
3. **模型/模板全局复用**：`create_shape_model` 等**只建一次**，别每帧重建（最大性能坑）。
4. **预分配**：循环外 new 对象，循环内 reuse，减少 GC 抖动。
5. **异步回传**：结果通过消息队列异步给 PLC/UI，别阻塞算法线程。
6. **测耗时定位瓶颈**：`count_seconds` 给各阶段打点，先优化最慢那段（80/20 法则）。

## 关键坑
- 共享资源（结果队列、日志）要加锁，避免竞态。
- GPU 是**全局唯一**设备，多线程都抢——DL 推理多线程反而要串行或限定并发数，否则显存炸。
- 线程数 ≠ 核数越多越好，I/O 密集可超配，计算密集别超物理核。
