# L5-3 企业级部署与最佳实践

> 前置：[[halcon/18-性能优化与并行处理]]
> 上接总览：[[halcon/00-总览与学习路线]]

## 1. 工程化结构

```
VisionApp/
├─ Models/          # .shm .omc .mlp .hdl 模型文件（版本管理）
├─ Config/          # 参数 JSON（阈值、ROI、相机 SN）
├─ Logs/            # 运行日志 + 坏图存档（追溯）
├─ Core/           # HALCON 算法封装（与 UI 解耦）
└─ UI/             # WinForm/WPF 界面
```
- **算法与界面解耦**：Core 层只暴露 `Process(Image) → Result`，便于单测和换 UI。

## 2. 参数外置与可视化调参

- 阈值、ROI、相机参数全部放 **JSON/XML 配置文件**，不硬编码。
- 提供**调试模式**：显示中间结果（区域、轮廓、得分），现场调参不改代码。

## 3. 健壮性与异常处理

```csharp
try {
    HOperatorSet.FindShapeModel(...);
} catch (HOperatorException ex) {
    // 记录错误码 + 存当前坏图
    Logger.Error($"匹配失败: {ex.Message}");
    SaveDebugImage(image, "fail_match");
}
```
- 所有 HALCON 调用包 try-catch，失败时**存图溯源**。
- 通信超时、相机掉线要能重连并报警。

## 4. 相机与触发稳定

- 产线用**硬件触发**（PLC/编码器），保证拍照时机。
- 相机掉线检测 + 自动重连。
- 多相机用**统一时钟/触发同步**。

## 5. 日志与追溯（质量体系要求）

- 每帧记录：时间、SN、结果、关键尺寸、置信度。
- 坏图/可疑图自动存档，供 SPC 分析与复判。
- 结果对接 MES/数据库。

## 6. 版本与模型管理

- 模型文件纳入版本控制（或单独模型服务器）。
- 上线模型需**留上一版可回滚**。
- 算法变更走评审 + 回归测试集。

## 7. 部署与运维

- 目标机装 **HALCON Runtime License**（开发用 full，部署用 runtime）。
- 注意 HALCON 版本、位数（x64）与开发机一致。
- 用 **HDevEngine** 可热更新 `.hdev` 逻辑而无需重编译。

## 8. 企业级自检清单（最终达标）

- [ ] 算法封装为独立 Core，UI 可换
- [ ] 参数全外置，支持现场无代码调参
- [ ] 异常全捕获 + 坏图存档 + 日志
- [ ] 模型有版本、可回滚
- [ ] Runtime License 正确、性能达标产线节拍
- [ ] 对接 MES/数据库，结果可追溯
