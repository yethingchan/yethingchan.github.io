# MySQL 与 Redis 学习路线

> 对应 Java 全栈路线思维导图「数据与框架」第一叶。后端存储双支柱：持久化 + 缓存。

## 一、学习阶段

### 入门：能存能取
- MySQL：建库建表、CRUD、常用类型、索引初识
- Redis：五种结构（String/Hash/List/Set/ZSet）、基本命令

### 进阶：懂原理与优化
- MySQL：索引（B+树、聚簇/二级、最左前缀、覆盖索引、回表）
- 事务：ACID、隔离级别、MVCC、幻读
- 锁：行锁/表锁、间隙锁、死锁
- SQL 优化：EXPLAIN、慢查询
- Redis：持久化（RDB/AOF）、过期与淘汰、主从/哨兵/Cluster

### 高级：能扛量与排错
- 分库分表（垂直/水平、sharding）
- 缓存三连：击穿 / 雪崩 / 穿透，布隆过滤器
- 分布式锁（SET NX）、缓存与数据库一致性
- 大表治理、慢 SQL 治理

## 二、关键要点与常见坑
- 索引不是越多越好，写多读少表要克制
- 最左前缀失效：范围查询后索引断、函数包裹失效
- 缓存与 DB 双写一致性：先更新 DB 再删缓存（延迟双删）
- Redis 大 key / 热 key 是性能杀手

## 三、实战
- 入门：电商商品表 + 用 Redis 做详情页缓存
- 进阶：秒杀库存用 Redis 预扣减 + MySQL 落库

## 六、心法
1. MySQL 管"准"，Redis 管"快"；各司其职。
2. 缓存的坑比缓存本身多，先想一致性再想性能。
3. 索引和 EXPLAIN 是 SQL 优化的两把钥匙。
