# 微服务与分布式学习路线

> 对应 Java 全栈路线思维导图「架构与实战」第一叶。从"能写"到"能架构"的跃迁。

## 一、学习阶段

### 入门：懂概念
- 单体 vs 微服务、SOA
- 服务拆分原则（单一职责、独库、团队边界）
- CAP / BASE 理论

### 进阶：懂组件（见对应路线）
- 注册配置：Nacos
- 远程调用：OpenFeign / Dubbo
- 网关：Spring Cloud Gateway
- 容错：Sentinel
- 消息：Kafka / RabbitMQ
- 分布式事务：Seata（AT/TCC/Saga）

### 高级：能落地与治理
- 服务粒度与边界（康威定律）
- 分布式锁、分布式 ID（雪花）
- 链路追踪、全链路压测
- 灰度、蓝绿、滚动发布

## 二、关键要点与常见坑
- 过早微服务是灾难，先单体后拆分
- 分布式事务能避则避，最终一致优先
- 服务边界划错，比不拆还痛
- 没有监控的微服务是盲人骑马

## 三、实战
- 入门：拆出用户/订单/库存三服务 + 网关
- 进阶：加链路追踪 + 熔断 + 分布式事务的完整电商骨架

## 四、衔接
- 前置《SpringCloud》《MQ 与 RPC 与 Nacos》
- 联动《高并发与高可用》《K8s 与 CI-CD 与监控》

## 五、资源
- 《微服务架构设计模式》（Chris Richardson）；《凤凰架构》

## 六、心法
1. 微服务解决"大"，代价是"复杂度"，先问值不值。
2. 拆分看边界，治理看监控，缺一不可。
3. 一致性是分布式第一难题，能最终一致就别强一致。
