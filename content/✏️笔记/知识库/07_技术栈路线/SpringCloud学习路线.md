# SpringCloud 学习路线

> 对应 Java 全栈路线思维导图「数据与框架」第四叶。微服务全家桶，架构岗进阶必备。

## 一、学习阶段

### 入门：服务能拆能调
- 为什么微服务：单体痛点到服务拆分
- 注册中心：Nacos（注册发现 + 配置）
- 远程调用：OpenFeign、RestTemplate
- 网关：Spring Cloud Gateway（路由/过滤）

### 进阶：治理与容错
- 熔断限流：Sentinel（流控/降级/热点）
- 配置中心：Nacos / Apollo 动态配置
- 分布式事务：Seata（AT/TCC）
- 链路追踪：SkyWalking / Sleuth

### 高级：能落地一套微服务
- 服务拆分原则（单一职责、独库）
- 网关鉴权、灰度发布
- 容器化部署（Docker/K8s，见对应路线）
- 全链路压测与监控

## 二、关键要点与常见坑
- 别为了微服务而微服务，小团队单体更稳
- 分布式事务能避则避（最终一致 > 强一致）
- 熔断阈值要压测得出，别拍脑袋
- 配置中心改了要能回滚

## 三、实战
- 入门：用户/订单两个服务 + Nacos + Gateway 打通
- 进阶：加 Sentinel 限流 + Seata 下单扣库存

## 六、心法
1. 微服务解决"大"，也带来"复杂度"，先问值不值。
2. 注册/配置/网关/容错是四块基石，先搭稳。
3. 分布式事务是深坑，能用最终一致就别强一致。
