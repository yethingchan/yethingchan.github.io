```env
# MySQL异步连接地址
MYSQL_DATABASE_URI=mysql+asyncmy://root:123456@localhost:3306/test_db?charset=UTF8MB4
```
解释：

`root:123456`：数据库账号:密码
`localhost:3306`：数据库地址端口
`test_db`：要操作的数据库名
`charset=UTF8MB4`：支持中文、emoji字符集

## 2. config.py 配置读取（Pydantic读取.env）
```python
# 导入读取环境变量专用父类
from pydantic_settings import BaseSettings

# 全局配置类，继承BaseSettings自动读取.env
class Settings(BaseSettings):
    # 定义变量，对应.env里的MYSQL_DATABASE_URI，缺失直接报错
    MYSQL_DATABASE_URI: str

    # 内部Config子类，配置读取规则
    class Config:
        env_file = ".env"       # 指定读取当前目录下.env文件
        env_file_encoding = "utf-8" # 文件编码

# 实例化全局唯一配置对象，整个项目共用
config = Settings()
```
逐行拆解：
1. `from pydantic_settings import BaseSettings`
普通`BaseModel`只能校验内存数据；`BaseSettings`额外支持自动读取操作系统环境变量、.env文件。
2. `MYSQL_DATABASE_URI: str`
声明必填字符串变量，程序启动时会去.env匹配同名key，找不到直接抛出`Field required`报错（你之前启动报错就是这里）。
3. `class Config:`
Pydantic内置配置类，固定名称不能修改，用来控制模型读取/序列化行为。
4. `env_file = ".env"`
告诉程序环境变量文件名称，不写则不会读取.env。
5. `config = Settings()`
实例化一次，后续所有文件导入这个`config`即可拿到数据库地址。

## 3. database.py 数据库连接公共底层
```python
# 导入异步引擎、异步会话对象
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession
# 会话工厂、ORM基类
from sqlalchemy.orm import declarative_base, sessionmaker
# 导入全局数据库地址配置
from config import config

# 1. 创建异步数据库引擎（全局唯一数据库连接核心）
engine = create_async_engine(config.MYSQL_DATABASE_URI, echo=False)
# 参数说明：
# config.MYSQL_DATABASE_URI：数据库连接地址
# echo=False：关闭SQL打印，开发可改为True查看执行SQL

# 2. 创建异步会话工厂，用来生成数据库连接
AsyncSessionLocal = sessionmaker(
    bind=engine,               # 绑定上面创建的数据库引擎
    class_=AsyncSession,       # 使用异步会话对象
    expire_on_commit=False     # 提交后不自动失效数据，方便提交后读取数据
)

# 3. ORM基类，所有数据表模型必须继承这个Base
Base = declarative_base()

# 4. 依赖函数：接口自动获取数据库会话
async def get_db() -> AsyncSession:
    # 自动创建会话
    async with AsyncSessionLocal() as session:
        # 把会话交给接口使用，接口执行完自动关闭释放连接
        yield session
```
逐行解释：
1. `create_async_engine`
创建数据库连接池，管理所有MySQL连接，异步非阻塞，FastAPI高性能核心。
2. `sessionmaker`
会话生成器，每次接口请求生成一个独立数据库会话，隔离事务。
3. `expire_on_commit=False`
执行`commit()`提交数据后，数据库对象不会清空属性，提交后依然能读取id等自增字段。
4. `Base = declarative_base()`
SQLAlchemy所有数据表的父类，后续`models`里的表都继承`Base`，才能自动映射数据库。
5. `async def get_db()`
FastAPI依赖注入专用函数，`Depends(get_db)`会自动执行这个函数拿到db会话。
6. `async with AsyncSessionLocal() as session`
上下文管理器，请求结束自动关闭会话，避免数据库连接泄漏。
7. `yield session`
把session会话传给接口，函数暂停；接口执行完毕后继续执行上下文关闭逻辑。

## 4. models/skill.py 数据库表映射（SQLAlchemy实体）
```python
# 导入字段类型
from sqlalchemy import Column, Integer, String, Float
# 导入ORM基类Base
from database import Base

# 技能数据表，映射MySQL真实表 tb_skill
class Skill(Base):
    # 指定数据库真实表名
    __tablename__ = "tb_skill"

    # 主键自增ID
    id = Column(Integer, primary_key=True, autoincrement=True, comment="主键ID")
    # 技能名称，字符串50长度，不允许为空
    skill_name = Column(String(50), nullable=False, comment="技能名称")
    # 技能价格，浮点型，不能为空
    price = Column(Float, nullable=False, comment="技能价格")
```
逐行解释：
1. `Column(Integer, primary_key=True)`
定义数据库字段，Integer整型；primary_key=True标记为主键。
2. `autoincrement=True`
主键自动自增，新增数据不用手动传id。
3. `String(50)`
varchar(50)字符串类型，限制最大长度50。
4. `nullable=False`
数据库层面约束该字段不能为空，插入不传会直接数据库报错。
5. `__tablename__ = "tb_skill"`
固定属性，告诉SQLAlchemy这个类对应MySQL哪一张表。
6. `comment="xxx"`
字段注释，生成数据库文档时可见。

## 5. schemas/skill.py Pydantic数据模型（校验+序列化）
```python
# 基础模型、字段校验工具
from pydantic import BaseModel, Field
# 可选类型
from typing import Optional

# 新增技能：前端POST提交参数校验模型
class SkillCreate(BaseModel):
    # 技能名称，最小2字符最大50字符，接口文档描述
    skill_name: str = Field(min_length=2, max_length=50, description="技能名称")
    # 价格必须大于0
    price: float = Field(gt=0, description="技能单价")

# 修改技能：所有字段可选，不传不更新
class SkillUpdate(BaseModel):
    skill_name: Optional[str] = None
    price: Optional[float] = None

# 返回给前端的模型，控制输出字段
class SkillResp(BaseModel):
    id: int
    skill_name: str
    price: float

    # ORM兼容配置，允许数据库SQLAlchemy对象直接转模型
    class Config:
        from_attributes = True
```
逐行拆解：
1. `BaseModel`
Pydantic基础模型，自带类型校验、自动转换、序列化能力。
2. `Field(min_length=2, max_length=50)`
字段约束：字符串长度限制，前端传参不满足直接返回错误，不用自己写if判断。
3. `gt=0`
greater than 0，数字必须大于0，价格不能为负数。
4. `Optional[str] = None`
代表字段可选，前端不传该参数时默认值为None。
5. `SkillResp`
专门用于接口返回，只定义需要展示给前端的字段，可隐藏数据库密码、创建时间等敏感字段。
6. `from_attributes = True`
核心配置：让Pydantic可以读取SQLAlchemy数据库对象的属性，不用手动循环赋值。

## 6. crud/skill.py 纯数据库操作层（增删改查封装）
```python
# 异步会话
from sqlalchemy.ext.asyncio import AsyncSession
# 数据库查询语句
from sqlalchemy import select, update, delete
# 数据表实体
from models.skill import Skill
# 入参校验模型
from schemas.skill import SkillCreate, SkillUpdate

# 新增技能
async def create_skill(db: AsyncSession, data: SkillCreate):
    # model_dump()把Pydantic对象转为字典，**解包赋值给Skill数据库实体
    db_obj = Skill(**data.model_dump())
    # 添加到数据库会话缓存
    db.add(db_obj)
    # 提交事务，写入MySQL
    await db.commit()
    # 刷新对象，获取数据库生成的自增id
    await db.refresh(db_obj)
    # 返回完整数据库对象
    return db_obj

# 根据ID查询单条技能
async def get_skill_by_id(db: AsyncSession, sid: int):
    # 构建查询语句 select * from tb_skill where id = sid
    stmt = select(Skill).where(Skill.id == sid)
    # 执行SQL语句
    res = await db.execute(stmt)
    # 获取单条数据，无数据返回None
    return res.scalar_one_or_none()

# 修改技能
async def update_skill(db: AsyncSession, sid: int, update_data: SkillUpdate):
    # exclude_unset=True：只保留前端实际传入的字段，忽略没传的None字段
    data_dict = update_data.model_dump(exclude_unset=True)
    # 构建更新语句 update tb_skill set xxx where id=sid
    stmt = update(Skill).where(Skill.id == sid).values(**data_dict)
    # 执行更新
    await db.execute(stmt)
    # 提交事务
    await db.commit()
    # 更新完成后重新查询最新数据返回
    return await get_skill_by_id(db, sid)

# 删除技能
async def delete_skill(db: AsyncSession, sid: int):
    # 删除语句 delete from tb_skill where id=sid
    stmt = delete(Skill).where(Skill.id == sid)
    await db.execute(stmt)
    await db.commit()
    return True
```
逐行解释关键代码：
1. `data.model_dump()`
Pydantic模型转标准Python字典，`model_dump()`替代旧版`dict()`。
2. `db.add(db_obj)`
把数据加入会话缓冲区，此时还没写入数据库，仅存在内存。
3. `await db.commit()`
提交事务，缓冲区数据真正写入MySQL；多语句要么全部成功，要么全部回滚。
4. `await db.refresh(db_obj)`
主动查询数据库，把自增id、默认值等数据库生成的值同步到对象里。
5. `select(Skill).where(Skill.id == sid)`
ORM查询语法，等价原生SQL `SELECT * FROM tb_skill WHERE id = ?`。
6. `res.scalar_one_or_none()`
提取查询结果中的ORM对象，匹配到数据返回对象，无匹配返回None，不会抛出报错。
7. `model_dump(exclude_unset=True)`
只序列化前端主动传递的字段，用户没传的字段忽略，避免把字段覆盖成null。
8. `update().values(**data_dict)`
动态更新传入的字段，不用手动写每一列。
9. `delete()`
构造删除语句，执行后commit永久删除数据。

## 7. api/skill.py 路由接口层（对接前端请求）
```python
# 路由分组、依赖、异常
from fastapi import APIRouter, Depends, HTTPException
# 异步数据库会话
from sqlalchemy.ext.asyncio import AsyncSession
# 导入获取数据库会话的依赖函数
from database import get_db
# 入参、返回模型
from schemas.skill import SkillCreate, SkillUpdate, SkillResp
# 封装好的CRUD方法
from crud.skill import create_skill, get_skill_by_id, update_skill, delete_skill

# 创建路由分组对象
router = APIRouter()

# 新增技能接口 POST /skill/add
@router.post("/add", response_model=SkillResp)
async def add_skill(
    # 前端JSON自动解析为SkillCreate，自动校验参数
    form: SkillCreate,
    # 自动注入数据库会话db
    db: AsyncSession = Depends(get_db)
):
    # 调用CRUD层新增方法，传入会话和校验好的数据
    new_skill = await create_skill(db=db, data=form)
    # 返回数据库对象，FastAPI自动用SkillResp过滤字段转JSON
    return new_skill

# 根据ID查询单条 GET /skill/{skill_id}
@router.get("/{skill_id}", response_model=SkillResp)
async def get_skill(skill_id: int, db: AsyncSession = Depends(get_db)):
    # 调用CRUD查询方法
    skill = await get_skill_by_id(db, skill_id)
    # 判断是否查询到数据，无数据抛出404异常
    if not skill:
        raise HTTPException(status_code=404, detail="技能不存在")
    return skill

# 修改技能 PUT /skill/{skill_id}
@router.put("/{skill_id}", response_model=SkillResp)
async def modify_skill(skill_id: int, form: SkillUpdate, db: AsyncSession = Depends(get_db)):
    # 先判断数据是否存在
    skill = await get_skill_by_id(db, skill_id)
    if not skill:
        raise HTTPException(status_code=404, detail="技能不存在")
    # 调用CRUD更新方法
    return await update_skill(db, skill_id, form)

# 删除技能 DELETE /skill/{skill_id}
@router.delete("/{skill_id}")
async def remove_skill(skill_id: int, db: AsyncSession = Depends(get_db)):
    skill = await get_skill_by_id(db, skill_id)
    if not skill:
        raise HTTPException(status_code=404, detail="技能不存在")
    await delete_skill(db, skill_id)
    return {"msg": "删除成功"}
```
逐行核心代码解释：
1. `router = APIRouter()`
创建独立路由分组，用于统一加前缀、标签，区分不同业务模块（用户/技能/订单）。
2. `@router.post("/add")`
定义POST接口路径，对应前端新增操作。
3. `response_model=SkillResp`
强制接口返回数据按照SkillResp模型序列化，自动过滤多余字段，自动生成接口文档。
4. `form: SkillCreate`
FastAPI自动读取POST请求体JSON，转为Pydantic对象；参数不合法直接返回错误，不进入函数。
5. `db: AsyncSession = Depends(get_db)`
依赖注入，自动执行`get_db()`拿到数据库会话，每个请求独立连接。
6. `await create_skill(db=db, data=form)`
调用CRUD层纯数据库逻辑，接口层不写任何SQL，解耦。
7. `raise HTTPException(status_code=404, detail="技能不存在")`
主动抛出标准HTTP错误，前端收到404提示文案。
8. `@router.get("/{skill_id}")`
路径参数，url中数字自动转为int类型skill_id。

## 8. main.py 项目总入口、路由聚合
```python
# 框架核心
from fastapi import FastAPI
# 跨域中间件
from fastapi.middleware.cors import CORSMiddleware
# 导入技能模块路由
from api.skill import router as skill_router

# 创建FastAPI服务实例
app = FastAPI(title="技能管理后端", version="1.0")

# 配置跨域，允许前端页面跨域访问接口
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],        # 允许所有前端域名，生产环境写具体域名
    allow_credentials=True,     # 允许携带cookie/token
    allow_methods=["*"],        # 允许所有请求方式 GET/POST/PUT/DELETE
    allow_headers=["*"],        # 允许所有请求头
)

# 注册技能路由，统一前缀 /skill，接口文档分组标签
app.include_router(skill_router, prefix="/skill", tags=["技能管理"])

# 项目启动入口命令：uvicorn main:app --reload
# main：当前文件名main.py
# app：上面创建的FastAPI实例
# --reload：开发热更新，修改代码自动重启服务
```
逐行解释：
1. `app = FastAPI(title="技能管理后端")`
初始化服务，title会展示在自动生成的接口文档页面。
2. `CORSMiddleware`
跨域中间件，前端Vue/React本地调试时，浏览器会拦截跨域请求，配置后放行。
3. `app.include_router()`
把api里的分组路由注册到总服务，统一加上`/skill`前缀。
4. `prefix="/skill"`
所有skill接口自动拼接前缀，例如`/add`完整地址变成`/skill/add`。
5. `tags=["技能管理"]`
接口文档页面把该模块接口归类到「技能管理」分组，方便查看。

# 完整一条请求数据流逐行走一遍（前端新增技能）
1. 前端POST `http://127.0.0.1:8000/skill/add` 传JSON
2. `main.py` 注册了skill路由，请求转发到`api/skill.py`的add_skill函数
3. `form: SkillCreate` 自动校验JSON，名称长度、价格合法性，非法直接返回报错
4. `Depends(get_db)` 自动执行database.py的get_db，拿到异步数据库会话db
5. 函数执行 `await create_skill(db=db, data=form)`，进入crud/skill.py
6. `data.model_dump()` 将校验后的Pydantic转为字典，赋值给models.Skill数据表对象
7. `db.add()` 加入会话缓冲区，`await db.commit()` 写入MySQL
8. `await db.refresh()` 同步数据库自增id，返回数据库对象逐层回传
9. 回到api接口，`response_model=SkillResp` 自动过滤字段，转为标准JSON返回前端

# 分层调用铁律（代码引用方向）
```
main.py → api/xxx.py → crud/xxx.py → models/xxx.py
config.py → database.py → api/crud
schemas.py → api + crud
```
禁止反向引用：crud不能导入api，models不能导入crud，分层单向流转，代码好维护。
