# 01 - 项目架构设计

> 本文详细讲解上位机项目的常见架构模式，帮助你设计出可维护、可扩展的上位机系统。

---

## 一、知识讲解

### 1.1 上位机项目常见架构概览

上位机软件通常需要处理通信、数据存储、业务逻辑和用户界面等多个方面的工作。选择合适的架构直接决定了项目的可维护性和可扩展性。

| 架构类型 | 适用场景 | 优点 | 缺点 |
|----------|----------|------|------|
| **单层架构** | 简单工具、demo、小型测试工具 | 开发快速、结构简单 | 难以维护、代码耦合严重 |
| **分层架构** | 中小型上位机项目（推荐） | 职责清晰、易于测试和维护 | 需要提前设计，学习成本略高 |
| **插件化架构** | 大型上位机平台、需要支持多种设备 | 极其灵活、可热插拔 | 复杂度高、开发周期长 |

### 1.2 分层架构详解

分层架构是上位机项目中最推荐的架构模式，它将系统分为三个核心层次：

```
┌─────────────────────────────────────────┐
│           UI 表现层 (Presentation)        │
│    ┌──────────┐ ┌──────────┐             │
│    │  主界面   │ │  设置界面  │  数据查询界面 │
│    └──────────┘ └──────────┘             │
├─────────────────────────────────────────┤
│         业务逻辑层 (Business Logic)       │
│    ┌──────────┐ ┌──────────┐             │
│    │ 报警管理  │ │ 数据处理  │  配置管理    │
│    └──────────┘ └──────────┘             │
├─────────────────────────────────────────┤
│         数据/通信层 (Data/Comm)           │
│    ┌──────────┐ ┌──────────┐             │
│    │ PLC通信   │ │ 数据库    │  文件系统    │
│    └──────────┘ └──────────┘             │
└─────────────────────────────────────────┘
```

**各层职责说明：**

| 层次 | 职责 | 关键原则 |
|------|------|----------|
| **UI表现层** | 负责界面展示、用户交互、数据显示 | 只负责显示和接收用户操作，不包含业务逻辑 |
| **业务逻辑层** | 负责数据处理、报警判断、设备状态管理 | 核心业务规则在此层，不依赖具体的UI控件 |
| **数据/通信层** | 负责PLC通信、数据库操作、文件读写 | 提供统一的数据访问接口，屏蔽底层细节 |

**层间交互规则：**
- 上层可以调用下层，下层不能直接调用上层
- 层与层之间通过接口进行交互
- 每层只依赖下一层的接口，不依赖具体实现

### 1.3 MVVM模式在WinForms中的应用

MVVM（Model-View-ViewModel）是一种UI架构模式，在WPF中被广泛使用。虽然WinForms原生不直接支持数据绑定，但我们可以手动实现MVVM的核心思想。

**MVVM三个核心组件：**

| 组件 | 职责 | 示例 |
|------|------|------|
| **Model（模型）** | 数据实体和业务数据 | PlcData、AlarmRecord、DeviceConfig |
| **View（视图）** | UI界面 | MainForm、SettingForm |
| **ViewModel（视图模型）** | 连接View和Model的桥梁，处理UI逻辑 | MainViewModel、SettingViewModel |

**在WinForms中实现MVVM的要点：**
- ViewModel通过事件（INotifyPropertyChanged）通知View更新
- View通过订阅ViewModel的事件来响应数据变化
- ViewModel不引用任何UI控件

### 1.4 依赖注入基础

依赖注入（Dependency Injection，简称DI）是一种设计原则，核心思想是：**不要在类内部创建依赖对象，而是从外部传入**。

**为什么要用依赖注入？**

| 场景 | 不使用DI（硬编码） | 使用DI |
|------|-------------------|--------|
| 切换PLC品牌 | 需要修改多处代码，容易遗漏 | 只需更换注册的实例 |
| 单元测试 | 无法Mock通信对象 | 可以轻松注入Mock对象 |
| 代码复用 | 类之间强耦合 | 类之间松耦合，可独立使用 |

**依赖注入的三种方式：**

1. **构造函数注入（推荐）**：通过构造函数参数传入依赖
2. **属性注入**：通过公共属性设置依赖
3. **方法注入**：通过方法参数传入依赖

### 1.5 接口设计

在上位机项目中，定义良好的接口是分层架构的基础。以下是核心接口设计：

**ICommunicationService - 通信服务接口：**
- 负责与PLC等设备的数据通信
- 支持连接/断开/读写操作

**IDataService - 数据服务接口：**
- 负责数据的存储和查询
- 屏蔽具体的数据库实现细节

**IAlarmService - 报警服务接口：**
- 负责报警条件的检测和管理
- 提供报警记录的存储和查询

```csharp
// ============================================================
// 文件：ICommunicationService.cs
// 说明：通信服务接口 - 定义所有通信设备必须实现的功能
// ============================================================
namespace HwPlcMonitor.Core.Interfaces
{
    /// <summary>
    /// 通信服务接口
    /// 所有PLC通信实现类都必须实现此接口
    /// </summary>
    public interface ICommunicationService : IDisposable
    {
        // ---- 连接管理 ----

        /// <summary>
        /// 连接到设备
        /// </summary>
        /// <returns>连接是否成功</returns>
        Task<bool> ConnectAsync();

        /// <summary>
        /// 断开设备连接
        /// </summary>
        Task DisconnectAsync();

        /// <summary>
        /// 当前是否已连接
        /// </summary>
        bool IsConnected { get; }

        // ---- 数据读写 ----

        /// <summary>
        /// 从指定地址读取一个值
        /// </summary>
        /// <param name="address">寄存器地址，如 "D100"</param>
        /// <param name="value">读取到的值</param>
        /// <returns>读取是否成功</returns>
        bool ReadValue(string address, out object value);

        /// <summary>
        /// 从指定地址批量读取多个值
        /// </summary>
        /// <param name="addresses">地址列表</param>
        /// <returns>地址-值字典</returns>
        Dictionary<string, object> ReadMultipleValues(List<string> addresses);

        /// <summary>
        /// 向指定地址写入一个值
        /// </summary>
        /// <param name="address">寄存器地址</param>
        /// <param name="value">要写入的值</param>
        /// <returns>写入是否成功</returns>
        bool WriteValue(string address, object value);

        // ---- 事件通知 ----

        /// <summary>
        /// 连接状态变化时触发
        /// </summary>
        event EventHandler<bool> ConnectionStateChanged;

        /// <summary>
        /// 通信错误时触发
        /// </summary>
        event EventHandler<string> CommunicationError;
    }
}
```

### 2.3 MVVM模式实现 - ViewModel基类

```csharp
// ============================================================
// 文件：ViewModelBase.cs
// 说明：ViewModel基类 - 实现属性变更通知
// ============================================================
using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace HwPlcMonitor.UI.ViewModels
{
    /// <summary>
    /// ViewModel基类
    /// 实现了INotifyPropertyChanged接口，当属性值变化时自动通知UI更新
    /// 这是MVVM模式的核心机制
    /// </summary>
    public class ViewModelBase : INotifyPropertyChanged
    {
        /// <summary>
        /// 属性变更事件 - WinForms中由ViewModel自行触发UI更新
        /// </summary>
        public event PropertyChangedEventHandler PropertyChanged;

        /// <summary>
        /// 设置属性值并自动触发变更通知
        /// 使用CallerMemberName特性自动获取调用方的属性名
        /// </summary>
        /// <typeparam name="T">属性类型</typeparam>
        /// <param name="field">属性的字段引用</param>
        /// <param name="value">新值</param>
        /// <param name="propertyName">属性名（自动获取）</param>
        /// <returns>如果值发生了变化返回true，否则返回false</returns>
        protected bool SetProperty<T>(ref T field, T value, [CallerMemberName] string propertyName = null)
        {
            // 如果新值和旧值相同，不做任何处理
            if (EqualityComparer<T>.Default.Equals(field, value))
                return false;

            field = value;
            OnPropertyChanged(propertyName);
            return true;
        }

        /// <summary>
        /// 手动触发属性变更通知
        /// </summary>
        protected void OnPropertyChanged([CallerMemberName] string propertyName = null)
        {
            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
        }
    }
}
```

### 2.4 依赖注入实现 - 简易DI容器

```csharp
// ============================================================
// 文件：SimpleServiceContainer.cs
// 说明：简易依赖注入容器 - 演示DI的核心原理
// ============================================================
namespace HwPlcMonitor.Core
{
    /// <summary>
    /// 简易服务容器
    /// 实现基本的依赖注入功能，理解DI原理后可替换为Microsoft.Extensions.DependencyInjection
    /// </summary>
    public class SimpleServiceContainer
    {
        // 存储已注册的服务：接口类型 -> 实现类型
        private readonly Dictionary<Type, Type> _registrations = new Dictionary<Type, Type>();

        // 存储已创建的单例实例
        private readonly Dictionary<Type, object> _singletons = new Dictionary<Type, object>();

        /// <summary>
        /// 注册服务：将接口类型映射到实现类型
        /// </summary>
        /// <typeparam name="TInterface">接口类型</typeparam>
        /// <typeparam name="TImplementation">实现类型</typeparam>
        /// <param name="isSingleton">是否为单例模式（默认是）</param>
        public void Register<TInterface, TImplementation>(bool isSingleton = true)
            where TImplementation : TInterface
        {
            _registrations[typeof(TInterface)] = typeof(TImplementation);

            // 如果是单例，提前创建实例
            if (isSingleton)
            {
                var instance = Activator.CreateInstance(typeof(TImplementation));
                _singletons[typeof(TInterface)] = instance;
            }
        }

        /// <summary>
        /// 解析服务：获取接口的实例
        /// </summary>
        public T Resolve<T>() where T : class
        {
            if (_singletons.TryGetValue(typeof(T), out var instance))
            {
                return (T)instance;
            }

            if (_registrations.TryGetValue(typeof(T), out var implType))
            {
                return (T)Activator.CreateInstance(implType);
            }

            throw new InvalidOperationException($"未注册的服务类型：{typeof(T).Name}");
        }
    }
}
```

```csharp
// ============================================================
// 文件：Program.cs 中注册服务
// 说明：应用程序启动时配置依赖注入
// ============================================================
using HwPlcMonitor.Core.Interfaces;
using HwPlcMonitor.Core.Services;
using HwPlcMonitor.Data.Repositories;
using HwPlcMonitor.UI;

namespace HwPlcMonitor
{
    static class Program
    {
        // 全局服务容器
        public static SimpleServiceContainer Services { get; private set; }

        [STAThread]
        static void Main()
        {
            Application.EnableVisualStyles();
            Application.SetCompatibleTextRenderingDefault(false);

            // ========== 第1步：创建服务容器 ==========
            Services = new SimpleServiceContainer();

            // ========== 第2步：注册服务 ==========
            // 注册通信服务：ModbusTcp通信实现
            Services.Register<ICommunicationService, ModbusTcpCommunication>();

            // 注册数据服务：SQLite数据仓库实现
            Services.Register<IDataService, PlcDataRepository>();

            // 注册报警服务
            Services.Register<IAlarmService, AlarmService>();

            // ========== 第3步：启动主窗体 ==========
            // 通过DI容器获取服务并传入窗体
            var mainForm = new MainForm(
                Services.Resolve<ICommunicationService>(),
                Services.Resolve<IDataService>(),
                Services.Resolve<IAlarmService>()
            );

            Application.Run(mainForm);
        }
    }
}
```

## 三、注意事项

### 3.1 架构设计注意事项

| 注意点 | 说明 | 示例 |
|--------|------|------|
| **不要跳层调用** | UI层不要直接操作数据库，必须经过业务逻辑层 | UI -> AlarmService -> DataService -> Database |
| **接口优先** | 层与层之间通过接口交互，不要直接依赖具体类 | 依赖ICommunicationService，不依赖ModbusTcpComm |
| **单一职责** | 每个类只负责一件事 | 通信类只管通信，不负责界面更新 |
| **避免循环依赖** | 下层不要引用上层 | Core层不能引用UI层的任何类 |
| **配置与代码分离** | 连接参数、报警阈值等不要写死在代码中 | 使用配置文件或数据库存储 |

### 3.2 MVVM在WinForms中的注意事项

| 注意点 | 说明 |
|--------|------|
| **WinForms不自带双向绑定** | 需要手动实现属性变更通知机制 |
| **UI线程安全** | ViewModel通知UI更新时必须回到UI线程 |
| **不要在ViewModel中引用控件** | ViewModel应该完全独立于UI |
| **事件是桥梁** | ViewModel通过事件通知View，View订阅事件并更新控件 |

### 3.3 依赖注入注意事项

| 注意点 | 说明 |
|--------|------|
| **接口粒度要合理** | 不要设计过大的接口，保持接口小而精 |
| **生命周期管理** | 理解瞬态（Transient）和单例（Singleton）的区别 |
| **避免服务定位器反模式** | 不要到处调用container.Resolve()，在构造函数中注入 |
| **推荐使用成熟框架** | 生产项目建议使用Microsoft.Extensions.DependencyInjection |

## 四、实战案例

### 案例：设计汇川PLC上位机监控系统的完整架构

**项目背景：**
设计一个汇川PLC数据监控系统，需要实现以下功能：
1. 通过Modbus TCP连接汇川PLC，采集温度、压力、流量等数据
2. 在界面上实时显示采集数据，并绘制趋势曲线
3. 当数据超过阈值时触发报警
4. 所有采集数据和报警记录保存到SQLite数据库
5. 支持数据查询和导出

**关键代码 - 主窗体如何使用分层架构：**

```csharp
// ============================================================
// 文件：MainForm.cs
// 说明：主监控窗体 - 只负责UI展示，通过接口调用下层服务
// ============================================================
using HwPlcMonitor.Core.Interfaces;
using HwPlcMonitor.Core.Models;

namespace HwPlcMonitor.UI
{
    public partial class MainForm : Form
    {
        // 通过构造函数注入依赖服务（依赖注入）
        private readonly ICommunicationService _commService;
        private readonly IDataService _dataService;
        private readonly IAlarmService _alarmService;

        // 数据采集定时器
        private System.Windows.Forms.Timer _pollTimer;
        private DeviceConfig _config;

        public MainForm(
            ICommunicationService commService,
            IDataService dataService,
            IAlarmService alarmService)
        {
            InitializeComponent();

            // 保存注入的服务引用
            _commService = commService;
            _dataService = dataService;
            _alarmService = alarmService;

            // 订阅事件
            _commService.ConnectionStateChanged += OnConnectionStateChanged;
            _commService.CommunicationError += OnCommunicationError;
            _alarmService.AlarmTriggered += OnAlarmTriggered;
            _alarmService.AlarmRecovered += OnAlarmRecovered;

            InitializeTimer();
        }

        /// <summary>
        /// 初始化数据采集定时器
        /// </summary>
        private void InitializeTimer()
        {
            _pollTimer = new System.Windows.Forms.Timer();
            _pollTimer.Interval = 1000; // 默认1秒采集一次
            _pollTimer.Tick += async (s, e) => await PollDataAsync();
        }

        /// <summary>
        /// 连接按钮点击事件
        /// </summary>
        private async void btnConnect_Click(object sender, EventArgs e)
        {
            btnConnect.Enabled = false;
            var success = await _commService.ConnectAsync();

            if (success)
            {
                _pollTimer.Start(); // 开始定时采集
                UpdateStatus("已连接", Color.Green);
            }
            else
            {
                MessageBox.Show("连接失败，请检查网络和配置");
                UpdateStatus("连接失败", Color.Red);
            }
            btnConnect.Enabled = true;
        }

        /// <summary>
        /// 定时采集数据
        /// 注意：此方法在定时器的Tick事件中调用，运行在UI线程
        /// </summary>
        private async Task PollDataAsync()
        {
            try
            {
                // 1. 批量读取PLC数据（通信层）
                var addresses = new List<string> { "D100", "D102", "D104" };
                var values = _commService.ReadMultipleValues(addresses);

                // 2. 更新界面显示（UI层）
                UpdateDataDisplay(values);

                // 3. 保存到数据库（数据层）- 异步执行不阻塞UI
                var dataModel = ConvertToDataModel(values);
                _ = _dataService.SavePlcDataAsync(dataModel);

                // 4. 检查报警（业务逻辑层）
                foreach (var kvp in values)
                {
                    var alarm = _alarmService.CheckAlarm(kvp.Key, Convert.ToDouble(kvp.Value));
                    // 报警通知由事件机制处理
                }
            }
            catch (Exception ex)
            {
                // 通信异常由CommunicationError事件处理
                _commService.CommunicationError?.Invoke(this, ex.Message);
            }
        }

        /// <summary>
        /// 更新数据显示（UI操作）
        /// </summary>
        private void UpdateDataDisplay(Dictionary<string, object> values)
        {
            if (values.TryGetValue("D100", out var temp))
                lblTemperature.Text = $"{temp} ℃";

            if (values.TryGetValue("D102", out var pressure))
                lblPressure.Text = $"{pressure} MPa";

            if (values.TryGetValue("D104", out var flow))
                lblFlow.Text = $"{flow} L/min";
        }

        // ... 其他事件处理方法省略
    }
}
```

**架构设计总结：**

| 设计决策 | 说明 | 好处 |
|----------|------|------|
| 使用分层架构 | 通信/业务/UI三层分离 | 各层独立开发、测试和修改 |
| 使用接口抽象 | ICommunicationService等接口 | 可替换通信实现、方便Mock测试 |
| 使用依赖注入 | 通过构造函数注入服务 | 解耦、便于单元测试 |
| 使用MVVM思想 | ViewModel处理UI逻辑 | 业务逻辑与UI控件分离 |
| 使用定时器采集 | Timer触发周期性数据采集 | 不阻塞UI线程、稳定可靠 |
