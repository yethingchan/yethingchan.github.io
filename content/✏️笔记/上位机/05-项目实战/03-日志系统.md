# 03 - 日志系统

> 本文讲解上位机项目中日志系统的重要性、日志库的选型与使用，以及在上位机场景下的日志最佳实践。

---

## 一、知识讲解

### 1.1 日志的重要性

上位机软件通常需要7x24小时不间断运行，日志是排查问题的重要依据。没有日志的上位机系统就像是"黑盒"，出了问题无法追溯原因。

**日志的五大作用：**

| 作用 | 说明 | 上位机场景示例 |
|------|------|----------------|
| **故障排查** | 记录程序运行时的错误信息，帮助快速定位问题 | PLC通信突然断开，通过日志查看断开时间、错误码 |
| **运行追溯** | 记录系统操作过程，追溯操作历史 | 查看某日某时操作员是否手动修改了参数 |
| **数据分析** | 记录关键业务数据，用于统计分析 | 统计每天的通信成功率、报警次数 |
| **审计合规** | 记录用户行为，满足行业审计要求 | 医药行业要求记录所有参数修改历史 |
| **性能监控** | 记录操作耗时，发现性能瓶颈 | 一次批量读取耗时从50ms变成2000ms，说明网络异常 |

### 1.2 日志级别

| 级别 | 名称 | 用途 | 上位机使用场景 |
|------|------|------|----------------|
| **0 - Debug** | 调试信息 | 记录详细的调试数据，生产环境通常关闭 | Modbus请求报文、响应报文的原始字节 |
| **1 - Information** | 信息日志 | 记录正常运行的关键事件 | 程序启动、PLC连接成功、数据采集正常 |
| **2 - Warning** | 警告日志 | 记录不影响运行的异常情况 | 通信延迟增大、磁盘空间不足 |
| **3 - Error** | 错误日志 | 记录影响功能的错误 | PLC通信超时、数据库写入失败 |
| **4 - Fatal** | 致命错误 | 记录导致程序崩溃的严重错误 | 数据库损坏、内存溢出、无法恢复的通信故障 |

**日志级别使用原则：**
- 日志级别从低到高包含关系：Fatal > Error > Warning > Information > Debug
- 设置级别为 Information 时，只会记录 Information、Warning、Error、Fatal
- **生产环境推荐设置 Information 级别**，需要排查问题时临时调为 Debug
- Debug级别日志必须包含足够的信息来复现问题

### 1.3 常用日志库对比

| 特性 | Serilog | NLog | log4net |
|------|---------|------|---------|
| **学习难度** | 低 | 低 | 中 |
| **配置方式** | 代码配置为主，支持JSON | XML/代码配置 | XML配置为主 |
| **结构化日志** | 原生支持，非常优秀 | 支持，较好 | 支持，一般 |
| **性能** | 优秀 | 优秀 | 良好 |
| **社区活跃度** | 非常活跃 | 活跃 | 维护中（更新较慢） |
| **扩展性** | 丰富的Sink插件 | 丰富的Target插件 | 较多Appender插件 |
| **NuGet安装** | `Serilog` | `NLog` | `log4net` |
| **推荐度** | **强烈推荐** | 推荐 | 一般 |

> **推荐选择 Serilog**：结构化日志支持最完善，API设计最现代，社区最活跃，适合新项目。

### 1.4 日志文件滚动策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **按日期滚动** | 每天创建一个新日志文件 | 上位机推荐，便于按天查找问题 |
| **按大小滚动** | 文件超过指定大小后创建新文件 | 单台设备产生大量日志的场景 |
| **混合滚动** | 同时按日期和大小滚动 | 日志量特别大的场景 |
| **日志保留天数** | 自动删除超过N天的日志文件 | 防止磁盘被日志占满（必须配置） |

### 1.5 结构化日志

**结构化日志**是指在记录日志时，不仅记录一条文本消息，还将关键信息以键值对的形式附带，便于后续查询和分析。

```
普通日志： 2024-01-15 14:30:22 [INFO] PLC 192.168.1.100 连接失败，超时3000ms
结构化日志：2024-01-15 14:30:22 [INFO] PLC连接失败
            {IpAddress: "192.168.1.100", ErrorCode: "Timeout", TimeoutMs: 3000, SlaveId: 1}
```

结构化日志的好处：
- 可以按字段搜索（如搜索所有IP为192.168.1.100的日志）
- 可以导入数据库进行统计分析
- 便于日志分析工具（如Seq）进行可视化展示

## 二、代码示例（带详细注释）

### 2.1 Serilog 安装与初始化

```csharp
// ============================================================
// 文件：LogHelper.cs
// 说明：Serilog日志帮助类 - 上位机日志系统核心
// 需要安装以下NuGet包：
//   1. Serilog
//   2. Serilog.Sinks.File        （文件输出）
//   3. Serilog.Sinks.RollingFile （滚动文件输出）
//   4. Serilog.Enrichers.Thread  （线程ID增强）
//   5. Serilog.Enrichers.Process （进程ID增强）
// ============================================================
using Serilog;
using Serilog.Events;

namespace HwPlcMonitor.Core.Logging
{
    /// <summary>
    /// 日志帮助类
    /// 封装Serilog的初始化和使用
    /// </summary>
    public static class LogHelper
    {
        /// <summary>
        /// Serilog全局Logger实例
        /// 所有模块通过这个实例记录日志
        /// </summary>
        public static ILogger Logger { get; private set; }

        /// <summary>
        /// 初始化日志系统
        /// 在程序启动时调用一次
        /// </summary>
        /// <param name="logPath">日志文件目录</param>
        /// <param name="minLevel">最低日志级别</param>
        public static void Init(string logPath = "logs\\", LogEventLevel minLevel = LogEventLevel.Information)
        {
            // 确保日志目录存在
            if (!Directory.Exists(logPath))
                Directory.CreateDirectory(logPath);

            // 创建Serilog Logger配置
            Logger = new LoggerConfiguration()
                // 设置最低日志级别
                .MinimumLevel.Is(minLevel)
                // Debug级别的日志只输出到调试窗口，不写入文件
                .MinimumLevel.Override("Microsoft", LogEventLevel.Warning)
                .MinimumLevel.Override("System", LogEventLevel.Warning)
                // 增强日志信息：添加线程ID和进程ID
                .Enrich.FromLogContext()           // 支持上下文属性
                .Enrich.WithThreadId()             // 添加线程ID
                .Enrich.WithProcessId()             // 添加进程ID
                .Enrich.WithMachineName()           // 添加机器名
                // 输出到文件（按日期滚动）
                .WriteTo.File(
                    path: Path.Combine(logPath, "log-.txt"),
                    rollingInterval: RollingInterval.Day,        // 每天一个文件
                    retainedFileCountLimit: 30,                   // 保留30天
                    outputTemplate: "{Timestamp:yyyy-MM-dd HH:mm:ss.fff} "
                                  + "[{Level:u3}] "
                                  + "[{ThreadId}] "
                                  + "{SourceContext} "
                                  + "{Message:lj}{NewLine}"
                                  + "{Exception}",
                    fileSizeLimitBytes: 50 * 1024 * 1024,        // 单文件最大50MB
                    rollOnFileSizeLimit: true,                     // 超大小也滚动
                    encoding: System.Text.Encoding.UTF8,
                    shared: false                                    // 不共享文件（多进程场景设true）
                )
                // 输出到控制台（调试时使用）
                .WriteTo.Console(
                    outputTemplate: "{Timestamp:HH:mm:ss} [{Level:u3}] {Message:lj}{NewLine}{Exception}"
                )
                .CreateLogger();

            // 记录日志系统启动
            Logger.Information("日志系统初始化完成。日志目录: {LogPath}, 最低级别: {MinLevel}",
                logPath, minLevel);
        }

        // ========== 便捷日志方法 ==========

        /// <summary>记录调试信息</summary>
        public static void Debug(string message, params object[] propertyValues)
            => Logger.Debug(message, propertyValues);

        /// <summary>记录信息</summary>
        public static void Info(string message, params object[] propertyValues)
            => Logger.Information(message, propertyValues);

        /// <summary>记录警告</summary>
        public static void Warning(string message, params object[] propertyValues)
            => Logger.Warning(message, propertyValues);

        /// <summary>记录错误</summary>
        public static void Error(string message, Exception ex = null, params object[] propertyValues)
        {
            if (ex != null)
                Logger.Error(ex, message, propertyValues);
            else
                Logger.Error(message, propertyValues);
        }

        /// <summary>记录致命错误</summary>
        public static void Fatal(string message, Exception ex = null, params object[] propertyValues)
        {
            if (ex != null)
                Logger.Fatal(ex, message, propertyValues);
            else
                Logger.Fatal(message, propertyValues);
        }

        /// <summary>
        /// 创建子日志器（带上下文标识）
        /// 用于区分不同模块的日志
        /// </summary>
        public static ILogger ForContext<T>()
            => Logger.ForContext<T>();
    }
}
```

### 2.3 在通信模块中使用日志

```csharp
// ============================================================
// 文件：ModbusTcpComm.cs（日志使用示例）
// 说明：展示如何在通信模块中正确使用日志
// ============================================================
using HwPlcMonitor.Core.Logging;
using Serilog;

namespace HwPlcMonitor.Core.Communication
{
    public class ModbusTcpComm : ICommunicationService
    {
        // 使用通信模块专用日志器
        private readonly ILogger _log = LogCategories.Communication;

        public async Task<bool> ConnectAsync()
        {
            try
            {
                // Info级别：记录正常的业务事件
                _log.Information("正在连接PLC {IpAddress}:{Port}, 站号: {SlaveId}",
                    _ipAddress, _port, _slaveId);

                // ... 连接逻辑 ...

                // Debug级别：记录详细的调试信息（生产环境通常关闭）
                _log.Debug("TCP连接建立成功，Socket句柄: {Handle}", _socket.Handle);

                // Info级别：记录关键成功事件
                _log.Information("PLC连接成功 {IpAddress}:{Port}", _ipAddress, _port);

                return true;
            }
            catch (SocketException ex)
            {
                // Error级别：记录影响功能的错误，附带异常对象
                _log.Error(ex, "PLC连接失败 {IpAddress}:{Port}, 错误码: {ErrorCode}",
                    _ipAddress, _port, ex.SocketErrorCode);

                return false;
            }
        }

        public Dictionary<string, object> ReadMultipleValues(List<string> addresses)
        {
            var result = new Dictionary<string, object>();
            var sw = System.Diagnostics.Stopwatch.StartNew(); // 计时

            try
            {
                // Debug级别：记录请求细节
                _log.Debug("批量读取请求，地址列表: {Addresses}, 数量: {Count}",
                    string.Join(", ", addresses), addresses.Count);

                // ... 读取逻辑 ...

                sw.Stop();

                // Debug级别：记录响应细节和耗时
                _log.Debug("批量读取完成，耗时: {ElapsedMs}ms", sw.ElapsedMilliseconds);

                return result;
            }
            catch (TimeoutException ex)
            {
                // Warning级别：超时不一定是致命错误，可能只是偶尔的网络波动
                _log.Warning(ex, "批量读取超时，耗时: {ElapsedMs}ms，地址: {Addresses}",
                    sw.ElapsedMilliseconds, string.Join(", ", addresses));

                throw;
            }
            catch (Exception ex)
            {
                // Error级别：未知异常
                _log.Error(ex, "批量读取失败，地址: {Addresses}", string.Join(", ", addresses));
                throw;
            }
        }

        public void Dispose()
        {
            // Info级别：记录正常的资源释放
            _log.Information("通信连接已释放 {IpAddress}:{Port}", _ipAddress, _port);
        }
    }
}
```

### 2.4 在报警模块中使用日志

```csharp
// ============================================================
// 文件：AlarmService.cs（日志使用示例）
// 说明：展示报警模块中的日志使用
// ============================================================
using HwPlcMonitor.Core.Logging;
using Serilog;

namespace HwPlcMonitor.Core.Services
{
    public class AlarmService : IAlarmService
    {
        private readonly ILogger _log = LogCategories.Alarm;

        public AlarmRecord CheckAlarm(string tagName, double value)
        {
            var threshold = FindThreshold(tagName);
            if (threshold == null) return null;

            // 检查是否超限
            if (value > threshold.HighLimit)
            {
                var alarm = new AlarmRecord
                {
                    TagName = tagName,
                    TriggerValue = value,
                    Threshold = threshold.HighLimit,
                    AlarmLevel = threshold.Level,
                    AlarmTime = DateTime.Now,
                    AlarmDescription = $"{tagName} 超上限: {value}{threshold.Unit} > {threshold.HighLimit}{threshold.Unit}"
                };

                // Warning或Error级别记录报警（根据报警级别）
                if (alarm.AlarmLevel == "Critical")
                {
                    _log.Error("触发严重报警: {TagName}={Value}{Unit}, 阈值: {Threshold}{Unit}",
                        alarm.TagName, alarm.TriggerValue, threshold.Unit,
                        threshold.HighLimit, threshold.Unit);
                }
                else
                {
                    _log.Warning("触发报警: {TagName}={Value}{Unit}, 阈值: {Threshold}{Unit}",
                        alarm.TagName, alarm.TriggerValue, threshold.Unit,
                        threshold.HighLimit, threshold.Unit);
                }

                // 同时记录到审计日志（结构化，便于统计）
                LogCategories.Audit.Information("报警触发 {@AlarmRecord}", alarm);

                return alarm;
            }

            return null;
        }
    }
}
```

### 2.5 操作审计日志

```csharp
// ============================================================
// 文件：AuditLogger.cs
// 说明：操作审计日志 - 专门记录用户的操作行为
// ============================================================
using HwPlcMonitor.Core.Logging;

namespace HwPlcMonitor.Core.Logging
{
    /// <summary>
    /// 操作审计日志帮助类
    /// 所有用户操作都应通过此类记录
    /// </summary>
    public static class AuditLogger
    {
        /// <summary>
        /// 记录用户操作
        /// </summary>
        /// <param name="operatorName">操作人</param>
        /// <param name="action">操作类型</param>
        /// <param name="target">操作对象</param>
        /// <param name="detail">操作详情</param>
        public static void LogOperation(string operatorName, string action, string target, string detail = "")
        {
            // 使用结构化日志，便于后续查询统计
            LogCategories.Audit.Information(
                "用户操作 | 操作人: {Operator} | 操作: {Action} | 对象: {Target} | 详情: {Detail}",
                operatorName, action, target, detail
            );
        }

        // ========== 常用操作快捷方法 ==========

        /// <summary>记录参数修改操作</summary>
        public static void LogParameterChange(string operatorName, string paramName, 
            object oldValue, object newValue)
        {
            LogCategories.Audit.Warning(
                "参数修改 | 操作人: {Operator} | 参数: {ParamName} | 旧值: {OldValue} | 新值: {NewValue}",
                operatorName, paramName, oldValue, newValue
            );
        }

        /// <summary>记录设备控制操作（启停等）</summary>
        public static void LogDeviceControl(string operatorName, string deviceName, string controlAction)
        {
            LogCategories.Audit.Warning(
                "设备控制 | 操作人: {Operator} | 设备: {Device} | 操作: {ControlAction}",
                operatorName, deviceName, controlAction
            );
        }

        /// <summary>记录报警确认操作</summary>
        public static void LogAlarmAcknowledge(string operatorName, int alarmId, string alarmDesc)
        {
            LogCategories.Audit.Information(
                "报警确认 | 操作人: {Operator} | 报警ID: {AlarmId} | 描述: {AlarmDesc}",
                operatorName, alarmId, alarmDesc
            );
        }
    }
}
```

## 三、注意事项

### 3.1 日志使用常见错误

| 错误做法 | 正确做法 | 原因 |
|----------|----------|------|
| 不记录日志 | 所有异常和关键操作都记录 | 出问题后无法排查 |
| 只用Debug级别 | 根据重要性选择合适级别 | 生产环境Debug日志应关闭 |
| 日志内容过于简单 | 包含关键上下文信息 | "操作失败"无法定位原因 |
| 日志内容过于详细 | 分清Debug和Info级别 | 避免日志文件增长过快 |
| 在循环中大量写日志 | 使用批量或摘要方式记录 | 避免IO开销影响性能 |
| 日志中包含敏感信息 | 脱敏处理密码等敏感数据 | 防止信息泄露 |

### 3.2 上位机日志特别注意事项

| 注意点 | 说明 |
|--------|------|
| **磁盘空间监控** | 设置日志保留天数，定期清理旧日志，避免磁盘写满 |
| **日志路径可配置** | 日志保存路径应该可以通过配置文件修改 |
| **通信日志要克制** | 通信报文日志量巨大，只在Debug级别开启 |
| **报警日志双写** | 报警信息除了写日志文件，还要写入数据库（便于查询统计） |
| **操作日志要持久化** | 用户的关键操作（参数修改、设备控制）要永久保存 |
| **时间戳要精确** | 工业场景下毫秒级时间戳很重要，便于排查通信时序问题 |

### 3.3 Serilog配置要点

| 要点 | 说明 |
|------|------|
| **retainedFileCountLimit** | 必须设置，否则日志文件会无限增长 |
| **fileSizeLimitBytes** | 建议设置，防止单个文件过大 |
| **encoding** | 始终使用UTF-8，避免中文乱码 |
| **shared** | 单进程设false（性能更好），多进程设true |
| **outputTemplate** | 包含时间、级别、线程ID、消息、异常堆栈 |

### 案例：通信日志、操作日志、报警日志的完整实现

**完整日志输出配置（三种日志分别写入不同文件）：**

```csharp
// ============================================================
// 文件：LogHelper.cs（完整版 - 多文件分类输出）
// 说明：为不同类型的日志配置不同的输出目标
// ============================================================
using Serilog;
using Serilog.Events;

namespace HwPlcMonitor.Core.Logging
{
    public static class LogHelper
    {
        public static ILogger Logger { get; private set; }

        /// <summary>
        /// 初始化日志系统（多文件分类输出）
        /// </summary>
        public static void Init(string logPath = "logs\\")
        {
            if (!Directory.Exists(logPath))
                Directory.CreateDirectory(logPath);

            Logger = new LoggerConfiguration()
                .MinimumLevel.Debug()
                .MinimumLevel.Override("Microsoft", LogEventLevel.Warning)
                .MinimumLevel.Override("System", LogEventLevel.Warning)
                .Enrich.FromLogContext()
                .Enrich.WithThreadId()
                .Enrich.WithProcessId()

                // ========== 输出1：全量日志文件 ==========
                // 记录所有级别的日志，按日期滚动
                .WriteTo.File(
                    path: Path.Combine(logPath, "all-.log"),
                    rollingInterval: RollingInterval.Day,
                    retainedFileCountLimit: 7,        // 全量日志只保留7天（占用空间大）
                    fileSizeLimitBytes: 100 * 1024 * 1024,
                    rollOnFileSizeLimit: true,
                    outputTemplate: "{Timestamp:yyyy-MM-dd HH:mm:ss.fff} [{Level:u3}] [{ThreadId}] {SourceContext} {Message:lj}{NewLine}{Exception}"
                )

                // ========== 输出2：报警专用日志文件 ==========
                // 单独记录报警信息，保留更长时间（90天），便于统计分析
                .WriteTo.File(
                    path: Path.Combine(logPath, "alarm-.log"),
                    rollingInterval: RollingInterval.Day,
                    retainedFileCountLimit: 90,       // 报警日志保留90天
                    restrictedToMinimumLevel: LogEventLevel.Warning,
                    outputTemplate: "{Timestamp:yyyy-MM-dd HH:mm:ss.fff} [{Level:u3}] {Message:lj}{NewLine}{Exception}"
                )

                // ========== 输出3：操作审计日志文件 ==========
                // 单独记录用户操作，作为审计依据永久保存（通过备份）
                .WriteTo.File(
                    path: Path.Combine(logPath, "audit-.log"),
                    rollingInterval: RollingInterval.Day,
                    retainedFileCountLimit: 365,      // 审计日志保留1年
                    restrictedToMinimumLevel: LogEventLevel.Information,
                    outputTemplate: "{Timestamp:yyyy-MM-dd HH:mm:ss.fff} {Message:lj}{NewLine}{Exception}"
                )

                // ========== 输出4：控制台（调试用）==========
                .WriteTo.Console(
                    restrictedToMinimumLevel: LogEventLevel.Information,
                    outputTemplate: "{Timestamp:HH:mm:ss} [{Level:u3}] {Message:lj}{NewLine}{Exception}"
                )
                .CreateLogger();

            Logger.Information("日志系统初始化完成，日志目录: {LogPath}", logPath);
        }
    }
}
```

**在程序启动时初始化日志：**

```csharp
static class Program
{
    [STAThread]
    static void Main()
    {
        // 第一步：初始化日志（必须在所有代码之前）
        LogHelper.Init("logs\\");

        try
        {
            Application.EnableVisualStyles();
            Application.SetCompatibleTextRenderingDefault(false);

            LogHelper.Info("程序启动，版本: {Version}", "1.0.0");

            // ... 启动主窗体 ...

            Application.Run(new MainForm());
        }
        catch (Exception ex)
        {
            // 捕获未处理的异常，记录到日志
            LogHelper.Fatal(ex, "程序发生未处理的致命错误");
            MessageBox.Show($"程序发生严重错误：{ex.Message}", "致命错误",
                MessageBoxButtons.OK, MessageBoxIcon.Error);
        }
        finally
        {
            LogHelper.Info("程序退出");
            Log.CloseAndFlush(); // 确保所有日志写入磁盘
        }
    }
}
```

**日志文件目录结构：**

```
logs/
├── all-20240115.log          # 全量日志（保留7天）
├── all-20240116.log
├── alarm-20240115.log         # 报警日志（保留90天）
├── alarm-20240116.log
├── audit-20240115.log         # 审计日志（保留365天）
├── audit-20240116.log
└── ...
```

> **提示**：日志系统的设计原则是**全面但不冗余**。每个模块的日志都要有明确的SourceContext标识，关键操作和异常必须记录，但普通运行时信息不要过度记录。日志保留策略要合理设置，特别是通信类日志量很大，需要控制保留天数。
