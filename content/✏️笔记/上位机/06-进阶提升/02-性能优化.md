# 02 - 性能优化

> 本文讲解上位机项目中常见的性能瓶颈和优化方案，涵盖通信性能、UI性能、内存管理和数据库优化。

---

## 一、知识讲解

### 1.1 上位机常见性能瓶颈

| 瓶颈类型 | 典型表现 | 常见原因 |
|----------|----------|----------|
| **通信瓶颈** | 数据采集延迟、超时频繁 | 采集频率过高、单次读取地址过多 |
| **UI卡顿** | 界面响应慢、操作不流畅 | UI线程执行耗时操作、频繁重绘 |
| **内存泄漏** | 程序运行越久越慢，最终崩溃 | 事件未取消订阅、未释放资源 |
| **数据库瓶颈** | 数据保存慢、查询超时 | 缺少索引、频繁单条插入、未用连接池 |
| **CPU占用高** | 程序CPU使用率持续很高 | 死循环、大量计算、频繁GC |

### 1.2 性能优化总体思路

```
性能优化四步法：
1. 测量：找到真正的瓶颈在哪里（不要猜测！）
2. 分析：确定瓶颈的根本原因
3. 优化：针对原因采取优化措施
4. 验证：优化后重新测量，确认效果

重要原则：
- 不要提前优化！先让代码工作，再让它快。
- 优化前先测量，用数据说话。
- 优先优化最明显的瓶颈（80/20法则）。
```

## 二、通信性能优化

### 2.1 知识讲解

| 优化策略 | 说明 | 效果 |
|----------|------|------|
| **批量读写** | 一次请求读取多个连续寄存器，而不是逐个读取 | 减少90%以上的通信次数 |
| **合并地址** | 将需要读取的地址按大小排序，合并为连续读取 | 进一步减少请求次数 |
| **合理设置采集周期** | 不要设置过高的采集频率 | 减轻PLC和网络负担 |
| **通信超时优化** | 根据网络情况调整超时时间 | 避免不必要等待 |
| **异步通信** | 读写操作使用异步方式 | 不阻塞UI线程 |
| **请求限流** | 控制单位时间内的最大请求数 | 防止PLC过载 |

```csharp
// ============================================================
// 优化示例：批量读取（性能好）
// ============================================================
// D100、D102、D104是连续地址（100-104），可以一次读取5个寄存器

public Dictionary<string, object> ReadDataOptimized()
{
    var result = new Dictionary<string, object>();

    // 一次请求：从地址100开始，读取5个连续寄存器
    // D100=地址100, D101=地址101, D102=地址102, D103=地址103, D104=地址104
    var data = _master.ReadHoldingRegisters(slaveId, 100, 5);

    // 从结果中提取需要的值
    result["D100"] = data[0];  // D100
    result["D102"] = data[2];  // D102（跳过D101）
    result["D104"] = data[4];  // D104（跳过D103）

    return result;
    // 优势：1次请求 = 1次网络延迟（约20ms）
    // 性能提升：60ms -> 20ms，提升3倍
}
```

```csharp
// ============================================================
// 高级优化：地址排序与合并读取
// 说明：将不连续的地址分组，每组做一次批量读取
// ============================================================
public class BatchReadOptimizer
{
    /// <summary>
    /// 智能批量读取优化器
    /// 将地址列表按连续性分组，每组做一次批量读取
    /// </summary>
    /// <param name="addresses">需要读取的地址列表</param>
    /// <param name="master">Modbus主站</param>
    /// <param name="slaveId">从站地址</param>
    /// <param name="maxGap">允许的最大间隔（超过此值则分为两组）</param>
    public Dictionary<string, object> OptimizedBatchRead(
        List<string> addresses, IModbusMaster master, byte slaveId, int maxGap = 10)
    {
        var result = new Dictionary<string, object>();

        // 1. 解析地址
        var parsed = addresses
            .Select(a => new { Name = a, Address = ParseAddress(a) })
            .OrderBy(a => a.Address)
            .ToList();

        // 2. 按连续性分组
        var groups = new List<List<int>>();
        var currentGroup = new List<int> { parsed[0].Address };

        for (int i = 1; i < parsed.Count; i++)
        {
            var gap = parsed[i].Address - parsed[i - 1].Address;
            if (gap <= maxGap)
            {
                // 连续或间隔较小，归入同一组
                currentGroup.Add(parsed[i].Address);
            }
            else
            {
                // 间隔较大，新建一组
                groups.Add(currentGroup);
                currentGroup = new List<int> { parsed[i].Address };
            }
        }
        groups.Add(currentGroup);

        // 3. 每组做一次批量读取
        foreach (var group in groups)
        {
            var startAddr = group.Min();
            var count = group.Max() - startAddr + 1;
            var data = master.ReadHoldingRegisters(slaveId, startAddr, count);

            // 将数据映射回地址
            for (int i = 0; i < group.Count; i++)
            {
                var addr = group[i];
                var name = parsed.First(p => p.Address == addr).Name;
                result[name] = data[addr - startAddr];
            }
        }

        return result;
        // 示例：需要读取 D100, D102, D200, D202, D204
        // 分组结果：
        //   第1组: D100-D104 (地址100-104)，1次请求
        //   第2组: D200-D204 (地址200-204)，1次请求
        // 总计：2次请求（而非5次）
    }
}
```

## 三、UI性能优化

### 3.1 知识讲解

| 优化策略 | 说明 | 效果 |
|----------|------|------|
| **双缓冲** | 在内存中绘制好图形后一次性显示 | 消除闪烁 |
| **减少重绘** | 避免不必要的Invalidate调用 | 减少CPU占用 |
| **SuspendLayout/ResumeLayout** | 批量更新控件时暂停布局 | 避免重复布局计算 |
| **虚拟模式** | DataGridView使用虚拟模式显示大数据 | 内存占用从GB降到KB |
| **后台线程更新** | 耗时操作在后台线程执行 | UI不卡顿 |
| **控件数量控制** | 减少窗体上的控件数量 | 减少渲染开销 |

```csharp
// ============================================================
// 优化2：SuspendLayout/ResumeLayout - 批量更新控件
// ============================================================
public void RefreshDataGrid(List<PlcDataModel> dataList)
{
    // 暂停自动布局（避免每添加一行就重新布局一次）
    dataGridView1.SuspendLayout();

    try
    {
        dataGridView1.Rows.Clear();

        // 批量添加行（不会触发中间布局）
        foreach (var item in dataList)
        {
            dataGridView1.Rows.Add(
                item.CollectTime.ToString("yyyy-MM-dd HH:mm:ss"),
                item.TagName,
                item.Value,
                item.Unit
            );
        }
    }
    finally
    {
        // 恢复自动布局（只做一次布局计算）
        dataGridView1.ResumeLayout(true);
    }
}

// ============================================================
// 优化3：DataGridView虚拟模式 - 处理大数据量
// 说明：当数据量超过1万行时，使用虚拟模式避免内存问题
// ============================================================
public partial class DataQueryForm : Form
{
    private List<PlcDataModel> _allData; // 完整数据（内存中）

    public DataQueryForm()
    {
        InitializeComponent();

        // 启用虚拟模式
        dataGridView1.VirtualMode = true;

        // 虚拟模式必须处理这些事件
        dataGridView1.RowCount = 0;
        dataGridView1.CellValueNeeded += OnCellValueNeeded;
    }

    /// <summary>
    /// 虚拟模式核心：按需提供单元格值
    /// 只有当单元格需要显示时才会调用
    /// </summary>
    private void OnCellValueNeeded(object sender, DataGridViewCellValueEventArgs e)
    {
        if (e.RowIndex < 0 || e.RowIndex >= _allData.Count)
            return;

        var item = _allData[e.RowIndex];

        switch (e.ColumnIndex)
        {
            case 0: e.Value = item.CollectTime.ToString("yyyy-MM-dd HH:mm:ss"); break;
            case 1: e.Value = item.TagName; break;
            case 2: e.Value = item.Value; break;
            case 3: e.Value = item.Unit; break;
        }
    }

    /// <summary>
    /// 查询数据后更新显示
    /// </summary>
    public void ShowQueryResult(List<PlcDataModel> data)
    {
        _allData = data;
        dataGridView1.RowCount = data.Count; // 只设置行数，不创建行对象
        // 虚拟模式下设置RowCount不会分配内存，即使100万行也只占几KB
    }
}
```

## 四、内存优化

### 4.1 知识讲解

| 优化策略 | 说明 | 适用场景 |
|----------|------|----------|
| **对象池** | 复用对象而不是频繁创建和销毁 | 高频创建的短生命周期对象 |
| **减少GC压力** | 避免在热路径中创建大量临时对象 | 数据采集循环中 |
| **using语句** | 确保IDisposable对象及时释放 | 数据库连接、文件流、网络流 |
| **避免内存泄漏** | 取消事件订阅、释放非托管资源 | 长时间运行的程序 |
| **StringBuilder** | 替代字符串拼接 | 循环中拼接字符串 |
| **合理选择集合类型** | 根据场景选择List/Dictionary/Array | 数据存储 |

### 4.2 代码示例

```csharp
// ============================================================
// 优化1：对象池 - 复用数据采集结果对象
// 说明：上位机每秒采集一次数据，频繁创建Dictionary会产生大量GC
// ============================================================
public class DataResultPool
{
    // 对象池（线程安全）
    private readonly ConcurrentBag<Dictionary<string, object>> _pool = new();

    /// <summary>从池中获取对象</summary>
    public Dictionary<string, object> Get()
    {
        if (_pool.TryTake(out var dict))
        {
            dict.Clear(); // 清空数据，复用对象
            return dict;
        }
        return new Dictionary<string, object>(); // 池空则创建新对象
    }

    /// <summary>将对象放回池中</summary>
    public void Return(Dictionary<string, object> dict)
    {
        // 池大小限制，避免无限增长
        if (_pool.Count < 100)
            _pool.Add(dict);
    }
}

// 使用示例：
public void PollData()
{
    var pool = DataResultPool.Instance;
    var result = pool.Get();  // 从池中获取

    try
    {
        // 填充数据...
        result["D100"] = ReadValue(100);
        result["D102"] = ReadValue(102);

        // 处理数据...
        ProcessData(result);
    }
    finally
    {
        pool.Return(result); // 放回池中复用
    }
}
```

## 五、数据库优化

### 5.1 知识讲解

| 优化策略 | 说明 | 效果 |
|----------|------|------|
| **索引** | 为查询条件字段创建索引 | 查询速度提升10-100倍 |
| **批量插入** | 使用事务一次插入多条记录 | 插入速度提升10-50倍 |
| **连接池** | 复用数据库连接 | 减少连接创建开销 |
| **参数化查询** | 使用参数而非字符串拼接 | 防SQL注入 + 性能更好 |
| **数据清理** | 定期删除旧数据 | 保持数据库文件大小可控 |
| **WAL模式** | 使用Write-Ahead Logging | 读写并发性能更好 |

### 5.2 代码示例

```csharp
// ============================================================
// 优化1：创建索引（必须在数据库创建时执行）
// ============================================================
public static void CreateIndexes(SQLiteConnection conn)
{
    using (var cmd = conn.CreateCommand())
    {
        // 为常用查询条件创建索引
        cmd.CommandText = @"
            -- 按采集时间查询的索引
            CREATE INDEX IF NOT EXISTS idx_plc_data_time ON plc_data(collect_time);

            -- 按标签名查询的索引
            CREATE INDEX IF NOT EXISTS idx_plc_data_tag ON plc_data(tag_name);

            -- 组合索引（同时按时间和标签查询）
            CREATE INDEX IF NOT EXISTS idx_plc_data_time_tag ON plc_data(collect_time, tag_name);
        ";
        cmd.ExecuteNonQuery();
    }
}

// ============================================================
// 优化2：批量插入（使用事务）
// ============================================================

// 不良示例：逐条插入
public void InsertDataBad(List<PlcDataModel> dataList)
{
    foreach (var item in dataList)
    {
        using (var conn = DatabaseHelper.GetConnection())
        {
            conn.Open();
            using (var cmd = conn.CreateCommand())
            {
                cmd.CommandText = "INSERT INTO plc_data VALUES(...)";
                cmd.ExecuteNonQuery();
                conn.Close(); // 每次都开关连接
            }
        }
    }
    // 1000条数据 -> 1000次连接 + 1000次事务 = 约10秒
}

// 优化示例：批量插入（事务 + 参数化）
public void InsertDataGood(List<PlcDataModel> dataList)
{
    using (var conn = DatabaseHelper.GetConnection())
    {
        conn.Open();
        using (var transaction = conn.BeginTransaction())
        {
            try
            {
                using (var cmd = conn.CreateCommand())
                {
                    cmd.CommandText = @"
                        INSERT INTO plc_data (tag_name, address, value, unit, quality, collect_time)
                        VALUES (@TagName, @Address, @Value, @Unit, @Quality, @CollectTime)
                    ";

                    // 添加参数（只创建一次，后续只更新值）
                    cmd.Parameters.Add(new SQLiteParameter("@TagName", DbType.String));
                    cmd.Parameters.Add(new SQLiteParameter("@Address", DbType.String));
                    cmd.Parameters.Add(new SQLiteParameter("@Value", DbType.Double));
                    cmd.Parameters.Add(new SQLiteParameter("@Unit", DbType.String));
                    cmd.Parameters.Add(new SQLiteParameter("@Quality", DbType.Int32));
                    cmd.Parameters.Add(new SQLiteParameter("@CollectTime", DbType.String));

                    foreach (var item in dataList)
                    {
                        // 更新参数值
                        cmd.Parameters["@TagName"].Value = item.TagName;
                        cmd.Parameters["@Address"].Value = item.Address;
                        cmd.Parameters["@Value"].Value = item.Value;
                        cmd.Parameters["@Unit"].Value = item.Unit;
                        cmd.Parameters["@Quality"].Value = item.Quality;
                        cmd.Parameters["@CollectTime"].Value = item.CollectTime.ToString("s");

                        cmd.ExecuteNonQuery();
                    }
                }

                transaction.Commit(); // 一次性提交所有插入
            }
            catch
            {
                transaction.Rollback();
                throw;
            }
        }
    }
    // 1000条数据 -> 1次连接 + 1次事务 = 约0.1秒（提升100倍）
}

// ============================================================
// 优化3：启用WAL模式
// ============================================================
public static void EnableWALMode(SQLiteConnection conn)
{
    using (var cmd = conn.CreateCommand())
    {
        // 启用WAL模式（写操作不阻塞读操作）
        cmd.CommandText = "PRAGMA journal_mode=WAL;";
        cmd.ExecuteNonQuery();

        // 设置适当的缓存大小（单位：KB）
        cmd.CommandText = "PRAGMA cache_size=-64000;"; // 64MB缓存
        cmd.ExecuteNonQuery();

        // 设置同步模式为NORMAL（平衡安全性和性能）
        cmd.CommandText = "PRAGMA synchronous=NORMAL;";
        cmd.ExecuteNonQuery();
    }
}
```

## 六、注意事项

### 6.1 性能优化常见误区

| 误区 | 正确做法 |
|------|----------|
| 不测量就优化 | 先用性能分析工具找到瓶颈 |
| 过度优化 | 优化到满足需求即可，不要追求极致 |
| 只优化一个方面 | 全面考虑通信、UI、内存、数据库 |
| 优化后不验证 | 优化后重新测量确认效果 |
| 忽略可读性 | 性能优化不能以牺牲代码可读性为代价 |

### 6.2 性能分析工具推荐

| 工具 | 用途 | 说明 |
|------|------|------|
| **Visual Studio Profiler** | CPU和内存分析 | 内置，使用方便 |
| **Stopwatch** | 代码段耗时测量 | 简单精确 |
| **PerfView** | 深度性能分析 | 免费工具，功能强大 |
| **dotMemory** | 内存泄漏分析 | JetBrains出品 |

## 七、实战案例

### 案例：上位机性能问题排查与优化全流程

**问题：上位机运行2小时后界面明显卡顿，数据查询变慢**

**排查步骤：**

```csharp
// 第1步：添加性能监控代码
public class PerformanceMonitor
{
    private Stopwatch _collectSw = new Stopwatch();
    private int _collectCount = 0;
    private long _totalCollectMs = 0;

    public void StartCollect()
    {
        _collectSw.Restart();
    }

    public void EndCollect()
    {
        _collectSw.Stop();
        _collectCount++;
        _totalCollectMs += _collectSw.ElapsedMilliseconds;

        // 每分钟输出一次统计
        if (_collectCount % 60 == 0)
        {
            Console.WriteLine($"[性能] 采集 {_collectCount} 次, " +
                $"平均耗时: {_totalCollectMs / _collectCount}ms");
        }
    }
}

// 第2步：发现问题
// 日志输出：
// [性能] 采集 60 次, 平均耗时: 15ms   <- 刚启动时正常
// [性能] 采集 3600 次, 平均耗时: 45ms <- 1小时后变慢
// [性能] 采集 7200 次, 平均耗时: 150ms <- 2小时后更慢

// 第3步：定位原因
// 使用Visual Studio Profiler发现：
// - GC次数急剧增加（每秒多次Gen2 GC）
// - 趋势图数据点列表无限增长（已积累7200个点）
// - DataGridView未使用虚拟模式（100万条数据占1.5GB内存）

// 第4步：针对性优化
```

**优化方案与效果：**

| 优化项 | 优化前 | 优化后 | 效果 |
|--------|--------|--------|------|
| 趋势图数据点 | 无限增长 | 限制200个点，超出删除最早的 | 内存占用稳定 |
| DataGridView | 普通模式 | 虚拟模式 | 内存占用从1.5GB降到10MB |
| 数据保存 | 逐条插入 | 批量插入（事务） | 写入速度提升50倍 |
| 通信读取 | 3次请求 | 1次批量读取 | 通信延迟降低67% |
| 字符串拼接 | + 操作符 | StringBuilder | GC次数减少80% |

> **提示**：性能优化的核心是**先测量，再优化**。不要凭感觉优化，用工具和数据说话。上位机程序需要长时间运行，特别要关注内存泄漏和内存增长问题，建议在开发过程中就使用性能分析工具定期检查。
