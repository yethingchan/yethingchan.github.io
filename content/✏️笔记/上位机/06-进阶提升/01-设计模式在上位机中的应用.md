# 01 - 设计模式在上位机中的应用

> 本文讲解常用的设计模式在上位机开发中的实际应用场景，每个模式都配有完整的上位机场景代码示例。

---

## 一、知识讲解

### 1.1 什么是设计模式？

设计模式是前人在大量软件开发实践中总结出来的**可复用的解决方案模板**。它们解决的是软件开发中的常见设计问题，而不是具体的代码实现。

**为什么上位机开发需要设计模式？**

| 不使用设计模式 | 使用设计模式 |
|----------------|-------------|
| 代码杂乱，难以维护 | 代码结构清晰，职责明确 |
| 修改一个功能要改很多地方 | 修改范围可控，影响最小 |
| 更换PLC品牌需要重写大量代码 | 只需新增一个类即可 |
| 代码难以测试 | 易于Mock和单元测试 |
| 项目越大越难维护 | 架构稳定，可扩展性好 |

### 1.2 本文涵盖的设计模式

| 设计模式 | 类型 | 上位机应用场景 |
|----------|------|----------------|
| **单例模式** | 创建型 | 全局配置管理器、日志管理器 |
| **工厂模式** | 创建型 | 创建不同品牌PLC的通信对象 |
| **观察者模式** | 行为型 | 数据变化通知UI更新 |
| **策略模式** | 行为型 | 不同通信协议的切换 |
| **模板方法模式** | 行为型 | 数据采集流程的标准化 |

## 二、代码示例（带详细注释）

### 2.1 单例模式 - 全局配置管理器

**场景说明：** 配置管理器在整个程序中只需要一个实例，所有模块共享同一份配置。

```
单例模式核心思想：
- 确保一个类只有一个实例
- 提供全局访问点
- 线程安全（多线程环境下不能创建多个实例）
```

```csharp
// ============================================================
// 文件：ConfigManager.cs
// 说明：单例模式 - 全局配置管理器
// 整个程序只需要一个配置管理器实例，所有模块共享
// ============================================================
namespace HwPlcMonitor.Core.Configuration
{
    /// <summary>
    /// 配置管理器（单例模式）
    /// 使用双重检查锁定（Double-Check Locking）确保线程安全
    /// </summary>
    public class ConfigManager
    {
        // ---- 第1步：私有静态字段，持有唯一实例 ----
        private static ConfigManager _instance;

        // ---- 第2步：私有静态锁对象，用于线程同步 ----
        private static readonly object _lock = new object();

        // ---- 第3步：私有构造函数，防止外部new创建实例 ----
        private ConfigManager()
        {
            // 初始化配置
            _settings = LoadSettingsFromFile();
        }

        // ---- 第4步：公有静态属性，提供全局访问点 ----
        public static ConfigManager Instance
        {
            get
            {
                // 第一次检查（无锁，性能好）
                if (_instance == null)
                {
                    // 加锁，确保只有一个线程能创建实例
                    lock (_lock)
                    {
                        // 第二次检查（防止锁内多个线程同时通过第一次检查）
                        if (_instance == null)
                        {
                            _instance = new ConfigManager();
                        }
                    }
                }
                return _instance;
            }
        }

        // ---- 配置数据 ----
        private AppSettings _settings;

        /// <summary>获取当前配置</summary>
        public AppSettings Settings => _settings;

        /// <summary>保存并更新配置</summary>
        public void SaveSettings(AppSettings newSettings)
        {
            _settings = newSettings;
            SaveSettingsToFile(_settings);
        }

        // ... 文件读写方法省略
    }
}
```

**使用方式（在任何地方都可以直接访问）：**

```csharp
// 在通信模块中使用
var ipAddress = ConfigManager.Instance.Settings.PlcConnection.IpAddress;

// 在UI模块中使用
var pollInterval = ConfigManager.Instance.Settings.DataCollect.PollIntervalMs;

// 在报警模块中使用
var thresholds = ConfigManager.Instance.Settings.Alarm.Thresholds;
```

### 2.2 工厂模式 - 创建不同PLC的通信对象

**场景说明：** 系统需要支持多种PLC品牌（汇川、西门子、三菱），每种PLC的通信方式不同。工厂模式可以根据配置动态创建对应的通信对象。

```
工厂模式核心思想：
- 定义一个创建对象的接口
- 由子类决定实例化哪个类
- 将对象的创建和使用分离
```

```csharp
// ============================================================
// 文件：ICommunicationService.cs
// 说明：通信服务接口（已在架构设计章节定义）
// ============================================================
public interface ICommunicationService
{
    Task<bool> ConnectAsync();
    Task DisconnectAsync();
    bool IsConnected { get; }
    bool ReadValue(string address, out object value);
    Dictionary<string, object> ReadMultipleValues(List<string> addresses);
    bool WriteValue(string address, object value);
    event EventHandler<bool> ConnectionStateChanged;
    event EventHandler<string> CommunicationError;
}
```

```csharp
// ============================================================
// 文件：CommunicationFactory.cs
// 说明：工厂模式 - 根据配置创建不同的通信对象
// ============================================================
namespace HwPlcMonitor.Core.Communication
{
    /// <summary>
    /// 通信工厂
    /// 根据设备配置中的协议类型，创建对应的通信服务实例
    /// 新增PLC品牌时，只需在此添加新的分支，不影响已有代码
    /// </summary>
    public static class CommunicationFactory
    {
        /// <summary>
        /// 创建通信服务
        /// </summary>
        /// <param name="config">设备配置</param>
        /// <returns>通信服务实例</returns>
        public static ICommunicationService Create(DeviceConfig config)
        {
            // 根据协议类型创建不同的通信对象
            switch (config.ProtocolType.ToLower())
            {
                case "modbustcp":
                    return new ModbusTcpCommunication(config);

                case "modbusrtu":
                    return new ModbusRtuCommunication(config);

                case "s7":
                    return new S7Communication(config);

                case "mc":
                    return new McCommunication(config);

                default:
                    throw new NotSupportedException(
                        $"不支持的协议类型: {config.ProtocolType}");
            }
        }
    }
}
```

```csharp

```

**使用工厂创建通信对象：**

```csharp
// 在程序启动时，根据配置创建通信对象
var config = ConfigManager.Instance.Settings.PlcConnection;
var deviceConfig = new DeviceConfig
{
    ProtocolType = config.ProtocolType,  // 从配置读取协议类型
    IpAddress = config.IpAddress,
    Port = config.Port,
    SlaveId = config.SlaveId
};

// 通过工厂创建 - 无需知道具体是哪个类
ICommunicationService commService = CommunicationFactory.Create(deviceConfig);

// 后续代码只依赖接口，不管具体是什么PLC
await commService.ConnectAsync();
var values = commService.ReadMultipleValues(new List<string> { "D100", "D102" });
```

**扩展新品牌时：**
1. 创建新的通信类，实现 `ICommunicationService`
2. 在工厂中添加一个新的 case 分支
3. 其他代码完全不需要修改

### 2.3 观察者模式 - 数据变化通知

**场景说明：** PLC数据采集后，多个模块需要知道数据变化（UI更新、报警检测、数据存储、日志记录）。观察者模式实现一对多的数据通知。

```
观察者模式核心思想：
- 一个对象（主题）状态变化时，自动通知所有依赖它的对象（观察者）
- 主题不需要知道观察者的具体类型
- 观察者可以动态添加和移除
```

```csharp
// ============================================================
// 文件：DataNotifier.cs
// 说明：观察者模式 - 数据变化通知中心
// 当PLC数据采集完成后，通知所有订阅的模块
// ============================================================
namespace HwPlcMonitor.Core.Events
{
    /// <summary>
    /// 数据变更事件参数
    /// 携带变化的数据内容
    /// </summary>
    public class DataChangedEventArgs : EventArgs
    {
        /// <summary>采集时间</summary>
        public DateTime CollectTime { get; set; }

        /// <summary>变更的数据（地址 -> 值）</summary>
        public Dictionary<string, object> ChangedData { get; set; }

        /// <summary>数据质量</summary>
        public int Quality { get; set; }
    }

    /// <summary>
    /// 数据变更通知中心（主题/被观察者）
    /// 数据采集模块采集到数据后，通过此类通知所有观察者
    /// </summary>
    public class DataNotifier
    {
        // 私有构造函数，单例模式
        private static readonly Lazy<DataNotifier> _instance =
            new Lazy<DataNotifier>(() => new DataNotifier());

        public static DataNotifier Instance => _instance.Value;

        // 事件定义 - 当数据变化时触发
        public event EventHandler<DataChangedEventArgs> DataChanged;

        /// <summary>
        /// 通知数据变化
        /// 由数据采集模块调用
        /// </summary>
        public void NotifyDataChanged(Dictionary<string, object> data)
        {
            var args = new DataChangedEventArgs
            {
                CollectTime = DateTime.Now,
                ChangedData = data,
                Quality = 0 // 假设数据质量好
            };

            // 触发事件，通知所有订阅者
            DataChanged?.Invoke(this, args);
        }
    }
}
```

```csharp
// ============================================================
// 文件：观察者订阅示例
// 说明：各模块作为观察者订阅数据变化事件
// ============================================================

/// <summary>UI模块 - 订阅数据变化来更新界面</summary>
public class MainViewModel
{
    public MainViewModel()
    {
        // 订阅数据变化事件
        DataNotifier.Instance.DataChanged += OnDataChanged;
    }

    private void OnDataChanged(object sender, DataChangedEventArgs e)
    {
        // 在UI线程上更新界面
        if (_mainForm.InvokeRequired)
        {
            _mainForm.BeginInvoke(new Action(() =>
            {
                UpdateDisplay(e.ChangedData);
            }));
        }
        else
        {
            UpdateDisplay(e.ChangedData);
        }
    }

    private void UpdateDisplay(Dictionary<string, object> data)
    {
        // 更新温度显示
        if (data.TryGetValue("D100", out var temp))
            _mainForm.lblTemp.Text = $"{temp} ℃";

        // 更新压力显示
        if (data.TryGetValue("D102", out var pressure))
            _mainForm.lblPressure.Text = $"{pressure} MPa";
    }
}

/// <summary>报警模块 - 订阅数据变化来检查报警</summary>
public class AlarmService : IAlarmService
{
    public AlarmService()
    {
        // 订阅数据变化事件
        DataNotifier.Instance.DataChanged += OnDataChanged;
    }

    private void OnDataChanged(object sender, DataChangedEventArgs e)
    {
        // 检查每个数据点是否触发报警
        foreach (var kvp in e.ChangedData)
        {
            CheckAlarm(kvp.Key, Convert.ToDouble(kvp.Value));
        }
    }
}

/// <summary>数据存储模块 - 订阅数据变化来保存数据</summary>
public class DataStorageObserver
{
    public DataStorageObserver()
    {
        // 订阅数据变化事件
        DataNotifier.Instance.DataChanged += OnDataChanged;
    }

    private async void OnDataChanged(object sender, DataChangedEventArgs e)
    {
        // 保存到数据库
        foreach (var kvp in e.ChangedData)
        {
            var data = new PlcDataModel
            {
                TagName = kvp.Key,
                Value = Convert.ToDouble(kvp.Value),
                CollectTime = e.CollectTime
            };
            await _dataService.SavePlcDataAsync(data);
        }
    }
}
```

### 2.4 策略模式 - 不同通信协议的切换

**场景说明：** 上位机可能需要在运行时切换通信协议（如从Modbus TCP切换到Modbus RTU），策略模式将不同的通信算法封装为独立的策略类。

```
策略模式核心思想：
- 定义一系列算法，将每个算法封装起来
- 算法之间可以互相替换
- 算法的变化独立于使用它的客户
```

```csharp
// ============================================================
// 文件：ICommStrategy.cs
// 说明：策略模式 - 通信策略接口
// ============================================================
namespace HwPlcMonitor.Core.Communication.Strategies
{
    /// <summary>
    /// 通信策略接口
    /// 每种通信协议是一种策略
    /// </summary>
    public interface ICommStrategy
    {
        /// <summary>策略名称</summary>
        string StrategyName { get; }

        /// <summary>连接设备</summary>
        Task<bool> ConnectAsync(DeviceConfig config);

        /// <summary>断开连接</summary>
        Task DisconnectAsync();

        /// <summary>读取单个值</summary>
        bool ReadValue(string address, out object value);

        /// <summary>写入值</summary>
        bool WriteValue(string address, object value);

        /// <summary>批量读取</summary>
        Dictionary<string, object> ReadBatch(List<string> addresses);

        /// <summary>是否已连接</summary>
        bool IsConnected { get; }
    }
}
```

```csharp
// ============================================================
// 文件：具体策略实现
// ============================================================

/// <summary>Modbus TCP策略</summary>
public class ModbusTcpStrategy : ICommStrategy
{
    public string StrategyName => "Modbus TCP";
    public bool IsConnected { get; private set; }

    private TcpClient _tcpClient;
    private IModbusMaster _master;
    private byte _slaveId;

    public async Task<bool> ConnectAsync(DeviceConfig config)
    {
        _tcpClient = new TcpClient();
        await _tcpClient.ConnectAsync(config.IpAddress, config.Port);
        _master = new ModbusFactory().CreateMaster(_tcpClient);
        _slaveId = config.SlaveId;
        IsConnected = true;
        return true;
    }

    public Dictionary<string, object> ReadBatch(List<string> addresses)
    {
        var result = new Dictionary<string, object>();
        var parsed = addresses.Select(a => (Name: a, Addr: int.Parse(a.Substring(1))))
                              .OrderBy(a => a.Addr).ToList();

        var data = _master.ReadHoldingRegisters(_slaveId, parsed.First().Addr, parsed.Count);
        for (int i = 0; i < parsed.Count; i++)
            result[parsed[i].Name] = data[i];

        return result;
    }

    // ... 其他方法实现省略
}

/// <summary>Modbus RTU策略（串口通信）</summary>
public class ModbusRtuStrategy : ICommStrategy
{
    public string StrategyName => "Modbus RTU";
    public bool IsConnected { get; private set; }

    private SerialPort _serialPort;
    private IModbusSerialMaster _master;
    private byte _slaveId;

    public async Task<bool> ConnectAsync(DeviceConfig config)
    {
        _serialPort = new SerialPort(config.ComPort, config.BaudRate, Parity.None, 8, StopBits.One);
        _serialPort.Open();
        _master = new ModbusFactory().CreateRtuMaster(_serialPort);
        _slaveId = config.SlaveId;
        IsConnected = true;
        return true;
    }

    // ... 其他方法实现类似，但使用串口通信
}
```

```csharp
// ============================================================
// 文件：CommunicationContext.cs
// 说明：策略上下文 - 使用策略的类
// ============================================================

/// <summary>
/// 通信上下文
/// 持有一个策略对象，可以在运行时切换策略
/// </summary>
public class CommunicationContext
{
    private ICommStrategy _currentStrategy;

    /// <summary>当前使用的策略</summary>
    public ICommStrategy CurrentStrategy
    {
        get => _currentStrategy;
        set
        {
            // 切换策略前先断开旧连接
            if (_currentStrategy != null && _currentStrategy.IsConnected)
                _currentStrategy.DisconnectAsync().Wait();

            _currentStrategy = value;
            Console.WriteLine($"通信策略已切换为: {_currentStrategy.StrategyName}");
        }
    }

    /// <summary>连接设备</summary>
    public async Task<bool> Connect(DeviceConfig config)
    {
        return await _currentStrategy.ConnectAsync(config);
    }

    /// <summary>读取数据</summary>
    public Dictionary<string, object> ReadData(List<string> addresses)
    {
        return _currentStrategy.ReadBatch(addresses);
    }
}
```

**运行时切换策略的示例：**

```csharp
// 创建通信上下文
var context = new CommunicationContext();

// 初始使用Modbus TCP策略

// 运行时切换到Modbus RTU策略
```

### 2.5 模板方法模式 - 数据采集流程标准化

**场景说明：** 不同设备的数据采集流程基本相同（连接 -> 读取 -> 验证 -> 保存 -> 检查报警），但某些步骤的具体实现不同。模板方法模式将公共流程固定，允许子类自定义特定步骤。

```
模板方法模式核心思想：
- 定义算法的骨架（模板方法）
- 将某些步骤延迟到子类实现
- 子类可以重写特定步骤而不改变算法结构
```

```csharp
// ============================================================
// 文件：DataCollectTemplate.cs
// 说明：模板方法模式 - 数据采集流程模板
// ============================================================
namespace HwPlcMonitor.Core.Services
{
    /// <summary>
    /// 数据采集服务基类（抽象模板）
    /// 定义了数据采集的标准流程，子类可以重写特定步骤
    /// </summary>
    public abstract class DataCollectTemplate
    {
        /// <summary>
        /// 采集流程（模板方法 - 固定流程，子类不应重写）
        /// </summary>
        public async Task CollectOnceAsync()
        {
            // 步骤1：采集前预处理
            OnBeforeCollect();

            // 步骤2：从设备读取原始数据（子类实现）
            Dictionary<string, object> rawData;
            try
            {
                rawData = await ReadRawDataAsync();
            }
            catch (Exception ex)
            {
                OnCollectError(ex);
                return; // 读取失败，后续步骤不执行
            }

            // 步骤3：验证数据有效性（子类可重写验证规则）
            if (!ValidateData(rawData))
            {
                OnDataInvalid(rawData);
                return;
            }

            // 步骤4：数据转换/缩放（子类可重写转换逻辑）
            var convertedData = ConvertData(rawData);

            // 步骤5：数据保存
            SaveData(convertedData);

            // 步骤6：报警检测
            CheckAlarms(convertedData);

            // 步骤7：采集后处理
            OnAfterCollect(convertedData);
        }

        // ========== 抽象方法 - 子类必须实现 ==========

        /// <summary>读取原始数据（核心步骤，必须子类实现）</summary>
        protected abstract Task<Dictionary<string, object>> ReadRawDataAsync();

        // ========== 虚方法 - 子类可以重写 ==========

        /// <summary>采集前预处理（默认空实现）</summary>
        protected virtual void OnBeforeCollect()
        {
            // 默认什么都不做，子类可以重写
        }

        /// <summary>验证数据有效性（默认检查是否为空）</summary>
        protected virtual bool ValidateData(Dictionary<string, object> data)
        {
            return data != null && data.Count > 0;
        }

        /// <summary>数据转换/缩放（默认直接返回原始数据）</summary>
        protected virtual Dictionary<string, object> ConvertData(Dictionary<string, object> rawData)
        {
            // 默认不做转换，子类可以重写进行数据缩放
            // 例如：PLC原始值是整数，需要除以10得到实际温度
            return rawData;
        }

        /// <summary>采集后处理（默认空实现）</summary>
        protected virtual void OnAfterCollect(Dictionary<string, object> data)
        {
            // 默认什么都不做，子类可以重写
        }

        // ========== 钩子方法 - 子类可以重写 ==========

        /// <summary>采集错误处理</summary>
        protected virtual void OnCollectError(Exception ex)
        {
            Console.WriteLine($"采集错误: {ex.Message}");
        }

        /// <summary>数据无效处理</summary>
        protected virtual void OnDataInvalid(Dictionary<string, object> data)
        {
            Console.WriteLine($"数据验证失败: {data.Count}个数据点");
        }

        // ========== 具体方法 - 子类不应重写 ==========

        /// <summary>保存数据到数据库</summary>
        private void SaveData(Dictionary<string, object> data)
        {
            foreach (var kvp in data)
            {
                _dataService.SavePlcDataAsync(new PlcDataModel
                {
                    TagName = kvp.Key,
                    Value = Convert.ToDouble(kvp.Value),
                    CollectTime = DateTime.Now
                });
            }
        }

        /// <summary>检查报警</summary>
        private void CheckAlarms(Dictionary<string, object> data)
        {
            foreach (var kvp in data)
                _alarmService.CheckAlarm(kvp.Key, Convert.ToDouble(kvp.Value));

    }
```

```csharp
/// <summary>
/// 汇川PLC数据采集服务
/// 重写ReadRawDataAsync实现Modbus通信读取
/// 重写ConvertData实现数据缩放
/// </summary>
public class HwPlcCollectService : DataCollectTemplate
{
    private readonly ICommunicationService _commService;

    public HwPlcCollectService(ICommunicationService commService)
    {
        _commService = commService;
    }

    protected override async Task<Dictionary<string, object>> ReadRawDataAsync()
    {
        // 汇川PLC使用Modbus协议读取
        var addresses = new List<string> { "D100", "D102", "D104" };
        return await Task.FromResult(_commService.ReadMultipleValues(addresses));
    }

    protected override Dictionary<string, object> ConvertData(Dictionary<string, object> rawData)
    {
        // 汇川PLC的D寄存器是16位无符号整数
        // 温度寄存器D100: 实际温度 = 原始值 / 10
        // 压力寄存器D102: 实际压力 = 原始值 / 100
        var result = new Dictionary<string, object>();

        if (rawData.TryGetValue("D100", out var tempRaw))
            result["D100"] = Convert.ToDouble(tempRaw) / 10.0; // 753 -> 75.3

        if (rawData.TryGetValue("D102", out var pressRaw))
            result["D102"] = Convert.ToDouble(pressRaw) / 100.0; // 152 -> 1.52

        if (rawData.TryGetValue("D104", out var flowRaw))
            result["D104"] = Convert.ToDouble(flowRaw) / 10.0; // 285 -> 28.5

        return result;
    }

    protected override void OnCollectError(Exception ex)
    {
        // 汇川特有的错误处理：增加通信计数器
        _commErrorCount++;
        _log.Warning(ex, "汇川PLC采集失败，累计错误次数: {Count}", _commErrorCount);
    }
}
```

## 三、注意事项

### 3.1 设计模式使用原则

| 原则 | 说明 |
|------|------|
| **不要过度设计** | 小项目不需要用所有设计模式，按需使用 |
| **先解决问题再套模式** | 不要为了用模式而用模式，先有需求再有设计 |
| **组合优于继承** | 优先使用组合和委托，而不是复杂的继承层次 |
| **简单优先** | 能用简单方法解决的就不要引入复杂模式 |

### 3.2 上位机中各模式的适用场景总结

| 设计模式 | 最适用场景 | 不适用场景 |
|----------|-----------|-----------|
| **单例模式** | 配置管理、日志管理、全局状态 | 需要多个实例的场景 |
| **工厂模式** | 创建不同品牌的PLC通信对象 | 只有唯一实现时 |
| **观察者模式** | 数据变化通知多个模块 | 只有一个订阅者时（直接调用即可） |
| **策略模式** | 运行时需要切换算法 | 算法固定不变时 |
| **模板方法** | 流程相同但步骤实现不同 | 流程各异时 |

## 四、实战案例

### 案例：整合所有设计模式的完整示例

**场景：一个支持多PLC品牌的上位机监控系统**

```csharp
// 程序入口 - 整合所有设计模式
static class Program
{
    [STAThread]
    static void Main()
    {
        // 1. 单例模式：获取全局配置
        var config = ConfigManager.Instance.Settings;

        // 2. 工厂模式：根据配置创建通信对象
        var deviceConfig = new DeviceConfig
        {
            ProtocolType = config.PlcConnection.ProtocolType,
            IpAddress = config.PlcConnection.IpAddress,
            Port = config.PlcConnection.Port,
            SlaveId = config.PlcConnection.SlaveId
        };
        ICommunicationService commService = CommunicationFactory.Create(deviceConfig);

        // 3. 模板方法模式：创建采集服务（选择具体实现）
        DataCollectTemplate collectService;
        switch (config.PlcConnection.ProtocolType)
        {
            case "ModbusTcp":
                collectService = new HwPlcCollectService(commService);
                break;
            case "S7":
                collectService = new SiemensPlcCollectService(commService);
                break;
            default:
                collectService = new HwPlcCollectService(commService);
                break;
        }

        // 4. 启动主界面
        Application.Run(new MainForm(commService, collectService));
    }
}

// MainForm中使用观察者模式
public partial class MainForm : Form
{
    public MainForm(ICommunicationService commService, DataCollectTemplate collectService)
    {
        // 5. 观察者模式：订阅数据变化
        DataNotifier.Instance.DataChanged += OnDataChanged;
    }

    private void OnDataChanged(object sender, DataChangedEventArgs e)
    {
        // 更新UI显示
        UpdateDisplay(e.ChangedData);
    }

    // 6. 策略模式：在设置界面可以切换通信策略
    private void ChangeProtocol(string newProtocol)
    {
        var newStrategy = CommunicationFactory.Create(new DeviceConfig
        {
            ProtocolType = newProtocol,
            IpAddress = txtIpAddress.Text,
            Port = int.Parse(txtPort.Text)
        });
        // 切换通信策略
        _commContext.CurrentStrategy = newStrategy;
    }
}
```

> **提示**：设计模式是工具，不是目的。在实际项目中，建议从最简单的实现开始，当遇到代码扩展和维护困难时，再引入合适的设计模式进行重构。过度使用设计模式反而会让代码变得复杂难懂。
