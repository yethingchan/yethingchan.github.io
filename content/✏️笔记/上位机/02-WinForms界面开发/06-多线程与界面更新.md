## 1. WinForms 的 UI 线程模型

### 知识讲解

WinForms 基于 Windows 消息循环机制，具有严格的线程规则。

**核心概念：**

```
┌─────────────────────────────────────────────┐
│              UI 线程（主线程）                 │
│                                              │
│  ┌──────────┐    ┌──────────┐               │
│  │ 消息队列  │───→│ 消息泵    │───→ 控件方法  │
│  │ (MSG)    │    │ (Dispatch)│               │
│  └──────────┘    └──────────┘               │
│       ↑                                      │
│  鼠标/键盘事件、Timer、Invoke、Paint...       │
└─────────────────────────────────────────────┘
```

**消息循环的工作流程：**

1. `Application.Run()` 启动消息循环
2. 系统不断从消息队列中取出消息（MSG）
3. 消息泵（Dispatch）将消息分发给对应的窗口过程
4. 窗口过程处理消息（如 Click、Paint、Timer）
5. 处理完毕后继续取下一条消息

**关键规则：**

| 规则 | 说明 |
|------|------|
| **单线程规则** | 创建控件的线程拥有该控件，只有创建线程可以直接操作控件 |
| **消息循环** | UI 线程通过消息循环处理所有 UI 事件（包括重绘） |
| **阻塞后果** | 如果 UI 线程被阻塞（执行耗时操作），消息循环停滞，界面冻结 |

### 代码示例

```csharp
// Program.cs —— 消息循环的入口
static class Program
{
    [STAThread]
    static void Main()
    {
        Application.EnableVisualStyles();
        Application.SetCompatibleTextRenderingDefault(false);

        // Application.Run 内部启动消息循环：
        // while (GetMessage(&msg, hWnd, 0, 0))
        // {
        //     TranslateMessage(&msg);
        //     DispatchMessage(&msg);
        // }
        Application.Run(new MainForm());
    }
}
```

### 注意事项

- **UI 线程只有一个**：整个应用程序通常只有一个 UI 线程（主线程），所有控件都创建在这个线程上。
- **消息循环是顺序的**：一条消息处理完后才处理下一条。如果某条消息的处理耗时很长，后续消息（包括重绘消息）都会排队等待。
- **Timer 在 UI 线程触发**：`System.Windows.Forms.Timer` 的 Tick 事件在 UI 线程上执行，不创建新线程。

### 练习建议

1. 在一个按钮的 Click 事件中添加 `Thread.Sleep(5000)`，点击按钮后尝试拖动窗口，观察界面的冻结效果。
2. 使用 `Application.DoEvents()`（了解即可，不推荐使用）临时缓解界面冻结，但理解其副作用。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| 界面冻结无响应 | UI 线程被耗时操作阻塞 | 将耗时操作放到后台线程 |

## 2. 为什么不能在子线程操作 UI 控件

### 知识讲解

在子线程（非 UI 线程）中直接修改控件属性或调用控件方法，会抛出 `InvalidOperationException` 异常。

**异常信息：**
```
System.InvalidOperationException: 跨线程操作无效: 从不是创建控件"xxx"的线程访问它。
```

**为什么会有这个限制？**

1. **线程安全**：WinForms 控件不是线程安全的，多个线程同时操作同一个控件可能导致内部状态损坏。
2. **消息循环一致性**：UI 操作必须通过消息循环分发，子线程直接操作绕过了消息循环。
3. **调试辅助**：这个异常是在 .NET 2.0 之后引入的，帮助开发者尽早发现线程安全问题。

### 代码示例

```csharp
public partial class CrossThreadDemo : Form
{
    private Label lblStatus;

    public CrossThreadDemo()
    {
        // 模拟在子线程中直接操作 UI 控件（错误示范）
        var thread = new Thread(() =>
        {
            // 这行代码会抛出 InvalidOperationException
            lblStatus.Text = "操作完成";  // 错误！
        });
        thread.Start();
    }
}

// ====== 正确的做法（后续章节详解）======
public partial class CrossThreadCorrectDemo : Form
{
    private Label lblStatus;

    public CrossThreadCorrectDemo()
    {
        var thread = new Thread(() =>
        {
            // 使用 Invoke 将操作切换到 UI 线程执行
            if (lblStatus.InvokeRequired)
            {
                lblStatus.Invoke(new Action(() =>
                {
                    lblStatus.Text = "操作完成";  // 正确！在 UI 线程上执行
                }));
            }
            else
            {
                lblStatus.Text = "操作完成";  // 已经在 UI 线程上，直接操作
            }
        });
        thread.Start();
    }
}
```

### 注意事项

- **InvokeRequired 属性**：如果当前线程不是创建控件的线程，`InvokeRequired` 返回 `true`。
- **调试时的异常**：在 Visual Studio 调试模式下，跨线程操作默认会抛出异常。但在 Release 模式下，可以通过 `Control.CheckForIllegalCrossThreadCalls = false` 禁用检查（**不推荐**，只是隐藏了问题）。

### 练习建议

1. 创建一个后台线程，在其中尝试直接修改 Label 的 Text，观察异常。
2. 使用 `Control.CheckForIllegalCrossThreadCalls = false` 禁用检查（仅了解，不要在实际项目中使用），看看会发生什么。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| InvalidOperationException | 子线程直接操作 UI 控件 | 使用 Invoke/BeginInvoke 切回 UI 线程 |
| 界面偶尔崩溃（不调试时） | 禁用了跨线程检查 | 使用正确的跨线程方式 |

## 3. Control.Invoke 与 BeginInvoke

### 知识讲解

`Invoke` 和 `BeginInvoke` 是将操作从后台线程发送到 UI 线程执行的标准方法。

**对比：**

| 方法 | 类型 | 等待 UI 线程执行完毕 | 返回值 |
|------|------|---------------------|--------|
| `Invoke` | 同步 | **是**，阻塞后台线程直到 UI 线程执行完毕 | `object`（委托的返回值） |
| `BeginInvoke` | 异步 | **否**，立即返回，后台线程继续执行 | `IAsyncResult` |

**工作原理：**

```
后台线程                    UI 线程（消息循环）
   │                            │
   ├─ Invoke(delegate) ────────→│ 将 delegate 放入消息队列
   │   （等待...）               │ 取出并执行 delegate
   │←─────── 返回结果 ──────────│
   │                            │
   ├─ BeginInvoke(delegate) ───→│ 将 delegate 放入消息队列
   ├─ 继续执行（不等待）         │ 取出并执行 delegate（稍后）
   │                            │
```

### 代码示例

```csharp
using System;
using System.Threading;
using System.Windows.Forms;

public partial class InvokeDemo : Form
{
    private Label lblStatus;
    private ProgressBar progressBar;
    private DataGridView dgvData;

    public InvokeDemo()
    {
        InitializeComponent();
    }

    // ========== Invoke 示例（同步）==========
    /// <summary>
    /// 批量读取 PLC 寄存器 —— 使用 Invoke 同步更新进度
    /// </summary>
    private void btnReadAll_Click(object sender, EventArgs e)
    {
        btnReadAll.Enabled = false;

        // 启动后台线程
        var thread = new Thread(() =>
        {
            int total = 100;
            for (int i = 0; i < total; i++)
            {
                // 模拟读取 PLC（耗时操作）
                Thread.Sleep(50);

                // 使用 Invoke 同步更新 UI（会等待 UI 线程执行完毕）
                this.Invoke(new Action(() =>
                {
                    progressBar.Value = i + 1;
                    lblStatus.Text = $"读取中... ({i + 1}/{total})";
                }));
            }

            // 读取完成，更新 UI
            this.Invoke(new Action(() =>
            {
                lblStatus.Text = "批量读取完成";
                btnReadAll.Enabled = true;
                MessageBox.Show("读取完成！", "提示");
            }));
        });
        thread.IsBackground = true;  // 设为后台线程，主窗口关闭时自动结束
        thread.Start();
    }

    // ========== BeginInvoke 示例（异步）==========
    /// <summary>
    /// 使用 BeginInvoke 异步更新 UI（不等待 UI 线程执行完毕）
    /// 场景：高频数据更新，不需要等待 UI 线程绘制完成
    /// </summary>
    private void HighFrequencyUpdate()
    {
        var thread = new Thread(() =>
        {
            while (true)
            {
                // 读取 PLC 数据
                var data = ReadPlcData();

                // 使用 BeginInvoke 异步更新 UI（不等待绘制完成）
                this.BeginInvoke(new Action(() =>
                {
                    lblStatus.Text = $"温度：{data.Temperature}°C";
                }));

                Thread.Sleep(100);  // 每 100ms 读取一次
            }
        });
        thread.IsBackground = true;
        thread.Start();
    }

    // ========== 封装 Invoke 辅助方法 ==========
    /// <summary>
    /// 线程安全的 UI 更新辅助方法
    /// </summary>
    private void UpdateUI(Action action)
    {
        if (this.InvokeRequired)
        {
            this.Invoke(action);
        }
        else
        {
            action();
        }
    }

    /// <summary>
    /// 线程安全的异步 UI 更新辅助方法
    /// </summary>
    private void UpdateUIAsync(Action action)
    {
        if (this.InvokeRequired)
        {
            this.BeginInvoke(action);
        }
        else
        {
            action();
        }
    }

    // ========== 使用封装方法简化代码 ==========
    private void btnConnect_Click(object sender, EventArgs e)
    {
        var thread = new Thread(() =>
        {
            // 连接 PLC（耗时操作）
            Thread.Sleep(2000);

            // 更新 UI —— 使用辅助方法
            UpdateUI(() =>
            {
                lblStatus.Text = "已连接";
                lblStatus.ForeColor = Color.Green;
            });
        });
        thread.IsBackground = true;
        thread.Start();
    }

    // ========== Invoke 带返回值 ==========
    /// <summary>
    /// 从后台线程获取 UI 控件的值
    /// </summary>
    private string GetTextBoxTextThreadSafe()
    {
        if (txtIpAddress.InvokeRequired)
        {
            return (string)txtIpAddress.Invoke(new Func<string>(() => txtIpAddress.Text));
        }
        return txtIpAddress.Text;
    }

    // ========== 批量更新时避免频繁 Invoke ==========
    /// <summary>
    /// 批量读取后一次性更新 DataGridView（而不是每读一个就 Invoke 一次）
    /// </summary>
    private void btnBatchRead_Click(object sender, EventArgs e)
    {
        var thread = new Thread(() =>
        {
            var results = new System.Collections.Generic.List<(string Addr, double Value)>();

            // 在后台线程中完成所有读取
            for (int i = 0; i < 100; i++)
            {
                Thread.Sleep(20);
                results.Add(($"D{i + 100}", i * 1.5));
            }

            // 一次性更新 UI（只 Invoke 一次）
            UpdateUI(() =>
            {
                dgvData.Rows.Clear();
                foreach (var (addr, val) in results)
                {
                    dgvData.Rows.Add(addr, val.ToString("F1"), "正常");
                }
                lblStatus.Text = $"已读取 {results.Count} 个寄存器";
            });
        });
        thread.IsBackground = true;
        thread.Start();
    }

    private object ReadPlcData()
    {
        return new { Temperature = 45.2 + new Random().NextDouble() * 5 };
    }
}
```

### 注意事项

- **Invoke vs BeginInvoke 的选择**：大多数情况下使用 `Invoke`（同步）更安全。`BeginInvoke`（异步）适用于高频更新场景，但可能导致消息队列积压。
- **避免频繁 Invoke**：每次 Invoke 都会向 UI 消息队列发送一条消息。如果在循环中频繁 Invoke（如每 10ms 一次），会导致消息队列积压，UI 线程处理不过来。建议批量收集数据后一次性更新。
- **IsBackground = true**：将后台线程设为后台线程，主窗口关闭时线程会自动结束，避免程序退出后线程仍在运行。
- **Invoke 死锁风险**：如果 UI 线程正在等待后台线程完成（如 `thread.Join()`），而后台线程又在 `Invoke` 等待 UI 线程，就会产生死锁。

### 练习建议

1. 创建一个按钮，点击后启动后台线程执行耗时操作，使用 `Invoke` 更新进度条。
2. 对比 `Invoke` 和 `BeginInvoke` 在高频更新场景下的表现差异。
3. 实现一个 `UpdateUI(Action)` 辅助方法，封装 Invoke/InvokeRequired 的判断逻辑。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| 死锁 | UI 线程等后台线程，后台线程等 Invoke | 不要在 UI 线程上 Join/Wait 后台线程 |
| 界面卡顿 | 循环中频繁 Invoke | 批量更新，减少 Invoke 次数 |
| Invoke 后控件已被释放 | 窗体已关闭但后台线程仍在运行 | 在 Invoke 前检查 `IsHandleCreated` 或 `IsDisposed` |

## 4. BackgroundWorker 组件

### 知识讲解

`BackgroundWorker` 是 .NET 提供的异步操作组件，封装了线程创建、进度报告和完成通知。虽然现代开发中推荐使用 `async/await`，但了解 `BackgroundWorker` 对于维护旧项目仍有价值。

**核心事件：**

| 事件 | 触发线程 | 说明 |
|------|---------|------|
| `DoWork` | 后台线程 | 执行耗时操作的地方 |
| `ProgressChanged` | UI 线程 | 报告进度（自动切换到 UI 线程） |
| `RunWorkerCompleted` | UI 线程 | 操作完成/取消/出错（自动切换到 UI 线程） |

**核心方法：**

| 方法 | 说明 |
|------|------|
| `RunWorkerAsync()` | 启动后台操作 |
| `ReportProgress(percent)` | 报告进度（触发 ProgressChanged） |
| `CancelAsync()` | 请求取消操作 |

### 代码示例

```csharp
using System;
using System.ComponentModel;
using System.Windows.Forms;

public partial class BackgroundWorkerDemo : Form
{
    private BackgroundWorker _worker;
    private ProgressBar progressBar;
    private Label lblStatus;
    private Button btnStart;
    private Button btnCancel;

    public BackgroundWorkerDemo()
    {
        InitializeComponent();
        InitializeBackgroundWorker();
    }

    private void InitializeBackgroundWorker()
    {
        _worker = new BackgroundWorker
        {
            WorkerReportsProgress = true,   // 允许报告进度
            WorkerSupportsCancellation = true // 允许取消
        };

        // 订阅事件
        _worker.DoWork += Worker_DoWork;
        _worker.ProgressChanged += Worker_ProgressChanged;
        _worker.RunWorkerCompleted += Worker_RunWorkerCompleted;
    }

    /// <summary>
    /// 启动按钮
    /// </summary>
    private void btnStart_Click(object sender, EventArgs e)
    {
        if (_worker.IsBusy) return;  // 防止重复启动

        btnStart.Enabled = false;
        btnCancel.Enabled = true;
        progressBar.Value = 0;
        lblStatus.Text = "开始批量读取...";

        // 启动后台操作（可传递参数）
        _worker.RunWorkerAsync(100);  // 参数：读取 100 个寄存器
    }

    /// <summary>
    /// 取消按钮
    /// </summary>
    private void btnCancel_Click(object sender, EventArgs e)
    {
        _worker.CancelAsync();  // 请求取消
        lblStatus.Text = "正在取消...";
    }

    // ========== DoWork —— 在后台线程执行 ==========
    private void Worker_DoWork(object sender, DoWorkEventArgs e)
    {
        int total = (int)e.Argument;  // 获取传入的参数
        var worker = (BackgroundWorker)sender;

        for (int i = 0; i < total; i++)
        {
            // 检查是否请求取消
            if (worker.CancellationPending)
            {
                e.Cancel = true;  // 标记为已取消
                return;
            }

            // 模拟读取 PLC（耗时操作）
            System.Threading.Thread.Sleep(50);

            // 报告进度（自动切换到 UI 线程触发 ProgressChanged）
            int percent = (i + 1) * 100 / total;
            worker.ReportProgress(percent, $"读取 D{i + 100}...");
        }

        e.Result = $"成功读取 {total} 个寄存器";  // 设置结果
    }

    // ========== ProgressChanged —— 在 UI 线程执行 ==========
    private void Worker_ProgressChanged(object sender, ProgressChangedEventArgs e)
    {
        // 直接更新 UI 控件（无需 Invoke）
        progressBar.Value = e.ProgressPercentage;
        lblStatus.Text = $"进度：{e.ProgressPercentage}% - {e.UserState}";
    }

    // ========== RunWorkerCompleted —— 在 UI 线程执行 ==========
    private void Worker_RunWorkerCompleted(object sender, RunWorkerCompletedEventArgs e)
    {
        btnStart.Enabled = true;
        btnCancel.Enabled = false;

        if (e.Cancelled)
        {
            lblStatus.Text = "操作已取消";
            MessageBox.Show("操作已被用户取消。", "提示");
        }
        else if (e.Error != null)
        {
            lblStatus.Text = "操作出错";
            MessageBox.Show($"操作出错：{e.Error.Message}", "错误", MessageBoxButtons.OK, MessageBoxIcon.Error);
        }
        else
        {
            lblStatus.Text = "操作完成";
            MessageBox.Show($"结果：{e.Result}", "完成");
        }
    }
}
```

### 注意事项

- **ProgressChanged 和 RunWorkerCompleted 自动在 UI 线程执行**，不需要手动 Invoke，这是 BackgroundWorker 最大的优势。
- **CancellationToken 模式**：`CancelAsync()` 只是设置一个标志，`DoWork` 中需要手动检查 `CancellationPending`。
- **不要重复启动**：检查 `IsBusy` 属性，防止多次点击启动多个后台操作。
- **BackgroundWorker 已过时**：新项目推荐使用 `async/await`（更简洁、更现代），但旧项目维护中仍会遇到。

### 练习建议

1. 使用 BackgroundWorker 实现一个批量读取 PLC 寄存器的功能，支持进度显示和取消操作。
2. 在 RunWorkerCompleted 事件中处理三种结果：成功、取消、异常。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| 重复启动报错 | IsBusy 为 true 时再次 RunWorkerAsync | 检查 IsBusy 后再启动 |
| 取消后仍继续执行 | DoWork 中未检查 CancellationPending | 定期检查 CancellationPending |
| 传参报错 | RunWorkerAsync 参数类型不对 | 使用 e.Argument 获取参数 |

## 5. async/await 配合 UI 更新（推荐方案）

### 知识讲解

`async/await` 是 .NET 4.5 引入的异步编程模型，是目前 WinForms 后台操作 + UI 更新的**最佳实践**。相比 `BackgroundWorker` 和手动 `Invoke`，它更简洁、更直观、更不容易出错。

**核心原理：**

```csharp
private async void btnRead_Click(object sender, EventArgs e)
{
    // UI 线程上执行
    btnRead.Enabled = false;
    
    // await 后面的代码会在后台线程执行
    var data = await Task.Run(() =>
    {
        return ReadPlcData();  // 耗时操作在线程池中执行
    });
    
    // await 之后的代码自动回到 UI 线程
    lblValue.Text = data.ToString();  // 安全！已在 UI 线程上
    btnRead.Enabled = true;
}
```

**`await` 前后线程切换图：**

```
UI 线程：  [btnRead.Enabled=false] ──── [await...] ──── [lblValue.Text=...] ──── [btnRead.Enabled=true]
                                                  │
                                        ┌─────────┴─────────┐
                                        │   线程池线程       │
                                        │  ReadPlcData()    │
                                        │  （耗时操作）      │
                                        └───────────────────┘
```

### 代码示例

```csharp
using System;
using System.Collections.Generic;
using System.Threading;
using System.Threading.Tasks;
using System.Windows.Forms;

public partial class AsyncAwaitDemo : Form
{
    private Label lblStatus;
    private Label lblTemperature;
    private Label lblPressure;
    private DataGridView dgvData;
    private ProgressBar progressBar;
    private CancellationTokenSource _cts;  // 取消令牌源

    public AsyncAwaitDemo()
    {
        InitializeComponent();
    }
```

### 注意事项

- **async void 仅用于事件处理方法**：在所有其他场景中，应使用 `async Task` 返回类型。`async void` 方法中未捕获的异常会直接导致程序崩溃。
- **Task.Run 中的 CancellationToken**：`Task.Run(action, cancellationToken)` 会在取消时自动中断任务。
- **Task.WhenAll 并行执行**：当需要同时读取多台 PLC 时，使用 `Task.WhenAll` 可以并行执行，大幅缩短总耗时。
- **避免在 async 方法中同步阻塞**：不要在 async 方法中使用 `.Result`、`.Wait()`、`Thread.Sleep()`，应使用 `await`、`await Task.Delay()`。
- **UI 线程返回保证**：`await` 之前的代码和 `await` 之后回到调用方的代码，都在 UI 线程上执行（WinForms 的 SynchronizationContext 保证）。

### 练习建议

1. 使用 `async/await` 实现一个带进度条的批量读取功能，支持取消。
2. 使用 `Task.WhenAll` 并行读取 3 台 PLC 的数据。
3. 在 `async void` 事件处理方法中故意不写 try-catch，观察异常导致的程序崩溃。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| 程序崩溃（无异常信息） | async void 中异常未捕获 | async void 中始终用 try-catch |
| 死锁 | async 方法中调用 .Result 或 .Wait() | 使用 await 代替 |
| 取消不生效 | 未传递 CancellationToken | Task.Run(action, token) 传递令牌 |
| 界面冻结 | async 中使用了 Thread.Sleep | 使用 await Task.Delay() |

## 6. SynchronizationContext

### 知识讲解

`SynchronizationContext` 是 .NET 中用于在线程间同步执行的抽象机制。在 WinForms 中，UI 线程维护了一个 `WindowsFormsSynchronizationContext`，它捕获了 UI 线程的同步上下文，使得 `await` 能够自动回到 UI 线程。

**工作原理：**

```
UI 线程启动时：
  SynchronizationContext.Current = new WindowsFormsSynchronizationContext()

await 捕获当前 SynchronizationContext：
  var context = SynchronizationContext.Current;  // WindowsForms 的

await 完成后通过 context.Post 回调：
  context.Post(callback, state);  // 等同于 Control.BeginInvoke
```

### 代码示例

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

/// <summary>
/// SynchronizationContext 在 WinForms 中的应用
/// </summary>
public partial class SyncContextDemo : Form
{
    // 保存 UI 线程的 SynchronizationContext
    private readonly SynchronizationContext _uiContext;

    public SyncContextDemo()
    {
        InitializeComponent();

        // 在 UI 线程上捕获 SynchronizationContext
        _uiContext = SynchronizationContext.Current;
    }

    // ========== 方式一：使用 SynchronizationContext.Post（异步回调）==========
    /// <summary>
    /// 使用 SynchronizationContext 更新 UI
    /// Post = 异步（等同 BeginInvoke）
    /// Send = 同步（等同 Invoke）
    /// </summary>
    private void UpdateViaSynchronizationContext(string message)
    {
        // 从任意线程调用
        _uiContext.Post(state =>
        {
            // 这段代码会在 UI 线程上执行
            lblStatus.Text = (string)state;
        }, message);
    }

    // ========== 方式二：在非 UI 组件中使用 async/await ==========
    /// <summary>
    /// 场景：在独立的业务类中执行异步操作，并通过回调通知 UI
    /// SynchronizationContext 确保回调在 UI 线程执行
    /// </summary>
    public class PlcService
    {
        private SynchronizationContext _syncContext;
        private Timer _pollTimer;

        public event Action<string> StatusChanged;
        public event Action<double> DataReceived;

        public PlcService()
        {
            // 在构造时捕获调用者的 SynchronizationContext
            // （如果在 UI 线程上创建此对象，就能捕获 UI 上下文）
            _syncContext = SynchronizationContext.Current;
        }

        public void StartPolling()
        {
            _pollTimer = new Timer(state =>
            {
                // 在线程池线程中执行
                var data = ReadPlcData();

                // 通过 SynchronizationContext 回调到 UI 线程
                if (_syncContext != null)
                {
                    _syncContext.Post(_ =>
                    {
                        DataReceived?.Invoke(data);
                        StatusChanged?.Invoke("数据已更新");
                    }, null);
                }
            }, null, 0, 1000);
        }

        public void StopPolling()
        {
            _pollTimer?.Dispose();
        }

        private double ReadPlcData()
        {
            Thread.Sleep(100);  // 模拟通信
            return 45.2 + new Random().NextDouble() * 5;
        }
    }

    // ========== 使用 PlcService（自动回调到 UI 线程）==========
    private PlcService _plcService;

    private void btnStart_Click(object sender, EventArgs e)
    {
        // 在 UI 线程上创建 PlcService（自动捕获 SynchronizationContext）
        _plcService = new PlcService();
        _plcService.StatusChanged += msg => lblStatus.Text = msg;  // 自动在 UI 线程
        _plcService.DataReceived += val => lblValue.Text = $"{val:F1}";  // 自动在 UI 线程
        _plcService.StartPolling();
    }
}
```

### 注意事项

- **在 UI 线程上创建服务对象**：`SynchronizationContext.Current` 在 UI 线程上调用时才能获取到 `WindowsFormsSynchronizationContext`。如果在后台线程上创建服务对象，`Current` 可能为 null。
- **async/await 的底层原理**：`await` 在 WinForms 中就是通过 `SynchronizationContext` 实现自动回到 UI 线程的。了解这一点有助于理解 async/await 的工作方式。
- **Post vs Send**：`Post` 是异步的（类似 BeginInvoke），`Send` 是同步的（类似 Invoke）。通常使用 `Post`。

### 练习建议

1. 创建一个 `PlcService` 类，在 UI 线程上创建实例，验证事件回调是否在 UI 线程上执行。
2. 在后台线程上创建 `PlcService`，观察 `SynchronizationContext.Current` 是否为 null。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| 回调中操作 UI 仍报跨线程异常 | 在后台线程创建服务，SynchronizationContext 为 null | 在 UI 线程上创建服务对象 |
| SynchronizationContext 为 null | 在非 UI 线程上访问 Current | 确保在 UI 线程上捕获 |

```csharp
        {
            _dgvData.SuspendLayout();
            _dgvData.Rows.Clear();

            foreach (var reg in result.Registers)
            {
                string status = reg.Value > 80 ? "报警" : reg.Value > 60 ? "警告" : "正常";
                _dgvData.Rows.Add(reg.Address, reg.Value.ToString("F1"), reg.Unit, status,
                    DateTime.Now.ToString("HH:mm:ss"));
            }

            _dgvData.ResumeLayout();
        }

        private void UpdateChart(PlcPollResult result)
        {
            int tick = _pollCount;
            double temp = result.Registers.FirstOrDefault(r => r.Address == "D100").Value;
            double pressure = result.Registers.FirstOrDefault(r => r.Address == "D101").Value;

            _chartData.Add((tick, temp, pressure));

            // 最多显示 60 个点
            if (_chartData.Count > 60)
                _chartData.RemoveAt(0);

            _chartTrend.Series["温度"].Points.Clear();
            _chartTrend.Series["压力"].Points.Clear();

            foreach (var (t, tp, pr) in _chartData)
            {
                _chartTrend.Series["温度"].Points.AddXY(t, tp);
                _chartTrend.Series["压力"].Points.AddXY(t, pr);
            }

            // 调整 X 轴
            var area = _chartTrend.ChartAreas["Main"];
            area.AxisX.Minimum = Math.Max(0, tick - 60);
            area.AxisX.Maximum = Math.Max(60, tick);
        }

        // ========== 窗体关闭 ==========
        private void MainForm_FormClosing(object sender, FormClosingEventArgs e)
        {
            _cts?.Cancel();
            _pollingService?.Stop();
        }
    }

    #region ===== 轮询服务类 =====

    /// <summary>
    /// PLC 轮询服务 —— 独立于 UI 的业务逻辑层
    /// 通过 SynchronizationContext 自动将事件回调到 UI 线程
    /// </summary>
    public class PlcPollingService
    {
        private SynchronizationContext _syncContext;
        private Timer _pollTimer;
        private PlcSimulator _plc = new PlcSimulator();
        private bool _isRunning;

        public event Action<PlcPollResult> DataReceived;
        public event Action<string> ErrorOccurred;
        public event Action<string> StatusChanged;

        public PlcPollingService()
        {
            // 捕获当前线程的 SynchronizationContext
            _syncContext = SynchronizationContext.Current;
        }

        /// <summary>
        /// 启动轮询（异步方法）
        /// </summary>
        public async Task StartAsync(string plcIp, int port, int intervalMs, CancellationToken ct)
        {
            _isRunning = true;
            RaiseStatusChanged("正在连接...");

            // 模拟连接
            await Task.Delay(1000, ct);

            RaiseStatusChanged("已连接，开始轮询");
            _plc.Connect(plcIp, port);

            // 创建轮询定时器（使用 System.Threading.Timer，在后台线程执行）
            var tcs = new TaskCompletionSource<bool>();

            _pollTimer = new Timer(async _ =>
            {
                if (!_isRunning || ct.IsCancellationRequested)
                {
                    tcs.TrySetResult(true);
                    return;
                }

                try
                {
                    // 在线程池线程中读取 PLC
                    var sw = System.Diagnostics.Stopwatch.StartNew();
                    var result = _plc.ReadAll();
                    sw.Stop();

                    result.ResponseMs = (int)sw.ElapsedMilliseconds;

                    // 通过 SynchronizationContext 回调到 UI 线程
                    RaiseDataReceived(result);
                }
                catch (Exception ex)
                {
                    RaiseErrorOccurred(ex.Message);
                }
            }, null, 0, intervalMs);

            // 等待取消
            await tcs.Task;
        }

        /// <summary>
        /// 停止轮询
        /// </summary>
        public void Stop()
        {
            _isRunning = false;
            _pollTimer?.Dispose();
            _pollTimer = null;
            _plc.Disconnect();
            RaiseStatusChanged("已停止");
        }

        // 通过 SynchronizationContext 触发事件（自动回到 UI 线程）
        private void RaiseDataReceived(PlcPollResult result)
        {
            if (_syncContext != null)
                _syncContext.Post(_ => DataReceived?.Invoke(result), null);
            else
                DataReceived?.Invoke(result);
        }

        private void RaiseErrorOccurred(string error)
        {
            if (_syncContext != null)
                _syncContext.Post(_ => ErrorOccurred?.Invoke(error), null);
            else
                ErrorOccurred?.Invoke(error);
        }

        private void RaiseStatusChanged(string status)
        {
            if (_syncContext != null)
                _syncContext.Post(_ => StatusChanged?.Invoke(status), null);
            else
                StatusChanged?.Invoke(status);
        }
    }

    #endregion

    #region ===== 数据模型 =====

    public class PlcPollResult
    {
        public List<PlcRegister> Registers { get; set; } = new List<PlcRegister>();
        public int ResponseMs { get; set; }
    }

    public class PlcRegister
    {
        public string Address { get; set; }
        public double Value { get; set; }
        public string Unit { get; set; }
    }

    public class PlcSimulator
    {
        private Random _rnd = new Random();
        public bool IsConnected { get; private set; }
        private static int _tick = 0;

        public void Connect(string ip, int port) { Thread.Sleep(500); IsConnected = true; }
        public void Disconnect() { IsConnected = false; }

        public PlcPollResult ReadAll()
        {
            if (!IsConnected) throw new Exception("PLC 未连接");
            Thread.Sleep(50 + _rnd.Next(100));
            _tick++;

            return new PlcPollResult
            {
                Registers = new List<PlcRegister>
                {
                    new PlcRegister { Address = "D100", Value = 45 + 15 * Math.Sin(_tick * 0.1) + _rnd.NextDouble() * 3, Unit = "°C" },
                    new PlcRegister { Address = "D101", Value = 2.5 + Math.Sin(_tick * 0.08) * 0.5 + _rnd.NextDouble() * 0.2, Unit = "MPa" },
                    new PlcRegister { Address = "D102", Value = 1200 + _rnd.Next(-100, 100), Unit = "RPM" },
                    new PlcRegister { Address = "D103", Value = 22 + _rnd.NextDouble() * 3, Unit = "°C" },
                    new PlcRegister { Address = "D104", Value = 380 + _rnd.Next(-10, 10), Unit = "V" },
                    new PlcRegister { Address = "D105", Value = 5 + _rnd.NextDouble() * 2, Unit = "A" },
                }
            };
        }
    }

    #endregion
}
```

### 注意事项

- **分层设计**：本案例将轮询逻辑封装在 `PlcPollingService` 中，UI 层只负责展示，实现了业务逻辑与 UI 的分离。
- **SynchronizationContext 自动捕获**：在 UI 线程上创建 `PlcPollingService`，自动捕获 UI 线程的 SynchronizationContext，事件回调自动回到 UI 线程。
- **CancellationToken 取消**：使用 `CancellationTokenSource` 实现优雅的取消机制，避免粗暴终止线程。
- **图表数据限制**：只保留最近 60 个数据点，避免内存增长。
- **SuspendLayout/ResumeLayout**：批量更新 DataGridView 时使用，减少界面闪烁。

2. 在 `PlcPollingService` 中添加「批量读取」和「单次读取」两种模式。
3. 实现轮询间隔动态调整功能（通过 NumericUpDown 修改，即时生效）。
4. 添加错误恢复机制：通信失败后自动重连，而不是直接停止。

### 常见错误

| 错误现象 | 原因 | 解决方法 |
|---------|------|---------|
| 关闭窗体报异常 | 后台线程仍在运行 | FormClosing 中取消并停止服务 |
| 图表更新卡顿 | 图表点数过多 | 限制最大显示点数 |
| 跨线程异常 | SynchronizationContext 为 null | 在 UI 线程上创建服务对象 |
| 取消后任务还在跑 | 未检查 CancellationToken | 定时器回调中检查 ct.IsCancellationRequested |

## 总结

本章学习了 WinForms 多线程与界面更新的核心技术：

| 技术 | 特点 | 推荐程度 |
|------|------|---------|
| UI 线程模型 | 消息循环 + 单线程规则 | 必须理解 |
| 跨线程异常 | InvalidOperationException | 必须避免 |
| Control.Invoke | 同步回到 UI 线程 | 传统方案，旧项目常见 |
| Control.BeginInvoke | 异步回到 UI 线程 | 高频更新场景 |
| BackgroundWorker | 封装异步操作 | 旧方案，了解即可 |
| **async/await** | **最推荐的现代方案** | **首选方案** |
| SynchronizationContext | 线程间同步的底层机制 | 高级场景 |
| CancellationToken | 优雅取消异步操作 | 必须掌握 |

**多线程 UI 更新的核心原则：**
1. **永远不要在子线程直接操作 UI 控件**，必须通过 Invoke/BeginInvoke/async/await 切回 UI 线程
2. **优先使用 `async/await`**，它是最简洁、最安全、最不易出错的方式
3. **减少跨线程调用次数**，批量收集数据后一次性更新 UI
4. **async void 只用于事件处理方法**，其他场景使用 async Task
5. **使用 CancellationToken 实现取消**，避免粗暴终止线程
6. **窗体关闭时停止所有后台操作**，防止访问已释放的资源
