## 1. try-catch-finally 语法

### 1.1 基本结构

异常处理是程序应对运行时错误的核心机制。C# 使用 `try-catch-finally` 结构来捕获和处理异常，防止程序因未预期的错误而崩溃。

```
try-catch-finally 执行流程：

  ┌──────────┐
  │  try     │ ── 正常执行 ──→ finally ──→ 后续代码
  │  块      │
  └────┬─────┘
       │ 发生异常
       ▼
  ┌──────────┐
  │  catch   │ ── 捕获异常并处理
  │  块      │
  └────┬─────┘
       │
       ▼
  ┌──────────┐
  │ finally  │ ── 无论如何都会执行（资源释放）
  └────┬─────┘
       │
       ▼
    后续代码
```

### 1.2 代码示例

```csharp
using System;
using System.IO;

public class TryCatchBasicDemo
{
    public void Run()
    {
        // ========================
        // 1. 最基本的 try-catch
        // ========================

        Console.WriteLine("=== 基本异常处理 ===");

        try
        {
            // 尝试执行可能出错的代码
            int a = 10;
            int b = 0;

            // 这行会抛出 DivideByZeroException
            int result = a / b;
            Console.WriteLine($"结果: {result}");  // 不会执行到这里
        }
        catch (Exception ex)
        {
            // 捕获异常后执行
            Console.WriteLine($"捕获到异常: {ex.Message}");
            // 输出: 捕获到异常: 尝试除以零。
        }

        // 程序不会崩溃，继续执行
        Console.WriteLine("程序继续运行\n");

        // ========================
        // 2. try-catch-finally（完整结构）
        // ========================

        Console.WriteLine("=== try-catch-finally ===");

        string configFilePath = "config_not_exist.txt";

        try
        {
            Console.WriteLine("尝试读取配置文件...");

            // 模拟读取不存在的文件
            string content = File.ReadAllText(configFilePath);
            Console.WriteLine($"文件内容: {content}");
        }
        catch (FileNotFoundException ex)
        {
            Console.WriteLine($"文件未找到: {ex.FileName}");
            Console.WriteLine($"异常类型: {ex.GetType().Name}");
        }
        catch (Exception ex)
        {
            Console.WriteLine($"其他异常: {ex.Message}");
        }
        finally
        {
            // finally 块：无论是否发生异常都会执行
            // 通常用于释放资源（关闭文件、断开连接等）
            Console.WriteLine("finally 块已执行 - 资源已清理");
        }

        Console.WriteLine("程序继续运行\n");

        // ========================
        // 3. 只有 try-finally（不捕获异常，但确保清理）
        // ========================

        Console.WriteLine("=== try-finally ===");

        try
        {
            Console.WriteLine("执行关键操作...");
            // 如果这里抛出异常，finally 仍会执行
        }
        finally
        {
            Console.WriteLine("finally 块已执行");
            // 注意：没有 catch，异常会继续向上抛出
        }

        // ========================
        // 4. 上位机场景：打开串口通信
        // ========================

        Console.WriteLine("=== 上位机场景：串口通信 ===");

        SimulateSerialCommunication();
    }

    /// <summary>
    /// 模拟串口通信（演示 finally 的资源释放作用）
    /// </summary>
    private void SimulateSerialCommunication()
    {
        // 模拟串口对象
        bool serialPortOpened = false;

        try
        {
            Console.WriteLine("正在打开 COM3...");
            // 模拟打开串口
            serialPortOpened = true;
            Console.WriteLine("COM3 已打开");

            // 模拟通信（可能出错）
            Random rnd = new Random();
            if (rnd.Next(100) < 30)  // 30%概率出错
            {
                throw new InvalidOperationException("通信数据校验失败");
            }

            Console.WriteLine("数据通信成功");
        }
        catch (InvalidOperationException ex)
        {
            Console.WriteLine($"通信错误: {ex.Message}");
        }
        finally
        {
            // 无论通信是否成功，都要确保关闭串口
            if (serialPortOpened)
            {
                serialPortOpened = false;
                Console.WriteLine("COM3 已关闭（finally块）");
            }
        }
    }
}
```

### 1.3 finally 的执行保证

```csharp
using System;

public class FinallyGuaranteeDemo
{
    public static void Main()
    {
        Console.WriteLine("=== finally 的执行保证 ===\n");

        // 情况1：try 块正常完成
        Console.WriteLine("情况1: 正常完成");
        ExecuteFinally(throwException: false);

        // 情况2：try 块抛出异常且被捕获
        Console.WriteLine("\n情况2: 异常被捕获");
        ExecuteFinally(throwException: true);

        // 情况3：try 块中 return
        Console.WriteLine("\n情况3: try中有return");
        string result = ExecuteWithReturn();
        Console.WriteLine($"返回值: {result}");  // 输出: "操作结果" （finally在return之前执行）

        // 情况4：即使在 finally 中修改了返回值（不推荐）
        Console.WriteLine("\n情况4: finally中修改返回值（不推荐！）");
        int value = ExecuteWithReturnInt();
        Console.WriteLine($"返回值: {value}");  // 输出: 100 （finally修改了值）
    }

    static void ExecuteFinally(bool throwException)
    {
        try
        {
            Console.WriteLine("  try: 开始执行");
            if (throwException)
            {
                throw new Exception("模拟异常");
            }
            Console.WriteLine("  try: 正常完成");
        }
        catch (Exception ex)
        {
            Console.WriteLine($"  catch: 捕获异常 - {ex.Message}");
        }
        finally
        {
            Console.WriteLine("  finally: 无论如何都执行");
        }
    }

    static string ExecuteWithReturn()
    {
        try
        {
            return "操作结果";
        }
        finally
        {
            Console.WriteLine("  finally: 在return之前执行");
            // 注意：这里不能改变返回值（string是引用类型但不可变）
        }
    }

    // 不推荐的写法：在finally中修改返回值
    static int ExecuteWithReturnInt()
    {
        int result = 10;
        try
        {
            result = 100;
            return result;
        }
        finally
        {
            // 警告：finally中对值类型返回值的修改会生效
            // 但这种写法非常不推荐，容易造成混淆
            result = 999;  // 这行代码实际上会覆盖return的值！
        }
    }
}
```

## 2. 多异常捕获

### 2.1 异常类层次结构

在 C# 中，所有异常都继承自 `System.Exception`。理解异常层次结构是正确进行多异常捕获的基础。

```
System.Object
  └── System.Exception                    (所有异常的基类)
        ├── System.SystemException         (系统异常)
        │     ├── System.ArgumentException (参数异常)
        │     │     ├── ArgumentNullException
        │     │     └── ArgumentOutOfRangeException
        │     ├── System.IndexOutOfRangeException  (索引越界)
        │     ├── System.InvalidOperationException (无效操作)
        │     ├── System.IO.IOException     (IO异常基类)
        │     │     ├── FileNotFoundException
        │     │     ├── DirectoryNotFoundException
        │     │     └── EndOfStreamException
        │     ├── System.Net.Sockets.SocketException (网络异常)
        │     └── System.TimeoutException   (超时异常)
        │
        └── System.ApplicationException    (应用程序异常，现已不推荐使用)
```

### 2.2 多异常捕获代码示例

```csharp
using System;
using System.IO;
using System.Collections.Generic;
using System.Net.Sockets;

public class MultiCatchDemo
{
    public void Run()
    {
        // ========================
        // 1. 基本多 catch 语法
        // ========================

        // 注意顺序：从具体到一般
        // 子类异常必须在父类之前捕获

        try
        {
            // 可能抛出不同类型的异常
            Console.WriteLine("执行可能出错的操作...");
        }
        catch (FileNotFoundException ex)
        {
            // 最具体的异常优先捕获
            Console.WriteLine($"文件未找到: {ex.FileName}");
        }
        catch (IOException ex)
        {
            // 稍微宽泛一些的IO异常
            Console.WriteLine($"IO异常: {ex.Message}");
        }
        catch (TimeoutException ex)
        {
            // 超时异常
            Console.WriteLine($"操作超时: {ex.Message}");
        }
        catch (Exception ex)
        {
            // 最宽泛的异常（兜底）
            Console.WriteLine($"未知异常: {ex.Message}");
        }

        // ========================
        // 2. when 子句（C# 6.0）：条件过滤
        // ========================

        try
        {
            SimulatePlcError(PlcErrorType.Timeout);
        }
        catch (Exception ex) when (ex is TimeoutException && IsCriticalPort())
        {
            // only when 条件满足时才捕获
            Console.WriteLine($"关键端口超时: {ex.Message} - 触发重连");
        }
        catch (TimeoutException ex)
        {
            // 非关键端口的超时
            Console.WriteLine($"普通超时: {ex.Message} - 仅记录日志");
        }

        // ========================
        // 3. 上位机场景：PLC数据解析
        // ========================

        ParsePlcData("25.5");      // 正常
        ParsePlcData("abc");       // 格式错误
        ParsePlcData(null);        // 空值
        ParsePlcData("999999");    // 范围超限
    }

    /// <summary>
    /// 判断是否是关键通信端口
    /// </summary>
    private bool IsCriticalPort()
    {
        return true;  // 简化示例
    }

    /// <summary>
    /// 模拟PLC错误
    /// </summary>
    private void SimulatePlcError(PlcErrorType errorType)
    {
        switch (errorType)
        {
            case PlcErrorType.Timeout:
                throw new TimeoutException("PLC响应超时");
            case PlcErrorType.FormatError:
                throw new FormatException("PLC返回数据格式错误");
            case PlcErrorType.ConnectionLost:
                throw new IOException("PLC连接已断开");
        }
    }

    /// <summary>
    /// 解析PLC数据（演示多异常捕获）
    /// </summary>
    private void ParsePlcData(string rawValue)
    {
        Console.WriteLine($"\n解析数据: {rawValue ?? "null"}");

        try
        {
            // 检查 null
            if (rawValue == null)
            {
                throw new ArgumentNullException(nameof(rawValue), "PLC数据不能为null");
            }

            // 解析数值
            double value = double.Parse(rawValue);

            // 范围检查
            if (value < -100 || value > 200)
            {
                throw new ArgumentOutOfRangeException(
                    nameof(rawValue),
                    value,
                    "PLC数据值超出有效范围 [-100, 200]"
                );
            }

            Console.WriteLine($"  解析成功: {value}");
        }
        catch (ArgumentNullException ex)
        {
            Console.WriteLine($"  [空值异常] {ex.ParamName}: {ex.Message}");
        }
        catch (FormatException)
        {
            Console.WriteLine($"  [格式异常] 数据 \"{rawValue}\" 不是有效的数值格式");
        }
        catch (ArgumentOutOfRangeException ex)
        {
            Console.WriteLine($"  [范围异常] 值 {ex.ActualValue} 超出允许范围");
        }
        catch (Exception ex)
        {
            Console.WriteLine($"  [其他异常] {ex.GetType().Name}: {ex.Message}");
        }
    }
}

public enum PlcErrorType
{
    Timeout,
    FormatError,
    ConnectionLost
}
```

### 2.3 上位机通信中的异常捕获策略

```csharp
using System;
using System.Net.Sockets;
using System.IO.Ports;

/// <summary>
/// 上位机通信异常处理策略
/// </summary>
public class CommunicationExceptionHandler
{
    /// <summary>
    /// 处理通信操作中的异常（统一入口）
    /// </summary>
    public bool ExecuteSafely(Action communicationAction, string operationName)
    {
        try
        {
            communicationAction();
            return true;  // 执行成功
        }
        catch (SocketException ex) when (ex.SocketErrorCode == SocketError.TimedOut)
        {
            Console.WriteLine($"[超时] {operationName}: 网络通信超时 (错误码: {ex.SocketErrorCode})");
            return false;
        }
        catch (SocketException ex)
        {
            Console.WriteLine($"[网络错误] {operationName}: {ex.Message}");
            return false;
        }
        catch (TimeoutException ex)
        {
            Console.WriteLine($"[超时] {operationName}: 操作超时");
            return false;
        }
        catch (InvalidOperationException ex)
        {
            Console.WriteLine($"[状态错误] {operationName}: 通信端口未打开或已关闭");
            return false;
        }
        catch (Exception ex)
        {
            Console.WriteLine($"[未知错误] {operationName}: {ex.GetType().Name} - {ex.Message}");
            return false;
        }
    }

    /// <summary>
    /// 带返回值的异常安全执行
    /// </summary>
    public T ExecuteSafely<T>(Func<T> communicationFunc, string operationName, T defaultValue = default)
    {
        try
        {
            return communicationFunc();
        }
        catch (SocketException ex)
        {
            Console.WriteLine($"[网络错误] {operationName}: {ex.Message}");
            return defaultValue;
        }
        catch (TimeoutException ex)
        {
            Console.WriteLine($"[超时] {operationName}: 操作超时");
            return defaultValue;
        }
        catch (Exception ex)
        {
            Console.WriteLine($"[错误] {operationName}: {ex.Message}");
            return defaultValue;
        }
    }
}

public class CommunicationStrategyDemo
{
    public static void Main()
    {
        var handler = new CommunicationExceptionHandler();

        Console.WriteLine("=== 通信异常处理策略演示 ===\n");

        // 场景1：安全执行通信操作
        bool success = handler.ExecuteSafely(() =>
        {
            Console.WriteLine("  正在连接PLC...");
            // 模拟连接（可能抛出异常）
            // throw new TimeoutException("连接超时");
            Console.WriteLine("  连接成功");
        }, "连接PLC");

        Console.WriteLine($"操作结果: {(success ? "成功" : "失败")}");

        // 场景2：带返回值的安全执行
        double value = handler.ExecuteSafely(() =>
        {
            Console.WriteLine("  读取D100寄存器...");
            return 25.5;
        }, "读取D100", defaultValue: 0.0);

        Console.WriteLine($"读取结果: {value}");
    }
}
```

## 3. 自定义异常类

### 3.1 为什么要自定义异常

系统内置的异常类无法精确描述业务特定的错误场景。在上位机开发中，PLC通信超时、数据校验失败、设备离线等都是特定业务异常，需要自定义异常类来精确表达。

### 3.2 自定义异常类的编写规范

```csharp
using System;

/// <summary>
/// PLC通信异常 —— 上位机最核心的自定义异常
/// </summary>
public class PlcCommunicationException : Exception
{
    /// <summary>设备地址/IP</summary>
    public string DeviceAddress { get; }

    /// <summary>通信端口号</summary>
    public int Port { get; }

    /// <summary>异常发生时的操作类型</summary>
    public string OperationType { get; }

    /// <summary>
    /// 完整构造函数
    /// </summary>
    public PlcCommunicationException(
        string message,
        string deviceAddress,
        int port,
        string operationType,
        Exception innerException = null
    ) : base(message, innerException)
    {
        DeviceAddress = deviceAddress;
        Port = port;
        OperationType = operationType;
    }

    /// <summary>
    /// 仅消息（简化构造）
    /// </summary>
    public PlcCommunicationException(string message)
        : base(message)
    {
        DeviceAddress = "Unknown";
        Port = 0;
        OperationType = "Unknown";
    }

    /// <summary>
    /// 序列化构造函数（如果需要序列化异常）
    /// </summary>
    protected PlcCommunicationException(
        System.Runtime.Serialization.SerializationInfo info,
        System.Runtime.Serialization.StreamingContext context
    ) : base(info, context)
    {
        DeviceAddress = info.GetString(nameof(DeviceAddress));
        Port = info.GetInt32(nameof(Port));
        OperationType = info.GetString(nameof(OperationType));
    }
}

/// <summary>
/// PLC数据解析异常
/// </summary>
public class PlcDataParseException : Exception
{
    /// <summary>原始数据字符串</summary>
    public string RawData { get; }

    /// <summary>期望的数据格式</summary>
    public string ExpectedFormat { get; }

    /// <summary>寄存器地址</summary>
    public string RegisterAddress { get; }

    public PlcDataParseException(
        string message,
        string rawData,
        string registerAddress,
        string expectedFormat = null,
        Exception innerException = null
    ) : base(message, innerException)
    {
        RawData = rawData;
        RegisterAddress = registerAddress;
        ExpectedFormat = expectedFormat;
    }
}

/// <summary>
/// PLC连接断开异常
/// </summary>
public class PlcConnectionLostException : PlcCommunicationException
{
    /// <summary>断开时间</summary>
    public DateTime DisconnectedTime { get; }

    /// <summary>是否正在自动重连</summary>
    public bool IsAutoReconnecting { get; }

    public PlcConnectionLostException(
        string deviceAddress,
        int port,
        bool isAutoReconnecting,
        Exception innerException = null
    ) : base(
        $"PLC连接已断开 ({deviceAddress}:{port})",
        deviceAddress,
        port,
        "通信",
        innerException)
    {
        DisconnectedTime = DateTime.Now;
        IsAutoReconnecting = isAutoReconnecting;
    }
}

/// <summary>
/// 设备报警异常
/// </summary>
public class DeviceAlarmException : Exception
{
    /// <summary>报警设备名称</summary>
    public string DeviceName { get; }

    /// <summary>报警级别</summary>
    public AlarmSeverity Severity { get; }

    /// <summary>报警代码</summary>
    public int AlarmCode { get; }

    public DeviceAlarmException(
        string deviceName,
        int alarmCode,
        string message,
        AlarmSeverity severity = AlarmSeverity.Warning,
        Exception innerException = null
    ) : base(message, innerException)
    {
        DeviceName = deviceName;
        AlarmCode = alarmCode;
        Severity = severity;
    }
}

/// <summary>
/// 报警严重程度
/// </summary>
public enum AlarmSeverity
{
    /// <summary>提示</summary>
    Info,
    /// <summary>警告</summary>
    Warning,
    /// <summary>一般报警</summary>
    Alarm,
    /// <summary>紧急报警</summary>
    Critical
}
```

### 3.3 自定义异常的使用

```csharp
using System;

public class CustomExceptionUsageDemo
{
    public static void Main()
    {
        Console.WriteLine("=== 自定义异常使用演示 ===\n");

        var demo = new CustomExceptionUsageDemo();

        // 场景1：PLC通信超时
        demo.ReadPlcData("192.168.1.10", 502, "D100");

        // 场景2：数据解析失败
        Console.WriteLine();
        demo.ParsePlcResponse("ERR:INVALID", "D200");

        // 场景3：设备报警
        Console.WriteLine();
        demo.CheckDeviceAlarm("温度传感器A", 125.0);
    }

    /// <summary>
    /// 模拟读取PLC数据
    /// </summary>
    public void ReadPlcData(string ip, int port, string address)
    {
        try
        {
            Console.WriteLine($"正在读取 {ip}:{port} 的 {address}...");

            // 模拟通信超时
            throw new TimeoutException("PLC响应超时（5000ms无响应）");
        }
        catch (TimeoutException ex)
        {
            // 将系统异常包装为自定义异常，添加业务上下文
            throw new PlcCommunicationException(
                message: $"读取PLC数据失败: {address}",
                deviceAddress: ip,
                port: port,
                operationType: "读取",
                innerException: ex  // 保留原始异常作为内部异常
            );
        }
    }

    /// <summary>
    /// 模拟解析PLC响应数据
    /// </summary>
    public void ParsePlcResponse(string rawData, string registerAddress)
    {
        try
        {
            Console.WriteLine($"解析PLC响应: {rawData} (地址: {registerAddress})");

            if (rawData.StartsWith("ERR:"))
            {
                throw new PlcDataParseException(
                    message: $"PLC返回错误响应: {rawData}",
                    rawData: rawData,
                    registerAddress: registerAddress,
                    expectedFormat: "数值格式（如: 25.5）"
                );
            }

            double value = double.Parse(rawData);
            Console.WriteLine($"  解析成功: {value}");
        }
        catch (PlcDataParseException ex)
        {
            Console.WriteLine($"  [解析异常] {ex.Message}");
            Console.WriteLine($"  寄存器地址: {ex.RegisterAddress}");
            Console.WriteLine($"  原始数据: {ex.RawData}");
            Console.WriteLine($"  期望格式: {ex.ExpectedFormat}");
        }
    }

    /// <summary>
    /// 模拟检查设备报警
    /// </summary>
    public void CheckDeviceAlarm(string deviceName, double temperature)
    {
        try
        {
            Console.WriteLine($"检查设备: {deviceName} (温度: {temperature})");

            if (temperature > 120)
            {
                throw new DeviceAlarmException(
                    deviceName: deviceName,

                    message: $"温度过高: {temperature}°C (阈值: 120°C)",
                    severity: AlarmSeverity.Critical

                    severity: AlarmSeverity.Warning
                );
            }

        }
        catch (DeviceAlarmException ex)
        {

                AlarmSeverity.Warning => "[警告]",
                AlarmSeverity.Info => "[提示]",
                _ => "[未知]"
            };

            Console.WriteLine($"  {severityText} 报警代码: {ex.AlarmCode}");
            Console.WriteLine($"  {severityText} 设备: {ex.DeviceName}");
            Console.WriteLine($"  {severityText} 描述: {ex.Message}");
        }
    }
}
```

## 4. throw 与 throw ex 的区别

### 4.1 核心区别：异常堆栈信息

这是 C# 异常处理中**最容易犯的错误**之一。`throw` 和 `throw ex` 的区别在于是否保留原始的异常堆栈信息。

```
throw:
  保留完整的异常堆栈，从最初抛出异常的位置开始追踪
  → 可以看到异常真正的来源

throw ex:
  重置异常堆栈，从当前 catch 块重新开始
  → 丢失了原始抛出位置的堆栈信息，只看到 catch 的位置
```

### 4.2 对比演示

```csharp
using System;

public class ThrowVsThrowExDemo
{
    public static void Main()
    {
        Console.WriteLine("=== throw vs throw ex 对比 ===\n");

        // 方式1：使用 throw（正确）
        Console.WriteLine("===== 方式1: throw（保留堆栈）=====");
        try
        {
            Method_Level1_Throw();
        }
        catch (Exception ex)
        {
            Console.WriteLine($"捕获异常: {ex.Message}");
            Console.WriteLine($"堆栈追踪:\n{ex.StackTrace}");
        }

        Console.WriteLine("\n===== 方式2: throw ex（丢失堆栈）=====");
        try
        {
            Method_Level1_ThrowEx();
        }
        catch (Exception ex)
        {
            Console.WriteLine($"捕获异常: {ex.Message}");
            Console.WriteLine($"堆栈追踪:\n{ex.StackTrace}");
        }
    }

    // ========================
    // throw 方式（正确）
    // ========================

    static void Method_Level1_Throw()
    {
        try
        {
            Method_Level2_Throw();  // 调用更深层的方法
        }
        catch (Exception ex)
        {
            // 记录日志
            Console.WriteLine($"[日志] Level1 捕获到异常: {ex.Message}");

            // 使用 throw（不加 ex） → 保留完整堆栈
            throw;  // 堆栈从 Method_Level3 开始追踪
        }
    }

    static void Method_Level2_Throw()
    {
        Method_Level3_Throw();
    }

    static void Method_Level3_Throw()
    {
        throw new InvalidOperationException("PLC通信初始化失败");
        // ↑ 异常从这里抛出
    }

    // ========================
    // throw ex 方式（错误）
    // ========================

    static void Method_Level1_ThrowEx()
    {
        try
        {
            Method_Level2_ThrowEx();
        }
        catch (Exception ex)
        {
            Console.WriteLine($"[日志] Level1 捕获到异常: {ex.Message}");

            // 使用 throw ex → 重置堆栈！
            throw ex;  // 堆栈从 Method_Level1_ThrowEx 开始追踪
            // ↑ 原始的 Method_Level3_ThrowEx 的位置信息丢失了！
        }
    }

    static void Method_Level2_ThrowEx()
    {
        Method_Level3_ThrowEx();
    }

    static void Method_Level3_ThrowEx()
    {
        throw new InvalidOperationException("PLC通信初始化失败");
    }
}
```

```

堆栈追踪:
   at ThrowVsThrowExDemo.Method_Level3_Throw()    ← 异常真正的来源
   at ThrowVsThrowExDemo.Method_Level2_Throw()
   at ThrowVsThrowExDemo.Method_Level1_Throw()

===== 方式2: throw ex（丢失堆栈）=====
堆栈追踪:
   at ThrowVsThrowExDemo.Method_Level1_ThrowEx()  ← 只能看到catch的位置！
```

### 4.4 最佳实践总结

```csharp
// 规则1：如果你想在 catch 中重新抛出同一个异常 → 使用 throw（不加 ex）
try { ... }
catch (Exception ex)
{
    Log(ex);
    throw;  // 正确：保留完整堆栈
}

// 规则2：如果你想抛出一个新的异常 → 使用 throw new ... (ex)
try { ... }
catch (SocketException ex)
{
    throw new PlcCommunicationException("通信失败", "192.168.1.10", 502, "读取", ex);
    // 正确：新异常 + 原异常作为 InnerException
}

// 规则3：永远不要使用 throw ex
try { ... }
catch (Exception ex)
{
    throw ex;  // 错误！堆栈信息被截断
}

// 规则4：如果需要异常过滤，使用 when 子句代替 catch + throw
try { ... }
catch (Exception ex) when (ex is TimeoutException)  // 正确的过滤方式
{
    // 处理超时
}
```

## 5. Debug 与 Release 模式区别

### 5.1 两种模式的核心区别

| 特性 | Debug | Release |
|------|-------|---------|
| **编译优化** | 无优化（代码按原样编译） | 有优化（内联、死代码消除等） |
| **调试信息** | 包含完整的PDB调试符号 | 不包含或精简PDB |
| **断言检查** | `Debug.Assert` 生效 | `Debug.Assert` 被移除 |
| **条件编译** | `DEBUG` 常量已定义 | `RELEASE` 常量已定义 |
| **性能** | 较慢（无优化） | 较快（有优化） |
| **可调试性** | 变量可查看，断点可设 | 优化后变量可能被优化掉 |
| **发布用途** | 开发调试阶段 | 最终发布部署 |

### 5.2 条件编译指令


### 6.2 条件断点

条件断点让断点只在满足特定条件时才会触发，这在调试上位机中循环读取PLC数据的场景时特别有用。

```
设置条件断点的步骤：
1. 在代码行左侧点击设置断点（红点）
2. 右键点击红点 → "条件"（或 "Actions"）
3. 输入条件表达式

示例：调试PLC轮询，只在读取到D100时中断
  条件: address == "D100"

示例：调试温度报警，只在温度超过100度时中断
  条件: temperature > 100

示例：调试通信重连，只在第3次重试时中断
  条件: retryCount == 3
```

```csharp
using System;
using System.Threading;

/// <summary>
/// 条件断点调试示例代码
/// 在Visual Studio中打开此文件，设置条件断点来练习
/// </summary>
public class ConditionalBreakpointDemo
{
    private Dictionary<string, double> _registers = new Dictionary<string, double>();

    public void PollAllRegisters()
    {
        string[] addresses = { "D100", "D102", "D104", "D106", "D108", "D110" };

        foreach (var address in addresses)
        {
            double value = ReadRegister(address);

            // ★ 在这里设置条件断点，条件：address == "D104"
            // 这样只有读取D104时才会停下来
            ProcessValue(address, value);
        }
    }

    private double ReadRegister(string address)
    {
        // 模拟读取
        Random rnd = new Random();
        double value = 20 + rnd.NextDouble() * 10;
        return value;
    }

    private void ProcessValue(string address, double value)
    {
        // ★ 在这里设置条件断点，条件：value > 27.0
        // 这样只有值异常时才会停下来调试

        if (value > 28.0)
        {
            // ★ 在这里设置条件断点，条件：address == "D108"
            // 调试特定地址的高温报警
            Console.WriteLine($"[报警] {address} 温度过高: {value:F2}");
        }

        _registers[address] = value;
    }

    /// <summary>
    /// 带重试的通信方法
    /// ★ 设置条件断点来调试重试逻辑
    /// </summary>
    public bool ConnectWithRetry(string ip, int port, int maxRetries)
    {
        for (int retry = 0; retry < maxRetries; retry++)
        {
            // ★ 在这里设置条件断点：retry == 2
            // 调试第3次重试时的状态
            Console.WriteLine($"第{retry + 1}次连接尝试...");

            try
            {
                bool connected = TryConnect(ip, port);
                if (connected)
                {
                    // ★ 在这里设置条件断点：retry > 0
                    // 只在重试成功时停下来
                    Console.WriteLine($"连接成功（第{retry + 1}次尝试）");
                    return true;
                }
            }
            catch (TimeoutException ex)
            {
                // ★ 在这里设置条件断点：retry == maxRetries - 1
                // 只在最后一次失败时停下来
                Console.WriteLine($"连接超时: {ex.Message}");
            }

            Thread.Sleep(1000);
        }

        return false;
    }

    private bool TryConnect(string ip, int port)
    {
        Random rnd = new Random();
        if (rnd.Next(100) < 40)
            return true;  // 40%成功率
        throw new TimeoutException("连接超时");
    }
}
```

```csharp
        Log(ConsoleLogger.LogLevel.Error, source, $"堆栈: {ex.StackTrace}");

        if (ex.InnerException != null)
```

### 8.3 案例三：数据解析错误处理

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.Linq;

/// <summary>
/// PLC响应数据解析器 —— 上位机中数据解析的完整异常处理
/// </summary>
public class PlcResponseParser
{
    /// <summary>
    /// 解析Modbus RTU响应（模拟）
    /// 格式: "地址:值,地址:值,地址:值"
    /// 示例: "D100:25.5,D102:30.0,D104:15.8"
    /// </summary>
    public Dictionary<string, double> ParseModbusResponse(string response)
    {
        var result = new Dictionary<string, double>();

        // 1. 空值检查
        if (string.IsNullOrWhiteSpace(response))
        {
            throw new PlcDataParseException(
                "PLC响应为空",
                response ?? "null",
                "ALL",
                "有效的Modbus响应字符串"
            );
        }

        // 2. 分割数据项
        string[] items = response.Split(',');

        foreach (var item in items)
        {
            try
            {
                // 3. 分割地址和值
                string[] parts = item.Trim().Split(':');

                if (parts.Length != 2)
                {
                    throw new PlcDataParseException(
                        $"数据格式错误: 缺少冒号分隔符 (项: '{item.Trim()}')",
                        item,
                        "UNKNOWN",
                        "地址:值 格式"
                    );
                }

                string address = parts[0].Trim();
                string valueStr = parts[1].Trim();

                // 4. 验证地址格式
                if (string.IsNullOrEmpty(address) ||
                    (!address.StartsWith("D") && !address.StartsWith("M")))
                {
                    throw new PlcDataParseException(
                        $"地址格式错误: '{address}'",
                        address,
                        address,
                        "D或M开头的地址（如D100, M200）"
                    );
                }

                // 5. 解析数值
                // 使用 InvariantCulture 避免小数点/逗号的地区差异
                if (!double.TryParse(valueStr, NumberStyles.Float,
                    CultureInfo.InvariantCulture, out double value))
                {
                    throw new PlcDataParseException(
                        $"数值解析失败: '{valueStr}' 不是有效数字",
                        valueStr,
                        address,
                        "有效的浮点数（如 25.5, -10.0）"
                    );
                }

                // 6. 范围检查（根据地址类型）
                if (address.StartsWith("D"))
                {
                    if (value < -32768 || value > 32767)
                    {
                        throw new PlcDataParseException(
                            $"D寄存器值超出16位范围: {value} (有效范围: -32768 ~ 32767)",
                            valueStr,
                            address,
                            "-32768 ~ 32767"
                        );
                    }
                }

                result[address] = value;
            }
            catch (PlcDataParseException)
            {
                // 自定义异常：记录后继续解析其他数据项
                Console.WriteLine($"  [解析错误] {item} - 跳过该项，继续解析");
                continue;
            }
            catch (Exception ex)
            {
                // 未知异常：记录后继续
                Console.WriteLine($"  [未知错误] {item}: {ex.Message} - 跳过该项");
                continue;
            }
        }

        return result;
    }

    /// <summary>
    /// 安全的批量解析（不抛出异常，返回成功和失败的结果）
    /// </summary>
    public (Dictionary<string, double> Success, List<string> Errors) ParseSafely(
        string response)
    {
        var success = new Dictionary<string, double>();
        var errors = new List<string>();

        if (string.IsNullOrWhiteSpace(response))
        {
            errors.Add("响应为空");
            return (success, errors);
        }

        string[] items = response.Split(',');

        foreach (var item in items)
        {
            string[] parts = item.Trim().Split(':');
            if (parts.Length != 2)
            {
                errors.Add($"格式错误: {item}");
                continue;
            }

            string address = parts[0].Trim();
            string valueStr = parts[1].Trim();

            if (double.TryParse(valueStr, NumberStyles.Float,
                CultureInfo.InvariantCulture, out double value))
            {
                success[address] = value;
            }
            else
            {
                errors.Add($"数值错误: {item}");
            }
        }

        return (success, errors);
    }
}
```

```csharp
    catch (PlcCommunicationException ex)
    {
        HandleError(ex);
    }
}
```

### 9.2 不要吞掉异常

```csharp
// 错误：捕获异常后不做任何处理（吞掉异常）
try
{
    PlcWrite();
}
catch (Exception)
{
    // 什么也不做！错误被隐藏了，出问题根本不知道
}

// 正确：至少记录日志
try
{
    PlcWrite();
}
catch (Exception ex)
{
    LogError(ex);  // 记录日志
    // 或者重新抛出：throw;
    // 或者触发异常事件
}
```

### 9.3 catch 的顺序很重要

```csharp
// 错误：子类异常在父类之后（编译错误）
try
{
    File.ReadAllText("config.txt");
}
catch (Exception ex)          // ← 先捕获父类
{
    // 所有异常都会被这里捕获
}
catch (FileNotFoundException ex)  // ← 永远不会执行（死代码）
{
    // 这个catch永远到达不了
}

// 正确：从具体到一般
try
{
    File.ReadAllText("config.txt");
}
catch (FileNotFoundException ex)    // ← 先捕获具体异常
{
    // 处理文件未找到
}
catch (IOException ex)               // ← 再捕获IO异常
{
    // 处理其他IO异常
}
catch (Exception ex)                  // ← 最后是兜底
{
    // 处理其他所有异常
}
```

### 9.4 finally 中的代码也可能抛异常

```csharp
// 注意：finally 块中的代码也可能抛出异常
// 如果 finally 中抛出异常，会覆盖 try/catch 中的异常
try
{
    throw new InvalidOperationException("原始异常");
}
finally
{
    throw new ArgumentException("finally中的异常");
    // ↑ 如果执行到这里，"原始异常"的信息就丢失了！
}

// 正确做法：finally 中也要用 try-catch
try
{
    throw new InvalidOperationException("原始异常");
}
finally
{
    try
    {
        // 可能有风险的清理代码
        CloseConnection();
    }
    catch (Exception ex)
    {
        // 记录但不抛出
        Console.WriteLine($"清理异常: {ex.Message}");
    }
}
```

## 11. 常见错误

### 错误1：throw ex 导致堆栈丢失

```csharp
try { PlcOperation(); }
catch (Exception ex)
{
    Log(ex);
    throw ex;  // 错误！堆栈信息被截断
}

// 正确：
try { PlcOperation(); }
catch (Exception ex)
{
    Log(ex);
    throw;  // 正确！保留完整堆栈
}
```

### 错误2：catch 块中不记录就重新抛出

```csharp
try { PlcOperation(); }
catch (Exception)
{
    throw;  // 错误：没有记录日志，错误信息丢失
}

// 正确：
try { PlcOperation(); }
catch (Exception ex)
{
    Logger.Error(ex);  // 先记录
    throw;             // 再重新抛出
}
```

### 错误3：在 finally 中 return

```csharp
public double Calculate()
{
    try
    {
        return 100.0;
    }
    finally
    {
        return 0.0;  // 编译错误！C#不允许在finally中return
        // 这会覆盖try块的返回值，逻辑混乱
    }
}
```

### 错误4：异常类不调用基类构造函数

```csharp
// 错误：没有调用基类的构造函数
public class MyException : Exception
{
    public string ErrorCode { get; }

    public MyException(string message, string errorCode)
    {
        ErrorCode = errorCode;
        // 忘记调用 : base(message) 了！
        // Message 属性会是空的
    }
}

// 正确：
public class MyException : Exception
{
    public string ErrorCode { get; }

    public MyException(string message, string errorCode)
        : base(message)  // 调用基类构造函数，设置Message属性
    {
        ErrorCode = errorCode;
    }
}
```

### 错误5：Release 模式下依赖 Debug.Assert

```csharp
public void ProcessData(double value)
{
    Debug.Assert(value >= 0, "值不能为负数");

    // 错误：在Release模式下，Debug.Assert 被移除
    // 如果 value < 0，Release 模式下不会有任何检查！

    // 正确：关键的业务检查不应该依赖 Debug.Assert
    if (value < 0)
    {
        throw new ArgumentException("值不能为负数", nameof(value));
    }
}
```
