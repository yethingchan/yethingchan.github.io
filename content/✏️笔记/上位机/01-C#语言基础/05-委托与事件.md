## 1. 委托基础

### 1.1 什么是委托

**委托（Delegate）** 是 C# 中的一种类型，它表示对具有特定参数列表和返回类型的方法的引用。通俗来说，委托就是一个"方法容器"，你可以把一个方法"装进"委托变量中，然后通过这个变量来调用该方法。

委托的本质是一个**类**，它继承自 `System.MulticastDelegate`，而 `MulticastDelegate` 又继承自 `System.Delegate`。

```
委托的本质：
┌──────────────────────────────────┐
│           Delegate               │
│  (抽象基类，定义委托的基本行为)    │
└────────────┬─────────────────────┘
             │ 继承
┌────────────▼─────────────────────┐
│       MulticastDelegate          │
│  (支持多播，可绑定多个方法)        │
└────────────┬─────────────────────┘
             │ 继承
┌────────────▼─────────────────────┐
│    你定义的委托类型（如MyDelegate） │
└──────────────────────────────────┘
```

### 1.2 使用 delegate 关键字定义委托

```csharp
using System;

/// <summary>
/// 自定义委托：无参数无返回值
/// 上位机场景：作为 PLC 数据刷新回调
/// </summary>
public delegate void DataRefreshCallback();

/// <summary>
/// 自定义委托：接收一个字符串参数，无返回值
/// 上位机场景：作为日志输出回调
/// </summary>
public delegate void LogOutputHandler(string message);

/// <summary>
/// 自定义委托：接收 PLC 地址和数据值，返回布尔值表示是否处理成功
/// 上位机场景：数据写入校验
/// </summary>
public delegate bool PlcWriteValidator(string address, double value);

public class DelegateBasicDemo
{
    public void Run()
    {
        // ========================
        // 1. 委托的基本使用
        // ========================

        // 创建委托实例，绑定一个方法
        LogOutputHandler logger = LogToConsole;

        // 通过委托调用方法
        logger("系统启动完成");  // 等同于直接调用 LogToConsole("系统启动完成")

        // ========================
        // 2. 委托的赋值与重新绑定
        // ========================

        // 将委托变量指向另一个方法
        logger = LogToFile;
        logger("这条日志会写入文件");

        // ========================
        // 3. 多播委托（+= / -=）
        // ========================

        // 使用 += 添加多个方法（多播委托）
        LogOutputHandler multiLogger = LogToConsole;
        multiLogger += LogToFile;  // 同时绑定两个方法

        // 调用时，两个方法都会被执行
        // 执行顺序：先绑定的先执行
        multiLogger("PLC连接成功");  // 同时输出到控制台和写入文件

        // 使用 -= 移除某个方法
        multiLogger -= LogToConsole;
        multiLogger("断开PLC连接");  // 只写入文件

        // ========================
        // 4. 委托作为方法参数
        // ========================

        ProcessData("D100", 25.5, LogToConsole);
        ProcessData("D102", 30.0, LogToFile);
    }

    /// <summary>
    /// 委托绑定的方法：输出到控制台
    /// </summary>
    private void LogToConsole(string message)
    {
        Console.WriteLine($"[控制台] {DateTime.Now:HH:mm:ss} - {message}");
    }

    /// <summary>
    /// 委托绑定的方法：模拟写入文件
    /// </summary>
    private void LogToFile(string message)
    {
        Console.WriteLine($"[文件]   {DateTime.Now:HH:mm:ss} - {message}");
    }

    /// <summary>
    /// 委托作为参数传入：处理PLC数据并记录日志
    /// </summary>
    /// <param name="address">PLC地址</param>
    /// <param name="value">数据值</param>
    /// <param name="logger">日志输出委托</param>
    private void ProcessData(string address, double value, LogOutputHandler logger)
    {
        // 使用传入的委托来记录日志
        logger($"开始处理数据 - 地址: {address}, 值: {value}");

        // 模拟数据处理
        value = Math.Round(value, 2);

        logger($"数据处理完成 - 地址: {address}, 结果: {value}");
    }
}
```

### 1.3 内置委托 Func 和 Action

C# 提供了两个泛型委托族，可以覆盖绝大多数委托使用场景，**无需自定义委托类型**：

| 委托类型 | 说明 | 用法 |
|---------|------|------|
| `Action` | 无返回值 | `Action<string> a = msg => Console.WriteLine(msg);` |
| `Action<T1,T2>` | 两个参数，无返回值 | `Action<int, int> a = (x, y) => { ... };` |
| `Func<TResult>` | 有返回值，无输入参数 | `Func<int> f = () => 42;` |
| `Func<T, TResult>` | 一个输入参数，有返回值 | `Func<double, string> f = v => v.ToString();` |
| `Predicate<T>` | 一个参数，返回 bool | `Predicate<int> p = n => n > 0;` |

> `Action` 有最多 16 个泛型参数的重载版本（`Action<T1,...,T16>`），`Func` 同理（多一个返回类型参数 `TResult`）。

```csharp
using System;

public class BuiltInDelegateDemo
{
    public void Run()
    {
        // ========================
        // Action 委托（无返回值）
        // ========================

        // Action<string>：接收一个字符串参数
        Action<string> showMessage = msg =>
        {
            Console.WriteLine($"提示: {msg}");
        };
        showMessage("PLC设备已连接");

        // Action：无参数
        Action heartbeat = () =>
        {
            Console.WriteLine($"心跳检测 - {DateTime.Now:HH:mm:ss}");
        };
        heartbeat();

        // Action<int, string>：两个参数
        Action<int, string> logWithLevel = (level, msg) =>
        {
            string levelText = level switch
            {
                0 => "[INFO]",
                1 => "[WARN]",
                2 => "[ERROR]",
                _ => "[DEBUG]"
            };
            Console.WriteLine($"{levelText} {msg}");
        };
        logWithLevel(0, "通信初始化完成");
        logWithLevel(2, "PLC通信超时");

        // ========================
        // Func 委托（有返回值）
        // ========================

        // Func<string, double>：接收字符串，返回 double
        // 场景：将PLC读取到的原始字符串转为数值
        Func<string, double> parsePlcValue = raw =>
        {
            if (double.TryParse(raw, out double result))
                return result;
            return 0.0;  // 解析失败返回默认值
        };

        double temperature = parsePlcValue("25.5");
        Console.WriteLine($"温度值: {temperature}");  // 输出: 25.5

        // Func<double, double, double>：两个输入参数，一个返回值
        // 场景：传感器数据换算（原始值 -> 工程值）
        Func<double, double, double> scaleValue = (rawValue, factor) =>
        {
            return rawValue * factor;
        };

        double scaled = scaleValue(4095, 10.0 / 4095.0);  // 12位ADC换算
        Console.WriteLine($"换算后的工程值: {scaled:F3}");

        // ========================
        // Predicate 委托（返回bool）
        // ========================

        // 场景：判断PLC数据是否在报警范围
        Predicate<double> isAlarm = value => value > 100.0 || value < 0.0;

        Console.WriteLine($"75.0 是否报警: {isAlarm(75.0)}");    // False
        Console.WriteLine($"120.0 是否报警: {isAlarm(120.0)}");  // True
    }
}
```

## 2. 匿名方法与Lambda表达式

### 2.1 匿名方法

匿名方法允许你直接内联定义一个没有名字的方法，用 `delegate` 关键字引入。它是 Lambda 表达式的前身，在较老的代码中仍然常见。

```csharp
using System;

public class AnonymousMethodDemo
{
    public void Run()
    {
        // 传统方式：先定义方法，再赋值给委托
        Action<string> method1 = PrintMessage;
        method1("传统方式调用");

        // 匿名方法方式：直接内联定义（C# 2.0）
        Action<string> method2 = delegate (string msg)
        {
            Console.WriteLine($"[匿名方法] {msg}");
        };
        method2("使用匿名方法调用");

        // 匿名方法的好处：可以直接访问外部变量（闭包）
        int counter = 0;
        Action increment = delegate
        {
            counter++;  // 访问外部变量
            Console.WriteLine($"计数器: {counter}");
        };

        increment();  // 计数器: 1
        increment();  // 计数器: 2
        increment();  // 计数器: 3

        Console.WriteLine($"最终计数: {counter}");  // 3
    }

    private void PrintMessage(string msg)
    {
        Console.WriteLine($"[普通方法] {msg}");
    }
}
```

### 2.2 Lambda 表达式

Lambda 表达式是匿名方法的简化写法（C# 3.0 引入），使用 `=>`（读作"goes to"）运算符。

**语法格式：**

```
(参数列表) => { 方法体 }          // 语句Lambda（有花括号）
(参数列表) => 表达式              // 表达式Lambda（无花括号）
参数 => 表达式                    // 单参数时可省略括号
() => 表达式                      // 无参数时必须有括号
```

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public class LambdaDemo
{
    public void Run()
    {
        // ========================
        // 1. 各种Lambda语法形式
        // ========================

        // 语句Lambda（花括号内可写多条语句）
        Action<string> log = (msg) =>
        {
            string time = DateTime.Now.ToString("HH:mm:ss");
            Console.WriteLine($"[{time}] {msg}");
        };
        log("PLC通信开始");

        // 表达式Lambda（单行表达式，无需return关键字）
        Func<int, int, int> add = (a, b) => a + b;
        Console.WriteLine($"3 + 5 = {add(3, 5)}");  // 8

        // 单参数省略括号
        Func<int, bool> isPositive = n => n > 0;
        Console.WriteLine($"-5 是正数: {isPositive(-5)}");  // False

        // 无参数Lambda
        Func<DateTime> getNow = () => DateTime.Now;
        Console.WriteLine($"当前时间: {getNow():HH:mm:ss}");

        // ========================
        // 2. Lambda 在上位机场景中的典型用法
        // ========================

        // 场景：模拟一批PLC传感器数据
        List<SensorData> sensors = new List<SensorData>
        {
            new SensorData { Name = "温度传感器1", Value = 25.5, IsOnline = true },
            new SensorData { Name = "压力传感器1", Value = 101.3, IsOnline = true },
            new SensorData { Name = "温度传感器2", Value = 85.0, IsOnline = true },
            new SensorData { Name = "流量传感器1", Value = 0.0, IsOnline = false },
            new SensorData { Name = "压力传感器2", Value = 200.0, IsOnline = true },
        };

        // 使用 Lambda 过滤在线传感器
        var onlineSensors = sensors.Where(s => s.IsOnline).ToList();
        Console.WriteLine($"在线传感器数量: {onlineSensors.Count}");  // 4

        // 使用 Lambda 筛选温度超过80度的传感器（报警）
        var alarmSensors = sensors.Where(s =>
            s.Name.Contains("温度") && s.Value > 80.0
        ).ToList();
        Console.WriteLine("报警传感器:");
        foreach (var s in alarmSensors)
        {
            Console.WriteLine($"  {s.Name}: {s.Value}");
        }

        // 使用 Lambda 计算所有在线传感器的平均值
        double avgValue = sensors
            .Where(s => s.IsOnline && s.Value > 0)
            .Average(s => s.Value);
        Console.WriteLine($"在线传感器平均值: {avgValue:F2}");

        // 使用 Lambda 排序：按值从大到小
        var sorted = sensors
            .Where(s => s.IsOnline)
            .OrderByDescending(s => s.Value)
            .ToList();

        Console.WriteLine("按值排序:");
        sorted.ForEach(s => Console.WriteLine($"  {s.Name}: {s.Value:F1}"));

        // ========================
        // 3. 闭包（Closure）注意事项
        // ========================

        // Lambda 可以捕获外部变量，这就是"闭包"
        string deviceName = "PLC-001";
        Action<string> deviceLog = (msg) =>
        {
            // 捕获了外部的 deviceName 变量
            Console.WriteLine($"[{deviceName}] {msg}");
        };

        deviceLog("设备已连接");

        // 修改外部变量后，Lambda中使用的值也会改变
        deviceName = "PLC-002";
        deviceLog("设备已连接");  // 输出 [PLC-002] 设备已连接
    }
}

/// <summary>
/// 传感器数据模型
/// </summary>
public class SensorData
{
    /// <summary>传感器名称</summary>
    public string Name { get; set; }

    /// <summary>当前值</summary>
    public double Value { get; set; }

    /// <summary>是否在线</summary>
    public bool IsOnline { get; set; }
}
```

### 2.3 Lambda 与 LINQ 的配合

Lambda 表达式是 LINQ 查询的基础，几乎所有 LINQ 方法都接受 Lambda 参数：

```csharp
using System;
using System.Linq;

public class LambdaWithLinqDemo
{
    public void Run()
    {
        // 模拟PLC寄存器数据（地址D0-D19）
        var registers = Enumerable.Range(0, 20)
            .Select(i => new { Address = $"D{i:D3}", Value = i * 10.5 })
            .ToList();

        // Any：是否存在值超过100的寄存器
        bool hasHighValue = registers.Any(r => r.Value > 100);
        Console.WriteLine($"是否存在高值: {hasHighValue}");  // True

        // FirstOrDefault：查找第一个值大于50的寄存器
        var firstHigh = registers.FirstOrDefault(r => r.Value > 50);
        Console.WriteLine($"第一个高值: {firstHigh?.Address} = {firstHigh?.Value}");

        // Select：投影转换（只取地址和是否大于50的标志）
        var statusList = registers.Select(r => new
        {
            r.Address,
            IsHigh = r.Value > 50
        }).ToList();

        // Sum / Max / Min
        Console.WriteLine($"总值: {registers.Sum(r => r.Value)}");
        Console.WriteLine($"最大值: {registers.Max(r => r.Value)}");
        Console.WriteLine($"最小值: {registers.Min(r => r.Value)}");

        // GroupBy：按值范围分组
        var groups = registers.GroupBy(r =>
            r.Value > 100 ? "高" : (r.Value > 50 ? "中" : "低")
        );

        foreach (var group in groups)
        {
            Console.WriteLine($"{group.Key}范围: {group.Count()}个寄存器");
        }
    }
}
```

## 3. 事件机制

### 3.1 什么是事件

**事件（Event）** 是基于委托的一种封装机制。如果说委托是一个"方法容器"，那么事件就是对委托的一种"保护性限制"——**外部只能订阅（+=）和取消订阅（-=），但不能直接调用或清除**。

```
委托 vs 事件：

委托（完全公开）：
  外部可以：赋值（=）、订阅（+=）、取消订阅（-=）、直接调用、清空

事件（受保护）：
  外部可以：订阅（+=）、取消订阅（-=）
  外部不可以：赋值（=）、直接调用、清空
  只有声明事件的类内部才能触发（调用）事件
```

### 3.2 event 关键字的使用

```csharp
using System;

/// <summary>
/// PLC通信设备类 —— 演示事件的基本使用
/// </summary>
public class PlcDevice
{
    // ========================
    // 1. 定义事件（使用 event 关键字）
    // ========================

    // 方式一：使用自定义委托类型
    public event LogOutputHandler LogMessage;

    // 方式二：使用 EventHandler（标准事件模式，.NET 推荐）
    // EventHandler<TEventArgs> 是 .NET 内置的泛型事件委托
    // 两个参数：sender（事件源）和 e（事件参数）
    public event EventHandler<string> DataReceived;

    // 方式三：使用 EventHandler（无自定义参数时）
    public event EventHandler ConnectionChanged;

    // ========================
    // 2. 触发事件（仅在类内部）
    // ========================

    /// <summary>
    /// 模拟接收PLC数据并触发事件
    /// </summary>
    public void ReadData()
    {
        // 模拟读取数据
        string data = "D100=25.5";

        // 触发事件前，先检查是否有订阅者（避免空引用异常）
        // 这是标准的触发方式
        DataReceived?.Invoke(this, data);

        // 旧式写法（也可以，但不推荐）：
        // if (DataReceived != null)
        //     DataReceived(this, data);
    }

    /// <summary>
    /// 模拟连接PLC
    /// </summary>
    public void Connect()
    {
        LogMessage?.Invoke("正在连接PLC...");

        // 模拟连接成功
        LogMessage?.Invoke("PLC连接成功");

        // 触发连接改变事件
        ConnectionChanged?.Invoke(this, EventArgs.Empty);
    }

    /// <summary>
    /// 模拟断开PLC
    /// </summary>
    public void Disconnect()
    {
        LogMessage?.Invoke("PLC已断开连接");
        ConnectionChanged?.Invoke(this, EventArgs.Empty);
    }
}

public class EventBasicDemo
{
    public void Run()
    {
        PlcDevice plc = new PlcDevice();

        // 订阅事件（使用 +=）
        plc.LogMessage += OnLogMessage;
        plc.DataReceived += OnDataReceived;
        plc.ConnectionChanged += OnConnectionChanged;

        // 操作PLC，事件会自动触发
        plc.Connect();
        plc.ReadData();
        plc.Disconnect();

        // 取消订阅（使用 -=）
        plc.DataReceived -= OnDataReceived;

        // 再次读取，DataReceived 事件不再触发
        plc.ReadData();  // 只有 LogMessage 会输出

        // 清理
        plc.LogMessage -= OnLogMessage;
        plc.ConnectionChanged -= OnConnectionChanged;
    }

    // ========================
    // 事件处理方法
    // ========================

    /// <summary>
    /// 日志消息事件处理
    /// </summary>
    private void OnLogMessage(string message)
    {
        Console.WriteLine($"[日志] {DateTime.Now:HH:mm:ss} | {message}");
    }

    /// <summary>
    /// 数据接收事件处理（标准模式：sender + e）
    /// </summary>
    private void OnDataReceived(object sender, string data)
    {
        Console.WriteLine($"[数据接收] 来源: {((PlcDevice)sender)?.GetType().Name} | 数据: {data}");
    }

    /// <summary>
    /// 连接状态改变事件处理
    /// </summary>
    private void OnConnectionChanged(object sender, EventArgs e)
    {
        Console.WriteLine($"[状态改变] PLC连接状态已发生变化");
    }
}
```

### 3.3 自定义事件参数（EventArgs）

在 .NET 事件模式中，推荐使用继承自 `EventArgs` 的类来传递事件数据，这样可以携带更丰富的信息：

```csharp
using System;

/// <summary>
/// PLC数据变化事件参数
/// </summary>
public class PlcDataChangedEventArgs : EventArgs
{
    /// <summary>变化的PLC地址</summary>
    public string Address { get; }

    /// <summary>变化后的新值</summary>
    public double NewValue { get; }

    /// <summary>变化前的旧值</summary>
    public double OldValue { get; }

    /// <summary>变化的时间戳</summary>
    public DateTime Timestamp { get; }

    public PlcDataChangedEventArgs(string address, double oldValue, double newValue)
    {
        Address = address;
        OldValue = oldValue;
        NewValue = newValue;
        Timestamp = DateTime.Now;
    }
}

/// <summary>
/// 通信异常事件参数
/// </summary>
public class CommunicationErrorEventArgs : EventArgs
{
    /// <summary>异常消息</summary>
    public string ErrorMessage { get; }

    /// <summary>通信端口/地址</summary>
    public string Port { get; }

    /// <summary>异常等级</summary>
    public ErrorLevel Level { get; }

    /// <summary>发生时间</summary>
    public DateTime ErrorTime { get; }

    public CommunicationErrorEventArgs(string errorMessage, string port, ErrorLevel level)
    {
        ErrorMessage = errorMessage;
        Port = port;
        Level = level;
        ErrorTime = DateTime.Now;
    }
}

/// <summary>
/// 异常等级枚举
/// </summary>
public enum ErrorLevel
{
    /// <summary>警告（可自动恢复）</summary>
    Warning,
    /// <summary>错误（需要干预）</summary>
    Error,
    /// <summary>严重（通信中断）</summary>
    Critical
}

/// <summary>
/// 具有自定义事件参数的PLC设备类
/// </summary>
public class AdvancedPlcDevice
{
    public string DeviceName { get; }

    // 使用自定义 EventArgs 的事件
    public event EventHandler<PlcDataChangedEventArgs> DataChanged;
    public event EventHandler<CommunicationErrorEventArgs> CommunicationError;

    // 存储当前值（模拟寄存器）
    private Dictionary<string, double> _registers = new Dictionary<string, double>();

    public AdvancedPlcDevice(string name)
    {
        DeviceName = name;
        // 初始化一些默认值
        _registers["D100"] = 0;
        _registers["D102"] = 0;
        _registers["D104"] = 0;
    }

    /// <summary>
    /// 模拟写入PLC数据（触发DataChanged事件）
    /// </summary>
    public void WriteRegister(string address, double value)
    {
        try
        {
            // 记录旧值
            double oldValue = _registers.ContainsKey(address) ? _registers[address] : 0;

            // 检查值是否真的发生变化
            if (Math.Abs(oldValue - value) < 0.001)
                return;  // 值没有变化，不触发事件

            // 更新值
            _registers[address] = value;

            // 触发数据变化事件
            var args = new PlcDataChangedEventArgs(address, oldValue, value);
            DataChanged?.Invoke(this, args);
        }
        catch (Exception ex)
        {
            // 触发通信异常事件
            var errorArgs = new CommunicationErrorEventArgs(
                ex.Message, "COM3", ErrorLevel.Error
            );
```

这是上位机开发中**最核心**的事件应用场景：底层通信模块检测到数据变化后，通过事件通知上层界面进行更新，实现**数据层与界面层的解耦**。

```csharp
using System;

/// <summary>
/// PLC通信服务层 —— 负责底层通信和数据读取
/// 与界面完全解耦，通过事件通知数据变化
/// </summary>
public class PlcCommunicationService
{
    // ========================
    // 定义事件
    // ========================

    /// <summary>数据变化事件</summary>
    public event EventHandler<PlcDataChangedEventArgs> DataChanged;

    /// <summary>连接状态改变事件</summary>
    public event EventHandler<bool> ConnectionStateChanged;

    /// <summary>通信异常事件</summary>
    public event EventHandler<string> ErrorOccurred;

    // ========================
    // 内部状态
    // ========================

    /// <summary>当前寄存器值缓存</summary>
    private Dictionary<string, double> _registerCache = new Dictionary<string, double>();

    /// <summary>是否已连接</summary>
    private bool _isConnected = false;

    /// <summary>模拟通信端口</summary>
    public string PortName { get; }

    public PlcCommunicationService(string portName)
    {
        PortName = portName;
    }

    /// <summary>
    /// 连接PLC
    /// </summary>
    public void Connect()
    {
        // 模拟连接过程
        Console.WriteLine($"[{PortName}] 正在连接...");
        Thread.Sleep(500);  // 模拟通信延迟

        _isConnected = true;
        ConnectionStateChanged?.Invoke(this, true);
        Console.WriteLine($"[{PortName}] 连接成功");
    }

    /// <summary>
    /// 断开PLC连接
    /// </summary>
    public void Disconnect()
    {
        _isConnected = false;
        ConnectionStateChanged?.Invoke(this, false);
        Console.WriteLine($"[{PortName}] 已断开连接");
    }

    /// <summary>
    /// 模拟从PLC读取一批寄存器数据
    /// 在实际项目中，这里会调用真实的通信协议库（如Modbus、MC协议等）
    /// </summary>
    public void PollRegisters(List<string> addresses)
    {
        if (!_isConnected)
        {
            ErrorOccurred?.Invoke(this, $"设备未连接，无法读取 {PortName}");
            return;
        }

        try
        {
            // 模拟随机数据变化
            Random rnd = new Random();

            foreach (var address in addresses)
            {
                // 模拟读取值（加随机波动）
                double baseValue = _registerCache.ContainsKey(address)
                    ? _registerCache[address]
                    : 25.0;
                double newValue = baseValue + (rnd.NextDouble() - 0.5) * 2;

                // 检查值是否变化超过阈值
                double oldValue = _registerCache.ContainsKey(address)
                    ? _registerCache[address]
                    : 0;

                if (Math.Abs(oldValue - newValue) > 0.01)
                {
                    // 更新缓存
                    _registerCache[address] = newValue;

                    // 触发数据变化事件
                    var args = new PlcDataChangedEventArgs(address, oldValue, newValue);
                    DataChanged?.Invoke(this, args);
                }
            }
        }
        catch (Exception ex)
        {
            ErrorOccurred?.Invoke(this, $"读取异常: {ex.Message}");
        }
    }
}
```

```csharp
using System;
using System.Threading;

/// <summary>
/// 通信异常管理器
/// 演示：异常事件的多级订阅和处理链
/// </summary>
public class CommunicationManager
{
    // 事件定义
    public event EventHandler<CommunicationErrorEventArgs> Error;
    public event EventHandler AutoReconnecting;     // 开始自动重连
    public event EventHandler<bool> ReconnectResult; // 重连结果

    private string _ipAddress;
    private int _port;
    private bool _isConnected;
    private int _retryCount;

    public CommunicationManager(string ip, int port)
    {
        _ipAddress = ip;
        _port = port;
    }

    /// <summary>
    /// 模拟通信操作（可能失败）
    /// </summary>
    public void SendCommand(string command)
    {
        if (!_isConnected)
        {
            // 触发通信异常事件
            Error?.Invoke(this, new CommunicationErrorEventArgs(
                "未连接，无法发送命令",
                $"{_ipAddress}:{_port}",
                ErrorLevel.Error
            ));
            return;
        }

        try
        {
            // 模拟通信（有10%概率失败）
            Random rnd = new Random();
            if (rnd.Next(100) < 10)
            {
                throw new TimeoutException("PLC响应超时");
            }

            Console.WriteLine($"  命令发送成功: {command}");
        }
        catch (TimeoutException ex)
        {
            // 触发通信异常事件
            Error?.Invoke(this, new CommunicationErrorEventArgs(
                ex.Message,
                $"{_ipAddress}:{_port}",
                ErrorLevel.Critical
            ));

            // 自动触发重连
            TryAutoReconnect();
        }
    }

    /// <summary>
    /// 自动重连机制
    /// </summary>
    private void TryAutoReconnect()
    {
        _retryCount = 0;
        const int maxRetries = 3;

        AutoReconnecting?.Invoke(this, EventArgs.Empty);
        Console.WriteLine($"  开始自动重连 (最多{maxRetries}次)...");

        while (_retryCount < maxRetries)
        {
            _retryCount++;
            Thread.Sleep(500);  // 模拟重连延迟

            // 模拟重连（50%成功率）
            Random rnd = new Random();
            if (rnd.Next(100) < 50)
            {
                _isConnected = true;
                ReconnectResult?.Invoke(this, true);
                Console.WriteLine($"  重连成功! (第{_retryCount}次尝试)");
                return;
            }

            Console.WriteLine($"  第{_retryCount}次重连失败...");
        }

        _isConnected = false;
        ReconnectResult?.Invoke(this, false);
        Console.WriteLine($"  重连失败，已达到最大重试次数");

        // 触发严重错误事件
        Error?.Invoke(this, new CommunicationErrorEventArgs(
            $"重连失败（已尝试{maxRetries}次）",
            $"{_ipAddress}:{_port}",
            ErrorLevel.Critical
        ));
    }

    public void Connect()
    {
        _isConnected = true;
        Console.WriteLine($"已连接 {_ipAddress}:{_port}");
    }
}
```

## 5. 观察者模式在上位机中的应用

### 5.1 什么是观察者模式

**观察者模式（Observer Pattern）** 是一种行为设计模式。核心思想是：当一个对象的状态发生改变时，所有依赖于它的对象都会得到通知并自动更新。

在 C# 中，**事件机制就是观察者模式的标准实现**。

```
观察者模式结构：

  ┌─────────────────────────────────────────┐
  │           主题（Subject）                │
  │   被观察的对象（如：PLC通信服务）          │
  │                                         │
  │   + Attach(observer)    ← 订阅          │
  │   + Detach(observer)    ← 取消订阅      │
  │   + Notify()            ← 通知变化      │
  └─────────┬───────────────────────────────┘
            │ 通知
    ┌───────┼───────┐
    ▼       ▼       ▼
 ┌──────┐ ┌──────┐ ┌──────┐
 │观察者A│ │观察者B│ │观察者C│
 │(界面) │ │(日志) │ │(报警) │
 └──────┘ └──────┘ └──────┘
```

### 5.2 在上位机中的实际应用

```csharp

{
    // 使用事件实现观察者模式的通知机制
    public event EventHandler<AlarmInfo> AlarmRaised;
    public event EventHandler<string> DataUpdated;

    private Dictionary<string, double> _lastValues = new Dictionary<string, double>();

    // 报警阈值配置
    private Dictionary<string, (double Min, double Max)> _alarmThresholds
        = new Dictionary<string, (double, double)>();

    /// <summary>
    /// 设置报警阈值
    /// </summary>
    public void SetThreshold(string tag, double min, double max)
    {
        _alarmThresholds[tag] = (min, max);
    }

    /// <summary>
    /// 更新数据值（自动检查报警）
    /// 这个方法由底层数据采集模块调用
    /// </summary>
    public void UpdateValue(string tag, double value)
    {
        // 通知数据更新
        DataUpdated?.Invoke(this, $"{tag}={value:F1}");

        // 检查是否需要报警
        if (_alarmThresholds.TryGetValue(tag, out var threshold))
        {
            double lastValue = _lastValues.ContainsKey(tag) ? _lastValues[tag] : value;

            // 检查是否越限
            if (value > threshold.Max)
            {
                var alarm = new AlarmInfo(tag,
                    $"值超上限: {value:F1} > {threshold.Max}",
                    AlarmLevel.Alarm);
                AlarmRaised?.Invoke(this, alarm);
            }
            else if (value < threshold.Min)
            {
                var alarm = new AlarmInfo(tag,
                    $"值低于下限: {value:F1} < {threshold.Min}",
                    AlarmLevel.Alarm);
                AlarmRaised?.Invoke(this, alarm);
            }
            // 检查是否接近限值（预警）
            else if (value > threshold.Max * 0.9)
            {
                var alarm = new AlarmInfo(tag,
                    $"值接近上限: {value:F1} (上限:{threshold.Max})",
                    AlarmLevel.Warning);
                AlarmRaised?.Invoke(this, alarm);
            }
            else if (value < threshold.Min + (threshold.Max - threshold.Min) * 0.1)
            {
                var alarm = new AlarmInfo(tag,
                    $"值接近下限: {value:F1} (下限:{threshold.Min})",
                    AlarmLevel.Warning);
                AlarmRaised?.Invoke(this, alarm);
            }

            _lastValues[tag] = value;
        }
    }
}
```

## 6. 注意事项

### 6.1 事件与委托的内存泄漏

```csharp
// 常见错误：忘记取消订阅导致内存泄漏
public class BadExample
{
    private PlcDevice _plc = new PlcDevice();

    public BadExample()
    {
        // 订阅了事件，但从未取消订阅
        _plc.DataReceived += OnDataReceived;

        // 如果 _plc 是长生命周期对象，而 this 被频繁创建/销毁
        // 那么 _plc 会一直持有 this 的引用，导致 this 无法被GC回收
        // 这就是"事件引起的内存泄漏"
    }

    private void OnDataReceived(object sender, string data) { }
}

// 正确做法：
public class GoodExample : IDisposable
{
    private PlcDevice _plc = new PlcDevice();

    public GoodExample()
    {
        _plc.DataReceived += OnDataReceived;
    }

    private void OnDataReceived(object sender, string data) { }

    public void Dispose()
    {
        // 释放时取消订阅
        _plc.DataReceived -= OnDataReceived;
    }
}
```

### 6.2 多播委托中的异常处理

```csharp
// 注意：多播委托中，如果某个方法抛出异常，后续方法不会被执行
Action handlers = MethodA;
handlers += MethodB;  // 如果MethodA抛出异常，MethodB不会被调用
handlers += MethodC;

// 安全调用方式：
public static void SafeInvoke(this Action action)
{
    if (action == null) return;

    // 获取多播委托中的所有方法
    Delegate[] delegates = action.GetInvocationList();

    foreach (Delegate d in delegates)
    {
        try
        {
            ((Action)d)();
        }
        catch (Exception ex)
        {
            Console.WriteLine($"事件处理器异常: {ex.Message}");
            // 继续执行下一个处理器
        }
    }
}
```

### 6.3 Lambda 捕获变量的陷阱

```csharp
// 常见陷阱：在循环中使用Lambda
var actions = new List<Action>();

for (int i = 0; i < 5; i++)
{
    // 错误：所有Lambda都捕获同一个变量 i
    // 循环结束后 i = 5，所有Lambda都会输出5
    actions.Add(() => Console.WriteLine(i));
}

foreach (var action in actions)
{
    action();  // 全部输出 5!
}

// 正确做法：在Lambda内部创建局部变量
var correctActions = new List<Action>();

for (int i = 0; i < 5; i++)
{
    int local_i = i;  // 每次循环创建新的局部变量
    correctActions.Add(() => Console.WriteLine(local_i));
}

foreach (var action in correctActions)
{
    action();  // 输出 0, 1, 2, 3, 4
}
```

> **注意**：C# 5.0 之后，`foreach` 循环中的变量捕获问题已经被修复（每次迭代都会创建新变量），但 `for` 循环中仍然存在这个问题。

### 6.4 事件的 null 条件调用

```csharp
// 推荐使用 ?. 运算符来安全触发事件
public event EventHandler DataChanged;

// 推荐：
DataChanged?.Invoke(this, EventArgs.Empty);

// 不推荐（可能存在竞态条件）：
// if (DataChanged != null)
//     DataChanged(this, EventArgs.Empty);
// 在多线程环境下，检查和调用之间，DataChanged可能被其他线程改为null
```

## 8. 常见错误

### 错误1：事件外部调用

```csharp
public class PlcDevice
{
    public event EventHandler DataReceived;
}

// 错误：在类外部直接调用事件
var plc = new PlcDevice();
plc.DataReceived(plc, EventArgs.Empty);  // 编译错误！事件只能在声明类内部调用

// 如果确实需要在外部触发，应改为使用委托（不用 event 关键字）
// 或者在类内部提供一个公有方法来触发
```

### 错误2：用 = 替代 += 订阅事件

```csharp
var plc = new PlcDevice();

plc.DataReceived += HandlerA;
plc.DataReceived += HandlerB;

// 错误：使用 = 会覆盖之前的所有订阅！
plc.DataReceived = HandlerC;  // HandlerA 和 HandlerB 会被移除

// 正确：始终使用 += 添加订阅
plc.DataReceived += HandlerC;
```

### 错误3：Lambda 闭包导致意外行为

```csharp
// 错误：期望创建5个独立的计数器
var counters = new List<Func<int>>();

for (int i = 0; i < 5; i++)
{
    counters.Add(() => i);  // 所有Lambda都捕获同一个i
}

Console.WriteLine(counters[0]());  // 5 (不是0!)
Console.WriteLine(counters[3]());  // 5 (不是3!)

// 正确做法
var correctCounters = new List<Func<int>>();
for (int i = 0; i < 5; i++)
{
    int captured = i;  // 每次循环捕获一个新的变量
    correctCounters.Add(() => captured);
}
```

### 错误4：忘记取消订阅导致内存泄漏

```csharp
// 在WinForms/WPF上位机中，窗体关闭时没有取消事件订阅
// 会导致窗体对象无法被垃圾回收，造成内存泄漏
public partial class MonitorForm : Form
{
    private PlcService _plcService;

    protected override void OnLoad(EventArgs e)
    {
        base.OnLoad(e);
        _plcService = PlcService.Instance;
        _plcService.DataChanged += UpdateDisplay;  // 订阅
    }

    protected override void OnClosed(EventArgs e)
    {
        base.OnClosed(e);
        // 错误：缺少取消订阅！
        // 正确：
        _plcService.DataChanged -= UpdateDisplay;
    }
}
```

### 错误5：多播委托中使用 out/ref 参数

```csharp
// 错误：多播委托不支持 ref/out 参数
public delegate void RefHandler(ref int value);

RefHandler h = MethodA;
h += MethodB;  // 编译错误！多播委托不能有 ref/out 参数

// 正确做法：使用返回值或封装到类中
```
