# 完整流程：git log 查看历史 → 切换/回退指定版本
## 一、退出 git log 界面
查看完日志先退出，才能输后续命令：
```bash
q
```

## 二、简洁查看提交（推荐）
```bash
# 每行一条，只显示前7位commit哈希（复制用）
git log --oneline
# 只看最近10条
git log --oneline -10
```
输出示例：
```
f32a90d 修复登录bug
78c12b5 新增用户模块
a45d789 初始化项目
```
`f32a90d` 就是版本唯一标识 commit-id，复制前7位即可使用。

## 三、两种操作：临时查看旧版 / 永久回退代码
### 场景1：只临时看旧版本，不修改分支历史（git checkout）
适合调试、对比旧代码，看完能轻松切回最新代码，**安全无风险**
```bash
# 切换到指定commit（进入游离HEAD状态）
git checkout a45d789
```
看完返回最新分支（如main/master）：
```bash
git checkout main
# 或者一键回到上一次所在分支
git checkout @{-1}
```

### 场景2：永久回退分支到旧版本（git reset，分3种模式）
#### 1）彻底丢弃所有修改（最常用，本地回退）
**--hard：工作区、暂存区、提交全部回退，未保存修改直接清空**
```bash
git reset --hard a45d789
```
风险：本地未提交代码全部丢失，操作前建议备份：
```bash
git branch backup_before_reset # 备份当前版本到新分支
```

#### 2）温和回退，保留代码改动（--mixed 默认）
提交记录回退，但代码留在本地未暂存区，可重新修改提交：
```bash
git reset a45d789
```

#### 3）极致温和（--soft）
只移动提交指针，修改全部保留在暂存区，适合合并多次commit：
```bash
git reset --soft a45d789
```

### 场景3：团队协作，安全回退远程（git revert，推荐多人项目）
reset会改写历史，多人共用分支强制推送会造成冲突；
revert**新建提交抵消旧修改，不删除历史**，所有人正常pull即可
```bash
# 撤销某一次提交，生成新提交覆盖它
git revert f32a90d
# 回车后编辑提交说明，保存退出即完成
```

## 四、回退后推送到远程仓库（谨慎操作）
1. 如果你用 `git reset --hard` 本地改写历史，推送必须强制：
```bash
# 危险！团队共用分支慎用，会覆盖别人已拉取的代码
git push -f origin main
```
2. 如果你用 `git revert`，正常推送即可：
```bash
git push origin main
```

## 五、误回退，想恢复最新代码（找回丢失commit）
reset后git log看不到新版本时，用 `git reflog` 查看所有操作记录：
```bash
git reflog
# 找到回退前最新commit哈希，重新硬重置恢复
git reset --hard f32a90d
```

## 命令速查表
| 需求 | 命令 | 适用场景 |
|------|------|----------|
| 临时看旧代码，看完切回 | `git checkout commit-id` | 调试、对比历史版本 |
| 本地彻底回退，丢弃所有改动 | `git reset --hard commit-id` | 个人本地分支，未推送远程 |
| 多人协作安全回退 | `git revert commit-id` | 公共分支、线上代码 |
| 找回误删的新版本 | `git reflog && git reset --hard 最新hash` | reset操作后悔 |

## 完整实操示例
```bash
# 1. 查看简洁提交日志
git log --oneline
# 2. 退出log界面
q
# 3. 永久回退到初始化版本
git reset --hard a45d789
# 4. 备份/恢复（后悔了）
git reflog
git reset --hard f32a90d
```
