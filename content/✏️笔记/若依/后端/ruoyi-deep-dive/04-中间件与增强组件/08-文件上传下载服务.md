# 08 - 文件上传下载服务

## 一、概述

若依框架提供了一套完整的文件上传下载服务，包括文件上传（大小限制、扩展名校验、日期目录+序列号命名）、文件下载（通用下载、资源下载）、静态资源映射等功能。通过`CommonController`暴露REST接口，`FileUploadUtils`封装上传逻辑，`ResourcesConfig`配置静态资源映射，形成从上传到访问的完整链路。

### 2.2 文件处理流程

```
上传流程：
  前端选择文件 -> POST /common/upload
    |
  FileUploadUtils.upload()
    |-- 校验文件名长度(<=100)
    |-- 校验文件大小(<=50M)
    |-- 校验扩展名(白名单)
    |-- 生成文件名(日期目录/原名_序列.扩展名)
    |-- 写入磁盘
    |
  返回: {url, fileName, newFileName, originalFilename}

访问流程：
  前端请求 /profile/upload/2024/06/13/xxx.jpg
    |
  ResourcesConfig静态资源映射
    |
  file:D:/ruoyi/uploadPath/upload/2024/06/13/xxx.jpg
    |
  返回文件内容

下载流程：
  GET /common/download?fileName=xxx
    |
  FileUtils.checkAllowDownload() -- 安全校验
    |
  FileUtils.writeBytes() -- 写入响应流
    |
  可选: delete=true 删除源文件
```

## 三、源码关键片段引用

### 3.1 FileUploadUtils - 文件上传工具

> 源码位置：`ruoyi-common/src/main/java/com/ruoyi/common/utils/file/FileUploadUtils.java`

```java
public class FileUploadUtils
{
    /** 默认大小 50M */
    public static final long DEFAULT_MAX_SIZE = 50 * 1024 * 1024L;
    /** 默认的文件名最大长度 100 */
    public static final int DEFAULT_FILE_NAME_LENGTH = 100;
    /** 默认上传的地址 */
    private static String defaultBaseDir = RuoYiConfig.getProfile();

    /**
     * 文件上传
     */
    public static final String upload(String baseDir, MultipartFile file, String[] allowedExtension, boolean useCustomNaming)
            throws FileSizeLimitExceededException, IOException, FileNameLengthLimitExceededException, InvalidExtensionException
    {
        int fileNameLength = Objects.requireNonNull(file.getOriginalFilename()).length();
        if (fileNameLength > FileUploadUtils.DEFAULT_FILE_NAME_LENGTH)
        {
            throw new FileNameLengthLimitExceededException(FileUploadUtils.DEFAULT_FILE_NAME_LENGTH);
        }

        assertAllowed(file, allowedExtension);

        String fileName = useCustomNaming ? uuidFilename(file) : extractFilename(file);

        String absPath = getAbsoluteFile(baseDir, fileName).getAbsolutePath();
        file.transferTo(Paths.get(absPath));
        return getPathFileName(baseDir, fileName);
    }

    /**
     * 编码文件名(日期格式目录 + 原文件名 + 序列值 + 后缀)
     */
    public static final String extractFilename(MultipartFile file)
    {
        return StringUtils.format("{}/{}_{}.{}", DateUtils.datePath(), FilenameUtils.getBaseName(file.getOriginalFilename()), Seq.getId(Seq.uploadSeqType), getExtension(file));
    }

    /**
     * 编码文件名(日期格式目录 + UUID + 后缀)
     */
    public static final String uuidFilename(MultipartFile file)
    {
        return StringUtils.format("{}/{}.{}", DateUtils.datePath(), IdUtils.fastSimpleUUID(), getExtension(file));
    }

    /**
     * 文件大小校验 + 扩展名校验
     */
    public static final void assertAllowed(MultipartFile file, String[] allowedExtension)
            throws FileSizeLimitExceededException, InvalidExtensionException
    {
        long size = file.getSize();
        if (size > DEFAULT_MAX_SIZE)
        {
            throw new FileSizeLimitExceededException(DEFAULT_MAX_SIZE / 1024 / 1024);
        }

        String fileName = file.getOriginalFilename();
        String extension = getExtension(file);
        if (allowedExtension != null && !isAllowedExtension(extension, allowedExtension))
        {
            if (allowedExtension == MimeTypeUtils.IMAGE_EXTENSION)
            {
                throw new InvalidExtensionException.InvalidImageExtensionException(allowedExtension, extension, fileName);
            }
            else if (allowedExtension == MimeTypeUtils.FLASH_EXTENSION)
            {
                throw new InvalidExtensionException.InvalidFlashExtensionException(allowedExtension, extension, fileName);
            }
            else if (allowedExtension == MimeTypeUtils.MEDIA_EXTENSION)
            {
                throw new InvalidExtensionException.InvalidMediaExtensionException(allowedExtension, extension, fileName);
            }
            else if (allowedExtension == MimeTypeUtils.VIDEO_EXTENSION)
            {
                throw new InvalidExtensionException.InvalidVideoExtensionException(allowedExtension, extension, fileName);
            }
            else
            {
                throw new InvalidExtensionException(allowedExtension, extension, fileName);
            }
        }
    }

    /**
     * 获取文件名的后缀
     */
    public static final String getExtension(MultipartFile file)
    {
        String extension = FilenameUtils.getExtension(file.getOriginalFilename());
        if (StringUtils.isEmpty(extension))
        {
            extension = MimeTypeUtils.getExtension(Objects.requireNonNull(file.getContentType()));
        }
        return extension;
    }
}
```

**剖析要点：**
- 三重校验：文件名长度(<=100)、文件大小(<=50M)、扩展名(白名单)
- 两种命名策略：`extractFilename`（日期目录+原名+序列号）和`uuidFilename`（日期目录+UUID）
- `DateUtils.datePath()`生成日期目录，如`2024/06/13`
- `Seq.getId(Seq.uploadSeqType)`生成全局唯一序列号，防止同秒上传同名文件冲突
- 扩展名校验分类型抛出不同异常：图片/Flash/媒体/视频/通用
- 如果文件名无扩展名，从ContentType中推断扩展名

### 3.2 CommonController - 上传下载接口

> 源码位置：`ruoyi-admin/src/main/java/com/ruoyi/web/controller/common/CommonController.java`

```java
@RestController
@RequestMapping("/common")
public class CommonController
{
    @Autowired
    private ServerConfig serverConfig;

    /**
     * 通用上传请求（单个）
     */
    @PostMapping("/upload")
    public AjaxResult uploadFile(MultipartFile file) throws Exception
    {
        try
        {
            String filePath = RuoYiConfig.getUploadPath();
            String fileName = FileUploadUtils.upload(filePath, file);
            String url = serverConfig.getUrl() + fileName;
            AjaxResult ajax = AjaxResult.success();
            ajax.put("url", url);
            ajax.put("fileName", fileName);
            ajax.put("newFileName", FileUtils.getName(fileName));
            ajax.put("originalFilename", file.getOriginalFilename());
            return ajax;
        }
        catch (Exception e)
        {
            return AjaxResult.error(e.getMessage());
        }
    }

    /**
     * 通用上传请求（多个）
     */
    @PostMapping("/uploads")
    public AjaxResult uploadFiles(List<MultipartFile> files) throws Exception
    {
        try
        {
            String filePath = RuoYiConfig.getUploadPath();
            List<String> urls = new ArrayList<String>();
            List<String> fileNames = new ArrayList<String>();
            List<String> newFileNames = new ArrayList<String>();
            List<String> originalFilenames = new ArrayList<String>();
            for (MultipartFile file : files)
            {
                String fileName = FileUploadUtils.upload(filePath, file);
                String url = serverConfig.getUrl() + fileName;
                urls.add(url);
                fileNames.add(fileName);
                newFileNames.add(FileUtils.getName(fileName));
                originalFilenames.add(file.getOriginalFilename());
            }
            AjaxResult ajax = AjaxResult.success();
            ajax.put("urls", StringUtils.join(urls, FILE_DELIMITER));
            ajax.put("fileNames", StringUtils.join(fileNames, FILE_DELIMITER));
            ajax.put("newFileNames", StringUtils.join(newFileNames, FILE_DELIMITER));
            ajax.put("originalFilenames", StringUtils.join(originalFilenames, FILE_DELIMITER));
            return ajax;
        }
        catch (Exception e)
        {
            return AjaxResult.error(e.getMessage());
        }
    }

    /**
     * 通用下载请求
     */
    @GetMapping("/download")
    public void fileDownload(String fileName, Boolean delete, HttpServletResponse response, HttpServletRequest request)
    {
        try
        {
            if (!FileUtils.checkAllowDownload(fileName))
            {
                throw new Exception(StringUtils.format("文件名称({})非法，不允许下载。 ", fileName));
            }
            String realFileName = System.currentTimeMillis() + fileName.substring(fileName.indexOf("_") + 1);
            String filePath = RuoYiConfig.getDownloadPath() + fileName;

            response.setContentType(MediaType.APPLICATION_OCTET_STREAM_VALUE);
            FileUtils.setAttachmentResponseHeader(response, realFileName);
            FileUtils.writeBytes(filePath, response.getOutputStream());
            if (delete)
            {
                FileUtils.deleteFile(filePath);
            }
        }
        catch (Exception e)
        {
            log.error("下载文件失败", e);
        }
    }

    /**
     * 本地资源通用下载
     */
    @GetMapping("/download/resource")
    public void resourceDownload(String resource, HttpServletRequest request, HttpServletResponse response) throws Exception
    {
        try
        {
            if (!FileUtils.checkAllowDownload(resource))
            {
                throw new Exception(StringUtils.format("资源文件({})非法，不允许下载。 ", resource));
            }
            String localPath = RuoYiConfig.getProfile();
            String downloadPath = localPath + FileUtils.stripPrefix(resource);
            String downloadName = StringUtils.substringAfterLast(downloadPath, "/");
            response.setContentType(MediaType.APPLICATION_OCTET_STREAM_VALUE);
            FileUtils.setAttachmentResponseHeader(response, downloadName);
            FileUtils.writeBytes(downloadPath, response.getOutputStream());
        }
        catch (Exception e)
        {
            log.error("下载文件失败", e);
        }
    }
}
```

**剖析要点：**
- 上传返回4个字段：url（完整访问地址）、fileName（相对路径）、newFileName（文件名）、originalFilename（原始文件名）
- 多文件上传返回逗号分隔的字符串列表
- 下载接口支持`delete`参数，下载后自动删除源文件
- `checkAllowDownload`校验文件名合法性，防止路径遍历攻击
- `resourceDownload`用于下载已上传的资源文件，去除`/profile`前缀后拼接本地路径

### 3.3 ResourcesConfig - 静态资源映射

> 源码位置：`ruoyi-framework/src/main/java/com/ruoyi/framework/config/ResourcesConfig.java`

```java
@Override
public void addResourceHandlers(ResourceHandlerRegistry registry)
{
    /** 本地文件上传路径 */
    registry.addResourceHandler(Constants.RESOURCE_PREFIX + "/**")
            .addResourceLocations("file:" + RuoYiConfig.getProfile() + "/");
}
```

**剖析要点：**
- `RESOURCE_PREFIX = "/profile"`，所有上传文件的访问前缀
- 映射到本地文件系统的`file:D:/ruoyi/uploadPath/`目录
- 访问示例：`/profile/upload/2024/06/13/xxx.jpg` -> `D:/ruoyi/uploadPath/upload/2024/06/13/xxx.jpg`

### 3.4 application.yml - 上传配置

```yaml
ruoyi:
  # 文件路径
  profile: D:/ruoyi/uploadPath

spring:
  servlet:
    multipart:
      # 单个文件大小
      max-file-size: 10MB
      # 设置总上传的文件大小
      max-request-size: 20MB
```

**剖析要点：**
- Spring的multipart配置限制为10MB/20MB
- `FileUploadUtils`的限制为50MB，两者取较小值生效
- 实际限制 = min(Spring multipart限制, FileUploadUtils限制) = 10MB

## 四、细节留神

1. **双重大小限制**：Spring multipart配置（10MB）和FileUploadUtils（50MB）同时存在，实际生效的是Spring的10MB限制。需要保持两者一致。
2. **路径遍历防护**：`FileUtils.checkAllowDownload`校验文件名中不能包含`..`等路径遍历字符，防止下载任意文件。
3. **文件名冲突**：使用`日期目录 + 原名 + 序列号`命名，序列号基于`System.currentTimeMillis()`，理论上高并发下仍可能冲突。
4. **磁盘空间**：上传文件直接写入本地磁盘，没有磁盘空间检查和清理机制，长期运行可能导致磁盘满。
5. **文件下载安全**：下载接口需要认证（在SecurityConfig中未放行），但资源访问路径`/profile/**`在SecurityConfig中是放行的（GET请求）。

## 五、提问方向

1. **Spring multipart限制（10MB）和FileUploadUtils限制（50MB）不一致，实际生效的是哪个？如何统一管理文件大小限制？**

2. **当前文件上传到本地磁盘，如果需要迁移到对象存储（如OSS、MinIO），需要改造哪些组件？如何设计一个可插拔的存储策略？**

3. **`extractFilename`使用`System.currentTimeMillis()`作为序列号，在高并发场景下是否可能产生文件名冲突？如何保证文件名唯一性？**

4. **`/profile/**`路径在SecurityConfig中是GET放行的，这意味着已上传的文件任何人都可以通过URL直接访问。如何实现文件访问权限控制？**

5. **文件上传没有实现断点续传和大文件分片上传功能，如果需要支持GB级文件上传，应该如何设计？**

6. **`FileUtils.checkAllowDownload`如何防止路径遍历攻击？如果攻击者使用URL编码（如`%2e%2e`）绕过校验，应该如何防御？**
