# 09 - 线程池与异步任务

## 一、概述

若依框架的线程池与异步任务体系由三个核心组件构成：`ThreadPoolConfig`（线程池配置）、`AsyncManager`（异步任务管理器）和`ShutdownManager`（优雅关闭管理器）。这套体系支撑了操作日志记录、登录日志记录等异步场景，确保日志写入不阻塞业务请求，同时保证应用关闭时线程池的安全终止。

## 三、源码关键片段引用

### 3.1 ThreadPoolConfig - 线程池配置

> 源码位置：`ruoyi-framework/src/main/java/com/ruoyi/framework/config/ThreadPoolConfig.java`

```java
@Configuration
public class ThreadPoolConfig
{
    // 核心线程池大小
    private int corePoolSize = 50;
    // 最大可创建的线程数
    private int maxPoolSize = 200;
    // 队列最大长度
    private int queueCapacity = 1000;
    // 线程池维护线程所允许的空闲时间
    private int keepAliveSeconds = 300;

    @Bean(name = "threadPoolTaskExecutor")
    public ThreadPoolTaskExecutor threadPoolTaskExecutor()
    {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setMaxPoolSize(maxPoolSize);
        executor.setCorePoolSize(corePoolSize);
        executor.setQueueCapacity(queueCapacity);
        executor.setKeepAliveSeconds(keepAliveSeconds);
        // 线程池对拒绝任务(无线程可用)的处理策略
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        return executor;
    }

    /**
     * 执行周期性或定时任务
     */
    @Bean(name = "scheduledExecutorService")
    protected ScheduledExecutorService scheduledExecutorService()
    {
        return new ScheduledThreadPoolExecutor(corePoolSize,
            BasicThreadFactory.builder().namingPattern("schedule-pool-%d").daemon(true).build(),
            new ThreadPoolExecutor.CallerRunsPolicy())
        {
            @Override
            protected void afterExecute(Runnable r, Throwable t)
            {
                super.afterExecute(r, t);
                Threads.printException(r, t);
            }
        };
    }
}
```

**剖析要点：**

**threadPoolTaskExecutor（异步任务执行池）：**
- 核心线程50：常驻线程数，即使空闲也不回收
- 最大线程200：高峰期最多创建200个线程
- 队列容量1000：核心线程满后，任务进入等待队列
- 空闲时间300秒：非核心线程空闲300秒后回收
- `CallerRunsPolicy`：队列满且线程满时，由调用线程自己执行任务（降级策略）

**scheduledExecutorService（定时调度池）：**
- 核心线程50：用于执行延迟/周期任务
- `daemon=true`：守护线程，JVM退出时自动终止
- 命名模式`schedule-pool-%d`：便于日志排查
- `afterExecute`：任务执行后检查异常，通过`Threads.printException`打印

**线程池参数关系：**
```
总处理能力 = maxPoolSize + queueCapacity = 200 + 1000 = 1200
当活跃任务 <= 50时：使用核心线程
当活跃任务 50~1050时：核心线程 + 队列
当活跃任务 1050~1200时：核心线程 + 队列 + 新建线程(最多150个)
当活跃任务 > 1200时：CallerRunsPolicy，调用线程自己执行
```

### 3.2 AsyncManager - 异步任务管理器

> 源码位置：`ruoyi-framework/src/main/java/com/ruoyi/framework/manager/AsyncManager.java`

```java
public class AsyncManager
{
    /**
     * 操作延迟10毫秒
     */
    private final int OPERATE_DELAY_TIME = 10;

    /**
     * 异步操作任务调度线程池
     */
    private ScheduledExecutorService executor = SpringUtils.getBean("scheduledExecutorService");

    /**
     * 单例模式
     */
    private AsyncManager(){}

    private static AsyncManager me = new AsyncManager();

    public static AsyncManager me()
    {
        return me;
    }

    /**
     * 执行任务
     */
    public void execute(TimerTask task)
    {
        executor.schedule(task, OPERATE_DELAY_TIME, TimeUnit.MILLISECONDS);
    }

    /**
     * 停止任务线程池
     */
    public void shutdown()
    {
        Threads.shutdownAndAwaitTermination(executor);
    }
}
```

**剖析要点：**
- 饿汉式单例：类加载时创建实例，线程安全
- 延迟10ms执行：给当前请求留出完成时间，避免异步任务影响响应
- 使用`ScheduledExecutorService.schedule()`而非`execute()`，实现延迟执行
- 通过`SpringUtils.getBean`获取线程池Bean，而非直接new，保证使用Spring管理的线程池

### 3.3 ShutdownManager - 优雅关闭

> 源码位置：`ruoyi-framework/src/main/java/com/ruoyi/framework/manager/ShutdownManager.java`

```java
@Component
public class ShutdownManager
{
    private static final Logger logger = LoggerFactory.getLogger("sys-user");

    @PreDestroy
    public void destroy()
    {
        shutdownAsyncManager();
    }

    private void shutdownAsyncManager()
    {
        try
        {
            logger.info("====关闭后台任务任务线程池====");
            AsyncManager.me().shutdown();
        }
        catch (Exception e)
        {
            logger.error(e.getMessage(), e);
        }
    }
}
```

**剖析要点：**
- `@PreDestroy`：Spring容器销毁Bean之前执行，确保线程池安全关闭
- 优雅关闭顺序：Spring容器关闭 -> @PreDestroy -> 线程池shutdown -> 等待任务完成
- 使用`sys-user` Logger记录关闭日志

**剖析要点：**

## 四、异步任务执行流程

```
业务请求到达
    |
LogAspect / SysLoginService 调用 AsyncManager.me().execute(AsyncFactory.recordXxx())
    |
创建TimerTask（捕获当前请求上下文信息）
    |
ScheduledExecutorService.schedule(task, 10ms)
    |
10ms后在线程池线程中执行TimerTask.run()
    |-- 获取Spring Bean
    |-- 执行数据库操作
    |-- 捕获异常（afterExecute打印）
    |
任务完成

应用关闭时：
    |
Spring容器销毁
    |
@PreDestroy -> ShutdownManager.destroy()
    |
AsyncManager.shutdown()
    |
Threads.shutdownAndAwaitTermination(executor)
    |-- executor.shutdown() -- 停止接受新任务
    |-- 等待已提交任务完成
    |-- 超时后强制shutdownNow()
```

## 五、细节留神

1. **CallerRunsPolicy影响**：当线程池和队列都满时，日志写入任务会在业务请求线程中同步执行，可能导致接口响应变慢。
2. **请求上下文丢失**：TimerTask在异步线程中执行，无法直接访问HttpServletRequest。AsyncFactory在创建TimerTask时就提取了所需信息（IP、User-Agent等）。
3. **单例线程池**：`threadPoolTaskExecutor`和`scheduledExecutorService`是全局共享的，所有异步任务共用同一个线程池。
4. **延迟10ms的设计**：10ms延迟的目的是让当前HTTP请求先返回响应，日志写入在后台异步完成。但如果10ms内应用关闭，任务可能丢失。
5. **线程池参数不可配置**：核心线程数、最大线程数、队列容量等参数是硬编码的，无法通过配置文件调整。

## 六、提问方向

1. **线程池参数（核心50/最大200/队列1000）是硬编码的，如果需要根据服务器配置动态调整，应该如何改造？**

2. **`CallerRunsPolicy`策略下，如果线程池满了，日志写入会在业务线程中同步执行。如何监控线程池的使用情况，及时发现线程池饱和？**

3. **AsyncFactory中在创建TimerTask时就提取了`ServletUtils.getRequest()`的信息，如果请求已经结束（响应已返回），在TimerTask中还能获取到Request信息吗？为什么？**

4. **当前只有一个全局共享的线程池，如果日志写入任务和业务异步任务共用线程池，日志任务可能影响业务任务的执行。如何设计线程池隔离？**

5. **`ShutdownManager`使用`@PreDestroy`优雅关闭线程池，如果关闭时间超过等待超时，未完成的日志任务会怎样？如何保证日志不丢失？**

6. **`scheduledExecutorService`设置为daemon线程（`daemon=true`），这意味着如果所有非daemon线程结束，JVM会直接退出而不等待任务完成。这种设计是否合理？**

7. **若依的异步任务使用`ScheduledExecutorService.schedule()`延迟10ms执行，为什么不直接使用`ExecutorService.execute()`立即执行？延迟10ms有什么好处？**
