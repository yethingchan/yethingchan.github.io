# 03 - 部署与运维指南

> 本文档详细介绍 RuoYi-Vue 项目的打包方式、部署流程、环境配置、监控方案和日志管理。

## 一、打包方式

### 1.1 JAR 打包（推荐）

**查看&剖析点**

RuoYi 默认使用 `spring-boot-maven-plugin` 打包为可执行 JAR 文件。

**源码关键片段**

文件：`ruoyi-admin/pom.xml`

```xml
<packaging>jar</packaging>
<artifactId>ruoyi-admin</artifactId>

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
            <configuration>
                <addResources>true</addResources>
            </configuration>
            <executions>
                <execution>
                    <goals>
                        <goal>repackage</goal>
                    </goals>
                </execution>
            </executions>
        </plugin>
    </plugins>
    <finalName>${project.artifactId}</finalName>
</build>
```

**打包命令**

```bash
# 在项目根目录执行
mvn clean package -Dmaven.test.skip=true

# 打包产物位置
# ruoyi-admin/target/ruoyi-admin.jar
```

**运行方式**

```bash
# 前台运行
java -jar ruoyi-admin.jar

# 后台运行
nohup java -jar ruoyi-admin.jar --spring.profiles.active=druid > ruoyi.log 2>&1 &

# 指定配置文件
java -jar ruoyi-admin.jar --spring.config.location=./application.yml,./application-druid.yml
```

### 1.2 WAR 打包（外部 Tomcat）

**查看&剖析点**

RuoYi 同时支持 WAR 包部署到外部 Tomcat 容器。

**源码关键片段**

文件：`ruoyi-admin/pom.xml`

```xml
<!-- WAR 打包插件 -->
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-war-plugin</artifactId>
    <version>3.1.0</version>
    <configuration>
        <failOnMissingWebXml>false</failOnMissingWebXml>
        <warName>${project.artifactId}</warName>
    </configuration>
</plugin>
```

文件：`ruoyi-admin/src/main/java/com/ruoyi/RuoYiServletInitializer.java`

```java
public class RuoYiServletInitializer extends SpringBootServletInitializer
{
    @Override
    protected SpringApplicationBuilder configure(SpringApplicationBuilder application)
    {
        return application.sources(RuoYiApplication.class);
    }
}
```

**切换为 WAR 打包**

```xml
<!-- 修改 ruoyi-admin/pom.xml -->
<packaging>war</packaging>
```

**部署步骤**

```bash
# 1. 打包
mvn clean package -Dmaven.test.skip=true

# 2. 将 WAR 包复制到 Tomcat webapps 目录
cp ruoyi-admin/target/ruoyi-admin.war /opt/tomcat/webapps/

# 3. 启动 Tomcat
/opt/tomcat/bin/startup.sh
```

### 1.3 前端打包

**查看&剖析点**

前端项目位于 `ruoyi-ui` 目录，使用 Vue.js + Element UI 构建。

**打包命令**

```bash
cd ruoyi-ui

# 安装依赖
npm install

# 构建生产版本
npm run build:prod

# 产物位置：ruoyi-ui/dist/
```

**Nginx 配置示例**

```nginx
server {
    listen       80;
    server_name  localhost;

    location / {
        root   /home/ruoyi/projects/ruoyi-ui/dist;
        try_files $uri $uri/ /index.html;
        index  index.html index.htm;
    }

    # 反向代理后端 API
    location /prod-api/ {
        proxy_pass http://localhost:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## 二、部署流程

### 2.1 环境要求

| 组件 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 17+ | RuoYi 3.9.2 基于 Spring Boot 3.x |
| MySQL | 5.7+ / 8.0+ | 推荐 8.0 |
| Redis | 3.0+ | 推荐 6.0+ |
| Node.js | 12+ | 前端构建 |
| Maven | 3.6+ | 后端构建 |

### 2.2 完整部署步骤

```bash
# 1. 数据库初始化
mysql -u root -p < sql/ry_vue.sql

# 2. 修改后端配置
# 编辑 application-druid.yml（数据库连接）
# 编辑 application.yml（Redis 连接、文件路径）

# 3. 后端打包
mvn clean package -Dmaven.test.skip=true

# 4. 前端打包
cd ruoyi-ui && npm run build:prod

# 5. 启动后端
java -jar ruoyi-admin/target/ruoyi-admin.jar &

# 6. 配置 Nginx（参考上方配置）

# 7. 启动 Nginx
nginx -s reload
```

### 2.3 多环境配置

**源码关键片段**

文件：`ruoyi-admin/src/main/resources/application.yml`

```yaml
spring:
  profiles:
    active: druid
```

**环境切换方式**

```bash
# 开发环境
java -jar ruoyi-admin.jar --spring.profiles.active=druid

# 生产环境（需要创建 application-prod.yml）
java -jar ruoyi-admin.jar --spring.profiles.active=prod
```

**建议的环境配置分离**

```
application.yml          # 公共配置
application-druid.yml    # 数据源配置
application-dev.yml      # 开发环境（本地数据库、Redis）
application-prod.yml     # 生产环境（生产数据库、Redis、安全配置）
```

## 三、环境配置详解

### 3.1 服务器配置

**源码关键片段**

```yaml
server:
  port: 8080
  servlet:
    context-path: /
  tomcat:
    uri-encoding: UTF-8
    accept-count: 1000
    threads:
      max: 800
      min-spare: 100
```

**配置说明**

| 参数 | 值 | 说明 |
|------|-----|------|
| server.port | 8080 | 服务端口 |
| server.tomcat.max-threads | 800 | Tomcat 最大线程数 |
| server.tomcat.min-spare | 100 | 最小空闲线程数 |
| server.tomcat.accept-count | 1000 | 连接队列大小 |

### 3.2 文件上传配置

**源码关键片段**

```yaml
ruoyi:
  profile: D:/ruoyi/uploadPath

spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 20MB
```

**注意事项**

- `ruoyi.profile` 在 Windows 和 Linux 下路径格式不同
- 生产环境建议使用独立的文件存储服务（如 MinIO、OSS）

### 3.3 关键配置项汇总

| 配置项 | 文件 | 说明 |

| 数据库连接 | application-druid.yml | MySQL 地址、用户名、密码 |

| Token 密钥 | application.yml | JWT 签名密钥 |

### 4.3 缓存监控

**源码关键片段**

文件：`ruoyi-admin/src/main/java/com/ruoyi/web/controller/monitor/CacheController.java`

```java
@RestController
@RequestMapping("/monitor/cache")
public class CacheController
{
    @GetMapping()
    public AjaxResult getInfo() throws Exception
    {
        Properties info = (Properties) redisTemplate.execute(
            (RedisCallback<Object>) connection -> connection.info());
        Properties commandStats = (Properties) redisTemplate.execute(
            (RedisCallback<Object>) connection -> connection.info("commandstats"));
        Object dbSize = redisTemplate.execute(
            (RedisCallback<Object>) connection -> connection.dbSize());
        // ...
    }

    @GetMapping("/getNames")
    public AjaxResult cache()
    {
        return AjaxResult.success(caches);
    }

    @GetMapping("/getKeys/{cacheName}")
    public AjaxResult getCacheKeys(@PathVariable String cacheName)
    {
        Set<String> cacheKeys = redisTemplate.keys(cacheName + "*");
        return AjaxResult.success(new TreeSet<>(cacheKeys));
    }

    @DeleteMapping("/clearCacheName/{cacheName}")
    public AjaxResult clearCacheName(@PathVariable String cacheName)
    {
        Collection<String> cacheKeys = redisTemplate.keys(cacheName + "*");
        redisTemplate.delete(cacheKeys);
        return AjaxResult.success();
    }

    @DeleteMapping("/clearCacheAll")
    public AjaxResult clearCacheAll()
    {
        Collection<String> cacheKeys = redisTemplate.keys("*");
        redisTemplate.delete(cacheKeys);
        return AjaxResult.success();
    }
}
```

**监控内容**

- Redis 基本信息（版本、内存使用、连接数、命中率）
- 命令统计（各命令执行次数和耗时）
- 缓存 Key 列表（按缓存类型分类查看）
- 缓存清理（按类型或全部清理）

## 五、日志管理

### 5.1 Logback 配置

**查看&剖析点**

**源码关键片段**

文件：`ruoyi-admin/src/main/resources/logback.xml`

```xml
<!-- 日志存放路径 -->
<property name="log.path" value="/home/ruoyi/logs" />
<!-- 日志输出格式 -->
<property name="log.pattern" value="%d{HH:mm:ss.SSS} [%thread] %-5level %logger{20} - [%method,%line] - %msg%n" />

<!-- 控制台输出 -->
<appender name="console" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
        <pattern>${log.pattern}</pattern>
    </encoder>
</appender>

<!-- 系统日志输出（INFO 级别） -->
<appender name="file_info" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${log.path}/sys-info.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
        <fileNamePattern>${log.path}/sys-info.%d{yyyy-MM-dd}.log</fileNamePattern>
        <maxHistory>60</maxHistory>
    </rollingPolicy>
    <filter class="ch.qos.logback.classic.filter.LevelFilter">
        <level>INFO</level>
        <onMatch>ACCEPT</onMatch>
        <onMismatch>DENY</onMismatch>
    </filter>
</appender>

<!-- 错误日志输出（ERROR 级别） -->
<appender name="file_error" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${log.path}/sys-error.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
        <fileNamePattern>${log.path}/sys-error.%d{yyyy-MM-dd}.log</fileNamePattern>
        <maxHistory>60</maxHistory>
    </rollingPolicy>
    <filter class="ch.qos.logback.classic.filter.LevelFilter">
        <level>ERROR</level>
        <onMatch>ACCEPT</onMatch>
        <onMismatch>DENY</onMismatch>
    </filter>
</appender>

<!-- 用户访问日志 -->
<appender name="sys-user" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${log.path}/sys-user.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
        <fileNamePattern>${log.path}/sys-user.%d{yyyy-MM-dd}.log</fileNamePattern>
        <maxHistory>60</maxHistory>
    </rollingPolicy>
</appender>
```

### 5.2 日志文件说明

| 日志文件 | 级别 | 内容 |
|---------|------|------|
| `sys-info.log` | INFO | 系统运行日志 |
| `sys-error.log` | ERROR | 错误日志 |
| `sys-user.log` | INFO | 用户操作日志（登录、登出等） |
| 控制台 | ALL | 开发调试用 |

### 5.3 日志配置要点

- **按天分割**：使用 `TimeBasedRollingPolicy`，每天生成一个新日志文件
- **保留 60 天**：`maxHistory` 设为 60，超过 60 天的日志自动删除
- **级别分离**：INFO 和 ERROR 分别写入不同文件，便于排查问题
- **日志格式**：包含时间、线程、级别、Logger、方法名、行号、消息

### 5.4 日志级别控制

**源码关键片段**

```xml
<!-- 系统模块日志级别控制 -->
<logger name="com.ruoyi" level="info" />
<!-- Spring日志级别控制 -->
<logger name="org.springframework" level="warn" />
```

```yaml
# application.yml 中的日志级别
logging:
  level:
    com.ruoyi: debug
    org.springframework: warn
```

**注意**：`application.yml` 中的日志级别会覆盖 `logback.xml` 中的配置。开发环境设为 `debug`，生产环境应设为 `info` 或 `warn`。

## 六、优雅停机

### 6.1 ShutdownManager

**查看&剖析点**

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/manager/ShutdownManager.java`

```java
@Component
public class ShutdownManager
{
    private static final Logger logger = LoggerFactory.getLogger("sys-user");

    @PreDestroy
    public void destroy()
    {
        shutdownAsyncManager();
    }

    private void shutdownAsyncManager()
    {
        try
        {
            logger.info("====关闭后台任务任务线程池====");
            AsyncManager.me().shutdown();
        }
        catch (Exception e)
        {
            logger.error(e.getMessage(), e);
        }
    }
}
```

**优雅停机流程**

1. Spring 容器关闭时触发 `@PreDestroy` 回调
2. `ShutdownManager.destroy()` 调用 `AsyncManager.shutdown()`
3. `AsyncManager` 内部调用 `Threads.shutdownAndAwaitTermination(executor)`，等待正在执行的任务完成
4. 线程池关闭后，JVM 可以安全退出

**建议增加的停机配置**

```yaml
server:
  shutdown: graceful

spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s
```

## 七、细节留神

1. **logback.xml 日志路径**：默认配置为 `/home/ruoyi/logs`（Linux 路径），在 Windows 开发环境下需要手动修改或通过启动参数覆盖。

2. **Druid 监控白名单为空**：`allow:` 未配置任何 IP，意味着所有 IP 都可以访问。生产环境必须配置白名单。

3. **CacheController 使用 KEYS 命令**：`redisTemplate.keys(cacheName + "*")` 在大数据量下会阻塞 Redis，生产环境应改用 SCAN。

4. **Nginx 代理路径**：前端请求 `/prod-api/` 会被代理到后端，但后端的 `context-path` 为 `/`，需要确保路径映射正确。

5. **WAR 部署的 classpath 问题**：WAR 部署时，`logback.xml` 的日志路径需要确保应用有写入权限。
