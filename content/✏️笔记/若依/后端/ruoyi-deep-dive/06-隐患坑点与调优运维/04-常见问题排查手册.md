# 04 - 常见问题排查手册

> 本文档系统整理 RuoYi-Vue 项目在开发、测试和生产环境中遇到的常见问题，提供详细的排查步骤和解决方案。

---

## 一、启动失败

### 1.1 端口被占用

**现象**

```
***************************
APPLICATION FAILED TO START
***************************

Web server failed to start. Port 8080 was already in use.
Action: Identify and stop the process that's listening on port 8080 or configure this application to listen on another port.
```

**排查步骤**

```bash
# Linux/Mac
lsof -i :8080
# 或
netstat -tlnp | grep 8080

# Windows
netstat -ano | findstr 8080
taskkill /PID <进程ID> /F
```

**解决方案**

- 方案一：停止占用端口的进程
- 方案二：修改配置文件中的端口

```yaml
server:
  port: 8081
```

### 1.2 数据库连接失败

**现象**

```
Error creating bean with name 'dataSource' defined in class path resource
...
Caused by: com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure
```

**排查步骤**

```bash
# 1. 检查 MySQL 是否启动
systemctl status mysqld

# 2. 检查端口是否可达
telnet localhost 3306

# 3. 检查用户名密码是否正确
mysql -u root -p123456 -h localhost

# 4. 检查数据库是否存在
mysql -u root -p -e "SHOW DATABASES LIKE 'ry-vue';"
```

**源码关键片段**

文件：`ruoyi-admin/src/main/resources/application-druid.yml`

```yaml
spring:
    datasource:
        druid:
            master:
                url: jdbc:mysql://localhost:3306/ry-vue?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
                username: root
                password: 123456
```

**常见原因**

| 原因 | 检查方式 | 解决方案 |
|------|---------|---------|
| MySQL 未启动 | `systemctl status mysqld` | 启动 MySQL |
| 端口不对 | 检查 URL 中的端口号 | 修改为正确端口 |
| 用户名密码错误 | 手动连接测试 | 修改配置 |
| 数据库不存在 | `SHOW DATABASES` | 创建数据库并导入 SQL |
| SSL 证书问题 | URL 中 `useSSL=true` | 改为 `useSSL=false`（开发环境） |
| 时区问题 | `serverTimezone` 参数 | 设置为 `GMT%2B8` 或 `Asia/Shanghai` |

### 1.3 Redis 连接失败

**现象**

```
Error creating bean with name 'redisTemplate' defined in class path resource
...
Caused by: io.lettuce.core.RedisConnectionException: Unable to connect to localhost:6379
```

**排查步骤**

```bash
# 1. 检查 Redis 是否启动
redis-cli ping
# 应返回 PONG

# 2. 检查端口
netstat -tlnp | grep 6379

# 3. 检查 Redis 密码配置
redis-cli -a <password> ping
```

**源码关键片段**

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      database: 0
      password:
      timeout: 10s
```

**解决方案**

- 确保 Redis 服务已启动
- 如果 Redis 设置了密码，在配置中填写 `password` 字段
- 检查防火墙是否阻止了 6379 端口

### 1.4 Bean 创建失败（循环依赖）

**现象**

```
***************************
APPLICATION FAILED TO START
***************************

Description:
The dependencies of some of the beans in the application context form a cycle:

┌─────┐
|  A (field private B b)
↑     ↓
|  B (field private A a)
└─────┘
```

**RuoYi 中的循环依赖处理**

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/manager/factory/AsyncFactory.java`

```java
// 通过 SpringUtils.getBean() 延迟获取，避免循环依赖
SpringUtils.getBean(ISysLogininforService.class).insertLogininfor(logininfor);
```

文件：`ruoyi-common/src/main/java/com/ruoyi/common/utils/spring/SpringUtils.java`

```java
public static <T> T getBean(Class<T> clz) throws BeansException
{
    T result = (T) beanFactory.getBean(clz);
    return result;
}
```

**排查步骤**

1. 查看错误日志中的 Bean 依赖链
2. 检查是否在 `@Autowired` 注入的 Bean 中又注入了对方
3. 参考 RuoYi 的做法，使用 `SpringUtils.getBean()` 延迟获取

## 二、数据库相关问题

### 2.1 SQL 执行异常

**现象**

```
Bad SQL grammar []; nested exception is java.sql.SQLSyntaxErrorException
```

**排查步骤**

1. 查看完整异常堆栈中的 SQL 语句
2. 检查 Mapper XML 中的 SQL 语法
3. 检查参数是否正确传递

**RuoYi 的 SQL 注入防护**

文件：`ruoyi-common/src/main/java/com/ruoyi/common/utils/sql/SqlUtil.java`

```java
public static String escapeOrderBySql(String value)
{
    if (StringUtils.isNotEmpty(value) && !isValidOrderBySql(value))
    {
        throw new UtilException("参数不符合规范，不能进行查询");
    }
    if (StringUtils.length(value) > ORDER_BY_MAX_LENGTH)
    {
        throw new UtilException("参数已超过最大限制，不能进行查询");
    }
    return value;
}
```

**注意**：如果前端传递的 `orderBy` 参数包含特殊字符，会被 `SqlUtil` 拦截并抛出 `UtilException`。

### 2.2 连接池耗尽

**现象**

```
com.alibaba.druid.pool.GetConnectionTimeoutException:
wait millis 60000, active 20, idle 0, waitting 100
```

**排查步骤**

1. 访问 Druid 监控页面查看连接池状态
2. 检查是否有未关闭的数据库连接
3. 检查是否有长事务占用连接

**源码关键片段**

```yaml
druid:
    maxActive: 20
    maxWait: 60000
```

**解决方案**

- 短期：增大 `maxActive` 值
- 长期：排查连接泄漏，优化事务范围

### 2.3 慢 SQL 排查

**查看&剖析点**

RuoYi 配置了 Druid 慢 SQL 记录。

```yaml
filter:
    stat:
        enabled: true
        log-slow-sql: true
        slow-sql-millis: 1000
        merge-sql: true
```

**排查步骤**

1. 查看 Druid 监控页面的 "SQL 监控" 标签
2. 按 "执行时间" 降序排列，找到最慢的 SQL
3. 使用 `EXPLAIN` 分析执行计划
4. 检查是否缺少索引

## 三、Redis 相关问题

### 3.1 Token 失效异常

**现象**

前端提示 "登录状态已过期，请重新登录"，或后端返回 401。

**排查步骤**

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/TokenService.java`

```java
public LoginUser getLoginUser(HttpServletRequest request)
{
    String token = getToken(request);
    if (StringUtils.isNotEmpty(token))
    {
        try
        {
            Claims claims = parseToken(token);
            String uuid = (String) claims.get(Constants.LOGIN_USER_KEY);
            String userKey = getTokenKey(uuid);
            LoginUser user = redisCache.getCacheObject(userKey);
            return user;  // 如果 Redis 中没有，返回 null
        }
        catch (Exception e)
        {
            log.error("获取用户信息异常'{}'", e.getMessage());
        }
    }
    return null;
}
```

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/security/filter/JwtAuthenticationTokenFilter.java`

```java
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
        throws ServletException, IOException
{
    LoginUser loginUser = tokenService.getLoginUser(request);
    if (StringUtils.isNotNull(loginUser) && StringUtils.isNull(SecurityUtils.getAuthentication()))
    {
        tokenService.verifyToken(loginUser);
        // ...
    }
    chain.doFilter(request, response);
}
```

**常见原因**

| 原因 | 排查方式 | 解决方案 |
|------|---------|---------|
| Redis 中 Token 已过期 | `redis-cli GET login_tokens:<uuid>` | 重新登录 |
| Redis 重启导致数据丢失 | 检查 Redis 是否配置了持久化 | 配置 RDB/AOF 持久化 |
| JWT 解析失败 | 检查 Token 格式是否正确 | 检查前端 Token 传递方式 |
| Token 被手动清除 | 检查是否执行了缓存清理 | 重新登录 |

### 3.2 Redis 内存占用过高

**排查步骤**

```bash
# 查看 Redis 内存使用
redis-cli info memory

# 查看各类型 Key 的数量
redis-cli info keyspace

# 查看大 Key
redis-cli --bigkeys
```

**RuoYi 中可能占用大量内存的 Key**

- `login_tokens:*`：每个在线用户一个 Key，`LoginUser` 对象包含完整用户信息和权限列表
- `sys_dict:*`：数据字典缓存
- `sys_config:*`：系统配置缓存

**解决方案**

1. 清理过期的 Token
2. 对大 Value 进行压缩
3. 设置合理的过期时间

### 3.3 验证码获取失败

**现象**

登录时验证码图片不显示，或输入验证码后提示 "验证码错误"。

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/SysLoginService.java`

```java
public void validateCaptcha(String username, String code, String uuid)
{
    boolean captchaEnabled = configService.selectCaptchaEnabled();
    if (captchaEnabled)
    {
        String verifyKey = CacheConstants.CAPTCHA_CODE_KEY + StringUtils.nvl(uuid, "");
        String captcha = redisCache.getCacheObject(verifyKey);
        if (captcha == null)
        {
            throw new CaptchaExpireException();
        }
        redisCache.deleteObject(verifyKey);
        if (!code.equalsIgnoreCase(captcha))
        {
            throw new CaptchaException();
        }
    }
}
```

**常见原因**

- Redis 连接异常，验证码存不进去
- 验证码已过期（通常 2 分钟有效期）
- 前端 UUID 和后端 UUID 不匹配

## 四、权限异常

### 4.1 接口返回 403 Forbidden

**现象**

调用接口返回 403，提示 "请求访问：xxx，认证失败，无法访问系统资源"。

**排查步骤**

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/config/SecurityConfig.java`

```java
.authorizeHttpRequests((requests) -> {
    permitAllUrl.getUrls().forEach(url -> requests.requestMatchers(url).permitAll());
    requests.requestMatchers("/login", "/register", "/captchaImage").permitAll()
        .requestMatchers(HttpMethod.GET, "/", "/*.html", "/**.html", "/**.css", "/**.js", "/profile/**").permitAll()
        .requestMatchers("/swagger-ui.html", "/v3/api-docs/**", "/swagger-ui/**", "/druid/**").permitAll()
        .anyRequest().authenticated();
})
```

**常见原因**

| 原因 | 排查方式 | 解决方案 |
|------|---------|---------|
| 未携带 Token | 检查请求 Header 中的 `Authorization` | 前端确保携带 Token |
| Token 已过期 | 检查 Redis 中的 Token | 重新登录 |
| 接口需要特定权限 | 检查接口的 `@PreAuthorize` 注解 | 分配对应权限 |
| CSRF 问题 | 检查是否被 CSRF 拦截 | RuoYi 已禁用 CSRF |

### 4.2 数据权限过滤异常

**现象**

用户登录后查询列表数据为空，但该用户应该有数据权限。

**排查步骤**

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/DataScopeAspect.java`

```java
LoginUser loginUser = SecurityUtils.getLoginUser();
if (StringUtils.isNotNull(loginUser))
{
    SysUser currentUser = loginUser.getUser();
    if (StringUtils.isNotNull(currentUser) && !currentUser.isAdmin())
    {
        // 非管理员才会进行数据权限过滤
        dataScopeFilter(joinPoint, currentUser, ...);
    }
}
```

**常见原因**

1. 用户的角色数据权限设置不正确
2. 角色状态被禁用（`status = '1'`）
3. `@DataScope` 注解的 `deptAlias` 或 `userAlias` 与 SQL 中的表别名不匹配
4. 用户没有分配部门

### 4.3 @PreAuthorize 权限校验失败

**现象**

返回 403，提示 "您没有数据的xxx权限"。

**源码关键片段**

```java
@PreAuthorize("@ss.hasPermi('system:user:list')")
@GetMapping("/list")
public TableDataInfo list(SysUser user) { ... }
```

**排查步骤**

1. 检查用户的角色是否分配了对应的菜单权限
2. 检查菜单的权限标识（如 `system:user:list`）是否正确
3. 检查 Redis 中缓存的用户权限是否已更新

## 五、文件上传下载问题

### 5.1 文件上传失败

**现象**

上传文件时返回错误 "上传文件大小超过限制"。

**源码关键片段**

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 20MB

ruoyi:
  profile: D:/ruoyi/uploadPath
```

**排查步骤**

1. 检查文件大小是否超过 10MB
2. 检查上传目录是否存在且有写入权限
3. 检查 Nginx 的 `client_max_body_size` 配置

### 5.2 文件下载/预览 404

**现象**

上传的文件无法下载或预览，返回 404。

**排查步骤**

1. 检查文件是否实际存在于 `ruoyi.profile` 配置的目录
2. 检查 Nginx 的静态资源代理配置
3. 检查文件路径中的中文是否被正确编码

## 六、前端相关问题

### 6.1 跨域问题

**现象**

前端请求后端 API 时出现 CORS 错误。

**源码关键片段**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/config/ResourcesConfig.java`（通过 CorsFilter 配置跨域）

**排查步骤**

1. 检查前端 `.env.development` 中的 `VUE_APP_BASE_API` 配置
2. 检查后端跨域配置是否正确
3. 如果使用 Nginx 代理，检查 Nginx 的跨域配置

### 6.2 静态资源 404

**现象**

页面空白或部分样式/JS 加载失败。

**排查步骤**

1. 检查 Nginx 的 `root` 配置是否指向正确的 `dist` 目录
2. 检查 `try_files` 配置是否正确
3. 检查前端路由模式（history 模式需要 Nginx 配合）

## 七、定时任务问题

### 7.1 定时任务不执行

**排查步骤**

1. 检查定时任务的 Cron 表达式是否正确
2. 检查任务状态是否为 "正常"
3. 检查 `ruoyi-quartz` 模块是否被正确引入
4. 查看后台日志是否有异常信息

### 7.2 定时任务执行失败

**排查步骤**

1. 查看调度日志（`sys_job_log` 表）
2. 检查任务目标字符串是否正确（如 `ryTask.ryNoParams`）
3. 检查任务执行方法的参数是否匹配

## 八、细节留神

1. **Spring DevTools 热部署**：`spring-boot-devtools` 在生产环境中应排除，它会增加启动时间并可能导致内存泄漏。

2. **Swagger 生产环境暴露**：`SecurityConfig` 中 `/swagger-ui/**` 和 `/v3/api-docs/**` 被设为 `permitAll()`，生产环境应禁用。

3. **Druid 监控 SQL 注入风险**：`wall` 配置中 `multi-statement-allow: true` 允许多条 SQL，增加了安全风险。

4. **logback.xml 中的日志路径**：默认 `/home/ruoyi/logs` 在 Windows 环境下无效，需要通过启动参数覆盖。

5. **Redis 序列化兼容性**：升级 RuoYi 版本后，如果 `LoginUser` 类结构变更，Redis 中旧的序列化数据可能无法反序列化，导致 Token 失效。

## 九、提问方向

1. **应用启动时报 "Port 8080 was already in use"，除了修改端口和杀进程，还有哪些优雅的处理方式？Spring Boot 是否支持端口自动探测？**

2. **Token 失效后前端如何感知并跳转到登录页？RuoYi 的前端 HTTP 拦截器是如何处理 401 响应的？**

3. **数据权限过滤后查询结果为空，如何快速定位是权限配置问题还是 SQL 拼接问题？有没有调试数据权限 SQL 的方法？**

4. **Redis 重启后所有用户需要重新登录，如何通过 Redis 持久化（RDB/AOF）来避免这个问题？各自的优缺点是什么？**

5. **Druid 监控显示有慢 SQL，但 Mapper XML 中的 SQL 看起来很简单，可能是什么原因导致的？如何进一步排查？**

6. **@PreAuthorize("@ss.hasPermi('system:user:list')") 中的 `@ss` 是什么？它是如何注册为 Spring Bean 的？**

7. **文件上传时 Nginx 报 413 Request Entity Too Large，但 Spring Boot 的 max-file-size 已设为 10MB，问题出在哪里？**

8. **定时任务执行时间超过了下次触发时间（如任务执行需要 5 分钟但每 1 分钟触发一次），RuoYi 是如何处理并发执行的？**
