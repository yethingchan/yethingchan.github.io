# 05 - 生产环境改造建议

> 本文档详细列出 RuoYi-Vue 从开发环境迁移到生产环境需要做的各项改造，涵盖配置安全、日志级别、监控告警、性能调优和高可用方案。

---

## 一、配置安全改造

### 1.1 敏感信息外部化

**查看&剖析点**

当前所有敏感配置都明文写在配置文件中，必须改为环境变量注入。

**源码关键片段（改造前）**

文件：`ruoyi-admin/src/main/resources/application.yml`

```yaml
token:
  secret: abcdefghijklmnopqrstuvwxyz

spring:
  data:
    redis:
      host: localhost
      port: 6379
      password:
```

文件：`ruoyi-admin/src/main/resources/application-druid.yml`

```yaml
spring:
    datasource:
        druid:
            master:
                username: root
                password: 123456
            statViewServlet:
                login-username: ruoyi
                login-password: 123456
```

**改造方案**

```yaml
# application.yml
token:
  secret: ${TOKEN_SECRET}

spring:
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD:}
```

```yaml
# application-druid.yml
spring:
    datasource:
        druid:
            master:
                username: ${DB_USERNAME}
                password: ${DB_PASSWORD}
            statViewServlet:
                login-username: ${DRUID_USERNAME}
                login-password: ${DRUID_PASSWORD}
```

**环境变量注入方式**

```bash
# 方式一：命令行参数
java -jar ruoyi-admin.jar \
  --token.secret=your-strong-secret-key-at-least-32-chars \
  --spring.datasource.druid.master.password=real-password \
  --spring.data.redis.password=redis-password

# 方式二：环境变量
export TOKEN_SECRET=your-strong-secret-key-at-least-32-chars
export DB_PASSWORD=real-password
export REDIS_PASSWORD=redis-password
java -jar ruoyi-admin.jar

# 方式三：使用 Jasypt 加密
# 引入 jasypt-spring-boot-starter，对敏感配置进行加密
```

### 1.2 JWT 密钥强化

**当前问题**

```yaml
token:
  secret: abcdefghijklmnopqrstuvwxyz  # 连续字母，极易猜测
```

**改造建议**

```bash
# 生成强密钥（至少 64 字符）
openssl rand -base64 64

# 示例密钥
# aB3dE5fG7hJ9kL1mN3oP5qR7sT9uV1wX3yZ5aB7cD9eF1gH3iJ5kL7mN9oP1qR3sT5uV7wX9yZ
```

```yaml
token:
  secret: ${TOKEN_SECRET:aB3dE5fG7hJ9kL1mN3oP5qR7sT9uV1wX3yZ5aB7cD9eF1gH3iJ5kL7mN9oP1qR3sT5uV7wX9yZ}
  expireTime: 30
```

### 1.3 数据库安全加固

**当前问题**

```yaml
master:
    username: root
    password: 123456
```

**改造建议**

1. 创建专用数据库用户，只授予必要权限
2. 使用强密码
3. 限制远程访问

```sql
-- 创建专用用户
CREATE USER 'ruoyi_app'@'%' IDENTIFIED BY 'Str0ng!P@ssw0rd';
GRANT SELECT, INSERT, UPDATE, DELETE ON `ry-vue`.* TO 'ruoyi_app'@'%';
FLUSH PRIVILEGES;
```

### 1.4 Redis 安全加固

**当前问题**

```yaml
redis:
  password:    # 空密码
```

**改造建议**

```bash
# redis.conf 中设置密码
requirepass Str0ng!R3disP@ss

# 防火墙限制访问
iptables -A INPUT -p tcp --dport 6379 -s 10.0.0.0/8 -j ACCEPT
iptables -A INPUT -p tcp --dport 6379 -j DROP
```

### 1.5 Druid 监控安全加固

**当前问题**

```yaml
statViewServlet:
    enabled: true
    allow:       # 白名单为空，所有 IP 可访问
    login-username: ruoyi
    login-password: 123456
```

**改造建议**

```yaml
statViewServlet:
    enabled: true
    allow: 192.168.1.0/24    # 只允许内网访问
    deny:                     # 黑名单
    url-pattern: /druid/*
    login-username: ${DRUID_USERNAME}
    login-password: ${DRUID_PASSWORD}
```

同时修改 `SecurityConfig`，移除 Druid 路径的 `permitAll`：

```java
// 改造前
.requestMatchers("/swagger-ui.html", "/v3/api-docs/**", "/swagger-ui/**", "/druid/**").permitAll()

// 改造后（生产环境移除 /druid/** 的公开访问）
.requestMatchers("/swagger-ui.html", "/v3/api-docs/**", "/swagger-ui/**").denyAll()
// Druid 通过自身认证保护，但不再在 Spring Security 中放行
```

## 二、日志级别调整

### 2.1 生产环境日志配置

**查看&剖析点**

**源码关键片段（改造前）**

文件：`ruoyi-admin/src/main/resources/application.yml`

```yaml
logging:
  level:
    com.ruoyi: debug    # 开发环境使用 debug
    org.springframework: warn
```

文件：`ruoyi-admin/src/main/resources/logback.xml`

```xml
<logger name="com.ruoyi" level="info" />
```

**改造方案**

```yaml
# application-prod.yml
logging:
  level:
    com.ruoyi: info
    org.springframework: warn
    com.alibaba.druid: warn
    io.lettuce: warn
```

```xml
<!-- logback-spring.xml（推荐使用 logback-spring.xml 支持多环境） -->
<springProfile name="prod">
    <logger name="com.ruoyi" level="info"/>
    <logger name="org.springframework" level="warn"/>
    <root level="info">
        <appender-ref ref="file_info"/>
        <appender-ref ref="file_error"/>
    </root>
    <!-- 生产环境不输出到控制台 -->
</springProfile>
```

### 2.2 日志格式优化

**改造建议**

```xml
<!-- 生产环境日志格式增加 traceId，便于链路追踪 -->
<property name="log.pattern"
    value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] [%X{traceId}] %-5level %logger{50} - [%method,%line] - %msg%n"/>
```

### 2.3 日志文件管理

**改造建议**

```xml
<!-- 增加文件大小限制，防止单个日志文件过大 -->
<appender name="file_info" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${log.path}/sys-info.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
        <fileNamePattern>${log.path}/sys-info.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
        <maxFileSize>100MB</maxFileSize>
        <maxHistory>30</maxHistory>
        <totalSizeCap>10GB</totalSizeCap>
    </rollingPolicy>
</appender>
```

### 3.2 自定义监控指标

**改造建议**

```java
@Component
public class RuoYiMetrics
{
    private final Counter loginSuccessCounter;
    private final Counter loginFailCounter;
    private final Gauge onlineUserGauge;

    public RuoYiMetrics(MeterRegistry registry)
    {
        this.loginSuccessCounter = Counter.builder("ruoyi.login.success")
            .description("Login success count").register(registry);
        this.loginFailCounter = Counter.builder("ruoyi.login.fail")
            .description("Login fail count").register(registry);
        this.onlineUserGauge = Gauge.builder("ruoyi.online.users", this::getOnlineUserCount)
            .description("Online user count").register(registry);
    }
}
```

### 3.3 告警规则建议

| 监控项 | 阈值 | 告警级别 | 处理方式 |
|--------|------|---------|---------|
| CPU 使用率 | > 80% | Warning | 检查是否有死循环或 GC 频繁 |
| 内存使用率 | > 85% | Warning | 检查内存泄漏 |
| JVM Heap | > 90% | Critical | 触发 HeapDump |
| 数据库连接池 | 活跃连接 > maxActive 的 80% | Warning | 检查慢 SQL |
| Redis 连接 | 连接失败 | Critical | 检查 Redis 服务 |
| 接口响应时间 | P99 > 3s | Warning | 检查慢接口 |
| 错误率 | > 1% | Warning | 检查错误日志 |
| 磁盘使用率 | > 90% | Warning | 清理日志或扩容 |

## 四、性能调优

### 4.1 JVM 参数优化

**源码关键片段（当前状态）**

RuoYi 项目没有自定义 JVM 参数，使用 Spring Boot 默认配置。

**改造建议**

```bash
# 4C8G 服务器推荐配置
java -Xms2g -Xmx2g \
     -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m \
     -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -XX:+HeapDumpOnOutOfMemoryError \
     -XX:HeapDumpPath=/home/ruoyi/logs/heapdump.hprof \
     -XX:+PrintGCDetails \
     -XX:+PrintGCDateStamps \
     -Xlog:gc*:file=/home/ruoyi/logs/gc.log:time,tags:filecount=5,filesize=50m \
     -Djava.awt.headless=true \
     -Dfile.encoding=UTF-8 \
     -jar ruoyi-admin.jar --spring.profiles.active=prod
```

### 4.2 数据库连接池优化

**源码关键片段（改造前）**

```yaml
druid:
    initialSize: 5
    minIdle: 10
    maxActive: 20
    maxWait: 60000
```

**改造建议**

```yaml
druid:
    initialSize: 10
    minIdle: 20
    maxActive: 100
    maxWait: 5000
    timeBetweenEvictionRunsMillis: 30000
    minEvictableIdleTimeMillis: 180000
    maxEvictableIdleTimeMillis: 600000
    # 生产环境开启连接泄漏检测
    removeAbandoned: true
    removeAbandonedTimeout: 1800
    logAbandoned: true
```

### 4.3 Tomcat 线程优化

**源码关键片段（改造前）**

```yaml
server:
  tomcat:
    threads:
      max: 800
      min-spare: 100
    accept-count: 1000
```

**改造建议**

```yaml
server:
  tomcat:
    threads:
      max: 200          # 降低最大线程数，减少上下文切换开销
      min-spare: 20     # 降低最小空闲线程
    accept-count: 500   # 降低排队数
    max-connections: 1000
    connection-timeout: 10000
```

### 4.4 Redis 连接池优化

**源码关键片段（改造前）**


### 4.5 线程池优化

**源码关键片段（改造前）**

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/config/ThreadPoolConfig.java`

```java
private int corePoolSize = 50;
private int maxPoolSize = 200;
private int queueCapacity = 1000;
```

**改造建议**

```java
@Configuration
public class ThreadPoolConfig
{
    // 根据服务器 CPU 核数动态设置
    private int corePoolSize = Runtime.getRuntime().availableProcessors() * 2;
    private int maxPoolSize = corePoolSize * 4;
    private int queueCapacity = 500;
    private int keepAliveSeconds = 60;

    @Bean(name = "threadPoolTaskExecutor")
    public ThreadPoolTaskExecutor threadPoolTaskExecutor()
    {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(corePoolSize);
        executor.setMaxPoolSize(maxPoolSize);
        executor.setQueueCapacity(queueCapacity);
        executor.setKeepAliveSeconds(keepAliveSeconds);
        executor.setThreadNamePrefix("async-pool-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        // 允许核心线程超时回收
        executor.setAllowCoreThreadTimeOut(true);
        return executor;
    }
}
```

## 五、高可用方案

### 5.1 应用层高可用

**改造建议**

```bash
# 多实例部署 + Nginx 负载均衡
# 实例1
java -jar ruoyi-admin.jar --server.port=8080 &
# 实例2
java -jar ruoyi-admin.jar --server.port=8081 &
```

```nginx
upstream ruoyi_backend {
    server 127.0.0.1:8080 weight=1;
    server 127.0.0.1:8081 weight=1;
    # 健康检查
    # keepalive 32;
}

server {
    listen 80;
    location / {
        proxy_pass http://ruoyi_backend;
    }
}
```

**注意事项**

- 多实例部署时，文件上传路径需要共享（NFS 或对象存储）
- Spring Session 或 Redis Session 需要配置（RuoYi 使用 Redis 存储 Token，天然支持多实例）

### 5.2 数据库高可用

**改造建议**

```yaml
# 主从读写分离
spring:
    datasource:
        druid:
            master:
                url: jdbc:mysql://master-db:3306/ry-vue
                username: ruoyi_app
                password: ${DB_PASSWORD}
            slave:
                enabled: true
                url: jdbc:mysql://slave-db:3306/ry-vue
                username: ruoyi_readonly
                password: ${DB_READONLY_PASSWORD}
```

**源码关键片段**

RuoYi 已内置了多数据源支持：

文件：`ruoyi-framework/src/main/java/com/ruoyi/framework/config/DruidConfig.java`

```java
@Bean(name = "dynamicDataSource")
@Primary
public DynamicDataSource dataSource(DataSource masterDataSource)
{
    Map<Object, Object> targetDataSources = new HashMap<>();
    targetDataSources.put(DataSourceType.MASTER.name(), masterDataSource);
    setDataSource(targetDataSources, DataSourceType.SLAVE.name(), "slaveDataSource");
    return new DynamicDataSource(masterDataSource, targetDataSources);
}
```

通过 `@DataSource(DataSourceType.SLAVE)` 注解切换到从库。

## 六、安全加固清单

### 6.1 接口安全

**改造建议**

1. **移除 Swagger 生产环境访问**

```java
// SecurityConfig.java
@Profile("!prod")  // 只在非生产环境启用
@Bean
public SecurityFilterChain filterChain(HttpSecurity httpSecurity) throws Exception
{
    // ...
    .requestMatchers("/swagger-ui.html", "/v3/api-docs/**", "/swagger-ui/**").permitAll()
    // ...
}
```

2. **启用 HTTPS**

```yaml
server:
  ssl:
    enabled: true
    key-store: classpath:keystore.p12
    key-store-password: ${SSL_PASSWORD}
    key-store-type: PKCS12
```

3. **添加安全响应头**

```java
.headers(headers -> headers
    .contentSecurityPolicy(csp -> csp.policyDirectives("default-src 'self'"))
    .frameOptions(fo -> fo.sameOrigin())
    .xssProtection(xss -> xss.headerValue(XXssProtectionHeaderWriter.HeaderValue.ENABLED_MODE_BLOCK))
    .httpStrictTransportSecurity(hsts -> hsts.includeSubDomains(true).maxAgeInSeconds(31536000))
)
```

### 6.2 XSS 防护增强

**源码关键片段（改造前）**

```yaml
xss:
  enabled: true
  excludes: /system/notice
  urlPatterns: /system/*,/monitor/*,/tool/*
```

**改造建议**

```yaml
xss:
  enabled: true
  excludes:                    # 最小化排除列表
  urlPatterns: /*              # 所有路径都启用 XSS 过滤
```

```java
// XssFilter.java 改造
// 移除 GET 和 DELETE 请求的跳过逻辑
private boolean handleExcludeURL(HttpServletRequest request, HttpServletResponse response)
{
    String url = request.getServletPath();
    // 不再跳过 GET 请求
    return StringUtils.matches(url, excludes);
}
```

### 6.3 防盗链加固

**源码关键片段（改造前）**

```yaml
referer:
  enabled: false    # 未启用
  allowed-domains: localhost,127.0.0.1,ruoyi.vip,www.ruoyi.vip
```

**改造建议**

```yaml
referer:
  enabled: true
```

## 八、细节留神

1. **配置文件不要提交到 Git**：生产环境的配置文件（包含密码、密钥等）不应提交到版本控制。使用 `.gitignore` 排除或使用配置中心。

2. **Spring DevTools 必须排除**：`spring-boot-devtools` 在生产环境中会增加安全风险和性能开销。

3. **热部署关闭**：生产环境必须关闭 `spring.devtools.restart.enabled`。

4. **日志路径权限**：确保应用对日志目录有写入权限，且日志目录不在系统关键目录下。

5. **文件上传路径共享**：多实例部署时，文件上传路径需要使用共享存储（如 NFS、MinIO），否则文件只在一个实例上可见。

## 九、提问方向

1. **RuoYi 将敏感配置从配置文件迁移到环境变量后，如何管理多环境（开发/测试/生产）的配置差异？是否需要引入配置中心（如 Nacos、Apollo）？**

2. **JWT 密钥更换后，所有已发放的 Token 都会失效，如何实现密钥的无缝轮换（新旧密钥共存过渡期）？**

3. **RuoYi 的 Token 存储在 Redis 中，如果 Redis 主从切换或集群故障，如何保证用户会话不丢失？**

4. **多实例部署时，AsyncManager 的异步任务（如日志记录）如何保证不重复执行？是否需要分布式任务调度？**

5. **Druid 连接池的 `removeAbandoned` 功能开启后，如何区分真正的连接泄漏和长时间运行的事务？误杀正常连接会有什么后果？**

6. **生产环境禁用了 Swagger，但开发团队仍需要 API 文档，如何在保证安全的前提下提供 API 文档服务？**

7. **Docker 化部署后，JVM 的内存参数应该如何设置？容器的内存限制和 JVM 的 -Xmx 参数之间有什么关系？**

8. **RuoYi 的 @RateLimiter 注解使用 Redis 实现限流，如果 Redis 不可用，限流功能会怎样？如何实现限流的降级方案？**
