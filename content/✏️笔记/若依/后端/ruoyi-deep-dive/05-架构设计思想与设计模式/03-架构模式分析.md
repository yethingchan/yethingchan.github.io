# 03 - 架构模式分析

> 本文档深入分析 RuoYi-Vue 项目的四大架构模式：MVC 分层架构、RBAC 权限模型、前后端分离架构、多模块 Maven 架构。

---

## 一、MVC 传统分层架构

### 1.1 架构概览

RuoYi-Vue 采用经典的 **Controller -> Service -> Mapper** 三层架构，每一层都有明确的职责边界和调用规范。

```
┌─────────────────────────────────────────────────────────┐
│                     Controller 层                         │
│  接收请求、参数校验、权限校验、调用Service、返回响应       │
│  继承 BaseController，使用 @Log/@DataScope 等注解        │
├─────────────────────────────────────────────────────────┤
│                      Service 层                          │
│  业务逻辑处理、事务管理、数据组装、权限判断                │
│  接口(ISysXxxService) + 实现类(SysXxxServiceImpl)        │
├─────────────────────────────────────────────────────────┤
│                      Mapper 层                           │
│  数据访问、SQL编写、结果映射                              │
│  接口(XxxMapper) + XML(XxxMapper.xml)                    │
└─────────────────────────────────────────────────────────┘
```

### 1.2 查看&剖析点

| 层级 | 目录位置 | 关键文件 |
|------|----------|----------|
| Controller | `ruoyi-admin/src/main/java/com/ruoyi/web/controller/` | `SysUserController.java` |
| Service接口 | `ruoyi-system/src/main/java/com/ruoyi/system/service/` | `ISysUserService.java` |
| Service实现 | `ruoyi-system/src/main/java/com/ruoyi/system/service/impl/` | `SysUserServiceImpl.java` |
| Mapper接口 | `ruoyi-system/src/main/java/com/ruoyi/system/mapper/` | `SysUserMapper.java` |
| Mapper XML | `ruoyi-system/src/main/resources/mapper/system/` | `SysUserMapper.xml` |
| Domain | `ruoyi-common/src/main/java/com/ruoyi/common/core/domain/` | `BaseEntity.java` |

### 1.3 源码关键片段引用

**Controller 层 -- 请求入口：**

```java
// 典型 Controller 写法（SysUserController 示例）
@RestController
@RequestMapping("/system/user")
public class SysUserController extends BaseController
{
    @Autowired
    private ISysUserService userService;

    @PreAuthorize("@ss.hasPermi('system:user:list')")
    @GetMapping("/list")
    public TableDataInfo list(SysUser user)
    {
        startPage();  // 开启分页
        List<SysUser> list = userService.selectUserList(user);  // 调用Service
        return getDataTable(list);  // 封装分页响应
    }

    @PreAuthorize("@ss.hasPermi('system:user:add')")
    @Log(title = "用户管理", businessType = BusinessType.INSERT)
    @PostMapping
    public AjaxResult add(@Validated @RequestBody SysUser user)
    {
        if (!userService.checkUserNameUnique(user)) {
            return error("新增用户'" + user.getUserName() + "'失败，登录账号已存在");
        }
        user.setCreateBy(getUsername());
        user.setPassword(SecurityUtils.encryptPassword(user.getPassword()));
        return toAjax(userService.insertUser(user));
    }
}
```

**Mapper 层 -- 数据访问：**

```xml
<!-- 文件：ruoyi-system/src/main/resources/mapper/system/SysUserMapper.xml -->
<mapper namespace="com.ruoyi.system.mapper.SysUserMapper">
    <select id="selectUserList" parameterType="SysUser" resultMap="SysUserResult">
        select u.user_id, u.dept_id, u.user_name, u.nick_name, u.email, u.phonenumber,
               u.status, u.create_time
        from sys_user u
        left join sys_dept d on u.dept_id = d.dept_id
        where u.del_flag = '0'
        <!-- 数据权限SQL由 DataScopeAspect 动态注入 -->
        ${params.dataScope}
    </select>
</mapper>
```

### 1.4 分层调用链路

以"查询用户列表"为例的完整调用链路：

```
HTTP GET /system/user/list
    |
    v
[Servlet Filter Chain]
    XssFilter -> RepeatableFilter -> CorsFilter -> JwtAuthenticationTokenFilter -> RefererFilter
    |
    v
[Spring Security Filter Chain]
    CorsFilter -> JwtAuthenticationTokenFilter -> LogoutFilter -> UsernamePasswordAuthenticationFilter
    |
    v
[HandlerInterceptor]
    RepeatSubmitInterceptor.preHandle()
    |
    v
[AOP Aspect - Before]
    DataScopeAspect.doBefore()  -- 拼接数据权限SQL
    |
    v
SysUserController.list()
    -> startPage()  -- PageHelper 设置分页参数
    -> userService.selectUserList(user)  -- 调用Service接口
        -> SysUserServiceImpl.selectUserList(user)
            -> SysUserMapper.selectUserList(user)  -- MyBatis执行SQL
    -> getDataTable(list)  -- 封装分页结果
    |
    v
[AOP Aspect - AfterReturning]
    LogAspect.doAfterReturning()  -- 异步记录操作日志
    |
    v
HTTP Response: TableDataInfo JSON
```

## 二、RBAC 权限模型

### 2.1 模型设计

RuoYi-Vue 实现了完整的 **RBAC（Role-Based Access Control）** 权限模型，包含两个维度：

**功能权限（菜单权限）**：
```
用户(User) --N:N--> 角色(Role) --N:N--> 菜单(Menu/权限)
```

**数据权限（部门权限）**：
```
用户(User) --1:N--> 部门(Department)
角色(Role) --数据范围--> 部门数据可见性
```

### 2.2 查看&剖析点

| 数据库表 | 对应实体 | 说明 |
|----------|----------|------|
| `sys_user` | `SysUser` | 用户表 |
| `sys_role` | `SysRole` | 角色表 |
| `sys_menu` | `SysMenu` | 菜单/权限表 |
| `sys_dept` | `SysDept` | 部门表 |
| `sys_user_role` | `SysUserRole` | 用户-角色关联表 |
| `sys_role_menu` | `SysRoleMenu` | 角色-菜单关联表 |
| `sys_role_dept` | `SysRoleDept` | 角色-部门关联表（自定义数据权限用） |

### 2.3 功能权限实现

**权限标识设计**：每个菜单对应一个权限标识（如 `system:user:list`、`system:user:add`）。

```java
// Controller 中使用 @PreAuthorize 注解进行权限校验
@PreAuthorize("@ss.hasPermi('system:user:list')")   // 查询权限
@GetMapping("/list")
public TableDataInfo list(SysUser user) { ... }

@PreAuthorize("@ss.hasPermi('system:user:add')")    // 新增权限
@Log(title = "用户管理", businessType = BusinessType.INSERT)
@PostMapping
public AjaxResult add(@Validated @RequestBody SysUser user) { ... }

@PreAuthorize("@ss.hasPermi('system:user:remove')")  // 删除权限
@Log(title = "用户管理", businessType = BusinessType.DELETE)
@DeleteMapping("/{userIds}")
public AjaxResult remove(@PathVariable Long[] userIds) { ... }
```

**权限加载流程**：

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/core/domain/model/LoginUser.java
// LoginUser 中持有权限集合
private Set<String> permissions;

@Override
public Collection<? extends GrantedAuthority> getAuthorities()
{
    if (permissions == null || permissions.isEmpty()) {
        return Collections.emptyList();
    }
    return permissions.stream()
        .filter(Objects::nonNull)
        .map(SimpleGrantedAuthority::new)
        .collect(Collectors.toList());
}
```

### 2.4 数据权限实现

**五种数据权限范围**：

| 权限范围 | 常量 | SQL 效果 |
|----------|------|----------|
| 全部数据权限 | `DATA_SCOPE_ALL` | 不追加任何条件 |
| 自定义数据权限 | `DATA_SCOPE_CUSTOM` | 通过 `sys_role_dept` 表关联查询 |
| 本部门数据权限 | `DATA_SCOPE_DEPT` | `dept_id = 当前用户部门ID` |
| 本部门及以下数据权限 | `DATA_SCOPE_DEPT_AND_CHILD` | `dept_id IN (当前部门及所有子部门)` |
| 仅本人数据权限 | `DATA_SCOPE_SELF` | `user_id = 当前用户ID` |

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/DataScopeAspect.java
// 数据权限通过 @DataScope 注解 + AOP 切面实现
@DataScope(deptAlias = "d", userAlias = "u")
public List<SysUser> selectUserList(SysUser user) {
    return userMapper.selectUserList(user);
}
```

**SQL 注入机制**：

```java
// DataScopeAspect 将拼接好的SQL片段放入 BaseEntity.params
baseEntity.getParams().put(DATA_SCOPE, " AND (" + sqlString.substring(4) + ")");

// Mapper XML 中通过 ${params.dataScope} 引用
// ${} 是 MyBatis 的字符串替换，直接将SQL片段嵌入
<select id="selectUserList" parameterType="SysUser" resultMap="SysUserResult">
    select ... from sys_user u left join sys_dept d on u.dept_id = d.dept_id
    where u.del_flag = '0'
    ${params.dataScope}
</select>
```

### 2.5 安全防护

```java
// DataScopeAspect 在拼接SQL前先清空，防止SQL注入
private void clearDataScope(final JoinPoint joinPoint)
{
    Object params = joinPoint.getArgs()[0];
    if (StringUtils.isNotNull(params) && params instanceof BaseEntity)
    {
        BaseEntity baseEntity = (BaseEntity) params;
        baseEntity.getParams().put(DATA_SCOPE, "");  // 清空防止注入
    }
}
```

## 三、前后端分离架构

### 3.1 架构概览

```
┌──────────────┐     HTTP/RESTful API     ┌──────────────┐
│   Vue 前端    │ <======================> │  Spring Boot  │
│  ruoyi-ui    │      JSON + JWT Token    │   后端        │
│  Element Plus │                          │  ruoyi-admin  │
└──────────────┘                          └──────────────┘
```

### 3.2 JWT Token 认证流程

```
1. 用户提交登录表单（username + password + captcha）
    |
2. 后端验证验证码 -> 验证用户名密码 -> 创建 JWT Token
    |
3. Token 返回前端，前端存储到 localStorage
    |
4. 后续请求前端在 Header 中携带 Token：Authorization: Bearer <token>
    |
5. JwtAuthenticationTokenFilter 拦截请求，解析Token，获取LoginUser
    |
6. 将 LoginUser 设置到 SecurityContextHolder
    |
7. Spring Security 进行权限校验 -> 执行业务逻辑
```

### 3.3 查看&剖析点

| 组件 | 文件位置 | 职责 |
|------|----------|------|
| TokenService | `ruoyi-framework/.../web/service/TokenService.java` | Token创建/解析/刷新/删除 |
| JwtAuthenticationTokenFilter | `ruoyi-framework/.../security/filter/JwtAuthenticationTokenFilter.java` | Token验证过滤器 |
| SecurityConfig | `ruoyi-framework/.../config/SecurityConfig.java` | 安全配置 |
| LoginUser | `ruoyi-common/.../core/domain/model/LoginUser.java` | 登录用户信息 |

### 3.4 源码关键片段引用

**Token 创建与存储**：

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/TokenService.java
public String createToken(LoginUser loginUser)
{
    String token = IdUtils.fastUUID();  // 生成唯一标识
    loginUser.setToken(token);
    setUserAgent(loginUser);            // 设置用户代理信息
    refreshToken(loginUser);            // 刷新Token有效期

    Map<String, Object> claims = new HashMap<>();
    claims.put(Constants.LOGIN_USER_KEY, token);     // 将UUID放入JWT
    claims.put(Constants.JWT_USERNAME, loginUser.getUsername());
    return createToken(claims);  // 生成JWT字符串
}

public void refreshToken(LoginUser loginUser)
{
    loginUser.setLoginTime(System.currentTimeMillis());
    loginUser.setExpireTime(loginUser.getLoginTime() + expireTime * MILLIS_MINUTE);
    // 将LoginUser缓存到Redis，key为 login_tokens:{uuid}
    String userKey = getTokenKey(loginUser.getToken());
    redisCache.setCacheObject(userKey, loginUser, expireTime, TimeUnit.MINUTES);
}
```

**Token 验证过滤器**：

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/security/filter/JwtAuthenticationTokenFilter.java
@Override
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
        throws ServletException, IOException
{
    LoginUser loginUser = tokenService.getLoginUser(request);
    if (StringUtils.isNotNull(loginUser) && StringUtils.isNull(SecurityUtils.getAuthentication()))
    {
        tokenService.verifyToken(loginUser);  // 验证Token有效期，不足20分钟自动刷新
        UsernamePasswordAuthenticationToken authenticationToken =
            new UsernamePasswordAuthenticationToken(loginUser, null, loginUser.getAuthorities());
        authenticationToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
        SecurityContextHolder.getContext().setAuthentication(authenticationToken);
    }
    chain.doFilter(request, response);
}
```

**安全配置 -- 无状态会话**：

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/SecurityConfig.java
.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
// 基于Token，不使用Session，实现真正的无状态认证
```


## 细节留神

1. **MVC分层中**，`BaseEntity.params` 是数据权限SQL传递的桥梁，使用 `${params.dataScope}` 进行字符串替换而非 `#{}` 参数绑定。这是因为数据权限SQL是动态拼接的条件片段，不是参数值。但这也带来了SQL注入的风险，因此 `DataScopeAspect.clearDataScope()` 方法在拼接前先清空了该字段。
2. **RBAC模型中**，一个用户可以拥有多个角色，多个角色的数据权限取并集。`DataScopeAspect` 中通过 `conditions.contains(dataScope)` 避免重复处理同一权限范围。
3. **JWT认证中**，JWT Token 本身只存储了 UUID 和用户名，真正的用户信息存储在 Redis 中。这种设计使得Token可以随时通过删除Redis中的缓存来失效（如强制下线）。
4. **多模块架构中**，`ruoyi-framework` 依赖 `ruoyi-system` 是一个值得注意的设计。通常框架层不应该依赖业务层，但这里是因为AOP切面需要操作 `SysUser`、`SysRole` 等业务实体。如果项目规模扩大，可以考虑将公共实体提取到 common 模块中。
5. **前后端分离中**，`SessionCreationPolicy.STATELESS` 确保了服务端不创建Session，所有状态通过Token和Redis维护。这对于水平扩展非常友好。

## 提问方向

1. **MVC分层**：RuoYi-Vue 的 Controller 层直接继承了 `BaseController`，这种继承方式在复杂的业务场景中可能导致基类过于臃肿。如果不用继承，有什么替代方案？
2. **RBAC权限**：当前的数据权限模型只支持到部门级别，如果需要支持"按项目组"、"按区域"等更灵活的数据权限，应该如何扩展数据权限模型？
3. **前后端分离**：JWT Token 存储在 Redis 中，如果 Redis 发生故障重启，所有用户都需要重新登录。如何设计高可用的Token存储方案？
4. **多模块架构**：`ruoyi-framework` 依赖 `ruoyi-system` 是否合理？如果要将框架层和业务层彻底解耦，应该如何重构模块依赖关系？
5. **综合架构**：如果要在 RuoYi-Vue 中引入消息队列（如 RabbitMQ）实现异步操作日志记录，应该放在哪个模块？如何设计才能保持架构的清晰性？
6. **RBAC扩展**：当前的权限模型中，角色是直接分配给用户的。如果需要支持"角色继承"（如"超级管理员"自动拥有"管理员"的所有权限），应该如何改造？
7. **前后端分离**：前端 Vue 项目中 `ruoyi-ui/src/api/` 目录下的 API 文件是如何与后端 Controller 对应的？这种约定式的前后端协作有什么优劣？
