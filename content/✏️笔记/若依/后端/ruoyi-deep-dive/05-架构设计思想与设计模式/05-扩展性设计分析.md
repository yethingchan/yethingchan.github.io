# 05 - 扩展性设计分析

> 本文档分析 RuoYi-Vue 项目的扩展性设计，包括如何新增功能模块、如何新增自定义注解+AOP切面、如何新增数据源、以及代码生成器的扩展设计。

---

## 一、新增功能模块

### 1.1 标准流程

在 RuoYi-Vue 中新增一个完整的业务模块（如"商品管理"），需要按照以下步骤操作：

```
Step 1: 创建数据库表
Step 2: 使用代码生成器生成基础代码（或手动创建）
Step 3: 创建 Domain 实体类
Step 4: 创建 Mapper 接口 + XML
Step 5: 创建 Service 接口 + 实现类
Step 6: 创建 Controller 类
Step 7: 配置菜单和权限
```

### 1.2 查看&剖析点

| 步骤 | 参考文件 | 模块位置 |
|------|----------|----------|
| Domain | `ruoyi-common/.../core/domain/BaseEntity.java` | 继承基类 |
| Mapper | `ruoyi-system/.../mapper/SysUserMapper.java` | 接口定义 |
| Mapper XML | `ruoyi-system/.../resources/mapper/system/SysUserMapper.xml` | SQL编写 |
| Service | `ruoyi-system/.../service/ISysUserService.java` | 接口定义 |
| ServiceImpl | `ruoyi-system/.../service/impl/SysUserServiceImpl.java` | 业务实现 |
| Controller | `ruoyi-admin/.../controller/system/SysUserController.java` | 请求处理 |

### 1.3 源码关键片段引用

**Step 1: Domain 实体类 -- 继承 BaseEntity**

```java
// 新建实体类示例（参考 SysUser 的设计模式）
public class Goods extends BaseEntity
{
    private static final long serialVersionUID = 1L;

    private Long goodsId;       // 商品ID
    private String goodsName;   // 商品名称
    private BigDecimal price;   // 价格
    private Integer stock;      // 库存
    private Integer status;     // 状态

```

**Step 2: Mapper 接口**

```java
// 参考：ruoyi-system/src/main/java/com/ruoyi/system/mapper/SysUserMapper.java
public interface GoodsMapper

    public List<Goods> selectGoodsList(Goods goods);
```

**Step 3: Mapper XML**

```xml
<!-- 参考：ruoyi-system/src/main/resources/mapper/system/SysUserMapper.xml -->
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.ruoyi.goods.mapper.GoodsMapper">
    <resultMap type="Goods" id="GoodsResult">
        <result property="goodsId"    column="goods_id"    />
        <result property="goodsName"  column="goods_name"  />
        <result property="price"      column="price"        />
        <result property="stock"      column="stock"        />
        <result property="status"     column="status"       />
        <result property="createBy"   column="create_by"   />
        <result property="createTime" column="create_time"  />
    </resultMap>

    <sql id="selectGoodsVo">
        select goods_id, goods_name, price, stock, status, create_by, create_time
        from goods
    </sql>

    <select id="selectGoodsList" parameterType="Goods" resultMap="GoodsResult">
        <include refid="selectGoodsVo"/>
        <where>
            <if test="goodsName != null and goodsName != ''"> AND goods_name like concat('%', #{goodsName}, '%') </if>
            <if test="status != null and status != ''"> AND status = #{status} </if>
        </where>
    </select>
</mapper>
```

**Step 4: Service 接口 + 实现类**

```java
// 接口
public interface IGoodsService
{
    public List<Goods> selectGoodsList(Goods goods);
    public Goods selectGoodsById(Long goodsId);
    public int insertGoods(Goods goods);
    public int updateGoods(Goods goods);
    public int deleteGoodsByIds(Long[] goodsIds);
}

// 实现类
@Service
public class GoodsServiceImpl implements IGoodsService
{
    @Autowired
    private GoodsMapper goodsMapper;

    @Override
    public List<Goods> selectGoodsList(Goods goods) {
        return goodsMapper.selectGoodsList(goods);
    }
    // ...
}
```

**Step 5: Controller 类**

```java
// 参考：ruoyi-admin/.../controller/system/SysUserController.java
@RestController
@RequestMapping("/goods/goods")
public class GoodsController extends BaseController
{
    @Autowired
    private IGoodsService goodsService;

    @PreAuthorize("@ss.hasPermi('goods:goods:list')")
    @GetMapping("/list")
    public TableDataInfo list(Goods goods)
    {
        startPage();
        List<Goods> list = goodsService.selectGoodsList(goods);
        return getDataTable(list);
    }

    @PreAuthorize("@ss.hasPermi('goods:goods:add')")
    @Log(title = "商品管理", businessType = BusinessType.INSERT)
    @PostMapping
    public AjaxResult add(@Validated @RequestBody Goods goods)
    {
        goods.setCreateBy(getUsername());
        return toAjax(goodsService.insertGoods(goods));
    }

    @PreAuthorize("@ss.hasPermi('goods:goods:remove')")
    @Log(title = "商品管理", businessType = BusinessType.DELETE)
    @DeleteMapping("/{goodsIds}")
    public AjaxResult remove(@PathVariable Long[] goodsIds)
    {
        return toAjax(goodsService.deleteGoodsByIds(goodsIds));
    }
}
```

### 1.4 扩展性设计亮点

- **BaseController 提供了通用的分页、响应封装方法**，新 Controller 只需继承即可获得这些能力
- **BaseEntity 提供了通用的审计字段**（createBy/createTime/updateBy/updateTime），新实体只需继承
- **@Log 注解声明式日志**，新 Controller 方法只需添加注解即可获得日志记录
- **@PreAuthorize 注解声明式权限**，新接口只需添加注解即可获得权限控制

## 二、新增自定义注解 + AOP 切面

### 2.1 标准流程

以新增一个 `@OperationLock`（操作锁）注解为例，防止同一用户对同一资源并发操作：

```
Step 1: 在 ruoyi-common 中定义注解
Step 2: 在 ruoyi-framework 中定义切面
Step 3: 在 Controller 中使用注解
```

### 2.2 查看&剖析点

| 参考组件 | 文件位置 | 作用 |
|----------|----------|------|
| 注解参考 | `ruoyi-common/.../annotation/RateLimiter.java` | 注解定义模式 |
| 切面参考 | `ruoyi-framework/.../aspectj/RateLimiterAspect.java` | 切面实现模式 |
| Redis工具 | `ruoyi-common/.../core/redis/RedisCache.java` | Redis操作封装 |

### 2.3 源码关键片段引用

**Step 1: 定义注解（参考 @RateLimiter 的设计）**

```java
// 参考：ruoyi-common/src/main/java/com/ruoyi/common/annotation/RateLimiter.java
// @RateLimiter 注解的设计模式：
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RateLimiter
{
    public String key() default CacheConstants.RATE_LIMIT_KEY;
    public int time() default 60;
    public int count() default 100;
    public LimitType limitType() default LimitType.DEFAULT;
}
```

**新增 @OperationLock 注解（示例）**：

```java
// 放在 ruoyi-common/src/main/java/com/ruoyi/common/annotation/OperationLock.java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface OperationLock
{
    /** 锁的key前缀 */
    String key() default "op_lock";

    /** 锁的过期时间（秒） */
    int expireTime() default 30;

    /** 获取锁失败时的提示消息 */
    String message() default "操作过于频繁，请稍后再试";
}
```

**Step 2: 定义切面（参考 @RateLimiterAspect 的设计）**

```java
// 参考：ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/RateLimiterAspect.java
// RateLimiterAspect 的设计模式：
@Aspect
@Component
public class RateLimiterAspect
{
    @Autowired
    private RedisTemplate<Object, Object> redisTemplate;
    @Autowired
    private RedisScript<Long> limitScript;

    @Before("@annotation(rateLimiter)")
    public void doBefore(JoinPoint point, RateLimiter rateLimiter) throws Throwable
    {
        // 1. 获取注解参数
        // 2. 构建Redis key
        // 3. 执行限流判断
        // 4. 超过限制抛出异常
    }
}
```

**新增 OperationLockAspect（示例）**：

```java
// 放在 ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/OperationLockAspect.java
@Aspect
@Order(2)  // 在 DataSourceAspect(1) 之后，DataScopeAspect 之前
@Component
public class OperationLockAspect
{
    @Autowired
    private RedisCache redisCache;

    @Before("@annotation(operationLock)")
    public void doBefore(JoinPoint point, OperationLock operationLock) throws Throwable
    {
        LoginUser loginUser = SecurityUtils.getLoginUser();
        if (loginUser == null) { return; }

        String lockKey = operationLock.key() + ":" + loginUser.getUserId()
            + ":" + point.getSignature().getName();

        Boolean hasLock = redisCache.setCacheObjectIfAbsent(lockKey, "1",
            operationLock.expireTime(), TimeUnit.SECONDS);
        if (hasLock == null || !hasLock) {
            throw new ServiceException(operationLock.message());
        }
    }
}
```

**Step 3: 在 Controller 中使用**

```java
@OperationLock(key = "order:pay", expireTime = 60, message = "订单正在处理中，请勿重复操作")
@PostMapping("/pay/{orderId}")
public AjaxResult payOrder(@PathVariable Long orderId) {
    return toAjax(orderService.payOrder(orderId));
}
```

### 2.4 注解+AOP扩展的设计模式总结

```
┌────────────────────────────────────────────────────────────┐
│                    ruoyi-common 模块                       │
│  定义注解（@Target + @Retention + @Documented）              │
│  定义枚举（如 LimitType、BusinessType）                     │
│  定义常量（如 CacheConstants.RATE_LIMIT_KEY）               │
├────────────────────────────────────────────────────────────┤
│                   ruoyi-framework 模块                     │

│  实现通知方法（@Before/@Around/@AfterReturning）            │

├────────────────────────────────────────────────────────────┤
│                    ruoyi-admin 模块                         │
│  在Controller方法上使用注解                                  │
│  业务代码零侵入                                             │
└────────────────────────────────────────────────────────────┘
```

## 三、新增数据源

### 3.1 标准流程

RuoYi-Vue 支持通过配置文件和少量代码新增数据源：

```
Step 1: 在 DataSourceType 枚举中新增数据源类型
Step 2: 在 application-druid.yml 中配置新数据源
Step 3: 在 DruidConfig 中创建新数据源 Bean
Step 4: 在 Service 方法上使用 @DataSource 注解
```

### 3.2 查看&剖析点

| 组件 | 文件位置 | 说明 |
|------|----------|------|
| 数据源枚举 | `ruoyi-common/.../enums/DataSourceType.java` | 数据源类型定义 |
| 数据源配置 | `ruoyi-admin/.../resources/application-druid.yml` | 连接信息 |
| 数据源Bean | `ruoyi-framework/.../config/DruidConfig.java` | Bean创建 |
| 动态数据源 | `ruoyi-framework/.../datasource/DynamicDataSource.java` | 路由选择 |
| 数据源上下文 | `ruoyi-framework/.../datasource/DynamicDataSourceContextHolder.java` | ThreadLocal |

### 3.3 源码关键片段引用

**Step 1: 扩展数据源枚举**

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/enums/DataSourceType.java
public enum DataSourceType
{
    MASTER,  // 主库
    SLAVE    // 从库
    // 新增: REPORT  // 报表库
}
```

**Step 2: 配置新数据源**

```yaml
# 文件：ruoyi-admin/src/main/resources/application-druid.yml
spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    druid:
      master:
        url: jdbc:mysql://localhost:3306/ry
        username: root
        password: password
      slave:
        enabled: true
        url: jdbc:mysql://localhost:3306/ry_slave
        username: root
        password: password
      # 新增报表数据源
      # report:
      #   enabled: true
      #   url: jdbc:mysql://localhost:3306/ry_report
      #   username: root
      #   password: password
```

**Step 3: 创建新数据源 Bean**

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/DruidConfig.java
// 参考现有的 slaveDataSource 创建方式：
@Bean
@ConfigurationProperties("spring.datasource.druid.slave")
@ConditionalOnProperty(prefix = "spring.datasource.druid.slave", name = "enabled", havingValue = "true")
public DataSource slaveDataSource(DruidProperties druidProperties)
{
    DruidDataSource dataSource = DruidDataSourceBuilder.create().build();
    return druidProperties.dataSource(dataSource);
}

// 新增报表数据源：
// @Bean
// @ConfigurationProperties("spring.datasource.druid.report")
// @ConditionalOnProperty(prefix = "spring.datasource.druid.report", name = "enabled", havingValue = "true")
// public DataSource reportDataSource(DruidProperties druidProperties)
// {
//     DruidDataSource dataSource = DruidDataSourceBuilder.create().build();
//     return druidProperties.dataSource(dataSource);
// }

// 在 dynamicDataSource 方法中注册新数据源：
@Bean(name = "dynamicDataSource")
@Primary
public DynamicDataSource dataSource(DataSource masterDataSource)
{
    Map<Object, Object> targetDataSources = new HashMap<>();
    targetDataSources.put(DataSourceType.MASTER.name(), masterDataSource);
    setDataSource(targetDataSources, DataSourceType.SLAVE.name(), "slaveDataSource");
    // 新增: setDataSource(targetDataSources, DataSourceType.REPORT.name(), "reportDataSource");
    return new DynamicDataSource(masterDataSource, targetDataSources);
}
```

**Step 4: 使用 @DataSource 注解切换**

```java
// 在Service方法上标注
@DataSource(DataSourceType.SLAVE)
public List<ReportData> selectReportData(ReportQuery query) {
    return reportMapper.selectReportData(query);
}
```

### 3.4 动态数据源路由机制

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/datasource/DynamicDataSource.java
// 继承 Spring 的 AbstractRoutingDataSource，实现动态路由
public class DynamicDataSource extends AbstractRoutingDataSource
{
    public DynamicDataSource(DataSource defaultTargetDataSource, Map<Object, Object> targetDataSources)
    {
        super.setDefaultTargetDataSource(defaultTargetDataSource);
        super.setTargetDataSources(targetDataSources);
        super.afterPropertiesSet();
    }

    @Override
    protected Object determineCurrentLookupKey()
    {
        // 从 ThreadLocal 中获取当前线程的数据源类型
        return DynamicDataSourceContextHolder.getDataSourceType();
    }
}
```

**数据源切换完整链路**：

```
Service方法调用（标注 @DataSource(SLAVE)）
    |
    v
DataSourceAspect.around()
    |-- DynamicDataSourceContextHolder.setDataSourceType("SLAVE")
    |
    v
MyBatis 获取数据库连接
    |
    v
DynamicDataSource.determineCurrentLookupKey()
    |-- return "SLAVE"
    |
    v
AbstractRoutingDataSource 根据 key 返回对应的 DataSource
    |
    v
DruidDataSource（SLAVE）提供连接
    |
    v
SQL在从库上执行
    |
    v
DataSourceAspect.finally
    |-- DynamicDataSourceContextHolder.clearDataSourceType()
```

```java
// 文件：ruoyi-generator/src/main/java/com/ruoyi/generator/util/VelocityInitializer.java
public class VelocityInitializer
{
    public static void initVelocity()
    {
        Properties p = new Properties();
        try
        {
            // 加载classpath目录下的vm文件
            p.setProperty("resource.loader.file.class",
                "org.apache.velocity.runtime.resource.loader.ClasspathResourceLoader");
            p.setProperty(Velocity.INPUT_ENCODING, Constants.UTF8);
            Velocity.init(p);
        }
        catch (Exception e)
        {
            throw new RuntimeException(e);
        }
    }
}
```

### 4.5 代码生成器与项目架构的关系

代码生成器生成的代码严格遵循 RuoYi-Vue 的架构规范：

```
生成的代码 ──────────────────> 遵循的架构规范
Controller extends BaseController    --> 继承通用基类
@PreAuthorize + @Log 注解            --> 声明式权限+日志
Service 接口 + Impl 实现              --> 面向接口编程
```

## 细节留神

1. **新增模块时**，如果需要数据权限支持，Service 方法的第一个参数必须是继承 `BaseEntity` 的实体类，因为 `DataScopeAspect` 默认从 `joinPoint.getArgs()[0]` 获取参数。
2. **新增数据源时**，`DynamicDataSourceContextHolder` 使用 `ThreadLocal` 存储数据源类型，在异步场景（如 `@Async`）中 ThreadLocal 不会传递到子线程，需要在异步方法中重新设置数据源。
3. **代码生成器**生成的代码是标准模板代码，实际项目中通常需要根据业务需求进行二次开发。模板本身也可以根据团队规范进行定制。
4. **新增 AOP 切面时**，必须注意 `@Order` 的设置。特别是与 `DataSourceAspect`（Order=1）的配合，如果新切面需要在数据源切换之后执行，Order 值必须大于 1。
5. **新增过滤器时**，`FilterRegistrationBean.HIGHEST_PRECEDENCE` 对应的 Order 值为 `Integer.MIN_VALUE`，`LOWEST_PRECEDENCE` 对应 `Integer.MAX_VALUE`。XSS 过滤器使用最高优先级是因为它需要在所有处理之前过滤恶意输入。
6. **代码生成器的 Velocity 模板**中使用了 `${}` 语法，这与 MyBatis 的 `${}` 含义不同。Velocity 的 `${}` 是变量替换，MyBatis 的 `${}` 是 SQL 字符串替换。
