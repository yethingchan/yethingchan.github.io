## 二、核心设计思想

RuoYi-Vue 的拦截器机制基于 Spring MVC 的 `HandlerInterceptor` 接口，实现了两个核心功能：

1. **防重复提交拦截器**（RepeatSubmitInterceptor）：基于 Redis 实现，通过 `@RepeatSubmit` 注解标记需要防重的接口
2. **国际化拦截器**（I18nConfig）：基于 `LocaleChangeInterceptor`，通过 `lang` 参数切换语言

拦截器与过滤器的区别：
- **Filter**：Servlet 级别，在 DispatcherServlet 之前执行
- **Interceptor**：Spring MVC 级别，在 Controller 之前/之后执行，可以访问 Handler 方法信息

## 三、源码关键片段引用

### 3.1 @RepeatSubmit 注解

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/annotation/RepeatSubmit.java
@Inherited
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RepeatSubmit
{
    /**
     * 间隔时间(ms)，小于此时间视为重复提交
     */
    public int interval() default 5000;

    /**
     * 提示消息
     */
    public String message() default "不允许重复提交，请稍候再试";
}
```

**设计要点**：
- 只能标注在方法上（`ElementType.METHOD`）
- 默认间隔 5000ms（5秒），可自定义
- `@Inherited` 允许子类继承该注解
- 提示消息支持自定义

### 3.2 RepeatSubmitInterceptor -- 模板方法模式

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/interceptor/RepeatSubmitInterceptor.java
@Component
public abstract class RepeatSubmitInterceptor implements HandlerInterceptor
{
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws Exception
    {
        if (handler instanceof HandlerMethod)
        {
            HandlerMethod handlerMethod = (HandlerMethod) handler;
            Method method = handlerMethod.getMethod();
            RepeatSubmit annotation = method.getAnnotation(RepeatSubmit.class);
            if (annotation != null)
            {
                if (this.isRepeatSubmit(request, annotation))
                {
                    AjaxResult ajaxResult = AjaxResult.error(annotation.message());
                    ServletUtils.renderString(response, JSON.toJSONString(ajaxResult));
                    return false;
                }
            }
            return true;
        }
        else
        {
            return true;
        }
    }

    /**
     * 验证是否重复提交由子类实现具体的防重复提交的规则
     */
    public abstract boolean isRepeatSubmit(HttpServletRequest request, RepeatSubmit annotation);
}
```

**设计要点**：
- 使用 **模板方法模式**：父类定义流程骨架，`isRepeatSubmit` 由子类实现
- `abstract` 关键字表明这是一个抽象类，必须有子类实现
- 只拦截 `HandlerMethod`（即 Controller 方法），不拦截静态资源
- 重复提交时直接通过 `ServletUtils.renderString` 写入 JSON 响应，返回 `false` 阻止请求继续执行

### 3.3 拦截器注册

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/ResourcesConfig.java
@Configuration
public class ResourcesConfig implements WebMvcConfigurer
{
    @Autowired
    private RepeatSubmitInterceptor repeatSubmitInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry)
    {
        registry.addInterceptor(repeatSubmitInterceptor).addPathPatterns("/**");
    }
}
```

**设计要点**：
- 拦截所有路径 `/**`，但实际只对标注了 `@RepeatSubmit` 的方法生效
- 通过 `@Autowired` 注入的是 `RepeatSubmitInterceptor` 的子类实现

### 3.4 I18nConfig -- 国际化配置

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/I18nConfig.java
@Configuration
public class I18nConfig implements WebMvcConfigurer
{
    @Bean
    public LocaleResolver localeResolver()
    {
        SessionLocaleResolver slr = new SessionLocaleResolver();
        // 默认语言
        slr.setDefaultLocale(Constants.DEFAULT_LOCALE);
        return slr;
    }

    @Bean
    public LocaleChangeInterceptor localeChangeInterceptor()
    {
        LocaleChangeInterceptor lci = new LocaleChangeInterceptor();
        // 参数名
        lci.setParamName("lang");
        return lci;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry)
    {
        registry.addInterceptor(localeChangeInterceptor());
    }
}
```

**设计要点**：
- 使用 `SessionLocaleResolver` 将语言信息存储在 Session 中
- 默认语言为 `Constants.DEFAULT_LOCALE`（`Locale.SIMPLIFIED_CHINESE`，简体中文）
- 通过 URL 参数 `lang` 切换语言，如 `?lang=en_US`
- 国际化消息文件位于 `resources/i18n/messages.properties`

@Override
public String getMessage()
{
    String message = null;
    if (!StringUtils.isEmpty(code))
    {
        message = MessageUtils.message(code, args);
    }
    if (message == null)
    {
        message = defaultMessage;
    }
    return message;

## 四、防重复提交的完整流程

```
1. 用户发起请求
    |
    v
2. RepeatSubmitInterceptor.preHandle()
    |
    +--> 检查方法是否有 @RepeatSubmit 注解
    |       |
    |       +--> 无注解 --> 放行
    |       |
    |       v
    |    有注解 --> 调用 isRepeatSubmit()
    |       |
    |       +--> 生成唯一key（基于请求参数 + URL + 用户标识）
    |       |
    |       +--> 检查Redis中是否存在该key
    |       |       |
    |       |       +--> 存在 --> 重复提交，返回错误
    |       |       |
    |       |       +--> 不存在 --> 设置key（带过期时间），放行
    |       |
    |       v
    |    请求处理完成后，key自动过期
    |
    v
3. Controller 处理请求
```

### Redis Key 设计

```
Key格式：repeat_submit:{请求唯一标识}
过期时间：@RepeatSubmit.interval() / 1000 秒
```

## 五、拦截器 vs 过滤器对比

| 对比维度 | Filter | Interceptor |
|---------|--------|------------|
| 所属层级 | Servlet | Spring MVC |
| 执行时机 | DispatcherServlet之前 | Controller之前/之后 |
| 可访问内容 | ServletRequest/Response | Handler方法、注解、参数 |
| 异常处理 | 需自行处理 | 可由GlobalExceptionHandler统一处理 |
| 适用场景 | XSS、CORS、编码 | 防重提交、权限检查、日志 |

## 六、细节留神

1. **RepeatSubmitInterceptor 是抽象类**：项目中必须有子类实现 `isRepeatSubmit` 方法。子类通常基于 Redis 判断重复提交。

2. **防重提交的 key 生成策略**：key 的生成需要考虑请求 URL、参数、用户标识等多个维度。如果 key 设计不合理，可能导致误判或漏判。

3. **I18nConfig 使用 Session 存储语言**：在前后端分离架构中，Session 机制可能不太适合。可以考虑使用请求头 `Accept-Language` 或自定义 header。

4. **LocaleChangeInterceptor 没有限制路径**：任何请求都可以通过 `?lang=xxx` 切换语言，可能被恶意利用。

5. **防重复提交只拦截 POST/PUT 等修改操作**：GET 请求天然幂等，不需要防重。但 RepeatSubmitInterceptor 本身没有做 HTTP 方法过滤，需要在使用时注意。

6. **RepeatSubmit 注解的 interval 是毫秒**：注意单位是毫秒，不是秒。5000ms = 5秒。

## 七、提问方向

1. **RepeatSubmitInterceptor 使用模板方法模式，`isRepeatSubmit` 由子类实现。你会如何设计基于 Redis 的防重复提交实现？key 应该包含哪些要素？**

2. **当前防重复提交是基于时间间隔的，如果用户快速提交两个不同的表单（间隔小于5秒），如何避免误判？你会如何改进 key 的生成策略？**

3. **I18nConfig 使用 Session 存储语言信息，在前后端分离架构中这种方案有什么问题？你会如何改为基于 Token 或请求头的方式？**

4. **如果同一个用户在两台设备上同时操作，防重复提交机制如何处理？是否需要考虑分布式场景？**

5. **RepeatSubmit 注解只能设置固定的时间间隔，如果需要根据不同接口设置不同的间隔时间，当前设计是否足够灵活？**

6. **拦截器中直接通过 `ServletUtils.renderString` 写入响应，绕过了 Spring MVC 的正常渲染流程。这种做法有什么优缺点？**

7. **如果要在防重复提交中增加"白名单"功能（某些角色或接口不需要防重），你会如何设计？**

8. **在分布式部署场景下，多个实例的拦截器配置如何保持一致？Redis 的过期时间如何选择？**
