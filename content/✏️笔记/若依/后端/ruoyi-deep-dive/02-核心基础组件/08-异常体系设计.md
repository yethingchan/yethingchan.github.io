## 二、核心设计思想

RuoYi-Vue 的异常体系采用 **"分层分类"** 设计，按业务领域划分为多个异常家族：

```
RuntimeException
    |
    +--> ServiceException（业务异常，最常用）
    +--> GlobalException（全局异常）
    +--> DemoModeException（演示模式异常）
    +--> UtilException（工具类异常）
    |
    +--> BaseException（基础异常，支持国际化）
    |       |
    |       +--> UserException（用户异常）
    |       |       +--> UserNotExistsException
    |       |       +--> UserPasswordNotMatchException
    |       |       +--> CaptchaException
    |       |       +--> CaptchaExpireException
    |       |       +--> UserPasswordRetryLimitExceedException
    |       |       +--> BlackListException
    |       |
    |       +--> FileException（文件异常）
    |               +--> FileNameLengthLimitExceededException
    |               +--> FileSizeLimitExceededException
    |               +--> InvalidExtensionException
    |                   +--> InvalidImageExtensionException
    |                   +--> InvalidFlashExtensionException
    |                   +--> InvalidMediaExtensionException
    |                   +--> InvalidVideoExtensionException
    |
    +--> TaskException（计划任务异常，继承 Exception）
```

## 三、源码关键片段引用

### 3.1 BaseException -- 基础异常（支持国际化）

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/exception/base/BaseException.java
public class BaseException extends RuntimeException
{
    private String module;           // 所属模块
    private String code;             // 错误码（对应国际化消息的key）
    private Object[] args;           // 错误码参数
    private String defaultMessage;    // 默认消息（国际化消息不存在时使用）

    public BaseException(String module, String code, Object[] args, String defaultMessage)
    {
        this.module = module;
        this.code = code;
        this.args = args;
        this.defaultMessage = defaultMessage;
    }

    @Override
    public String getMessage()
    {
        String message = null;
        if (!StringUtils.isEmpty(code))
        {
            // 通过 MessageUtils 从国际化资源文件中获取消息
            message = MessageUtils.message(code, args);
        }
        if (message == null)
        {
            message = defaultMessage;
        }
        return message;
    }
}
```

**设计要点**：
- `module` 标识异常所属模块（如 "user"、"file"）
- `code` 是国际化消息的 key（如 "user.password.not.match"）
- `args` 是消息参数（如 `{0}`、`{1}` 占位符的值）
- `getMessage()` 优先从国际化资源文件获取消息，获取不到则使用 defaultMessage
- 这是整个异常体系中国际化支持的核心

### 3.2 ServiceException -- 业务异常（最常用）

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/exception/ServiceException.java
public final class ServiceException extends RuntimeException
{
    private Integer code;           // 自定义错误码
    private String message;        // 错误消息
    private String detailMessage;  // 详细错误信息（内部调试用）

    public ServiceException(String message)
    {
        this.message = message;
    }

    public ServiceException(String message, Integer code)
    {
        this.message = message;
        this.code = code;
    }

    // 链式设置
    public ServiceException setMessage(String message)
    {
        this.message = message;
        return this;
    }

    public ServiceException setDetailMessage(String detailMessage)
    {
        this.detailMessage = detailMessage;
        return this;
    }
}
```

**设计要点**：
- `final` 类，不允许被继承
- **不继承 BaseException**，不支持国际化消息
- `code` 是 Integer 类型的 HTTP 状态码，不是字符串错误码
- `detailMessage` 用于存储内部调试信息，不暴露给前端
- 支持链式调用设置属性

### 3.5 TaskException -- 计划任务异常

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/exception/job/TaskException.java
public class TaskException extends Exception  // 注意：继承 Exception，不是 RuntimeException
{
    private Code code;

    public enum Code
    {
        TASK_EXISTS,              // 任务已存在
        NO_TASK_EXISTS,          // 任务不存在
        TASK_ALREADY_STARTED,    // 任务已启动
        UNKNOWN,                 // 未知错误
        CONFIG_ERROR,             // 配置错误
        TASK_NODE_NOT_AVAILABLE   // 任务节点不可用
    }
}
```

**设计要点**：
- **继承 `Exception`（受检异常）**，而非 `RuntimeException`（非受检异常）
- 这是因为计划任务异常需要强制调用方处理
- 使用内部枚举 `Code` 定义错误类型

### 3.6 GlobalExceptionHandler 中的异常处理

```java
// ServiceException -- 支持自定义错误码
@ExceptionHandler(ServiceException.class)
public AjaxResult handleServiceException(ServiceException e, HttpServletRequest request)
{
    log.error(e.getMessage(), e);
    Integer code = e.getCode();
    return StringUtils.isNotNull(code)
        ? AjaxResult.error(code, e.getMessage())
        : AjaxResult.error(e.getMessage());
}

// DemoModeException -- 演示模式
@ExceptionHandler(DemoModeException.class)
public AjaxResult handleDemoModeException(DemoModeException e)
{
    return AjaxResult.error("演示模式，不允许操作");
}

// RuntimeException 兜底
@ExceptionHandler(RuntimeException.class)
public AjaxResult handleRuntimeException(RuntimeException e, HttpServletRequest request)
{
    log.error("请求地址'{}',发生未知异常.", requestURI, e);
    return AjaxResult.error(e.getMessage());
}
```

## 四、国际化消息文件

```properties
# 文件：ruoyi-admin/src/main/resources/i18n/messages.properties

# 用户模块
user.not.exists=用户不存在/密码错误
user.password.not.match=用户不存在/密码错误
user.password.retry.limit.exceed=密码输入错误{0}次，帐户锁定{1}分钟
user.jcaptcha.error=验证码错误
user.jcaptcha.expire=验证码已过期
user.blacklist=用户已列入黑名单[{0}]
```

**国际化消息的使用流程**：
```
1. 抛出异常：throw new UserPasswordRetryLimitExceedException(5, 10)
2. 异常构造：super("user.password.retry.limit.exceed", new Object[]{5, 10})
3. 获取消息：MessageUtils.message("user.password.retry.limit.exceed", 5, 10)
4. 返回结果："密码输入错误5次，帐户锁定10分钟"
```

## 五、异常使用场景对照表

| 异常类 | 使用场景 | 是否国际化 | 是否受检 | GlobalExceptionHandler处理 |
|--------|---------|-----------|---------|------------------------|
| ServiceException | 业务逻辑错误（如"该用户已存在"） | 否 | 否 | 是（支持自定义code） |
| BaseException | 基础异常（一般不直接使用） | 是 | 否 | 否（由子类处理） |
| UserException | 用户认证相关错误 | 是 | 否 | 是（RuntimeException兜底） |
| FileException | 文件操作相关错误 | 是 | 否 | 是（RuntimeException兜底） |
| TaskException | 计划任务相关错误 | 否 | 是 | 否（需手动处理） |
| DemoModeException | 演示模式保护 | 否 | 否 | 是（专门处理） |
| GlobalException | 全局性错误 | 否 | 否 | 是（RuntimeException兜底） |
| UtilException | 工具类内部错误 | 否 | 否 | 是（RuntimeException兜底） |

## 六、细节留神

1. **ServiceException 不继承 BaseException**：这是设计上的不一致。ServiceException 是最常用的异常，但不支持国际化；UserException 继承 BaseException 支持国际化，但使用频率较低。

2. **UserException 子类不被 GlobalExceptionHandler 专门处理**：这些异常会被 `RuntimeException` 兜底处理器捕获，直接返回 `e.getMessage()`。虽然 BaseException 的 `getMessage()` 已经处理了国际化，但兜底处理器不会返回自定义错误码。

3. **InvalidExtensionException 继承 FileUploadException**：而 FileUploadException 继承自 `java.io.IOException`，不是 RuntimeException。这意味着 InvalidExtensionException 是受检异常，需要 try-catch 处理。

4. **TaskException 继承 Exception**：是唯一的受检异常，需要调用方显式处理。这符合计划任务场景中"调用方需要知道任务可能失败"的设计意图。

5. **GlobalException 与 ServiceException 结构几乎相同**：都有 message 和 detailMessage，区别在于 GlobalException 没有被 GlobalExceptionHandler 专门处理。

6. **DemoModeException 没有消息属性**：固定返回"演示模式，不允许操作"，不支持自定义消息。

## 七、提问方向

1. **ServiceException 是最常用的异常但不支持国际化，而 UserException 支持国际化但使用较少。你会如何统一异常体系，使所有异常都支持国际化？**

2. **UserException 的子类（如 UserPasswordRetryLimitExceedException）没有被 GlobalExceptionHandler 专门处理，而是被 RuntimeException 兜底捕获。这种设计是否合理？你会如何改进？**

3. **InvalidExtensionException 继承 FileUploadException（受检异常），而 FileException 继承 BaseException（非受检异常）。文件异常家族的继承关系不一致，你会如何统一？**

4. **TaskException 是项目中唯一的受检异常，继承 Exception。在什么场景下应该使用受检异常？你会如何决定一个异常应该是受检还是非受检？**

5. **如果要在异常体系中增加"错误码"体系（如 B-001 表示用户不存在，B-002 表示密码错误），你会如何设计错误码的生成和管理规范？**

6. **GlobalExceptionHandler 的兜底异常直接返回 e.getMessage()，可能暴露内部信息。你会如何设计异常消息的安全过滤机制？**

7. **在微服务架构中，异常需要在服务间传递。你会如何设计统一的异常序列化/反序列化机制？**

8. **如果需要实现"异常告警"功能（特定异常触发告警通知），你会如何设计异常分级和告警策略？**
