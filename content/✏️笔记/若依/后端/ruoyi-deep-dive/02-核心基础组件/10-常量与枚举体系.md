## 二、核心设计思想

RuoYi-Vue 的常量与枚举体系遵循 **"按业务领域分类"** 的设计原则：

- **常量类**：使用 `public static final` 定义不可变值，按业务领域分为6个类
- **枚举类**：使用 Java 枚举定义有限集合的值，提供类型安全和自文档化

```
常量体系
|
+--> Constants（通用常量：编码、Token、权限标识等）
+--> CacheConstants（Redis Key前缀）
+--> HttpStatus（HTTP状态码）
+--> UserConstants（用户/角色/部门/菜单/字典相关）
+--> GenConstants（代码生成相关）
+--> ScheduleConstants（定时任务相关）

枚举体系
|
+--> BusinessType（业务操作类型）
+--> BusinessStatus（业务操作状态）
+--> DataSourceType（数据源类型）
+--> DesensitizedType（脱敏类型）
+--> HttpMethod（HTTP请求方法）
+--> LimitType（限流类型）
+--> OperatorType（操作人类别）
+--> UserStatus（用户状态）
```

## 三、常量类详解

### 3.1 Constants -- 通用常量

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/constant/Constants.java
public class Constants
{
    // 编码

    public static final String FAIL = "1";

    // 登录相关
    public static final String LOGIN_SUCCESS = "Success";
    public static final String LOGIN_FAIL = "Error";
    public static final String LOGOUT = "Logout";
    public static final String REGISTER = "Register";

    // 权限相关
    public static final String ALL_PERMISSION = "*:*:*";
    public static final String SUPER_ADMIN = "admin";
    public static final String ROLE_DELIMITER = ",";
    public static final String PERMISSION_DELIMITER = ",";

    // Token相关
    public static final String TOKEN = "token";
    public static final String TOKEN_PREFIX = "Bearer ";
    public static final String LOGIN_USER_KEY = "login_user_key";
    public static final Integer CAPTCHA_EXPIRATION = 2;  // 验证码有效期（分钟）

    // JWT Claims
    public static final String JWT_USERID = "userid";
    public static final String JWT_USERNAME = Claims.SUBJECT;
    public static final String JWT_AVATAR = "avatar";
    public static final String JWT_CREATED = "created";
    public static final String JWT_AUTHORITIES = "authorities";

    // 资源路径
    public static final String RESOURCE_PREFIX = "/profile";

    // 安全白名单
    public static final String[] JSON_WHITELIST_STR = { "com.ruoyi" };
    public static final String[] JOB_WHITELIST_STR = { "com.ruoyi.quartz.task" };
    public static final String[] JOB_ERROR_STR = { "java.net.URL", "javax.naming.InitialContext", ... };

    // 内部类：部门数据权限
    public static class Dept
    {
        public static final String DATA_SCOPE_ALL = "1";            // 全部数据
        public static final String DATA_SCOPE_CUSTOM = "2";         // 自定义数据
        public static final String DATA_SCOPE_DEPT = "3";           // 本部门数据
        public static final String DATA_SCOPE_DEPT_AND_CHILD = "4"; // 本部门及以下
        public static final String DATA_SCOPE_SELF = "5";           // 仅本人数据
    }
}
```

**设计要点**：
- 使用内部类 `Dept` 组织部门相关常量，避免命名空间污染
- `ALL_PERMISSION = "*:*:*"` 是超级权限标识，匹配所有权限
- `JOB_WHITELIST_STR` 和 `JOB_ERROR_STR` 用于定时任务安全控制
- `TOKEN_PREFIX = "Bearer "` 符合 OAuth 2.0 规范

### 3.3 HttpStatus -- HTTP状态码

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/constant/HttpStatus.java
public class HttpStatus
{
    // 2xx 成功
    public static final int SUCCESS = 200;
    public static final int CREATED = 201;
    public static final int ACCEPTED = 202;
    public static final int NO_CONTENT = 204;

    // 3xx 重定向
    public static final int MOVED_PERM = 301;
    public static final int SEE_OTHER = 303;
    public static final int NOT_MODIFIED = 304;

    // 4xx 客户端错误
    public static final int BAD_REQUEST = 400;
    public static final int UNAUTHORIZED = 401;
    public static final int FORBIDDEN = 403;
    public static final int NOT_FOUND = 404;
    public static final int BAD_METHOD = 405;
    public static final int CONFLICT = 409;
    public static final int UNSUPPORTED_TYPE = 415;

    // 5xx 服务器错误
    public static final int ERROR = 500;
    public static final int NOT_IMPLEMENTED = 501;

    // 6xx 自定义
    public static final int WARN = 601;  // 系统警告
}
```

**设计要点**：
- 覆盖标准 HTTP 状态码 + 自定义 601 警告码
- 这是若依自定义的 HttpStatus，不是 Spring 的 `org.springframework.http.HttpStatus`
- 601 不属于任何 HTTP 标准，是若依的特色扩展

### 4.4 DesensitizedType -- 脱敏类型

```java
public enum DesensitizedType
{
    USERNAME(s -> s.replaceAll("(\\S)\\S(\\S*)", "$1*$2")),
    PASSWORD(DesensitizedUtil::password),
    ID_CARD(s -> s.replaceAll("(\\d{4})\\d{10}(\\d{3}[Xx]|\\d{4})", "$1** **** ****$2")),
    PHONE(s -> s.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2")),
    EMAIL(s -> s.replaceAll("(^.)[^@]*(@.*$)", "$1****$2")),
    BANK_CARD(s -> s.replaceAll("\\d{15}(\\d{3})", "**** **** **** **** $1")),
    CAR_LICENSE(DesensitizedUtil::carLicense);

    private final Function<String, String> desensitizer;
}
```

**设计要点**：
- 每个枚举值关联一个 `Function<String, String>`，封装脱敏逻辑
- 使用 Lambda 表达式和正则表达式实现脱敏规则
- 配合 `@Sensitive` 注解和 Jackson 序列化器使用

## 六、细节留神

1. **Constants.SUCCESS = "0" vs HttpStatus.SUCCESS = 200**：两个不同模块的"成功"标识使用不同的值和类型，需要注意区分使用场景。

2. **CacheConstants 的 key 以冒号结尾**：这是 Redis 的命名惯例，冒号作为层级分隔符，方便在 Redis 客户端中查看树形结构。

3. **HttpStatus.WARN = 601**：非标准状态码，如果对接第三方系统可能产生兼容性问题。

4. **GenConstants 中的数据库类型数组**：只包含了 MySQL 的数据类型，如果使用 PostgreSQL 或 Oracle，需要扩展。

5. **DesensitizedType 使用正则表达式**：手机号脱敏使用 `(\\d{3})\\d{4}(\\d{4})`，只匹配11位数字。如果手机号格式不标准（如带国际区号），可能无法正确脱敏。

6. **UserStatus 是唯一携带额外数据的枚举**：其他枚举都是简单的值枚举。如果需要扩展枚举携带数据，可以参考 UserStatus 的设计。

## 七、提问方向

1. **Constants.SUCCESS = "0" 和 HttpStatus.SUCCESS = 200 表示"成功"，但值和类型不同。在项目中如何避免混淆？你会如何统一"成功"的表示方式？**

2. **CacheConstants 的 Redis Key 以冒号结尾，如 `login_tokens:`。如果 Redis 中存储了大量 key，如何设计合理的 key 过期策略和清理机制？**

3. **GenConstants 中的数据库类型数组只支持 MySQL，如果需要支持多种数据库（PostgreSQL、Oracle），你会如何设计数据库类型映射？**

4. **DesensitizedType 使用正则表达式实现脱敏，如果需要支持自定义脱敏规则（如只显示前2位和后4位），你会如何扩展？**

5. **如果要将常量和枚举抽取为独立的 API 模块供多个微服务共享，你会如何设计模块的依赖关系和版本管理？**

6. **HttpStatus.WARN = 601 是自定义状态码，在前后端分离架构中，前端如何统一处理这个非标准状态码？如果对接第三方系统，如何处理兼容性？**

7. **ScheduleConstants 内部定义了 Status 枚举，而其他常量类没有使用内部枚举。你认为在常量类中使用内部枚举是否是好的设计实践？**

8. **如果项目需要支持多语言（中英文切换），当前基于字符串常量的设计（如 UserConstants.TYPE_DIR = "M"）是否足够？你会如何改进以支持国际化？**
