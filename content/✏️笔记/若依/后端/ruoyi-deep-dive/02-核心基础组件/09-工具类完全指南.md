### 3.1 StringUtils -- 字符串工具类

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/utils/StringUtils.java
public class StringUtils extends org.apache.commons.lang3.StringUtils
{
    private static final String NULLSTR = "";
    private static final char SEPARATOR = '_';

    public static <T> T nvl(T value, T defaultValue) { ... }
    public static boolean isEmpty(Collection<?> coll) { ... }
    public static boolean isNotEmpty(Collection<?> coll) { ... }

    // 驼峰/下划线转换
    public static String toUnderScoreCase(String str) { ... }
    public static String toCamelCase(String str) { ... }

    public static boolean matches(String str, List<String> patterns) { ... }

    public static boolean containsAny(CharSequence cs, char... searchChars) { ... }

```

**设计要点**：
- 继承 `org.apache.commons.lang3.StringUtils`，扩展了驼峰/下划线转换、路径匹配等功能
- `nvl` 方法类似 Oracle 的 NVL 函数，提供默认值
- `matches` 使用 `AntPathMatcher` 实现 Spring 风格的路径匹配

### 3.2 SecurityUtils -- 安全工具类

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/utils/SecurityUtils.java
public class SecurityUtils
{
    // 获取当前登录用户信息
    public static Long getUserId() { ... }
    public static Long getDeptId() { ... }
    public static String getUsername() { ... }
    public static LoginUser getLoginUser() { ... }
    public static Authentication getAuthentication() { ... }

    // 密码加密与验证
    public static String encryptPassword(String password)
    {
        BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();
        return passwordEncoder.encode(password);
    }

    public static boolean matchesPassword(String rawPassword, String encodedPassword)
    {
        BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();
        return passwordEncoder.matches(rawPassword, encodedPassword);
    }

    // 管理员判断
    public static boolean isAdmin(Long userId)
    {
        return userId != null && 1L == userId;
    }

    // 权限验证
    public static boolean hasPermi(String permission) { ... }
    public static boolean hasPermi(Collection<String> authorities, String permission) { ... }

    // 角色验证
    public static boolean hasRole(String role) { ... }
    public static boolean hasRole(Collection<String> roles, String role) { ... }
}
```

**设计要点**：
- 所有方法都是静态方法，通过 `SecurityContextHolder` 获取当前用户
- 密码使用 BCrypt 加密，每次加密结果不同（加盐）
- `hasPermi` 支持通配符匹配（如 `system:user:*`）
- 获取用户信息失败时抛出 `ServiceException`（401）

## 四、细节留神

1. **StringUtils 继承 commons-lang3**：如果项目升级 commons-lang3 版本，需要注意方法签名变化。

2. **SecurityUtils 每次创建新的 BCryptPasswordEncoder**：`encryptPassword` 和 `matchesPassword` 每次调用都创建新的实例，可以考虑复用。

3. **SpringUtils 的双重接口实现**：同时实现 `BeanFactoryPostProcessor` 和 `ApplicationContextAware`，需要注意初始化顺序。

4. **RedisCache 使用原始 RedisTemplate**：没有指定序列化器，默认使用 JDK 序列化，可能存在兼容性和性能问题。

5. **SqlUtil 的 SQL_REGEX 是硬编码**：如果需要支持新的 SQL 关键字检测，需要修改源码。

6. **FileUploadUtils 默认 50MB 限制**：如果需要上传更大的文件，需要修改配置。

## 五、提问方向

1. **StringUtils 继承 commons-lang3 的 StringUtils，这种"继承并扩展"的方式有什么优缺点？如果 commons-lang3 升级导致方法签名变化，会产生什么影响？**

2. **SecurityUtils 每次调用 `encryptPassword` 都创建新的 BCryptPasswordEncoder 实例，这是否有性能问题？你会如何优化？**

3. **RedisCache 使用默认的 JDK 序列化，存储的对象需要实现 Serializable。如果改用 JSON 序列化，会有什么优缺点？**

4. **SqlUtil 的 SQL 关键字黑名单是硬编码的，如果攻击者使用新的绕过方式，如何快速更新黑名单？你会如何设计更灵活的 SQL 防护机制？**

5. **SpringUtils 在非 Spring 管理的类中获取 Bean，如果在多线程环境中使用，是否存在线程安全问题？**

6. **FileUploadUtils 的文件路径按日期分类（如 `/2024/01/15/`），如果单日上传量巨大，同一目录下文件过多会影响性能。你会如何改进文件存储策略？**

7. **如果要将这些工具类抽取为独立的工具包供其他项目使用，你会如何设计模块划分和依赖管理？**

8. **当前工具类体系中缺少"缓存工具"（如本地缓存 Caffeine/Guava Cache），如果需要增加本地缓存支持，你会如何设计？**
