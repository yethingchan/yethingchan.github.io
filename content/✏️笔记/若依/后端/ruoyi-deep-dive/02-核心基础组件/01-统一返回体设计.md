## 二、核心设计思想

RuoYi-Vue 的统一返回体设计遵循"三要素"原则：**状态码(code) + 消息(msg) + 数据(data)**。项目提供了两套返回体实现：

- **AjaxResult**：继承 `HashMap<String, Object>`，灵活可扩展，是项目中的主力返回体
- **R<T>**：泛型响应体，类型安全，支持更严格的泛型约束

两套方案并存的原因：AjaxResult 是若依早期设计的核心，R<T> 是后期引入的泛型增强版本，二者在不同场景下各有优势。

## 三、源码关键片段引用

### 3.1 AjaxResult -- 继承HashMap的巧妙设计

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/core/domain/AjaxResult.java
public class AjaxResult extends HashMap<String, Object>
{
    private static final long serialVersionUID = 1L;

    /** 状态码 */
    public static final String CODE_TAG = "code";
    /** 返回内容 */
    public static final String MSG_TAG = "msg";
    /** 数据对象 */
    public static final String DATA_TAG = "data";

    public AjaxResult(int code, String msg, Object data)
    {
        super.put(CODE_TAG, code);
        super.put(MSG_TAG, msg);
        if (StringUtils.isNotNull(data))
        {
            super.put(DATA_TAG, data);
        }
    }

    // 链式调用支持
    @Override
    public AjaxResult put(String key, Object value)
    {
        super.put(key, value);
        return this;
    }
}
```

**设计要点**：
- 继承 `HashMap` 使得 AjaxResult 天然支持序列化为 JSON 对象
- 使用 `CODE_TAG`/`MSG_TAG`/`DATA_TAG` 常量定义 key，避免硬编码字符串
- `put` 方法返回 `this`，支持链式调用：`AjaxResult.success().put("token", token)`
- data 为 null 时不放入 Map，避免 JSON 中出现 `"data": null`

### 3.2 AjaxResult 静态工厂方法

```java
// 成功系列
public static AjaxResult success()
{
    return AjaxResult.success("操作成功");
}

public static AjaxResult success(Object data)
{
    return AjaxResult.success("操作成功", data);
}

public static AjaxResult success(String msg, Object data)
{
    return new AjaxResult(HttpStatus.SUCCESS, msg, data);
}

// 警告系列（状态码 601）
public static AjaxResult warn(String msg)
{
    return AjaxResult.warn(msg, null);
}

public static AjaxResult warn(String msg, Object data)
{
    return new AjaxResult(HttpStatus.WARN, msg, data);
}

// 错误系列
public static AjaxResult error()
{
    return AjaxResult.error("操作失败");
}

public static AjaxResult error(String msg)
{
    return AjaxResult.error(msg, null);
}

public static AjaxResult error(int code, String msg)
{
    return new AjaxResult(code, msg, null);
}

// 状态判断
public boolean isSuccess()
{
    return Objects.equals(HttpStatus.SUCCESS, this.get(CODE_TAG));
}
```

**设计要点**：
- 提供了三层状态：`success(200)` / `warn(601)` / `error(500)`，比传统的成功/失败二分法更精细
- `warn` 状态是若依的特色设计，用于"操作成功但有警告"的场景
- `error(int code, String msg)` 允许自定义错误码，方便与业务异常码对接

### 3.3 R<T> -- 泛型响应体

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/core/domain/R.java
public class R<T> implements Serializable
{
    private static final long serialVersionUID = 1L;

    public static final int SUCCESS = HttpStatus.SUCCESS;
    public static final int FAIL = HttpStatus.ERROR;

    private int code;
    private String msg;
    private T data;

    public static <T> R<T> ok()
    {
        return restResult(null, SUCCESS, "操作成功");
    }

    public static <T> R<T> ok(T data)
    {
        return restResult(data, SUCCESS, "操作成功");
    }

    public static <T> R<T> ok(T data, String msg)
    {
        return restResult(data, SUCCESS, msg);
    }

    public static <T> R<T> fail(String msg)
    {
        return restResult(null, FAIL, msg);
    }

    public static <T> R<T> fail(int code, String msg)
    {
        return restResult(null, code, msg);
    }

    private static <T> R<T> restResult(T data, int code, String msg)
    {
        R<T> apiResult = new R<>();
        apiResult.setCode(code);
        apiResult.setData(data);
        apiResult.setMsg(msg);
        return apiResult;
    }

    // 静态判断方法
    public static <T> Boolean isSuccess(R<T> ret)
    {
        return R.SUCCESS == ret.getCode();
    }
}
```

**设计要点**：
- 实现 `Serializable` 接口，支持序列化
- 泛型 `T` 保证了 `getData()` 返回的类型安全
- `restResult` 私有工厂方法统一构建，避免重复代码
- 没有 `warn` 状态，设计更简洁

### 3.4 HttpStatus -- 状态码常量

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/constant/HttpStatus.java
public class HttpStatus
{
    public static final int SUCCESS = 200;      // 操作成功
    public static final int CREATED = 201;       // 对象创建成功
    public static final int ACCEPTED = 202;      // 请求已经被接受
    public static final int NO_CONTENT = 204;    // 操作已执行成功，无返回数据
    public static final int MOVED_PERM = 301;    // 资源已被移除
    public static final int SEE_OTHER = 303;     // 重定向
    public static final int NOT_MODIFIED = 304;  // 资源没有被修改
    public static final int BAD_REQUEST = 400;   // 参数列表错误
    public static final int UNAUTHORIZED = 401; // 未授权
    public static final int FORBIDDEN = 403;    // 访问受限
    public static final int NOT_FOUND = 404;     // 资源未找到
    public static final int BAD_METHOD = 405;    // 不允许的HTTP方法
    public static final int CONFLICT = 409;      // 资源冲突
    public static final int UNSUPPORTED_TYPE = 415; // 不支持的数据类型
    public static final int ERROR = 500;        // 系统内部错误
    public static final int NOT_IMPLEMENTED = 501; // 接口未实现
    public static final int WARN = 601;          // 系统警告消息（自定义扩展）
}
```

**设计要点**：
- 覆盖了标准 HTTP 状态码（2xx/3xx/4xx/5xx）
- **601 是自定义扩展**，不属于标准 HTTP 规范，是若依的特色
- 注意：这里的 `HttpStatus` 是若依自定义的，**不是** Spring 的 `org.springframework.http.HttpStatus`

### 3.6 BaseController -- 统一返回的桥梁

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/core/controller/BaseController.java
public class BaseController
{
    // 分页数据响应
    protected TableDataInfo getDataTable(List<?> list)
    {
        TableDataInfo rspData = new TableDataInfo();
        rspData.setCode(HttpStatus.SUCCESS);
        rspData.setMsg("查询成功");
        rspData.setRows(list);
        rspData.setTotal(new PageInfo(list).getTotal());
        return rspData;
    }

    // 影响行数判断
    protected AjaxResult toAjax(int rows)
    {
        return rows > 0 ? AjaxResult.success() : AjaxResult.error();
    }

    protected AjaxResult toAjax(boolean result)
    {
        return result ? success() : error();
    }

    // 快捷方法
    public AjaxResult success() { return AjaxResult.success(); }
    public AjaxResult error() { return AjaxResult.error(); }
    public AjaxResult warn(String message) { return AjaxResult.warn(message); }
}
```

**设计要点**：
- `toAjax(int rows)` 是增删改操作的标准响应模式，rows > 0 返回成功
- `getDataTable` 利用 PageHelper 的 `PageInfo` 自动获取 total
- 所有 Controller 继承 `BaseController` 即可使用这些快捷方法

## 四、前端JSON响应格式

### AjaxResult 典型响应

```json
// 成功
{ "code": 200, "msg": "操作成功", "data": { "userId": 1, "userName": "admin" } }

// 成功带分页（TableDataInfo）
{ "code": 200, "msg": "查询成功", "total": 100, "rows": [...] }

// 警告
{ "code": 601, "msg": "操作成功，但部分数据存在问题" }

// 错误
{ "code": 500, "msg": "操作失败" }

// 权限不足
{ "code": 403, "msg": "没有权限，请联系管理员授权" }
```

### R<T> 典型响应

```json
// 成功
{ "code": 200, "msg": "操作成功", "data": "token_value" }

// 失败
{ "code": 500, "msg": "用户名或密码错误" }
```

## 五、AjaxResult vs R<T> 对比

| 对比维度 | AjaxResult | R<T> |
|---------|-----------|------|
| 基类 | HashMap<String, Object> | 普通POJO |
| 类型安全 | 弱（data是Object） | 强（data是T） |
| 可扩展性 | 强（可put任意key） | 弱（固定三个字段） |
| 链式调用 | 支持 | 不支持 |
| warn状态 | 支持 | 不支持 |
| 使用场景 | Controller通用返回 | 特定接口返回 |
| 序列化 | 自动（HashMap天然JSON） | 需要getter/setter |

## 六、细节留神

1. **AjaxResult 继承 HashMap 的隐患**：由于是 Map，任何代码都可以 `put` 额外的 key，可能导致返回结构不一致。建议团队约定只使用 `code/msg/data` 三个标准字段。

2. **601 状态码非标准**：`HttpStatus.WARN = 601` 是若依自定义的，前端需要专门处理这个状态码。如果对接第三方系统，需注意兼容性。

3. **TableDataInfo 的 rows 类型是 `List<?>`**：通配符泛型意味着前端拿到的 rows 中元素类型不确定，TypeScript 端需要手动定义接口类型。

4. **AjaxResult 的 data 为 null 时不存入 Map**：这意味着前端判断数据是否存在不能依赖 `data !== null`，而应该判断 `data !== undefined` 或直接判断 `code`。

5. **BaseController 的 toAjax 方法**：`rows > 0` 的判断意味着如果 MyBatis 的 `update` 返回 0（未更新任何行），也会返回 error，这在"幂等更新"场景下可能产生误导。

6. **R<T> 在项目中的使用较少**：目前主要在登录接口等少数地方使用，大部分 Controller 仍使用 AjaxResult。
