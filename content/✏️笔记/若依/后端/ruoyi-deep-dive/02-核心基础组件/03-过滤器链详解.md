## 二、核心设计思想

RuoYi-Vue 的过滤器链采用 **"分层防御"** 策略，每个过滤器负责单一职责：

```
请求 --> XssFilter --> RepeatableFilter --> CorsFilter --> JwtFilter --> RefererFilter --> Controller
```

过滤器分为两类：
- **Servlet Filter**（FilterConfig 注册）：XssFilter、RepeatableFilter、RefererFilter
- **Spring Security Filter**（SecurityConfig 注册）：CorsFilter、JwtAuthenticationTokenFilter

## 三、过滤器注册配置

### 3.1 FilterConfig -- Servlet过滤器注册

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/FilterConfig.java
@Configuration
public class FilterConfig
{
    @Value("${xss.excludes}")
    private String excludes;

    @Value("${xss.urlPatterns}")
    private String urlPatterns;

    @Value("${referer.allowed-domains}")
    private String allowedDomains;

    // XSS过滤器 -- 最高优先级
    @Bean
    @ConditionalOnProperty(value = "xss.enabled", havingValue = "true")
    public FilterRegistrationBean xssFilterRegistration()
    {
        FilterRegistrationBean registration = new FilterRegistrationBean();
        registration.setDispatcherTypes(DispatcherType.REQUEST);
        registration.setFilter(new XssFilter());
        registration.addUrlPatterns(StringUtils.split(urlPatterns, ","));
        registration.setName("xssFilter");
        registration.setOrder(FilterRegistrationBean.HIGHEST_PRECEDENCE);
        Map<String, String> initParameters = new HashMap<>();
        initParameters.put("excludes", excludes);
        registration.setInitParameters(initParameters);
        return registration;
    }

    // 防盗链过滤器 -- 最高优先级
    @Bean
    @ConditionalOnProperty(value = "referer.enabled", havingValue = "true")
    public FilterRegistrationBean refererFilterRegistration()
    {
        FilterRegistrationBean registration = new FilterRegistrationBean();
        registration.setDispatcherTypes(DispatcherType.REQUEST);
        registration.setFilter(new RefererFilter());
        registration.addUrlPatterns(Constants.RESOURCE_PREFIX + "/*");
        registration.setName("refererFilter");
        registration.setOrder(FilterRegistrationBean.HIGHEST_PRECEDENCE);
        Map<String, String> initParameters = new HashMap<>();
        initParameters.put("allowedDomains", allowedDomains);
        registration.setInitParameters(initParameters);
        return registration;
    }

    // 请求体可重复读过滤器 -- 最低优先级
    @Bean
    public FilterRegistrationBean someFilterRegistration()
    {
        FilterRegistrationBean registration = new FilterRegistrationBean();
        registration.setFilter(new RepeatableFilter());
        registration.addUrlPatterns("/*");
        registration.setName("repeatableFilter");
        registration.setOrder(FilterRegistrationBean.LOWEST_PRECEDENCE);
        return registration;
    }
}
```

**设计要点**：
- XSS 和 Referer 过滤器使用 `HIGHEST_PRECEDENCE`（最高优先级），在最前面执行
- RepeatableFilter 使用 `LOWEST_PRECEDENCE`（最低优先级），在最后执行
- XSS 和 Referer 过滤器支持通过配置文件开关控制（`@ConditionalOnProperty`）
- RefererFilter 只拦截 `/profile/*` 路径（静态资源），不影响 API 请求

### 3.2 SecurityConfig -- Spring Security过滤器链

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/SecurityConfig.java
@Bean
protected SecurityFilterChain filterChain(HttpSecurity httpSecurity) throws Exception
{
    return httpSecurity
        .csrf(csrf -> csrf.disable())
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests((requests) -> {
            requests.requestMatchers("/login", "/register", "/captchaImage").permitAll()
                .requestMatchers(HttpMethod.GET, "/", "/*.html", "/**.html", "/**.css", "/**.js", "/profile/**").permitAll()
                .anyRequest().authenticated();
        })
        // 添加JWT filter（在UsernamePasswordAuthenticationFilter之前）
        .addFilterBefore(authenticationTokenFilter, UsernamePasswordAuthenticationFilter.class)
        // 添加CORS filter（在JwtFilter和LogoutFilter之前）
        .addFilterBefore(corsFilter, JwtAuthenticationTokenFilter.class)
        .addFilterBefore(corsFilter, LogoutFilter.class)
        .build();
}
```

**Security过滤器链执行顺序**：
```
CorsFilter --> JwtAuthenticationTokenFilter --> LogoutFilter --> UsernamePasswordAuthenticationFilter --> ...
```

## 四、各过滤器详解

### 4.1 XssFilter -- XSS防护过滤器

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/filter/XssFilter.java
public class XssFilter implements Filter
{
    public List<String> excludes = new ArrayList<>();

    @Override
    public void init(FilterConfig filterConfig) throws ServletException
    {
        String tempExcludes = filterConfig.getInitParameter("excludes");
        if (StringUtils.isNotEmpty(tempExcludes))
        {
            String[] urls = tempExcludes.split(",");
            for (String url : urls)
            {
                excludes.add(url);
            }
        }
    }

    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException
    {
        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse resp = (HttpServletResponse) response;
        if (handleExcludeURL(req, resp))
        {
            chain.doFilter(request, response);
            return;
        }
        XssHttpServletRequestWrapper xssRequest = new XssHttpServletRequestWrapper((HttpServletRequest) request);
        chain.doFilter(xssRequest, response);
    }

    private boolean handleExcludeURL(HttpServletRequest request, HttpServletResponse response)
    {
        String url = request.getServletPath();
        String method = request.getMethod();
        // GET DELETE 不过滤
        if (method == null || HttpMethod.GET.matches(method) || HttpMethod.DELETE.matches(method))
        {
            return true;
        }
        return StringUtils.matches(url, excludes);
    }
}
```

**设计要点**：
- 使用 `XssHttpServletRequestWrapper` 包装原始 Request，对参数值进行 HTML 转义
- **GET 和 DELETE 请求不进行 XSS 过滤**，因为 GET 请求的参数通常用于查询，不修改数据
- 支持通过配置排除特定 URL（如富文本编辑器提交接口）
- `StringUtils.matches(url, excludes)` 使用 AntPathMatcher 进行路径匹配

### 4.2 RepeatableFilter -- 请求体可重复读过滤器

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/filter/RepeatableFilter.java
public class RepeatableFilter implements Filter
{
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException
    {
        ServletRequest requestWrapper = null;
        if (request instanceof HttpServletRequest
                && StringUtils.startsWithIgnoreCase(request.getContentType(), MediaType.APPLICATION_JSON_VALUE))
        {
            requestWrapper = new RepeatedlyRequestWrapper((HttpServletRequest) request, response);
        }
        if (null == requestWrapper)
        {
            chain.doFilter(request, response);
        }
        else
        {
            chain.doFilter(requestWrapper, response);
        }
    }
}
```

**设计要点**：
- **只对 `application/json` 类型的请求进行包装**，因为只有 JSON 请求体才需要重复读取
- `RepeatedlyRequestWrapper` 将请求体缓存到字节数组中，支持多次 `getInputStream()` 调用
- 这个过滤器解决了 HttpServletRequest 的 InputStream 只能读取一次的问题
- 为什么放在最低优先级？因为它需要包装 Request，后续过滤器应该使用原始 Request

**为什么需要 RepeatableFilter？**

```
场景：JwtAuthenticationTokenFilter 需要读取请求体中的 token
问题：HttpServletRequest 的 InputStream 只能读取一次
解决：RepeatableFilter 将请求体缓存，允许多次读取
```

### 4.3 CorsFilter -- 跨域过滤器

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/config/ResourcesConfig.java
@Bean
public CorsFilter corsFilter()
{
    CorsConfiguration config = new CorsConfiguration();
    config.addAllowedOriginPattern("*");  // 允许所有来源
    config.addAllowedHeader("*");         // 允许所有请求头
    config.addAllowedMethod("*");         // 允许所有HTTP方法
    config.setMaxAge(1800L);              // 预检请求缓存1800秒
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return new CorsFilter(source);
}
```

**设计要点**：
- 使用 `addAllowedOriginPattern("*")` 而非 `addAllowedOrigin("*")`，因为后者在 Spring 5.3+ 中已废弃
- 允许所有来源、所有请求头、所有方法，开发环境方便，**生产环境需收紧**
- `setMaxAge(1800L)` 减少预检请求（OPTIONS）的频率
- CorsFilter 放在 Security 过滤器链的最前面，确保跨域请求先被处理

### 4.4 JwtAuthenticationTokenFilter -- JWT认证过滤器

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/security/filter/JwtAuthenticationTokenFilter.java
@Component
public class JwtAuthenticationTokenFilter extends OncePerRequestFilter
{
    @Autowired
    private TokenService tokenService;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
            throws ServletException, IOException
    {
        LoginUser loginUser = tokenService.getLoginUser(request);
        if (StringUtils.isNotNull(loginUser) && StringUtils.isNull(SecurityUtils.getAuthentication()))
        {
            tokenService.verifyToken(loginUser);
            UsernamePasswordAuthenticationToken authenticationToken =
                new UsernamePasswordAuthenticationToken(loginUser, null, loginUser.getAuthorities());
            authenticationToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
            SecurityContextHolder.getContext().setAuthentication(authenticationToken);
        }
        chain.doFilter(request, response);
    }
}
```

**设计要点**：
- 继承 `OncePerRequestFilter`，确保每个请求只执行一次
- 从请求头中解析 token，验证有效性后设置到 `SecurityContextHolder`
- `StringUtils.isNull(SecurityUtils.getAuthentication())` 避免重复设置认证信息
- 即使 token 无效，也会 `chain.doFilter(request, response)` 放行，由后续 Security 机制处理未认证

### 4.5 RefererFilter -- 防盗链过滤器

```java
// 文件：ruoyi-common/src/main/java/com/ruoyi/common/filter/RefererFilter.java
public class RefererFilter implements Filter
{
    public List<String> allowedDomains;

    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException
    {
        HttpServletRequest req = (HttpServletRequest) request;
        HttpServletResponse resp = (HttpServletResponse) response;

        String referer = req.getHeader("Referer");

        // Referer为空，拒绝访问
        if (referer == null || referer.isEmpty())
        {
            resp.sendError(HttpServletResponse.SC_FORBIDDEN, "Access denied: Referer header is required");
            return;
        }

        // 检查Referer是否在允许的域名列表中
        boolean allowed = false;
        for (String domain : allowedDomains)
        {
            if (referer.contains(domain))
            {
                allowed = true;
                break;
            }
        }

        if (allowed)
        {
            chain.doFilter(request, response);
        }
        else
        {
            resp.sendError(HttpServletResponse.SC_FORBIDDEN,
                "Access denied: Referer '" + referer + "' is not allowed");
        }
    }
}
```

**设计要点**：
- 只拦截 `/profile/*` 路径（静态资源），不影响 API 请求
- Referer 为空直接拒绝，防止直接通过 URL 访问资源
- 使用 `contains` 匹配域名，简单但有效
- 通过 `referer.allowed-domains` 配置允许的域名列表

## 五、完整过滤器执行顺序

```
HTTP请求
    |
    v
[Servlet Filter 链]
    |
    +--> XssFilter (HIGHEST_PRECEDENCE)     -- XSS防护
    +--> RefererFilter (HIGHEST_PRECEDENCE)  -- 防盗链（仅/profile/*）
    +--> RepeatableFilter (LOWEST_PRECEDENCE) -- 请求体可重复读
    |
    v
[Spring Security Filter 链]
    |
    +--> CorsFilter                           -- 跨域处理
    +--> JwtAuthenticationTokenFilter          -- JWT认证
    +--> LogoutFilter                          -- 登出处理
    +--> UsernamePasswordAuthenticationFilter   -- Spring Security认证
    +--> ...其他Security过滤器
    |
    v
[Spring MVC DispatcherServlet]
    |
    v
Controller
```

## 六、细节留神

1. **XSS 过滤器对 GET 请求不生效**：这意味着通过 URL 参数注入的 XSS 攻击不会被过滤。前端需要自行转义。

2. **RepeatableFilter 放在最低优先级**：这意味着 XSS 过滤器处理的是原始 Request 而非包装后的 Request。如果 XSS 过滤器需要读取请求体，可能会消耗掉 InputStream。

3. **CorsFilter 允许所有来源**：`addAllowedOriginPattern("*")` 在生产环境有安全风险，建议配置具体的域名白名单。

4. **RefererFilter 使用 contains 匹配**：`referer.contains(domain)` 可能被绕过，例如配置 `allowed.com` 但 `evil-allowed.com` 也能匹配。

5. **JwtFilter 不抛异常**：token 无效时不抛异常而是放行，依赖后续的 `AuthenticationEntryPointImpl` 处理未认证请求。

6. **XSS 过滤器的 excludes 配置**：富文本编辑器等接口需要排除 XSS 过滤，但排除过多会降低安全性。

## 七、提问方向

1. **XssFilter 对 GET 和 DELETE 请求不做过滤，这种设计是否安全？如果 GET 请求的参数被用于日志记录或数据库查询，是否存在 XSS 风险？**

2. **RepeatableFilter 放在最低优先级（最后执行），而 XSS 过滤器在最高优先级（最先执行）。如果 XSS 过滤器需要读取请求体内容，是否会产生冲突？**

3. **CorsFilter 允许所有来源（`*`），在生产环境中如何收紧跨域策略？你会如何设计支持多环境的跨域配置？**

4. **RefererFilter 使用 `contains` 匹配域名，这种方式存在被绕过的风险。你会如何改进域名匹配逻辑？**

5. **JwtAuthenticationTokenFilter 在 token 无效时不抛异常而是放行，这种设计有什么好处？如果需要记录非法 token 的访问日志，你会如何改造？**

6. **如果要在过滤器链中增加一个"请求日志过滤器"（记录请求和响应的完整信息），应该放在哪个位置？为什么？**

7. **当前 XSS 过滤器是基于 Servlet Filter 实现的，如果改用 Spring 的 `ContentNegotiatingViewResolver` 或 Jackson 的序列化层来做 XSS 过滤，各有什么优缺点？**

8. **在分布式部署场景下，多个实例的过滤器配置如何保持一致？你会如何设计统一的安全策略管理？**
