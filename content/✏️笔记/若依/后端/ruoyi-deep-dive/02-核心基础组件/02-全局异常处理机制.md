## 二、核心设计思想

RuoYi-Vue 的全局异常处理基于 Spring 的 `@RestControllerAdvice` 注解，实现了 **"异常分级处理"** 策略：

1. **权限异常**（AccessDeniedException）-- 403
2. **请求方法异常**（HttpRequestMethodNotSupportedException）
3. **业务异常**（ServiceException）-- 支持自定义错误码
4. **参数校验异常**（BindException / MethodArgumentNotValidException）
5. **路径参数缺失**（MissingPathVariableException）
6. **参数类型不匹配**（MethodArgumentTypeMismatchException）
7. **演示模式异常**（DemoModeException）
8. **运行时异常**（RuntimeException）
9. **兜底异常**（Exception）

所有异常最终都统一返回 `AjaxResult` 格式，保证前端接收到的数据结构一致。

## 三、源码关键片段引用

### 3.1 GlobalExceptionHandler 整体结构

```java
// 文件：ruoyi-framework/src/main/java/com/ruoyi/framework/web/exception/GlobalExceptionHandler.java
@RestControllerAdvice
public class GlobalExceptionHandler
{
    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    // 9个异常处理方法，按优先级从高到低排列
    // ...
}
```

**设计要点**：
- `@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody`，异常方法返回值直接序列化为 JSON
- 每个异常处理方法都接收 `HttpServletRequest` 参数，用于记录请求地址
- 所有方法返回 `AjaxResult`，保持响应格式统一

### 3.2 权限校验异常处理

```java
@ExceptionHandler(AccessDeniedException.class)
public AjaxResult handleAccessDeniedException(AccessDeniedException e, HttpServletRequest request)
{
    String requestURI = request.getRequestURI();
    log.error("请求地址'{}',权限校验失败'{}'", requestURI, e.getMessage());
    return AjaxResult.error(HttpStatus.FORBIDDEN, "没有权限，请联系管理员授权");
}
```

**设计要点**：
- 使用 `HttpStatus.FORBIDDEN`（403）作为状态码
- 日志记录请求地址和异常信息，方便排查权限问题
- 返回固定的中文提示信息，不暴露内部错误细节

### 3.3 业务异常处理 -- 核心中的核心

```java
@ExceptionHandler(ServiceException.class)
public AjaxResult handleServiceException(ServiceException e, HttpServletRequest request)
{
    log.error(e.getMessage(), e);
    Integer code = e.getCode();
    return StringUtils.isNotNull(code)
        ? AjaxResult.error(code, e.getMessage())
        : AjaxResult.error(e.getMessage());
}
```

**设计要点**：
- `ServiceException` 是项目中使用最频繁的异常类型
- 支持自定义错误码：如果 `ServiceException` 设置了 code，则使用自定义 code；否则使用默认的 500
- `log.error(e.getMessage(), e)` 同时记录消息和完整堆栈

### 3.4 参数校验异常处理

```java
// BindException -- 表单绑定校验异常
@ExceptionHandler(BindException.class)
public AjaxResult handleBindException(BindException e)
{
    log.error(e.getMessage(), e);
    String message = e.getAllErrors().get(0).getDefaultMessage();
    return AjaxResult.error(message);
}

// MethodArgumentNotValidException -- @Valid 注解校验异常
@ExceptionHandler(MethodArgumentNotValidException.class)
public Object handleMethodArgumentNotValidException(MethodArgumentNotValidException e)
{
    log.error(e.getMessage(), e);
    String message = e.getBindingResult().getFieldError().getDefaultMessage();
    return AjaxResult.error(message);
}
```

**设计要点**：
- 两种校验异常分别处理：`BindException` 用于表单提交，`MethodArgumentNotValidException` 用于 JSON 请求体
- 只取第一个错误信息 `get(0).getDefaultMessage()`，避免返回过多错误信息
- 返回的是校验注解中定义的消息（如 `@NotBlank(message = "用户名不能为空")`）

### 3.5 参数类型不匹配异常

```java
@ExceptionHandler(MethodArgumentTypeMismatchException.class)
public AjaxResult handleMethodArgumentTypeMismatchException(
        MethodArgumentTypeMismatchException e, HttpServletRequest request)
{
    String requestURI = request.getRequestURI();
    String value = Convert.toStr(e.getValue());
    if (StringUtils.isNotEmpty(value))
    {
        value = EscapeUtil.clean(value);  // XSS清洗
    }
    log.error("请求参数类型不匹配'{}',发生系统异常.", requestURI, e);
    return AjaxResult.error(String.format(
        "请求参数类型不匹配，参数[%s]要求类型为：'%s'，但输入值为：'%s'",
        e.getName(), e.getRequiredType().getName(), value));
}
```

**设计要点**：
- 对用户输入值进行 `EscapeUtil.clean()` XSS 清洗，防止错误信息中注入恶意脚本
- 使用 `String.format` 构建详细的错误提示，包含参数名、期望类型和实际值
- 注意返回值类型是 `Object` 而非 `AjaxResult`，这里其实可以直接用 `AjaxResult`

### 3.6 兜底异常处理

```java
// RuntimeException 兜底
@ExceptionHandler(RuntimeException.class)
public AjaxResult handleRuntimeException(RuntimeException e, HttpServletRequest request)
{
    String requestURI = request.getRequestURI();
    log.error("请求地址'{}',发生未知异常.", requestURI, e);
    return AjaxResult.error(e.getMessage());
}

// Exception 最终兜底
@ExceptionHandler(Exception.class)
public AjaxResult handleException(Exception e, HttpServletRequest request)
{
    String requestURI = request.getRequestURI();
    log.error("请求地址'{}',发生系统异常.", requestURI, e);
    return AjaxResult.error(e.getMessage());
}
```

**设计要点**：
- 两层兜底：先拦截 `RuntimeException`，再拦截 `Exception`
- 兜底异常直接返回 `e.getMessage()`，**可能暴露内部实现细节**，生产环境需注意
- 日志中记录完整请求地址，方便排查问题

### 3.7 演示模式异常

```java
@ExceptionHandler(DemoModeException.class)
public AjaxResult handleDemoModeException(DemoModeException e)
{
    return AjaxResult.error("演示模式，不允许操作");
}
```

**设计要点**：
- 演示模式是若依的特色功能，用于在线演示环境防止数据被修改
- 不记录日志，因为这不是真正的错误

## 四、异常处理优先级

Spring `@ExceptionHandler` 的匹配规则是：**最具体的异常类型优先匹配**。处理顺序如下：

```
AccessDeniedException          --> 403 权限不足
HttpRequestMethodNotSupportedException --> 请求方法不支持
ServiceException               --> 自定义业务错误码
MissingPathVariableException   --> 路径参数缺失
MethodArgumentTypeMismatchException --> 参数类型不匹配
BindException                  --> 表单校验异常
MethodArgumentNotValidException --> @Valid校验异常
DemoModeException              --> 演示模式
RuntimeException                --> 未知运行时异常
Exception                      --> 最终兜底
```

## 五、异常处理流程图

```
请求进入Controller
    |
    v
业务逻辑执行（可能抛出异常）
    |
    v
Spring MVC 捕获异常
    |
    v
GlobalExceptionHandler 匹配 @ExceptionHandler
    |
    +--> AccessDeniedException --> 403
    +--> ServiceException --> 自定义code或500
    +--> BindException --> 校验错误消息
    +--> MethodArgumentNotValidException --> 校验错误消息
    +--> RuntimeException --> 500
    +--> Exception --> 500（兜底）
    |
    v
统一返回 AjaxResult JSON
```

## 六、细节留神

1. **ServiceException 不继承 BaseException**：`ServiceException` 直接继承 `RuntimeException`，而 `UserException`/`FileException` 继承 `BaseException`。这意味着 `ServiceException` 不支持国际化消息，而 `UserException` 支持。

2. **兜底异常直接返回 e.getMessage()**：这在生产环境中可能泄露敏感信息（如 SQL 错误、文件路径等）。建议在生产环境配置中返回通用错误信息。

3. **缺少自定义异常处理的统一日志格式**：各异常处理方法的日志格式不完全一致，有的记录 requestURI，有的不记录。

4. **MethodArgumentTypeMismatchException 返回类型是 Object**：虽然实际返回的是 `AjaxResult`，但方法签名声明为 `Object`，可能是历史遗留问题。

5. **没有 @ControllerAdvice 的 basePackages 限制**：`@RestControllerAdvice` 没有指定包范围，会拦截所有 Controller 的异常。在多模块项目中可能需要限制范围。

6. **缺少异步异常处理**：`@Async` 方法抛出的异常不会被 `@RestControllerAdvice` 捕获，需要通过 `AsyncUncaughtExceptionHandler` 单独处理。

## 七、提问方向

1. **GlobalExceptionHandler 中兜底异常直接返回 `e.getMessage()`，这在生产环境可能泄露敏感信息。你会如何改进，使其在生产环境返回通用信息而在开发环境返回详细信息？**

2. **ServiceException 直接继承 RuntimeException，而 UserException 继承 BaseException 支持国际化。你认为这种不一致的设计是否合理？如何统一？**

3. **如果项目需要支持多语言错误消息（中英文切换），当前的异常处理机制需要做哪些改造？**

4. **在微服务架构中，全局异常处理器只能处理当前服务的异常。如果调用下游服务返回了错误，你如何设计统一的异常传递机制？**

5. **当前缺少 @Async 异步任务的异常处理，如果异步任务抛出异常，你如何设计统一的异步异常处理机制？**

6. **参数校验异常只返回第一条错误信息，如果前端需要展示所有校验错误，你会如何改进？**

7. **GlobalExceptionHandler 没有设置 basePackages，在大型项目中可能产生冲突。你会如何设计模块化的异常处理机制？**

8. **如果要在异常处理中增加"异常告警"功能（如发送钉钉/企业微信通知），你会如何设计？如何避免告警风暴？**
