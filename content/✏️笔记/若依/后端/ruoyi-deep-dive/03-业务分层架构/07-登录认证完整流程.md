# 07 - 登录认证完整流程

> 本文档深入剖析 RuoYi-Vue 登录认证的完整流程，从验证码生成到退出登录的全链路分析，涵盖验证码校验、用户名密码校验、密码错误锁定、Spring Security 认证、JWT Token 生成、Redis 缓存、JWT 过滤器验证、Token 刷新和退出登录。

## 一、认证架构总览

RuoYi-Vue 的认证体系基于 **Spring Security + JWT + Redis** 三者结合：

```
┌─────────────────────────────────────────────────────────────┐
│                    认证架构全景图                              │
│                                                             │
│  ┌──────────┐    ┌──────────────┐    ┌──────────────────┐   │
│  │ 验证码    │    │ Spring       │    │ JWT Token        │   │
│  │ (Redis)   │───→│ Security     │───→│ (生成/验证/刷新)  │   │
│  └──────────┘    │ (认证管理器)  │    └────────┬─────────┘   │
│                  └──────┬───────┘             │              │
│                         │              ┌─────▼──────┐      │
│                  ┌──────▼───────┐       │ Redis      │      │
│                  │ UserDetails  │       │ (缓存Token │      │
│                  │ Service      │       │  和用户信息) │      │
│                  └──────────────┘       └────────────┘      │
│                                                             │
│  请求过滤器链：                                               │
│  CorsFilter → JwtFilter → Spring Security → Controller      │
└─────────────────────────────────────────────────────────────┘
```

### 核心组件

| 组件 | 类名 | 职责 |
|------|------|------|

### 3.2 关键源码引用

```java
// 文件：ruoyi-admin/.../SysLoginController.java
@PostMapping("/login")
public AjaxResult login(@RequestBody LoginBody loginBody) {
    AjaxResult ajax = AjaxResult.success();
    String token = loginService.login(loginBody.getUsername(), loginBody.getPassword(),
            loginBody.getCode(), loginBody.getUuid());
    ajax.put(Constants.TOKEN, token);
    return ajax;
}

// 文件：ruoyi-framework/.../SysLoginService.java
public String login(String username, String password, String code, String uuid) {
    // Step 1: 验证码校验
    validateCaptcha(username, code, uuid);
    // Step 2: 前置校验
    loginPreCheck(username, password);
    // Step 3: Spring Security 认证
    Authentication authentication = null;
    try {
        UsernamePasswordAuthenticationToken authenticationToken =
            new UsernamePasswordAuthenticationToken(username, password);
        AuthenticationContextHolder.setContext(authenticationToken);
        authentication = authenticationManager.authenticate(authenticationToken);
    } catch (Exception e) {
        if (e instanceof BadCredentialsException) {
            AsyncManager.me().execute(AsyncFactory.recordLogininfor(username,
                Constants.LOGIN_FAIL, MessageUtils.message("user.password.not.match")));
            throw new UserPasswordNotMatchException();
        }
        // ...
    } finally {
        AuthenticationContextHolder.clearContext();
    }
    // Step 4: 认证成功
    AsyncManager.me().execute(AsyncFactory.recordLogininfor(username,
        Constants.LOGIN_SUCCESS, MessageUtils.message("user.login.success")));
    LoginUser loginUser = (LoginUser) authentication.getPrincipal();
    recordLoginInfo(loginUser.getUserId());
    return tokenService.createToken(loginUser);
}

// 文件：ruoyi-framework/.../UserDetailsServiceImpl.java
@Override
public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
    SysUser user = userService.selectUserByUserName(username);
    if (StringUtils.isNull(user)) {
        log.info("登录用户：{} 不存在.", username);
        throw new ServiceException(MessageUtils.message("user.not.exists"));
    }
    else if (UserStatus.DELETED.getCode().equals(user.getDelFlag())) {
        throw new ServiceException(MessageUtils.message("user.password.delete"));
    }
    else if (UserStatus.DISABLE.getCode().equals(user.getStatus())) {
        throw new ServiceException(MessageUtils.message("user.blocked"));
    }
    passwordService.validate(user);
    return createLoginUser(user);
}
```

## 四、JWT Token 生成机制

### 4.1 Token 生成流程

```java
// 文件：ruoyi-framework/.../TokenService.java
public String createToken(LoginUser loginUser) {
    String token = IdUtils.fastUUID();              // 生成 UUID
    loginUser.setToken(token);
    setUserAgent(loginUser);                          // 设置 IP、浏览器、OS
    refreshToken(loginUser);                          // 刷新 Token 缓存

    Map<String, Object> claims = new HashMap<>();
    claims.put(Constants.LOGIN_USER_KEY, token);      // UUID
    claims.put(Constants.JWT_USERNAME, loginUser.getUsername());  // 用户名
    return createToken(claims);                       // 生成 JWT
}

private String createToken(Map<String, Object> claims) {
    return Jwts.builder()
        .setClaims(claims)
        .signWith(SignatureAlgorithm.HS512, secret)  // HS512 签名
        .compact();
}
```

### 4.2 JWT Token 结构

```
JWT Token = Header.Payload.Signature

Header:  { "alg": "HS512" }
Payload: { "login_user_key": "uuid-xxx", "sub": "admin" }
Signature: HS512 签名值

Redis 缓存:
  Key:   login_tokens:uuid-xxx
  Value: LoginUser { userId, deptId, user, permissions, token, loginTime, expireTime, ipaddr, ... }
  TTL:   30 分钟（可配置）
```

### 4.3 Token 与 Redis 的关系

```
JWT Token 本身只包含 uuid 和 username（不包含敏感信息）
真正的用户信息存储在 Redis 中
每次请求时通过 JWT 中的 uuid 去 Redis 查找 LoginUser
这样做的好处：
  1. JWT Token 体积小
  2. 可以主动使 Token 失效（删除 Redis 中的缓存）
  3. Token 刷新只需更新 Redis 中的过期时间
```

## 五、后续请求 JWT 验证流程

### 5.1 过滤器链

```java
// 文件：ruoyi-framework/.../SecurityConfig.java
@Bean
protected SecurityFilterChain filterChain(HttpSecurity httpSecurity) throws Exception {
    return httpSecurity
        .csrf(csrf -> csrf.disable())
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests((requests) -> {
            requests.requestMatchers("/login", "/register", "/captchaImage").permitAll()
                .anyRequest().authenticated();
        })
        .logout(logout -> logout.logoutUrl("/logout").logoutSuccessHandler(logoutSuccessHandler))
        .addFilterBefore(authenticationTokenFilter, UsernamePasswordAuthenticationFilter.class)
        .addFilterBefore(corsFilter, JwtAuthenticationTokenFilter.class)
        .build();
}
```

### 5.2 JWT 过滤器验证流程

```
每次 HTTP 请求到达 Controller 之前
    │
    ▼
JwtAuthenticationTokenFilter.doFilterInternal(request, response, chain)
    │
    ├─ 1. tokenService.getLoginUser(request)
    │     ├─ 从请求头获取 Token：request.getHeader("Authorization")
    │     ├─ 去掉前缀 "Bearer "：token.replace("Bearer ", "")
    │     ├─ 解析 JWT：parseToken(token) → 获取 claims
    │     ├─ 从 claims 获取 UUID：claims.get("login_user_key")
    │     ├─ 从 Redis 获取 LoginUser：redisCache.getCacheObject("login_tokens:" + uuid)
    │     └─ 如果 Token 无效或 Redis 中无缓存 → 返回 null
    │
    ├─ 2. 如果 loginUser 不为 null 且 SecurityContext 中无认证信息
    │     ├─ tokenService.verifyToken(loginUser)
    │     │   └─ 如果距过期不足 20 分钟 → refreshToken(loginUser)  [自动续期]
    │     ├─ 创建 AuthenticationToken：new UsernamePasswordAuthenticationToken(loginUser, null, authorities)
    │     ├─ 设置到 SecurityContext：SecurityContextHolder.getContext().setAuthentication(token)
    │     └─ 后续 @PreAuthorize 可以从 SecurityContext 获取认证信息
    │
    └─ 3. chain.doFilter(request, response)  → 继续过滤器链
```

**源码引用：**

```java
// 文件：ruoyi-framework/.../security/filter/JwtAuthenticationTokenFilter.java
@Component
public class JwtAuthenticationTokenFilter extends OncePerRequestFilter {
    @Autowired
    private TokenService tokenService;

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
            FilterChain chain) throws ServletException, IOException {
        LoginUser loginUser = tokenService.getLoginUser(request);
        if (StringUtils.isNotNull(loginUser) && StringUtils.isNull(SecurityUtils.getAuthentication())) {
            tokenService.verifyToken(loginUser);
            UsernamePasswordAuthenticationToken authenticationToken =
                new UsernamePasswordAuthenticationToken(loginUser, null, loginUser.getAuthorities());
            authenticationToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
            SecurityContextHolder.getContext().setAuthentication(authenticationToken);
        }
        chain.doFilter(request, response);
    }
}
```

## 六、Token 刷新机制

### 6.1 自动续期

```java
// 文件：ruoyi-framework/.../TokenService.java
public void verifyToken(LoginUser loginUser) {
    long expireTime = loginUser.getExpireTime();
    long currentTime = System.currentTimeMillis();
    if (expireTime - currentTime <= MILLIS_MINUTE_TWENTY) {  // 不足20分钟
        refreshToken(loginUser);  // 自动续期
    }
}

public void refreshToken(LoginUser loginUser) {
    loginUser.setLoginTime(System.currentTimeMillis());
    loginUser.setExpireTime(loginUser.getLoginTime() + expireTime * MILLIS_MINUTE);
    String userKey = getTokenKey(loginUser.getToken());
    redisCache.setCacheObject(userKey, loginUser, expireTime, TimeUnit.MINUTES);
}
```

**续期策略：** 滑动窗口，每次请求时检查，如果距过期不足 20 分钟则自动续期 30 分钟。

### 6.2 Token 刷新流程图

```
Token 有效期：30 分钟
自动续期阈值：20 分钟

时间线：
  0min        10min       20min       30min
  ├───────────┼───────────┼───────────┤
  │ 登录      │ 正常使用   │ ← 触发续期 │ 过期
  │           │           │           │

  如果用户在 25 分钟时发起请求：
  → 距过期还有 5 分钟（< 20分钟）
  → 自动续期 30 分钟
  → 新过期时间 = 当前时间 + 30分钟 = 55 分钟
```

## 七、退出登录流程

```
前端 POST /logout  Header: Authorization: Bearer xxx
    │
    ▼
SecurityConfig 配置的 logoutUrl("/logout")
    │
    ▼
LogoutSuccessHandlerImpl.onLogoutSuccess(request, response, authentication)
    │
    ├─ 1. 从请求头获取 Token
    ├─ 2. tokenService.getLoginUser(request) → 获取 LoginUser
    ├─ 3. tokenService.delLoginUser(token) → 删除 Redis 缓存
    │     → redisCache.deleteObject("login_tokens:" + uuid)
    ├─ 4. AsyncManager 记录退出日志
    └─ 5. 返回成功响应
```

**退出后 Token 立即失效**：Redis 中的 LoginUser 被删除，后续请求即使携带 JWT 也无法通过验证。

## 十、细节留神

1. **JWT Token 不包含用户权限信息**：Token 中只有 uuid 和 username，权限信息存储在 Redis 的 LoginUser 中。这意味着修改权限后只需更新 Redis，无需重新生成 Token
2. **验证码是一次性的**：`validateCaptcha` 中获取验证码后立即 `redisCache.deleteObject(verifyKey)`，无论验证成功还是失败
3. **密码错误锁定机制**：`SysPasswordService` 会记录密码错误次数，超过限制后自动停用用户。这是在 `BadCredentialsException` 捕获后触发的
4. **Token 自动续期是"滑动窗口"**：不是固定时间续期，而是每次请求检查剩余时间，不足 20 分钟才续期
5. **AuthenticationContextHolder 使用 ThreadLocal**：在 `SysLoginService.login()` 的 finally 块中清理，防止内存泄漏
6. **登录日志异步记录**：`AsyncManager.me().execute(AsyncFactory.recordLogininfor(...))` 使用异步线程池记录，不影响登录响应速度

## 十一、提问方向

1. **RuoYi-Vue 的 JWT Token 中只包含 uuid 和 username，不包含过期时间和权限信息。如果 Redis 宕机，所有用户会怎样？有没有办法让 JWT Token 在无 Redis 的情况下也能工作？**

2. **Token 自动续期的阈值是 20 分钟（`MILLIS_MINUTE_TWENTY`），如果用户在 21 分钟时发起请求，距过期还有 9 分钟，不会触发续期。如果用户在 29 分钟时又发起一次请求，距过期只有 1 分钟，仍然不会续期。这种设计是否合理？如何避免 Token 在活跃使用中过期？**

3. **验证码校验在 `SysLoginService` 中实现，而不是在 Spring Security 的过滤器中。如果攻击者直接调用 `authenticationManager.authenticate()` 绕过验证码，会发生什么？如何防止这种绕过？**

4. **密码错误锁定机制在 `SysPasswordService` 中实现，锁定后用户状态变为"停用"。管理员如何解锁被锁定的用户？如果管理员自己也因为密码错误被锁定了怎么办？**

5. **`JwtAuthenticationTokenFilter` 继承了 `OncePerRequestFilter`，确保每个请求只过滤一次。但如果前端在同一个页面同时发起多个 AJAX 请求，每个请求都会经过这个过滤器，都会检查 Redis。在高并发场景下，这是否会成为性能瓶颈？**

6. **退出登录时删除 Redis 中的 LoginUser，但如果用户在退出后仍然持有 JWT Token（前端未清除），再次请求时 `getLoginUser` 返回 null，Spring Security 会返回 401。这个过程是否有安全风险？Token 本身是否还能被利用？**

7. **RuoYi-Vue 使用 HS512 算法签名 JWT，secret 存储在配置文件中。如果配置文件泄露，攻击者可以伪造任意用户的 Token。如何增强 JWT 的安全性？是否应该使用非对称加密（RS256）？**
