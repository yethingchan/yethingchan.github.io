# 01 - 分层架构总览

> 本文档深入剖析 RuoYi-Vue 项目的分层架构设计，涵盖 Controller / Service / Mapper 三层职责划分、依赖关系和设计原则。

---

## 一、整体架构概览

RuoYi-Vue 采用经典的 **三层架构（Three-Tier Architecture）**，基于 Spring Boot + Spring MVC + MyBatis 技术栈，将业务逻辑按照职责清晰划分为三层：

```
┌─────────────────────────────────────────────────────────┐
│                    前端 (ruoyi-ui)                        │
│              Vue + Element UI / Axios                    │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP 请求 (RESTful API)
                       ▼
┌─────────────────────────────────────────────────────────┐
│              Controller 层 (ruoyi-admin)                  │
│    接收请求 → 参数校验 → 权限控制 → 调用Service → 返回    │
│    继承 BaseController，使用注解驱动                       │
└──────────────────────┬──────────────────────────────────┘
                       │ 接口调用
                       ▼
┌─────────────────────────────────────────────────────────┐
│              Service 层 (ruoyi-system / ruoyi-framework)│
│    接口定义(ISysXxxService) + 实现类(SysXxxServiceImpl)   │
│    事务管理 → 业务逻辑 → 数据权限 → 调用Mapper            │
└──────────────────────┬──────────────────────────────────┘
                       │ 接口调用
                       ▼
┌─────────────────────────────────────────────────────────┐
│              Mapper 层 (ruoyi-system)                     │
│    Mapper接口(SysXxxMapper.java) + XML映射(SysXxxMapper.xml)│
│    SQL映射 → PageHelper分页 → 数据权限SQL拼接             │
└──────────────────────┬──────────────────────────────────┘
                       │ JDBC
                       ▼
┌─────────────────────────────────────────────────────────┐
│                    数据库 (MySQL)                          │
└─────────────────────────────────────────────────────────┘
```

## 二、项目模块划分与三层对应关系

RuoYi-Vue 的 Maven 多模块结构如下，每一层对应不同的模块：

| 模块 | 职责 | 包路径 |
|------|------|--------|
| **ruoyi-admin** | Controller 层，启动入口 | `com.ruoyi.web.controller` |
| **ruoyi-framework** | 框架层（安全、切面、过滤器） | `com.ruoyi.framework` |
| **ruoyi-system** | Service 层 + Mapper 层 | `com.ruoyi.system.service` / `com.ruoyi.system.mapper` |
| **ruoyi-common** | 公共工具类、注解、常量、域对象 | `com.ruoyi.common` |
| **ruoyi-generator** | 代码生成器（独立的完整三层） | `com.ruoyi.generator` |
| **ruoyi-quartz** | 定时任务（独立的完整三层） | `com.ruoyi.quartz` |

### 模块依赖关系

```
ruoyi-admin
  ├── ruoyi-framework
  │     ├── ruoyi-system
  │     │     └── ruoyi-common
  │     └── ruoyi-common
  ├── ruoyi-system
  │     └── ruoyi-common
  ├── ruoyi-generator
  │     └── ruoyi-common
  └── ruoyi-quartz
        └── ruoyi-common
```

**关键设计要点：**
- `ruoyi-admin` 作为启动模块，聚合所有功能模块
- `ruoyi-common` 是最底层模块，被所有模块依赖
- `ruoyi-system` 包含 Service 接口、Service 实现、Mapper 接口和 XML 映射文件
- `ruoyi-framework` 包含安全配置、AOP 切面、过滤器等横切关注点

## 三、各层职责详解

### 3.1 Controller 层职责

Controller 层是整个应用的入口，负责：

1. **接收和解析 HTTP 请求**：接收前端发来的 RESTful 请求，解析路径变量、请求参数、请求体
2. **参数校验**：通过 `@Validated` 注解触发 JSR-303 校验
3. **权限控制**：通过 `@PreAuthorize` 注解进行细粒度权限校验
4. **操作日志记录**：通过 `@Log` 注解标记需要记录日志的操作
5. **调用 Service 层**：将业务逻辑委托给 Service 层处理
6. **封装返回值**：统一使用 `AjaxResult` 或 `TableDataInfo` 封装响应

**源码位置：** `ruoyi-admin/src/main/java/com/ruoyi/web/controller/`

**典型 Controller 代码片段（SysUserController）：**

```java
// 文件：ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java

@RestController
@RequestMapping("/system/user")
public class SysUserController extends BaseController
{
    @Autowired
    private ISysUserService userService;

    @PreAuthorize("@ss.hasPermi('system:user:list')")
    @GetMapping("/list")
    public TableDataInfo list(SysUser user)
    {
        startPage();
        List<SysUser> list = userService.selectUserList(user);
        return getDataTable(list);
    }
}
```

### 3.2 Service 层职责

Service 层是业务逻辑的核心，负责：

1. **业务逻辑编排**：实现具体的业务规则和流程
2. **事务管理**：通过 `@Transactional` 注解管理数据库事务
3. **数据权限控制**：通过 `@DataScope` 注解实现数据级别的权限过滤
4. **业务校验**：唯一性校验、数据范围校验、操作权限校验
5. **多 Mapper 协调**：一个 Service 可能注入多个 Mapper，协调完成复杂业务

**源码位置：**
- 接口：`ruoyi-system/src/main/java/com/ruoyi/system/service/ISysXxxService.java`
- 实现：`ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysXxxServiceImpl.java`

**典型 Service 代码片段（SysUserServiceImpl）：**

```java
// 文件：ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java

@Service
public class SysUserServiceImpl implements ISysUserService
{
    @Autowired
    private SysUserMapper userMapper;
    @Autowired
    private SysUserRoleMapper userRoleMapper;
    @Autowired
    private SysUserPostMapper userPostMapper;

    @Override
    @DataScope(deptAlias = "d", userAlias = "u")
    public List<SysUser> selectUserList(SysUser user)
    {
        return userMapper.selectUserList(user);
    }

    @Override
    @Transactional
    public int insertUser(SysUser user)
    {
        int rows = userMapper.insertUser(user);
        insertUserPost(user);
        insertUserRole(user);
        return rows;
    }
}
```

### 3.3 Mapper 层职责

Mapper 层是数据访问层，负责：

1. **SQL 映射**：将 Java 方法调用映射为 SQL 语句
2. **结果映射**：将数据库查询结果映射为 Java 对象
3. **分页支持**：配合 PageHelper 实现物理分页
4. **数据权限 SQL 拼接**：通过 `${params.dataScope}` 支持动态 SQL 拼接

**源码位置：**
- 接口：`ruoyi-system/src/main/java/com/ruoyi/system/mapper/SysXxxMapper.java`
- XML：`ruoyi-system/src/main/resources/mapper/system/SysXxxMapper.xml`

**典型 Mapper 接口代码片段（SysUserMapper）：**

```java
// 文件：ruoyi-system/src/main/java/com/ruoyi/system/mapper/SysUserMapper.java

public interface SysUserMapper
{
    public List<SysUser> selectUserList(SysUser sysUser);
    public SysUser selectUserByUserName(String userName);
    public int insertUser(SysUser user);
    public int updateUser(SysUser user);
    public int deleteUserByIds(Long[] userIds);
}
```

**典型 Mapper XML 代码片段（SysUserMapper.xml）：**

```xml
<!-- 文件：ruoyi-system/src/main/resources/mapper/system/SysUserMapper.xml -->
<mapper namespace="com.ruoyi.system.mapper.SysUserMapper">
    <select id="selectUserList" parameterType="SysUser" resultMap="SysUserResult">
        select u.user_id, u.dept_id, u.nick_name, u.user_name, ...
        from sys_user u
        left join sys_dept d on u.dept_id = d.dept_id
        where u.del_flag = '0'
        <if test="userName != null and userName != ''">
            AND u.user_name like concat('%', #{userName}, '%')
        </if>
        <!-- 数据范围过滤 -->
        ${params.dataScope}
    </select>
</mapper>
```

## 四、跨层协作机制

### 4.1 横切关注点（AOP）

RuoYi-Vue 通过 Spring AOP 实现了多个横切关注点，这些切面贯穿于三层之间：

| 切面 | 注解 | 作用层 | 功能 |
|------|------|--------|------|
| **LogAspect** | `@Log` | Controller | 操作日志记录 |
| **DataScopeAspect** | `@DataScope` | Service | 数据权限过滤 |
| **RateLimiterAspect** | `@RateLimiter` | Controller | 接口限流 |
| **DataSourceAspect** | `@DataSource` | Service/Mapper | 动态数据源切换 |

### 4.2 安全过滤器链

```
HTTP 请求
  → CorsFilter (跨域处理)
  → JwtAuthenticationTokenFilter (JWT Token 验证)
  → UsernamePasswordAuthenticationFilter (Spring Security)
  → @PreAuthorize 权限校验 (Controller 方法级)
  → Controller 处理
```

### 4.3 数据流转完整链路

以"查询用户列表"为例，完整的数据流转过程：

```
1. 前端发起 GET /system/user/list?userName=xxx
2. JwtAuthenticationTokenFilter 验证 Token
3. Spring Security 校验用户认证状态
4. SysUserController.list() 被调用
5. @PreAuthorize("@ss.hasPermi('system:user:list')") 校验权限
6. startPage() 设置 PageHelper 分页参数
7. userService.selectUserList(user) 调用 Service
8. @DataScope 切面注入数据权限 SQL
9. SysUserMapper.selectUserList() 执行 SQL
10. PageHelper 拦截 SQL 添加 LIMIT 分页
11. MyBatis 执行 SQL 并映射结果
12. getDataTable(list) 封装分页数据返回
13. @Log 切面异步记录操作日志
14. 前端接收 JSON 响应
```

## 六、设计原则总结

### 6.1 单一职责原则（SRP）
- Controller 只负责接收请求和返回响应
- Service 只负责业务逻辑处理
- Mapper 只负责数据访问

### 6.2 接口隔离原则（ISP）
- Service 层采用接口 + 实现分离，Controller 只依赖接口
- `ISysUserService` 接口定义契约，`SysUserServiceImpl` 提供实现

### 6.3 依赖倒置原则（DIP）
- Controller 依赖 Service 接口而非实现类
- Service 依赖 Mapper 接口而非具体实现

### 6.4 开闭原则（OCP）
- 通过 AOP 切面扩展功能（日志、权限、限流），无需修改业务代码
- 通过注解驱动，新增功能只需添加注解

### 6.5 统一返回值封装
- 普通操作返回 `AjaxResult`（code + msg + data）
- 分页查询返回 `TableDataInfo`（code + msg + rows + total）

## 八、细节留神

1. **删除操作是逻辑删除而非物理删除**：`SysUserMapper.xml` 中的 `deleteUserById` 实际执行的是 `update sys_user set del_flag = '2'`，而非真正的 DELETE 语句
2. **数据权限 SQL 使用 `${}` 而非 `#{}`**：`${params.dataScope}` 是直接拼接 SQL 片段，由 AOP 切面在运行时注入，注意 SQL 注入风险已被切面控制
3. **Service 接口与实现在同一模块**：不同于一些项目将接口和实现分模块，RuoYi-Vue 的接口和实现都在 `ruoyi-system` 模块中
4. **BaseController 不在 web 层模块**：`BaseController` 位于 `ruoyi-common` 模块，这样所有模块的 Controller 都可以使用
5. **PageHelper 的线程变量机制**：`startPage()` 设置的分页参数存储在 ThreadLocal 中，必须在 Mapper 执行前调用，执行后通过 `PageInfo` 获取分页信息
