# 05 - 用户管理业务流程

> 本文档深入剖析 RuoYi-Vue 用户管理模块的完整业务流程，涵盖从请求到响应的全链路分析，包括用户列表查询、新增、编辑、删除、导入导出、重置密码、分配角色等操作。

---

## 一、模块概览

用户管理是 RuoYi-Vue 最核心的业务模块，涉及 3 张主表和 2 张关联表：

```
核心表：
  sys_user          - 用户主表
  sys_dept          - 部门表
  sys_role          - 角色表
  sys_post          - 岗位表

关联表：
  sys_user_role     - 用户-角色关联表
  sys_user_post     - 用户-岗位关联表
```

**三层调用链：**

```
SysUserController (ruoyi-admin)
    │
    ├─ ISysUserService (ruoyi-system/service)
    │      └─ SysUserServiceImpl (ruoyi-system/service/impl)
    │            ├─ SysUserMapper
    │            ├─ SysUserRoleMapper
    │            └─ SysUserPostMapper
    │
    ├─ ISysRoleService
    ├─ ISysDeptService
    └─ ISysPostService
```

## 二、用户列表查询流程

### 2.1 请求流程图

```
前端 GET /system/user/list?pageNum=1&pageSize=10&userName=admin
    │
    ▼
JwtAuthenticationTokenFilter
    → 解析 Token → 获取 LoginUser → 设置 SecurityContext
    │
    ▼
SysUserController.list(SysUser user)
    → @PreAuthorize("@ss.hasPermi('system:user:list')")  [权限校验]
    → startPage()                                          [启动分页]
    → userService.selectUserList(user)                      [调用Service]
    │
    ▼
SysUserServiceImpl.selectUserList(SysUser user)
    → @DataScope(deptAlias = "d", userAlias = "u")         [数据权限切面]
    → DataScopeAspect.doBefore()
        → clearDataScope()                                  [清空dataScope]
        → handleDataScope()                                 [拼接数据权限SQL]
        → user.getParams().put("dataScope", "AND (...)")    [注入SQL]
    → userMapper.selectUserList(user)                        [调用Mapper]
    │
    ▼
SysUserMapper.selectUserList(SysUser) (XML)
    → 执行 SQL:
        SELECT u.user_id, u.dept_id, u.nick_name, u.user_name, ...
        FROM sys_user u
        LEFT JOIN sys_dept d ON u.dept_id = d.dept_id
        WHERE u.del_flag = '0'
        AND u.user_name LIKE concat('%', #{userName}, '%')
        ${params.dataScope}                                 [数据权限SQL]
        LIMIT 0, 10                                         [PageHelper分页]
    │
    ▼
返回 List<SysUser>
    │
    ▼
SysUserController.getDataTable(list)
    → 封装 TableDataInfo { code: 200, msg: "查询成功", rows: [...], total: 100 }
    │
    ▼
LogAspect.doAfterReturning()
    → AsyncManager.execute(AsyncFactory.recordOper(operLog))  [异步记录日志]
    │
    ▼
前端接收 JSON 响应
```

## 三、用户新增流程

### 3.1 请求流程图

```
前端 POST /system/user  Body: { userName, nickName, deptId, roleIds, postIds, password }
    │
    ▼
SysUserController.add(@Validated @RequestBody SysUser user)
    │
    ├─ 1. @PreAuthorize("@ss.hasPermi('system:user:add')")     [权限校验]
    ├─ 2. @Validated 触发 JSR-303 校验                         [参数校验]
    ├─ 3. deptService.checkDeptDataScope(user.getDeptId())    [部门数据权限]
    ├─ 4. roleService.checkRoleDataScope(user.getRoleIds())    [角色数据权限]
    ├─ 5. userService.checkUserNameUnique(user)                 [用户名唯一性]
    ├─ 6. userService.checkPhoneUnique(user)                   [手机号唯一性]
    ├─ 7. userService.checkEmailUnique(user)                   [邮箱唯一性]
    ├─ 8. user.setCreateBy(getUsername())                       [设置创建人]
    ├─ 9. SecurityUtils.encryptPassword(user.getPassword())     [密码加密]
    └─ 10. userService.insertUser(user)                          [调用Service]
         │
         ▼
    SysUserServiceImpl.insertUser(SysUser user)
         → @Transactional                                      [开启事务]
         → userMapper.insertUser(user)                          [插入用户主表]
         → insertUserPost(user)                                 [插入用户-岗位关联]
              → userPostMapper.batchUserPost(list)
         → insertUserRole(user)                                  [插入用户-角色关联]
              → userRoleMapper.batchUserRole(list)
         │
         ▼
    toAjax(rows) → AjaxResult.success() 或 AjaxResult.error()
    │
    ▼
LogAspect 异步记录操作日志
```

### 3.2 关键源码引用

```java
// Controller 层 - 新增用户
@PreAuthorize("@ss.hasPermi('system:user:add')")
@Log(title = "用户管理", businessType = BusinessType.INSERT)
@PostMapping
public AjaxResult add(@Validated @RequestBody SysUser user) {
    deptService.checkDeptDataScope(user.getDeptId());
    roleService.checkRoleDataScope(user.getRoleIds());
    if (!userService.checkUserNameUnique(user)) {
        return error("新增用户'" + user.getUserName() + "'失败，登录账号已存在");
    }
    else if (StringUtils.isNotEmpty(user.getPhonenumber()) && !userService.checkPhoneUnique(user)) {
        return error("新增用户'" + user.getUserName() + "'失败，手机号码已存在");
    }
    else if (StringUtils.isNotEmpty(user.getEmail()) && !userService.checkEmailUnique(user)) {
        return error("新增用户'" + user.getUserName() + "'失败，邮箱账号已存在");
    }
    user.setCreateBy(getUsername());
    user.setPassword(SecurityUtils.encryptPassword(user.getPassword()));
    return toAjax(userService.insertUser(user));
}

// Service 层 - 新增用户（事务）
@Override
@Transactional
public int insertUser(SysUser user) {
    int rows = userMapper.insertUser(user);
    insertUserPost(user);
    insertUserRole(user);
    return rows;
}

// Service 层 - 插入用户角色关联
public void insertUserRole(Long userId, Long[] roleIds) {
    if (StringUtils.isNotEmpty(roleIds)) {
        List<SysUserRole> list = new ArrayList<SysUserRole>(roleIds.length);
        for (Long roleId : roleIds) {
            SysUserRole ur = new SysUserRole();
            ur.setUserId(userId);
            ur.setRoleId(roleId);
            list.add(ur);
        }
        userRoleMapper.batchUserRole(list);
    }
}
```

## 四、用户编辑流程

### 4.1 请求流程图

```
前端 PUT /system/user  Body: { userId, nickName, deptId, roleIds, postIds, ... }
    │
    ▼
SysUserController.edit(@Validated @RequestBody SysUser user)
    │
    ├─ 1. @PreAuthorize("@ss.hasPermi('system:user:edit')")
    ├─ 2. @Validated JSR-303 校验
    ├─ 3. userService.checkUserAllowed(user)                   [不允许操作管理员]
    ├─ 4. userService.checkUserDataScope(user.getUserId())     [数据权限校验]
    ├─ 5. deptService.checkDeptDataScope(user.getDeptId())
    ├─ 6. roleService.checkRoleDataScope(user.getRoleIds())
    ├─ 7. 唯一性校验（用户名/手机/邮箱）
    ├─ 8. user.setUpdateBy(getUsername())
    └─ 9. userService.updateUser(user)
         │
         ▼
    SysUserServiceImpl.updateUser(SysUser user)
         → @Transactional
         → userRoleMapper.deleteUserRoleByUserId(userId)        [删除旧角色关联]
         → insertUserRole(user)                                   [插入新角色关联]
         → userPostMapper.deleteUserPostByUserId(userId)         [删除旧岗位关联]
         → insertUserPost(user)                                  [插入新岗位关联]
         → userMapper.updateUser(user)                            [更新用户主表]
```

### 4.2 编辑与新增的差异

| 步骤 | 新增 | 编辑 |
|------|------|------|
| 操作权限校验 | 无 | `checkUserAllowed` (不允许操作管理员) |
| 数据权限校验 | 无 | `checkUserDataScope` (校验数据权限) |
| 关联数据处理 | 直接插入 | 先删后增 |
| 操作人字段 | `createBy` | `updateBy` |
| 密码处理 | 加密后存储 | 不修改密码（前端不传密码字段） |

## 五、用户删除流程

### 5.1 请求流程图

```
前端 DELETE /system/user/1,2,3
    │
    ▼
SysUserController.remove(@PathVariable Long[] userIds)
    │
    ├─ 1. @PreAuthorize("@ss.hasPermi('system:user:remove')")
    ├─ 2. 检查是否删除自己：ArrayUtils.contains(userIds, getUserId())
    │     → 如果是，返回 error("当前用户不能删除")
    └─ 3. userService.deleteUserByIds(userIds)
         │
         ▼
    SysUserServiceImpl.deleteUserByIds(Long[] userIds)
         → @Transactional
         → for 循环每个 userId:
              ├─ checkUserAllowed(new SysUser(userId))     [不允许删管理员]
              └─ checkUserDataScope(userId)                 [数据权限校验]
         → userRoleMapper.deleteUserRole(userIds)           [删除角色关联]
         → userPostMapper.deleteUserPost(userIds)           [删除岗位关联]
         → userMapper.deleteUserByIds(userIds)             [逻辑删除: del_flag='2']
```

### 5.2 关键源码引用

```java
// Controller 层
@PreAuthorize("@ss.hasPermi('system:user:remove')")
@Log(title = "用户管理", businessType = BusinessType.DELETE)
@DeleteMapping("/{userIds}")
public AjaxResult remove(@PathVariable Long[] userIds) {
    if (ArrayUtils.contains(userIds, getUserId())) {
        return error("当前用户不能删除");
    }
    return toAjax(userService.deleteUserByIds(userIds));
}

// Service 层
@Override
@Transactional
public int deleteUserByIds(Long[] userIds) {
    for (Long userId : userIds) {
        checkUserAllowed(new SysUser(userId));
        checkUserDataScope(userId);
    }
    userRoleMapper.deleteUserRole(userIds);
    userPostMapper.deleteUserPost(userIds);
    return userMapper.deleteUserByIds(userIds);
}

// Mapper XML - 逻辑删除
<delete id="deleteUserByIds" parameterType="Long">
    update sys_user set del_flag = '2' where user_id in
    <foreach collection="array" item="userId" open="(" separator="," close=")">
        #{userId}
    </foreach>
</delete>
```

```
前端 POST /system/user/importData  FormData: file + updateSupport
    │
    ▼

    → @Log(title = "用户管理", businessType = BusinessType.IMPORT)
```

### 6.3 关键源码引用

```java
// Controller 层 - 导入
@Log(title = "用户管理", businessType = BusinessType.IMPORT)
@PreAuthorize("@ss.hasPermi('system:user:import')")
@PostMapping("/importData")
public AjaxResult importData(MultipartFile file, boolean updateSupport) throws Exception {
    ExcelUtil<SysUser> util = new ExcelUtil<SysUser>(SysUser.class);
    List<SysUser> userList = util.importExcel(file.getInputStream());
    String operName = getUsername();
    String message = userService.importUser(userList, updateSupport, operName);
    return success(message);
}

// Service 层 - 导入（逐条处理，无事务）
@Override
public String importUser(List<SysUser> userList, Boolean isUpdateSupport, String operName) {
    // ... 逐条处理逻辑
    for (SysUser user : userList) {
        try {
            SysUser u = userMapper.selectUserByUserName(user.getUserName());
            if (StringUtils.isNull(u)) {
                // 新用户导入
                BeanValidators.validateWithException(validator, user);
                deptService.checkDeptDataScope(user.getDeptId());
                String password = configService.selectConfigByKey("sys.user.initPassword");
                user.setPassword(SecurityUtils.encryptPassword(password));
                user.setCreateBy(operName);
                userMapper.insertUser(user);
                successNum++;
            } else if (isUpdateSupport) {
                // 更新已有用户
                BeanValidators.validateWithException(validator, user);
                checkUserAllowed(u);
                checkUserDataScope(u.getUserId());
                user.setUserId(u.getUserId());
                user.setUpdateBy(operName);
                userMapper.updateUser(user);
                successNum++;
            } else {
                failureNum++;
            }
        } catch (Exception e) {
            failureNum++;
        }
    }
    // ... 返回结果消息
}
```

## 十、细节留神

1. **新增用户时密码在 Controller 层加密**：`SecurityUtils.encryptPassword()` 在 Controller 中调用，Service 层存储的是已加密的密码。这意味着即使有人绕过 Controller 直接调用 Service，也需要自己处理加密
2. **导入用户没有使用 @Transactional**：每条用户独立处理，一条失败不影响其他条。但如果某条用户插入成功后后续抛异常，已插入的不会回滚
3. **编辑用户时不修改密码**：Controller 的 edit 方法不接收密码字段，密码修改通过独立的 resetPwd 接口完成
4. **删除操作是逻辑删除**：`del_flag` 从 `'0'` 变为 `'2'`，数据库记录仍然存在。查询时通过 `where del_flag = '0'` 过滤
5. **分配角色使用先删后增策略**：先删除用户的所有角色关联，再批量插入新的角色关联，在事务中执行

## 十一、提问方向

1. **新增用户时，Controller 层依次进行了部门数据权限校验、角色数据权限校验、用户名唯一性校验、手机号唯一性校验、邮箱唯一性校验。这些校验的顺序是否可以调整？如果唯一性校验放在数据权限校验之前会有什么问题？**

2. **编辑用户时使用"先删后增"策略更新角色关联（先 deleteUserRoleByUserId 再 insertUserRole），如果数据库在删除后、插入前发生异常，用户会丢失所有角色关联。这种风险如何防范？是否可以使用 MERGE 语句替代？**

3. **导入用户方法没有使用 @Transactional，这意味着每条用户是独立事务。如果导入 100 条用户，第 50 条失败了，前 49 条已经提交。这种设计的利弊是什么？如果需要保证"全部成功或全部失败"，应该如何修改？**

4. **重置密码时，新密码在 Controller 层通过 `SecurityUtils.encryptPassword()` 加密后传给 Service。如果密码加密算法需要更换（如从 BCrypt 换为 Argon2），需要修改哪些地方？这种设计是否违反了"修改封闭原则"？**

5. **删除用户时先检查 `ArrayUtils.contains(userIds, getUserId())` 防止删除自己，但这个检查在 Controller 层。如果通过其他途径（如批量操作接口）调用 Service 的 deleteUserByIds，这个保护还会生效吗？**

6. **用户列表查询中，`selectUserList` 不查询密码字段（安全考虑），但 `selectUserByUserName` 通过 `<include refid="selectUserVo"/>` 查询了密码字段。这两个查询的 resultMap 都是 `SysUserResult`，密码字段在列表查询中为 null，这是否可能导致前端问题？**

7. **分配角色时，Controller 层同时校验了用户数据权限（`checkUserDataScope`）和角色数据权限（`checkRoleDataScope`），请分析为什么需要同时校验两个权限？如果只校验其中一个会有什么安全风险？**
