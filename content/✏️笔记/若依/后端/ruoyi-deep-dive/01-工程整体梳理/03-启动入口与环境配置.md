# 03 - 启动入口与环境配置

## 一、RuoYiApplication 启动类分析

### 1.1 源码

启动类位于 `ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`：

```java
package com.ruoyi;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration;

/**
 * 启动程序
 *
 * @author ruoyi
 */
@SpringBootApplication(exclude = { DataSourceAutoConfiguration.class })
public class RuoYiApplication
{
    public static void main(String[] args)
    {
        // System.setProperty("spring.devtools.restart.enabled", "false");
        SpringApplication.run(RuoYiApplication.class, args);
        System.out.println("(♥◠‿◠)ﾉﾞ  若依启动成功   ლ(´ڡ`ლ)ﾞ  \n" +
                " .-------.       ____     __        \n" +
                " |  _ _   \\      \\   \\   /  /    \n" +
                " | ( ' )  |       \\  _. /  '       \n" +
                " |(_ o _) /        _( )_ .'         \n" +
                " | (_,_).' __  ___(_ o _)'          \n" +
                " |  |\\ \\  |  ||   |(_,_)'         \n" +
                " |  | \\ `'   /|   `-'  /           \n" +
                " |  |  \\    /  \\      /           \n" +
                " ''-'   `'-'    `-..-'              ");
    }
}
```

### 1.2 @SpringBootApplication 注解拆解

`@SpringBootApplication` 是一个组合注解，等价于：

```java
@SpringBootConfiguration      // 标识为配置类
@EnableAutoConfiguration      // 启用自动配置
@ComponentScan                 // 组件扫描（扫描当前包及子包）
(exclude = { DataSourceAutoConfiguration.class })  // 排除数据源自动配置
```

### 1.3 为什么 exclude DataSourceAutoConfiguration？

这是启动类中最关键的设计决策。原因如下：

**1) 自定义了 Druid 多数据源**

项目在 `ruoyi-framework` 模块中自定义了数据源配置类 `DruidConfig`，手动创建了 `DruidDataSource` Bean。如果不禁用 `DataSourceAutoConfiguration`，Spring Boot 的自动配置机制会尝试创建默认的数据源 Bean，导致冲突。

**2) 支持主从数据源切换**

项目支持主从数据源的动态切换（通过 `DynamicDataSource` + `@DataSource` 注解实现），这需要自定义数据源路由逻辑，而非 Spring Boot 的默认单数据源配置。

**3) Druid 专属 Starter**

项目使用的是 `druid-spring-boot-4-starter`，这个 Starter 有自己的自动配置类。排除 `DataSourceAutoConfiguration` 可以避免 Spring Boot 默认的 HikariCP 数据源自动配置与 Druid 自动配置产生冲突。

**源码佐证**（`ruoyi-framework/pom.xml`）：

```xml
<!-- 阿里数据库连接池 -->
<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid-spring-boot-4-starter</artifactId>
</dependency>
```

**自动配置排位关系**：

```
DataSourceAutoConfiguration (Spring Boot 默认)
  -> 创建 HikariCP DataSource

DruidDataSourceAutoConfigure (Druid Starter)
  -> 创建 Druid DataSource

两者同时存在会冲突 -> 所以排除前者
```

### 1.4 main 方法中的注释代码

```java
// System.setProperty("spring.devtools.restart.enabled", "false");
```

这行被注释掉的代码用于**禁用 DevTools 热部署**。在开发环境中 DevTools 提供热重载能力，但在某些场景下（如调试时不想频繁重启）可以取消注释来禁用。

## 二、RuoYiServletInitializer 分析

### 2.1 源码

```java
package com.ruoyi;

import org.springframework.boot.builder.SpringApplicationBuilder;
import org.springframework.boot.web.servlet.support.SpringBootServletInitializer;

/**
 * web容器中进行部署
 *
 * @author ruoyi
 */
public class RuoYiServletInitializer extends SpringBootServletInitializer
{
    @Override
    protected SpringApplicationBuilder configure(SpringApplicationBuilder application)
    {
        return application.sources(RuoYiApplication.class);
    }
}
```

### 2.2 作用分析

`RuoYiServletInitializer` 继承了 `SpringBootServletInitializer`，这是 Spring Boot 支持**传统 WAR 部署**的方式。

**两种部署模式对比**：

| 特性 | JAR 部署（默认） | WAR 部署 |
|------|-----------------|---------|
| 入口 | `RuoYiApplication.main()` | `RuoYiServletInitializer` |
| 容器 | 内嵌 Tomcat | 外部 Tomcat/Jetty |
| 打包方式 | `java -jar ruoyi-admin.jar` | 部署到 `webapps/` 目录 |
| 是否需要此类 | 不需要 | 需要 |
| 使用场景 | 微服务、容器化部署 | 传统运维、共享服务器 |

### 2.3 WAR 部署配置

`ruoyi-admin/pom.xml` 中配置了 `maven-war-plugin`：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-war-plugin</artifactId>
    <version>3.1.0</version>
    <configuration>
        <failOnMissingWebXml>false</failOnMissingWebXml>
        <warName>${project.artifactId}</warName>
    </configuration>
</plugin>
```

`failOnMissingWebXml=false` 表示不需要传统的 `WEB-INF/web.xml` 文件，因为 Spring Boot 通过 Servlet 3.0+ 的 `ServletContainerInitializer` 机制进行注册。

### 2.4 实际使用

在当前项目中，默认使用 JAR 方式部署（通过 `bin/run.bat` 或 `java -jar` 启动）。`RuoYiServletInitializer` 作为一个"备用入口"，仅在需要 WAR 部署时才会被使用。

## 三、环境区分机制

### 3.1 spring.profiles.active

`application.yml` 中通过 `spring.profiles.active` 激活额外的配置文件：

```yaml
# application.yml
spring:
  profiles:
    active: druid
```

这表示启动时会额外加载 `application-druid.yml` 配置文件。

**配置文件加载顺序**：

```
1. application.yml          # 主配置（通用配置）
2. application-druid.yml    # druid profile（数据源专用配置）
```

Spring Boot 的配置合并机制会将两个文件的内容合并，`application-druid.yml` 中的同名配置会覆盖 `application.yml` 中的值。

### 3.2 为什么用 profile 而非直接写在 application.yml？

1. **关注点分离**：数据源配置（URL、密码、连接池参数）与通用配置（端口、日志、Redis）分属不同关注点
2. **安全性**：数据源配置通常包含敏感信息（密码），单独文件便于安全管理
3. **灵活性**：可以轻松切换不同的数据源配置（如开发环境用 H2、生产用 MySQL）
4. **可扩展**：未来可以增加 `application-dev.yml`、`application-prod.yml` 等环境配置

### 3.3 配置文件加载完整链路

```
Spring Boot 启动
  -> 读取 application.yml（主配置）
  -> 检测 spring.profiles.active=druid
  -> 加载 application-druid.yml
  -> 合并配置（druid 覆盖主配置中的同名项）
  -> 同时加载 mybatis-config.xml（通过 mybatis.configLocation 指定）
  -> 同时加载 logback.xml（日志配置）
  -> 同时加载 i18n/messages.properties（国际化）
  -> 同时加载 banner.txt（启动 Banner）
```

### 3.4 配置文件清单

| 文件 | 路径 | 用途 |
|------|------|------|
| `application.yml` | `ruoyi-admin/src/main/resources/` | 主配置文件 |
| `application-druid.yml` | `ruoyi-admin/src/main/resources/` | 数据源配置 |
| `mybatis-config.xml` | `ruoyi-admin/src/main/resources/mybatis/` | MyBatis 全局配置 |
| `logback.xml` | `ruoyi-admin/src/main/resources/` | 日志配置 |
| `banner.txt` | `ruoyi-admin/src/main/resources/` | 启动 Banner |
| `messages.properties` | `ruoyi-admin/src/main/resources/i18n/` | 国际化消息 |

## 四、DevTools 热部署配置

### 4.1 依赖引入

```xml
<!-- ruoyi-admin/pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <optional>true</optional>
</dependency>
```

`<optional>true</optional>` 确保此依赖不会传递到其他模块。

### 4.2 配置启用

```yaml
# application.yml
spring:
  devtools:
    restart:
      enabled: true
```

### 4.3 触发重启的配置

`META-INF/spring-devtools.properties`：

```properties
restart.include.json=/com.alibaba.fastjson2.*.jar
```

这行配置告诉 DevTools：当 `fastjson2` 的 JAR 文件发生变化时，触发重启。这是因为 FastJson2 的类加载可能影响序列化行为。

### 4.4 DevTools 工作原理

```
1. DevTools 监听 classpath 下的文件变化
2. 当检测到变化时，触发"重启"（不是 JVM 重启）
3. 重启使用两个类加载器：
   - "base classloader"：加载不会改变的类（第三方库）
   - "restart classloader"：加载开发者编写的类
4. 重启时只丢弃 restart classloader 并重新创建，速度很快
5. spring-devtools.properties 中的配置控制哪些变化触发重启
```

### 4.5 生产环境注意事项

- `spring-boot-devtools` 设置了 `<optional>true</optional>`，在 `mvn package` 时不会被打包
- Spring Boot 默认在生产环境（`spring.profiles.active=prod`）禁用 DevTools
- 可通过 `System.setProperty("spring.devtools.restart.enabled", "false")` 手动禁用

## 六、启动流程完整链路

```
1. JVM 启动，执行 RuoYiApplication.main()
2. SpringApplication.run() 开始初始化
3. 读取 application.yml + application-druid.yml
4. 排除 DataSourceAutoConfiguration（不创建默认数据源）
5. 组件扫描 com.ruoyi 及子包
6. 加载 DruidConfig（创建 Druid 数据源）
7. 加载 SecurityConfig（配置 Spring Security）
8. 加载 RedisConfig（配置 Redis 连接）
9. 加载 MyBatisConfig（配置 MyBatis）
10. 加载 FilterConfig（注册 XSS 过滤器、Referer 过滤器）
11. 加载 ThreadPoolConfig（初始化线程池）
12. 加载 CaptchaConfig（配置验证码生成器）
13. 初始化 Quartz 调度器
14. 启动内嵌 Tomcat（端口 8080）
15. 打印 Banner 和启动成功信息
```

## 八、细节留神

1. **exclude 的写法**：`exclude = { DataSourceAutoConfiguration.class }` 使用了数组形式，如果需要排除多个自动配置类，可以写成 `exclude = { DataSourceAutoConfiguration.class, X.class }`
2. **包扫描的隐含条件**：所有模块的 Java 包必须在 `com.ruoyi` 下才能被扫描到。如果引入了第三方 JAR，其中的 `@Component` 不会被自动扫描
3. **WAR 部署的打包方式**：虽然 `ruoyi-admin/pom.xml` 的 `<packaging>` 是 `jar`，但配置了 `maven-war-plugin`，如果要打 WAR 包需要将 packaging 改为 `war`
4. **DevTools 的局限性**：DevTools 只能在开发环境使用，且对 Spring Security 的配置变更可能需要完全重启才能生效
5. **Banner 变量**：`${ruoyi.version}` 和 `${spring-boot.version}` 来自 Maven 的 resource filtering，需要在 `pom.xml` 中配置 `<resource>` 的 filtering 才能生效

## 九、提问方向

1. **"RuoYiApplication 启动类中为什么要排除 `DataSourceAutoConfiguration`？如果不排除会发生什么？"**

   > 参考思路：Spring Boot 会自动创建 HikariCP 数据源，与自定义的 Druid 数据源冲突，导致 `BeanCreationException`

2. **"Spring Boot 的自动配置机制是如何工作的？`exclude` 排除自动配置类的原理是什么？"**

   > 参考思路：`@EnableAutoConfiguration` 通过 `SpringFactoriesLoader`（或 Spring Boot 3.x+ 的 `AutoConfiguration.imports`）加载自动配置类，`exclude` 在加载后移除指定类

3. **"项目中 `RuoYiServletInitializer` 在什么场景下会被使用？JAR 部署和 WAR 部署各自的优缺点是什么？"**

   > 参考思路：WAR 部署用于传统运维场景，JAR 部署适合容器化和微服务

4. **"spring.profiles.active=druid 这种配置方式与直接在 application.yml 中写数据源配置有什么区别？如果需要区分 dev/test/prod 环境，应该如何扩展？"**

   > 参考思路：可以增加 `application-dev.yml`、`application-test.yml`、`application-prod.yml`，通过 `spring.profiles.active=dev,druid` 激活多个 profile

5. **"DevTools 热部署的 `restart.include.json=/com.alibaba.fastjson2.*.jar` 配置是什么意思？为什么 FastJson2 的变化需要触发重启？"**

   > 参考思路：FastJson2 涉及序列化/反序列化，类变更可能影响缓存中的序列化结果

6. **"如果将启动类从 `com.ruoyi` 包移到 `com.example` 包，项目还能正常启动吗？为什么？"**

   > 参考思路：不能，因为 `@ComponentScan` 默认只扫描启动类所在包及子包，其他模块的组件将无法被扫描到

7. **"Banner 文件中的 `${ruoyi.version}` 变量是如何被替换的？这个机制依赖什么配置？"**

   > 参考思路：Spring Boot 的 `ApplicationBanner` 在打印时会从 `Environment` 中读取属性值，这些值来自 `application.yml` 中的 `ruoyi.version` 配置
