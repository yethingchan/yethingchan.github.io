# 04 - 配置文件深度解析

## 一、配置文件总览

RuoYi-Vue 的配置文件全部位于 `ruoyi-admin/src/main/resources/` 目录下：

| 文件 | 类型 | 用途 |
|------|------|------|
| `application.yml` | YAML | 主配置文件（通用配置） |
| `application-druid.yml` | YAML | 数据源配置（通过 profile 激活） |
| `mybatis-config.xml` | XML | MyBatis 全局配置 |
| `logback.xml` | XML | 日志配置 |
| `banner.txt` | TXT | 启动 Banner |
| `i18n/messages.properties` | Properties | 国际化消息 |
| `META-INF/spring-devtools.properties` | Properties | DevTools 配置 |

## 二、application.yml 逐项分析

### 2.1 项目自定义配置（ruoyi.*）

```yaml
# 项目相关配置
ruoyi:
  name: RuoYi
  version: 3.9.2
  copyrightYear: 2026
  profile: D:/ruoyi/uploadPath
  addressEnabled: false
  captchaType: math
```

**逐项解析**：

| 配置项 | 值 | 说明 |
|--------|---|------|
| `name` | RuoYi | 项目名称，用于页面标题等展示 |
| `version` | 3.9.2 | 项目版本号 |
| `copyrightYear` | 2026 | 版权年份，用于页面底部展示 |
| `profile` | D:/ruoyi/uploadPath | 文件上传根路径（Windows 示例） |
| `addressEnabled` | false | 是否获取 IP 地址对应的地理位置 |
| `captchaType` | math | 验证码类型：`math`（数学运算）或 `char`（字符验证） |

**对应配置类**（`ruoyi-common/src/main/java/com/ruoyi/common/config/RuoYiConfig.java`）：

```java
@Component
@ConfigurationProperties(prefix = "ruoyi")
public class RuoYiConfig
{
    private String name;
    private String version;
    private String copyrightYear;
    private static String profile;
    private static boolean addressEnabled;
    private static String captchaType;

    // 提供多个静态方法获取子路径
    public static String getImportPath() { return getProfile() + "/import"; }
    public static String getAvatarPath() { return getProfile() + "/avatar"; }
    public static String getDownloadPath() { return getProfile() + "/download/"; }
    public static String getUploadPath() { return getProfile() + "/upload"; }
}
```

**注意**：`profile`、`addressEnabled`、`captchaType` 使用了 `static` 修饰符，可以通过静态方法直接访问，无需注入 Bean。

### 2.2 服务器配置（server.*）

```yaml
server:
  port: 8080
  servlet:
    context-path: /
  tomcat:
    uri-encoding: UTF-8
    accept-count: 1000
    threads:
      max: 800
      min-spare: 100
```

**逐项解析**：

| 配置项 | 值 | 默认值 | 说明 |
|--------|---|--------|------|
| `port` | 8080 | 8080 | HTTP 服务端口 |
| `servlet.context-path` | / | / | 应用上下文路径 |
| `tomcat.uri-encoding` | UTF-8 | UTF-8 | URI 编码 |
| `tomcat.accept-count` | 1000 | 100 | 连接队列满后的排队等待数 |
| `tomcat.threads.max` | 800 | 200 | 最大工作线程数 |
| `tomcat.threads.min-spare` | 100 | 10 | 最小空闲线程数 |

**性能分析**：
- `max: 800` 是默认值 200 的 4 倍，适合中等并发量的后台管理系统
- `min-spare: 100` 是默认值 10 的 10 倍，减少了线程创建的开销
- `accept-count: 1000` 是默认值 100 的 10 倍，允许更多请求排队等待

**生产环境建议**：
- 根据实际并发量调整线程数
- 建议配合 Nginx 反向代理使用，Tomcat 不直接暴露
- 考虑启用 HTTPS（`server.ssl` 配置）

### 2.3 日志配置（logging.*）

```yaml
logging:
  level:
    com.ruoyi: debug
    org.springframework: warn
```

**分析**：
- `com.ruoyi: debug`：项目代码使用 DEBUG 级别，可以看到详细的调试日志
- `org.springframework: warn`：Spring 框架只输出 WARN 及以上级别的日志，减少噪音

**注意**：`application.yml` 中的日志级别会被 `logback.xml` 中的配置覆盖。在 `logback.xml` 中：
```xml
<logger name="com.ruoyi" level="info" />
```
实际运行时 `com.ruoyi` 的日志级别是 `info`（logback.xml 优先级更高）。

### 2.6 Redis 配置（spring.data.redis.*）

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      database: 0
      password:
      timeout: 10s
      lettuce:
        pool:
          min-idle: 0
          max-idle: 8
          max-active: 8
          max-wait: -1ms
```

**逐项解析**：

| 配置项 | 值 | 说明 |
|--------|---|------|
| `host` | localhost | Redis 服务器地址 |
| `port` | 6379 | Redis 端口 |
| `database` | 0 | Redis 数据库索引（0-15） |
| `password` | (空) | Redis 密码（开发环境未设置） |
| `timeout` | 10s | 连接超时时间 |
| `lettuce.pool.min-idle` | 0 | 最小空闲连接数 |
| `lettuce.pool.max-idle` | 8 | 最大空闲连接数 |
| `lettuce.pool.max-active` | 8 | 最大活跃连接数 |
| `lettuce.pool.max-wait` | -1ms | 连接池最大阻塞等待时间（-1 表示无限制） |

**注意**：
- 使用 Lettuce 作为 Redis 客户端（Spring Boot 默认），而非 Jedis
- `password` 为空，生产环境必须设置密码
- 连接池参数较小（max-active: 8），适合开发环境，生产环境需要根据并发量调大

### 2.7 Token 配置（token.*）

```yaml
token:
  header: Authorization
  secret: abcdefghijklmnopqrstuvwxyz
  expireTime: 30
```

**逐项解析**：

| 配置项 | 值 | 说明 |
|--------|---|------|
| `header` | Authorization | Token 存放在 HTTP Header 中的字段名 |
| `secret` | abcdefghijklmnopqrstuvwxyz | JWT 签名密钥 |
| `expireTime` | 30 | Token 有效期（分钟） |

**安全警告**：
- `secret` 的值 `abcdefghijklmnopqrstuvwxyz` 是一个极弱的密钥，仅用于开发环境
- 生产环境必须使用足够长的随机字符串（建议 64+ 字符）
- `expireTime: 30` 表示 30 分钟过期，需配合前端刷新 Token 机制

### 2.8 MyBatis 配置（mybatis.*）

```yaml
mybatis:
  typeAliasesPackage: com.ruoyi.**.domain
  mapperLocations: classpath*:mapper/**/*Mapper.xml
  configLocation: classpath:mybatis/mybatis-config.xml
```

**逐项解析**：

| 配置项 | 值 | 说明 |
|--------|---|------|
| `typeAliasesPackage` | com.ruoyi.**.domain | 实体类别名包路径（支持 `**` 通配符） |
| `mapperLocations` | classpath*:mapper/**/*Mapper.xml | Mapper XML 文件位置（`classpath*` 表示跨 JAR 搜索） |
| `configLocation` | classpath:mybatis/mybatis-config.xml | MyBatis 全局配置文件 |

**`classpath*` vs `classpath`**：
- `classpath*`：搜索所有 JAR 包中匹配的路径（用于多模块项目）
- `classpath`：只搜索第一个匹配的路径

**mybatis-config.xml 内容**：

```xml
<configuration>
    <settings>
        <setting name="cacheEnabled"             value="true"   />
        <setting name="useGeneratedKeys"         value="true"   />
        <setting name="defaultExecutorType"      value="SIMPLE" />
        <setting name="logImpl"                  value="SLF4J"  />
        <!-- <setting name="mapUnderscoreToCamelCase" value="true"/> -->
    </settings>
</configuration>
```

**关键发现**：`mapUnderscoreToCamelCase` 被注释掉了，这意味着数据库字段 `user_name` 不会自动映射到 Java 字段 `userName`。项目中通过 MyBatis 的 `<resultMap>` 手动映射。

### 3.2 主从数据源配置

```yaml
master:
    url: jdbc:mysql://localhost:3306/ry-vue?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
    username: root
    password: 123456
slave:
    enabled: false
    url:
    username:
    password:
```

**JDBC URL 参数解析**：

| 参数 | 值 | 说明 |
|------|---|------|
| `useUnicode` | true | 使用 Unicode 字符集 |
| `characterEncoding` | utf8 | 字符编码 |
| `zeroDateTimeBehavior` | convertToNull | 零日期转为 null |
| `useSSL` | true | 启用 SSL |
| `serverTimezone` | GMT+8 | 服务器时区 |

**从库配置**：默认关闭（`enabled: false`），URL、用户名、密码均为空。需要读写分离时开启并填写从库信息。

### 3.3 连接池参数详解

```yaml
initialSize: 5          # 初始连接数
minIdle: 10             # 最小空闲连接数
maxActive: 20           # 最大活跃连接数
maxWait: 60000          # 获取连接最大等待时间（毫秒）
connectTimeout: 30000   # 连接超时（毫秒）
socketTimeout: 60000     # Socket 超时（毫秒）
```

**连接池大小分析**：
- `initialSize: 5`：启动时创建 5 个连接
- `minIdle: 10`：保持至少 10 个空闲连接
- `maxActive: 20`：最大 20 个活跃连接

**注意**：`initialSize(5) < minIdle(10)`，这意味着启动后 Druid 会立即扩展到 10 个连接。

### 3.4 连接回收参数

```yaml
timeBetweenEvictionRunsMillis: 60000      # 每 60 秒检测一次空闲连接
minEvictableIdleTimeMillis: 300000        # 连接最小空闲时间 5 分钟
maxEvictableIdleTimeMillis: 900000        # 连接最大空闲时间 15 分钟
validationQuery: SELECT 1 FROM DUAL       # 连接有效性检测 SQL
testWhileIdle: true                        # 空闲时检测连接有效性
testOnBorrow: false                        # 借出时不检测（提升性能）
testOnReturn: false                        # 归还时不检测
```

**回收策略**：
1. 每 60 秒扫描一次连接池
2. 空闲超过 5 分钟的连接可能被回收
3. 空闲超过 15 分钟的连接一定会被回收
4. 回收前执行 `SELECT 1 FROM DUAL` 验证连接是否有效

### 3.5 Druid 监控配置

```yaml
webStatFilter:
    enabled: true                          # 开启 Web 监控统计
statViewServlet:
    enabled: true                          # 开启监控页面
    allow:                                 # 白名单（空=允许所有）
    url-pattern: /druid/*                  # 监控页面路径
    login-username: ruoyi                   # 监控页面用户名
    login-password: 123456                  # 监控页面密码
```

**访问地址**：`http://localhost:8080/druid/`
- 可以查看 SQL 执行统计、连接池状态、Spring 监控等
- **安全警告**：`allow` 为空表示允许所有 IP 访问，生产环境必须配置白名单

### 3.6 慢 SQL 配置

```yaml
filter:
    stat:
        enabled: true
        log-slow-sql: true                 # 开启慢 SQL 记录
        slow-sql-millis: 1000              # 慢 SQL 阈值：1 秒
        merge-sql: true                    # 合并相同 SQL 的统计

        config:
            multi-statement-allow: true    # 允许多语句执行
```

**分析**：
- 执行时间超过 1000ms 的 SQL 会被记录为慢 SQL
- `merge-sql: true` 将参数不同的相同 SQL 合并统计
- `multi-statement-allow: true` 允许一次执行多条 SQL（代码生成模块可能需要）

## 四、敏感配置问题

### 4.1 密码硬编码问题

项目中存在多处密码硬编码：

| 位置 | 配置项 | 硬编码值 | 风险等级 |
|------|--------|---------|---------|
| `application-druid.yml` | `spring.datasource.druid.master.password` | `123456` | 高 |
| `application-druid.yml` | `spring.datasource.druid.statViewServlet.login-password` | `123456` | 中 |
| `application.yml` | `token.secret` | `abcdefghijklmnopqrstuvwxyz` | 高 |
| `application.yml` | `spring.data.redis.password` | (空) | 中 |

### 4.2 安全改进建议

1. **使用环境变量**：

```yaml
password: ${DB_PASSWORD:123456}    # 优先读取环境变量，默认值 123456
```

2. **使用 Jasypt 加密**：

```yaml
password: ENC(加密后的字符串)
```

3. **使用 Spring Cloud Config / Nacos**：将配置集中管理，避免密码出现在代码仓库中

4. **`.gitignore` 敏感配置文件**：创建 `application-local.yml`（不提交到 Git）存放本地开发密码

## 五、自定义配置类 RuoYiConfig 分析

### 5.1 源码

```java
@Component
@ConfigurationProperties(prefix = "ruoyi")
public class RuoYiConfig
{
    private String name;
    private String version;
    private String copyrightYear;
    private static String profile;
    private static boolean addressEnabled;
    private static String captchaType;

    // getter/setter ...

    public static String getImportPath() { return getProfile() + "/import"; }
    public static String getAvatarPath() { return getProfile() + "/avatar"; }
    public static String getDownloadPath() { return getProfile() + "/download/"; }
    public static String getUploadPath() { return getProfile() + "/upload"; }
}
```

### 5.2 设计分析

1. **`@ConfigurationProperties(prefix = "ruoyi")`**：将 `application.yml` 中 `ruoyi.*` 前缀的配置自动绑定到此类
2. **`@Component`**：注册为 Spring Bean，在容器启动时自动创建
3. **混合实例/静态字段**：`name`、`version`、`copyrightYear` 是实例字段，`profile`、`addressEnabled`、`captchaType` 是静态字段
4. **静态方法获取路径**：`getUploadPath()` 等方法为静态方法，可以在任何地方直接调用而无需注入 Bean

### 5.3 静态字段的 setter 模式

```java
private static String profile;

public void setProfile(String profile) {
    RuoYiConfig.profile = profile;  // 赋值给静态字段
}
```

这种写法利用了 Spring 的 setter 注入机制：Spring 创建 Bean 后调用 `setProfile()`，将配置值赋给静态字段。之后可以通过 `RuoYiConfig.getProfile()` 静态方法直接访问。

### 5.4 文件路径体系

```
D:/ruoyi/uploadPath/           # profile 根路径
  ├── upload/                  # getUploadPath() - 文件上传
  ├── download/                # getDownloadPath() - 文件下载
  ├── import/                  # getImportPath() - Excel 导入
  └── avatar/                  # getAvatarPath() - 头像上传
```

## 七、细节留神

1. **Tomcat 线程数与连接池大小的关系**：Tomcat `max: 800` 线程 vs Druid `maxActive: 20` 连接，意味着最多 800 个请求并发，但只有 20 个数据库连接。高并发时会出现连接等待
2. **Redis 连接池 `max-active: 8`**：与 Druid 的 `maxActive: 20` 相比更小，因为 Redis 操作通常比数据库快得多
3. **`mapUnderscoreToCamelCase` 被注释**：MyBatis 不会自动将 `user_name` 映射到 `userName`，项目中通过 `resultMap` 手动映射，这增加了 XML 配置的复杂度
4. **XSS 过滤的 `excludes` 配置**：`/system/notice` 被排除在 XSS 过滤之外，需确保通知内容的使用场景安全
5. **Druid 监控的 `allow` 为空**：意味着任何 IP 都可以访问 `/druid/*` 监控页面，生产环境必须配置白名单

## 八、提问方向

1. **"application.yml 中 `spring.profiles.active=druid` 的作用是什么？如果同时需要区分开发/测试/生产环境，应该如何设计多 profile 配置？"**

   > 参考思路：可以创建 `application-dev.yml`、`application-test.yml`、`application-prod.yml`，使用 `spring.profiles.active=dev,druid` 同时激活多个 profile

2. **"Druid 连接池的 `maxActive: 20` 是否足够？如何根据业务场景计算合理的连接池大小？"**

   > 参考思路：连接池大小 = (平均响应时间 * TPS) / (最大容忍等待时间)，同时考虑数据库最大连接数限制

3. **"Token 的 `secret: abcdefghijklmnopqrstuvwxyz` 在生产环境中存在什么安全风险？应该如何改进？"**

   > 参考思路：弱密钥容易被暴力破解，应使用至少 64 字符的随机字符串，并通过环境变量或加密方式存储

4. **"MyBatis 配置中 `mapUnderscoreToCamelCase` 被注释掉了，这对开发有什么影响？为什么要这样设计？"**

   > 参考思路：项目选择手动维护 resultMap 以获得更精确的映射控制，但增加了开发工作量

5. **"XSS 过滤配置中 `/system/notice` 被排除在外，这样做的原因是什么？是否存在安全风险？"**

   > 参考思路：通知内容可能需要支持富文本（HTML），排除 XSS 过滤后需要在前端做额外的安全处理

6. **"Druid 监控页面的 `allow` 白名单为空，在生产环境中如何正确配置？"**

   > 参考思路：设置 `allow: 192.168.1.0/24` 限制内网访问，或通过 Nginx 限制 `/druid/*` 路径的访问

7. **"`RuoYiConfig` 中混合使用了实例字段和静态字段，这种设计有什么优缺点？"**

   > 参考思路：优点是静态方法可以直接调用，缺点是违反了依赖注入的原则，不利于单元测试
