## 一、自定义注解

  

### 1. @Log - 操作日志注解

  

**文件位置**: `ruoyi-common/src/main/java/com/ruoyi/common/annotation/Log.java`

  

#### 功能说明

  

自动记录用户操作日志到`sys_oper_log`表，通过AOP切面实现，无需手动编写日志记录代码。

  

#### 注解定义

  

```java

@Target({ ElementType.PARAMETER, ElementType.METHOD })

@Retention(RetentionPolicy.RUNTIME)

@Documented

public @interface Log {

    public String title() default "";                      // 模块标题

    public BusinessType businessType() default BusinessType.OTHER;  // 业务类型

    public OperatorType operatorType() default OperatorType.MANAGE; // 操作人类别

    public boolean isSaveRequestData() default true;       // 是否保存请求参数

    public boolean isSaveResponseData() default true;      // 是否保存响应参数

    public String[] excludeParamNames() default {};        // 排除的参数名

}

```

  

#### 属性详解

  

| 属性 | 类型 | 默认值 | 说明 |

|------|------|--------|------|

| title | String | "" | 模块标题，如"用户管理" |

| businessType | BusinessType | OTHER | 业务类型（新增/修改/删除/导出/导入等） |

| operatorType | OperatorType | MANAGE | 操作人类别（管理员/手机端用户等） |

| isSaveRequestData | boolean | true | 是否保存请求参数到日志 |

| isSaveResponseData | boolean | true | 是否保存响应结果到日志 |

| excludeParamNames | String[] | {} | 需要排除的请求参数名（如密码字段） |

  

#### BusinessType枚举值

  

```java

public enum BusinessType {

    OTHER,      // 其他

    INSERT,     // 新增

    UPDATE,     // 修改

    DELETE,     // 删除

    GRANT,      // 授权

    EXPORT,     // 导出

    IMPORT,     // 导入

    FORCE,      // 强退

    GENCODE,    // 生成代码

    CLEAN       // 清空数据

}

```

  

#### 使用示例

  

**基础用法**:

  

```java

@RestController

@RequestMapping("/system/user")

public class SysUserController extends BaseController {

    /**

     * 新增用户

     *

     * 为什么这样写：

     * 1. title="用户管理" - 标识这个操作属于哪个模块，方便日志查询时筛选

     * 2. businessType=INSERT - 标记为新增操作，统计时可分类

     * 3. AOP切面会自动记录：操作人、操作时间、IP地址、请求参数、返回结果、执行耗时

     */

    @Log(title = "用户管理", businessType = BusinessType.INSERT)

    @PostMapping

    public AjaxResult add(@Validated @RequestBody SysUser user) {

        // 业务逻辑

        return toAjax(userService.insertUser(user));

    }

}

```

  

**排除敏感参数**:

  

```java

/**

 * 修改用户密码

 *

 * 为什么excludeParamNames={"password"}：

 * - 密码是敏感信息，不应该明文记录到日志中

 * - 排除后，日志表中oper_param字段不会包含password参数

 */

@Log(

    title = "用户管理",

    businessType = BusinessType.UPDATE,

    excludeParamNames = {"password"}

)

@PutMapping("/resetPwd")

public AjaxResult resetPwd(@RequestBody SysUser user) {

    userService.resetPwd(user);

    return AjaxResult.success();

}

```

  

**不保存响应数据**:

  

```java

/**

 * 导出用户数据

 *

 * 为什么isSaveResponseData=false：

 * - 导出接口返回的是二进制文件流，数据量可能很大

 * - 保存到日志会占用大量存储空间

 * - 而且二进制数据也没有阅读价值

 */

@Log(

    title = "用户管理",

    businessType = BusinessType.EXPORT,

    isSaveResponseData = false

)

@PostMapping("/export")

public void export(HttpServletResponse response, SysUser user) {

    List<SysUser> list = userService.selectUserList(user);

    ExcelUtil<SysUser> util = new ExcelUtil<>(SysUser.class);

    util.exportExcel(response, list, "用户数据");

}

```

  

#### 实现原理

  

```java

@Aspect

@Component

public class LogAspect {

    // 切入点：匹配所有@Log注解的方法

    @Pointcut("@annotation(controllerLog)")

    public void logPointCut(Log controllerLog) {}

    // 方法执行成功后记录日志

    @AfterReturning(pointcut = "logPointCut(controllerLog)", returning = "jsonResult")

    public void doAfterReturning(JoinPoint joinPoint, Log controllerLog, Object jsonResult) {

        handleLog(joinPoint, controllerLog, null, jsonResult);

    }

    // 方法抛出异常后也记录日志

    @AfterThrowing(value = "logPointCut(controllerLog)", throwing = "e")

    public void doAfterThrowing(JoinPoint joinPoint, Log controllerLog, Exception e) {

        handleLog(joinPoint, controllerLog, e, null);

    }

    protected void handleLog(...) {

        // 1. 获取当前登录用户

        LoginUser loginUser = SecurityUtils.getLoginUser();

        // 2. 构建操作日志对象

        OperLogEvent operLog = new OperLogEvent();

        operLog.setOperName(loginUser.getUsername());

        operLog.setTitle(controllerLog.title());

        operLog.setBusinessType(controllerLog.businessType().ordinal());

        // 3. 记录请求参数（如果isSaveRequestData=true）

        if (controllerLog.isSaveRequestData()) {

            operLog.setOperParam(JSON.toJSONString(argsArrayToString(joinPoint.getArgs())));

        }

        // 4. 记录返回结果（如果isSaveResponseData=true）

        if (controllerLog.isSaveResponseData() && jsonResult != null) {

            operLog.setJsonResult(JSON.toJSONString(jsonResult));

        }

        // 5. 异步保存到数据库

        asyncManager.execute(AsyncFactory.recordOper(operLog));

    }

}

```

### 2. @DataScope - 数据权限注解

  

**文件位置**: `ruoyi-common/src/main/java/com/ruoyi/common/annotation/DataScope.java`

  

#### 功能说明

  

根据用户的角色数据范围，自动在SQL中添加部门或用户过滤条件，实现行级数据权限控制。

  

#### 注解定义

  

```java

@Target(ElementType.METHOD)

@Retention(RetentionPolicy.RUNTIME)

@Documented

public @interface DataScope {

    public String userAlias() default "";      // 用户表别名

    public String deptAlias() default "";      // 部门表别名

    public String userField() default "user_id";   // 用户字段名

    public String deptField() default "dept_id";   // 部门字段名

    public String permission() default "";     // 权限字符

}

```

  

#### 属性详解

  

| 属性 | 类型 | 默认值 | 说明 |

|------|------|--------|------|

| userAlias | String | "" | SQL中用户表的别名，如"u" |

| deptAlias | String | "" | SQL中部门表的别名，如"d" |

| userField | String | "user_id" | 用户ID字段名 |

| deptField | String | "dept_id" | 部门ID字段名 |

| permission | String | "" | 权限字符，用于匹配角色的权限 |

  

#### 数据范围类型

  

存储在`sys_role.data_scope`字段：

  

| 值 | 说明 | SQL条件 |

|----|------|---------|

| 1 | 全部数据权限 | 无过滤 |

| 2 | 自定义数据权限 | `dept_id IN (SELECT dept_id FROM sys_role_dept)` |

| 3 | 本部门数据 | `dept_id = 当前用户部门ID` |

| 4 | 本部门及以下 | `dept_id IN (本部门及子部门)` |

| 5 | 仅本人数据 | `user_id = 当前用户ID` |

  

#### 使用示例

  

**基础用法**:

  

```java

@Service

public class SysUserServiceImpl implements ISysUserService {

    /**

     * 查询用户列表（带数据权限过滤）

     *

     * 为什么这样写：

     * 1. deptAlias="d" - 对应SQL中sys_dept表的别名"d"

     * 2. userAlias="u" - 对应SQL中sys_user表的别名"u"

     * 3. AOP切面会根据当前用户的角色data_scope，自动生成WHERE条件

     *

     * 例如：

     * - 如果用户角色data_scope=3（本部门），则追加：AND d.dept_id = 103

     * - 如果用户角色data_scope=4（本部门及以下），则追加：AND d.dept_id IN (...)

     * - 如果用户角色data_scope=5（仅本人），则追加：AND u.user_id = 1

     */

    @DataScope(deptAlias = "d", userAlias = "u")

    @Override

    public List<SysUser> selectUserList(SysUser user) {

        return userMapper.selectUserList(user);

    }

}

```

  

**对应的Mapper XML**:

  

```xml

<!-- 为什么需要在XML中预留${params.dataScope}：

     - AOP切面会将生成的SQL片段存入params map中

     - key为"dataScope"

     - MyBatis动态SQL会将其拼接到WHERE子句中

-->

<select id="selectUserList" parameterType="SysUser" resultMap="SysUserResult">

    select u.user_id, u.user_name, ..., d.dept_id, d.dept_name

    from sys_user u

    left join sys_dept d on u.dept_id = d.dept_id

    where u.del_flag = '0'

    <if test="userName != null and userName != ''">

        AND u.user_name like concat('%', #{userName}, '%')

    </if>

    <!-- 数据权限过滤（由@DataScope注解自动生成） -->

    ${params.dataScope}

</select>

```

  

**指定权限字符**:

```java
 * 查询已分配用户角色列表
```

**自定义字段名**:

  

```java

/**

 * 查询订单列表（订单表使用不同的字段名）

 *

 * 为什么设置userField和deptField：

 * - 不是所有表都用user_id和dept_id作为字段名

 * - 例如订单表可能用create_by和dept_id

 */

@DataScope(

    deptAlias = "o",

    userAlias = "o",

    userField = "create_by",   // 订单表的用户字段

    deptField = "dept_id"      // 订单表的部门字段

)

public List<Order> selectOrderList(Order order) {

    return orderMapper.selectOrderList(order);

}

```

  

#### 实现原理

  

```java

@Aspect

@Component

public class DataScopeAspect {

    @Before("@annotation(controllerDataScope)")

    public void doBefore(JoinPoint point, DataScope dataScope) {

        handleDataScope(point, dataScope);

    }

    protected void handleDataScope(JoinPoint joinPoint, DataScope dataScope) {

        // 1. 获取当前用户

        LoginUser loginUser = SecurityUtils.getLoginUser();

        // 2. 超级管理员不添加过滤

        if (loginUser.getUser().isAdmin()) {

            return;

        }

        // 3. 遍历用户的所有角色，构建SQL条件

        StringBuilder sqlString = new StringBuilder();

        for (SysRole role : loginUser.getUser().getRoles()) {

            String dataScope = role.getDataScope();

            if (DATA_SCOPE_ALL.equals(dataScope)) {

                // 全部数据权限，直接返回

                return;

            } else if (DATA_SCOPE_CUSTOM.equals(dataScope)) {

                // 自定义数据权限

                sqlString.append(" OR ").append(dataScope.deptAlias())

                    .append(".").append(dataScope.deptField())

                    .append(" IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ")

                    .append(role.getRoleId()).append(")");

            } else if (DATA_SCOPE_DEPT.equals(dataScope)) {

                // 本部门数据

                sqlString.append(" OR ").append(dataScope.deptAlias())

                    .append(".").append(dataScope.deptField())

                    .append(" = ").append(loginUser.getDeptId());

            } else if (DATA_SCOPE_DEPT_AND_CHILD.equals(dataScope)) {

                // 本部门及以下（利用ancestors字段）

                sqlString.append(" OR ").append(dataScope.deptAlias())

                    .append(".").append(dataScope.deptField())

                    .append(" IN (SELECT dept_id FROM sys_dept WHERE find_in_set(")

                    .append(loginUser.getDeptId()).append(", ancestors))");

            } else if (DATA_SCOPE_SELF.equals(dataScope)) {

                // 仅本人数据

                sqlString.append(" OR ").append(dataScope.userAlias())

                    .append(".").append(dataScope.userField())

                    .append(" = ").append(loginUser.getUserId());

            }

        }

        // 4. 将SQL片段注入到params中

        if (sqlString.length() > 0) {

            Object params = joinPoint.getArgs()[0];

            if (params instanceof BaseEntity) {

                ((BaseEntity) params).getParams().put(

                    DATA_SCOPE, " AND (" + sqlString.substring(4) + ")"

                );

            }

        }

    }

}

```

### 3. @Excel / @Excels - Excel导出注解

  

**文件位置**: `ruoyi-common/src/main/java/com/ruoyi/common/annotation/Excel.java`

  

#### 功能说明

  

通过注解配置实体类字段与Excel列的映射关系，实现零代码Excel导入导出。

  

#### 注解定义（核心属性）

  

```java

@Retention(RetentionPolicy.RUNTIME)

@Target(ElementType.FIELD)

public @interface Excel {

    // 基础属性

    public int sort() default Integer.MAX_VALUE;           // 排序

    public String name() default "";                       // 列头名称

    public String dateFormat() default "";                 // 日期格式

    public Type type() default Type.ALL;                   // 导出导入类型

    // 数据转换

    public String dictType() default "";                   // 字典类型

    public String readConverterExp() default "";           // 表达式转换

    public String separator() default ",";                 // 分隔符

    // 样式配置

    public double width() default 16;                      // 列宽

    public double height() default 14;                     // 行高

    public HorizontalAlignment align() default CENTER;     // 对齐方式

    public String suffix() default "";                     // 后缀

    // 高级功能

    public String prompt() default "";                     // 提示信息

    public String[] combo() default {};                    // 下拉框选项

    public boolean isStatistics() default false;           // 自动统计

    public ColumnType cellType() default STRING;           // 单元格类型

    // 跨对象属性

    public String targetAttr() default "";                 // 关联对象属性

    // 自定义处理器

    public Class<?> handler() default ExcelHandlerAdapter.class;

    public String[] args() default {};

}

```

  

#### 完整使用示例

  

**实体类配置**:

  

```java

public class SysUser extends BaseEntity {

    /**

     * 用户ID

     *

     * 为什么type=EXPORT：

     * - 用户ID是自增主键，导入时不需要填写

     * - 只在导出时显示

     */

    @Excel(name = "用户序号", type = Type.EXPORT, cellType = ColumnType.NUMERIC)

    private Long userId;

    /**

     * 部门ID

     *

     * 为什么type=IMPORT：

     * - 导入时需要填写部门ID

     * - 导出时用部门名称代替（见下面的dept字段）

     */

    @Excel(name = "部门编号", type = Type.IMPORT)

    private Long deptId;

    /**

     * 用户名称

     *

     * 为什么width=30：

     * - 用户名可能较长，增加列宽便于阅读

     */

    @Excel(name = "用户名称", width = 30)

    private String userName;

    /**

     * 手机号码

     *

     * 为什么cellType=TEXT：

     * - 防止Excel将手机号显示为科学计数法（13812345678 → 1.38E+10）

     * - TEXT类型会以文本形式存储

     */

    @Excel(name = "手机号码", cellType = ColumnType.TEXT)

    private String phonenumber;

    /**

     * 用户性别

     *

     * 为什么readConverterExp：

     * - 数据库存储的是"0"、"1"、"2"

     * - Excel显示为"男"、"女"、"未知"

     * - 导入时自动反向转换

     */

    @Excel(name = "用户性别", readConverterExp = "0=男,1=女,2=未知")

    private String sex;

    /**

     * 帐号状态

     *

     * 为什么dictType：

     * - 从sys_normal_disable字典获取标签

     * - 导出时："0" → "正常"

     * - 导入时："正常" → "0"

     * - 优势：统一管理，修改字典即可全局生效

     */

    @Excel(name = "帐号状态", dictType = "sys_normal_disable")

    private String status;

    /**

     * 最后登录时间

     *

     * 为什么dateFormat和type=EXPORT：

     * - 导出时按指定格式显示

     * - 导入时不需要此字段

     */

    @Excel(

        name = "最后登录时间",

        width = 30,

        dateFormat = "yyyy-MM-dd HH:mm:ss",

        type = Type.EXPORT

    )

    private Date loginDate;

    /**

     * 部门对象

     *

     * 为什么用@Excels和targetAttr：

     * - 一个dept对象需要导出多个字段（部门名称、部门负责人）

     * - targetAttr="deptName"表示访问dept.getDeptName()

     * - 支持多级访问，如"dept.manager.name"

     */

    @Excels({

        @Excel(name = "部门名称", targetAttr = "deptName", type = Type.EXPORT),

        @Excel(name = "部门负责人", targetAttr = "leader", type = Type.EXPORT)

    })

    private SysDept dept;

    /**

     * 金额

     *

     * 为什么isStatistics=true：

     * - 导出时在最后一行自动统计总和

     * - 适用于数值型字段

     */

    @Excel(name = "余额", isStatistics = true)

    private BigDecimal balance;

    /**

     * 头像

     *

     * 为什么cellType=IMAGE：

     * - 导出时将图片嵌入Excel单元格

     * - 值为图片路径，多个用逗号分隔

     */

    @Excel(name = "头像", cellType = ColumnType.IMAGE)

    private String avatar;

    // getter/setter...

}

```

  

#### Controller导出方法

  

```java

@RestController
```

**按IP限流**:

```java
 * 为什么limitType=IP：

 * - 防止同一IP暴力破解密码

 * - 每个IP 60秒内最多尝试10次登录

 */

@RateLimiter(key = "login", time = 60, count = 10, limitType = LimitType.IP)
```

**按用户限流**:

```java
 *

 * - 防止同一用户短时间内重复下单

 * - 每个用户30秒内最多提交3次

 */

    orderService.submitOrder(order);

    return AjaxResult.success();
```

#### 实现原理

  

```java

@Aspect

public class RateLimiterAspect {

    @Autowired

    private RedisCache redisCache;

    @Around("@annotation(rateLimiter)")

    public Object around(ProceedingJoinPoint joinPoint, RateLimiter rateLimiter)

            throws Throwable {

        // 1. 生成限流key

        String key = rateLimiter.key();

        if (rateLimiter.limitType() == LimitType.IP) {

            key += ":" + IpUtils.getIpAddr();

        } else if (rateLimiter.limitType() == LimitType.USER) {

            key += ":" + SecurityUtils.getUserId();

        }

        // 2. 检查是否超限

        Integer count = redisCache.getCacheObject(key);

        if (count != null && count >= rateLimiter.count()) {

            throw new ServiceException("请求过于频繁，请稍后再试");

        }

        // 3. 计数+1，设置过期时间

        if (count == null) {

            redisCache.setCacheObject(key, 1, rateLimiter.time(), TimeUnit.SECONDS);

        } else {

            redisCache.redisTemplate.opsForValue().increment(key);

        }

        // 4. 执行目标方法

        return joinPoint.proceed();

    }

}

```

### 6. @RepeatSubmit - 防重复提交注解

  

**文件位置**: `ruoyi-common/src/main/java/com/ruoyi/common/annotation/RepeatSubmit.java`

  

#### 功能说明

  

防止用户快速点击导致表单重复提交，基于Redis实现。

  

#### 注解定义

  

```java

@Inherited

@Target(ElementType.METHOD)

@Retention(RetentionPolicy.RUNTIME)

@Documented

public @interface RepeatSubmit {

    public int interval() default 5000;  // 间隔时间（毫秒）

    public String message() default "不允许重复提交，请稍候再试";

}

```

  

#### 使用示例

  

```java

@RestController

@RequestMapping("/system/order")

public class OrderController extends BaseController {

    /**

     * 提交订单

     *

     * 为什么需要防重复提交：

     * 1. 用户快速点击"提交"按钮，可能发出多个相同请求

     * 2. 网络延迟导致用户多次点击

     * 3. 5秒内相同请求视为重复提交

     *

     * 如何实现：

     * - 根据用户ID+请求URL+请求参数生成唯一key

     * - 存入Redis，5秒过期

     * - 第二次请求发现key已存在，拒绝执行

     */

    @RepeatSubmit(interval = 5000, message = "订单提交中，请勿重复点击")

    @PostMapping("/submit")

    public AjaxResult submit(@RequestBody Order order) {

        orderService.submitOrder(order);

        return AjaxResult.success();

    }

}

```

  

#### 实现原理

  

```java

@Aspect

public class RepeatSubmitAspect {

    @Autowired

    private RedisCache redisCache;

    @Around("@annotation(repeatSubmit)")

    public Object around(ProceedingJoinPoint joinPoint, RepeatSubmit repeatSubmit)

            throws Throwable {

        // 1. 生成唯一key（用户ID + URL + 参数MD5）

        String key = generateKey(joinPoint);

        // 2. 尝试设置Redis（不存在才设置成功）

        Boolean flag = redisCache.setIfAbsent(

            key,

            "1",

            repeatSubmit.interval(),

            TimeUnit.MILLISECONDS

        );

        if (!flag) {

            // 3. key已存在，说明是重复提交

            throw new ServiceException(repeatSubmit.message());

        }

        // 4. 执行目标方法

        return joinPoint.proceed();

    }

    private String generateKey(ProceedingJoinPoint joinPoint) {

        String url = ServletUtils.getRequest().getRequestURI();

        String userId = SecurityUtils.getUserId().toString();

        String params = JSON.toJSONString(joinPoint.getArgs());

        String md5 = Md5Utils.hash(userId + url + params);

        return "repeat_submit:" + md5;

    }

}

```


  

#### DesensitizedType枚举

  

```java

public enum DesensitizedType {

    PHONE,        // 手机号：138****5678

    EMAIL,        // 邮箱：a***@example.com

    ID_CARD,      // 身份证：110**********1234

    ADDRESS,      // 地址：北京市******

    BANK_CARD,    // 银行卡：6222********1234

    PASSWORD      // 密码：******

```

  

#### 使用示例

  

```java

public class SysUser extends BaseEntity {

    /**

     * 手机号码（脱敏）

     *

     * 为什么脱敏：

     * - 保护用户隐私

     * - 前端展示时中间4位用*代替

     * - 13812345678 → 138****5678

     *

     * 注意：

     * - 只在JSON序列化时脱敏

     * - 数据库中仍是完整手机号

     * - 后端业务逻辑仍可获取完整号码

     */

    @Sensitive(desensitizedType = DesensitizedType.PHONE)

    private String phonenumber;

    /**

     * 邮箱（脱敏）

     * - admin@example.com → a***@example.com

     */

    @Sensitive(desensitizedType = DesensitizedType.EMAIL)

    private String email;

    /**

     * 身份证号（脱敏）

     * - 110101199001011234 → 110**********1234

     */

    @Sensitive(desensitizedType = DesensitizedType.ID_CARD)

    private String idCard;

}

```

  

#### 实现原理

  

```java

public class SensitiveJsonSerializer extends JsonSerializer<String>

        implements ContextualSerializer {

    private DesensitizedType desensitizedType;

    @Override

    public void serialize(String value, JsonGenerator gen, SerializerProvider provider)

            throws IOException {

        if (value == null) {

            gen.writeNull();

            return;

        }

        // 根据脱敏类型处理

        String masked = desensitize(value, desensitizedType);

        gen.writeString(masked);

    }

    private String desensitize(String value, DesensitizedType type) {

        switch (type) {

            case PHONE:

                // 13812345678 → 138****5678

                return value.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");

            case EMAIL:

                // admin@example.com → a***@example.com

                return value.replaceAll("(^.)[^@]*(@.*$)", "$1***$2");

            case ID_CARD:

                // 110101199001011234 → 110**********1234

                return value.replaceAll("(\\d{3})\\d{15}(\\d{3})", "$1**********$2");

            default:

                return value;

        }

    }

}

```

### 5. @PreAuthorize - 权限校验

  

#### 功能说明

  

Spring Security方法级权限校验，在方法执行前验证权限。

  

#### 使用示例

  

```java

@RestController

@RequestMapping("/system/user")

public class SysUserController {

    /**

     * 单个权限校验

     *

     * @ss是PermissionService的Bean名称

     * hasPermi()方法判断用户是否有指定权限

     *

     * 执行流程：

     * 1. 请求进入 → JWT过滤器解析Token

     * 2. 获取LoginUser中的permissions集合

     * 3. 判断是否包含"system:user:list"

     * 4. 有权限→执行方法，无权限→返回403

     */

    @PreAuthorize("@ss.hasPermi('system:user:list')")

    @GetMapping("/list")

    public TableDataInfo list(SysUser user) {...}

    /**

     * 多个权限之一

     *

     * 用户只要有add或update任一权限即可访问

     */

    @PreAuthorize("@ss.hasAnyPermi('system:user:add,system:user:edit')")

    @PostMapping

    public AjaxResult add(@RequestBody SysUser user) {...}

    /**

     * 角色校验

     *

     * 只有admin角色才能删除用户

     */

    @PreAuthorize("@ss.hasRole('admin')")

    @DeleteMapping("/{userIds}")

    public AjaxResult remove(@PathVariable Long[] userIds) {...}

    /**

     * 多个角色之一

     */

    @PreAuthorize("@ss.hasAnyRoles('admin,common')")

    @GetMapping("/export")

    public void export(...) {...}

}

```

  

#### SpEL表达式

  

```java

// 内置表达式

@PreAuthorize("hasRole('ADMIN')")              // 是否有角色

@PreAuthorize("hasAuthority('READ')")          // 是否有权限

@PreAuthorize("isAuthenticated()")             // 是否已认证

@PreAuthorize("isAnonymous()")                 // 是否匿名

  

// 自定义表达式（@ss）

@PreAuthorize("@ss.hasRole('admin')")

  

// 方法参数引用

@PreAuthorize("#userId == authentication.principal.userId")

public AjaxResult getInfo(@PathVariable Long userId) {...}
```

### 6. @Transactional - 事务控制

  

#### 功能说明

  

声明式事务管理，保证数据一致性。

  

#### 使用示例

  

```java

@Service

public class SysUserServiceImpl implements ISysUserService {

    /**

     * 新增用户（事务控制）

     *

     * 为什么加@Transactional：

     * 1. 涉及多张表：sys_user、sys_user_role、sys_user_post

     * 2. 原子性：要么全部成功，要么全部回滚

     * 3. 如果插入用户后，插入角色关联失败，用户数据也会回滚

     *

     * rollbackFor = Exception.class：

     * - 默认只回滚RuntimeException

     * - 设置后，所有Exception都会回滚

     */

    @Override

    @Transactional(rollbackFor = Exception.class)

    public int insertUser(SysUser user) {

        // 1. 插入用户基本信息

        int rows = userMapper.insertUser(user);

        // 2. 插入用户角色关联

        insertUserRole(user);

        // 3. 插入用户岗位关联

        insertUserPost(user);

        return rows;

    }

    /**

     * 修改用户（先删后增策略）

     *

     * 为什么用事务：

     * - 删除旧关联和插入新关联必须是原子操作

     * - 防止中途失败导致数据不一致

     */

    @Override

    @Transactional

    public int updateUser(SysUser user) {

        // 1. 删除旧的角色关联

        userRoleMapper.deleteUserRoleByUserId(user.getUserId());

        // 2. 插入新的角色关联

        insertUserRole(user);

        // 3. 删除旧的岗位关联

        userPostMapper.deleteUserPostByUserId(user.getUserId());

        // 4. 插入新的岗位关联

        insertUserPost(user);

        // 5. 更新用户基本信息

        return userMapper.updateUser(user);

    }

}

```

  

#### 事务传播行为

  

```java

/**

 * 事务传播行为（Propagation）

 *

 * REQUIRED（默认）：如果当前有事务就加入，没有就新建

 * REQUIRES_NEW：总是新建事务，挂起当前事务

 * SUPPORTS：有事务就用，没有就不用

 * NOT_SUPPORTED：以非事务方式执行

 */

@Transactional(propagation = Propagation.REQUIRED)

public void method1() {

    // 默认传播行为

}

  

@Transactional(propagation = Propagation.REQUIRES_NEW)

public void method2() {

    // 总是新建事务，不受外层事务影响

}

```

  

#### 注意事项

  

```java

/**

 * @Transactional失效场景

 *

 * 1. 方法不是public

 * 2. 同类内部调用（绕过代理）

 * 3. 异常被捕获未抛出

 * 4. 数据库引擎不支持事务（如MyISAM）

 */

@Service

public class UserService {

    // ❌ 错误：private方法，事务不生效

    @Transactional

    private void privateMethod() {}

    // ❌ 错误：同类调用，绕过AOP代理

    public void method1() {

        this.method2();  // method2的事务不生效

    }

    @Transactional

    public void method2() {}

    // ❌ 错误：异常被捕获

    @Transactional

    public void method3() {

        try {

            // 业务逻辑

        } catch (Exception e) {

            // 吞掉异常，事务不会回滚

        }

    }

    // ✅ 正确：重新抛出异常

    @Transactional

    public void method4() {

        try {

            // 业务逻辑

        } catch (Exception e) {

            log.error("错误", e);

            throw e;  // 重新抛出，触发回滚

        }

    }

}

```

## 五、注解元注解详解

  

### Java内置元注解

  

| 元注解 | 作用 | 示例 |

|--------|------|------|

| @Target | 标注注解可以用在哪里 | METHOD, FIELD, TYPE |

| @Retention | 注解保留到什么时候 | RUNTIME, CLASS, SOURCE |

| @Documented | 是否生成到Javadoc | - |

| @Inherited | 子类是否继承父类注解 | - |

| @Repeatable | 是否可重复使用 | - |

  

### 示例分析

  

```java

/**

 * @Log注解的元注解分析

 */

@Target({ ElementType.PARAMETER, ElementType.METHOD })  

// 可以用在方法和参数上

@Retention(RetentionPolicy.RUNTIME)  

// 运行时保留，可以通过反射读取

@Documented  

// 生成Javadoc时会包含此注解

public @interface Log {

    ...

}

  

/**

 * 为什么@Retention要用RUNTIME：

 * - SOURCE：只在源码中保留，编译后丢弃（如@Override）

 * - CLASS：保留到class文件，运行时无法读取

 * - RUNTIME：运行时可通过反射读取（AOP需要）

 *

 * AOP切面通过反射读取注解信息：

 * Method method = joinPoint.getSignature().getMethod();

 * Log log = method.getAnnotation(Log.class);  // 只有RUNTIME才能读到

 */

```

## 六、总结

  

### 注解使用最佳实践

  

1. **权限控制**: Controller方法必须加`@PreAuthorize`

2. **操作日志**: 增删改操作加`@Log`

3. **事务控制**: 涉及多表操作加`@Transactional`

4. **数据权限**: 查询列表方法加`@DataScope`

5. **防重提交**: 关键业务接口加`@RepeatSubmit`

6. **接口限流**: 短信、登录等接口加`@RateLimiter`

7. **数据脱敏**: 敏感字段加`@Sensitive`

8. **Excel导出**: 实体字段加`@Excel`配置

  

### 注解优先级

  

```

方法注解 > 类注解 > 默认配置

```
