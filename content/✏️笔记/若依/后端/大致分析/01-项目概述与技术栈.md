# RuoYi-Vue 项目概述与技术栈详解

## 一、项目简介

### 1.1 什么是 RuoYi-Vue

RuoYi-Vue（若依管理系统）是一个基于 **Spring Boot + Vue** 前后端分离的 Java 快速开发框架。它提供了一套完整的企业级后台管理系统解决方案，包括用户管理、角色权限、菜单管理、字典管理、代码生成等核心功能。

**项目信息：**
- **版本**: 3.9.2
- **官方网站**: http://www.ruoyi.vip
- **开源协议**: MIT
- **适用场景**: 企业后台管理系统、CMS、OA系统、ERP系统等

### 1.2 核心特性

- **前后端分离**: 后端提供 RESTful API，前端独立部署
- **模块化设计**: Maven 多模块结构，职责清晰
- **权限管理**: 基于 Spring Security + JWT + RBAC 的完整权限体系
- **代码生成**: 一键生成前后端 CRUD 代码
- **数据权限**: 支持部门级别的数据范围控制
- **监控功能**: 系统监控、缓存监控、在线用户监控
- **定时任务**: 基于 Quartz 的任务调度
- **操作日志**: 自动记录用户操作行为

## 三、Maven 依赖管理

### 3.1 父 POM 统一管理

**文件位置**: `pom.xml` (根目录)

```xml
<properties>
    <ruoyi.version>3.9.2</ruoyi.version>
    <java.version>17</java.version>
    <spring-boot.version>4.0.3</spring-boot.version>
    <mybatis-spring-boot.version>4.0.1</mybatis-spring-boot.version>
    <druid.version>1.2.28</druid.version>
    <pagehelper.boot.version>2.1.1</pagehelper.boot.version>
    <fastjson.version>2.0.61</fastjson.version>
    <jwt.version>0.9.1</jwt.version>
    <poi.version>4.1.2</poi.version>
    <!-- 更多版本定义... -->
</properties>
```

**优势**:
- 统一版本管理，避免依赖冲突
- 子模块继承父POM，无需重复声明版本
- 便于升级和维护

### 3.2 子模块依赖关系

```
ruoyi-admin (Web入口)
├── ruoyi-framework (框架核心)
│   ├── ruoyi-system (系统业务)
│   │   └── ruoyi-common (通用工具)
│   └── ruoyi-common
├── ruoyi-quartz (定时任务)
│   └── ruoyi-common
└── ruoyi-generator (代码生成)
    └── ruoyi-common
```

**依赖传递规则**:
- A 依赖 B，B 依赖 C → A 自动获得 C
- 子模块只需声明直接依赖，间接依赖自动引入

## 五、技术选型原因分析

### 5.1 为什么选择 Spring Boot？

| 优势 | 说明 |
|------|------|
| **约定优于配置** | 零XML配置，开箱即用 |
| **内嵌服务器** | 自带Tomcat，无需单独部署 |
| **自动装配** | 根据依赖自动配置Bean |
| **生态丰富** | 大量Starter可用 |
| **微服务友好** | 易于迁移到Spring Cloud |

### 5.2 为什么选择 MyBatis 而非 JPA？

| 对比项 | MyBatis | JPA/Hibernate |
|--------|---------|---------------|
| **SQL控制** | 完全掌控，适合复杂查询 | 自动生成，简单场景方便 |
| **性能优化** | 精确优化每条SQL | 需要理解内部机制 |
| **学习曲线** | 较低，会SQL即可 | 较高，需理解ORM概念 |
| **动态SQL** | 强大的XML标签 | 需用Criteria API |
| **国内生态** | 广泛使用，资料多 | 相对较少 |

**RuoYi的选择理由**:
- 国内开发者更熟悉SQL
- 复杂的权限查询需要精细控制
- 动态SQL需求多（条件查询、数据权限）

### 5.3 为什么选择 JWT 而非 Session？

| 对比项 | JWT | Session |
|--------|-----|---------|
| **无状态** | 是，适合分布式 | 否，需要Session共享 |
| **跨域支持** | 天然支持 | 需要额外配置 |
| **移动端友好** | 是 | 否 |
| **服务端压力** | 低（不存储会话） | 高（存储Session） |
| **撤销困难** | 需要黑名单机制 | 直接删除Session |

**RuoYi的实现**: JWT + Redis 结合，既享受无状态优势，又支持主动撤销

### 5.4 为什么选择 Element UI？

- **组件丰富**: 60+高质量组件
- **文档完善**: 中文文档详细
- **社区活跃**: 大量第三方扩展
- **企业级设计**: 符合后台管理系统审美
- **Vue 2最佳搭档**: 稳定性好


## 九、常见问题

### Q1: 为什么启动报错 "找不到主类"？

**A**: 确保在 `ruoyi-admin` 模块中运行，主类是 `RuoYiApplication.java`

### Q2: 前端跨域问题如何解决？

**A**: 后端已配置CORS，检查 `ResourcesConfig.java` 中的跨域配置

### Q3: 如何修改端口号？

**A**: 修改 `application.yml` 中的 `server.port`

### Q4: Redis必须安装吗？

**A**: 是的，Token存储、字典缓存、验证码都依赖Redis

### Q5: 能否不使用前后端分离？

**A**: 可以，使用 RuoYi 单体版本（非Vue版）
