# RuoYi-Vue 权限管理系统深度解析

## 一、权限系统概述

RuoYi-Vue采用 **RBAC（Role-Based Access Control）基于角色的访问控制** 模型，实现完整的权限管理体系。

### 1.1 核心概念

```
用户 (User) → 角色 (Role) → 菜单/权限 (Menu)
   ↓
部门 (Dept) → 数据权限 (Data Scope)
```

**四层权限控制**:
1. **登录认证**: 验证用户身份（用户名+密码+验证码）
2. **功能权限**: 控制菜单和按钮的访问（基于角色）
3. **数据权限**: 控制数据可见范围（基于部门）
4. **接口权限**: 后端API级别的权限校验

## 二、数据库设计

### 2.1 核心表结构

```sql
-- 用户表
sys_user (user_id, user_name, password, dept_id, ...)

-- 角色表  
sys_role (role_id, role_name, role_key, data_scope, ...)

-- 菜单权限表
sys_menu (menu_id, menu_name, menu_type, perms, parent_id, ...)

-- 部门表
sys_dept (dept_id, dept_name, ancestors, parent_id, ...)

-- 关联表
sys_user_role (user_id, role_id)     -- 用户-角色
sys_role_menu (role_id, menu_id)     -- 角色-菜单
sys_role_dept (role_id, dept_id)     -- 角色-部门(数据权限)
```

### 2.2 菜单类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **M (目录)** | 一级/二级菜单目录 | 系统管理、系统监控 |
| **C (菜单)** | 具体功能页面 | 用户管理、角色管理 |
| **F (按钮)** | 页面内操作按钮 | 新增、修改、删除、导出 |

**权限标识 (perms字段)**:
- 格式：`模块:功能:操作`
- 示例：`system:user:list`、`system:user:add`、`system:user:edit`
- 超级管理员拥有 `*:*:*` 所有权限

### 3.1 Spring Security配置

**文件**: `ruoyi-framework/src/main/java/com/ruoyi/framework/config/SecurityConfig.java`

```java
@Configuration
@EnableMethodSecurity(prePostEnabled = true, securedEnabled = true)
public class SecurityConfig {
    
    @Bean
    protected SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())  // 禁用CSRF
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))  // 无状态
            .authorizeHttpRequests(auth -> {
                auth.requestMatchers("/login", "/captchaImage").permitAll()  // 匿名访问
                    .anyRequest().authenticated();  // 其他需要认证
            })
            .addFilterBefore(jwtAuthenticationFilter, 
                UsernamePasswordAuthenticationFilter.class)  // JWT过滤器
            .build();
    }
}
```

### 3.2 JWT认证过滤器

**文件**: `JwtAuthenticationTokenFilter.java`

```java
@Component
public class JwtAuthenticationTokenFilter extends OncePerRequestFilter {
    
    @Autowired
    private TokenService tokenService;
    
    @Override
    protected void doFilterInternal(HttpServletRequest request, 
            HttpServletResponse response, FilterChain chain) {
        
        // 1. 从请求头获取Token
        LoginUser loginUser = tokenService.getLoginUser(request);
        
        // 2. 验证Token并设置SecurityContext
        if (loginUser != null && SecurityUtils.getAuthentication() == null) {
            tokenService.verifyToken(loginUser);  // 自动续期
            
            UsernamePasswordAuthenticationToken authentication = 
                new UsernamePasswordAuthenticationToken(
                    loginUser, null, loginUser.getAuthorities());
            
            SecurityContextHolder.getContext().setAuthentication(authentication);
        }
        
        chain.doFilter(request, response);
    }
}
```

**执行流程**:
```
请求进入 → 提取Token → 解析JWT → Redis查用户 → 设置认证信息 → Controller
```

#### PermissionService 权限服务

**文件**: `PermissionService.java` (注册为Bean名称 "ss")

```java
@Service("ss")
public class PermissionService {
    
    /**
     * 验证用户是否具备某权限
     */
    public boolean hasPermi(String permission) {
        if (StringUtils.isEmpty(permission)) {
            return false;
        }
        
        LoginUser loginUser = SecurityUtils.getLoginUser();
        if (StringUtils.isNull(loginUser) || CollectionUtils.isEmpty(loginUser.getPermissions())) {
            return false;
        }
        
        // 超级管理员拥有所有权限
        return loginUser.getPermissions().contains(Constants.ALL_PERMISSION) 
            || loginUser.getPermissions().contains(permission);
    }
    
    /**
     * 验证用户是否具有任意一个权限
     */
    public boolean hasAnyPermi(String permissions) {
        Set<String> permissionsList = StringUtils.splitToSet(permissions, ',');
        return permissionsList.stream()
            .anyMatch(permission -> hasPermi(permission));
    }
    
    /**
     * 验证用户是否拥有某个角色
     */
    public boolean hasRole(String role) {
        if (StringUtils.isEmpty(role)) {
            return false;
        }
        
        LoginUser loginUser = SecurityUtils.getLoginUser();
        if (StringUtils.isNull(loginUser) || CollectionUtils.isEmpty(loginUser.getUser().getRoles())) {
            return false;
        }
        
        // 超级管理员拥有所有角色
        return loginUser.getUser().getRoles().stream()
            .anyMatch(r -> r.isAdmin() || r.getRoleKey().equals(role));
    }
}
```

## 四、数据权限实现

### 4.1 @DataScope 注解

**作用**: 根据用户的角色数据范围，自动在SQL中添加过滤条件

**文件**: `DataScopeAspect.java`

```java
@Aspect
@Component
public class DataScopeAspect {
    
    @Pointcut("@annotation(controllerDataScope)")
    public void dataScopePointCut(DataScope controllerDataScope) {}
    
    @Before("dataScopePointCut(controllerDataScope)")
    public void doBefore(JoinPoint point, DataScope controllerDataScope) {
        handleDataScope(point, controllerDataScope);
    }
    
    protected void handleDataScope(JoinPoint joinPoint, DataScope dataScope) {
        // 获取当前用户
        LoginUser loginUser = SecurityUtils.getLoginUser();
        
        // 如果是超级管理员，不添加过滤
        if (loginUser.getUser().isAdmin()) {
            return;
        }
        
        // 获取用户的数据权限范围
        for (SysRole role : loginUser.getUser().getRoles()) {
            String dataScope = role.getDataScope();
            
            if (DATA_SCOPE_ALL.equals(dataScope)) {
                // 全部数据权限，不添加过滤
                return;
            } else if (DATA_SCOPE_CUSTOM.equals(dataScope)) {
                // 自定义数据权限，根据sys_role_dept表过滤
                sqlString.append(" OR d.dept_id IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ")
                    .append(role.getRoleId()).append(")");
            } else if (DATA_SCOPE_DEPT.equals(dataScope)) {
                // 本部门数据
                sqlString.append(" OR d.dept_id = ").append(loginUser.getDeptId());
            } else if (DATA_SCOPE_DEPT_AND_CHILD.equals(dataScope)) {
                // 本部门及以下
                sqlString.append(" OR d.dept_id IN (SELECT dept_id FROM sys_dept WHERE find_in_set(")
                    .append(loginUser.getDeptId()).append(", ancestors))");
            } else if (DATA_SCOPE_SELF.equals(dataScope)) {
                // 仅本人数据
                sqlString.append(" OR u.user_id = ").append(loginUser.getUserId());
            }
        }
        
        // 将SQL片段注入到params中
        params.put(DATA_SCOPE, " AND (" + sqlString.substring(4) + ")");
    }
}
```

### 4.2 使用示例

```java
@Service
public class SysUserServiceImpl implements ISysUserService {
    
    // 自动注入数据权限SQL
    @DataScope(deptAlias = "d", userAlias = "u")
    public List<SysUser> selectUserList(SysUser user) {
        return userMapper.selectUserList(user);
    }
}
```

**生成的SQL**:
```sql
SELECT * FROM sys_user u
LEFT JOIN sys_dept d ON u.dept_id = d.dept_id
WHERE u.del_flag = '0'
AND (
    d.dept_id = 103  -- 本部门
    OR d.dept_id IN (SELECT dept_id FROM sys_dept WHERE find_in_set(103, ancestors))  -- 子部门
)
```

### 4.3 数据范围类型

| 值 | 说明 | SQL条件 |
|----|------|---------|
| **1** | 全部数据权限 | 无过滤 |
| **2** | 自定义数据权限 | `dept_id IN (SELECT dept_id FROM sys_role_dept)` |
| **3** | 本部门数据 | `dept_id = 当前用户部门ID` |
| **4** | 本部门及以下 | `dept_id IN (本部门及子部门)` |
| **5** | 仅本人数据 | `user_id = 当前用户ID` |

## 五、前端权限控制

### 5.1 路由级别权限

**文件**: `src/store/modules/permission.js`

```javascript
// 获取动态路由
const actions = {
  GenerateRoutes({ commit }) {
    return new Promise(resolve => {
      // 调用后端接口获取菜单树
      getRouters().then(res => {
        const accessedRoutes = filterAsyncRouter(res.data)
        commit('SET_ROUTES', accessedRoutes)
        resolve(accessedRoutes)
      })
    })
  }
}

// 将后端返回的菜单转换为Vue路由
function filterAsyncRouter(routerMap) {
  const accessedRouters = []
  routerMap.forEach(item => {
    const tmp = { ...item }
    if (tmp.component) {
      if (tmp.component === 'Layout') {
        tmp.component = Layout
      } else {
        tmp.component = loadView(tmp.component)
      }
      accessedRouters.push(tmp)
    }
    if (tmp.children) {
      tmp.children = filterAsyncRouter(tmp.children)
    }
  })
  return accessedRouters
}
```

**工作流程**:
```
登录后 → 调用/getRouters → 获取用户菜单 → 转换为Vue路由 → 动态添加
```

### 5.2 按钮级别权限

#### v-hasPermi 指令

**文件**: `src/directive/permission/hasPermi.js`

```javascript
export default {
  inserted(el, binding) {
    const { value } = binding
    const permissions = store.getters.permissions
    const all_permission = "*:*:*"
    
    const hasPermissions = permissions.some(permission => {
      return all_permission === permission || value.includes(permission)
    })
    
    if (!hasPermissions) {
      el.parentNode && el.parentNode.removeChild(el)  // 移除DOM元素
    }
  }
}
```

## 六、权限完整流程

### 6.1 登录与权限加载

```
1. 用户登录
   POST /login {username, password, code, uuid}
   ↓
2. 验证成功，返回Token
   { token: "eyJhbGci..." }
   ↓
3. 前端存储Token到localStorage
   ↓
4. 获取用户信息和权限
   GET /getInfo
   Response: {
     user: {...},
     roles: ["admin", "common"],
     permissions: ["system:user:list", "system:user:add", ...]
   }
   ↓
5. Vuex存储权限信息
   store.commit('SET_ROLES', roles)
   store.commit('SET_PERMISSIONS', permissions)
   ↓
6. 获取动态路由菜单
   GET /getRouters
   Response: [{ name: "System", path: "/system", children: [...] }]
   ↓
7. 动态添加路由
   router.addRoutes(accessedRoutes)
   ↓
8. 渲染侧边栏菜单
```

### 6.2 请求鉴权流程

```
1. 用户点击按钮触发请求
   ↓
2. Axios拦截器添加Token
   headers.Authorization = "Bearer " + token
   ↓
3. 后端JWT过滤器解析Token
   - 从Header提取Token
   - 解析JWT获取UUID
   - 从Redis查询LoginUser
   - 设置SecurityContext
   ↓
4. Controller方法权限校验
   @PreAuthorize("@ss.hasPermi('system:user:add')")
   ↓
5. PermissionService检查权限
   - 获取当前用户权限列表
   - 判断是否包含所需权限
   ↓
6. 通过则执行业务逻辑，否则返回403
```

## 八、权限系统总结

### 8.1 三层权限控制

| 层级 | 控制点 | 技术实现 |
|------|--------|----------|
| **路由层** | 菜单可见性 | 动态路由，未授权菜单不显示 |
| **按钮层** | 按钮可用性 | v-hasPermi指令，无权限按钮移除 |
| **接口层** | API访问权限 | @PreAuthorize注解，无权限返回403 |

### 8.2 关键要点

1. **超级管理员特权**: admin用户拥有所有权限（`*:*:*`）
2. **多角色合并**: 用户多个角色的权限取并集
3. **数据权限灵活**: 支持5种数据范围，满足不同场景
4. **前后端配合**: 前端控制UI显示，后端保证安全性
5. **Token自动续期**: 活跃用户Token永不过期

### 8.3 最佳实践

- **最小权限原则**: 只授予必要的权限
- **定期审计**: 检查角色权限分配是否合理
- **权限变更实时生效**: 修改权限后无需重新登录
- **日志记录**: 所有操作都有日志可追溯
