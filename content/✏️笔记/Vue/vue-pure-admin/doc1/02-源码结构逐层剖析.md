### 一、入口文件：main.ts 与 App.vue

#### 1.1 main.ts — 应用启动编排

`src/main.ts` 是整个应用的入口。vue-pure-admin 的 main.ts 采用了一种**有序初始化**的模式，确保各个插件和配置按照正确的依赖顺序注册：

```typescript
// main.ts 简化结构
import { createApp } from "vue";
import App from "./App.vue";

const app = createApp(App);

// 1. 注册 Element Plus（完整导入）
app.use(ElementPlus, { locale: zhCn });

// 2. 注册 Pinia 状态管理
app.use(store);

// 3. 注册路由
app.use(router);

// 4. 注册自定义指令
setupDirectives(app);

// 5. 注册全局组件
setupGlobalComponents(app);

// 6. 挂载应用
app.mount("#app");
```

关键点在于**注册顺序**：Pinia 必须在路由之前注册，因为路由守卫（`router.beforeEach`）中需要访问 store。自定义指令和全局组件在路由之后注册，因为它们可能依赖 store 中的状态。

#### 1.2 App.vue — 根组件

```vue
<script setup lang="ts">
import { useLayoutStore } from "@/store/modules/layout";

const layoutStore = useLayoutStore();
</script>

<template>
  <router-view />
</template>
```

App.vue 极其简洁——这是刻意为之的设计。根组件只负责提供 `<router-view>` 出口，所有的布局逻辑（侧边栏、头部、标签页等）都在 Layout 组件中处理。

#### 2.3 路由加载的四阶段流水线

路由加载是 vue-pure-admin 的核心机制之一，经历四个阶段：

```
阶段 1: Glob 导入
  import.meta.glob("./modules/**/*.ts", { eager: true })
  │  读取 modules/ 下所有路由模块文件
  ▼
阶段 2: ascending() 排序
  │  按 meta.rank 字段升序排列
  │  确保菜单顺序与配置一致
  ▼
阶段 3: buildHierarchyTree()
  │  将扁平路由数组构建为层级树结构
  │  处理嵌套路由的父子关系
  ▼
阶段 4: formatTwoStageRoutes()
  │  将层级树格式化为 Vue Router 所需的两层结构
  │  第一层：Layout 组件
  │  第二层：实际页面组件
  ▼
最终路由表 → router.addRoute() 动态注入
```

#### 2.4 路由守卫（beforeEach）

路由守卫是权限控制的第一道关卡：

```typescript
// router/index.ts 简化版
router.beforeEach(async (to, from, next) => {
  const userStore = useUserStoreHook();
  const permissionStore = usePermissionStoreHook();

  // 1. 设置页面标题
  document.title = to.meta.title as string;

  if (getToken()) {
    // 已登录
    if (to.path === "/login") {
      next({ path: "/" });
    } else {
      // 2. 检查是否已加载动态路由
      if (!permissionStore.isDynamicLoaded) {
        // 3. 获取用户信息 + 角色
        await userStore.getUserInfo();
        // 4. 根据角色过滤路由
        const dynamicRoutes = permissionStore.generateRoutes(
          userStore.roles
        );
        // 5. 动态注入路由
        dynamicRoutes.forEach(route => router.addRoute(route));
        permissionStore.setDynamicLoaded(true);
        // 6. 重新导航（确保新路由已生效）
        next({ ...to, replace: true });
      } else {
        next();
      }
    }
  } else {
    // 未登录 → 白名单检查
    whiteList.includes(to.path) ? next() : next(`/login?redirect=${to.path}`);
  }
});
```

关键设计点：当动态路由首次加载完成后，使用 `next({ ...to, replace: true })` 重新导航。这是因为 `router.addRoute()` 是异步生效的，直接 `next()` 可能导致 404。

#### 3.2 userStore — 用户状态管理

userStore 是权限系统的基石，管理用户信息、token 和角色：

```typescript
// store/modules/user.ts 简化版
export const useUserStore = defineStore({
  id: "pure-user",
  state: (): UserState => ({
    avatar: "",
    username: "",
    nickname: "",
    roles: [],              // 用户角色列表
    permissions: [],        // 用户权限码列表
    token: getToken(),      // 从 cookie 读取
    refreshToken: ""        // 用于静默刷新的 refresh token
  }),

  actions: {
    /** 登录 */
    async loginByUsername(data: LoginParams) {
      const { data: res } = await loginApi(data);
      this.setToken(res.accessToken);
      this.refreshToken = res.refreshToken;
      return res;
    },

    /** 获取用户信息 */
    async getUserInfo() {
      const { data } = await getuserInfoApi();
      this.roles = data.roles;
      this.permissions = data.permissions;
      this.username = data.username;
      this.avatar = data.avatar;
    },

    /** 登出 */
    async logOut() {
      await logoutApi();
      this.resetToken();
      resetRouter();
      router.push("/login");
    }
  }
});
```

#### 3.3 Store Hook 模式

vue-pure-admin 在非组件环境中（如路由守卫、工具函数）使用 Store 时，采用了 **Hook 模式**：

```typescript
// store/utils.ts
import { store } from "./index";
import { useUserStore } from "./modules/user";

/**
 * 在非组件环境中安全使用 Store
 * 在 store 初始化之前返回原始 hook
 */
export function useUserStoreHook() {
  return store ? useUserStore(store) : useUserStore();
}
```

这个模式解决了 Pinia 的一个常见问题：在组件外部使用 `useXxxStore()` 时需要传入 Pinia 实例。通过 Hook 包装，可以在路由守卫、HTTP 拦截器等非组件代码中安全使用 Store。

#### 3.4 permissionStore — 动态路由生成

permissionStore 负责根据用户角色过滤路由表：

```typescript
// store/modules/permission.ts 简化版
export const usePermissionStore = defineStore({
  id: "pure-permission",
  state: () => ({
    constantMenus,          // 静态菜单（无需权限）
    wholeMenus: [],         // 完整的动态菜单
    cachePageList: [],      // 需要缓存的页面列表
    isDynamicLoaded: false  // 动态路由是否已加载
  }),

  actions: {
    /** 根据角色生成可访问的路由 */
    generateRoutes(roles: string[]) {
      // 1. 获取原始路由表（通过 glob 导入）
      const asyncRoutes = getAsyncRoutes();

      // 2. 递归过滤：只保留 roles 匹配的路由
      const filtered = filterAsyncRoutes(asyncRoutes, roles);

      // 3. 存储过滤后的菜单
      this.wholeMenus = [...this.constantMenus, ...filtered];

      // 4. 返回格式化的路由表
      return formatTwoStageRoutes(
        formatFlatteningRoutes(buildHierarchyTree(filtered))
      );
    }
  }
});

/** 递归过滤路由 */
function filterAsyncRoutes(routes: RouteConfigs[], roles: string[]) {
  return routes.filter(route => {
    const routeRoles = route.meta?.roles;
    // 无 roles 限制 → 所有角色可访问
    if (!routeRoles || routeRoles.length === 0) return true;
    // 检查用户角色是否匹配
    if (roles.some(role => routeRoles.includes(role))) {
      // 递归过滤子路由
      if (route.children) {
        route.children = filterAsyncRoutes(route.children, roles);
      }
      return true;
    }
    return false;
  });
}
```

### 四、HTTP 服务层：utils/http/

HTTP 层是 vue-pure-admin 的另一个核心模块，封装了 Axios 并实现了**静默 Token 刷新**。

#### 4.1 PureHttp 类

```typescript
// utils/http/index.ts 简化版
export class PureHttp {
  private service: AxiosInstance;
  private refreshToken: string;
  private isRefreshing: boolean = false;
  private requestQueue: Array<(token: string) => void> = [];

  constructor() {
    this.service = axios.create({
      baseURL: import.meta.env.VITE_PROXY_DOMAIN_REAL,
      timeout: 20000
    });

    this.registerInterceptors();
  }

  private registerInterceptors() {
    // 请求拦截器
    this.service.interceptors.request.use(config => {
      const token = getToken();
      if (token) {
        config.headers["Authorization"] = `Bearer ${token}`;
      }
      return config;
    });

    // 响应拦截器
    this.service.interceptors.response.use(
      response => {
        const { code, data, message } = response.data;
        if (code === 200) {
          return data;
        }
        // 业务错误处理
        ElMessage.error(message || "请求失败");
        return Promise.reject(new Error(message));
      },
      async error => {
        const { response } = error;

        // 401 Token 过期 → 静默刷新
        if (response?.status === 401) {
          if (!this.isRefreshing) {
            this.isRefreshing = true;

            try {
              const newToken = await this.refreshAccessToken();
              // 重放队列中的所有请求
              this.requestQueue.forEach(cb => cb(newToken));
              this.requestQueue = [];
              // 重试当前请求
              response.config.headers["Authorization"] = `Bearer ${newToken}`;
              return this.service(response.config);
            } catch {
              // 刷新失败 → 登出
              useUserStoreHook().logOut();
              return Promise.reject(error);
            } finally {
              this.isRefreshing = false;
            }
          } else {
            // 正在刷新中 → 加入等待队列
            return new Promise(resolve => {
              this.requestQueue.push(token => {
                response.config.headers["Authorization"] = `Bearer ${token}`;
                resolve(this.service(response.config));
              });
            });
          }
        }

        return Promise.reject(error);
      }
    );
  }

  private async refreshAccessToken(): Promise<string> {
    const userStore = useUserStoreHook();
    const { data } = await refreshTokenApi(userStore.refreshToken);
    userStore.setToken(data.accessToken);
    return data.accessToken;
  }
}
```

这段代码的核心设计是**请求队列 + 重放机制**：当检测到 401 时，只发起一次刷新请求，同时将其他并发请求加入队列等待。刷新成功后用新 token 重放所有排队的请求，对业务代码完全透明。

#### 5.3 keepAlive 缓存策略

vue-pure-admin 实现了精细的页面缓存控制：

```vue
<!-- layout/index.vue 简化 -->
<template>
  <router-view v-slot="{ Component }">

      <component :is="Component" :key="route.fullPath" />
```

`keepAliveStore` 维护一个缓存页面列表。路由的 `meta.keepAlive` 字段决定页面是否默认缓存。当用户关闭标签页时，对应的页面从缓存列表中移除，确保下次打开时重新加载。

#### 6.2 ReDialog 组件详解

ReDialog 是项目中使用最频繁的可复用组件之一，它封装了 Element Plus 的 `ElDialog`，提供了标准化的弹窗表单模式：

```vue
<!-- 使用 ReDialog -->
<script setup lang="ts">
import { ref } from "vue";
import { ReDialog } from "@/components/ReDialog";

const dialogRef = ref();

function openDialog(row?: UserType) {
  dialogRef.value.show({
    title: row ? "编辑用户" : "新增用户",
    width: "500px",
    props: { row },
    // 弹窗内的表单组件
    contentRenderer: () => h(UserForm, { modelValue: row }),
    // 确定按钮回调
    beforeSure: async (done, { options }) => {
      const formData = options.props.formRef.getFormData();
      if (row) {
        await updateUserApi({ ...row, ...formData });
      } else {
        await addUserApi(formData);
      }
      done(); // 关闭弹窗
    }
  });
}
</script>

<template>
  <ReDialog ref="dialogRef" />
</template>
```

这种**编程式弹窗**模式相比传统的 `v-model` + 条件渲染，优势在于：弹窗的打开/关闭逻辑集中在方法中，不需要为每个弹窗定义 `visible` 状态变量。

#### 7.1 v-auth 指令实现

```typescript
// directives/auth/index.ts
import { useUserStoreHook } from "@/store/utils";
import type { Directive } from "vue";

/** v-auth 权限指令：检查用户是否拥有指定权限码 */
export const auth: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding<string>) {
    const { value: permissionCode } = binding;
    const { permissions } = useUserStoreHook();

    if (permissionCode && !permissions.includes(permissionCode)) {
      // 无权限 → 移除 DOM 元素
      el.parentNode?.removeChild(el);
    }
  }
};
```

使用方式：

```vue
<!-- 只有拥有 'system:user:add' 权限码的用户才能看到这个按钮 -->
<el-button v-auth="'system:user:add'" type="primary">新增用户</el-button>
```

#### 7.2 v-ripple 指令实现

```typescript
// directives/ripple/index.ts
export const ripple: Directive = {
  mounted(el: HTMLElement) {
    el.addEventListener("click", (e: MouseEvent) => {
      const ripple = document.createElement("span");
      const rect = el.getBoundingClientRect();
      const size = Math.max(rect.width, rect.height);

      ripple.style.width = ripple.style.height = `${size}px`;
      ripple.style.left = `${e.clientX - rect.left - size / 2}px`;
      ripple.style.top = `${e.clientY - rect.top - size / 2}px`;
      ripple.classList.add("ripple-effect");

      el.appendChild(ripple);
      setTimeout(() => ripple.remove(), 600);
    });
  }
};
```

#### 8.1 Token 管理

```typescript
// utils/auth.ts
import Cookies from "js-cookie";

const ACCESS_TOKEN_KEY = "authorized-token";
const REFRESH_TOKEN_KEY = "refresh-token";

export function getToken(): string {
  return Cookies.get(ACCESS_TOKEN_KEY) || "";
}

export function setToken(token: string): void {
  Cookies.set(ACCESS_TOKEN_KEY, token, { expires: 1 });
}

export function removeToken(): void {
  Cookies.remove(ACCESS_TOKEN_KEY);
  Cookies.remove(REFRESH_TOKEN_KEY);
}
```

Token 存储在 Cookie 中而非 localStorage，这是一个安全考量：Cookie 可以设置 `HttpOnly`、`Secure`、`SameSite` 属性，且自动随请求发送。

#### 8.2 树形数据处理

```typescript
// utils/tree.ts
/** 将扁平数组转为树形结构 */
export function buildHierarchyTree<T extends { id: number; parentId: number }>(
  list: T[]
): (T & { children: T[] })[] {
  const map = new Map<number, T & { children: T[] }>();
  const result: (T & { children: T[] })[] = [];

  // 第一遍：建立 id → node 映射
  list.forEach(item => map.set(item.id, { ...item, children: [] }));

  // 第二遍：构建父子关系
  list.forEach(item => {
    const node = map.get(item.id)!;
    if (item.parentId === 0) {
      result.push(node);
    } else {
      map.get(item.parentId)?.children.push(node);
    }
  });

  return result;
}
```

### 十、小结

vue-pure-admin 的源码结构体现了清晰的分层思想：

- **router/** 负责页面导航和权限过滤，是整个应用的"交通系统"
- **store/** 管理全局状态，是数据的"中央仓库"
- **utils/http/** 封装 HTTP 请求，是前后端通信的"桥梁"
- **layout/** 提供页面布局框架，是视觉呈现的"骨架"
- **components/** 提供可复用的 UI 组件，是业务开发的"积木"
- **directives/** 提供声明式的 DOM 行为扩展，是交互逻辑的"粘合剂"

每一层都有明确的职责边界，层与层之间通过 TypeScript 类型定义进行契约通信。这种架构使得新增业务模块时，只需要在对应的层添加文件，而不需要修改任何框架代码。
