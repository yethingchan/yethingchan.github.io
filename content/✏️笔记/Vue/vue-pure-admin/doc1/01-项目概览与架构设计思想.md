### 二、项目定位与设计哲学

vue-pure-admin 的设计哲学可以总结为三个关键词：**纯粹、模块化、可扩展**。

**纯粹（Pure）**：项目名中的 "pure" 体现了核心设计理念——不绑定特定的业务逻辑，只提供纯净的基础架构和通用组件。开发者拿到的是一个结构清晰、功能完备的脚手架，而非一个充斥着示例业务的半成品。

**模块化**：从路由、状态、组件到工具函数，每一层都遵循高内聚低耦合的原则。路由模块按功能域拆分到独立文件，Pinia store 按业务域独立定义，27 个 "Re*" 开头的可复用组件各自封装特定的交互逻辑。

**可扩展**：项目提供了完善的扩展机制。新增业务模块只需添加路由文件、创建页面组件、定义 store，无需修改框架层的任何代码。权限系统支持路由级（角色）和按钮级（权限码）两层控制，可以灵活适配各种业务场景。

### 三、技术选型分析

#### 3.1 为什么是 Vue 3 + `<script setup>`

Vue 3 的 Composition API 配合 `<script setup>` 语法宏，相比 Options API 有以下优势：

- **更好的类型推断**：`<script setup>` 中的变量和函数自动暴露给模板，TypeScript 无需额外声明
- **更少的模板代码**：不需要 `export default`、`setup()` 函数、`return` 语句
- **更好的 tree-shaking**：编译器能更精确地分析依赖关系，移除未使用的代码

```vue
<!-- 传统 Options API -->
<script lang="ts">
import { defineComponent, ref, computed } from "vue";
export default defineComponent({
  setup() {
    const count = ref(0);
    const double = computed(() => count.value * 2);
    return { count, double };
  }
});
</script>

<!-- <script setup> 语法 -->
<script setup lang="ts">
import { ref, computed } from "vue";
const count = ref(0);
const double = computed(() => count.value * 2);
</script>
```

vue-pure-admin 全面采用 `<script setup>` 语法，代码简洁度提升约 30%。

#### 3.2 为什么是 Vite 8

Vite 8 是截至 2026 年最新的构建工具版本，相比 Webpack 有以下核心优势：

- **极速冷启动**：基于原生 ESM，不需要打包整个项目
- **即时 HMR**：模块热更新速度与项目规模无关，始终保持毫秒级响应
- **强大的插件生态**：项目使用了 12+ 个 Vite 插件，包括自动导入、SVG 图标、Gzip/Brotli 压缩、CDN 外置等

#### 3.3 为什么是 Element Plus

Element Plus 是 Element UI 的 Vue 3 版本，具有以下特点：

- 完整的组件库（70+ 组件），覆盖管理后台的所有常见需求
- 原生 TypeScript 支持，类型定义完善
- 按需导入，配合 `unplugin-vue-components` 实现自动按需引入
- 活跃社区，问题修复和功能迭代速度快

#### 3.4 为什么是 Pinia 而非 Vuex

Pinia 是 Vue 官方推荐的新一代状态管理方案：

| 特性 | Vuex 4 | Pinia |
|------|--------|-------|
| TypeScript 支持 | 需要额外配置 | 原生支持 |
| DevTools 集成 | 支持 | 支持（含时间旅行调试） |
| 模块化 | 手动 modules 配置 | 独立 store 自动模块化 |
| 体积 | ~22KB | ~1KB |
| Composition API | 需要 `useStore` | 原生支持 |
| 热更新 | 有限 | 完整支持 |
| SSR | 需要额外配置 | 内置支持 |

vue-pure-admin 定义了 6 个核心 Pinia store，分别管理用户信息、权限、布局配置等状态。

#### 3.5 为什么是 Tailwind CSS 4

Tailwind CSS 4 相比 3.x 版本有重大升级：

- 基于 Rust 的新引擎 Oxide，构建速度提升 10 倍以上
- CSS-first 配置（不再需要 `tailwind.config.js`）
- 原生 CSS 级联层（`@layer`），减少样式冲突
- 自动内容检测，无需配置 `content` 数组

项目采用 Tailwind CSS + SCSS 混合方案：全局样式和复杂组件用 SCSS，工具类和布局用 Tailwind。

### 四、整体架构设计

#### 4.1 分层架构图

```
┌─────────────────────────────────────────────────────────┐
│                      视图层 (Views)                       │
│   页面组件 + Re* 可复用组件 + Element Plus 组件            │
├─────────────────────────────────────────────────────────┤
│                    路由层 (Router)                        │
│   静态路由 + 动态路由 + 权限守卫 + 路由过渡动画             │
├─────────────────────────────────────────────────────────┤
│                   状态层 (Pinia Store)                    │
│   userStore + permissionStore + layoutStore + ...        │
├─────────────────────────────────────────────────────────┤
│                   服务层 (API + Http)                     │
│   PureHttp 封装 + 请求拦截器 + Token 自动刷新              │
├─────────────────────────────────────────────────────────┤
│                  基础设施层 (Utils + Hooks)                │
│   工具函数 + 自定义 Hooks + 指令 + 插件                    │
└─────────────────────────────────────────────────────────┘
```

这个分层架构的核心特点是**单向依赖**：视图层依赖路由层和状态层，状态层依赖服务层，服务层依赖基础设施层。底层不依赖上层，确保了每一层都可以独立测试和替换。

#### 4.2 请求生命周期

一个典型的页面请求在 vue-pure-admin 中经历以下阶段：

```
用户操作（点击菜单/按钮）
  │
  ▼
路由守卫 (beforeEach)
  │  ├─ 检查 token 是否存在
  │  ├─ 检查权限 (roles / permissionCode)
  │  └─ 加载动态路由（首次进入时）
  │
  ▼
页面组件挂载 (setup)
  │  ├─ 调用 API 方法
  │  ├─ API → PureHttp 实例
  │  │    ├─ 请求拦截器：注入 Authorization header
  │  │    ├─ 发送请求
  │  │    ├─ 响应拦截器：检查 token 是否过期
  │  │    │    └─ 401 → 静默刷新 token → 重放请求
  │  │    └─ 返回数据
  │  └─ 更新 Pinia store → 响应式更新 UI
  │
  ▼
页面渲染完成
```

#### 4.3 权限模型

vue-pure-admin 实现了两层权限控制：

**路由级权限（角色控制）**：通过路由 `meta.roles` 字段配置。用户登录后，系统根据其角色过滤出可访问的路由，动态生成菜单和路由表。

```typescript
// 路由定义示例
{
  path: "/system",
  meta: {
    title: "系统管理",
    roles: ["admin"]  // 只有 admin 角色可访问
  },
  children: [
    {
      path: "user",
      meta: { title: "用户管理" }
    },
    {
      path: "role",
      meta: { title: "角色管理", roles: ["admin"] }
    }
  ]
}
```

**按钮级权限（权限码控制）**：通过自定义指令 `v-auth` / `v-perms` 或 `<Auth>` / `<Perms>` 组件控制。在组件模板中声明所需权限码，系统自动隐藏或禁用无权限的元素。

```vue
<!-- 指令方式 -->
<el-button v-auth="'system:user:add'">新增用户</el-button>
<el-button v-perms="['system:user:edit', 'system:user:add']">编辑</el-button>

<!-- 组件方式 -->
<Auth :value="'system:user:delete'">
  <el-button type="danger">删除</el-button>
</Auth>
```

#### 4.4 构建优化策略

项目采用了多项构建优化措施，确保生产环境性能：

| 策略 | 实现方式 | 效果 |
|------|----------|------|
| **CDN 外置** | `vite-plugin-cdn-import` 将 Vue、Element Plus 等大型库外置到 CDN | 首屏 JS 体积减少 60%+ |
| **Gzip/Brotli 压缩** | `vite-plugin-compression` | 传输体积减少 70%+ |
| **按需导入** | `unplugin-vue-components` + `unplugin-auto-import` | 消除未使用组件的引入 |
| **代码分割** | Vite 自动 + 手动 `manualChunks` | 按需加载，减少首屏请求 |
| **SVG 图标** | `vite-plugin-svg-icons` 生成 SVG Sprite | 图标请求合并为 1 个 |
| **Glob 导入** | `import.meta.glob` 动态加载路由模块 | 新增路由文件无需手动注册 |
