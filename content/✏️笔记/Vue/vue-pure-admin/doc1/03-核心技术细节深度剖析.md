### 一、静默 Token 刷新机制

Token 刷新是企业级管理后台必须解决的问题。vue-pure-admin 实现了一套完整的**静默刷新 + 请求队列重放**方案，确保用户在 Token 过期时无感知。

#### 1.1 问题场景

```
时间线：
T0: 用户登录，获得 accessToken（有效期 2 小时）和 refreshToken
T1: 用户操作，发送多个并发请求（A、B、C）
T2: accessToken 过期，三个请求同时收到 401
    ┌─ 如果没有刷新机制：三个请求全部失败，用户被踢回登录页
    └─ vue-pure-admin 的方案：
        请求 A 触发刷新流程
        请求 B、C 进入等待队列
        刷新成功 → 用新 token 重放 A、B、C
        用户完全无感知
```

#### 1.2 完整实现

```typescript
// utils/http/index.ts — PureHttp 类的核心刷新逻辑
class PureHttp {
  private isRefreshing = false;
  private requestQueue: Array<{
    resolve: (value: any) => void;
    config: InternalAxiosRequestConfig;
  }> = [];

  private handleUnauthorized = async (
    error: AxiosError
  ): Promise<AxiosResponse | void> => {
    const originalRequest = error.config!;

    // 防止重复刷新
    if (originalRequest._retry) {
      return Promise.reject(error);
    }
    originalRequest._retry = true;

    if (!this.isRefreshing) {
      this.isRefreshing = true;

      try {
        const userStore = useUserStoreHook();
        const { data } = await refreshTokenApi(userStore.refreshToken);

        // 更新 token
        userStore.setToken(data.accessToken);
        userStore.refreshToken = data.refreshToken;

        // 重放队列中的请求
        for (const queued of this.requestQueue) {
          queued.config.headers["Authorization"] =
            `Bearer ${data.accessToken}`;
          const res = await this.service(queued.config);
          queued.resolve(res);
        }
        this.requestQueue = [];

        // 重试原始请求
        originalRequest.headers["Authorization"] =
          `Bearer ${data.accessToken}`;
        return this.service(originalRequest);
      } catch (refreshError) {
        // 刷新 token 也过期 → 强制登出
        this.requestQueue.forEach(({ resolve }) =>
          resolve(Promise.reject(refreshError))
        );
        this.requestQueue = [];
        useUserStoreHook().logOut();
        return Promise.reject(refreshError);
      } finally {
        this.isRefreshing = false;
      }
    } else {
      // 已有刷新请求在进行中 → 排队等待
      return new Promise(resolve => {
        this.requestQueue.push({
          resolve,
          config: originalRequest
        });
      });
    }
  };
}
```

#### 1.3 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| Token 存储位置 | Cookie | 支持 `HttpOnly`、自动随请求发送 |
| 刷新触发方式 | 401 响应拦截 | 服务端驱动，避免客户端时钟不同步 |
| 并发处理 | 请求队列 | 保证只发起一次刷新，避免 Token 竞争 |
| 刷新失败策略 | 强制登出 | 防止无限重试循环 |
| 标记机制 | `_retry` 标志 | 防止重试请求再次触发刷新 |

### 二、权限系统的完整链路

权限系统贯穿路由、指令、组件三个层面，形成完整的权限控制链路。

#### 2.1 权限数据流

```
用户登录
  │
  ▼
后端返回 roles: ["admin", "editor"]
  │  + permissions: ["system:user:add", "system:user:edit", ...]
  │
  ▼
userStore 存储 roles 和 permissions
  │
  ├──→ permissionStore.generateRoutes(roles)
  │     │
  │     ▼
  │   路由过滤 → router.addRoute() → 动态菜单
  │     （路由级权限：控制页面访问）
  │
  ├──→ v-auth / v-perms 指令
  │     │
  │     ▼
  │   检查 permissions 列表
  │     → 无权限则移除 DOM 元素
  │     （按钮级权限：控制操作按钮）
  │
  └──→ <Auth> / <Perms> 组件
        │
        ▼
      检查 permissions 列表
        → 无权限则不渲染子组件
        （组件级权限：控制区域显隐）
```

#### 2.2 路由权限过滤算法

```typescript
// store/modules/permission.ts

/**
 * 四阶段路由处理流水线
 */
function processRoutes(rawModules: RouteModule[], roles: string[]) {
  // 阶段 1: 按 rank 升序排列
  const sorted = ascending(rawModules);

  // 阶段 2: 根据角色过滤
  const filtered = filterByRoles(sorted, roles);

  // 阶段 3: 构建层级树
  const tree = buildHierarchyTree(filtered);

  // 阶段 4: 格式化为 Vue Router 两层结构
  return formatTwoStageRoutes(tree);
}

/**
 * ascending — 路由排序
 * 支持 rank 字段和 path 兜底排序
 */
function ascending(arr: RouteModule[]): RouteModule[] {
  return arr.sort((a, b) => {
    const rankA = a.meta?.rank ?? 99;
    const rankB = b.meta?.rank ?? 99;
    if (rankA !== rankB) return rankA - rankB;
    return a.path.localeCompare(b.path);
  });
}

/**
 * formatTwoStageRoutes — 两层格式化
 * 第一层使用 Layout 组件，第二层是实际页面
 */
function formatTwoStageRoutes(tree: RouteTree[]): RouteRecordRaw[] {
  return tree.map(route => {
    if (route.children?.length) {
      return {
        path: route.path,
        component: () => import("@/layout/index.vue"),
        meta: route.meta,
        children: route.children.map(child => ({
          path: child.path,
          name: child.name,
          component: child.component,
          meta: child.meta
        }))
      };
    }
    // 没有子路由的情况（如登录页）
    return {
      path: route.path,
      name: route.name,
      component: route.component,
      meta: route.meta
    };
  });
}
```

#### 2.3 按钮权限的多模式控制

```vue
<template>
  <!-- 模式 1: 指令方式 — 无权限时移除元素 -->
  <el-button v-auth="'system:user:add'" type="primary">
    新增用户
  </el-button>

  <!-- 模式 2: 多权限码 — 满足任一即可 -->
  <el-button v-perms="['system:user:edit', 'system:user:add']">
    操作
  </el-button>

  <!-- 模式 3: 组件方式 — 无权限时不渲染 -->
  <Auth :value="'system:user:delete'">
    <el-button type="danger">删除</el-button>
  </Auth>

  <!-- 模式 4: 函数式权限检查 -->
  <el-button v-if="hasPermission('system:user:export')">
    导出
  </el-button>
</template>

<script setup lang="ts">
import { useUserStoreHook } from "@/store/utils";

function hasPermission(code: string): boolean {
  return useUserStoreHook().permissions.includes(code);
}
</script>
```

四种模式的选择原则：简单场景用指令，复杂条件用函数，需要条件渲染用组件。指令方式直接移除 DOM 元素，性能最优；组件方式支持 `v-else` 分支，灵活性更高。

### 三、Vite 构建优化策略

vue-pure-admin 的 Vite 配置是一个工程化的典范，通过 12+ 个插件的组合实现了极致的构建性能和产物体积。

#### 3.1 vite.config.ts 结构

```typescript
// vite.config.ts 简化版
import { defineConfig, loadEnv } from "vite";
import vue from "@vitejs/plugin-vue";
import AutoImport from "unplugin-auto-import/vite";
import Components from "unplugin-vue-components/vite";

  return {
```

#### 3.3 产物体积分析

| 优化策略 | 实现方式 | 体积减少 |
|----------|----------|----------|
| **CDN 外置** | Vue、Element Plus 等大型库从 CDN 加载 | -60% JS |
| **代码分割** | `manualChunks` 按依赖分组 | 按需加载 |
| **Gzip 压缩** | `vite-plugin-compression` | -70% 传输体积 |
| **Brotli 压缩** | 比 Gzip 再压缩 15-20% | -80% 传输体积 |
| **Tree Shaking** | Vite 原生支持 + Element Plus 按需导入 | -30% 组件代码 |
| **SVG Sprite** | 所有 SVG 图标合并为一个文件 | 减少 HTTP 请求数 |

最终产物：主 JS 包约 350KB（Brotli 压缩后），首屏加载时间 < 1.5s。

### 四、响应式布局系统

#### 4.1 断点定义

vue-pure-admin 定义了五个响应式断点，使用 Tailwind CSS 的标准断点体系：

| 断点 | 宽度 | 设备 | 布局变化 |
|------|------|------|----------|
| **xs** | < 576px | 手机 | 侧边栏隐藏，单列布局 |
| **sm** | >= 576px | 大手机 | 侧边栏折叠为图标 |
| **md** | >= 768px | 平板 | 侧边栏可展开 |
| **lg** | >= 992px | 小桌面 | 侧边栏固定 |
| **xl** | >= 1200px | 桌面 | 完整布局 |

#### 4.2 响应式监听实现

```typescript
// utils/resize-handler.ts
import { useDebounceFn } from "@vueuse/core";

const WIDTH_THRESHOLD = 992; // md 断点

export function useResponsiveLayout() {
  const layoutStore = useLayoutStoreHook();

  const handleResize = useDebounceFn(() => {
    const isMobile = document.body.getBoundingClientRect().width
      < WIDTH_THRESHOLD;

    layoutStore.setDevice(isMobile ? "mobile" : "desktop");

    if (isMobile) {
      layoutStore.setSidebarStatus(false); // 移动端默认隐藏侧边栏
    }
  }, 200);

  onMounted(() => {
    window.addEventListener("resize", handleResize);
    handleResize(); // 初始检测
  });

  onUnmounted(() => {
    window.removeEventListener("resize", handleResize);
  });
}
```

#### 7.2 ReIcon 组件实现

```typescript
// components/ReIcon/src/iconify.ts
import { IconifyIconOnline, IconifyIcon, SvgIcon } from "./components";

export default defineComponent({
  name: "ReIcon",
  props: {
    icon: { type: String, required: true },
    // ...其他 props
  },
  setup(props) {
    return () => {
      const { icon } = props;

      // 判断图标来源
      if (icon.startsWith("svg-")) {
        // 本地 SVG Sprite
        return h(SvgIcon, { icon, ...props });
      } else if (icon.includes(":")) {
        // Iconify 格式: "collection:name"
        const [collection, name] = icon.split(":");

        if (collection === "ep") {
          // Element Plus 图标
          return h(IconifyIcon, { icon, ...props });
        }

        // 其他 Iconify 图标
        return h(IconifyIconOnline, { icon, ...props });
      }

      return null;
    };
  }
});
```

### 八、标签页管理系统

#### 8.1 标签页状态管理

```typescript
// store/modules/tags.ts
export const useTagsStore = defineStore({
  id: "pure-tags",
  state: () => ({
    tagList: [] as TagItem[],    // 已打开的标签页列表
    activeTag: ""                 // 当前激活的标签
  }),

  actions: {
    /** 添加标签 */
    addTag(route: RouteLocationNormalized) {
      const exists = this.tagList.some(
        tag => tag.path === route.path
      );
      if (!exists) {
        this.tagList.push({
          path: route.path,
          name: route.name as string,
          title: route.meta.title as string,
          icon: route.meta.icon,
          query: route.query
        });
      }
      this.activeTag = route.path;
    },

    /** 关闭标签 */
    closeTag(path: string) {
      const index = this.tagList.findIndex(tag => tag.path === path);
      if (index === -1) return;

      this.tagList.splice(index, 1);

      // 如果关闭的是当前标签，导航到相邻标签
      if (this.activeTag === path) {
        const nextTag = this.tagList[index] || this.tagList[index - 1];
        if (nextTag) {
          router.push(nextTag.path);
        } else {
          router.push("/");
        }
      }
    },

    /** 关闭其他标签 */
    closeOtherTags(path: string) {
      this.tagList = this.tagList.filter(
        tag => tag.path === path || tag.meta?.affix
      );
    },

    /** 关闭所有标签 */
    closeAllTags() {
      // 保留固定标签（meta.affix = true）
      this.tagList = this.tagList.filter(tag => tag.meta?.affix);
      const lastFixed = this.tagList[this.tagList.length - 1];
      router.push(lastFixed?.path || "/");
    }
  }
});
```

```vue
      <ReIcon v-if="tag.icon" :icon="tag.icon" />

      <Close v-if="!tag.meta?.affix" @click.stop="closeTag(tag.path)" />
    </router-link>
  </div>

  <!-- 右键菜单 -->
  <ul v-show="contextMenuVisible" class="context-menu" :style="menuStyle">
    <li @click="refreshTag">刷新当前</li>
    <li @click="closeTag(selectedTag)">关闭当前</li>
    <li @click="closeOtherTags(selectedTag)">关闭其他</li>
    <li @click="closeAllTags">关闭所有</li>
  </ul>
</template>
```

### 九、Mock 数据方案

#### 9.1 开发环境 Mock

vue-pure-admin 在开发环境使用基于 Vite 插件的 Mock 方案：

```typescript
// mock/user.ts
import type { MockMethod } from "vite-plugin-mock";

export default [
  {
    url: "/api/login",
    method: "post",
    response: ({ body }) => {
      const { username, password } = body;

      if (username === "admin" && password === "admin123") {
        return {
          code: 200,
          data: {
            accessToken: "mock-access-token",
            refreshToken: "mock-refresh-token",
            expires: Date.now() + 2 * 60 * 60 * 1000
          },
          message: "登录成功"
        };
      }

      return {
        code: 401,
        data: null,
        message: "用户名或密码错误"
      };
    }
  },
  {
    url: "/api/getUserInfo",
    method: "get",
    response: () => ({
      code: 200,
      data: {
        username: "admin",
        nickname: "管理员",
        avatar: "https://example.com/avatar.png",
        roles: ["admin"],
        permissions: [
          "system:user:add",
          "system:user:edit",
          "system:user:delete"
        ]
      }
    })
  }
] as MockMethod[];
```

#### 9.2 Mock 开关控制

通过环境变量控制是否启用 Mock：

```bash
# .env.development
VITE_PUBLIC_PATH=/
VITE_PROXY_DOMAIN_REAL=http://localhost:8080
VITE_MOCK=true    # 启用 Mock
```

```typescript
// vite.config.ts
import { viteMockServe } from "vite-plugin-mock";
```

### 十、小结

本文深入剖析了 vue-pure-admin 中技术含量最高的几个核心机制：

- **静默 Token 刷新**通过请求队列 + 重放机制，在 Token 过期时对用户完全透明
