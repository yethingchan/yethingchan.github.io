### 一、路由系统

#### 1.1 路由整体架构

vue-pure-admin 的路由系统是项目中最复杂的模块，采用**静态路由 + 动态路由 + 权限过滤**的混合架构：

```
src/router/
├── index.ts           # 路由实例创建 + 守卫注册
├── utils.ts           # 路由处理工具函数（20+ 个函数）
├── modules/           # 静态路由模块文件
│   ├── home.ts
│   ├── system.ts
│   ├── permission.ts
│   └── ...
└── enums.ts           # 路由枚举
```

#### 1.2 静态路由与动态路由的分工

| 类型 | 来源 | 特点 | 示例 |
|------|------|------|------|
| **静态路由** | `src/router/modules/*.ts` | 代码中硬编码，无需权限控制 | 首页、登录页、404 |
| **动态路由** | 后端 API 返回 | 根据用户角色动态过滤 | 系统管理、权限管理等 |

#### 1.3 Glob 导入与路由模块发现


这行代码的作用：将 `src/views/` 下的所有 `.vue` 和 `.tsx` 文件注册为懒加载模块。返回的对象形如：

```javascript

  "/src/views/system/user/index.vue": () => import("/src/views/system/user/index.vue"),
  "/src/views/system/role/index.vue": () => import("/src/views/system/role/index.vue"),
  // ...
}
```

动态路由配置中只需要提供组件路径字符串，`addAsyncRoutes()` 函数会自动匹配对应的懒加载函数。

#### 1.4 路由排序：ascending()

```typescript
// src/router/utils.ts — 项目实际源码
function handRank(routeInfo: any) {
  const { name, path, parentId, meta } = routeInfo;
  return isAllEmpty(parentId)
    ? isAllEmpty(meta?.rank) || (meta?.rank === 0 && name !== "Home" && path !== "/")
      ? true : false
    : false;
}

function ascending(arr: any[]) {
  arr.forEach((v, index) => {
    // 当 rank 不存在时自动创建（首页永远在第一位）
    if (handRank(v)) v.meta.rank = index + 2;
  });
  return arr.sort((a, b) => a?.meta.rank - b?.meta.rank);
}
```

**设计细节**：
- 首页路由（`name === "Home"` 且 `path === "/"`）的 rank 永远为 0，排在最前面
- 其他路由如果没有设置 rank，自动从 2 开始递增
- 只有顶级路由参与排序（`parentId` 为空的才处理）

#### 1.5 路由过滤流水线

```typescript
// 三个过滤函数组成流水线

// 1. filterTree — 过滤 showLink: false 的路由（不在菜单中显示）
function filterTree(data: RouteComponent[]) {
  const newTree = cloneDeep(data).filter(
    v => v.meta?.showLink !== false
  );
  newTree.forEach(v => v.children && (v.children = filterTree(v.children)));
  return newTree;
}

// 2. filterNoPermissionTree — 根据角色过滤无权限的路由
function filterNoPermissionTree(data: RouteComponent[]) {
  const currentRoles = storageLocal().getItem<DataInfo<number>>(userKey)?.roles ?? [];
  const newTree = cloneDeep(data).filter(v =>
    isOneOfArray(v.meta?.roles, currentRoles)
  );
  newTree.forEach(v => v.children && (v.children = filterNoPermissionTree(v.children)));
  return filterChildrenTree(newTree);  // 级联过滤空目录
}

// 3. filterChildrenTree — 过滤无子路由的目录
function filterChildrenTree(data: RouteComponent[]) {
  const newTree = cloneDeep(data).filter(v => v?.children?.length !== 0);
  newTree.forEach(v => v.children && (v.children = filterTree(v.children)));
  return newTree;
}
```

**流水线**：`ascending(静态+动态)` → `filterTree` → `filterNoPermissionTree` → `filterChildrenTree`

最终得到一个排序正确、权限过滤完毕、无空目录的菜单树。

#### 1.6 动态路由注册

```typescript
// src/router/utils.ts — 处理后端返回的动态路由
function addAsyncRoutes(arrRoutes: Array<RouteRecordRaw>) {
  const modulesRoutesKeys = Object.keys(modulesRoutes);

  arrRoutes.forEach(v => {
    v.meta.backstage = true;  // 标记为后端路由

    // 自动设置 redirect 和 name
    if (v?.children?.length && !v.redirect) v.redirect = v.children[0].path;
    if (v?.children?.length && !v.name) v.name = v.children[0].name + "Parent";

    // 处理 iframe 嵌入
    if (v.meta?.frameSrc) {
      v.component = IFrame;
    } else {
      // 将后端传来的组件路径映射到 Glob 导入的懒加载函数
      const index = v?.component
        ? modulesRoutesKeys.findIndex(ev => ev.includes(v.component))
        : modulesRoutesKeys.findIndex(ev => ev.includes(v.path));
      v.component = modulesRoutes[modulesRoutesKeys[index]];
    }

    if (v?.children?.length) addAsyncRoutes(v.children);  // 递归处理子路由
  });

  return arrRoutes;
}
```

**核心映射逻辑**：后端返回路由配置时，`component` 字段是路径字符串（如 `"system/user/index"`），前端通过 `modulesRoutes` 对象查找匹配的懒加载函数。如果后端不传 `component`，则使用 `path` 作为查找依据。

#### 1.7 404 兜底路由

```typescript
function addPathMatch() {
  if (router.hasRoute(PAGE_NOT_FOUND_ROUTE_NAME)) return;
  router.addRoute({
    path: "/:pathMatch(.*)*",
    name: PAGE_NOT_FOUND_ROUTE_NAME,
    component: () => import("@/views/error/404.vue"),
    meta: { title: "menus.purePageNotFound", showLink: false }
  });
}
```

**关键设计**：404 路由在动态路由注册**之后**才添加。如果在动态路由之前添加，刷新页面时动态路由还未注册，所有路径都会匹配到 404。

#### 1.9 路由守卫

```typescript
// src/router/index.ts — 路由守卫逻辑（简化版）
router.beforeEach(async (to, from, next) => {
  // 1. 进度条
  NProgress.start();

  // 2. Token 检查
  const token = getToken();

  if (token) {
    // 已登录
    if (to.path === "/login") {
      next({ path: "/" });  // 已登录用户访问登录页 → 重定向到首页
    } else {
      if (!usePermissionStoreHook().wholeMenus.length) {
        // 首次进入（动态路由未加载）
        try {
          await initRouter();           // 从后端获取动态路由
          next({ ...to, replace: true }); // 重新导航确保新路由生效
        } catch {
          // 获取路由失败 → 清除 Token → 跳转登录
          removeToken();
          next(`/login?redirect=${to.path}`);
        }
      } else {
        next();  // 路由已加载，直接放行
      }
    }
  } else {
    // 未登录 → 白名单检查
    if (whiteList.includes(to.path)) {
      next();
    } else {
      next(`/login?redirect=${to.path}`);
    }
  }
});
```

#### 1.10 路由历史模式

```typescript
function getHistoryMode(routerHistory): RouterHistory {
  const historyMode = routerHistory.split(",");
  const leftMode = historyMode[0];
  const rightMode = historyMode[1];

  if (historyMode.length === 1) {
    if (leftMode === "hash") return createWebHashHistory("");
    else if (leftMode === "h5") return createWebHistory("");
  } else {
    if (leftMode === "hash") return createWebHashHistory(rightMode);
    else if (leftMode === "h5") return createWebHistory(rightMode);
  }

```

```typescript
// src/store/modules/user.ts — 项目实际源码
export const useUserStore = defineStore("pure-user", {
  state: (): userType => ({
    avatar: storageLocal().getItem<DataInfo<number>>(userKey)?.avatar ?? "",
    username: storageLocal().getItem<DataInfo<number>>(userKey)?.username ?? "",
    nickname: storageLocal().getItem<DataInfo<number>>(userKey)?.nickname ?? "",
    roles: storageLocal().getItem<DataInfo<number>>(userKey)?.roles ?? [],
    permissions: storageLocal().getItem<DataInfo<number>>(userKey)?.permissions ?? [],
    verifyCode: "",
    currentPage: 0,      // 登录页切换：0=账号 / 1=手机 / 2=扫码 / 3=注册 / 4=忘记密码
    isRemembered: false,
    loginDay: 7
  }),

  actions: {
    // SET_* 系列方法
    SET_AVATAR(avatar: string) { this.avatar = avatar; },
    SET_USERNAME(username: string) { this.username = username; },
    SET_ROLES(roles: Array<string>) { this.roles = roles; },
    SET_PERMS(permissions: Array<string>) { this.permissions = permissions; },

    // 登录
    async loginByUsername(data) {
      return new Promise<UserResult>((resolve, reject) => {
        getLogin(data).then(data => {
          if (data.code === 0) {
            setToken(data.data);   // 存储 Token + 用户信息
            resolve(data);
          } else { reject(data.message); }
        }).catch(reject);
      });
    },

    // 登出 — 联动清理所有 Store
    logOut() {
      this.username = "";
      this.roles = [];
      this.permissions = [];
      removeToken();
      useMultiTagsStoreHook().handleTags("equal", [...routerArrays]);
      resetRouter();
      router.push("/login");
    },

    // Token 刷新
    async handRefreshToken(data) {
      return new Promise<RefreshTokenResult>((resolve, reject) => {
        refreshTokenApi(data).then(data => {
          if (data.code === 0) {
            setToken(data.data);
            resolve(data);
          } else { reject(data.message); }
        }).catch(reject);
      });
    }
  }
});
```

#### 2.4 permissionStore — 权限与菜单

```typescript
// src/store/modules/permission.ts — 项目实际源码
export const usePermissionStore = defineStore("pure-permission", {
  state: () => ({
    constantMenus,                          // 静态菜单
    wholeMenus: [],                         // 完整菜单（静态 + 动态）
    flatteningRoutes: [],                   // 一维路由数组
    cachePageList: []                       // keep-alive 缓存页面
  }),

  actions: {
    // 组装菜单
    handleWholeMenus(routes: any[]) {
      this.wholeMenus = filterNoPermissionTree(
        filterTree(ascending(this.constantMenus.concat(routes)))
      );
      this.flatteningRoutes = formatFlatteningRoutes(
        this.constantMenus.concat(routes)
      );
    },

    // 缓存操作
    cacheOperate({ mode, name }: cacheType) {
      switch (mode) {
        case "refresh":
          this.cachePageList = this.cachePageList.filter(v => v !== name);
          break;
        case "add":
          this.cachePageList.push(name);
          break;
        case "delete":
          const delIndex = this.cachePageList.findIndex(v => v === name);
          delIndex !== -1 && this.cachePageList.splice(delIndex, 1);
          break;
      }
    },

    // 清理已关闭标签页的缓存
    clearCache() {
      const nameList = getKeyList(useMultiTagsStoreHook().multiTags, "name");
      // 如果缓存页面不在标签页中，则从缓存列表中移除
      let cacheLength = this.cachePageList.length;
      while (cacheLength > 0) {
        nameList.findIndex(v => v === this.cachePageList[cacheLength - 1]) === -1 &&
          this.cachePageList.splice(
            this.cachePageList.indexOf(this.cachePageList[cacheLength - 1]), 1
          );
        cacheLength--;
      }
    }
  }
});
```

**数据流向**：

```
后端 API 返回路由列表
  │
  ▼
handleWholeMenus(routes)
  │
  ├── constantMenus + routes → ascending() 排序
  ├── filterTree() — 过滤 showLink: false
  ├── filterNoPermissionTree() — 按角色过滤
  │
  ▼
wholeMenus → 菜单组件渲染侧边栏/顶部导航
flatteningRoutes → 路由匹配 + keep-alive 判断
```

#### 2.5 Store Hook 模式


**为什么需要 Hook 模式**：Pinia 的 `useXxxStore()` 在组件内部使用时，自动从 Vue 的 inject 系统获取 Pinia 实例。但在组件外部（如路由守卫、HTTP 拦截器），没有 inject 上下文，需要手动传入实例。Hook 模式统一了两种场景。

### 三、权限体系

#### 3.1 双层权限模型

vue-pure-admin 实现了**两套独立的权限检查机制**，分别适用于不同场景：

| 权限类型 | 数据来源 | 检查方式 | 适用场景 |
|----------|----------|----------|----------|
| **v-auth / Auth** | 路由 `meta.auths` | 检查当前路由的 auths 数组 | 页面级权限（此页面上有哪些操作） |
| **v-perms / Perms** | userStore.permissions | 检查用户的权限码列表 | 用户级权限（此用户有哪些权限） |

#### 3.2 v-auth 指令 — 页面级权限

```typescript
// src/directives/auth/index.ts — 项目实际源码
import { hasAuth } from "@/router/utils";

export const auth: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding<string | Array<string>>) {
    const { value } = binding;
    if (value) {
      !hasAuth(value) && el.parentNode?.removeChild(el);
    } else {
      throw new Error(
        "[Directive: auth]: need auths! Like v-auth=\"['btn.add','btn.edit']\""
      );
    }
  }
};
```

`hasAuth` 函数检查当前路由的 `meta.auths`：

```typescript
// src/router/utils.ts
function getAuths(): Array<string> {
  return router.currentRoute.value.meta.auths as Array<string>;
}

function hasAuth(value: string | Array<string>): boolean {
  if (!value) return false;
  const metaAuths = getAuths();
  if (!metaAuths) return false;
  const isAuths = isString(value)
    ? metaAuths.includes(value)           // 单个权限码
    : isIncludeAllChildren(value, metaAuths); // 多个权限码：全部匹配
  return isAuths ? true : false;
}
```

`hasPerms` 检查 userStore 中的 permissions：

```typescript
// src/utils/auth.ts
export const hasPerms = (value: string | Array<string>): boolean => {
  if (!value) return false;
  const allPerms = "*:*:*";
  const { permissions } = useUserStoreHook();
  if (!permissions) return false;
  // 超级管理员
  if (permissions.length === 1 && permissions[0] === allPerms) return true;
  const isAuths = isString(value)
    ? permissions.includes(value)
    : isIncludeAllChildren(value, permissions);
  return isAuths ? true : false;
};
```


**指令 vs 组件的选择**：

| 方式 | 行为 | 适用场景 |
|------|------|----------|
| `v-auth` 指令 | 无权限时**移除 DOM 元素** | 简单按钮/链接 |
| `<Auth>` 组件 | 无权限时**不渲染子组件** | 复杂区域、需要 `v-else` |
| `hasAuth()` 函数 | 编程式检查 | `v-if`、计算属性 |

#### 3.5 权限完整链路

```
用户登录成功
  │
  ▼
后端返回:
  roles: ["admin"]
  permissions: ["system:user:add", "system:user:edit", "system:user:delete"]
  │
  ▼
userStore 存储 roles + permissions
  │
  ├──→ permissionStore.handleWholeMenus(动态路由)
  │     ├── 按 roles 过滤路由树
  │     ├── 生成 wholeMenus（菜单）
  │     └── 生成 flatteningRoutes（路由表）
  │
  ├──→ 路由级权限
  │     └── 用户无 admin 角色 → 系统管理菜单不显示
  │
  ├──→ 按钮级权限（v-perms）
  │     └── <el-button v-perms="'system:user:add'">
  │         → 检查 permissions 是否包含 "system:user:add"
  │
  └──→ 页面级权限（v-auth）
        └── <el-button v-auth="'btn.export'">
            → 检查当前路由 meta.auths 是否包含 "btn.export"
```

```
存储分离策略：

Cookie (accessToken + refreshToken + expires)
├── 自动随 HTTP 请求发送
```

### 五、小结

第三阶段的核心收获：

- **路由系统**采用 Glob 导入 + 动态注册的混合方案，通过 `ascending → filterTree → filterNoPermissionTree` 三段式流水线处理路由
- **404 路由延迟注册**是一个关键设计细节，防止动态路由未加载时误跳 404
- **Token 客户端检测过期**比 401 响应拦截更快，避免无效请求到达服务端
- **Store Hook 模式**（`useXxxStoreHook()`）解决了 Pinia 在组件外部使用的问题
- **双权限系统**（`v-auth` vs `v-perms`）分别从路由和用户两个维度控制，覆盖所有场景
- **keep-alive 缓存管理**与标签页联动，关闭标签页时自动清理缓存
