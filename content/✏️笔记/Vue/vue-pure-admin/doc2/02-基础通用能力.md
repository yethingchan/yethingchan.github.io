### 一、网络请求（高频重点）

#### 1.1 整体架构

vue-pure-admin 的 HTTP 层采用**类封装 + 拦截器链 + Token 自动刷新**的架构：

```

  │
  ▼
```

#### 1.2 PureHttp 类完整源码解读

```typescript
// src/utils/http/index.ts — 项目实际源码（关键部分）
import Axios, { type AxiosInstance, type AxiosRequestConfig } from "axios";
import { stringify } from "qs";
import { getToken, formatToken } from "@/utils/auth";
import { useUserStoreHook } from "@/store/modules/user";

const defaultConfig: AxiosRequestConfig = {
  timeout: 10000,                              // 10 秒超时
  headers: {
    Accept: "application/json, text/plain, */*",
    "Content-Type": "application/json",
    "X-Requested-With": "XMLHttpRequest"
  },
  paramsSerializer: {
    serialize: stringify as unknown as CustomParamsSerializer  // qs 序列化数组参数
  }
};

class PureHttp {
  constructor() {
    this.httpInterceptorsRequest();
    this.httpInterceptorsResponse();
  }

  /** Token 过期后，暂存待执行的请求 */
  private static requests = [];

  /** 防止重复刷新 Token */
  private static isRefreshing = false;

  /** 保存当前 Axios 实例对象 */
  private static axiosInstance: AxiosInstance = Axios.create(defaultConfig);
}
```

**设计决策分析**：

| 决策 | 选择 | 原因 |
|------|------|------|
| 封装方式 | 类封装（非函数） | 需要维护实例级状态（`isRefreshing`、`requests` 队列） |
| 静态属性 | `static` | 整个应用只需要一个 PureHttp 实例，共享刷新状态 |
| 超时时间 | 10 秒 | 平衡用户体验和服务端处理能力 |
| 数组序列化 | `qs.stringify` | 后端通常期望 `ids=1&ids=2` 而非 `ids[]=1&ids[]=2` |

#### 1.3 请求拦截器：Token 注入与自动刷新

```typescript
// 请求拦截器 — 项目实际源码
private httpInterceptorsRequest(): void {
  PureHttp.axiosInstance.interceptors.request.use(
    async (config: PureHttpRequestConfig): Promise<any> => {
      // 1. 优先执行自定义回调
      if (typeof config.beforeRequestCallback === "function") {
        config.beforeRequestCallback(config);
        return config;
      }

      // 2. 白名单接口不需要 Token
      const whiteList = ["/refresh-token", "/login"];
      return whiteList.some(url => config.url.endsWith(url))
        ? config
        : new Promise(resolve => {
            const data = getToken();
            if (data) {
              const now = new Date().getTime();
              const expired = parseInt(data.expires) - now <= 0;

              if (expired) {
                // Token 已过期 → 触发刷新
                if (!PureHttp.isRefreshing) {
                  PureHttp.isRefreshing = true;

                  useUserStoreHook()
                    .handRefreshToken({ refreshToken: data.refreshToken })
                    .then(res => {
                      const token = res.data.accessToken;
                      config.headers["Authorization"] = formatToken(token);
                      // 重放队列中所有等待的请求
                      PureHttp.requests.forEach(cb => cb(token));
                      PureHttp.requests = [];
                    })
                    .catch(_err => {
                      // 刷新失败 → 清空队列 + 强制登出
                      PureHttp.requests = [];
                      useUserStoreHook().logOut();
                      message("登录已过期，请重新登录", { type: "warning" });
                    })
                    .finally(() => {
                      PureHttp.isRefreshing = false;
                    });
                }
                // 将当前请求加入等待队列
                resolve(PureHttp.retryOriginalRequest(config));
              } else {
                // Token 未过期 → 正常注入
                config.headers["Authorization"] = formatToken(data.accessToken);
                resolve(config);
              }
            } else {
              resolve(config);
            }
          });
    }
  );
}
```

**Token 刷新的完整时序图**：

```
T0: 请求 A 发送 → 检测到 Token 过期
    │
    ├── isRefreshing = true
    ├── 发起 refreshToken 请求
    │
T1: 请求 B 发送 → 检测到 Token 过期
    │  但 isRefreshing = true
    └── 加入 requests 队列等待
    │
T2: 请求 C 发送 → 同上，加入队列
    │
T3: refreshToken 成功 → 获得新 Token
    ├── 请求 A: 用新 Token 发送
    ├── 请求 B: 队列回放，用新 Token 发送
    ├── 请求 C: 队列回放，用新 Token 发送
    └── isRefreshing = false
    │
T4: 后续请求 D → Token 有效，正常注入
```

**关键设计**：

- **客户端检测过期**：通过比较 `expires` 和当前时间判断，而非等 401 响应
- **白名单机制**：`/refresh-token` 和 `/login` 不需要 Token，避免刷新时的死循环
- **请求队列**：使用 Promise + 回调数组，所有等待的请求在刷新完成后自动重放

#### 1.4 请求重放机制

```typescript
// 重连原始请求
private static retryOriginalRequest(config: PureHttpRequestConfig) {
  return new Promise(resolve => {
    PureHttp.requests.push((token: string) => {
      config.headers["Authorization"] = formatToken(token);
      resolve(config);
    });
  });
}
```

这个方法的精妙之处在于：它返回一个 Promise，但不会立即 resolve。Promise 的 resolve 函数被存入 `requests` 数组。当 Token 刷新成功后，遍历数组调用每个回调（传入新 Token），此时 Promise resolve，被暂停的请求继续执行。

#### 1.5 响应拦截器

```typescript
// 响应拦截器 — 项目实际源码
private httpInterceptorsResponse(): void {
  const instance = PureHttp.axiosInstance;

  instance.interceptors.response.use(
    (response: PureHttpResponse) => {
      const $config = response.config;

      // 1. 优先执行自定义回调
      if (typeof $config.beforeResponseCallback === "function") {
        $config.beforeResponseCallback(response);
        return response.data;
      }

      // 2. 返回 data 字段（自动解包）
      return response.data;
    },
    (error: PureHttpError) => {
      // 区分取消请求和普通错误
      $error.isCancelRequest = Axios.isCancel($error);
      return Promise.reject($error);
    }
  );
}
```

**设计要点**：

- 响应拦截器直接返回 `response.data`，API 调用方拿到的就是业务数据而非 Axios 包装对象
- 错误处理中标记 `isCancelRequest`，让上层逻辑区分用户主动取消和网络错误

#### 1.6 类型定义

```typescript
// src/utils/http/types.d.ts — 项目实际源码
export type RequestMethods = Extract<
  Method, "get" | "post" | "put" | "delete" | "patch" | "option" | "head"
>;

export interface PureHttpError extends AxiosError {
  isCancelRequest?: boolean;
}

export interface PureHttpResponse extends AxiosResponse {
  config: PureHttpRequestConfig;
}

export interface PureHttpRequestConfig extends AxiosRequestConfig {
  beforeRequestCallback?: (request: PureHttpRequestConfig) => void;
  beforeResponseCallback?: (response: PureHttpResponse) => void;
}
```

`PureHttpRequestConfig` 扩展了 `AxiosRequestConfig`，添加了两个回调钩子：`beforeRequestCallback` 和 `beforeResponseCallback`，允许单个请求绕过全局拦截器执行自定义逻辑。

#### 1.7 通用请求方法

```typescript
// 统一请求入口
public request<T>(
  method: RequestMethods,
  url: string,
  param?: AxiosRequestConfig,
  axiosConfig?: PureHttpRequestConfig
): Promise<T> {
  const config = { method, url, ...param, ...axiosConfig };
  return new Promise((resolve, reject) => {
    PureHttp.axiosInstance
      .request(config)
      .then(resolve)
      .catch(reject);
  });
}

// 便捷方法
public post<T, P>(url: string, params?: P, config?: PureHttpRequestConfig): Promise<T> {
  return this.request<T>("post", url, params, config);
}

public get<T, P>(url: string, params?: P, config?: PureHttpRequestConfig): Promise<T> {
  return this.request<T>("get", url, params, config);
}
```

泛型参数 `T` 约束返回类型，`P` 约束参数类型。在 API 调用时获得完整的类型安全：

#### 2.2 Token 管理工具

```typescript
// src/utils/auth.ts — 项目实际源码（核心部分）
import Cookies from "js-cookie";

const ACCESS_TOKEN_KEY = "authorized-token";

export interface DataInfo<T> {
  accessToken: string;
  refreshToken: string;
  expires: T;
  avatar?: string;
  username?: string;
  nickname?: string;
  roles?: string[];
  permissions?: string[];
}

export const userKey = "user-info";

/** 获取 Token（从 Cookie） */
export function getToken(): TokenInfo {
  return Cookies.get(ACCESS_TOKEN_KEY)
    ? JSON.parse(Cookies.get(ACCESS_TOKEN_KEY))
    : null;
}

/** 设置 Token */
export function setToken(data: DataInfo<number>) {
  // Cookie 存储 Token（支持 HttpOnly、自动过期）
  Cookies.set(ACCESS_TOKEN_KEY, JSON.stringify({
    accessToken: data.accessToken,
    refreshToken: data.refreshToken,
    expires: data.expires
  }), {
    expires: new Date(data.expires)  // 设置过期时间
  });

  // localStorage 存储用户信息（头像、用户名等）
  storageLocal().setItem(userKey, data);
}

/** 移除 Token */
export function removeToken() {
  Cookies.remove(ACCESS_TOKEN_KEY);
  storageLocal().removeItem(userKey);
}

/** 格式化 Authorization 头 */
export function formatToken(token: string): string {
  return `Bearer ${token}`;
}

/** 按钮级权限检查 */
export const hasPerms = (value: string | Array<string>): boolean => {
  if (!value) return false;
  const allPerms = "*:*:*";
  const { permissions } = useUserStoreHook();
  if (!permissions) return false;
  // 超级管理员拥有所有权限
  if (permissions.length === 1 && permissions[0] === allPerms) return true;
  const isAuths = isString(value)
    ? permissions.includes(value)
    : isIncludeAllChildren(value, permissions);
  return isAuths ? true : false;
};
```

**Token 存储分离策略**：

| 数据 | 存储位置 | 原因 |
|------|----------|------|
| accessToken / refreshToken / expires | Cookie | 自动随请求发送，可设过期时间 |
| avatar / username / roles / permissions | localStorage | 非敏感信息，需要跨会话持久化 |

#### 2.4 树形数据处理

```typescript
// src/utils/tree.ts
export function buildHierarchyTree<T extends { id?: number; parentId?: number }>(
  list: T[]
): (T & { children: T[] })[] {
  const map = new Map<number, T & { children: T[] }>();
  const result: (T & { children: T[] })[] = [];

  list.forEach(item => map.set(item.id, { ...item, children: [] }));

  list.forEach(item => {
    const node = map.get(item.id)!;
    if (item.parentId === 0) {
      result.push(node);
    } else {
      map.get(item.parentId)?.children.push(node);
    }
  });

  return result;
}
```

两次遍历：第一次建 Map，第二次建关系。时间复杂度 O(n)，远优于递归查找的 O(n²)。

### 七、小结

第二阶段的核心收获：

- **PureHttp 类**是整个项目的网络通信基石，通过拦截器链实现了 Token 自动注入、过期检测、静默刷新和请求队列重放
- **Token 存储分离**：敏感信息（Token）存 Cookie，用户信息存 localStorage，兼顾安全和便捷
- **双回调钩子**（`beforeRequestCallback` / `beforeResponseCallback`）允许单个请求绕过全局拦截器
- **工具函数**按职责拆分到独立文件，核心逻辑复用了 `@pureadmin/utils` 工具库
- **事件总线**使用 mitt 替代 Vue 2 的 `$emit`，通过 TypeScript 泛型确保事件类型安全
- **样式体系**五层导入（Reset → Global → Tailwind → Element Plus → IconFont），确保优先级正确
- **主题系统**三个维度（亮暗 / 主题色 / 布局）全部持久化，支持动态切换
- **Mock 服务**通过 `vite-plugin-fake-server` 实现，开发生产环境通用
