### 一、新增业务模块的完整流程

#### 1.1 标准 7 步流程

以新增"设备管理"模块为例：

**第 1 步：添加路由模块**

```typescript
// src/router/modules/device.ts
export default {
  path: "/device",
  meta: {
    icon: "ri:cpu-line",
    title: "设备管理",
    rank: 15
  },
  children: [
    {
      path: "list",
      name: "DeviceList",
      component: () => import("@/views/device/list/index.vue"),
      meta: { title: "设备列表", keepAlive: true }
    }
  ]
} satisfies RouteConfigsTable;
```

> 不需要手动注册！`import.meta.glob` 自动发现。

**第 2 步：创建页面组件**

```
src/views/device/
├── list/
│   ├── index.vue           # 主页面
│   └── components/
│       └── DeviceForm.vue  # 表单子组件
└── monitor/
    └── index.vue
```

**第 3 步：定义 TypeScript 类型**

```typescript
// src/api/types/device.ts
export interface DeviceInfo {
  id: number;
  name: string;
  model: string;
  status: "online" | "offline" | "alarm";
}
```

**第 4 步：创建 API 模块**

```typescript
// src/api/device.ts
import { http } from "@/utils/http";
export const getDeviceListApi = (params?: QueryParams) => {
  return http.request<PageResult<DeviceInfo>>("get", "/api/device/list", { params });
};
```

**第 5 步：创建 Composable（可选）**

```typescript
// src/composables/useDevice.ts
export function useDevice() {
  const table = useTable<DeviceInfo>(getDeviceListApi);
  // 业务逻辑...
  return { ...table };
}
```

**第 6 步：添加权限配置**

```typescript
// 路由 meta 中添加角色控制
meta: { roles: ["admin", "operator"] }

// 模板中使用权限指令
<el-button v-perms="'device:add'">新增</el-button>
```

**第 7 步：添加 Mock 数据（开发阶段）**

```typescript
// mock/device.ts
export default [{ url: "/api/device/list", method: "get", response: ... }];
```

### 二、测试策略

#### 2.1 测试工具链

vue-pure-admin 的 `package.json` 中虽然没有直接配置测试框架，但项目使用的主流工具链兼容以下方案：

| 测试类型 | 工具 | 用途 |
|----------|------|------|
| **单元测试** | Vitest | 测试 Composable、工具函数 |
| **组件测试** | @vue/test-utils | 测试 Re* 组件 |
| **E2E 测试** | Cypress / Playwright | 测试完整用户流程 |
| **视觉测试** | Chromatic | 组件样式回归 |

#### 2.2 单元测试示例

```typescript
// __tests__/utils/auth.test.ts
import { describe, it, expect, vi, beforeEach } from "vitest";
import { hasPerms } from "@/utils/auth";

// Mock userStore
vi.mock("@/store/modules/user", () => ({
  useUserStoreHook: () => ({
    permissions: ["system:user:add", "system:user:edit"]
  })
}));

describe("hasPerms", () => {
  it("should return true for existing permission", () => {
    expect(hasPerms("system:user:add")).toBe(true);
  });

  it("should return false for missing permission", () => {
    expect(hasPerms("system:user:delete")).toBe(false);
  });

  it("should support wildcard *:*:*", () => {
    // Mock 超级管理员
    vi.doMock("@/store/modules/user", () => ({
      useUserStoreHook: () => ({ permissions: ["*:*:*"] })
    }));
    expect(hasPerms("any:permission:code")).toBe(true);
  });
});
```

### 三、跨域问题解决方案

#### 3.1 开发环境：Vite 代理

```typescript
// vite.config.ts
server: {
  proxy: {
    "/api": {
      target: "http://localhost:8080",
      changeOrigin: true,
      rewrite: path => path.replace(/^\/api/, "")
    }
  }
}
```

#### 3.2 生产环境：Nginx 反向代理

```nginx
location /api/ {
    proxy_pass http://backend:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

#### 3.3 后端配置 CORS（不推荐前端处理）

```java
// Spring Boot 示例
@Configuration
public class CorsConfig {
    @Bean
    CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();
        config.addAllowedOrigin("https://your-domain.com");
        config.addAllowedMethod("*");
        config.addAllowedHeader("*");
        config.setAllowCredentials(true);
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);
        return source;
    }
}
```

**最佳实践**：生产环境统一使用 Nginx 反向代理，避免跨域问题。前端不需要做任何 CORS 配置。

### 四、监控与埋点

#### 4.1 错误监控

```typescript
// main.ts — Vue 错误捕获
app.config.errorHandler = (err, instance, info) => {
  // 上报到 Sentry / 自建监控平台
  reportError({
    error: err.message,
    stack: err.stack,
    component: instance?.$options?.name,
    info,
    url: location.href,
    timestamp: Date.now()
  });

// Promise 未捕获异常
window.addEventListener("unhandledrejection", event => {
  reportError({
    error: event.reason?.message,
    type: "unhandledrejection",
    url: location.href
  });
});
```

#### 4.2 性能监控

```typescript
// 使用 Performance API
const observer = new PerformanceObserver(list => {
  for (const entry of list.getEntries()) {
    if (entry.entryType === "largest-contentful-paint") {
      reportMetric("LCP", entry.startTime);
    }
    if (entry.entryType === "first-input") {
      reportMetric("FID", entry.processingStart - entry.startTime);
    }

});
observer.observe({ type: "largest-contentful-paint", buffered: true });
observer.observe({ type: "first-input", buffered: true });
```

#### 4.3 用户行为埋点

```typescript
// composables/useTrack.ts
export function useTrack() {
  function trackEvent(event: string, data?: Record<string, any>) {
    // 上报到埋点平台
    navigator.sendBeacon("/api/track", JSON.stringify({
      event,
      data,
      page: router.currentRoute.value.path,
      timestamp: Date.now()
    }));
  }

  return { trackEvent };
}

// 使用
```

### 五、技术深度话题（面试向）

#### 5.1 为什么选择后端路由而非前端路由权限

| 方案 | 优点 | 缺点 |
|------|------|------|
| **前端路由权限** | 实现简单，响应快 | 路由代码全在客户端，可被绕过 |
| **后端路由权限** | 安全，路由配置集中管理 | 需要额外 API 请求 |

vue-pure-admin 选择后端路由权限的原因：企业级应用对安全性要求高，前端路由表不能暴露敏感页面的路径。

#### 5.2 Token 刷新的竞态条件

**问题**：多个并发请求同时检测到 Token 过期，可能触发多次刷新。

**解决方案**：`isRefreshing` 锁 + 请求队列

```typescript
if (!PureHttp.isRefreshing) {
  PureHttp.isRefreshing = true;
  // 只发起一次刷新
}
// 其他请求加入队列等待
resolve(PureHttp.retryOriginalRequest(config));
```

#### 5.3 Vue 3 `<script setup>` 的编译原理

```vue
<script setup lang="ts">
import { ref } from "vue";
const count = ref(0);
function increment() { count.value++; }
</script>

<template>
  <button @click="increment">{{ count }}</button>
</template>
```

Vue 编译器将其转换为：

```javascript
// 编译后的代码
import { ref } from "vue";
const __sfc__ = {
  setup(__props) {
    const count = ref(0);
    function increment() { count.value++; }
    return { count, increment };
  }
};
```

`<script setup>` 中的变量和函数自动暴露给模板，不需要 `return`。编译器通过静态分析确定哪些标识符在模板中使用。

#### 5.4 Vite 的依赖预构建原理

```
原始 ES Module 依赖（浏览器无法直接使用）：
  element-plus/
  ├── lib/
  │   ├── button.mjs
  │   ├── input.mjs
  │   └── ... (200+ 个文件)

预构建后（浏览器直接使用）：
  node_modules/.vite/deps/
  └── element-plus.js  (1 个文件)
```

Vite 使用 esbuild（Go 编写）将 ES Module 依赖预构建为单个文件，开发时的浏览器请求数从数百个减少到一个。

#### 5.5 Pinia 与 Vuex 的架构差异

| 维度 | Vuex 4 | Pinia |
|------|--------|-------|
| 模块化 | `modules` + `namespaced` | 独立 Store 自动隔离 |
| Mutation | 必需（同步修改状态） | 废弃（直接修改 `this.xxx`） |
| 插件 | Vuex Plugin | Pinia Plugin |
| DevTools | Vuex DevTools | Pinia DevTools（更现代） |
| 热更新 | 部分支持 | 完整支持 |
| 体积 | ~22KB | ~1.5KB |

Pinia 废弃 Mutation 的理由：在 TypeScript 中，Action 已经能很好地处理同步和异步操作，Mutation 增加了不必要的概念负担。

### 六、项目演进方向

#### 6.1 微前端集成

对于大型企业应用，可以将 vue-pure-admin 作为主应用，通过 `qiankun` 或 `wujie` 集成子应用。

#### 6.2 Low-Code 页面

利用 Schema Form 和动态路由，可以扩展为低代码平台：后端配置页面结构 → 前端自动渲染。

#### 6.3 AI 辅助开发

项目中已包含 `deep-chat` 依赖和 `src/views/chatai/` 页面，可以集成 AI 助手辅助业务操作。

#### 6.4 Monorepo 演进

如果项目规模增长到多个子项目，可以考虑迁移到 pnpm workspace monorepo：

```
packages/
├── admin/           # 管理后台（当前项目）
├── portal/          # 门户网站
├── shared/          # 共享组件和工具
└── api-client/      # API 客户端
```

### 七、小结

- **新增业务模块**遵循"路由 → 类型 → API → Composable → 页面 → 权限 → Mock"的 7 步标准流程
- **测试策略**以 Vitest 为核心，覆盖工具函数、组件和 E2E 三个层面
- **跨域问题**生产环境用 Nginx 反向代理，前端零配置
- **监控埋点**覆盖错误监控、性能监控和用户行为三个维度
- **技术深度话题**（Token 竞态、script setup 编译、Vite 预构建、Pinia vs Vuex）是面试加分项
- **项目演进**可朝向微前端、低代码、AI 助手和 Monorepo 方向发展
