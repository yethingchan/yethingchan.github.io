#### 1.3 组件目录结构规范

每个 Re* 组件遵循统一的目录结构：

```
src/components/ReDialog/
├── index.ts           # 统一导出
├── src/
│   ├── hook.tsx       # 编程式 API（addDialog/closeDialog）
│   ├── popup.tsx      # 弹窗渲染逻辑
│   └── types.ts       # 类型定义
```

这种结构的好处：**导出层和实现层分离**。`index.ts` 只负责导出，使用者不需要关心内部实现细节。

### 二、核心组件深度解析

#### 2.1 ReDialog — 编程式弹窗系统

ReDialog 是项目中使用最频繁的组件，它颠覆了传统的 `v-model` 弹窗模式。

**传统方式**（每个弹窗一个 `visible` 变量）：

```vue
<!-- 传统方式：N 个弹窗需要 N 个 visible 变量 -->
<el-dialog v-model="dialogVisible1" title="弹窗1">...</el-dialog>
<el-dialog v-model="dialogVisible2" title="弹窗2">...</el-dialog>
```

**ReDialog 方式**（编程式调用）：

```typescript
// 只需要一行代码打开弹窗
addDialog({
  title: "新增用户",
  width: "500px",
  props: { userForm: {} },
  contentRenderer: () => h(UserForm, { /* ... */ }),
  beforeSure: (done, { options }) => {
    // 提交逻辑
    submitForm(options.props.userForm).then(() => done());
  }
});
```

**实现原理**：ReDialog 在 `App.vue` 根级别挂载了一个全局弹窗容器，通过响应式数组管理所有弹窗实例：

```tsx
// ReDialog/src/hook.tsx — 核心逻辑（简化）
const dialogStore = ref<DialogOptions[]>([]);

function addDialog(options: DialogOptions) {
  dialogStore.value.push(options);
}

function closeDialog() {
  dialogStore.value.pop();
}

function closeAllDialog() {
  dialogStore.value = [];
}
```

#### 2.2 ReIcon — 统一图标系统

ReIcon 统一了三种图标来源的渲染接口：

```typescript
// 使用方式完全一致，内部自动判断图标类型
<IconifyIconOffline icon="ep:edit" />          // Element Plus 图标
<IconifyIconOnline icon="ri:settings-3-line" />  // Iconify 在线图标
<FontIcon icon="icon-custom" />               // 本地图标字体
```

图标组件在 `main.ts` 中全局注册，无需在页面中导入。

#### 2.3 ReAuth / RePerms — 权限容器

```tsx
// src/components/ReAuth/src/auth.tsx — 项目实际源码
export default defineComponent({
  name: "Auth",
  props: {
    value: { type: undefined, default: [] }
  },
  setup(props, { slots }) {
    return () => {
      if (!slots) return null;
      return hasAuth(props.value)
        ? <Fragment>{slots.default?.()}</Fragment>
        : null;
    };
  }
});
```

使用 `<Fragment>` 而非 `<div>` 包裹，避免在 DOM 中引入多余的层级。

### 三、组件通信方式

#### 3.1 通信方式选型

| 通信场景 | 方式 | vue-pure-admin 中的使用 |
|----------|------|------------------------|
| **父 → 子** | Props | 所有 Re* 组件的 `defineProps` |
| **子 → 父** | Emits | 表格组件的 `@row-click` |
| **跨层级** | Provide/Inject | Layout 向下传递布局上下文 |
| **全局状态** | Pinia Store | userStore, permissionStore |
| **事件通知** | mitt 事件总线 | 标签页切换、布局变化 |
| **实例方法** | `defineExpose` + `ref` | ReDialog 的 `show/close` |

#### 3.2 Props 校验与默认值

```vue
<script setup lang="ts">
interface Props {
  title: string;            // 必需属性
  visible?: boolean;        // 可选属性
  width?: string;
  fullscreen?: boolean;
}

const props = withDefaults(defineProps<Props>(), {
  visible: false,
  width: "50%",
  fullscreen: false
});
</script>
```

使用 TypeScript 接口声明 Props 的优势：编译时类型检查 + IDE 自动提示 + 文档化。

### 四、UI 库二次封装

#### 4.1 @pureadmin/table

```typescript
// main.ts 中注册
import Table from "@pureadmin/table";
app.use(Table);
```

`@pureadmin/table` 是对 Element Plus `el-table` 的二次封装，添加了：
- 列配置化（JSON 定义列）
- 内置分页
- 工具栏集成

#### 4.2 @pureadmin/descriptions

```typescript
// main.ts 中注册
import PureDescriptions from "@pureadmin/descriptions";
app.use(PureDescriptions);
```

对 Element Plus `el-descriptions` 的二次封装，支持配置化的描述列表渲染。

#### 4.3 VxeTable 集成

```typescript
// src/plugins/vxeTable.ts
import VxeTable from "vxe-table";
import "vxe-table/lib/style.css";

export function useVxeTable(app) {
  app.use(VxeTable);
}
```

项目同时使用 Element Plus Table 和 VxeTable：简单表格用 Element Plus，复杂表格（虚拟滚动、树形、合并单元格）用 VxeTable。

#### 4.4 Element Plus 按需配置

```typescript
// src/plugins/elementPlus.ts
import ElementPlus from "element-plus";

export function useElementPlus(app) {
  app.use(ElementPlus);
}
```

项目选择完整导入 Element Plus（非按需导入），因为管理后台通常会用到大部分组件，完整导入更简单且 tree-shaking 会自动移除未使用的代码。

### 五、自定义指令

#### 5.1 六个自定义指令

```
src/directives/
├── auth/        # v-auth — 页面级权限
├── perms/       # v-perms — 用户级权限
├── copy/        # v-copy — 点击复制
├── longpress/   # v-longpress — 长按事件
├── optimize/    # v-optimize — 防抖/节流
└── ripple/      # v-ripple — 水波纹效果
```

#### 5.2 指令注册方式

```typescript
// main.ts — 批量注册所有自定义指令
import * as directives from "@/directives";
Object.keys(directives).forEach(key => {
  app.directive(key, (directives as { [key: string]: Directive })[key]);
});
```

遍历导出对象自动注册，新增指令时只需在 `directives/` 目录添加文件，无需修改 `main.ts`。

### 六、小结

- **26 个 Re* 组件**覆盖了管理后台的常见需求，统一 `Re` 前缀便于识别和搜索
- **ReDialog 编程式弹窗**是最大亮点，消除了 N 个 `visible` 变量的模板冗余
- **双权限系统**（Auth/Perms）各有侧重：Auth 看路由，Perms 看用户
- **通信方式选型清晰**：Props → Emits → Store → mitt → expose，由近到远
- **指令批量注册**实现了"新增即生效"的开闭原则
