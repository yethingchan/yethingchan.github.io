## 第七阶段：问题、坑点 & 可优化点 — 实战经验

> 本文是 vue-pure-admin 八阶段深度教程的第七篇，总结项目中的常见问题、已知坑点、架构不足和可优化方向。

---

### 一、典型 Bug 与兼容性问题

#### 1.1 动态路由刷新 404

**问题**：用户访问动态路由页面后刷新浏览器，页面跳到 404。

**原因**：刷新时路由表被重置，动态路由还未注册就进行了路由匹配。

**项目的解决方案**：

```typescript
// 404 兜底路由在动态路由注册之后才添加
function addPathMatch() {
  if (router.hasRoute(PAGE_NOT_FOUND_ROUTE_NAME)) return;
  router.addRoute({
    path: "/:pathMatch(.*)*",
    name: PAGE_NOT_FOUND_ROUTE_NAME,
    component: () => import("@/views/error/404.vue")
  });
}

// 在 handleAsyncRoutes 的最后才调用
addPathMatch();
```

#### 1.2 Token 刷新死循环

**问题**：Token 过期后刷新请求本身也带了过期的 Token，导致无限 401。

**解决方案**：请求白名单 + isRefreshing 锁

```typescript
const whiteList = ["/refresh-token", "/login"];
return whiteList.some(url => config.url.endsWith(url))
  ? config  // 白名单接口不注入 Token
  : ...     // 正常流程
```

#### 1.3 keep-alive 缓存不生效

**问题**：设置了 `meta.keepAlive: true` 但页面切换时仍然重新加载。

**原因**：`<keep-alive :include="cachePageList">` 匹配的是组件的 `name`，不是路由的 `name`。

**解决方案**：确保页面组件使用 `defineOptions` 设置正确的 name：

```vue
<script setup lang="ts">
defineOptions({ name: "SystemUser" });  // 必须与路由 name 一致
</script>
```

#### 1.4 Element Plus 表格列宽问题

**问题**：`el-table-column` 的 `min-width` 在某些浏览器中不生效。

**解决方案**：同时设置 `width` 和 `min-width`，或使用百分比宽度。

#### 1.5 pnpm 版本不兼容

**问题**：低版本 pnpm 安装依赖时报 peer dependency 错误。

**解决方案**：

```json
// package.json 中强制 pnpm 版本
"engines": {
  "node": ">=22.22.1",
  "pnpm": ">=11"
},
"preinstall": "npx only-allow pnpm"
```

### 二、当前架构的不足与改进方向

#### 2.1 TypeScript strict 模式未开启

**现状**：`tsconfig.json` 中 `strict: false`。

**影响**：无法捕获 `null` / `undefined` 相关的运行时错误。

**改进建议**：在实际业务项目中开启 `strict: true`，尤其是 `strictNullChecks`。可以渐进式迁移：先开启 `noImplicitAny`，修复所有错误后再开启完整 strict。

#### 2.2 路由文件缺少类型校验

**现状**：路由模块文件使用 `satisfies RouteConfigsTable` 但未充分利用 TypeScript 的类型守卫。

**改进建议**：

```typescript
// 为路由模块定义严格的类型
interface RouteModule {
  path: string;
  meta: {
    title: string;        // 必填
    icon: string;         // 必填
    rank: number;         // 必填
    roles?: string[];
  };
  children: RouteModule[];
}
```

#### 2.3 Store 缺少持久化

**现状**：只有部分状态通过 localStorage 手动持久化（用户信息），Store 本身没有使用 `pinia-plugin-persistedstate`。

**改进建议**：

```typescript
import piniaPluginPersistedstate from "pinia-plugin-persistedstate";
const store = createPinia();
store.use(piniaPluginPersistedstate);

// 在 Store 定义中
export const useSettingsStore = defineStore("settings", {
  state: () => ({ /* ... */ }),
  persist: {
    paths: ["theme", "layout", "primaryColor"]  // 只持久化配置项
  }
});
```

#### 2.4 API 缺少统一错误处理

**现状**：HTTP 响应拦截器返回 `response.data`，错误处理分散在各个 API 调用方。

**改进建议**：在响应拦截器中统一处理常见错误码：

```typescript
instance.interceptors.response.use(
  response => {
    const { code, data, message } = response.data;
    switch (code) {
      case 0: return data;           // 成功
      case 401: /* Token 过期 */; break;
      case 403: /* 无权限 */; break;
      case 500: ElMessage.error(message); break;
      default: ElMessage.warning(message);
    }
  }
);
```

#### 2.5 组件命名前缀 `Re` 的局限

**现状**：所有公共组件使用 `Re` 前缀，在大型项目中辨识度不够。

**改进建议**：可以考虑更具描述性的前缀，如 `PureDialog`、`PureAuth`，或在组件文档中强调 `Re` 代表 "Reusable"。

### 三、代码中的可优化点

#### 3.1 HTTP 类使用静态属性

**现状**：`PureHttp` 使用 `static` 属性存储状态（`isRefreshing`、`requests`），但导出的是一个实例。

```typescript
// 当前
export const http = new PureHttp();
```

**优化**：如果确定只需要一个实例，可以改为单例模式或直接导出函数，避免 `static` 和实例混用带来的理解成本。

#### 3.2 路由工具函数过多

**现状**：`router/utils.ts` 导出了 20+ 个函数，文件较长。

**优化**：按职责拆分为多个文件：

```
router/
├── utils/
│   ├── filter.ts      # filterTree, filterNoPermissionTree 等
│   ├── format.ts      # formatFlatteningRoutes, formatTwoStageRoutes
│   ├── async.ts       # addAsyncRoutes, initRouter
│   └── auth.ts        # hasAuth, getAuths
```

#### 3.3 Mock 数据与真实数据耦合

**现状**：`vite-plugin-fake-server` 的 `enableProd: true` 让 Mock 在生产环境也可用。

**风险**：如果忘记关闭，生产环境会使用假数据。

**优化**：通过环境变量严格控制：

```typescript
vitePluginFakeServer({
  enableProd: import.meta.env.MODE === "demo"  // 只在 demo 环境启用
})
```

### 四、兼容性处理

#### 4.1 浏览器兼容

项目构建目标为 `es2015`，支持所有现代浏览器：

- Chrome 60+
- Firefox 60+
- Safari 12+
- Edge 79+

不支持 IE（Vue 3 本身不支持 IE）。

#### 4.2 移动端适配

Layout 组件通过 `useResizeObserver` 实现响应式：

```typescript
// 宽度 <= 760px → 移动端模式
// 侧边栏隐藏，点击汉堡菜单展开
// 展开时显示半透明遮罩层 (app-mask)
```

#### 4.3 暗色模式适配

通过 `useDark()` 检测系统偏好，同时支持手动切换。Element Plus 的暗色模式通过 `.dark` 类触发。

---

### 五、小结

- **动态路由 404** 和 **Token 刷新死循环** 是两个最常见的坑，项目都有成熟的解决方案
- **TypeScript strict 未开启**是架构层面最大的妥协，业务项目中建议开启
- **Store 缺少持久化插件**可以通过引入 `pinia-plugin-persistedstate` 轻松解决
- **路由工具函数过多**建议按职责拆分，保持单一文件的可读性
- **Mock 生产环境风险**需要通过环境变量严格控制
