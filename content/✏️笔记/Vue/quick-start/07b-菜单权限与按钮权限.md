## 五、菜单权限控制

菜单权限控制是后台管理系统的核心功能，根据用户角色动态决定可访问的页面和可操作的功能。

### 5.1 根据用户角色过滤路由

路由过滤逻辑在 `src/store/modules/permission.js` 中实现：

```js
// src/store/modules/permission.js
import { defineStore } from 'pinia'
import { constantRoutes, asyncRoutes } from '@/router'

/**
 * 递归过滤异步路由表
 * @param {Array} routes - 待过滤的路由表
 * @param {Array} roles - 用户角色列表
 * @returns {Array} 过滤后的路由表
 */
function filterAsyncRoutes(routes, roles) {
  const result = []

  routes.forEach(route => {
    const tmp = { ...route }

    if (hasPermission(roles, tmp)) {
      // 如果有子路由，递归过滤子路由
      if (tmp.children) {
        tmp.children = filterAsyncRoutes(tmp.children, roles)
      }
      result.push(tmp)
    }
  })

  return result
}

/**
 * 判断用户是否有权限访问该路由
 * @param {Array} roles - 用户角色列表
 * @param {Object} route - 路由对象
 * @returns {boolean}
 */
function hasPermission(roles, route) {
  if (route.meta && route.meta.roles) {
    // 路由指定了 roles，检查用户角色是否包含在内
    return roles.some(role => route.meta.roles.includes(role))
  } else {
    // 路由未指定 roles，所有角色都可访问
    return true
  }
}

export const usePermissionStore = defineStore('permission', {
  state: () => ({
    routes: [],        // 完整可访问路由（静态 + 过滤后的动态）
    addedRoutes: []    // 动态添加的路由（用于侧边栏菜单渲染）
  }),

  actions: {
    /**
     * 根据角色生成可访问的路由
     * @param {Array} roles - 用户角色列表
     * @returns {Array} 需要动态添加的路由
     */
    generateRoutes(roles) {
      let accessedRoutes

      // admin 角色拥有所有路由权限
      if (roles.includes('admin')) {
        accessedRoutes = asyncRoutes
      } else {
        // 其他角色：根据 roles 字段过滤
        accessedRoutes = filterAsyncRoutes(asyncRoutes, roles)
      }

      this.addedRoutes = accessedRoutes
      this.routes = constantRoutes.concat(accessedRoutes)

      return accessedRoutes
    },

    /**
     * 重置路由状态（登出时调用）
     */
    resetRoutes() {
      this.addedRoutes = []
      this.routes = constantRoutes
    }
  }
})
```

### 5.2 动态路由 addRoute

动态路由的注册在路由守卫 `src/permission.js` 中完成：

```js
// src/permission.js（路由守卫中核心逻辑）
router.beforeEach(async (to, from, next) => {
  const hasToken = getToken()

  if (hasToken) {
    if (to.path === '/login') {
      // 已登录访问登录页 → 重定向首页
      next({ path: '/' })
    } else {
      if (hasRoles) {
        // 已生成过动态路由 → 直接放行
        next()
      } else {
        try {
          // 1. 获取用户信息（包含角色）
          const userStore = useUserStore()
          await userStore.getUserInfo()

          // 2. 根据角色过滤并生成可访问路由
          const permissionStore = usePermissionStore()
          const accessRoutes = permissionStore.generateRoutes(userStore.roles)

          // 3. 动态添加到 router 实例
          accessRoutes.forEach(route => {
            router.addRoute(route)
          })

          hasRoles = true

          // 4. 重新导航，确保新路由生效
          next({ ...to, replace: true })
        } catch (error) {
          // 获取用户信息失败 → 清除 Token → 跳转登录页
          userStore.resetState()
          next(`/login?redirect=${to.path}`)
        }
      }
    }
  } else {
    // 无 Token → 跳转登录页
    if (whiteList.includes(to.path)) {
      next()
    } else {
      next(`/login?redirect=${to.path}`)
    }
  }
})
```

### 5.3 菜单显示/隐藏

侧边栏菜单根据 `permissionStore.routes` 渲染，只显示用户有权限访问的菜单项：

```vue
<!-- src/layout/Sidebar/index.vue 中的菜单渲染 -->
<template>
  <el-menu :default-active="activeMenu" :collapse="!sidebar.opened">
    <!-- 遍历 permissionStore.routes（已过滤的路由表） -->
    <sidebar-item
      v-for="route in permissionRoutes"
      :key="route.path"
      :item="route"
      :base-path="route.path"
    />
  </el-menu>
</template>

<script setup>
import { computed } from 'vue'
import { usePermissionStore } from '@/store/modules/permission'

const permissionStore = usePermissionStore()

// 读取经过角色过滤后的路由表
const permissionRoutes = computed(() => permissionStore.routes)
</script>
```

**菜单显示规则**：

| 规则 | 说明 |
|------|------|
| `meta.hidden: true` | 该路由不在菜单中显示（如登录页、404） |
| `meta.roles` 未设置 | 所有角色可见（公共页面） |
| `meta.roles: ['admin']` | 只有 admin 角色可见 |
| `meta.roles: ['admin', 'editor']` | admin 和 editor 角色可见 |
| 子路由全部无权限 | 父级菜单也不显示（递归过滤自动处理） |

不同角色看到的菜单：

```
admin 角色：
├── 首页（Dashboard，所有人可见）
├── 系统管理
│   ├── 用户管理    ← 可见
│   └── 角色管理    ← 可见

editor 角色：
├── 首页（Dashboard，所有人可见）
├── 系统管理
│   └── 用户管理    ← 可见
│   （角色管理不可见，被过滤掉）

viewer 角色：
├── 首页（Dashboard，所有人可见）
（系统管理完全不可见，因为子路由全部被过滤掉）
```

## 六、按钮级别权限控制

菜单权限控制了"用户能看到哪些页面"，但页面内的按钮（如删除、编辑）还需要更细粒度的权限控制。

### 6.1 自定义指令 `v-permission`

通过 Vue 3 自定义指令实现按钮级别的权限控制：

```js
// src/directives/permission.js
import { useUserStore } from '@/store/modules/user'

/**
 * v-permission 自定义指令
 *
 * 用法：
 *   v-permission="['admin']"           → 仅 admin 角色可见
 *   v-permission="['admin', 'editor']" → admin 或 editor 角色可见
 *
 * 原理：
 *   - mounted 时检查用户角色是否包含在指令绑定的角色列表中
 *   - 如果不包含，从 DOM 中移除该元素
 *   - 通过 CSS display: none 而非移除 DOM，保留 v-if 等指令的兼容性
 *
 * 注意：
 *   - 使用 display: none 而非 remove()，避免影响其他指令（如 v-show）
 *   - 如果角色变化（如切换用户），需要配合 updated 钩子重新判断
 */
function checkPermission(el, binding) {
  const { value } = binding

  if (value && Array.isArray(value) && value.length > 0) {
    const userStore = useUserStore()
    const roles = userStore.roles

    const hasPermission = roles.some(role => value.includes(role))

    if (!hasPermission) {
      // 没有权限：隐藏元素
      el.style.display = 'none'
    } else {
      // 有权限：恢复显示
      el.style.display = ''
    }
  } else {
    throw new Error(
      `v-permission 需要传入角色数组，如 v-permission="['admin', 'editor']"`
    )
  }
}

export default {
  mounted(el, binding) {
    checkPermission(el, binding)
  },
  updated(el, binding) {
    checkPermission(el, binding)
  }
}
```

### 6.2 注册自定义指令

在 `src/main.js` 中全局注册：

```js
// src/main.js
import { createApp } from 'vue'
import App from './App.vue'
import { createPinia } from 'pinia'
import router from '@/router'
import permission from '@/directives/permission'
import '@/permission'  // 路由守卫
import '@/assets/styles/global.scss'

const app = createApp(App)

app.use(createPinia())
app.use(router)

// 注册全局自定义指令
app.directive('permission', permission)

app.mount('#app')
```

或者，如果项目有统一注册指令的入口文件：

```js
// src/directives/index.js
import permission from './permission'

export default function registerDirectives(app) {
  app.directive('permission', permission)
}
```

```js
// src/main.js 中调用
import registerDirectives from '@/directives'
registerDirectives(app)
```

### 6.3 权限判断组合式函数 `src/hooks/usePermission.js`

在 `<script setup>` 中不方便使用指令时（如需要在 `v-if` 条件中判断权限），可以使用组合式函数：

```js
// src/hooks/usePermission.js
import { computed } from 'vue'
import { useUserStore } from '@/store/modules/user'

/**
 * 权限判断组合式函数
 *
 * @returns {{ hasPermission, hasRole, isAdmin }}
 *
 * 用法：
 *   const { hasPermission } = usePermission()
 *   if (hasPermission(['admin'])) { ... }
 */
export function usePermission() {
  const userStore = useUserStore()

  /**
   * 判断用户是否拥有指定角色中的任意一个
   * @param {string[]} roles - 需要的角色列表
   * @returns {boolean}
   */
  const hasPermission = (roles) => {
    const userRoles = userStore.roles
    return userRoles.some(role => roles.includes(role))
  }

  /**
   * 判断用户是否拥有某个特定角色
   * @param {string} role - 角色名称
   * @returns {boolean}
   */
  const hasRole = (role) => {
    return userStore.roles.includes(role)
  }

  /**
   * 判断用户是否是管理员
   * @returns {boolean}
   */
  const isAdmin = computed(() => {
    return userStore.roles.includes('admin')
  })

  return {
    hasPermission,
    hasRole,
    isAdmin
  }
}
```

### 7.2 在 `v-if` 中使用 `usePermission`

当需要将权限判断与其他条件结合时，使用 `usePermission` 组合式函数：

```vue
<template>
  <div class="order-management">
    <!-- 权限 + v-if 组合使用 -->
    <el-button
      v-if="hasPermission(['admin']) && orderStatus === 'pending'"
      type="danger"
      @click="handleCancel(order)"
    >
      取消订单
    </el-button>

    <!-- 根据角色显示不同的操作 -->
    <template v-if="isAdmin">
      <el-button type="primary" @click="handleAudit">审核订单</el-button>
    </template>
    <template v-else-if="hasRole('editor')">
      <el-button type="warning" @click="handleReview">提交审核</el-button>
    </template>
  </div>
</template>

<script setup>
import { usePermission } from '@/hooks/usePermission'

const { hasPermission, hasRole, isAdmin } = usePermission()
</script>
```

### 7.3 三种权限控制方式对比

| 方式 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| `v-permission` 指令 | 控制单个按钮/元素的显示隐藏 | 简洁直观，声明式 | 只能控制 DOM 显示，不能控制逻辑 |
| `usePermission` Hook | 需要组合判断或多条件控制 | 灵活，可与其他条件组合 | 需要手动调用 |
| 路由 `meta.roles` | 控制整个页面的访问权限 | 拦截级别，无法绕过 | 粒度较粗（页面级） |

**推荐使用策略**：

```
页面级权限  → 路由 meta.roles（路由守卫拦截，无法绕过）
按钮级权限  → v-permission 指令（模板中简洁直观）
逻辑中判断  → usePermission Hook（v-if、函数内判断）
```

## 八、用户状态管理 `src/store/modules/user.js`

> **与第3章的关系**：该 Store 在第3章（路由与布局体系）中已完整创建。本章在此再次列出是为了展示登录认证体系的完整性。如果你已经在第3章创建过此文件，无需重复创建。

### 8.1 完整代码

```js
// src/store/modules/user.js
import { defineStore } from 'pinia'
import { login, getUserInfo, logout } from '@/api/user'
import { getToken, setToken, removeToken } from '@/utils/auth'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: getToken(),     // 从缓存中恢复 Token
    roles: [],             // 用户角色列表
    name: '',              // 用户名
    avatar: ''             // 头像地址
  }),

  getters: {
    // 判断是否是管理员
    isAdmin: (state) => {
      return state.roles.includes('admin')
    }
  },

  actions: {
    /**
     * 登录
     * @param {Object} loginForm - { username, password }
     */
    async login(loginForm) {
      try {
        const { data } = await login(loginForm)
        this.token = data.token
        setToken(data.token)
        return data
      } catch (error) {
        return Promise.reject(error)
      }
    },

    /**
     * 获取用户信息
     */
    async getUserInfo() {
      try {
        const { data } = await getUserInfo()
        this.roles = data.roles
        this.name = data.name
        this.avatar = data.avatar
        return data
      } catch (error) {
        return Promise.reject(error)
      }
    },

    /**
     * 退出登录
     */
    async logout() {
      try {
        await logout()
      } catch (error) {
        // 即使接口调用失败也要清除本地状态
        console.warn('登出接口调用失败，但仍清除本地状态')
      } finally {
        this.resetState()
      }
    },

    /**
     * 重置所有状态
     */
    resetState() {
      this.token = ''
      this.roles = []
      this.name = ''
      this.avatar = ''
      removeToken()
    }
  }
})
```
