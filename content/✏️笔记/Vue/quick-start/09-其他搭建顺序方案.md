# 第9章 其他搭建顺序方案

> 本章是本教程的最后一章。前面我们按照"先基础设施、再核心组件、最后业务页面"的顺序，从零搭建了一套完整的后台管理系统。但在实际开发中，搭建顺序并非唯一。本章将介绍三种常见的搭建顺序方案，帮助你根据自身情况选择最合适的路线。

---

## 9.1 方案一：先布局后功能（推荐新手）

### 搭建流程

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  项目初始化                                                      │
│      │                                                          │
│      ▼                                                          │
│  全局样式（reset / variables / 公共样式）                         │
│      │                                                          │
│      ▼                                                          │
│  布局骨架（侧边栏 + 顶栏 + 内容区）                               │
│      │                                                          │
│      ▼                                                          │
│  静态路由（先写死菜单，能看到页面切换效果）                          │
│      │                                                          │
│      ▼                                                          │
│  通用组件（表格 / 分页 / 搜索表单）                               │
│      │                                                          │
│      ▼                                                          │
│  登录页                                                          │
│      │                                                          │
│      ▼                                                          │
│  动态路由（根据权限加载菜单）                                      │
│      │                                                          │
│      ▼                                                          │
│  权限控制（按钮级 / 接口级）                                      │
│      │                                                          │
│      ▼                                                          │
│  业务页面（CRUD 页面逐个开发）                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 详细步骤说明

| 阶段 | 具体内容 | 产出物 |
|------|---------|--------|
| 1. 项目初始化 | `create-vue` 创建项目，安装 Element Plus、Vue Router、Pinia、Axios | 可运行的项目骨架 |
| 2. 全局样式 | CSS Reset、CSS 变量、公共布局样式、主题色定义 | `styles/` 目录 |
| 3. 布局骨架 | 搭建 `Layout` 组件：`<Sidebar>` + `<Header>` + `<Main>`，内容区先放占位内容 | 三栏布局可预览 |
| 4. 静态路由 | 在路由配置中写死菜单数据，配置几个空页面用于测试跳转 | 页面可切换 |
| 5. 通用组件 | 封装 `<ProTable>`、`<Pagination>`、`<SearchForm>` 等通用组件 | `components/` 目录 |
| 6. 登录页 | 完成登录表单、Token 存储、路由守卫拦截 | 可登录并跳转首页 |
| 7. 动态路由 | 将静态菜单改为后端接口获取，使用 `router.addRoute()` 动态注册 | 菜单由后端控制 |
| 8. 权限控制 | 自定义指令 `v-permission`、按钮权限控制、接口权限校验 | 完整权限体系 |
| 9. 业务页面 | 逐个开发用户管理、角色管理、菜单管理等业务模块 | 完整后台系统 |

### 优点

- **所见即所得**：早期就能看到系统整体外观，增强成就感和信心
- **结构清晰**：布局先固定下来，后续业务开发不需要再调整结构
- **适合学习**：每一步都有可视化的成果反馈，容易理解"为什么这样做"

### 缺点

- **前期投入大**：在还没写任何业务逻辑之前，就要完成布局和路由，可能让人感到"不知道在做什么"
- **返工风险**：后期发现布局不满足业务需求时，改动成本较高
- **过度设计风险**：新手容易过早封装组件，导致封装的组件并不贴合实际业务

### 适用人群

- Vue 初学者
- 需要先看到整体效果来建立全局认知的开发者
- 从传统服务端渲染转向 SPA 的开发者

## 9.2 方案二：先功能后布局（推荐有经验者）

### 搭建流程

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  项目初始化                                                      │
│      │                                                          │
│      ▼                                                          │
│  工具类封装（request / storage / auth）                         │
│      │                                                          │
│      ▼                                                          │
│  API 接口层定义（所有接口先写好）                                  │
│      │                                                          │
│      ▼                                                          │
│  登录功能（表单 + Token + 路由守卫）                              │
│      │                                                          │
│      ▼                                                          │
│  状态管理（Pinia stores：用户、权限、全局状态）                    │
│      │                                                          │
│      ▼                                                          │
│  通用组件（表格 / 分页 / 表单封装）                               │
│      │                                                          │
│      ▼                                                          │
│  业务 CRUD（在裸页面上直接写业务，不关心布局）                     │
│      │                                                          │
│      ▼                                                          │
│  包装布局（最后套上 Layout，配置路由 meta）                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 详细步骤说明

| 阶段 | 具体内容 | 产出物 |
|------|---------|--------|
| 1. 项目初始化 | `create-vue` 创建项目，只安装最小依赖（Router + Pinia + Axios） | 最小项目骨架 |
| 2. 工具类封装 | 封装 `request.ts`（拦截器、统一错误处理）、`storage.ts`、`auth.ts` | `utils/` 目录 |
| 3. API 接口层 | 定义所有业务接口（用户、角色、菜单等），可以先 mock 数据 | `api/` 目录 |
| 4. 登录功能 | 登录页 + Token 机制 + 路由守卫，确保"未登录不能访问" | 基本安全体系 |
| 5. 状态管理 | 用户信息 Store、权限 Store、全局配置 Store | `stores/` 目录 |
| 6. 通用组件 | 根据实际业务需求提炼通用组件，边写边封装 | `components/` 目录 |
| 7. 业务 CRUD | 在空白页面上直接写各模块的业务逻辑，快速验证数据流转 | 可用的功能页面 |
| 8. 包装布局 | 所有功能验证完毕后，统一套上 Layout 框架 | 完整后台系统 |

### 优点

- **功能优先**：先把核心逻辑跑通，布局只是外衣，最后穿即可
- **减少返工**：业务逻辑稳定后再做布局，布局设计更贴合实际需求
- **组件封装精准**：写了几次业务之后，自然知道哪些东西需要封装，避免过度设计
- **可独立测试**：每个功能模块在裸页面上就能测试，不依赖布局

### 缺点

- **前期无视觉效果**：很长一段时间页面看起来都很"丑"，需要有心理准备
- **需要经验判断**：需要知道哪些东西该提前封装、哪些该延后，新手容易把握不好
- **后期布局整合工作量大**：最后一步要把所有页面统一套上 Layout，路由需要重新调整

### 适用人群

- 有 Vue 基础和项目经验的开发者
- 关注业务逻辑、数据流转的开发者
- 从零搭建过至少一个后台系统的开发者

## 9.3 方案三：按页面逐步搭建（推荐快速出活）

### 搭建流程

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  项目初始化 + 安装依赖                                           │
│      │                                                          │
│      ▼                                                          │
│  创建 Layout + 配置路由骨架                                       │
│      │                                                          │
│      ▼                                                          │
│  ┌──────────────────────────────┐                              │
│  │ 写登录页                     │  ◄── 第1个完整页面             │
│  │   表单 → 提交 → Token → 跳转  │                              │
│  └──────────────┬───────────────┘                              │
│                 ▼                                               │
│  ┌──────────────────────────────┐                              │
│  │ 写 Dashboard                 │  ◄── 第2个完整页面             │
│  │   统计卡片 → 图表 → 搭配布局   │                              │
│  └──────────────┬───────────────┘                              │
│                 ▼                                               │
│  ┌──────────────────────────────┐                              │
│  │ 写用户管理                    │  ◄── 第3个完整页面             │
│  │   表格 → 搜索 → 分页 → CRUD   │                              │
│  │   (提取通用组件)              │                              │
│  └──────────────┬───────────────┘                              │
│                 ▼                                               │
│  ┌──────────────────────────────┐                              │
│  │ 写角色管理                    │  ◄── 第4个完整页面             │
│  │   复用用户管理的组件和模式      │                              │
│  └──────────────┬───────────────┘                              │
│                 ▼                                               │
│  ┌──────────────────────────────┐                              │
│  │ 写菜单管理                    │  ◄── 第5个完整页面             │
│  │   树形表格 + 递归组件          │                              │
│  └──────────────┬───────────────┘                              │
│                 ▼                                               │
│           逐步完善（权限、优化、细节打磨）                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 详细步骤说明

| 阶段 | 具体内容 | 产出物 |
|------|---------|--------|
| 1. 项目初始化 | 一口气装好所有依赖（Element Plus、Router、Pinia、Axios、ECharts 等） | 完整依赖的项目 |
| 2. Layout + 路由 | 快速搭一个 Layout 骨架，路由先配好基本结构 | 可导航的空壳 |
| 3. 登录页 | 一次性写完登录全流程：表单校验、请求、Token 存储、路由守卫 | 可登录的完整页面 |
| 4. Dashboard | 写首页：统计卡片、图表、快捷操作，感受布局效果 | 有内容的首页 |
| 5. 用户管理 | 完整的 CRUD 页面，写完后**立刻提取**通用组件（表格、分页、搜索表单） | 第一个业务页面 + 通用组件 |
| 6. 角色管理 | 复用上一步提取的通用组件，快速完成第二个业务页面 | 第二个业务页面 |
| 7. 菜单管理 | 引入树形组件、递归逻辑，扩展通用组件能力 | 第三个业务页面 |
| 8. 逐步完善 | 动态路由、权限指令、细节优化、错误处理完善 | 完整系统 |

### 优点

- **反馈最快**：每完成一个页面就是一个可交付的成果
- **边做边提炼**：写完第一个 CRUD 页面后再提取通用组件，封装最精准
- **适合迭代**：如果需求中途变化，已经做好的页面不受影响
- **快速出活**：最快能交付可用的页面，适合有交付压力的场景

### 缺点

- **架构不够统一**：前面写的页面可能在后期需要重构（比如后来加了权限，前面的页面要改）
- **代码风格可能不一致**：早期和后期写的代码风格可能有差异
- **通用组件可能需要多次调整**：因为每个页面可能有不同需求，导致通用组件反复修改
- **容易忽略全局视角**：只关注单个页面，可能导致全局体验不统一

### 适用人群

- 需要快速交付项目的开发者
- 边做边学的自学者
- 项目需求不明确、需要逐步确认的场景
- 接手维护型项目、需要逐步替换旧页面的场景

## 9.4 三种方案对比

| 维度 | 方案一：先布局后功能 | 方案二：先功能后布局 | 方案三：按页面逐步搭建 |
|------|---------------------|---------------------|---------------------|
| **学习难度** | 低 | 高 | 中 |
| **初始搭建速度** | 慢（前期看不到业务成果） | 中（功能跑通后很快） | 快（第一个页面很快完成） |
| **整体完成速度** | 中等 | 较慢（后期布局整合耗时） | 中等偏快 |
| **代码质量** | 良好（结构统一） | 优秀（封装精准） | 一般（可能有风格差异） |
| **可维护性** | 好（分层清晰） | 最好（逻辑和视图分离） | 一般（需要后期整理） |
| **扩展性** | 好 | 优秀 | 中等 |
| **返工风险** | 中（布局可能需调整） | 低（功能已验证） | 高（权限/架构变化时） |
| **成就感** | 高（早期看到效果） | 低（前期枯燥） | 最高（持续产出） |
| **适用场景** | 学习、教学、演示 | 正式项目、团队协作 | 快速出活、迭代交付 |
| **推荐人群** | Vue 初学者 | 有经验的开发者 | 需要快速交付的开发者 |

### 形象比喻

```
方案一 —— "先盖框架再装修"
  先把房子的骨架搭好，看到房子形状，再一间间装修。
  像搭积木，先搭底座。

方案二 —— "先造零件再组装"
  先把所有零件（功能模块）造好，测试通过后，最后组装成完整产品。
  像造汽车，先造发动机，再造底盘，最后组装。

方案三 —— "边盖边住"
  先盖好一间卧室就搬进去住，再慢慢盖客厅、厨房。
  像装修，先装好一间用着，其他房间慢慢来。
```

## 9.5 最佳实践建议

### 无论哪种顺序，以下内容建议优先完成

以下内容是后台系统的"基础设施"，无论选择哪种搭建顺序，都建议尽早完成：

```
┌────────────────────────────────────────────────────────────┐
│                     优先完成的事项                            │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  1. Axios 封装（请求/响应拦截器、统一错误处理）               │
│     └─ 原因：所有页面都要发请求，这是最底层的依赖             │
│                                                            │
│  2. 路由守卫（登录拦截、权限校验）                            │
│     └─ 原因：不然后面的页面谁都能访问，安全没有保障           │
│                                                            │
│  3. Token 管理机制                                          │
│     └─ 原因：登录后的所有操作都依赖 Token                    │
│                                                            │
│  4. 全局样式基础（CSS 变量、主题色、Reset）                   │
│     └─ 原因：后期改主题色会牵一发而动全身                    │
│                                                            │
│  5. Element Plus 按需引入配置                                │
│     └─ 原因：后期再改打包体积会很大                          │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 避坑指南

**1. 不要过早过度封装**

```javascript
// 错误示范：第一周就开始写"万能表格组件"
// 结果写了 500 行配置，后来发现根本用不上这么多功能

// 正确做法：先写两三个页面的表格，发现重复代码后再提取
// 封装的依据是"重复出现 3 次以上"的原则
```

**2. 不要忽视错误处理**

```javascript
// 错误示范：只写成功逻辑，不处理错误
const res = await getUserList()
tableData.value = res.data

// 正确做法：每个请求都要处理错误
try {
  const res = await getUserList()
  tableData.value = res.data
} catch (error) {
  ElMessage.error('获取用户列表失败：' + error.message)
}
```

**3. 不要在 Layout 里写业务逻辑**

```
Layout 只负责"壳"，不负责"内容"。

Layout/
├── index.vue          ← 只管布局结构（侧边栏 + 顶栏 + 内容区）
├── components/
│   ├── Sidebar.vue    ← 只管导航菜单的展示和折叠
│   └── Header.vue     ← 只管顶部栏（面包屑、用户信息、全屏等）
│
views/                  ← 所有业务页面放这里
├── dashboard/
├── system/
│   ├── user/
│   ├── role/
│   └── menu/
└── ...
```

**4. 不要一次性装太多依赖**

```bash
# 错误示范：项目第一天就装了 30 个包
npm install element-plus axios pinia vue-router echarts
  xlsx file-saver clipboard.js dayjs lodash-deep nprogress
  screenfull @vueuse/core ...

# 正确做法：用到什么装什么，按需引入
npm install vue-router pinia axios   # 第一步只装核心三件套
npm install element-plus              # 需要UI组件时再装
```

**5. 不要跳过 TypeScript（如果项目选择了 TS）**

```typescript
// 不要因为"先跑通再说"就写 any
const res: any = await getUserList()  // 错误示范

// 至少定义基本的接口类型
interface UserListResult {
  list: User[]
  total: number
}
const res = await getUserList<UserListResult>()
```

### 学习建议

**如果你是 Vue 初学者：**

```
推荐路线：本教程的顺序（方案一变体）

理由：
  本教程从工具类 → 路由布局 → 核心组件 → 业务页面
  介于"先布局后功能"和"按页面逐步搭建"之间
  既能看到整体结构，又不会前期投入过大

学习要点：
  1. 每一章都动手写，不要只看
  2. 遇到不懂的 API 先查官方文档
  3. 写完一章后，尝试自己不看教程重写一遍
```

**如果你有一定 Vue 基础：**

```
推荐路线：方案二（先功能后布局）

理由：
  你已经理解了 Vue 的基本概念
  把精力放在业务逻辑上会更高效
  布局对你来说只是最后一步的"包装"

进阶方向：
  1. 尝试使用组合式函数（Composables）抽取业务逻辑
  2. 学习 TypeScript 类型体操，让接口类型更精确
  3. 关注性能优化：虚拟滚动、懒加载、缓存策略
```

**如果你需要快速交付项目：**

```
推荐路线：方案三（按页面逐步搭建）

理由：
  每完成一个页面就能演示给产品/客户
  需求变化时只影响当前正在做的页面
  交付压力下，"完成"比"完美"更重要

加速技巧：
  1. 使用代码生成器（根据数据库表自动生成 CRUD 页面）
  2. 准备一套自己的后台模板，新项目直接复制
  3. 第一个完整页面写好后，后续页面复制改即可
```

## 9.6 本教程搭建顺序回顾

本教程采用的搭建顺序如下：

```
┌───────────────────────────────────────────────────────────────┐
│                       本教程搭建顺序                           │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  第1章 ─ 项目初始化                                            │
│      └─ create-vue、依赖安装、目录规范                          │
│                                                               │
│  第2章 ─ 工具类封装                                             │
│      └─ Axios 封装、Storage、Auth 工具                         │
│                                                               │
│  第3章 ─ 路由与布局体系                                         │
│      └─ 路由配置、Layout 结构、路由守卫                          │
│                                                               │
│  第4章 ─ 核心布局组件                                           │
│      └─ 侧边栏、顶栏、面包屑、标签页                            │
│                                                               │
```

这个顺序的核心思路是：**先铺基础设施，再搭核心组件，最后落地业务**。它介于方案一和方案二之间，兼顾了"看得见进度"和"代码质量"两个方面。

---

## 小结

搭建后台管理系统没有唯一的正确顺序。选择哪种方案取决于你的经验水平、项目需求和交付压力。但无论选择哪种方案，以下几点是通用的：

1. **基础设施（请求封装、路由守卫、Token 管理）优先完成**
2. **不要过早封装，先写重复代码，再提取通用组件**
3. **每完成一个阶段就 commit，方便回退和对比**
4. **布局和业务分离，Layout 里不写业务逻辑**
5. **先完成再完美，不要在细节上过度纠结**

希望本教程能帮助你从零搭建属于自己的后台管理系统。掌握了一种搭建方式后，再尝试其他方案，你会发现每种方案都有值得借鉴的地方。
