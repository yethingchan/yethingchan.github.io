# 第四章：核心布局组件

> 本章目标：实现后台管理系统的完整布局 UI，包括可折叠侧边栏（含多级递归菜单）、顶部导航栏（含面包屑与用户下拉菜单）、以及带 keep-alive 缓存的主内容区。所有组件均可直接运行，注释详尽。

```
1. permission store 的 routes ──→ Sidebar 用于渲染菜单

4. vue-router 的 currentRoute ──→ Breadcrumb 自动生成面包屑
5. user store 的 name/avatar ──→ UserDropdown 展示用户信息
```

## 二、主布局 `src/layout/index.vue`

主布局是整个后台的骨架，使用 `flex` 水平排列左侧 sidebar 与右侧区域，右侧区域再使用 `flex-direction: column` 垂直排列 header 和 AppMain。

```vue
<!-- src/layout/index.vue -->
<template>
  <div class="app-wrapper" :class="{ 'mobile': device === 'mobile' }">
    <!--
      侧边栏
      - class 根据 sidebar.opened 动态切换，控制宽度
      - v-if 在移动端控制显示/隐藏
    -->
    <sidebar
      class="sidebar-container"
      :class="{ 'is-collapse': !sidebar.opened }"
    />

    <!--
      右侧主区域
      - 包含顶部导航栏 + 主内容区
      - 使用 flex-column 垂直排列
    -->
    <div class="main-container" :class="{ 'is-collapse': !sidebar.opened }">
      <!-- 顶部导航栏：hamburger + 面包屑 + 用户下拉 -->
      <header-bar />

      <!-- 主内容区：路由视图 + 过渡动画 -->
      <app-main />
    </div>
  </div>
</template>

<script setup>
/**
 * 主布局组件 - 后台管理系统的骨架
 *
 * 职责：
 * 1. 组合 sidebar、header、app-main 三个子区域
 * 2. 读取 app store 的 sidebar 状态，控制折叠/展开
 * 3. 监听窗口尺寸变化，自动判断设备类型
 */
import { computed, watch, onMounted, onBeforeUnmount } from 'vue'
import Sidebar from './Sidebar/index.vue'
import HeaderBar from './Header/index.vue'
import AppMain from './AppMain.vue'
import { useAppStore } from '@/store/modules/app'

const appStore = useAppStore()

// 从 store 中解构需要的状态
const sidebar = computed(() => appStore.sidebar)
const device = computed(() => appStore.device)

// 移动端侧边栏宽度断点（与 Element Plus 的断点一致）
const MOBILE_BREAKPOINT = 992

/**
 * 监听窗口宽度变化
 * - 宽度 < 992px 时判定为移动设备，自动折叠侧边栏
 * - 宽度 >= 992px 时恢复桌面模式
 */
const handleResize = () => {
  const isMobile = window.innerWidth < MOBILE_BREAKPOINT
  appStore.setDevice(isMobile ? 'mobile' : 'desktop')

  // 移动端自动折叠侧边栏
  if (isMobile) {
    appStore.closeSidebar(true)
  }
}

// 监听路由变化：移动端跳转路由后自动关闭侧边栏
watch(
  () => appStore.sidebar.opened,
  (newVal) => {
    // 移动端打开侧边栏时，添加遮罩层
    const wrapper = document.querySelector('.app-wrapper')
    if (appStore.device === 'mobile') {
      if (newVal) {
        wrapper?.classList.add('mobile-sidebar-active')
      } else {
        wrapper?.classList.remove('mobile-sidebar-active')
      }
    }
  }
)

onMounted(() => {
  handleResize()
  window.addEventListener('resize', handleResize)
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', handleResize)
})
</script>

<style lang="scss" scoped>
.app-wrapper {
  // 整体使用 flex 水平排列
  display: flex;
  width: 100%;
  height: 100%;

  // ==================== 侧边栏 ====================
  .sidebar-container {
    width: $sideBarWidth;
    height: 100%;
    // 固定在左侧，不随内容滚动
    position: fixed;
    top: 0;
    left: 0;
    bottom: 0;
    z-index: 1001;
    // 折叠/展开的过渡动画
    transition: width $sidebarTransition ease;
    overflow: hidden;

    // 折叠状态：变窄
    &.is-collapse {
      width: $sideBarCollapsedWidth;
    }
  }

  // ==================== 右侧主区域 ====================
  .main-container {
    // 右侧区域 = 总宽度 - 侧边栏宽度
    margin-left: $sideBarWidth;
    min-height: 100vh;
    display: flex;
    flex-direction: column;
    transition: margin-left $sidebarTransition ease;
    position: relative;

    // 折叠状态：margin-left 同步缩小
    &.is-collapse {
      margin-left: $sideBarCollapsedWidth;
    }
  }

  // ==================== 移动端适配 ====================
  &.mobile {
    .sidebar-container {
      // 移动端侧边栏覆盖在内容上方
      width: $sideBarWidth !important;
      transition: transform $sidebarTransition ease;

      // 默认隐藏（向左滑出）
      &:not(.is-collapse) {
        // 移动端展开状态：显示侧边栏
        transform: translateX(0);
      }

      &.is-collapse {
        // 移动端折叠状态：隐藏侧边栏（向左滑出）
        transform: translateX(-$sideBarWidth);
      }
    }

    .main-container {
      // 移动端右侧区域占满宽度
      margin-left: 0 !important;
    }
  }

  // 移动端侧边栏激活状态：显示半透明遮罩
  &.mobile-sidebar-active {
    &::before {
      content: '';
      position: fixed;
      top: 0;
      left: 0;
      right: 0;
      bottom: 0;
      background: rgba(0, 0, 0, 0.3);
      z-index: 1000;
    }
  }
}
</style>
```

**核心要点：**

- 使用 `computed` 从 Pinia store 中获取响应式状态，避免直接解构丢失响应性
- `handleResize` 通过监听 `window.resize` 事件自动判断设备类型，移动端自动折叠侧边栏
- 侧边栏使用 `position: fixed` 固定定位，右侧区域通过 `margin-left` 让出空间
- 移动端侧边栏使用 `transform: translateX` 实现滑入滑出效果，而不是改变宽度

## 三、侧边栏 `src/layout/Sidebar/index.vue`

侧边栏容器组件，包含 Logo 和菜单两部分，负责从 permission store 读取路由数据并传递给 SidebarItem 渲染。

```vue
<!-- src/layout/Sidebar/index.vue -->
<template>
  <div class="sidebar">
    <!-- ==================== Logo 区域 ==================== -->
    <logo class="sidebar-logo" :collapse="!sidebar.opened" />

    <!--
      el-menu 菜单组件
      - collapse: 控制折叠/展开
      - collapse-transition: Element Plus 内置折叠动画
      - background-color / text-color / active-text-color: 菜单主题色
      - unique-opened: 保持只有一个子菜单展开
      - default-active: 当前激活菜单项（与路由 path 对应）
    -->
    <el-scrollbar>
      <el-menu
        :default-active="activeMenu"
        :collapse="!sidebar.opened"
        :collapse-transition="false"
        :unique-opened="true"
        background-color="#304156"
        text-color="#bfcbd9"
        active-text-color="#409eff"
      >
        <!--
          遍历路由表，渲染每个菜单项
          - SidebarItem 是递归组件，支持多级嵌套
          - 将 route 对象和根路径作为 props 传入
        -->
        <sidebar-item
          v-for="route in permissionRoutes"
          :key="route.path"
          :item="route"
          :base-path="route.path"
        />
      </el-menu>
    </el-scrollbar>
  </div>
</template>

<script setup>
/**
 * 侧边栏容器组件
 *
 * 职责：
 * 1. 展示 Logo
 * 2. 渲染 el-menu 菜单，配置折叠/展开
 * 3. 遍历路由表，将每个路由传递给 SidebarItem 递归渲染
 */
import { computed } from 'vue'
import { useRoute } from 'vue-router'
import Logo from './Logo.vue'
import SidebarItem from './SidebarItem.vue'
import { useAppStore } from '@/store/modules/app'
import { usePermissionStore } from '@/store/modules/permission'

const route = useRoute()
const appStore = useAppStore()
const permissionStore = usePermissionStore()

// 侧边栏折叠状态
const sidebar = computed(() => appStore.sidebar)

// 权限路由表（用于渲染侧边栏菜单）
const permissionRoutes = computed(() => permissionStore.routes)

/**
 * 当前激活的菜单路径
 * - 基于当前路由的 path，用于 el-menu 的高亮
 * - 如果路由配置了 activeMenu（用于详情页高亮列表页菜单），则使用它
 */
const activeMenu = computed(() => {
  const { meta, path } = route
  if (meta?.activeMenu) {
    return meta.activeMenu
  }
  return path
})
</script>

<style lang="scss" scoped>
.sidebar {
  height: 100%;
  display: flex;
  flex-direction: column;
  background-color: #304156;

  // Logo 区域固定在顶部
  .sidebar-logo {
    flex-shrink: 0;
  }

  // 菜单区域占据剩余空间
  :deep(.el-scrollbar) {
    flex: 1;
    overflow: hidden;

    // el-menu 隐藏默认的右边框
    .el-menu {
      border-right: none;
      height: 100%;
    }
  }
}
</style>
```

**核心要点：**

- `el-menu` 的 `collapse` 属性接受布尔值，为 `true` 时自动折叠为图标模式
- `collapse-transition` 设为 `false`，因为折叠动画由父组件的 CSS `transition: width` 控制，避免两种动画叠加
- `activeMenu` 使用 `computed` 实时跟踪当前路由变化，确保菜单高亮正确
- `el-scrollbar` 组件让菜单区域内容超出时可滚动，且滚动条样式统一

## 四、侧边栏菜单项 `src/layout/Sidebar/SidebarItem.vue`

这是整个侧边栏菜单系统的核心——一个**递归组件**。它能处理多级嵌套菜单，支持单子项优化显示、hidden 菜单隐藏、外链菜单特殊处理。

```vue
<!-- src/layout/Sidebar/SidebarItem.vue -->
<template>
  <!--
    递归组件说明：
    - 当路由有可见子项时，自身递归调用处理嵌套
    - 只有一个可见子项时，直接渲染为 el-menu-item（减少层级）
    - 没有子项时，渲染为叶子菜单项
  -->

  <!-- ==================== 隐藏菜单项 ==================== -->
  <!-- meta.hidden 为 true 的路由不在侧边栏显示 -->
  <template v-if="!item.meta || !item.meta.hidden">

    <!--
      情况一：只有一个可见子项（或无子项）→ 直接渲染为 el-menu-item
      常见场景：系统管理下只有一个子菜单时，不需要再展开一层
    -->
    <template v-if="hasOneShowingChild(item)">
      <!-- 外链菜单：使用 a 标签跳转 -->
      <app-link v-if="onlyOneChild.meta?.link" :to="resolvePath(onlyOneChild.path)">
        <el-menu-item :index="resolvePath(onlyOneChild.path)">
          <el-icon v-if="onlyOneChild.meta?.icon || item.meta?.icon">
            <component :is="onlyOneChild.meta?.icon || item.meta?.icon" />
          </el-icon>
          <template #title>
            {{ onlyOneChild.meta?.title }}
          </template>
        </el-menu-item>
      </app-link>

      <!-- 普通菜单项：使用 router-link 跳转 -->
      <app-link v-else :to="resolvePath(onlyOneChild.path)">
        <el-menu-item :index="resolvePath(onlyOneChild.path)">
          <el-icon v-if="onlyOneChild.meta?.icon || item.meta?.icon">
            <component :is="onlyOneChild.meta?.icon || item.meta?.icon" />
          </el-icon>
          <template #title>
            {{ onlyOneChild.meta?.title }}
          </template>
        </el-menu-item>
      </app-link>
    </template>

    <!--
      情况二：有多个可见子项 → 渲染为 el-sub-menu（可展开的子菜单）
      el-sub-menu 内递归调用 SidebarItem 处理嵌套
    -->
    <el-sub-menu
      v-else-if="showingChildren.length > 0"
      :index="resolvePath(item.path)"
    >
      <template #title>
        <el-icon v-if="item.meta?.icon">
          <component :is="item.meta.icon" />
        </el-icon>
        <span>{{ item.meta?.title }}</span>
      </template>

      <!-- 递归渲染子菜单项 -->
      <sidebar-item
        v-for="child in showingChildren"
        :key="child.path"
        :item="child"
        :base-path="resolvePath(child.path)"
      />
    </el-sub-menu>

    <!--
      情况三：无子项且非叶子菜单 → 渲染为 el-menu-item
      如：Layout 级别的路由，本身不渲染，children 才是实际页面
      但如果 children 为空或全部 hidden，则渲染自身
    -->
    <app-link v-else :to="resolvePath(item.path)">
      <el-menu-item :index="resolvePath(item.path)">
        <el-icon v-if="item.meta?.icon">
          <component :is="item.meta.icon" />
        </el-icon>
        <template #title>
          {{ item.meta?.title }}
        </template>
      </el-menu-item>
    </app-link>
  </template>
</template>

<script setup>
/**
 * 侧边栏菜单项 - 递归组件
 *
 * 职责：
 * 1. 判断路由是否只有一个可见子项，优化渲染层级
 * 2. 多个子项时使用 el-sub-menu 展开显示
 * 3. 支持外链菜单（meta.link）
 * 4. 递归处理无限层级的嵌套菜单
 *
 * Props:
 * - item: 路由对象（包含 path、meta、children 等）
 * - basePath: 父级路径，用于拼接完整的子路由路径
 */
import { ref } from 'vue'
import AppLink from './Link.vue'
import { isExternal } from '@/utils/validate'

const props = defineProps({
  item: {
    type: Object,
    required: true
  },
  basePath: {
    type: String,
    default: ''
  }
})

// 记录只有一个子项时的那个子项
const onlyOneChild = ref(null)

/**
 * 过滤出可见的子路由
 * 排除 hidden: true 的路由
 */
const showingChildren = () => {
  if (props.item.children) {
    return props.item.children.filter(child => {
      if (child.meta?.hidden) return false
      return true
    })
  }
  return []
}

/**
 * 判断是否只有一个可见子项
 * 如果只有一个子项（或子项路径与父路径相同），则不需要展开子菜单
 */
const hasOneShowingChild = (parent) => {
  const children = showingChildren()

  // 过滤后没有子项：使用父路由自身作为菜单项
  if (children.length === 0) {
    onlyOneChild.value = { ...parent, path: '' }
    return true
  }

  // 只有一个子项
  if (children.length === 1) {
    onlyOneChild.value = children[0]
    return true
  }

  // 多个子项：不使用单子项优化
  return false
}

/**
 * 解析完整路径
 * - 将子路由的相对路径与 basePath 拼接为完整路径
 * - 如果是外部链接，直接返回
 */
const resolvePath = (routePath) => {
  if (isExternal(routePath)) {
    return routePath
  }
  if (isExternal(props.basePath)) {
    return props.basePath
  }

  // 拼接路径：确保路径以 / 开头
  const base = props.basePath.endsWith('/')
    ? props.basePath
    : props.basePath + '/'
  const path = routePath.startsWith('/')
    ? routePath.substring(1)
    : routePath

  return base + path
}
</script>

    margin-right: 12px;
```

### 4.1 辅助工具函数 `src/utils/validate.js`

SidebarItem 依赖的 URL 校验工具：

```js
// src/utils/validate.js

/**
 * 判断是否是外部链接（http: / https: / mailto: / tel:）
 * @param {string} path
 * @returns {boolean}
 */
export function isExternal(path) {
  return /^(https?:|mailto:|tel:)/.test(path)
}
```

```vue
<template>
```

```vue
import { useRouter } from 'vue-router'

import { User, Lock, SwitchButton, ArrowDown } from '@element-plus/icons-vue'
import { useUserStore } from '@/store/modules/user'

  return name.charAt(0).toUpperCase()

  switch (command) {
    case 'profile':
      // 跳转到个人中心页面
      router.push('/profile')
      break
    case 'password':
      // 跳转到修改密码页面
      router.push('/password')
      break
    case 'logout':
      handleLogout()
      break
  }
}

 * 退出登录
 * 1. 弹出确认对话框
 * 2. 调用登出接口（清除服务端 session）

    '提示',

      cancelButtonText: '取消',
      type: 'warning'

      await userStore.logout()
      ElMessage.success('退出登录成功')

      // 即使登出接口失败，也继续清除本地状态

      // 清除本地状态并跳转登录页
      userStore.resetState()
      router.push(`/login?redirect=${router.currentRoute.value.fullPath}`)

  })
```

## 八、面包屑 `src/components/Breadcrumb/index.vue`

面包屑根据当前路由自动生成，支持多级层级、图标和点击跳转。

```vue
<!-- src/components/Breadcrumb/index.vue -->
<template>
  <el-breadcrumb class="breadcrumb" separator="/">
    <!--
      过渡组：当路由变化时，面包屑项平滑切换
    -->
    <transition-group name="breadcrumb">
      <!--
        遍历面包屑项
        - 每个项包含 title、path、icon
        - 最后一项是当前页面，不可点击（高亮显示）
      -->
      <el-breadcrumb-item
        v-for="(item, index) in breadcrumbs"
        :key="item.path"
      >
        <!-- 非最后一项：可点击跳转 -->
        <span
          v-if="index < breadcrumbs.length - 1"
          class="breadcrumb-link"
          @click="handleLink(item)"
        >
          <!-- 图标 -->
          <el-icon v-if="item.icon" class="breadcrumb-icon">
            <component :is="item.icon" />
          </el-icon>
          <!-- 文字 -->
          <span>{{ item.meta?.title }}</span>
        </span>

        <!-- 最后一项：当前页面，不可点击 -->
        <span v-else class="breadcrumb-current">
          <el-icon v-if="item.icon" class="breadcrumb-icon">
            <component :is="item.icon" />
          </el-icon>
          <span>{{ item.meta?.title }}</span>
        </span>
      </el-breadcrumb-item>
    </transition-group>
  </el-breadcrumb>
</template>

<script setup>
/**
 * 面包屑导航组件
 *
 * 职责：
 * 1. 根据当前路由自动生成面包屑（首页 > 一级 > 二级）
 * 2. 支持点击面包屑项跳转到对应页面
 * 3. 支持 meta.breadcrumb: false 隐藏某个路由
 * 4. 支持 meta.icon 显示图标
 *
 * 原理：
 * - 通过 route.matched 获取路由匹配链
 * - 从匹配链中提取每个层级的信息
 * - 过滤掉不需要显示的路由（redirect 路由、hidden 面包屑）
 */
import { ref, watch, onMounted } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { compile } from 'path-to-regexp'

const route = useRoute()
const router = useRouter()

// 面包屑数据
const breadcrumbs = ref([])

/**
 * 获取面包屑数据
 * - 从 route.matched 中获取完整的路由匹配链
 * - 过滤掉 redirect 路由和 hidden 面包屑
 * - 添加首页作为默认第一项
 */
const getBreadcrumb = () => {
  const matched = route.matched.filter(
    (item) => item.meta && item.meta.title
  )

  // 过滤掉设置了 breadcrumb: false 的路由
  const filtered = matched.filter(
    (item) => item.meta && item.meta.breadcrumb !== false
  )

  // 如果第一个面包屑不是首页，则在前面添加首页
  const first = filtered[0]
  if (first && first.path !== '/dashboard') {
    filtered.unshift({
      path: '/dashboard',
      meta: { title: '首页', icon: 'HomeFilled' }
    })
  }

  breadcrumbs.value = filtered
}

/**
 * 点击面包屑项跳转
 * - 使用 path-to-regexp 解析动态路径参数
 * - 支持 /user/:id 这类动态路由
 */
const handleLink = (item) => {
  const { redirect, path } = item

  // 如果有 redirect，跳转到 redirect 地址
  if (redirect) {
    router.push(redirect)
    return
  }

  // 解析路径中的动态参数
  router.push(path)
}

// 监听路由变化，重新生成面包屑
watch(
  () => route.path,
  () => {
    getBreadcrumb()
  }
)

onMounted(() => {
  getBreadcrumb()
})
</script>

<style lang="scss" scoped>
.breadcrumb {
  line-height: $headerHeight;
  padding: 0 8px;

  // 面包屑链接（可点击）
  .breadcrumb-link {
    display: inline-flex;
    align-items: center;
    cursor: pointer;
    color: #97a8be;
    font-weight: normal;
    transition: color 0.2s;

    &:hover {
      color: #409eff;
    }

    // 图标
    .breadcrumb-icon {
      margin-right: 4px;
      font-size: 14px;
    }
  }

  // 当前页面（不可点击）
  .breadcrumb-current {

    color: #606266;
    font-weight: 500;

    .breadcrumb-icon {
```

```vue
        <!--
          keep-alive 缓存：排除 noCache 的页面
          如果项目不需要缓存，去掉 keep-alive 包裹即可
        -->
        <keep-alive :exclude="cachedViews">
          <component
            :is="Component"
            :key="currentRoute.path"
            class="page-component"
          />
        </keep-alive>
      </transition>
    </router-view>
  </div>
</template>

<script setup>
/**
 * 主内容区组件
 *
 * 职责：
 * 1. 包裹 router-view，提供页面渲染区域
 * 2. 通过 keep-alive 缓存页面状态（可选）
 * 3. 提供页面切换的过渡动画
 *
 * keep-alive 说明：
 * - exclude: 排除不需要缓存的组件（通过组件名称匹配）
 * - 需要缓存：保持表单输入、滚动位置等状态
 * - 不需要缓存：实时数据页面、每次进入都需要刷新的页面
 */
import { computed } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()

/**
 * 不需要缓存的组件名称列表
 * - 通过路由 meta.noCache 控制
 * - noCache: true 的页面不缓存
 */
const cachedViews = computed(() => {
  // 返回需要排除缓存的路由的组件名
  // keep-alive 的 exclude 属性接收组件名称数组
  const noCacheRoutes = []
  const allRoutes = route.matched
  allRoutes.forEach(r => {
    if (r.meta?.noCache && r.components?.default?.name) {
      noCacheRoutes.push(r.components.default.name)
    }
  })
  return noCacheRoutes
})
</script>

<style lang="scss" scoped>
.app-main {
  // 主内容区域
  flex: 1;
  min-height: calc(100vh - #{$headerHeight});
  padding: 16px;
  background-color: $appMainBg;
  overflow: hidden;
  position: relative;

  // 页面组件基础样式
  .page-component {
    width: 100%;
    min-height: 100%;
  }
}

// ==================== 过渡动画 ====================
// fade-transform：淡入 + 轻微位移
.fade-transform-enter-active,
.fade-transform-leave-active {
  transition: all 0.25s ease;
}

.fade-transform-enter-from {
  opacity: 0;
  transform: translateX(-10px);
}

.fade-transform-leave-to {
  opacity: 0;
  transform: translateX(10px);
}
</style>
```

**关于 keep-alive 的注意事项：**

1. **组件必须有 name**：`keep-alive` 通过组件的 `name` 属性匹配，使用 `<script setup>` 时需要额外添加：

```vue
<script>
export default {
  name: 'UserManagement' // 必须与 keep-alive 的 include/exclude 匹配
}
</script>

<script setup>
// 组件逻辑...
</script>
```

2. **替代方案（推荐）**：如果不使用 keep-alive，简化为：

```vue
<template>
  <div class="app-main">
    <router-view v-slot="{ Component }">
      <transition name="fade-transform" mode="out-in">
        <component :is="Component" />
      </transition>
    </router-view>
  </div>
</template>
```

3. **max 属性**：限制最大缓存数量，超出时淘汰最早的缓存组件：

```vue
<keep-alive :max="10">
  <component :is="Component" :key="route.fullPath" />
</keep-alive>
```

### 10.2 用户操作触发的数据流

```
用户点击 Hamburger
  → emit('toggleClick')
  → Header 调用 appStore.toggleSidebar()
  → app store 中 sidebar.opened 取反
  → Sidebar 响应式更新：
      → el-menu :collapse 变化（折叠/展开动画）
      → Logo 显示/隐藏文字
      → Layout 的 sidebar-container class 变化（宽度过渡）

用户点击菜单项
  → router.push(path)
  → 路由跳转
  → route.matched 更新
  → Breadcrumb 重新生成面包屑
  → AppMain 切换页面（带过渡动画）
  → Sidebar 的 el-menu :default-active 更新（高亮当前菜单）

用户点击退出登录
  → UserDropdown handleCommand('logout')
  → ElMessageBox.confirm 二次确认
  → userStore.logout()（调用接口）
  → userStore.resetState()（清除 Token 和用户信息）
  → router.push('/login?redirect=...')
```

## 十一、本章小结

本章实现了后台管理系统的完整布局体系，共 8 个核心组件：

| 组件 | 文件路径 | 核心功能 |
|------|----------|---------|
| 主布局 | `src/layout/index.vue` | Flex 骨架，组合 sidebar + header + app-main，响应式适配 |
| 侧边栏容器 | `src/layout/Sidebar/index.vue` | Logo + el-menu 菜单，配置折叠/展开 |
| Logo | `src/layout/Sidebar/Logo.vue` | 折叠时隐藏文字只显示图标，点击回首页 |
| 菜单项 | `src/layout/Sidebar/SidebarItem.vue` | 递归组件，支持多级嵌套、单子项优化、外链处理 |
| 顶部导航 | `src/layout/Header/index.vue` | Hamburger + 面包屑 + 用户功能区 |
| 用户下拉 | `src/layout/Header/UserDropdown.vue` | 头像 + 下拉菜单（个人中心/修改密码/退出登录） |
| 面包屑 | `src/components/Breadcrumb/index.vue` | 自动根据路由生成，支持点击跳转和图标 |
| 主内容区 | `src/layout/AppMain.vue` | router-view + keep-alive + 过渡动画 |

**关键设计要点：**

1. **响应式折叠**：侧边栏的折叠状态由 Pinia `app store` 统一管理，Hamburger 按钮、窗口 resize、移动端都可以触发折叠
2. **递归菜单**：SidebarItem 通过递归调用自身处理无限层级嵌套，单子项时自动扁平化减少层级
3. **自动面包屑**：基于 `route.matched` 路由匹配链自动生成，无需手动维护
4. **数据流清晰**：所有跨组件状态通过 Pinia Store 共享，组件间通过 props/emit 通信，避免了复杂的跨层级传递
