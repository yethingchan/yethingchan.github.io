# 第三章：路由与布局体系

> 本章目标：搭建后台管理系统的路由体系，包括静态路由/动态路由配置、嵌套路由布局结构、路由守卫（登录拦截与权限控制）、以及配合路由工作的 Pinia 状态管理。

---

## 一、嵌套路由布局结构

后台管理系统的布局核心思想是：**部分页面使用 Layout 布局，部分页面独立存在（如登录页）**。

### 1.1 页面与布局的映射关系

```
/login              → 无布局（独立页面，全屏）
/404                → 无布局（独立页面，全屏）
/                   → Layout 布局（侧边栏 + 顶部栏 + 内容区）
  /dashboard        → Layout > Dashboard
  /system/user      → Layout > 用户管理
  /system/role      → Layout > 角色管理
```

### 1.2 布局组件骨架

Layout 组件是整个后台的骨架，包含三个核心区域：

```
┌──────────────────────────────────────────┐
│  Sidebar  │         Header               │
│           │──────────────────────────────│
│  Logo     │                              │
│           │         AppMain              │
│  Menu     │      （router-view）          │
│  - 用户   │                              │
│  - 角色   │                              │
│  - ...    │                              │
└──────────────────────────────────────────┘
```

Layout 组件的代码骨架（后续第四章会详细实现）：

```vue
<!-- src/layout/index.vue -->
<template>
  <div class="app-wrapper">
    <!-- 侧边栏 -->
    <sidebar class="sidebar-container" />

    <div class="main-container">
      <!-- 顶部导航栏 -->
      <header-bar />

      <!-- 主内容区域 -->
      <app-main />
    </div>
  </div>
</template>

<script setup>
import Sidebar from './Sidebar/index.vue'
import HeaderBar from './Header/index.vue'
import AppMain from './AppMain.vue'
</script>
```

## 二、路由配置 `src/router/index.js`

### 2.1 完整路由配置代码

```js
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import Layout from '@/layout/index.vue'

// 公共路由（不需要登录即可访问）
const publicRoutes = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/views/login/index.vue'),
    meta: { title: '登录', hidden: true } // hidden: true 表示不在菜单中显示
  },
  {
    path: '/404',
    name: 'NotFound',
    component: () => import('@/views/error-page/404.vue'),
    meta: { title: '404', hidden: true }
  }
]

// 静态路由（有 Layout 布局，所有角色都能访问）
const constantRoutes = [
  {
    path: '/',
    component: Layout,
    redirect: '/dashboard',     // 访问 / 时自动重定向到 dashboard
    children: [
      {
        path: 'dashboard',
        name: 'Dashboard',
        component: () => import('@/views/dashboard/index.vue'),
        meta: {
          title: '首页',
          icon: 'HomeFilled',
          affix: true           // affix: true 表示在标签栏中固定显示
        }
      }
    ]
  }
]

// 动态路由（根据用户角色动态添加，初始不注册到路由中）
const asyncRoutes = [
  {
    path: '/system',
    component: Layout,
    name: 'System',
    meta: { title: '系统管理', icon: 'Setting' },
    children: [
      {
        path: 'user',
        name: 'User',
        component: () => import('@/views/system/user/index.vue'),
        meta: {
          title: '用户管理',
          icon: 'User',
          roles: ['admin', 'editor']  // 只有 admin 和 editor 角色可访问
        }
      },
      {
        path: 'role',
        name: 'Role',
        component: () => import('@/views/system/role/index.vue'),
        meta: {
          title: '角色管理',
          icon: 'UserFilled',
          roles: ['admin']            // 只有 admin 角色可访问
        }
      }
    ]
  },
  {
    path: '/:pathMatch(.*)*',        // 兜底路由，匹配所有未定义的路径
    component: () => import('@/views/error-page/404.vue'),
    meta: { hidden: true }
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes: [...publicRoutes, ...constantRoutes]
  // 注意：asyncRoutes 不在这里注册，而是在路由守卫中根据权限动态添加
})

// 导出路由配置，供 permission store 使用
export { constantRoutes, asyncRoutes }

export default router
```

### 2.2 路由 meta 字段说明

`meta` 字段是路由的元信息，用于控制菜单显示、权限、面包屑等行为：

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | `string` | 页面标题，用于面包屑、浏览器标签页标题、菜单名称 |
| `icon` | `string` | 菜单图标名称，对应 Element Plus 图标组件名 |
| `roles` | `string[]` | 允许访问该路由的角色列表，不设置则所有角色可访问 |
| `hidden` | `boolean` | 为 `true` 时不在侧边栏菜单中显示（如登录页、404页） |
| `breadcrumb` | `boolean` | 是否在面包屑中显示，默认 `true`，设为 `false` 可隐藏 |
| `affix` | `boolean` | 是否固定在标签栏（TagsView）中，首页通常设为 `true` |
| `noCache` | `boolean` | 是否不缓存该页面，默认 `false`（即默认被 keep-alive 缓存） |
| `activeMenu` | `string` | 当路由匹配时，高亮指定的菜单路径（用于详情页高亮列表页菜单） |

### 2.3 路由懒加载

所有页面组件都使用动态 `import()` 实现懒加载：

```js
// 推荐：Vite 魔法注释，可指定 chunk 名称（便于调试）
component: () => import(/* webpackChunkName: "dashboard" */ '@/views/dashboard/index.vue')

// 基本写法
component: () => import('@/views/dashboard/index.vue')
```

**为什么用懒加载？**
- 首次加载只下载当前页面所需的代码
- 每个页面独立打包成 chunk，按需加载
- 减小首屏体积，提升加载速度

### 2.4 静态路由 vs 动态路由

| 对比项 | 静态路由 (constantRoutes) | 动态路由 (asyncRoutes) |
|--------|--------------------------|----------------------|
| 定义时机 | 项目初始化时直接注册 | 登录后根据角色动态注册 |
| 访问权限 | 所有已登录用户 | 需要特定角色权限 |
| 注册方式 | `createRouter` 时传入 `routes` | 通过 `router.addRoute()` 动态添加 |
| 典型页面 | 首页、个人中心 | 用户管理、角色管理、订单管理等业务页面 |

## 三、路由守卫 `src/permission.js`

路由守卫是后台管理系统的安全门卫，负责判断用户是否登录、是否有权限访问。

### 3.1 安装 NProgress 进度条

NProgress 会在路由跳转时在页面顶部显示一个进度条，提升用户体验。

```bash
npm install nprogress
```

```js

import 'nprogress/nprogress.css'

// 配置 NProgress

```

### 3.2 完整路由守卫代码

```js
// src/permission.js
import router from '@/router'
import NProgress from '@/utils/progress'
import { getToken } from '@/utils/auth'
import { useUserStore } from '@/store/modules/user'
import { usePermissionStore } from '@/store/modules/permission'

// 白名单：不需要登录即可访问的路径
const whiteList = ['/login', '/404']

// 是否已经生成过动态路由（防止重复生成）
let hasRoles = false

router.beforeEach(async (to, from, next) => {
  // 开始进度条
  NProgress.start()

  // 设置页面标题
  document.title = to.meta.title ? `${to.meta.title} - Vue Admin` : 'Vue Admin'

  // 获取 Token
  const hasToken = getToken()

  if (hasToken) {
    // ========== 已登录 ==========
    if (to.path === '/login') {
      // 已登录但访问登录页 → 重定向到首页
      next({ path: '/' })
      NProgress.done() // 手动关闭进度条（重定向不会触发 afterEach）
    } else {
      // 已登录且有路由 → 放行
      // 检查是否已经获取过用户信息和动态路由
      if (hasRoles) {
        next()
      } else {
        try {
          // 获取用户信息
          const userStore = useUserStore()
          await userStore.getUserInfo()

          // 根据角色生成可访问的路由
          const permissionStore = usePermissionStore()
          const accessRoutes = permissionStore.generateRoutes(userStore.roles)

          // 动态添加路由到 router
          accessRoutes.forEach(route => {
            router.addRoute(route)
          })

          // 标记已完成
          hasRoles = true

          // 使用 replace 确保路由已添加后再导航（避免白屏）
          // addRoute 后直接 next() 会导致 404，需要 redirect
          next({ ...to, replace: true })
        } catch (error) {
          // 获取用户信息失败（如 Token 过期）→ 清除 Token 并跳转登录页
          const userStore = useUserStore()
          userStore.resetState()
          NProgress.done()
          next(`/login?redirect=${to.path}`)
        }
      }
    }
  } else {
    // ========== 未登录 ==========
    if (whiteList.includes(to.path)) {
      // 在白名单中 → 直接放行
      next()
    } else {
      // 不在白名单 → 重定向到登录页，并记录原始目标路径
      next(`/login?redirect=${to.path}`)
      NProgress.done()
    }
  }
})

router.afterEach(() => {
  // 完成进度条
  NProgress.done()
})
```

### 3.4 路由守卫流程图

```
用户访问页面
    │
    ▼
是否有 Token？
    │
    ├── 没有 ──→ 是否在白名单？──→ 是 ──→ 放行
    │                 │
    │                 └── 否 ──→ 跳转登录页（记录 redirect）
    │
    └── 有 ──→ 是否访问登录页？──→ 是 ──→ 重定向首页
                      │
                      └── 否 ──→ 是否已生成动态路由？
                                    │
                                    ├── 是 ──→ 放行
                                    │
                                    └── 否 ──→ 获取用户信息
                                                │
                                                ├── 成功 ──→ 生成动态路由
                                                │              ──→ 添加路由
                                                │              ──→ 放行
                                                │
                                                └── 失败 ──→ 清除 Token
                                                           ──→ 跳转登录页
```

### 3.5 关键细节说明

**1. `next({ ...to, replace: true })` 的作用**

动态路由通过 `router.addRoute()` 添加后，当前导航周期中路由表还未更新。直接 `next()` 会导致匹配不到新添加的路由，出现 404。使用 `next({ ...to, replace: true })` 会中断当前导航，发起一次新的导航，此时路由表已经包含了新添加的路由。

**2. `hasRoles` 变量**

用于标记是否已经获取过用户信息并生成过动态路由，避免每次路由跳转都重新获取和添加。注意这是一个模块级变量，页面刷新后会被重置，正好可以重新触发获取逻辑。

**3. 白名单机制**

`whiteList` 中的路径不需要 Token 就可以直接访问。典型场景是登录页和 404 页面。如果有其他公开页面（如帮助文档、关于页面），也需要加入白名单。

### 4.2 用户状态 `src/store/modules/user.js`

管理用户信息、Token，以及登录/登出逻辑。

```js
// src/store/modules/user.js
import { defineStore } from 'pinia'
import { login, getUserInfo, logout } from '@/api/user'
import { getToken, setToken, removeToken } from '@/utils/auth'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: getToken(),      // 从缓存中读取 Token
    roles: [],              // 用户角色列表
    name: '',               // 用户名
    avatar: ''              // 头像地址
  }),

  getters: {
    // 判断是否是管理员
    isAdmin: (state) => {
      return state.roles.includes('admin')
    }
  },

  actions: {
    // 登录
    async login(loginForm) {
      try {
        const { data } = await login(loginForm)
        this.token = data.token
        setToken(data.token)  // 持久化存储到 Cookie / localStorage
        return data
      } catch (error) {
        return Promise.reject(error)
      }
    },

    // 获取用户信息（登录后调用）
    async getUserInfo() {
      try {
        const { data } = await getUserInfo()
        this.roles = data.roles
        this.name = data.name
        this.avatar = data.avatar
        return data
      } catch (error) {
        return Promise.reject(error)
      }
    },

    // 登出
    async logout() {
      try {
        await logout()
      } catch (error) {
        // 即使接口调用失败也要清除本地状态
        console.warn('登出接口调用失败，但仍清除本地状态')
      } finally {
        this.resetState()
      }
    },

    // 重置所有状态（用于 Token 过期等场景）
    resetState() {
      this.token = ''
      this.roles = []
      this.name = ''
      this.avatar = ''
      removeToken()  // 清除缓存中的 Token
    }
  }
})
```

### 4.4 权限路由状态 `src/store/modules/permission.js`

管理动态路由的生成逻辑，根据用户角色过滤可访问的路由。

```js
// src/store/modules/permission.js
import { defineStore } from 'pinia'
import { constantRoutes, asyncRoutes } from '@/router'

/**
 * 递归过滤异步路由表
 * @param {Array} routes - 待过滤的路由表
 * @param {Array} roles - 用户角色列表
 * @returns {Array} 过滤后的路由表
 */
function filterAsyncRoutes(routes, roles) {
  const result = []

  routes.forEach(route => {
    const tmp = { ...route }

    if (hasPermission(roles, tmp)) {
      // 如果有子路由，递归过滤子路由
      if (tmp.children) {
        tmp.children = filterAsyncRoutes(tmp.children, roles)
      }
      result.push(tmp)
    }
  })

  return result
}

/**
 * 判断用户是否有权限访问该路由
 * @param {Array} roles - 用户角色列表
 * @param {Object} route - 路由对象
 * @returns {boolean}
 */
function hasPermission(roles, route) {
  if (route.meta && route.meta.roles) {
    // 路由指定了 roles，则检查用户角色是否包含在内
    return roles.some(role => route.meta.roles.includes(role))
  } else {
    // 路由未指定 roles，则所有角色都可访问
    return true
  }
}

export const usePermissionStore = defineStore('permission', {
  state: () => ({
    // 最终可访问的路由表（由静态路由 + 过滤后的动态路由组成）
    routes: [],
    // 动态添加的路由（用于渲染侧边栏菜单）
    addedRoutes: []
  }),

  actions: {
    /**
     * 根据角色生成可访问的路由
     * @param {Array} roles - 用户角色列表
     * @returns {Array} 完整的可访问路由表
     */
    generateRoutes(roles) {
      let accessedRoutes

      // 如果角色包含 admin，则拥有所有路由权限
      if (roles.includes('admin')) {
        accessedRoutes = asyncRoutes
      } else {
        // 否则根据角色过滤路由
        accessedRoutes = filterAsyncRoutes(asyncRoutes, roles)
      }

      // 保存动态路由（用于侧边栏菜单渲染）
      this.addedRoutes = accessedRoutes

      // 将静态路由与动态路由合并，作为完整的可访问路由
      this.routes = constantRoutes.concat(accessedRoutes)

      return accessedRoutes
    },

    /**
     * 重置路由状态（登出时调用）
     */
    resetRoutes() {
      this.addedRoutes = []
      this.routes = constantRoutes
    }
  }
})
```

## 五、辅助工具：Token 管理 `src/utils/auth.js`

路由守卫和用户 Store 都依赖 Token 的读写操作。**该文件已在第2章（工具类封装）中完整实现**，此处不再重复。如果尚未创建，请回到第2章按顺序完成。

以下是完整代码（与第2章一致）：

```js
// src/utils/auth.js
import { getStorage, setStorage, removeStorage } from './storage'

const TOKEN_KEY = 'access_token'

/**
 * 获取 Token
 * @returns {string|''}
 */
export function getToken() {
  return getStorage(TOKEN_KEY) || ''
}

/**
 * 设置 Token
 * @param {string} token
 */
export function setToken(token) {
  setStorage(TOKEN_KEY, token)
}

/**
 * 移除 Token
 */
export function removeToken() {
  removeStorage(TOKEN_KEY)
}
```

> 与第2章的区别：第2章版本的 `storage.js` 支持过期时间参数，比直接操作 `localStorage` 更安全。如果项目对安全性要求更高，可以进一步使用 Cookie 并设置 `httpOnly` 属性，避免 XSS 攻击窃取 Token。

## 六、API 接口定义 `src/api/user.js`

用户 Store 调用的接口定义（实际项目中需要根据后端接口调整）。

> **API 导入风格说明**：第2章推荐了 `import { get, post } from '@/utils/request'` 的命名导出方式。本章使用 `import request from '@/utils/request'` 的默认导出方式，两种写法等价，都可以使用。选择其中一种保持项目内一致即可。后续章节统一使用默认导出 + `request.get/post` 的方式。

```js
// src/api/user.js
import request from '@/utils/request'

/**
 * 登录
 * @param {Object} data - { username, password }
 */
export function login(data) {
  return request({
    url: '/auth/login',
    method: 'post',
    data
  })
}

/**
 * 获取当前用户信息
 */
export function getUserInfo() {
  return request({
    url: '/auth/userinfo',
    method: 'get'
  })
}

/**
 * 登出
 */
export function logout() {
  return request({
    url: '/auth/logout',
    method: 'post'
  })
}
```

## 七、404 错误页面 `src/views/error-page/404.vue`

路由配置中引用了 404 页面作为兜底路由，以下是完整代码：

```vue
<!-- src/views/error-page/404.vue -->
<template>
  <div class="error-page">
    <div class="error-content">
      <h1 class="error-code">404</h1>

      </el-button>

  </div>

import { useRouter } from 'vue-router'

const router = useRouter()

  router.push('/dashboard')

<style scoped>
.error-page {
  display: flex;

  min-height: 100vh;

  font-size: 120px;
```
